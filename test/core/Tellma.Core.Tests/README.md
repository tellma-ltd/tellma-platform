# Tellma.Core.Tests

Unit tests for `Tellma.Core`. No database, no network: compositions run against in-memory
configuration, the startup gate runs under a real generic host, and the file-system blob store runs
in a fresh temporary directory per case.

| Folder | Covers |
|---|---|
| `Composition/` | The graph gate (every problem in one exception, one message line each, with its fix; unknown requirements, duplicate names, cycles and their paths, a feature type added twice, options bound twice, slug and feature-name grammars, unknown item kinds, nested features); realisation (topological order, a dependent feature replacing a required feature's service directly or transitively, two unrelated features registering one service refused, collection services including the framework's multi-registration types, the options seam refusing a second path, item validation, the deployment identity and versions, the gate inserted first); host-free validation; the startup gate under a real host (every problem at once, before any other hosted service starts; a throwing check; a multi-line problem kept to one line; an uncreatable check beside the built-in ones; one shared scope; the infrastructure filter); the feature graph; the C# renderings problem texts use. |
| `Composition/Checks/` | Each built-in startup check, through a realised composition. |
| `Blobs/` | The blob name grammar (kinds, reserved device names, variants, keys, names, listing prefixes, traversal strings); the kind presets and the blob-reference declaration's policy; content-type determination over fixture byte prefixes (signatures, OOXML and plain zip, text with and without NUL, executables, HTML and SVG in their disguises); file-name sanitisation (separators, controls, bidirectional controls, line and paragraph separators, joiners kept); the shared blob-store conformance suite against the file-system store in a temporary directory; the file-system store's layout, part files, the publish-time conflict of a writer that passed the early check, a failing lazy ensure, the hard-link probe, cancellation, shared reads and deletes, stray files, root rules and log events; `AddFileSystemBlobStore` (binding, the caller's action, the Development default, validation, idempotence); the store instruments' tag values and the pinned telemetry names; and the runtime's isolation from the imaging package (no reference to it, SkiaSharp or PDFtoImage, and no Skia or PDFium binary in a runtime-only output). |
| `Calendars/` | The Ethiopian conformance vectors and their inverses, the epoch, the leap rule, New Year and its century shifts, every day round-tripping from the epoch to `DateOnly.MaxValue`, the framework calendar's arithmetic; Umm al-Qura's published dates, its 2,196 contiguous months, the tabular calendar beyond AH 1500 and before AH 1318, the Islamic epoch; golden renderings of every calendar in every style in English, Arabic and Amharic over cultures whose formats are pinned, so ICU releases do not move them; over the host's own cultures, ASCII digits and no bidirectional controls, the numeric style reading back, and the Gregorian rendering equal to the framework's; month names and their fallback; reading any script's digits; the date-pattern reader; Core's month-name resources; the registry and its composition. |
| `Data/` | The tenant model a composition builds over a fixture-shaped test model (`Data/Model/`): one mapped type per table with leaves in place of their defaults, children and grandchildren discovered and substituted, an open Core configuration closed over its leaf, the platform tables and bulk types, the platform collation, the registered runtime model and the model cache per composition; every convention read back from the design-time model and the generated SQL, by name; the declarations a model cannot be built with; the initial migration scaffolded with a migrator's design-time services, compiled, and its snapshot replayed with no difference; `UseTellmaSqlServer` (application name, compatibility level, hierarchyid, sweep scopes); the table-type binder (metadata order and types, values by name, enums by name, lazy and repeatable records, standalone types, refusals). |
| `Repository/` | `taxonomy.json` at the repository root: every distribution folder registered, every slug well formed, no reserved slug taken but the reference distribution's. |
| `Infrastructure/` | Test features, items, checks and the helpers that compose them. |

## Running

```bash
dotnet test test/core/Tellma.Core.Tests
```
