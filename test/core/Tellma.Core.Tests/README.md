# Tellma.Core.Tests

Unit tests for `Tellma.Core`. No database, no network: compositions run against in-memory
configuration, the startup gate runs under a real generic host, and the file-system blob store runs
in a fresh temporary directory per case.

| Folder | Covers |
|---|---|
| `Access/` | The access model Core contributes, composed alone (`AccessModel`): the entities' names and ownership, the server-owned, derived and write-once flags, enum widths, value sets, blob references, children and references through the metadata provider; the stamps and preferences tables, which are not entities; the stored state, the subject's collation and covering index, each table's checks, indexes and foreign keys, and the seeds in the reserved band, from the design-time model. A distribution extending all four access entities (`AccessLeafTests`): every configuration closed over its leaf, every foreign key reaching the leaf, the defaults' names and seeds kept, and the startup gate passing. The access vocabulary's grammars. |
| `Composition/` | The graph gate (every problem in one exception, one message line each, with its fix; unknown requirements, duplicate names, cycles and their paths, a feature type added twice, options bound twice, slug and feature-name grammars, unknown item kinds, nested features); realisation (topological order, a dependent feature replacing a required feature's service directly or transitively, two unrelated features registering one service refused, collection services including the framework's multi-registration types, the options seam refusing a second path, item validation, the deployment identity and versions, the gate inserted first); host-free validation; the startup gate under a real host (every problem at once, before any other hosted service starts; a throwing check; a multi-line problem kept to one line; an uncreatable check beside the built-in ones; one shared scope; the infrastructure filter); the feature graph; the C# renderings problem texts use; server-built links (a tenant's home, a details page only for a stack with `Details` through a fake stack-route source, the home for an unknown resource and a null resource or id, the missing origin, the composed default). |
| `Composition/Checks/` | Each built-in startup check, through a realised composition; `core.sql-profiles` rule by rule; `core.languages`, `core.calendars` and `core.value-sets` gate by gate, with the satellite probe and the host's time-zone data substituted where a rule reads the host; `core.time-zones` warning once per unresolvable zone and never failing. |
| `Blobs/` | The blob name grammar (kinds, reserved device names, variants, keys, names, listing prefixes, traversal strings); the kind presets and the blob-reference declaration's policy; content-type determination over fixture byte prefixes (signatures, OOXML and plain zip, text with and without NUL, executables, HTML and SVG in their disguises); file-name sanitisation (separators, controls, bidirectional controls, line and paragraph separators, joiners kept); the shared blob-store conformance suite against the file-system store in a temporary directory; the file-system store's layout, part files, the publish-time conflict of a writer that passed the early check, a failing lazy ensure, the hard-link probe, cancellation, shared reads and deletes, stray files, root rules and log events; `AddFileSystemBlobStore` (binding, the caller's action, the Development default, validation, idempotence); the store instruments' tag values and the pinned telemetry names; and the runtime's isolation from the imaging package (no reference to it, SkiaSharp or PDFtoImage, and no Skia or PDFium binary in a runtime-only output). |
| `Calendars/` | The Ethiopian conformance vectors and their inverses, the epoch, the leap rule, New Year and its century shifts, every day round-tripping from the epoch to `DateOnly.MaxValue`, the framework calendar's arithmetic; Umm al-Qura's published dates, its 2,196 contiguous months, the tabular calendar beyond AH 1500 and before AH 1318, the Islamic epoch; golden renderings of every calendar in every style in English, Arabic and Amharic over the negotiated cultures, whose pinned formats no ICU release moves; the cleaning of raw culture data over clones pinned to it; over the host's own cultures, ASCII digits and no bidirectional controls, the numeric style reading back, and the Gregorian rendering equal to the framework's; month names and their fallback; reading any script's digits; the date-pattern reader; Core's month-name resources; the registry and its composition. |
| `Data/` | The tenant model a composition builds over a fixture-shaped test model (`Data/Model/`): one mapped type per table with leaves in place of their defaults, children and grandchildren discovered and substituted, an open Core configuration closed over its leaf, the platform tables and bulk types, the platform collation, the registered runtime model and the model cache per composition; every convention read back from the design-time model and the generated SQL, by name; the declarations a model cannot be built with; the initial migration scaffolded with a migrator's design-time services, compiled, and its snapshot replayed with no difference; `UseTellmaSqlServer` (application name, compatibility level, hierarchyid, sweep scopes); the table-type binder (metadata order and types, values by name, enums by name, lazy and repeatable records, standalone types, refusals). `Data/Metadata/`: the entity metadata of a sound model (leaves from any base, names, tables and table types, properties in declaration order, ownership by derivation and annotation, facets, the value set a string property draws from, compiled accessors, the resets, natural-key ranking and inference, groups, unique indexes, trees, blob references, display-name resolution, children, references and the one warning); each rule of the entity contract as a model that breaks it once (`Malformed/`), and a malformed model reporting every problem at once; the schema and storage fingerprints, pinned, stable and changed by exactly what they guard (`Fingerprinted/`). `DataOptionsTests`: the data layer's execution settings validated directly and when bound from configuration. |
| `Data/Batches/` | Batches over the default composition with no database (`BatchHarness`, whose connection refuses at the send): the frame with prologues in `Order` and epilogues reversed, pinned as text; the same batch assembling to the same text; the lazy prologue stage; the in-text transaction for `Auto` writes only; the guard wrapper, its absence around a body with no text, and its mark's refusals; a guarded batch with no verdict; statement-local names and ordinals; a discarded statement's ordinal reused; the line map, with terminators after a trailing comment; scalar holes typed by value and identifiers as text, a `nameof` hole binding as a value; refused holes; user ids naming declared tables only; a contributor's prologue statement shared with an identical caller statement; a throwing contributor leaving the batch unusable; the command timeout per purpose; deduplication; the caller's write authority over stack-owned tables; the parameter budget; a reserved name bound twice; the result-set count guards; a sealed batch; the members whose compilers are not composed. |
| `Data/Queries/` | The query layer over a query-shaped test model (`QueryModel`): one schema per multilingual shape differing only in the name twins, store types, nullability, withheld JSON, period and secret columns, navigations with a sibling's optional one, a tree's node and the fingerprint; golden SQL of every query statement (a rows page with its key-capture twin, count and ancestors; counts, constants and assertions; an entity query with its completion, child and grandchild statements), deduplication, refusals, an omitted parameter folding out and a typed null binding NULL, `Limits`; slot binding by origin and store type; the materializer's routing (root, related with projection, JSON by name, children and grandchildren, unknown columns); `IDisplayNames` and the rule against the client's shared `display-name-golden.json`. |
| `Tenancy/` | The tenant registry over a fake catalog and clock (the first load; a probe that confirms without reloading; a reload on a changed version and on an older one; forced reloads; single flight, with a forced refresh queued behind a running one rather than joining it; listeners told only of changed descriptors, with the state before, and a failing listener logged; the staleness bound serving, then refusing with `catalog-unavailable`, then serving again; a snapshot never loaded; rows outside the allowed servers, with an unknown profile, a malformed database or an unknown state left out and logged; Development's empty allowed list; the warm-tenant warning; a changed profile recomposing every string; startup over a behind, never-migrated, missing or unreachable catalog, and the first-load bound; the migrator skipping the verification; the instruments; no composed string or profile value in any log line); the location grammar and the allowed-servers rule; connection composition (profile keywords, the row's server and database as values, the deployment's application name, separators never adding a keyword, a redacted `ToString`); the state table over every pair; the database-creation statement on SQL Server and Azure SQL Database with and without options; the catalog model (the collation pin and the latest-migration pin over the migrator's migrations, the pinned column set of `catalog.Tenants`, schema, keys, sequence, binary identifiers and the membership table type); the write side's refusals before it touches the catalog; the landing rule over the shared `launch-landing-vectors.json` of the client's core package; the tenancy runtime under a real generic host (registrations and lifetimes, the startup load after the gate, the refresh loop on the host's clock, a behind catalog failing the start, a tenant's string reaching that tenant alone); the request context as composed, over a fake catalog and clock: the scoped holder (tenantless until bound and stamped once, one instance per scope, one tenant, one principal and one user for a scope's lifetime, and a structural pin, over every platform assembly the suite ships with and over method bodies as well as signatures, that only the two writers take its write side); the scope factory (the snapshot restored, initializers with empty inputs, every state with and without the maintenance door, refusals before a scope exists, a tenant the catalog no longer holds refused as a retired one is, a scope disposed when its user is not a member, when no user was bound and when it is cancelled while it is completed, no activity started, the scopes counter); | `Localization/` | The language catalogue (the fifteen entries, the 243 pairs frozen and predefined, native digits, default regions, a distribution's declaration and added languages, lenient resolution); the negotiated cultures (every pair named by its pair, Gregorian, read-only, carrying exactly its pinned data, formatting with Latin digits and no bidirectional control; numbers and dates as pinned; one instance per pair;
