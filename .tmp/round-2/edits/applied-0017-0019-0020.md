## Surprises and open points

- 0017 §8.1 already required `Tellma-Client` on the upload and §11 already pinned the 403; X-0017-3 only adds the spec 0011 §5.4 rule-4 citation and the client sender. The ruling's "§5" target is the download section.
- Ruling C-0026-4 collapses the support files into one `support-bundle` blob on `SupportRequest`, but design note 0026 §12.3–§12.4 still shows `SupportRequestFile.FileId` and four content types with a thumbnail. 0017 therefore names the owner entity only and cites spec 0026 §12.4 for the policy; the 0026 author must name the property (`BundleId`?) and narrow the types to `application/json`.
- Design note 0033 §12.4 puts `ExcelTableSpec`, `ExcelTableRow`, `ExcelRowStyle` in `Tellma.Core.Abstractions.Excel`, but they reference `ExcelColumnSpec`, a runtime type of `Tellma.Core.Excel` beside `IExcelExporter`. They are placed in the runtime namespace; 0033 should cite 0019 §4.4 and not restate them.
- `ExcelRowStyle` has five non-phantom values for 0033's "four styles"; 0019 §4.4 renders `Subtotal3` like `Normal` (regular). 0033 §12.3 also says "the same ladder applies to column totals", which the row-styled writer cannot express (no per-column style); 0033 must either drop that line or ask for a column-style member.
- The report export label `Core_Job_ExportReport { title }` (0033's key) is resx-style, while 0019's labels are code-style (`Excel.Export.Label`, looked up with `.` → `_`). Both resolve; the inconsistency is 0033's to settle.
- `ExportRequest.Columns` and `ExportForImportRequest.Columns` share a member name with different types (`ExportColumn[]` versus path strings); the member table qualifies both.
