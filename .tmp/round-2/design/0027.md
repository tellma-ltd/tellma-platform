## 2. Decisions

1. **Shells are route components loaded from `@tellma/core/shell` by the route table's
   `loadComponent`, preloaded by the build** (§1). Why: the primary may not import `/shell`
   statically (A§2.2); a preload keeps the cold path parallel and the warm path a cache read.
   Alt: shells in the primary (budget, and the import rule); the distribution importing `/shell`
   (rule 1). Challenge 1.
2. **Every declared entity, page and coded report gets a launcher entry; `section` decides only
   whether it is browsable** (§3.2). Why: one rule, zero extra lines; personal pages
   (Notifications, Assignments) stay findable without a section. Alt: entries only with a section
   (personal pages unreachable from search); a `launcher: 'none'` member (no consumer).
3. **Synonyms by string-key convention**: `<labelKey>_Synonyms`, a comma list per language
   (§3.3). Why: a distribution adds synonyms with one resx line per language, no declaration.
   Alt: a `synonymsKey` on every declaration (kept as the override).
4. **Two navigation levels (section → entry); no groups** (§3.1). Why: the design draws flat
   sections; ≤ 30 entries per section reads fine in a column. Alt: shell research D3's optional
   third level (review flag 8).
5. **Matching is client-side over a normalized multilingual index** of labels and synonyms in the
   active language, English and the switch's other languages (§9.4). Why: instant, offline,
   rule 2A/2B. Alt: server search (network per keystroke).
6. **The launcher is one APG combobox with a grouped listbox popup; DOM focus never leaves the
   input** (§9.5). Why: typing, arrows and Enter share one focus point in both states. Alt: shell
   research D19's `<nav aria-label="Main menu">` of links (two keyboard models).
7. **Launcher text and results survive Esc and navigation** in the tab; reopening selects the text
   (§9.2). Why: the brief; repeat navigation is one `Mod+K` + Enter. Alt: clear on navigation.
8. **A separate "Create" row follows a strongly matched entity entry** (§9.4), as the design
   draws. Why: a listbox option cannot hold a second control. Alt: shell research D2's inline
   "+ New" affordance.
9. **Providers append buckets below Pages; pages never wait** (§9.6). Why: rule 2C; the active
   row never moves when a provider answers. Alt: one merged ranking (rows jump).
10. **Pins store tenant-relative URLs, query included, `page` stripped** (§8.2). Why: any deep
    link is pinnable and a filtered search survives as a pin with no page cooperation; one pins
    value fits every tenant. Alt: shell research's page-state contributor (the URL already carries
    the state, A§8).
11. **Pinning is one click; the "Pinned" popover offers rename and folder afterwards** (§8.5).
    Why: rule 2B; the browser-bookmark habit. Alt: a dialog before pinning.
12. **Hard caps: 30 pins, 10 folders, one folder level** (§8.2). Why: the 32 KB value cap
    (0014) with worst-case Arabic labels; research Q7. Alt: research's soft cap ~20 with a nudge.
13. **No tenant default and no role seeds for pins in v1** (§8.2). Why: an editor and a settings
    save path for one convenience; research calls an empty v1 legitimate. Alt: a
    `navigation.defaultPins` setting (review flag 3).
14. **The pinned bar is a roving-tabindex toolbar of links: one tab stop** (§8.6). Why: ten pins
    would be ten tab stops before the page. Alt: one tab stop per pin.
15. **Shortcuts always carry a modifier; `Mod+/` opens the Shortcuts dialog instead of `?`**
    (§4.3). Why: WCAG 2.1.4 forbids single-character shortcuts without an off switch. Alt: `?`
    plus a "single-key shortcuts" switch (review flag 5).
16. **The `Alt+Shift+<letter>` family belongs to the platform; pages use `Mod+…`** (§4.3). Why:
    one rule prevents page/shell clashes; `Alt+Shift` is free in Chrome, Edge and Safari and
    collides only with Firefox accesskeys, which Tellma never sets. Alt: per-key review only.
17. **Tenant markers sit beside the session button, outside it** (§7.4). Why: a button inside a
    button is invalid; the design's in-button chips stay visually adjacent. Alt: inside (invalid
    nesting).
18. **The session menu is `tm-menu`**, with small Part C additions (a segmented radio group,
    `cssClass`, string icons, touch rows; note section 6) (§10). Why: one menu engine, one Escape
    stack. Alt: a bespoke popover (a second keyboard model).
19. **Back and forward show only in standalone, fullscreen or window-controls-overlay display
    modes, driven by the Navigation API with an in-memory fallback** (§7.3). Why: the brief;
    Navigation API is Baseline 2026 only. Alt: always hidden without the API.
20. **The tenant card's sub-line is "Tenant {id}" plus markers** (§10.2). Why: the core has no
    currency or location; the id disambiguates live and sandbox. Alt: the design's
    "AED · Abu Dhabi" through a feature hook (review flag 9).
21. **`users/me/locale` is one `Update<User>` round trip that moves `ModifiedAt`** (§12). Why:
    a typed column change is a row change (temporal history, concurrency). Alt: leave the stamp
    (a stale My profile save would silently revert the toggle).

## 3. Design (the future spec's sections)

### §1 Placement and vocabulary

The shell lives in `@tellma/core/shell`; the two registries every page calls live in the primary.

| Entry point | 0027 members |
|---|---|
| `@tellma/core` (primary) | `TmNavigation`, `TmNavSection`, `TmNavEntry`, `TmNavItem`, `TmShortcuts`, `TmShortcut`, `TM_RESERVED_SHORTCUTS`, `TM_BROWSER_KEYS`, `TmShellSlot`, `TmShellMain`, `TM_SHELL_LAYOUT` |
| `@tellma/core/shell` | `TmTenantlessShell`, `TmTenantPicker`, `TmSignedOutPage`, `TmTenantShell`, `TmAppBar`, `TmPinnedBar`, `TmPins`, `TmLauncher`, `TM_LAUNCHER_PROVIDERS`, `TmLauncherProvider`, `TmLauncherItem`, `TmSessionMenu`, `tmSearchNormalize`; deferred chunks: launcher panel, About, Shortcuts and Manage pins dialogs |
| `@tellma/core-testing` | `TmTenantShellHarness`, `TmLauncherHarness`, `TmPinnedBarHarness`, `TmSessionMenuHarness`, `TmTenantPickerHarness`, `tmTestShellSlot()` |

- **Loading.** 0024's route table loads `TmTenantlessShell` and `TmTenantShell` through
  `loadComponent: () => import('@tellma/core/shell')`; `tellma-client build` adds
  `<link rel="modulepreload">` for the `/shell` chunk and its static imports (`/attention`), so a
  cold launch fetches them with the initial JS and a warm launch reads them from the worker cache
  (decision 1, request to 0024).
- **Imports.** `/shell` imports the primary and `/attention`; it reaches `/support` (Diagnostics
  tab) and `/realtime` only through `import()`.
- **Budgets (gzip self-weight).** `/shell` eager part 16 KB; launcher panel 6 KB; About,
  Shortcuts and Manage pins dialogs 6 KB together; 0027's primary share 4 KB
  (`TmNavigation`, `TmShortcuts`).
- **Folders.** `client/projects/core/tellma-core/src/nav/` (primary), `client/projects/core/tellma-core/shell/`
  (`frame/`, `tenantless/`, `app-bar/`, `pins/`, `launcher/`, `session/`, `dialogs/`).
- **Vocabulary**
  - *Tenant shell* — the frame of every `/{t}/…` route: app bar, banner row, pinned bar, `main`.
  - *Tenantless shell* — the frame of `/tenants` and `/signed-out`.
  - *App bar* — the 40 px first row. *Pinned bar* — the 32 px row of pins. *Banner row* — the
    32 px row between them while a banner shows.
  - *Slot* — an app-bar icon button with a badge and a panel (`TmShellSlot`).
  - *Marker* — the Sandbox or Read-only chip beside the session button.
  - *Pin* — a saved tenant-relative URL in the pinned bar; *folder* — a named group of pins, one
    level deep.
  - *Launcher* — the overlay the Menu button, the search field and `Mod+K` open. *Browse state* —
    empty query. *Typed state* — a non-empty query.
  - *Entry* — one navigation registry item (`TmNavEntry`); *section* — a launcher column.
  - *Provider* — a source of launcher results other than pages (`TmLauncherProvider`).
  - *Installed mode* — the app runs in a window without browser navigation controls.

### §2 What a distribution writes

The common case writes nothing: entities, pages and coded reports become launcher entries from
their own declarations. A section is one line in the feature; a synonym is one resx line.

```ts
// acme.feature.ts — the only navigation code Acme writes (A§3.4)
export const acmeFeature = tmFeature({
  key: 'acme',
  sections: [{ id: 'sales', labelKey: 'Acme_Nav_Sales', icon: 'users', order: 20 }],
  entities: [customers, salesInvoices],                  // each with section: 'sales'
  pages: [tmPage('bank-reconciliation', { component: () => import('./bank/bank-page'),
    titleKey: 'Acme_BankReconciliation', section: 'financials' })],      // a GL section, from tmGlFeature()
});
```

```xml
<!-- Strings.resx: synonyms, comma-separated, matched but never shown -->
<data name="Acme_Customer_Plural_Synonyms"><value>Clients, Buyers, Debtors</value></data>
<!-- Strings.ar.resx: the same key in Arabic -->
<data name="Acme_Customer_Plural_Synonyms"><value>زبائن، مشترين، مدينون</value></data>
```

| Need | Hatch | §  |
|---|---|---|
| A launcher link that is not an entity, page or report | `entries: [{ id, section, labelKey, url: (t) => …, requires? }]` | §3.1 |
| Reorder or relabel a platform section or entry | `overrides` are entity-only (N24 §2.3); for sections and entries: `hide: ['section:administration']` then redeclare under a new id | §3.2 |
| Remove a launcher entry, keep the route | `hide: ['entry:core.Role']` (N24 §2.3) | §3.2 |
| An app-bar item | `appBar: [{ id, icon, labelKey, badge?, panel }]`, at most three (N24 §2.3) | §7.2 |
| A launcher bucket (records, help) | `providers: [{ provide: TM_LAUNCHER_PROVIDERS, multi: true, useClass: … }]` on the feature | §9.6 |
| A page shortcut | a `TmPageAction` with `shortcut` (0026), or `inject(TmShortcuts).register(…)` | §4 |

### §3 The navigation registry

`TmNavigation` turns the merged declarations into the permission-filtered, ordered list of
sections and entries that the launcher, recents, pins and the home page render.

#### §3.1 Contract

```ts
interface TmNavSection { id: string; labelKey: string; icon: string; order: number }      // A§5.11
interface TmNavEntry {                                                                    // A§5.11, completed
  id: string;                                   // the declaration's key: 'acme.Customer', 'bank-reconciliation', 'acme-aging', 'core.settings'
  section?: string;                             // absent: search-only (§3.2)
  labelKey: string;
  url: (t: number) => string;                   // canonical path (N24 §9.1): '/17/customers'
  icon?: string;                                // a registered icon name; default per kind (§3.2)
  order?: number;                               // within the section; default 100, ties by localized label
  synonymsKey?: string;                         // default `${labelKey}_Synonyms`
  requires?: TmSecurableRef | readonly TmSecurableRef[]; // any of them suffices
  helpKey?: string;                             // reserved (N26 §9.8)
}
interface TmNavItem extends TmNavEntry {        // a resolved, visible entry
  readonly href: string;                        // url(current tenant)
  readonly kind: 'entity' | 'page' | 'report' | 'core';
  readonly entity?: string;                     // kind 'entity'
  readonly createHref: string | null;           // '/17/customers/new' when the user can create (§3.2)
  readonly pinned: Signal<boolean>;             // a top-level or folder pin has this href without a query
}
interface TmNavSectionView extends TmNavSection { readonly entries: readonly TmNavItem[] }
declare class TmNavigation {
  readonly sections: Signal<readonly TmNavSectionView[]>; // browsable, permission-filtered, ordered; empty sections dropped
  readonly items: Signal<readonly TmNavItem[]>;           // every visible entry, search-only ones included
  byHref(href: string): TmNavItem | undefined;            // exact canonical path, no query (recents N25 §13, pins §8)
}
```

- **Source.** The merged, `hide`-applied declarations of every feature (N24 §2.3), read through
  the primary token `TM_APP_DECLARATIONS` (request to 0024).
- **Tenant.** `href` and permissions follow the routed tenant (`TmUrls.tenantId`); tenantless
  routes have no items.
- **Recomputed** when access (`me` permissions tag), the language (labels sort) or the tenant
  changes; never per keystroke.

#### §3.2 Where entries come from

| Declaration | Entry id | Label | URL | Requires | Default icon | Create row |
|---|---|---|---|---|---|---|
| `tmEntity` (any declared entity with a `query` operation) | entity name | `<Schema>_<Entity>_Plural` | `/{t}/{segment}` | `[name, 'Read']` | `file-text` | when the `save` operation exists, a details page is declared, and `can(name, 'Save')` |
| `tmPage` | path | `titleKey` | `/{t}/{path}` (no parameters; a path with `:param` gets no entry) | `securable` | `square-dashed` | — |
| `tmCodedReport` | key | `titleKey` | `/{t}/reports/{key}` | `securable` | `chart-column` | — |
| `entries` on a feature | `id` | `labelKey` | `url(t)` | `requires` | `link` | — |

- **`section`** on any of them puts the entry in that browse column; without it the entry is
  found by typed search, recents and pins only. An unknown section id is N24's
  `unknown-section` problem.
- **Navigation members of `tmEntity`** whose meaning this spec owns (shape 0029): `section`,
  `navOrder`, `icon`, `synonymsKey`. `tmPage` and `tmCodedReport` take `section`, `order`, `icon`,
  `synonymsKey` (request to 0024 and 0034).
- **Visibility.** An entry shows when `requires` is absent or any listed securable passes
  `TmPermissions.can(resource, action)` (0029). A section with no visible entry is dropped.

**The core feature's navigation (binding).**

| Section | Order | Icon | Entries (owner of the declaration) |
|---|---|---|---|
| `analysis` (`tm.nav.analysis` "Analysis") | 800 | `chart-column` | Reports `core.ReportDefinition` (0034), Dashboards `core.Dashboard` (0035) |
| `administration` (`tm.nav.administration` "Administration") | 900 | `settings` | Users, Roles, Settings, Schedules, Jobs, Exports, Imports, Outgoing emails, Support requests (0032, 0028, 0026); `gl.Center` Centers (`@tellma/module-gl`) |
| — (search-only) | — | — | Notifications, Assignments (0028), My profile `core.me`, Notification settings `core.me.notifications` |

- **Settings** is an explicit entry `core.settings` → `/{t}/settings` with `requires` = every
  `core.Settings.<category>` × `Read` of the metadata's setting categories (any of them).
- **Section order bands:** distribution and pack sections use 1–700 (`financials` 10, Acme's
  `sales` 20), so Analysis and Administration close the launcher, as the design draws.

#### §3.3 Labels and synonyms

- **Labels** resolve through the active language at render (`TmLocalization`, 0024); a missing
  key renders the key in development and warns once.
- **Synonyms** are the value of `synonymsKey ?? labelKey + '_Synonyms'`, split on `,` and `،`
  (Arabic comma), trimmed, empties dropped. A missing key means none, with no warning. Synonyms
  are matched, never displayed.
- **Example —** `Acme_Customer_Plural` "Customers" / "العملاء", synonyms "Clients, Buyers" /
  "زبائن": typing "clients", "زبائن" or "عملاء" finds Customers in either UI language (§9.4).

### §4 The shortcut registry

`TmShortcuts` is the one keyboard listener for app-level shortcuts. It owns the reserved keys,
refuses conflicts, and lists every live shortcut for the Shortcuts dialog. Components that own
keys (the grid, editors, menus) keep handling them locally and win.

#### §4.1 Contract

```ts
interface TmShortcut {                                  // A§5.11's register argument, completed
  readonly id: string;                                  // 'tm.launcher.open', 'details.save', 'acme.bank-reconciliation.auto-match'
  readonly keys: TmKeys;                                // 0023 grammar: 'Mod+K', 'Alt+Shift+P'
  readonly labelKey: string;                            // the Shortcuts dialog row
  readonly scope: 'global' | 'page';
  readonly group?: 'general' | 'navigation' | 'page';   // dialog section; default by scope
  readonly inFields?: boolean;                          // fires while focus is in an editable field; default true for Mod/Ctrl combinations, false otherwise
  readonly overModals?: boolean;                        // fires while a modal is open; default false
  run(event: KeyboardEvent): void | false;              // false: not handled, the event continues
}
declare class TmShortcuts {                             // primary
  register(shortcut: TmShortcut, destroyRef?: DestroyRef): void; // destroyRef defaults to the injection context's
  readonly active: Signal<readonly TmShortcut[]>;       // live registrations, for the Shortcuts dialog
}
declare const TM_RESERVED_SHORTCUTS: readonly { readonly id: string; readonly keys: TmKeys; readonly owner: string }[];
```

**Example —** a distribution page binds one key (most pages instead give a `TmPageAction` a
`shortcut`, which 0026 registers while its context is on top):

```ts
inject(TmShortcuts).register({ id: 'acme.bank-reconciliation.match-next', keys: 'Mod+Shift+M',
  labelKey: 'Acme_BankReconciliation_MatchNext', scope: 'page', run: () => this.matchNext() });
```

#### §4.2 Dispatch

1. One `keydown` listener on `document` in the **bubble** phase, so focused components (grid,
   editors, menus, dialogs) see the key first.
2. Skip when: `event.defaultPrevented`; `event.isComposing` or `key === 'Process'`;
   `event.repeat`; `TmBusyOverlay.active()` (0023); the session is not `active` (0024).
3. Find the registration whose keys match (`tmKeysMatch`, with 0026's physical-key fallback for
   non-Latin layouts, request to 0023). Page scope is tried before global; equal keys in both
   cannot exist (§4.3).
4. **Editable targets** (`input`, `textarea`, `select`, `[contenteditable]`, or inside a
   `[role=grid]` while its editor is open): run only when `inFields` is true, and never when
   `event.key` is one printable character other than the combination's own letter (an AltGr or
   Option combination that types a character, such as Option+Shift+P giving `∏` on macOS).
5. **Modals:** while a CDK dialog is open (`TmModal`, 0005), run only shortcuts with `overModals`
   and page shortcuts whose context is the dialog's (0026 registers those only while `top`).
6. Run; unless it returns `false`, `preventDefault()` and `stopPropagation()`. Telemetry
   `tm.shortcut.used { id }` (sampled; ids are code constants).

#### §4.3 Reserved keys and conflict rules

| Id | Keys (Apple) | Does | Fields | Over modals | Owner |
|---|---|---|---|---|---|
| `tm.launcher.open` | `Mod+K` (⌘K) | open the launcher; select its text (§9.2) | yes | no | 0027 |
| `tm.shortcuts.open` | `Mod+/` (⌘/) | open the Shortcuts dialog | yes | no | 0027 |
| `tm.pins.toggle` | `Alt+Shift+P` (⌥⇧P) | pin or unpin the current page (§8.5) | no | no | 0027 |
| `tm.toasts.focus` | `Alt+Shift+T` (⌥⇧T) | `TmToasts.focus()` (0023) | yes | yes | 0027 |
| `tm.attention.notifications` | `Alt+Shift+N` | open the bell panel | yes | no | 0028 |
| `tm.attention.assignments` | `Alt+Shift+A` | open the tray | yes | no | 0028 |
| `tm.help.open` | `Alt+Shift+H` | reserved: the help drawer | — | — | help (later) |
| `tm.assistant.open` | `Alt+Shift+I` | reserved: the assistant | — | — | assistant (later) |
| `tm.support.copy-diagnostics` | `Mod+Alt+Shift+D` | copy diagnostics (N26 §8.3) | yes | yes | 0026 |

- **Families.** The platform owns `Mod+K`, `Mod+/`, every `Alt+Shift+<letter or digit>` and every
  `Mod+Alt+Shift+<key>`. Pages and distributions use `Mod+<key>`, `Mod+Shift+<key>` and
  `Mod+Enter`.
- **Refused registrations** (a `TmShortcutConflictError` in development; in production the later
  registration is dropped and `tm.shortcut.conflict { id }` is emitted):
  - keys without `Mod`, `Ctrl` or `Alt` (WCAG 2.1.4; `Escape`, arrows and `Enter` are component
    keys, never registry keys);
  - a reserved combination or the platform families, from a non-platform id;
  - a grid key: the 0004 bindings that carry a modifier, exported by core-ui as
    `TM_GRID_KEYS` (request to 0010 Part C): `Mod+A`, `Mod+C`, `Mod+X`, `Mod+V`, `Mod+D`, `Mod+Z`,
    `Mod+Y`, `Mod+Shift+Z`, `Mod+F`, `Mod+Alt+Minus`, `Mod+Alt+Plus`, `Mod+Arrow…`, `Mod+Home`,
    `Mod+End`, `Ctrl+Space`, `Ctrl+Shift+Space`, `Alt+ArrowLeft`, `Alt+ArrowRight`,
    `Alt+ArrowDown`;
  - a browser-owned combination pages cannot take: `Mod+T`, `Mod+W`, `Mod+N`, `Mod+Shift+N`,
    `Mod+Shift+T`, `Mod+Tab`, `Mod+L`, `Mod+R`, `Mod+Q`, `Mod+H`, `Mod+M`, `Mod+P`, `Mod+Shift+W`,
    `Mod+Plus`, `Mod+Minus`, `Mod+0` (`TM_BROWSER_KEYS`, primary);
  - two live registrations of one combination in one scope.
- **Platform labels.** Every rendering goes through `tm-kbd` / `tmFormatKeys` (0023): "Ctrl K"

- **`aria-keyshortcuts`** is set from `tmAriaKeyShortcuts` on the control a shortcut activates
  (the search input, the pin control).

### §5 The shell frame: layout, landmarks, focus, print

Both shells are a fixed-height CSS grid; only `main` scrolls. The shell publishes its chrome
height once as `--tm-shell-top`, so no page computes it.

#### §5.1 Layout constants

| Row | Height | Present |
|---|---|---|

| Banner row | 32 px | while a banner shows (0028 holds entries and exits for 2 s of input idleness, A§9) |

- **TypeScript mirror** for harnesses: `TM_SHELL_LAYOUT = { appBar: 40, banner: 32, pinnedBar: 32 }`
  (primary).
- **The aside column** is the reserved inline-end host for the future help drawer (A§14 ruling 1):
  `--tm-aside-width` stays 0 and the column is empty in v1. The help spec opens it at ≥ `lg`
  (360 px, pushing `main`) and uses `TmModal` `placement: 'end'` below `lg`.
- **Viewport.** `100dvh` follows the iOS toolbar; `env(safe-area-inset-*)` pads the app bar in
  standalone mode (`viewport-fit=cover`, 0024's `index.html`).

#### §5.2 Landmarks and skip link

```html
<!-- tm-tenant-shell (outline; the tenantless shell omits the pinned nav) -->

```

- **Exactly one `main`, one `header`, no nested landmarks.** The launcher, menus and dialogs
  render in overlays outside the landmarks.
- **Skip link** ("Skip to content"): visually hidden until focused; activating it focuses `main`
  (WCAG 2.4.1). It sits before the wordmark in both directions.

#### §5.3 Focus rules

| Event | Focus goes to |
|---|---|
| Route path change | the page title (0024 §4.4) |
| Launcher opened by a click or focus on the field | the search input |
| Launcher opened by `Mod+K` | the search input; the previously focused element is remembered |
| Launcher closed by Escape or an outside click | the remembered element, else the trigger (Menu button, search icon) |
| Launcher item chosen | the new page's title (route change) |
| Menu, popover, dialog closed | its trigger (0005, BE C.10) |
| A pin removed from the pinned bar | the next pin, else the previous, else the pin control |
| A banner appears | nowhere (0028 announces it) |

#### §5.4 Print and reduced motion

- `@media print`: the header and aside are `display: none`; `main` becomes `overflow: visible`
  with `block-size: auto`, so the page prints in full.
- No shell surface animates (rule 2B): the launcher, menus, popovers and the full-screen launcher
  appear in the frame of the click. The job ring in the bell is 0028's and stops under
  `prefers-reduced-motion`.

#### §6.2 The tenant picker (`/tenants`)

```text
│  Banan AE                                    Last used                    [Connect] │
```

  `GET /bff/user`). Cached → the list renders in the first frame and revalidates in the

- **Heading** `h1` "Choose a tenant" (`[tmPageTitle]`), `document.title` "Tenants · {displayName}".
- **Rows** (`ul`, one `li` per membership):
  - **Name** in the active language: the position in the tenant's `languages` whose language

  - **Second line:** the other non-empty names, each in a `span` with its own `lang`, joined by

    brief asks.
  - **Badges** (`tm-badge`): Sandbox (accent), Read-only (warning), Suspended (error), Being set up

  depends on recency, so rows do not move between visits (rule 2D).

  It filters on every keystroke (`value`, not the debounced output) over every name and the id,
  with §9.4's normalizer, and writes `?q=` with `replaceUrl`; `?q=` pre-fills it. Enter in the
  field follows the only enabled match when exactly one remains. A sandbox matches through its
  own names; its live parent stays visible as a context row (dimmed) when only the sandbox
  matches. No match: "No tenants match “{q}”."
- **Notice.** `?notice=tenant-not-found&from=17` (N24 §11) shows an info `tm-alert` above the
  list: "You can no longer open {name}." when tenant 17 is in the cached list, else "You can no
  longer open tenant 17." The alert is `role="status"`; dismissing it removes both parameters
  (`replaceUrl`).
- **Empty.** No memberships: `tm-empty-state` "You're not a member of any tenant yet" / "Ask
  your administrator to invite you. You're signed in as {email}." with a Sign out button (the
  wrong account is the usual cause).
- **Errors.** `/bff/user` fails with nothing cached → `tm-error-state` from
  `TmErrorPresenter.describe(error, { kind: 'read' })` with Retry. With a cached list, a failed
  revalidation shows nothing.
- **Never redirects**, even with one membership (A§8); `/` is the redirect.
- **`Mod+K`** on this page focuses the search field when it shows (a page-scope shortcut).
- **Page context** (0026): `custom`, route template `/tenants`, title "Choose a tenant",
  `state { count, query }`, `visible` with the columns Name and Id over the shown rows (≤ 200).

#### §7.3 Back and forward in installed mode

- **Installed mode** is `matchMedia('(display-mode: standalone), (display-mode: fullscreen),
  (display-mode: window-controls-overlay)')`, or `navigator.standalone === true` (iOS home-screen
  apps, which report `fullscreen` or nothing reliable); a `change` listener follows installs.
  `minimal-ui` shows the browser's own buttons, so it is not installed mode.
- **Buttons.** "Back" (`arrow-left`) and "Forward" (`arrow-right`), both `mirrorInRtl`, right after
  the grouped control. Native `disabled` when the history cannot move that way.
- **State.** With the Navigation API (Baseline January 2026): `navigation.canGoBack` /
  `canGoForward`, re-read on `currententrychange`; clicks call `navigation.back()` /
  `forward()`. Without it (Safari before 26.2): an in-memory depth counter of the router's
  `NavigationEnd` events — push +1, `popstate` back −1 and forward +1 — enables Back when depth
  > 0 and Forward after a Back until the next push. A reload resets the counter (Back disabled
  until the next navigation; the browser keeps the real history).
- **Query-only history** follows 0030's rule (A§8: query changes replace, page changes push), so
  Back never steps through keystrokes.

### §8 The pinned bar and the pins model

The pinned bar is the user's own navigation: pages and folders of pages they pinned, in their
order, one click away. The shell owns the pin control, so no page writes pinning code.

#### §8.1 Anatomy

```text
≥ md:  [Sales invoices] [Customers]̲ [Trial balance] │ [Month end ▾] [··· More]              [📌]
< md:  (Customers) (Sales invoices) (···)                                                 [📌]
```

- **Row:** 32 px, `--ink-800`, `padding-inline` 8, hairline top border; `nav aria-label="Pinned
  pages"`.
- **Pin chip** (≥ `md`): 24 px, `padding-inline` 9, radius 6, 12 px, `#C6D4D8`; hover fill `.08`;
  the current page's pin is full height, 500 weight, teal-300 text with a 2 px block-end bar,
  `aria-current="page"`. Text truncates at 200 px with the full label as tooltip.
- **Folder chip:** label + `chevron-down`, after a 1 × 16 px separator before the first folder;
  a menu button (§8.8).
- **More** (`ellipsis` + "More"): shows when items overflow (§8.7).
- **Pin control** at the inline end: `pin` icon (filled `pin` when the current page is pinned),
  24 px; tooltip and accessible name "Pin this page" / "Edit pin"; `aria-keyshortcuts`
  `Alt+Shift+P`.
- **Below `md`:** at most two rounded chips (24 px pill, 11.5 px; current chip teal tint with a
  teal-400 border), the current page's pin moved first, then More; the control stays.
- **Empty:** "Nothing pinned yet. Use the pin button to pin this page." (12 px, muted); below
  `sm` only "Nothing pinned yet."

#### §8.2 The pins model

```ts
interface TmPinsDoc { readonly v: 1; readonly items: readonly TmPinItem[] }   // value of nav.pinned (curated)
type TmPinItem = TmPin | TmPinFolder;
interface TmPin {
  readonly id: string;                  // 8 base32 characters, client-generated
  readonly url: string;                 // tenant-relative, no leading slash: 'centers?f.CenterType=in:Service'
  readonly title: string;               // the page's title when pinned, in that language (≤ 80)
  readonly label?: string;              // the user's own name (≤ 40); wins over every derived label
}
interface TmPinFolder { readonly id: string; readonly folder: string; readonly items: readonly TmPin[] } // folder: its name (≤ 40)
declare const tmPinsKey: TmPreferenceKey<TmPinsDoc>;          // 'nav.pinned', curated, fallback { v: 1, items: [] }
declare const tmPinnedBarVisibleKey: TmPreferenceKey<boolean>; // 'nav.pinnedBarVisible', curated, fallback true
```

**Example —** the stored value:

```json
{ "v": 1, "items": [
  { "id": "k3j7q2m9", "url": "sales-invoices", "title": "Sales invoices" },
  { "id": "x1ba7hd2", "url": "customers?f.CustomerType=in:Corporate", "title": "Customers", "label": "Corporate customers" },
  { "id": "p0d9wqlm", "folder": "Month end", "items": [
    { "id": "z8rt5nb3", "url": "reports/acme-aging", "title": "Aging" },
    { "id": "vj4e2fhd", "url": "reports/42", "title": "Monthly sales by region" } ] } ] }
```

- **Per tenant** (the bag lives in the tenant database, 0014 §3.4). URLs are tenant-relative, so
  copying pins between a live tenant and its sandbox needs no rewrite (a later "copy pins"
  feature stays trivial).
- **What a pin captures:** the routed URL's path after `/{t}/` plus its query, minus `page` (the
  codec's paging parameter, N24 §9.5). Search filters, columns, order, `view` and a details
  `?child=` stay. Edit mode is never in a URL (A§8), so a pin always opens view mode.
- **Not pinnable:** the tenant home (`/{t}`; the wordmark is its link), `…/new` create pages, the
  drill-through list (`/{t}/list/…`, its free-form filter is the report's), tenantless routes. There
  the pin control is disabled with the tooltip "This page can't be pinned".
- **Caps** (decision 12): 30 pins in total, 10 folders, one folder level, `url` ≤ 512 characters.
  At the cap the pin control shows the tooltip "You've pinned 30 pages. Unpin one to add another."
  and does nothing; the stored value stays under 32 KB with worst-case labels.
- **Validation on read.** `tmPinsKey`'s `validate` (N25 §9.1) checks the shape, ids, lengths, caps
  and one level; an item that fails is dropped from the view (the stored value is kept until the
  next write rewrites it); a document that fails as a whole reads as the fallback and emits
  `tm.prefs.invalid` (0025).
- **Defaults.** None in v1: a user without the key starts with an empty bar (decision 13). An
  administrator holding `core.User × Preferences` can set a user's `nav.pinned` through
  `users/preferences/set` (0018); this spec ships no UI for it.

#### §8.3 Resolving a pin

Each pin resolves on render through `TmUrls.describe('/' + t + '/' + url)` (0024):

| Match | Label (first that exists) | State |
|---|---|---|
| `TmNavigation.byHref(path)` finds an entry and the URL has no query | `label`, the entry's localized label, `title` | `ok`, or `no-access` when the entry is hidden by permissions |
| entity search or details page | `label`, `title` | `ok` when `TmPermissions.can(entity, 'Read')`, else `no-access` |
| `tmPage`, coded report, core page | `label`, `title` | per its `securable` or `requires` |
| no route matches (the entity, page or report is gone) | `label`, `title` | `unavailable` |

- **Icons:** none on chips (the design draws text-only pins); the Manage pins dialog shows the
  entry's or the kind's icon.
- **Current pin:** the pin whose path and query equal the routed URL's (minus `page`); else the
  pin with the same path and no query. At most one chip is current.

#### §8.4 `TmPins`

- **Every mutation** computes the next document, calls `TmPreferences.set(tmPinsKey, doc)` (the

- **Home page** (0035) may render `TmPins.items`; it is the only other consumer.

#### §8.5 Pinning the current page

1. The user clicks the pin control (or presses `Alt+Shift+P`) on an unpinned page.
2. `TmPins.pinCurrent()` appends the pin: the chip appears at the end of the top level (or in
   More) and the control turns filled, in the click's frame.
3. A popover (`tm-popover` size `sm`) opens anchored to the control: title "Pinned", a name field
   (pre-filled with the label, selected), a folder select ("No folder", the folders, "New folder…"
   which reveals a name field), buttons Remove and Done. Enter or Done applies; Escape or an
   outside click keeps the pin as created. Focus returns to the control.
4. On a pinned page the same control opens the same popover titled "Edit pin". `Alt+Shift+P` on a
   pinned page unpins it at once and announces "Unpinned {label}".

- **Feedback** when the bar is hidden or the pin went into More: the polite announcement "Pinned
  {label}" (and, below `md`, the same text as a 0023 toast in the acting tab; request to 0028's
  toast policy).

#### §8.6 Keyboard and ARIA

- **One tab stop** (decision 14): the bar is a list (`ul role="list"`) of links inside the `nav`,
  with a roving `tabindex`. Tab enters on the current pin, else the first; Left and Right
  (direction-mapped through the live `Directionality`) move; Home and End jump; Enter follows a
  link (Ctrl or ⌘ and middle-click open new tabs natively); on a folder chip Enter, Space and
  Down open its menu. Tab leaves to the pin control (its own tab stop).
- **Context menu** (0004's `tmContextMenuTrigger`: right-click, the Menu key, a long press) on a pin: Rename…, Move to › (No
  folder, folders, New folder…), Open in new tab, Unpin, Manage pins…. On a folder chip: Rename…,
  Remove folder, Manage pins…. Rename opens §8.5's popover.
- **Announcements** (`LiveAnnouncer`, polite): "Pinned {label}", "Unpinned {label}", "Moved
  {label} to {folder}", "Moved {label}, position {i} of {n}".

#### §8.7 Overflow

- **Measured, not breakpoint-driven.** A `ResizeObserver` on the bar and changes to the items
  recompute how many leading items fit beside More and the control, from widths measured once per
  label set in an offscreen copy (`visibility: hidden`). It never recomputes on hover, focus or the
  current page changing (rule 2D).
- **More** is a menu button listing the hidden items in order: pins as link items, folders as
  submenus (BE C.10), a disabled lock row for revoked pins, then a separator and "Manage pins…".
- **The current pin in More** marks the More chip with the current styling and gives the item
  `aria-current="page"`.

#### §8.8 Folders

- **A folder chip** opens a `tm-menu` of its pins as link items (label, a lock for revoked ones),
  then a separator and "Manage pins…". An empty folder shows "No pages in this folder".
- **One level only:** the model has no folder inside a folder, and every UI that moves a pin offers
  "No folder" or a folder, never a folder in a folder.
- **Creating** a folder: "New folder…" in §8.5's popover, the context menu, or the dialog; names
  are trimmed, 1–40 characters, unique case-insensitively per user ("A folder with this name
  exists").

#### §8.9 Drag to reorder

- **Pointer path.** Pins and folders in the bar are `tmDragSource`s with the payload kind
  `tm.pin` (0023 `drag-drop`). A 2 px accent line marks the insertion point between chips; a
  folder chip highlights as a drop target and opening it on hover (500 ms) lets the user drop at a
  position inside. Dropping calls `TmPins.move`.
- **From the launcher:** launcher rows are `tmDragSource`s with kind `tm.page` (`{ url, title }`);
  dropping one on the bar pins it at that position. The pinned bar stays live while the launcher is
  open (§9.1), so "pin it from the launcher" works by dragging.
- **The non-drag path** (WCAG 2.5.7) is the Manage pins dialog (§8.10) and the context menu's
  "Move to".

#### §8.10 The Manage pins dialog

- `TmModal` size `md` (full screen below `sm`), title "Manage pins", deferred chunk.
- **Body:** a `tm-reorder-list` of the top-level items (0023: handle with the grab, move, drop
  keyboard model, Alt+Up/Down). A folder row shows its name, a count and an expand toggle; expanded,
  it holds its own `tm-reorder-list` that `accepts` `tm.pin`, so pins drag between the top level
  and folders. Each row: icon, label (`dir="auto"`), a "Rename" icon button (an inline text field),
  a "Move to" menu, a "Remove" icon button. Revoked rows show the lock and "No access".
- **Footer:** "New folder" (start), Cancel, Save. A switch "Show the pinned bar" above the
  footer (`nav.pinnedBarVisible`, applied at once).
- **Working copy:** edits change a copy; Save calls `TmPins.replace(copy)` (one curated write);
  Cancel or Escape discards. A pin change arriving from another tab while the dialog is open is
  overwritten on Save (last writer wins, as 0025 sets keys).

#### §8.11 Hiding the bar

- `nav.pinnedBarVisible = false` sets `--tm-pinned-bar-height: 0px` (main grows by 32 px) and
  removes the `nav` from the DOM. Toggled from the session menu (§10) and the dialog.
- **Without the bar** the launcher's browse state shows a "Pinned" band first (as below `md`), with
  the option "Pin this page" (or "Edit pin") at its start and "Manage pins…" at its end;
  `Alt+Shift+P` still pins.
- **Per tenant** like every preference; a default user sees the bar.

#### §8.12 Revoked and unavailable pins

- **`no-access`:** the chip renders dimmed with a `lock` icon and stays focusable; activating it
  opens a menu with the note "You no longer have access to this page." and Unpin. It is never a
  link, so it never navigates to a 403.
- **`unavailable`:** the same with "This page no longer exists."
- **The pin is never removed automatically:** access can come back with a role edit.

### §9 The launcher and global search

The launcher is one overlay with two states. Empty, it browses: recently visited pages, then
every section. Typed, it lists matching pages at once and, later, other providers' buckets below
them. It never navigates on its own, never waits on the network for pages, and keeps its text.

#### §9.1 Surfaces

| Width | Opened from | Surface | Its input |
|---|---|---|---|
| ≥ `lg` | Menu button, the app-bar field (focus or click), `Mod+K` | overlay panel below the shell rows, full width | the app-bar field |
| `md` | Menu button, the search icon, `Mod+K` | the same overlay panel | a field at the top of the panel |
| < `md` | Menu icon, search icon, `Mod+K` | `TmModal` size `lg` (full screen below `sm`), labelled "Menu" | a 44 px field in the modal header, with Close |

- **The overlay panel** is a `popover="manual"` element (top layer) at
  `inset-block-start: var(--tm-shell-top)`, inline 0 to 0, `max-block-size: calc(100dvh -
  var(--tm-shell-top) - 24px)`, card surface, `--shadow-lg`; its body scrolls and the footer stays.
  A scrim (`rgba(0,23,34,.34)`) covers the page below the shell rows only, so the app bar and the
  pinned bar stay live (shell research D2): a pin click navigates and closes the launcher.
- **Below `md`** the Menu icon opens the modal with focus on Close (no on-screen keyboard pops up
  for browsing); the search icon opens it with focus in its field.
- **The Escape stack:** opening pushes `tmPushEscapeDismissal` (BE D.1); Escape closes the
  innermost layer first.

#### §9.2 State and transitions

```ts
declare class TmLauncher {                               // @tellma/core/shell, root
  readonly state: Signal<'closed' | 'browse' | 'typed'>;
  readonly query: Signal<string>;                        // kept across close and navigation in this tab
  show(via: 'menu' | 'field' | 'shortcut' | 'icon'): void;
  close(reason: 'escape' | 'outside' | 'tab' | 'chosen' | 'route'): void;
  setQuery(text: string): void;
}
```

| Event | Empty text | Text present |
|---|---|---|
| Menu click, field focus or click, `Mod+K` | open in browse; focus the input | open in typed; select all the text; show the cached results |
| Typing | browse → typed | results update on every keystroke |
| Clearing the text | typed → browse | — |
| Menu click while open | close | close |
| `Mod+K` while open | focus the input and select the text | same |
| Escape, outside click | close; the text stays | close; the text stays |
| Tab | close; focus moves on | same |
| An option chosen | navigate (§9.5), close; the text stays | same |
| Any route change, tenant switch, a dialog opening | close; a tenant switch also clears the text | same |

- **The text survives** Escape, outside clicks and navigation within the tab, and is reselected on
  the next open, so typing replaces it and Enter repeats the last choice (decision 7). It never
  reaches storage or telemetry.

#### §9.3 Browse state

Top to bottom:

1. **Pinned band** — only below `md` or when the pinned bar is hidden (§8.11): heading "Pinned",
   pin chips in order (a folder's pins carry the folder name as their description), the command
   option "Pin this page" or "Edit pin" first and "Manage pins…" last.
2. **Recently visited band** — heading "Recently visited", up to ten chips from `TmRecents.pages`
   (0025; title and icon from the matching entry, N25 §13); hidden when empty.
3. **Sections** — `TmNavigation.sections` as columns: one below `md`, three at `md`–`lg`, four at
   ≥ `xl`, balanced with CSS columns (`break-inside: avoid` per section). A section heading shows
   its icon (14 px) and label (12 px, 600, underline rule); entries are 13 px links, `min-height`
   22 px (44 px below `sm`). A pinned entry shows a `pin` glyph at its inline end ("pinned" in its
   accessible name).
4. **Footer** (≥ `md`): "Type to search · ↑↓ to move · Enter to open · Esc to close" in the subtle
   fill; `aria-hidden`, because the input's description carries the same instructions.

- The current page's entry is shown in the selected style (teal tint and inline-start marker) but
  is not the active option until the user moves.

#### §9.4 Typed state: matching and ranking

**Normalization** (`tmSearchNormalize`, used by the launcher and the picker):

1. NFKD, then remove Latin, Greek and Cyrillic combining marks (U+0300–U+036F) and Arabic marks
   (U+064B–U+065F, U+0670, U+06D6–U+06ED); lower-case (`toLowerCase`).
2. Arabic letters: remove tatweel (U+0640); أ إ آ ٱ → ا; ى ی ئ → ي; ة → ه; ؤ → و; ک → ك.
3. Arabic-Indic and Extended Arabic-Indic digits → 0–9.
4. Punctuation and symbols → space; collapse spaces; trim.
5. Word variants for the index only: an Arabic word starting with "ال" and longer than three
   letters also indexes its remainder ("العملاء" also as "عملاء").

**Candidates and their terms:**

| Candidate | Terms (source rank) |
|---|---|
| every visible `TmNavItem` | label in the active language (0); its synonyms (1); label and synonyms in English and in each other language of `TmLocalization.languages()` (2) |
| every `ok` pin not identical to an entry | its `label`, its `title` (0) |
| every recent page not identical to an entry or a pin | its title (0) |

**Match classes** for a normalized query `q` split into tokens (at most five):

| Class | Rule | Example (`q` → term) |
|---|---|---|
| A | the term equals `q` | "customers" → "Customers" |
| B | the term starts with `q` | "cust" → "Customers" |
| C | every token is a prefix of a different word of the term, any order | "inv sal" → "Sales invoices" |
| D | every token of two or more characters occurs in the term | "voice" → "Sales invoices" |

- **Order:** class, then source rank, then recency (the candidate's position in recents, else
  last), then section order, entry order and the localized label (`Intl.Collator`).
- **A candidate's best term** decides its class. Up to 50 rows; the first row is active, so Enter
  opens the top match (the design's "↵ Enter" hint sits on the active row).
- **Create rows.** Right after an entity row of class A–C whose `createHref` is set, a row
  "{entity} · Create" (`plus` icon, the entity's singular label) links to `/{t}/{segment}/new`; at
  most three per query.
- **Row anatomy:** icon, label (the part matching a class A or B term is wrapped in `<mark>`),
  description = the section's label (muted, 12 px); 28 px rows, `padding-inline` 14.
- **No match:** "Nothing matched “{q}”." under the Pages heading, then provider buckets as usual.
- **Example —** Farah works in Arabic and types "inv":

| Row | Why |
|---|---|
| Invoices to chase (her pin) | class B on its own label, source 0 |
| فواتير المبيعات (Sales invoices) | class C on the English label, source 2; visited recently |
| فاتورة مبيعات · إنشاء (create row) | follows its class C entity row |
| فواتير المشتريات (Purchase invoices) | class C, source 2; not in recents |

  Typing "فوات" instead matches both Arabic labels at class B, source 0.

#### §9.5 Keyboard and ARIA

- **Roles.** The input is `role="combobox"` with `aria-expanded`, `aria-controls` (the listbox),
  `aria-autocomplete="list"`, `aria-activedescendant`, `aria-describedby` (the visually hidden
  instructions), `aria-keyshortcuts="Control+K"` (or `Meta+K`). The panel body is one
  `role="listbox"`; each band, section and bucket is a `role="group"` labelled by its heading; every
  row is `<a role="option" href>` with `aria-selected="true"` on the active one. DOM focus stays in
  the input (decision 6, APG combobox).

| Key | Browse | Typed |
|---|---|---|
| Down, Up | next, previous option across bands and sections in reading order; from none, Down = first, Up = last | the same over result rows |
| Right, Left (direction-mapped; only while the input is empty) | in a band: next, previous chip; in sections: the same index in the next, previous section (clamped) | move the caret |
| PageDown, PageUp | first option of the next, previous group | the same |
| Home, End | first, last option | move the caret |
| Enter | open the active option in this tab (`Router.navigateByUrl(href)`; a command option runs) | same |
| Mod+Enter, Shift+Enter | open the active option in a new tab (`window.open(href, '_blank', 'noopener')`) | same |
| Escape | close, keep the text | same |
| Tab | close | same |

- **Pointer:** hovering a row makes it active; a click navigates; Ctrl, ⌘ and middle-click open new
  tabs natively (the rows are links).
- **Announcements** (polite, 500 ms after the last keystroke): "{n} pages", "Nothing matched",
  and once per provider answer "{bucket}: {n} results".
- **RTL:** the panel and its columns mirror; Left and Right read the live direction at keydown;
  the footer's ↑↓ glyphs need no mirroring.

#### §9.6 The provider seam

```ts
interface TmLauncherItem {
  readonly id: string;                                    // unique within the provider
  readonly label: string; readonly description?: string;  // localized, as displayed: 'INV-2026-0431', 'Rawabi Trading · AED 12,400'
  readonly icon?: string;
  readonly href: string;                                  // a canonical in-app URL (TmUrls)
}
interface TmLauncherSearchContext {
  readonly tenantId: number; readonly language: string; readonly limit: number; // limit: 5
  readonly signal: AbortSignal;                           // aborted by the next keystroke, close, navigation
}
interface TmLauncherProvider {
  readonly id: string;                                    // 'records', 'settings', 'help'; kebab-case
  readonly labelKey: string;                              // the bucket heading
  readonly order: number;                                 // > 0; Pages is 0
  readonly minLength?: number;                            // normalized characters; default 2
  search(query: string, context: TmLauncherSearchContext): Promise<readonly TmLauncherItem[]>;
}
declare const TM_LAUNCHER_PROVIDERS: InjectionToken<readonly TmLauncherProvider[]>; // multi
```

- **Timing.** Pages recompute on every input event (`TmSearch.value`); providers run on the
  debounced `search` output (50 ms sliding, held keys wait, N23 §3.6), each with its own signal,
  aborted when superseded (rule 2C).
- **Placement.** Buckets render after Pages in `order`. While a provider runs, its bucket shows a
  one-row placeholder "Searching {bucket}…" (reserved height); results replace it in place, so the
  active row (always in Pages first) never moves. An empty answer removes the bucket.
- **Failure.** A rejected search shows "{bucket} search failed. Pages are still listed." with a
  Retry option; `cancelled` shows nothing. Telemetry `tm.launcher.provider-failed { provider,
  kind }`.
- **Registration** is the feature's `providers` (the "anything Angular" hatch, A§3.6). v1 ships no
  provider; the records, settings and help specs add theirs.
- **Reserved:** an Actions provider over `TmPageContexts.top().actions()` with origin `launcher`
  (N26 §9.4) is the intended first consumer (review flag 7).

#### §9.7 Caching

- **Page results** are memoized for the last 20 normalized queries, keyed by language and the
  navigation registry's version; reopening with the same text costs nothing.
- **Provider results** are kept in an LRU of 20 entries per provider, keyed by tenant, language and
  normalized query, for 2 minutes; a reopen inside that window shows them at once and does not
  refetch.
- **Memory only**, per tab; cleared on tenant switch and when the session ends.

#### §9.8 Loading

- **The panel and the index** live in a deferred chunk, prefetched at idle after first render (a
  worker-cache read once installed), so the first open renders in the click's frame. If the user
  is faster, the panel opens with a final-geometry skeleton of the bands and columns.
- **The index** builds on first open from the registry (≈ 300 entries in under 5 ms, pinned by a
  benchmark test) and rebuilds when the registry, the language or the pins change.
- **Other languages' labels** load at idle after the first open through `TmLocalization.load(code)`
  (request to 0024, a worker-cache read); until then the index holds the active language and
  English, which boot already loaded (N24 §7.3).
- **Preloading.** Hovering or keyboard-activating an option calls `TmUrls.preload(href)`.

### §12 Server additions

#### §12.1 `users/me/locale`

The session menu's language and calendar switches persist through one cheap action instead of
`me/save`'s three round trips and its stamp (A§6.1). It is written into 0018 (edit E1).

```csharp
// Tellma.Core.Abstractions.Access
public sealed record MeLocaleRequest(string? Language, string? Calendar);      // null member = unchanged; at least one is set
public sealed record MeLocaleResult(string? PreferredLanguage, string? PreferredCalendar,
    DateTimeOffset ModifiedAt, string PreferencesTag);                            // the stored values, the row's new stamp, the caller's tag

// Tellma.Core.Users — UserService<TUser>
[ApiAction("me/locale", MemberOnly = true)]                                      // POST /{tenantId}/api/web/users/me/locale; a write, never retried
public Task<MeLocaleResult> SetMyLocaleAsync(MeLocaleRequest request);
```

1. **Validation in memory** (422, 0018 §3.2's codes): both members null → `Users.LocaleEmpty` at
   `language`; `Language` not `ILanguageCatalog.IsOffered` → `Users.LanguageNotOffered` at
   `language`; `Calendar` not in `ICalendarRegistry.Codes` → `Users.CalendarUnknown` at `calendar`.
   A calendar outside the tenant's pair is accepted (negotiation ignores it, 0013 §9).
2. **One `Persist` batch** through `IGuardedBatchRunner`: `IAccessGuards.ContributeLock`, then 0012
   §9.1's `Update<TUser>` by ids (`[@tm_UserId]`) assigning only the members that are set, with
   stamps, then `ContributeInvariants` (0014 §8.3 applies to every persist touching `core.Users`),
   then `SELECT [PreferredLanguage], [PreferredCalendar], [ModifiedAt] FROM [core].[Users] WHERE
   [Id] = @tm_UserId`. `User`'s `[BumpsUserVersionTag(Preferences, "Id")]` bumps the caller's
   `PreferencesTag` in the epilogue (0014 §8.1).
3. A value equal to the stored one writes no history row and moves neither the stamp nor the tag
   (0012 §9.1 skips unchanged rows); the result still answers the current values and tag.
4. **One round trip** (0018 §8.1 row). A read-only tenant answers `403 tenant-read-only`; the
   client keeps the switch for this device (N24 §7.2).

**Example —**

```json
POST /17/api/web/users/me/locale     { "language": "ar" }
200  { "preferredLanguage": "ar", "preferredCalendar": "uq", "modifiedAt": "2026-10-20T11:02:41.1730000+00:00",
       "preferencesTag": "7f3c9a…" }
```

- **The client adopts the result** (N25 §9.5): under the sync lock it patches the stored `me` —
  `User.PreferredLanguage`, `User.PreferredCalendar`, `PreferencesTag`, `Tags.preferences` — so no
  tab syncs for its own write (request to 0025).
- **Moving `ModifiedAt`** means a My profile form opened before the switch meets 0031's conflict
  dialog on save instead of silently restoring the old language (decision 21).

#### §12.2 `DistributionInfo.links`

Written into 0011 §5.9 and §8 (edit E2), beside 0024's `identity.accountUrl` and 0026's `support`.

```csharp
// Tellma.Core.AspNetCore — DistributionInfo gains one member
```

## 12. Challenges to the architecture

1. **`/shell` cannot be "eager" under A§2.2's own import rule.** The primary imports no other entry
   point and the distribution imports only the primary and its packs, so nothing statically pulls
   `/shell` (or `/attention`, which only `/shell` imports) into the initial bundle. Followed as:
   the route table loads the shells through `import()`, preloaded by the build; warm launches read
   the chunk from the worker cache. Proposed A§2.2 text: "the primary's route table and its loader
   tokens may reference other entry points through `import()`; `tellma-client build` preloads
   `/shell` and its static imports." The same sentence answers N25 challenge 8 (`TM_REALTIME`).
2. **`TmShellSlot.badge?: Signal<number | null>` (A§5.11) cannot be built in a declaration.**
   Declarations are module-level constants (A§3.4), where `inject` is unavailable. Completed as
   `badge?: () => Signal<number | null>`, called once in the shell's injection context.
3. **A§5.1 lists only two core sections** (`administration`, `analysis`). Notifications,
   Assignments, My profile and Notification settings then have no browse home. Followed: they are
   search-only entries (§3.2). Alternative: a third core section `personal` ("My work").
4. **`TmNavEntry` needs two completions** (A§5.11): `section` optional (search-only entries) and
   `requires` accepting several securables (the Settings entry is visible when any category is
   readable). Both are additive.
5. **A§5.11 puts `help` and `assistant` between the tray and the session button; the brief lists
   them before the bell** ("The tenant shell" list). Followed the skeleton. Low stakes; flagged so
   the brief and the skeleton agree.
6. **A§3.6's menu hatch** ("redeclare sections or entries in `overrides`; `hide: ['core.roles']`")
   does not match N24 §2.3, where `overrides` take entity keys only and `hide` keys are
   kind-qualified. Followed N24: a section or entry is changed by `hide: ['section:…']` or
   `['entry:…']` and a redeclaration under a new id (§2).
7. **A§9 `xl` "pins overflow into More below this"** reads as a breakpoint rule; overflow depends
   on label lengths per language. Followed as measured overflow (§8.7); the design's frames agree
   at their widths.
