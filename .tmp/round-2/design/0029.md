## 2. Decisions

1. **One entity model, emitted at build, tenant-independent** (§2). The emit writes every Queryex
   root (stacks, child entities, read-only roots) once; `TmEntities` gates `Name2`/`Name3` by the
   tenant's shape at run time. Alt: a per-tenant metadata route (network on warm launch; A§5.2
   rejected it).
2. **Label keys are resolved at emit, not in the browser** (§2.4). The emit walks 0013's fallback
   chain (declaring assembly → bases → Core's bare key) and writes the first key that exists, or a
   humanized English `labelFallback`. Alt: the client re-implements the chain (it cannot: the pack
   is flat, so it does not know which assembly declared a key).
3. **The display-name rule is metadata, rendered identically on both sides** (§5). Server
   `[DisplayNameSource(property, Prefix?)]`; one template key `Entity_DisplayNameWithPrefix` in
   Core's `Strings`; a shared golden pins TS and C#. Alt: a client-only `displayName` function on
   `tmEntity` (the server needs the same text for Excel, MCP, notifications and conflict messages);
   a template language (A§10.1 rejected it).
4. **Paths are PascalCase C# names; values are the wire's camelCase objects** (§4.1). Queryex,
   declarations, URLs and label keys use `CreditLimit`; entity objects from `get`/`save` stay
   `creditLimit` with no conversion; every property descriptor carries both. Alt: convert every
   response to PascalCase (a recursive rename per response; two shapes on the wire side of tests).
5. **Column keys extend A§8's navigation rule to multilingual groups** (§6.1). A key ending at a
   navigation shows its display name; a key ending at a group anchor (`Name`, `Parent.Name`) shows
   the active content slot with fallback; twins (`Name2`) show that slot verbatim. Alt: anchor =
   slot 1 verbatim (then the common column `Name` shows English to Arabic users).
6. **Unreachable or unknown column keys are dropped from the plan, never sent** (§6.4). A shared
   URL or a stale preference can then never 403 the whole query. Alt: send and show the 403 (the
   brief's column-editor concern, A§4.3).
7. **Filters on a multilingual display column match every admitted slot** (§13.2). The same URL
   gives the same rows in every UI language. Alt: match the active slot only (a shared link would
   change meaning with the reader's language).
8. **The client Queryex is a lexer, a printer and a builder; no parser** (§8). Lexing gives instant
   highlighting, parameter detection and safe insertion; `queryex/discover` is the one authority
   for syntax and binding errors. Alt: a TS parser (a second grammar implementation to keep in
   step with frozen 0008, for errors that arrive 250 ms later anyway).
9. **`queryex/discover` compiles exactly as the pipeline would and reports the traversal rule as a
   diagnostic** (§9). An editor sees, before running, every error `query` would return, plus
   `Query.PathNotReachable` where `query` would answer `403`. Alt: `Discover` only (no binding
   errors); per-clause `Validate` (misses cross-clause checks such as QX4005).
10. **Drop-at-caret uses the textarea's native text drop** (§10.4). The 0023 drag payload already
    writes `text/plain`; the browser places the text at the drop caret, keeps undo, and fires
    `insertFromDrop`, which the editor post-processes. Alt: compute the caret from pointer
    coordinates over a mirror (`caretPositionFromPoint` is Baseline only since December 2025 and
    unspecified for text controls).
11. **The expression editor is a native `textarea` over a highlighted mirror** (§10.3). Native
    editing, IME, undo and screen-reader behaviour come for free. Alt: `contenteditable` (caret,
    IME and undo bugs) or a code-editor library (budget, Trusted Types, RTL).
12. **The path picker is built from local descriptors; no request ever loads a level** (§11). Alt:
    lazy server calls per expansion (network per click).
13. **Stock pages Q1: one generic picker binding** (§14). `tm-entity-field entity="gl.Center"` and
    the same binding in grid cells, driven by the target's descriptor; per-entity tweaks in the
    declaration's `picker` member. Alt: one picker component per entity (N components that drift).
14. **Cacheable targets search in memory** (§14.2). `TmLaunchCache.entitySet` already holds the rows;
    results are synchronous, so the picker shows no spinner and works offline. Alt: always query.
15. **`TmEntities` is split: summaries eager, descriptors after `load()`** (§4). The Core chunk
    carries name, segment, label keys, operations, capabilities and the display-name rule, which
    the shell, launcher, bell and route matching need before `/entity` loads. Alt: the Entities
    chunk at boot (A§5.2 loads it with `/entity`).
16. **Typing comes from the entity-name literal, not a type argument** (§15). The emitted
    `tellma-entities.d.ts` augments `TmEntityShapes`; `tmEntity('acme.Customer', …)` checks its
    paths with no type argument. Alt: `tmEntity<AcmeCustomer>(…)` (challenge 1).
17. **Instants and wall-clock date-times are read-only in v1 forms** (§12.2). No date-time picker
    exists (0005 non-goal, 0023 does not add one); every platform instant is server-owned. Alt: a
    date-time picker in 0023.

## 3. Design (the future spec's sections)

### §1 Placement and vocabulary

- **`@tellma/core` primary** (eager, budget share ≤ 6 KB gzip): `tmEntity` and the declaration
  types, `TmEntities` (summaries, `load()`, descriptors), `TmDisplayNames`, `TmPermissions`, the
  display-name renderer, `TM_ENTITY_DECLARATIONS`, `TM_ENTITY_PAGES`. Folder
  `client/projects/core/tellma-core/src/entity/`.
- **`@tellma/core/entity`** (lazy, shared by `/search`, `/details`, `/reports`; budget 28 KB gzip):
  `tmSelectPlan`; the Queryex client (`tmQxLex`, `tmQx`, `tmQxPrint`, `tmQxParameters`,
  `tmQxInsert`); `injectTmQueryexDraft`; `tm-expression-editor`; `tm-path-picker`; `TmFormats`,
  `tm-value`, `tm-value-editor`, `tmGridColumnFor`; `tm-column-filter` and the filter functions;
  `TmEntityPickers`, `tm-entity-field`, `tm-entity-multi-field`, `TmLazyPickerPage`;
  `tmCheckBlobFile`.
- **Server** (`Tellma.Core`): `EntityClientAssetContributor` and `ClientEntityModel` (namespace
  `Tellma.Core.Client`); `QueryexService` (`[ApiRoute("queryex")]`, namespace `Tellma.Core.Api`);
  `DisplayNames` implementing 0012's `IDisplayNames`. Records in `Tellma.Core.Abstractions.Client`.
- **Testing**: `@tellma/core-testing` gains `tmTestEntities()` (a fixture Entities chunk: Center,
  User, Customer with Contacts, Currency), `TmFakeDiscover`, and the harnesses
  `TmPathPickerHarness`, `TmExpressionEditorHarness`, `TmColumnFilterHarness`,
  `TmEntityFieldHarness`.
- **Vocabulary**
  - *Entity section* — the entity part of the client metadata: summaries in the Core chunk, full
    metadata in the Entities chunk.
  - *Descriptor* — metadata merged with the entity's declaration and gated by the tenant's shape.
  - *Shape* — the tenant's number of content languages, 1–3 (0013 `MultilingualShape`).
  - *Slot* — position 1–3 of a multilingual group (`Name`, `Name2`, `Name3`); the *active slot* is
    `TmLocalization.contentSlot()`.
  - *Display name* — the one-line text that stands for an entity row (§5).
  - *Column key* — a path or expression that a grid-like surface shows as one column (§6.1).
  - *Select plan* — the select, order and filter terms a list of column keys expands to (§6).
  - *Restricted entity* — an entity whose `Read` the user holds with a filter, or not at all
    (0015 §5.2's traversal rule).
  - *Queryex draft* — the clauses under authoring that one discover call checks together (§10.2).

### §2 The entity section of the client metadata

The emit writes one tenant-independent description of every entity the Queryex model knows: a
summary per entity into the eager Core chunk and the full metadata into the Entities chunk. The C#
records serialize exactly to the TypeScript interfaces of §2.2.

#### §2.1 Producer

```csharp
// Tellma.Core.Abstractions.Client
public interface IClientEntityModel                       // singleton; built once from the realised composition
{
    IReadOnlyList<ClientEntityMetadata> Entities { get; }  // ordered by Name, ordinal
    ClientEntityMetadata? Find(string entity);             // ordinal-ignore-case
}
// ClientEntitySummary, ClientEntityMetadata, ClientPropertyMetadata, ClientNavigationMetadata,
// ClientChildMetadata, ClientDisplayNameRule, ClientActionMetadata, ClientEntityLimits and
// ClientBlobKindPolicy mirror the §2.2 interfaces member for member: PascalCase members,
// camelCase JSON through a source-generated context, nulls omitted.

// Tellma.Core.Client — registered by CoreFeature
internal sealed class EntityClientAssetContributor : IClientAssetContributor
{
    // context.Section(Core, "entities", …)      → TmEntitySummary[]
    // context.Section(Entities, "entities", …)  → TmEntityMetadata[]
    // context.File("tellma-entities.d.ts", …)   → §15
}
```

- **Sources.** `IEntityMetadataProvider` (0012 §3.1); `IStackRegistry` (0015 §2.2);
  `IQueryexSchemaProvider.GetSchema(All)` for `queryable`; 0013's `ILabelProvider` key resolution
  (§2.4); 0017's kind registry; the argument-schema generator `tellma_describe` already uses
  (`JsonSchemaExporter`).
- **Which entities.** Every root of the `All`-shape Queryex schema: stacks (`kind: 'stack'`),
  child entities (`'child'`), read-only roots such as `core.Blob` and `core.UserStamp`
  (`'readonly'`).
- **Determinism.** Entities by name; properties in `EntityMetadata.Properties` order; navigations
  in `References` order; actions in `StackDescriptor.Actions` order. The same composition yields
  the same bytes (0024 §3.2).
- **One model for SPA and MCP.** `tellma_describe` renders from `IClientEntityModel` (0016 §11.5
  edit), so the two never describe an entity differently.

#### §2.2 Shapes

```ts
type TmEntityOperation = 'query' | 'details' | 'save' | 'delete' | 'import' | 'export';
type TmDataType = 'string' | 'integer' | 'decimal' | 'float' | 'bool' | 'date' | 'datetime'
  | 'instant' | 'time' | 'guid' | 'enum' | 'node' | 'json' | 'binary';
// integer: int, long, short, byte; date: DateOnly; datetime: DateTime (wall clock);
// instant: DateTimeOffset; node: hierarchyid. float, time, json, binary are never queryable.

interface TmEntitySummary {                       // Core chunk, eager
  readonly name: string;                          // 'gl.Center'

  readonly kind: 'stack' | 'child' | 'readonly';
  readonly labelKey: string; readonly pluralLabelKey: string; readonly labelFallback?: string; // §2.4
  readonly operations: readonly TmEntityOperation[];
  readonly capabilities: readonly string[];       // 0015 §12's closed vocabulary
  readonly displayName: TmDisplayNameRule;        // §5.1: the shell and the bell render names before /entity loads
}

interface TmEntityMetadata extends TmEntitySummary {   // Entities chunk
  readonly key: { readonly property: string; readonly type: 'int' | 'long' };
  readonly owner?: { readonly entity: string; readonly collection: string; readonly parentKey: string }; // children only
  readonly properties: readonly TmPropertyMetadata[];
  readonly navigations: readonly TmNavigationMetadata[];
  readonly children: readonly TmChildMetadata[];
  readonly relatedSelect: readonly string[];      // Id, display-name columns, Code, avatar blobs (0012 §2.5)
  readonly defaultOrderBy: string;                // StackDescriptor.DefaultOrderBy ?? 'Id desc'
  readonly searchable: readonly string[];         // the properties the server's Search covers (0015 §5.2.1)
  readonly naturalKeys: readonly string[];
  readonly tree?: { readonly maxDepth: number };
  readonly actions: readonly TmActionMetadata[];
  readonly extras: readonly string[];             // IDetailsContributor extra names (0031 includes them)
  readonly limits: TmEntityLimits;
}

interface TmPropertyMetadata {
  readonly name: string;                          // 'CreditLimit': Queryex, label keys, declarations
  readonly json: string;                          // 'creditLimit': the wire member
  readonly type: TmDataType; readonly queryable: boolean;
  readonly labelKey: string; readonly labelFallback?: string;
  readonly ownership: 'editable' | 'write-once' | 'server-owned' | 'derived' | 'database-owned';
  readonly nullable: boolean; readonly unique?: true;
  readonly maxLength?: number; readonly precision?: number; readonly scale?: number;
  readonly enum?: {
    readonly name: string;                        // 'gl.CenterType'
    readonly values: readonly { readonly value: string; readonly labelKey: string; readonly labelFallback?: string }[];
  };
  readonly multilingual?: { readonly group: string; readonly slot: 1 | 2 | 3 };
  readonly foreignKeyOf?: string;                 // the navigation this FK backs: 'Parent'
  readonly blob?: TmBlobKindPolicy;               // [BlobReference] (§16)
  readonly excel: boolean;                        // false under [ExcludeFromExcel]
}
interface TmNavigationMetadata {
  readonly name: string;                          // 'Parent'
  readonly foreignKey: string;                    // 'ParentId'
  readonly target: string;                        // 'gl.Center'
  readonly kind: 'reference' | 'owner' | 'sibling'; // owner: child → parent ([ParentKey]); sibling: 0012 [Sibling]
  readonly nullable: boolean; readonly labelKey: string; readonly labelFallback?: string;
}
interface TmChildMetadata {
  readonly name: string; readonly json: string;   // 'Contacts', 'contacts'
  readonly entity: string; readonly parentKey: string; readonly maxCount: number;
  readonly labelKey: string; readonly labelFallback?: string;
}
interface TmDisplayNameRule {
  readonly source: string;                        // a group anchor or a scalar: 'Name', 'SerialNumber', 'Id'
  readonly multilingual: boolean;                 // true when source anchors a [Multilingual] group
  readonly prefix?: string;                       // a scalar shown before the name: 'Code'
}
interface TmActionMetadata {
  readonly name: string;                          // 'invite', 'preferences/set', 'activate'
  readonly kind: 'entity' | 'api'; readonly builtIn: boolean;
  readonly action: string | null;                 // the securable action; null: member-only
  readonly labelKey: string; readonly labelFallback?: string;
  readonly mutation: boolean; readonly idempotent: boolean; readonly destructive: boolean;
  readonly singleTarget: boolean; readonly supportsFilter: boolean;
  readonly arguments?: TmJsonSchema;              // from ArgumentsType or RequestType, JSON Schema 2020-12
  readonly result: 'entities' | 'own' | 'none';

interface TmEntityLimits {
  readonly maxTake: number; readonly countCap: number; readonly maxSkipWindow: number;
  readonly maxSearchLength: number; readonly maxIds: number; readonly maxExtras: number;

```

- **Twins are emitted with their slot**; `TmEntities` drops those the tenant does not admit (§4.2).
- **Enum values are inline per property.** An enum shared by two entities is written twice; both
  copies come from one C# type, so they cannot disagree.
- **Queryex types derive on the client:** `integer`, `decimal` → `Numeric`; `string`, `enum` →
  `String`; `date` → `Date`; `datetime` → `DateTime`; `instant` → `DateTimeOffset`; `bool` →
  `Bool`; `guid` → `Guid`; `node` → `HierarchyId`.
- **Size.** Acme's composition (about 30 entities) emits about 90 KB raw, 12 KB gzip, for the
  Entities chunk and about 4 KB gzip of summaries. Both sit in the worker's `shell` group (A§6.6).

**Example —** one property and one navigation of `gl.Center`, as emitted:

```json
  "labelKey": "Gl_Center_CenterType", "ownership": "editable", "nullable": false,
  "enum": { "name": "gl.CenterType", "values": [
    { "value": "Abstract", "labelKey": "Gl_CenterType_Abstract" },
    { "value": "Service", "labelKey": "Gl_CenterType_Service" } ] }, "excel": true }
{ "name": "Parent", "foreignKey": "ParentId", "target": "gl.Center", "kind": "reference",
  "nullable": true, "labelKey": "Gl_Center_Parent" }
```

#### §2.3 What is deliberately absent

- **Tenant facts**: the shape, language symbols, permissions (launch documents, 0025).
- **UI layout**: default columns, tiles, details layouts (client declarations, §3).
- **Physical names**: tables, columns, store types, `SchemaFingerprint`.
- **Internals**: everything the Queryex schema omits, except `[JsonColumn]` properties, which
  appear with `queryable: false` so a details form can still bind them.

#### §2.4 Label keys

- **Resolution at emit.** For each label the emit asks `ILabelProvider` for the first key of its
  fallback chain that exists in a neutral `Strings.resx` of the composition (0013 §7.6 edit) and
  writes it. When none exists it writes the conventional key plus `labelFallback`, the humanized
  English name, which the client shows in every language. `tellma-client build` prints one
  `label-missing` warning per fallback; it never fails on one.
- **Chains.**

| Label of | Chain |
|---|---|
| property | `<Schema>_<Entity>_<Property>` → base assemblies → Core `<Property>` |
| navigation | `<Schema>_<Entity>_<Navigation>` → the FK property's chain → Core `<Navigation>` (`Parent`, `CreatedBy`) |
| child collection | `<Schema>_<Entity>_<Collection>` → the child entity's `<Schema>_<Child>_Plural` |
| entity, plural | `<Schema>_<Entity>`; `<Schema>_<Entity>_Plural` → the singular |
| enum value | `<Schema>_<Enum>_<Value>` |
| action | `<Schema>_<Entity>_Action_<Name>` → Core `Action_<Name>` (`Action_Activate`, `Action_Deactivate`). `<Name>` is the action name PascalCased with `/` removed: `take-over` → `TakeOver`, `preferences/set` → `PreferencesSet` |

- **Twin labels are computed on the client** (§4.2); the emit writes the primary's key for every
  slot.

### §3 The `tmEntity` declaration

A declaration names an entity and carries only what the metadata cannot know: where it sits in the
menu, what grids show by default, the layout of its details page, and its hatches. Every member is
optional. This section owns the shape; each member's meaning belongs to the spec its comment names.

```ts
declare function tmEntity<const N extends string>(name: N, declaration?: TmEntityDeclarationInput<N>): TmEntityDeclaration;

interface TmEntityDeclarationInput<N extends string> {
  // launcher (0027): an entry under this section, gated by Read; absent → no entry, routes still exist
  section?: string;
  launcher?: { readonly order?: number; readonly icon?: string; readonly synonymsKey?: string; readonly labelKey?: string };
  // search page (0030)
  columns?: readonly TmColumnInput<N>[];         // the one column default (A§3.3); keys per §6.1
  orderBy?: TmOrderInput<N>;                     // 'Code' | 'Name:desc'; else metadata defaultOrderBy
  tile?: TmTileDeclaration<N>;
  filters?: readonly TmCustomFilterDeclaration[];
  search?: TmLazyComponent;                      // hatch: replaces the search body
  // details page (0031)
  details?: TmLazyComponent | { readonly page: TmLazyComponent };
  clone?: (copy: TmJsonObject) => TmJsonObject;
  validate?: unknown;                            // a Signal Forms schema function (0031 types it)
  beforeSave?: (entity: TmJsonObject) => TmJsonObject | Promise<TmJsonObject>;
  actions?: readonly { readonly name: string; readonly dialog?: TmLazyComponent; readonly icon?: string; readonly button?: boolean }[];
  // pickers (0029, §14)
  picker?: TmPickerDeclaration<N>;
  // help (0026 §9.8, reserved)
  helpKey?: string;
}
type TmColumnInput<N extends string> = TmPath<N>
  | { readonly path: TmPath<N>; readonly display?: TmLazyComponent; readonly width?: number }   // 0030's cell hatch
  | { readonly expression: string; readonly labelKey: string; readonly type?: TmDataType };     // a computed column (§6.1)
interface TmPickerDeclaration<N extends string> {
  readonly filter?: string;                      // a Queryex predicate on every picker search (§14.2)
  readonly description?: readonly TmPath<N>[] | false; // the second line; false: one line (§14.2)
  readonly orderBy?: TmOrderInput<N>;            // default: the display name
  readonly create?: boolean;                     // offer "Create…"; default true when the user may save
}
interface TmEntityDeclaration { readonly name: string; readonly [member: string]: unknown } // frozen; the merge rule's unit (0024 §2.3)
```

- **Typed paths.** `TmPath<N>` is checked against the generated `TmEntityShapes` (§15): a scalar, a
  navigation (display), a group anchor, or a dotted path through navigations. Paths up to three
  navigation steps are checked exactly; beyond that only the first three steps are checked.
  Without generated typings (a pack compiled on its own) `TmPath<N>` is `string`.
- **Build check.** `tmCheckAppConfig` (0024 §2.2) runs `tmCheckEntityDeclaration` from this spec
  over every merged declaration against the Entities chunk and reports:

| Code (added to 0024's list) | When |
|---|---|
| `unknown-path` | a `columns`, `orderBy`, `tile` or `picker.description` path that does not resolve (§4.3) |
| `unknown-action` | an `actions[].name` the entity's metadata does not list |
| `operation-missing` | `details` on an entity without `details`; `search`, `columns` or `filters` without `query` |
| `entity-not-routable` | `section` on an entity whose summary has no segment or no `query` |

- **Overrides** follow 0024's merge rule member by member; `picker` is one member, replaced whole.

**Example —** Acme's customers, as in A§3.3, plus a picker tweak:

```ts
export const customers = tmEntity('acme.Customer', {
  section: 'sales',
  columns: ['Code', 'Name', 'CustomerType', 'Currency', 'CreditLimit', 'IsActive'],
  tile: { image: 'ImageId', title: 'Name', subtitle: 'Code', badge: 'IsActive' },
  details: () => import('./customer-details'),
  picker: { description: ['Code', 'CustomerType'] },   // 'Cod' would be a compile error
});
```

### §4 `TmEntities` and descriptors

`TmEntities` is the registry every page asks about entities. Summaries are available at once from
the Core chunk; full descriptors after one `load()` of the Entities chunk, merged with the
declaration and gated by the current tenant's shape.

#### §4.1 Contract

```ts
declare class TmEntities {                                   // @tellma/core primary
  summary(name: string): TmEntitySummary | undefined;        // Core chunk; ordinal-ignore-case
  bySegment(segment: string): TmEntitySummary | undefined;   // route matching (0024 §9.2), synchronous
  declaration(name: string): TmEntityDeclaration | undefined; // the merged declaration (0024 §2.3)
  label(name: string, plural?: boolean): Signal<string>;     // from the summary's keys
  readonly loaded: Signal<boolean>;
  load(): Promise<void>;                                     // fetches the Entities chunk once; a cache read when warm
  get(name: string): TmEntityDescriptor;                     // after load(); reads the shape signal
  resolve(root: string, key: string): TmPathResolution | null; // §4.3
}

interface TmEntityDescriptor {                               // A§5.12, completed
  readonly name: string; readonly segment: string | null; readonly kind: TmEntitySummary['kind'];
  readonly label: Signal<string>; readonly pluralLabel: Signal<string>;
```

- **Loading.** 0024's route host awaits `load()` beside the page chunk for every entity route; both
  come from the worker cache when warm, so the route skeleton is all the user sees (rule 2A).
  `get()` before `load()` settles throws in development and returns a summary-only descriptor in
  production (no properties).
- **`bySegment` returns a summary**, not a descriptor, so route matching never waits for the
  Entities chunk (challenge 2).
- **Reactivity.** `get()` reads the tenant's shape from `TmLaunchCache.docs.settings`; called
  inside a `computed`, a settings change that adds a language rebuilds the descriptor. At most three
  descriptors per entity exist (one per shape), cached.

#### §4.2 Shape gating and labels

- **Admitted slots** = `settings.languages.length` (1–3). Properties with `multilingual.slot`
  greater than that are removed from `properties`, from `relatedSelect`, from `searchable` and from
  every select the platform builds; a declaration naming one renders nothing (A§3.3's `Name2` rule).
- **Twin labels** follow 0013 §7.6: on a tenant with two or three content languages every slot's
  label is the primary label plus `" (" + symbol + ")"` of the content language at that position
  (`Name (E)`, `Name (ع)`); on a one-language tenant there is no suffix.
- **`contentDir`** of a slot property is its content language's direction, so an Arabic `Name2`
  input is `dir="rtl"` on an English page; other strings use `dir="auto"`.
- **Labels are signals** over the active language's strings: a language switch re-labels every
  header, field and slash label in place (0024 §7.2).

#### §4.3 Path resolution

`resolve(root, key)` walks a column key or a Queryex path through descriptors and is the one place
paths are interpreted on the client.

```ts
interface TmPathResolution {
  readonly root: string; readonly key: string;               // 'gl.Center', 'Parent.Manager'
  readonly steps: readonly TmNavigationDescriptor[];         // navigations crossed, in order
  readonly entity: string;                                   // the entity owning the last segment
  readonly end:
    | { readonly kind: 'value'; readonly property: TmPropertyDescriptor }     // a scalar or a twin
    | { readonly kind: 'text'; readonly slots: readonly TmPropertyDescriptor[] } // a group anchor (display)
    | { readonly kind: 'navigation'; readonly navigation: TmNavigationDescriptor } // display name
    | { readonly kind: 'image' | 'file'; readonly navigation: TmNavigationDescriptor; readonly policy: TmBlobKindPolicy };
  readonly label: Signal<string>;                            // slash label (§11.4)
  readonly fkPath?: string;                                  // navigation ends: 'Parent.ManagerId'

```

- **Segment rules.** Every segment but the last must name a navigation; the last names a scalar,
  a group anchor, a twin or a navigation (Queryex's rules, 0008 §6.1, plus the display endings).
  Names match ordinal-ignore-case and resolve to their declared spelling.
- **A navigation to `core.Blob` backed by a `[BlobReference]`** ends as `image` (preset `Avatar` or
  `Photo`) or `file` (any other preset).
- **Unknown** → `null`. Callers drop the key and emit `tm.entity.column-dropped { reason:
  'unknown' }` (§6.4).

### §5 Display names

A display name renders any row of an entity as one string in the user's language: the details
title, picker rows, navigation cells, tiles, the bell's actors. The rule is server metadata; the
client renders it from the row's display-name columns, in the active slot.

#### §5.1 The rule (server; written into 0012)

- **Declaration.** `[DisplayNameSource(property, Prefix = …)]` on the entity type (A§6.1's
  attribute). `property` names a `[Multilingual]` group anchor or a scalar of type string, integer
  or date; `Prefix` names a string or integer scalar.
- **Default** when absent: the `[Multilingual]` group named `Name`; else the first natural key;
  else `Id`.
- **Projection.** The related projection of every entity contains `Id`, the display-name columns
  (every admitted slot of the group, the scalar, the prefix) and `Code` when present; startup
  rejects a `[RelatedSelect]` that drops one (0012 §2.5 edit).
- **Metadata.** `EntityMetadata.DisplayName` and `StackDescriptor.DisplayName` carry it; the
  summary's `displayName` is its client form (§2.2).

**Example —** an invoice shows its serial number; an account shows code and name:

```csharp
[DisplayNameSource(nameof(SerialNumber))] public class SalesInvoice : TopLevelEntity { … }
[DisplayNameSource(nameof(Name), Prefix = nameof(Code))] public class Account : TopLevelEntity { … }
```

#### §5.2 Rendering (normative for both sides)

1. **Name.** For a group: the value in the active slot when non-empty, else slot 1's. For a scalar:
   the value formatted in the locale (integers without grouping, dates in the numeric style of the
   active calendar).
2. **Prefix**, when declared and non-empty, formats the same way.
3. **Text.** Prefix and name → the Core string `Entity_DisplayNameWithPrefix` ("{prefix} - {name}");
   one of them → that one; neither → `Entity_DisplayNameFallback` ("#{id}").
4. **Bidi.** The client wraps each value in U+2068 … U+2069 (first-strong isolates), so an English
   code beside an Arabic name keeps its order in RTL. Server text (Excel, e-mail) carries no
   isolates.

| Rule | Row | Active slot | Text |
|---|---|---|---|
| `Name` group | `{ id: 5, name: 'Head office', name2: 'المكتب الرئيسي' }` | 2 | المكتب الرئيسي |
| `Name` group | `{ id: 6, name: 'Jeddah', name2: null }` | 2 | Jeddah |
| `Name` + prefix `Code` | `{ id: 7, code: '1101', name: 'Cash' }` | 1 | 1101 - Cash |
| `SerialNumber` | `{ id: 9, serialNumber: 42 }` | 1, `ar-SA` | ٤٢ |
| `Name` group | `{ id: 3 }` | 1 | #3 |

- **Shared golden.** `display-name-golden.json` in `@tellma/core` holds rows of `{ rule, shape,
  row, slot, locale, calendar, expected }` and expansion rows (§6.2); the TS renderer's unit test and
  the C# `IDisplayNames` test read the same file.

#### §5.3 `TmDisplayNames`

```ts
declare class TmDisplayNames {                               // @tellma/core primary
  of(entity: string, row: TmJson): Signal<string>;           // A§5.12; memoized per row object (WeakMap)
  select(entity: string, navigation?: string): readonly string[]; // A§5.12; shape-aware columns
  label(entity: string, id: number): Signal<string | null>;  // a known row's display name; null when unknown
  remember(entity: string, rows: readonly TmJson[]): void;   // projections carrying id and display columns
  rememberRelated(related: Readonly<Record<string, readonly TmJson[]>>): void; // EntitiesResult.related
  resolve(entity: string, ids: readonly number[]): void;     // fetch unknown ids in the background
}
```

- **Rows are wire objects** (camelCase, as `get`, `save` and `related` deliver them). `of` reads
  the rule's members by their `json` names and `TmLocalization.contentSlot()`, so a language switch
  re-renders with no request (A§5.4).
- **`select`** returns `Id`, the admitted slots of the group (or the scalar) and the prefix,
  prefixed by the navigation: `select('gl.Center', 'Parent')` on an `en`+`ar` tenant →
  `['Parent.Id', 'Parent.Name', 'Parent.Name2']`.
- **The cache.** Memory only, per tab, per tenant: 5,000 rows per entity, least recently used
  evicted. Fed by every details read and save result (`rememberRelated`, 0031), every picker
  result and pick (§14), the bell's `Related` (0028). Cleared for a tenant when its held
  `permissions` or `settings` tag changes (the page-state rule, 0025 §10). Never written to disk
  (A§5.5).
- **Cacheable entities** (`cacheable` capability) answer `label` from `TmLaunchCache.entitySet()`
  (0025 §3.3) instead of the cache; the list loads lazily on first use.
- **`resolve`** batches unknown ids per entity until the next animation frame and reads
  `{segment}/query` with `filter: "Id in (…)"`, the display-name select and `take` = count, at most
  100 ids per call, `background: true`, aborted when the tenant changes. An entity the user may
  not query (no `query` operation or no `Read`) is not asked; its ids stay unknown, and consumers
  show `#id`.
- **Consumers** never fetch names themselves: the picker's `displayWith` is `label(entity, id)`
  (§14.1).

### §6 Navigation expansion and select plans

A select plan turns the column keys a surface shows into the select, order and filter terms a
query sends, and reads each column's cell back from the row set. Navigations and groups expand to
every admitted slot, so a language switch re-renders without a request.

#### §6.1 Column keys

| Key | Kind | Select terms (en + ar tenant) | Cell | Order terms |
|---|---|---|---|---|
| scalar path: `CreditLimit`, `Parent.Code`, a twin `Name2` | `value` | the path | the value, formatted by type (§12) | the path |
| group anchor: `Name`, `Parent.Name` | `text` | `Name`, `Name2` | active slot, else slot 1 | `coalesce(Name2, Name)` at slot 2; `Name` at slot 1 |
| navigation: `Parent`, `Parent.Manager` | `navigation` | `Parent.Id` + `TmDisplayNames.select('gl.Center', 'Parent')` | display name; a link when the user may read the target's details | the prefix, then the name as for `text` |
| image navigation: `Image` | `image` | `ImageId`, `Image.Variants` | thumbnail (§16) | none |
| file navigation: `File` | `file` | `FileId`, `File.FileName` | file name, a download link | `File.FileName` |
| `{ expression, labelKey }` | `expression` | the expression | the response column's type | the expression |

- **Always first:** the root `Id`, the row identity and paging tiebreaker.
- **Deduplicated:** `Parent` and `Parent.Code` share `Parent.Code`; the plan maps each column to
  term indexes.
- **No slot-1 key.** An Arabic user sees `Name` in Arabic; there is no key for "slot 1 verbatim"
  (review flag 2).
- **URL form.** Keys are exactly what 0024's codec carries in `cols`, `order` and `f.{path}`;
  expression columns live only in declarations and preferences, never in URLs.

#### §6.2 Contract

```ts
declare function tmSelectPlan(root: TmEntityDescriptor, keys: readonly TmColumnInput<string>[],
  options?: { aggregate?: boolean }): TmSelectPlan;            // @tellma/core/entity
interface TmSelectPlan {
  readonly select: string;                                     // comma list, for QueryRequest.Select
  readonly columns: readonly TmColumnPlan[];                   // in key order; dropped keys absent
  readonly dropped: readonly { readonly key: string; readonly reason: 'unknown' | 'unreachable' }[];
  rows(set: TmQueryRowSet): readonly TmPlanRow[];              // a row-major view keyed by column
}
interface TmColumnPlan {
  readonly key: string; readonly kind: 'value' | 'text' | 'navigation' | 'image' | 'file' | 'expression';
  readonly resolution: TmPathResolution | null;               // null for expressions
  readonly type: TmDataType | null;                           // null until the response types an expression
  readonly label: Signal<string>;                             // slash label, or the expression's label key
  orderBy(direction: 'asc' | 'desc'): string | null;          // reads the active slot; null: not orderable
  readonly filter: TmFilterKind | null;                       // which control §13 renders; null: none
  value(row: TmPlanRow): TmCellValue;                         // raw value; for navigations { id, names, prefix }
}
```

- **Aggregate mode** (0034's previews) expands navigations the same way; each expanded term is a
  grouping key, harmless because it depends on the id.
- **C# twin.** `IDisplayNames.Columns(entity, shape, navigationPath)` (0012 edit) returns the same
  terms for server hosts: report execution (0033), Excel display columns (0019 via 0030's edit),
  MCP. The expansion rows of `display-name-golden.json` pin both.
- **Language switch.** Cells re-render from the held rows. `orderBy` of a `text` or `navigation`
  column changes with the slot; the host decides whether to re-query (0030).

#### §6.3 Example — the Centers grid, `en` + `ar`, user in Arabic

`cols=Code,Name,Parent,Parent.Code&order=Parent`:

```text
select:  Id,Code,Name,Name2,Parent.Id,Parent.Name,Parent.Name2,Parent.Code
orderBy: coalesce(Parent.Name2, Parent.Name)
cells:   Code → "E-01"; Name → Name2 ?? Name; Parent → a link "المنطقة الشرقية"; Parent.Code → "R-1"
```

#### §6.4 Dropped keys

- A key that does not resolve (`unknown`) or that `TmPermissions.reachable` refuses
  (`unreachable`) is left out of `select` and `columns` and listed in `dropped`; the host never
  sends it, so a shared URL or a stale preference never turns the page into a `403`.
- Telemetry `tm.entity.column-dropped { reason, source }` (`source` is the host's: `url`,
  `preference`, `declaration`).

### §7 Client permissions

`TmPermissions` answers, from the cached access summary and the securables metadata, whether the
user may do something, so buttons, entries and offered paths never invite a refusal.

```ts
declare class TmPermissions {                                  // @tellma/core primary
  can(resource: string, action: string): Signal<boolean>;     // A§5.12
  filtered(resource: string, action: string): Signal<boolean>;
  allows(entity: string, operation: TmEntityOperation | 'activate' | `action:${string}`): Signal<boolean>;
  sensitive(resource: string, action: string): boolean;       // deployment fact: step-up ahead
  reachable(root: string, key: string): Signal<boolean>;      // the traversal rule; needs TmEntities.load()
}
```

- **Source.** `me.access` in the launch documents (0025): `isSystem` grants everything unfiltered;
  otherwise a securable is allowed when listed in `securables`, filtered when its `hasFilter` is
  set. Wildcards and "write implies read" are already composed by the server (0014 §5.2). No
  `me` yet (a cold launch before sync) → everything false; the chrome shows skeletons then anyway.
- **`allows`** = the operation exists in the entity's summary and its securable is allowed:
  `query`, `details`, `export` → `Read`; `save`, `import` → `Save`; `delete` → `Delete`;
  `activate` → `Activate` (with the `activatable` capability); `action:<name>` → the action's
  `action` (member-only actions → true). 0030 and 0031 gate Create, Export, Import, Activate,
  Delete and custom actions with it; 0027 gates launcher entries with `allows(e, 'query')`.
- **`sensitive`** reads the securables section (0014 §10 edit: `resource`, `action`, `filterRoot`,
  `isSensitive`). 0024's step-up dialog and 0031's save button use it to warn before the user
  starts.
- **`reachable(root, key)`** mirrors 0015 §5.2: root `Read` must be allowed; walking the key's
  segments, each segment that reads a column of an entity other than the root must, when that
  entity is restricted, name a column of its `relatedSelect` (a navigation segment reads its FK).
  An entity is unrestricted when `can(E, 'Read')` and not `filtered(E, 'Read')`; a child entity
  takes its owner's access; an entity with no `Read` securable (`core.Blob`) is restricted.
  **Example —** with a filtered `Read` on `gl.Center`: `Parent.Name` true, `Parent.Code` true
  (projected), `Parent.CreatedAt` false, `Parent.Manager` false (`ManagerId` is not projected).
- **The server stays the authority.** A refused traversal still answers `403` (0015) or
  `Query.PathNotReachable` in discover (§9); the client uses `reachable` only to choose what it
  offers and sends.

### §8 The client Queryex

The client never parses Queryex. It lexes (highlighting, parameters, safe insertion), and it
builds and prints the expressions it writes itself (column filters, picker filters, order terms),
so no client code concatenates query text by hand.

#### §8.1 Lexer

```ts
type TmQxTokenKind = 'number' | 'string' | 'identifier' | 'keyword' | 'parameter' | 'punctuator' | 'error';
interface TmQxToken { readonly kind: TmQxTokenKind; readonly start: number; readonly length: number; readonly text: string; readonly call?: true }
interface TmQxLexDiagnostic { readonly code: 'QX1001' | 'QX1002' | 'QX1003' | 'QX1004' | 'QX1005'; readonly start: number; readonly length: number }
declare function tmQxLex(text: string): { readonly tokens: readonly TmQxToken[]; readonly diagnostics: readonly TmQxLexDiagnostic[] };
declare function tmQxParameters(text: string): readonly { readonly name: string; readonly sites: readonly { start: number; length: number }[] }[];
```

- **Exactly 0008 §4:** Unicode `White_Space` separators (`\p{White_Space}` with the `u` flag);
  identifiers `(\p{L}|_)(\p{L}|\p{Nd}|_)*` or `[ … ]`; the ten case-insensitive keywords; numbers
  `\d+(\.\d+)?` (QX1003 for `.5`, `5.`, `1e3`; QX1004 beyond 38 significant digits); strings with
  `''`; `@Identifier` parameters; the punctuator set; maximal munch; no comments.
- **Spans are UTF-16 offsets**, as the engine's are, so a diagnostic's `start` feeds
  `setSelectionRange` directly.
- **`call`** marks an identifier followed (after whitespace) by `(`: highlighted as a function.
- **`tmQxParameters`** groups `parameter` tokens case-insensitively; the first spelling names
  the group. `'a@b'` yields none (it is inside a string).

#### §8.2 Builder and printer

```ts
type TmQx =
  | { readonly kind: 'path'; readonly segments: readonly string[] }
  | { readonly kind: 'string'; readonly value: string } | { readonly kind: 'number'; readonly value: string } // decimal text
  | { readonly kind: 'bool'; readonly value: boolean } | { readonly kind: 'null' }
  | { readonly kind: 'param'; readonly name: string }
  | { readonly kind: 'call'; readonly name: string; readonly args: readonly TmQx[] }
  | { readonly kind: 'not' | 'negate'; readonly operand: TmQx }
  | { readonly kind: 'binary'; readonly op: TmQxBinaryOp; readonly left: TmQx; readonly right: TmQx }
  | { readonly kind: 'in'; readonly value: TmQx; readonly items: readonly TmQx[] }
  | { readonly kind: 'is-null'; readonly value: TmQx; readonly negated: boolean };
type TmQxBinaryOp = 'or' | 'and' | '=' | '!=' | '<' | '<=' | '>' | '>=' | '+' | '-' | '||' | '*' | '/' | '%';
declare const tmQx: {
  path(path: string): TmQx; str(value: string): TmQx; num(value: number | string | TmDecimal): TmQx;
  bool(value: boolean): TmQx; null(): TmQx; param(name: string): TmQx;
  literal(type: TmDataType, value: unknown): TmQx;            // dates as 'yyyy-MM-dd', instants ISO with offset, enums as strings
  call(name: string, ...args: TmQx[]): TmQx; not(x: TmQx): TmQx;
  and(...xs: (TmQx | null)[]): TmQx; or(...xs: (TmQx | null)[]): TmQx;   // nulls skipped; flattened; empty and → true, empty or → false
  eq(a: TmQx, b: TmQx): TmQx; ne(a: TmQx, b: TmQx): TmQx; lt(a: TmQx, b: TmQx): TmQx;
  le(a: TmQx, b: TmQx): TmQx; gt(a: TmQx, b: TmQx): TmQx; ge(a: TmQx, b: TmQx): TmQx;
  in(value: TmQx, items: readonly TmQx[]): TmQx; isNull(value: TmQx, negated?: boolean): TmQx;
};
declare function tmQxPrint(expression: TmQx): string;
declare function tmQxInsert(text: string, caret: number, insertion: string): { readonly text: string; readonly start: number; readonly end: number };
```

- **Precedence** is 0008 §5.2's table: a child is parenthesized when it binds looser than its
  parent, a right operand of equal power is parenthesized (`a - (b - c)`), and comparisons, being
  non-associative, parenthesize comparison operands.
- **Identifiers** that are keywords or do not match the identifier grammar print bracketed
  (`[Order]`); a name containing `]` throws (no escape exists).
- **Literals.** Strings double `'`; numbers print their decimal text without exponent (a `number`
  beyond 15 significant digits is refused: pass the string or a `TmDecimal`); negative numbers
  print as unary minus.
- **`tmQxInsert`** never splits a token: an insertion inside an identifier, number or string moves
  to the token's end, and a space is added on a side that touches an identifier part, a digit or
  `)`. The returned range selects the inserted text.

**Example —** a numeric between filter:

```ts
const p = tmQx.path('CreditLimit');
tmQxPrint(tmQx.and(tmQx.ge(p, tmQx.num('100000')), tmQx.le(p, tmQx.num('500000'))));
// 'CreditLimit >= 100000 and CreditLimit <= 500000'
tmQxPrint(tmQx.or(tmQx.call('contains', tmQx.path('Name'), tmQx.str("O'Neil")), tmQx.eq(tmQx.path('Code'), tmQx.str('7'))));
// "contains(Name, 'O''Neil') or Code = '7'"
```

- **Cross-check with the engine.** `queryex-print-golden.json` lists builder trees with their
  expected text; the TS test asserts `tmQxPrint`, and a C# test asserts the engine's `Discover`
  parses each text with no diagnostic and finds the same parameters, paths and functions. A lexer
  corpus gives, per text, the engine's parameter names and QX1xxx codes, generated by a C# tool
  and checked in; the TS lexer must agree.

### §9 `queryex/discover`

One endpoint checks Queryex under authoring exactly as `query` (or a permission filter) would
compile it, and reports what it refers to: diagnostics with spans, parameters with inferred types
and the paths they meet, and path uses. It runs no SQL.

```csharp
// Tellma.Core.Api — registered by CoreFeature through contribution.ApiService<QueryexService>()
[ApiRoute("queryex")]
public sealed class QueryexService
{
    [ApiAction("discover", MemberOnly = true, Idempotent = true, Mutation = false, Mcp = McpExposure.Hidden)]
    public Task<QueryexDiscoverResult> DiscoverAsync(QueryexDiscoverRequest request);
}

// Tellma.Core.Abstractions.Api
public sealed record QueryexDiscoverRequest(
    string Root,                                     // entity name: 'gl.Center', 'acme.SalesInvoiceLine'
    string? Select = null, IReadOnlyList<string>? Filters = null, string? Having = null, string? OrderBy = null,
    bool Aggregate = false,
    IReadOnlyList<QueryexParameterInput>? Parameters = null,  // types the author confirmed; others are inferred
    QueryexProfile Profile = QueryexProfile.Query);
public sealed record QueryexParameterInput(string Name, QueryexType Type);
public enum QueryexProfile { Query, Permission }    // Permission: one filter, AccessLimits, no parameters, me() allowed (0014 §3.7)

public sealed record QueryexDiscoverResult(
    IReadOnlyList<QueryDiagnostic> Diagnostics,     // 0016 §3.4's record; Clause: select | filters[i] | having | orderBy
    IReadOnlyList<QueryexParameterInfo> Parameters,
    IReadOnlyList<QueryexPathInfo> Paths,
    bool UsesAggregation);
public sealed record QueryexParameterInfo(
    string Name, IReadOnlyList<QueryexSite> Sites,
    QueryexType? Type,                              // confirmed, else inferred; null: unconstrained or conflicting
    IReadOnlyList<QueryexType> Conflicts,
    IReadOnlyList<string>? ComparedWith,            // the path the parameter meets (0010 Part F)
    string? Entity);                                // ComparedWith's target when it is a key or a foreign key: 'gl.Center'
public sealed record QueryexPathInfo(IReadOnlyList<string> Segments, QueryexSite Site, string Entity, bool Reachable);
public sealed record QueryexSite(string Clause, string? Location, int Start, int Length);
```

1. **Authorize.** Member only; the root must be in the `All` schema (`404 not-found` otherwise).
   Runs in a `Read` batch through 0014's guarded runner with nothing appended: 0 round trips warm.
2. **Discover.** `DiscoverQuery` over every clause together (0008 §2.4) against the tenant's
   schema, `Root`, and the clause modes `CompileQuery` would give them.
3. **Compile.** `CompileQuery` of `QuerySpec { Root, Select = Select ?? "Id", Aggregate, Filter =
   And(Leaf(f) for each Filters), Having, OrderBy }` under `PipelineLimits` (Permission profile:
   `Validate` of the one filter in `Filter` mode under `AccessLimits`, `HasUser = true`, no
   parameters, as 0014 §3.7 step 6), with declarations = confirmed ∪ inferred. The SQL is
   discarded. QX3007 on a parameter left unconstrained is dropped: the parameter's `Type` is null
   and its chip asks for a type.
4. **Traverse.** The pipeline's traversal rule (0015 §5.2 step 4) over every path; each refusal
   becomes a diagnostic `Query.PathNotReachable { entity, path }` at the path's span (a new
   0015 §7.3 code), and the path's `Reachable` is false.
5. **Answer** `200` with every diagnostic, never `400`: a draft with errors is a successful
   discovery. Lexical and syntax errors do not stop parameter and path discovery.

- **Wire class.** Retried read (A§6.3's 0016 row), cancellable per keystroke; contract
  fingerprint like every projected endpoint; rate policy `tellma-user`. It stamps activity (it is
  the user typing).
- **Messages.** Diagnostics carry codes and arguments only. The client renders `Queryex_<code>`
  (`Queryex_QX3001`: "Unknown property '{name}' on {entity}") and `Query_*` keys from the string
  pack (0013 §10.1 edit); list arguments such as `expected` join through `Intl.ListFormat`.

### §10 The expression editor

#### §10.1 Contract

#### §10.2 Checking

- **When.** 250 ms after the last change to any clause of the draft (sliding), the draft calls
  `queryex/discover` with every non-empty clause; each change aborts the call in flight
  (`TmApi.read` with the draft's signal).
- **Stale answers.** A result applies only to clauses whose text still equals what was sent; an
  edited clause drops its server diagnostics at once (no squiggle ever sits at a wrong offset) and
  shows "Checking…".
- **Offline or failed.** Lexical diagnostics still show; the status line says "Can't check while
  offline" or "Couldn't check the expression" with Retry.
- **Parameters.** Names come from `tmQxParameters` on every keystroke; types, conflicts and the
  compared entity merge in from the last applied answer (0034 renders the definition's parameter
  table from `draft.parameters`).

#### §10.3 Rendering and layout

- **A native `textarea`** (`dir="ltr"`, the mono font, `spellcheck="false"`, `autocomplete="off"`)
  over a `pre` mirror with the same metrics. The mirror draws tokens (`--expr-*` colours: paths,
  functions, keywords, strings, numbers, parameters bold), wavy underlines at diagnostic spans and
  a 1.2 s tint on just-inserted text; the textarea's text is transparent with a visible caret. The
  two scroll together.
- **Fixed geometry.** `rows` lines tall, scrolling inside; below it one status line (20 px) always
  present: "No problems", "Checking…", or the first problem as "Line 2: Unknown property 'Accnt'"
  with "+2 more"; with `showParameters`, one chip row (24 px, horizontal scroll) of
  `@From · Date` chips, a warning tone for conflicting or untyped ones. Nothing below moves while
  the user types (rule 2D).
- **Problems list.** "+2 more" opens a `tm-popover` (`size: 'md'`) listing every problem as a
  button; activating one selects its span in the textarea and closes the popover.
- **RTL.** The code is always LTR (an isolate inside RTL pages); the status line, chips and popover
  follow the page direction; Arabic inside string literals renders by the bidi algorithm.

#### §10.4 Drop and insert

- **Drop.** A `tm.path` drag (§11.3) writes its Queryex text as `text/plain`; the textarea accepts
  it natively at the drop caret, keeping undo. On the resulting `input` event with
  `inputType: 'insertFromDrop'` the editor checks the range with `tmQxInsert` (token boundary,
  spacing), applies any adjustment through the insert path below, and tints the result.
- **Insert.** `insertAtCaret(text)` computes the edit with `tmQxInsert` at the last caret the
  textarea had (its end when it never had focus), focuses the textarea, selects the target range
  and applies it with `document.execCommand('insertText')`, so the insertion is one native undo
  step; where that command reports failure it falls back to `setRangeText` (no undo entry). The
  inserted range ends selected. The e2e pins undo after insert in Chromium, Firefox and WebKit.
- **The draft.** The editor writes its value into `draft.text(clause)`; a draft sends its `filter`
  clause as `filters[0]` and maps answers back by clause.

#### §10.5 Keyboard and ARIA

| Key | Effect |
|---|---|
| typing, arrows, selection, Ctrl/Cmd+Z | native |
| Tab, Shift+Tab | leave the editor (no tab insertion; no keyboard trap) |
| F8, Shift+F8 | select the next / previous problem's span |
| Ctrl/Cmd+Enter | `submit` |

- The textarea is labelled by `ariaLabel` (or the enclosing `tm-form-field`), `aria-invalid` while
  any diagnostic exists, `aria-describedby` the status line, a polite live region updated when a
  check completes, never per keystroke.

### §11 The path tree picker

`tm-path-picker` lists the fields of a root entity as a lazily expanded tree on 0023's `tm-tree`:
scalars as leaves, navigations as branches into their target. It is built from local descriptors,
so expanding never waits; it searches, offers drag sources, and labels nested fields with slashes.

#### §11.1 Contract

```ts
@Component({ selector: 'tm-path-picker' })

  readonly kind: 'value' | 'text' | 'navigation' | 'image' | 'file';

```

#### §11.2 Nodes

- **Shown:** queryable scalars; navigations as branches (with a type pill naming the target's
  singular label, as the design's "Parent center · Center"); a multilingual group as one `text`
  node, with its admitted slots as children on a multi-language tenant (`Name (E)`, `Name (ع)`; in
  `columns` mode the twins only, since slot 1 has no key, §6.1); image and file navigations as
  leaves in `columns` mode and branches into `core.Blob` in `fields` mode.
- **Hidden:** FK scalars (their navigation stands for them), `Node`, non-queryable properties,
  twins beyond the shape, and every unreachable path (§7); a restricted entity's branch shows only
  its projected fields.
- **Order:** by label in the UI language (`Intl.Collator`), then `Id` and the four audit fields
  last. **Icons** (0023 `tm-icon`): numbers `hash`, text `type`, enums `list`, booleans
  `toggle-left`, dates `calendar`, navigations `link-2`, images `image`, files `paperclip`, groups
  `languages`.

#### §11.3 Search, drag and activation

- **Search** matches the label and the path name, case- and diacritic-insensitively (the
  launcher's normalizer, 0027), breadth first to three navigation steps, at most 200 matches; the
  tree then shows matches with their ancestors as muted context rows (`tm-tree` `context`), every
  ancestor expanded. "12 fields" / "No fields match" is announced politely.
- **Drag payload** (0023 `TmDragPayload`): `kind: 'tm.path'`, `data: TmPathNode`, `label` = the
  slash label, `text` = the Queryex form of the node: the path for values and groups, the FK path
  for navigations (`Parent.ManagerId`), so a drop into an expression is always valid Queryex.
- **Activation** (Enter or double-click) emits `activate`; consumers add the field (0030's column
  editor, 0034's "Add to…") or call `insertAtCaret` on the last-focused editor (WCAG 2.5.7's
  non-drag path).

#### §11.4 Slash labels

- `pathLabel` joins each segment's label with " / ", each label wrapped in U+2068 … U+2069, so
  "Parent center / Code" and "المركز الأب / الرمز" both read correctly, mixed scripts included.
- The same function labels `TmColumnPlan.label` and the advanced-filter's path chips.

### §13 Filter controls

Each column kind has one filter control; each control writes 0024's `f.{key}` value and each value
becomes one Queryex leaf. The leaf travels as its own `QueryRequest.Filters` entry (0030's edit),
so its diagnostics never mix with other filters.

#### §13.1 Contract

```ts
type TmFilterOp = 'contains' | 'starts-with' | 'ends-with' | 'eq' | 'ne' | 'lt' | 'le' | 'gt' | 'ge'
  | 'between' | 'before' | 'after' | 'in' | 'is';
type TmFilterKind = 'text' | 'number' | 'date' | 'instant' | 'enum' | 'bool' | 'navigation';
interface TmFilterSpec { readonly op: TmFilterOp; readonly values: readonly string[] }   // culture-free
declare function tmParseFilter(value: string): TmFilterSpec | null;   // 'between:1,5' → { op, values: ['1', '5'] } (0024 §9.5 syntax)
declare function tmFormatFilter(spec: TmFilterSpec): string;
declare function tmFilterLeaf(column: TmColumnPlan, spec: TmFilterSpec, context: { timeZone: string }): string | null; // null: invalid here

@Component({ selector: 'tm-column-filter' })               // the content 0030 puts in a header popover (size 'sm')
declare class TmColumnFilter {
  readonly column: InputSignal<TmColumnPlan>;
  readonly value: InputSignal<string | null>;              // the current f. value
  readonly applied: OutputEmitterRef<string | null>;       // Apply → a value; Clear → null
}
```

#### §13.2 Kinds, operators and leaves

| Kind (column) | Ops, default first | Control | `f.` value → leaf |
|---|---|---|---|
| `text` (string, group) | `contains`, `starts-with`, `ends-with`, `eq`, `ne` | `tm-select` + `input[tmInput]` | `contains:jed` → `contains(Name, 'jed') or contains(Name2, 'jed')` (every admitted slot; one slot for a plain string) |
| `number` | `between`, `lt`, `le`, `eq`, `ge`, `gt` | `tm-select` + `tmNumber` (two for `between`) | `between:100000,500000` → `CreditLimit >= 100000 and CreditLimit <= 500000` |
| `date` | `between`, `before`, `after` | `tm-select` + `tm-date-picker`, `tm-date-range` for `between` | `before:2026-03-01` → `PostingDate < '2026-03-01'` |
| `instant` | as `date` | as `date`; days in the display zone | `between:2026-01-01,2026-01-31` → `CreatedAt >= '2025-12-31T21:00:00+00:00' and CreatedAt < '2026-01-31T21:00:00+00:00'` (Asia/Riyadh) |
| `enum` | `in` | a checkbox list up to 8 values, else `tm-multi-select` | `in:Service,Sale` → `CenterType in ('Service', 'Sale')` |
| `bool` | `is` | `tm-radio-group` True / False | `is:true` → `IsActive = true` |
| `navigation` | `in` | `tm-entity-multi-field` (`maxItems` 50) | `in:1012,1015` → `ParentId in (1012, 1015)`; `Parent.Manager` → `Parent.ManagerId in (…)` |
| `image`, `file`, `expression` | none | — | — |

- **Semantics are Queryex's** (0008 §9.2): `ne` also matches rows with no value; `between` and the
  orderings never do. `before` and `after` are strict; `between` includes both ends.
- **Instants** filter whole days in `TmLocalization.timeZone()`: a day starts at its first instant
  in that zone (the earliest valid instant when midnight does not exist).
- **Literals** come from `tmQx.literal` (§8.2): strings escaped, numbers culture-free, dates ISO.
- **An invalid value for the kind** (`contains` on a number, an unparsable date) makes
  `tmFilterLeaf` return null; 0030 drops that filter from the query and the URL (0024's lenient
  parsing).

#### §13.3 The control

- **Layout** (the design's filter panels): operator select, value inputs, then Clear and Apply;
  fixed width 320 px; the `between` pair side by side with "From" and "To" labels. Below `sm`,
  0030 hosts the same content in an end drawer and controls take the 44 px touch height (A§9).
- **Apply** is enabled only when the value is valid for the operator; Enter in any input applies;
  Clear emits null. Escape belongs to the host popover.
- **ARIA.** The operator select is labelled "Operator" (`tm.filter.operator`); each input by the
  column's label; the enum list is a labelled `group`. Values typed in Arabic-Indic digits parse
  through `tmNumber` and serialize Latin.

#### §14.2 Search

1. **Request.** `TmApi.read('{segment}/query', { select, search, filters, orderBy, take: 21 },
   { signal })`: `select` = `Id`, the display-name columns, the description columns; `search` = the
   text trimmed to `limits.maxSearchLength` (omitted when empty: browse); `filters` = the
   declaration's `picker.filter` and the field's `filter`, each its own leaf; `orderBy` =
   `picker.orderBy` or the display name's order terms; inactive rows excluded by the server's
   activatable conjunct.
2. **Result.** The first 20 rows; `hasMore` when a 21st came back. Every row is remembered in
   `TmDisplayNames` (§5.3).
3. **Cacheable targets** with no Queryex filter search `TmLaunchCache.entitySet(entity)` in memory
   instead (the client cannot evaluate Queryex, so a filtered picker always queries): active rows
   whose admitted slots or natural keys contain the normalized text, or whose id equals it, ordered
   by display name, synchronously (no debounce, no spinner, offline-capable); a promise only while
   the list first loads.
4. **Description** (the second line, 0010 E.1): `picker.description` paths joined with " · "; by
   default the natural keys the display name does not already show and, for tree entities, the
   parent's display name; `false` keeps one line.
5. **Unsearchable targets.** When `allows(entity, 'query')` is false the field renders read-only
   with its `displayWith` text (a user can keep a value they cannot choose again).

#### §14.3 Labels

- `itemLabel(row)` = `TmDisplayNames.of(entity, row)()`; `displayWith(id)` =
  `TmDisplayNames.label(entity, id)()`, so a committed value re-renders on a language switch; an
  unknown id calls `resolve` and shows the picker's own fallback meanwhile.

#### §14.4 Advanced search, Create and Edit

- **Pages.** `advancedSearch` is offered when the target has `query`; `create` when it has `save`,
  `allows(entity, 'save')` and neither the declaration nor the field turned it off; `edit` when
  `allows(entity, 'save')`.
- **Loading.** `/entity` may not import `/search` or `/details`, so the binding passes
  `TmLazyPickerPage`, a shim that loads `TM_ENTITY_PAGES.search` or `.details` inside the modal and
  renders it with the same modal data. The target travels in the page object's `context` (0010
  Part E request): `{ entity, filter, kind: 'search' | 'create' | 'edit' }`.
- **The pages are 0030's and 0031's** and follow 0006 §6's contract: the search page opens on the
  typed query, shows the target's column default, closes with `{ id, label, item }` on row
  activation (with `multiple`, checkboxes and Done, closing with an array); the details page opens
  in create mode with the typed text in the display-name source field, or on the id for Edit, and
  closes with the saved pick, or `null` when the entity is gone.

#### §14.5 Grid cells

- `tmGridColumnFor(column, { editable: true })` of a `navigation` column spreads the binding into
  0006 §7's column inputs (`search`, `itemId`, `itemLabel`, `advancedSearch`, `create`, `edit`) and
  sets `format` = `displayWith`; `resolvePastedLabels` resolves pasted names through one `query`
  with `Name in (…)` over the admitted slots.

### §16 Client blob-kind policies

Each `[BlobReference]` property carries its kind's policy (0017 §2.3), so the client checks a file

## 11. Review flags

1. **Display-name template "{prefix} - {name}"** (§5.2). Alternative: "{prefix} · {name}" or
   "{name} ({prefix})". Flips on Ahmad's or customers' preference; it is one resource string.
2. **No column key for slot 1 verbatim** (§6.1). An Arabic user cannot show the English name
   beside the Arabic one. Alternative: a slot suffix in the column-key grammar (0024's codec path
   rule changes). Flips if bilingual side-by-side review is a real workflow.
3. **Filters on multilingual columns match every slot** (decision 7). Alternative: the active slot
   only. Flips if users report matches on text they cannot see.
4. **Wire camelCase objects, PascalCase paths** (decision 4). Alternative: convert responses to
   PascalCase. Flips if agents writing layouts confuse the two casings in practice.
5. **No client parser** (decision 8); syntax errors arrive with discover after 250 ms. Alternative:
   a TS parser. Flips if offline authoring or sub-250 ms syntax feedback is required.
6. **Discover debounce 250 ms, sliding** (§10.2). Alternative: 50 ms like search. Flips on
   measured server load or user feedback.
7. **Native drop for drop-at-caret** (decision 10). Alternative: coordinate-based caret placement.
   Flips if a target browser misplaces native drops (the e2e covers three engines).
8. **The entity section ships in the anonymous bundle** (§2.1): property names of the
   distribution's model are visible to anyone who loads the app. Alternative: an authenticated
   metadata route (breaks the offline warm launch). Flips if a customer treats its data model as
   confidential.
9. **Instants read-only in forms** (decision 17). Alternative: a 0023 date-time picker. Flips on
   the first entity with an editable instant.
10. **Picker page 20 rows, multi-field cap 50, path search depth 3 and 200 matches** (§11.3,
    §14.2). Flips on usability findings.
11. **`resolve` needs the target's `Read`** (§5.3); otherwise `#id` shows. Alternative: a
    member-only "display names by ids" endpoint (it would bypass row-level security). Flips if
    `#id` shows up often for legitimate users.
12. **Cacheable picker search is client-side** (decision 14); its matching can differ slightly from
    the server's `contains` under SQL collation. Flips on mismatch reports.
13. **Typed paths checked to three navigation steps** (§3). Alternative: unlimited lazy checking
    (slower editor type-checks). Flips on type-check performance measurements.
14. **Humanized English `labelFallback` shown in every language** (§2.4). Alternative: fail the
    build on a missing label. Flips once packs are fully translated.

## 12. Challenges to the architecture

1. **`tmEntity<AcmeCustomer>(…)` (A§3.3) cannot type-check paths** without the entity name also
   being a type argument: TypeScript has no partial type-argument inference, so an explicit
   `<AcmeCustomer>` disables inferring the paths. Followed with name-literal typing through the
   generated `TmEntityShapes` augmentation; the type argument disappears ("optional" in A§3.3, now
   absent).
2. **`TmEntities.get`/`bySegment` returning full descriptors (A§5.12) in the eager primary** would
   pull the Entities chunk into boot. Followed with `summary`/`bySegment` → `TmEntitySummary`
   (Core chunk, synchronous, used at route matching) and `get` → descriptor after `load()`. The
   display-name rule moves into the summary because 0027 and 0028 render names before `/entity`.
3. **"Full descriptors" in `/entity` (A§2.2)**: the descriptor code lives in the primary, because
   `TmEntities.get` is primary API; only its data loads lazily (a JSON fetch, which the primary may
   do). `reachable` likewise needs the loaded data. Cost ≤ 6 KB gzip in the primary.
4. **A§8's column rule covers navigations only.** Groups need the same display rule, or `Name` shows
   slot 1 to Arabic users; decision 5 extends it. A slot-1 key is impossible without changing
   0024's `f.{path}` and `cols` grammar (review flag 2).
5. **`/entity` cannot reach `/search` and `/details`** (A§2.2's import rule), yet A§10.1 Stock Q1
   puts their pages in the picker's modals. Followed with `TM_ENTITY_PAGES` loaders from
   `provideTellma` (the dynamic-import exception 0024's route host and 0025 challenge 8 already
   need; one ruling should cover all three) and a `context` member on 0006's page object (Part E).
6. **`queryex/discover` gains a `Permission` profile** beyond A§6.1's description, so 0032's role
   editor validates permission filters exactly as role save does, without a second endpoint.
7. **Entity schema in an anonymous bundle** (A§5.2 with 0024 §6's anonymous static assets) is a
   disclosure A§12 does not list; added as review flag 8.
