# 0010-BE — design note: spec 0010 Parts B–E (amendments to 0002, 0004, 0005, 0006)

Designer note for the four library parts of spec 0010 ("Amendments to Implemented Specs"). Every
delta below was checked against the implemented code under `client/projects/core/` (paths are
relative to `client/projects/core/tellma-core-ui/` unless stated) and the f07 memory notes. Where the
code and the frozen spec text disagree, the code is the baseline the amendment edits.

Contract blocks are TypeScript sketches: names and shapes are normative; imports, documentation
comments and bodies are omitted. "Old → new" shows the implemented surface first.

## 2. Decisions

Each: the decision — why (alternative rejected) (where).

1. **Breakpoints are TS constants plus a lint rule, no CSS tokens** — custom properties cannot appear
   in media or container queries (tokens anyway: a dead `var()` in a query fails silently) (B.1).
2. **CSS spells thresholds only `(width >= N)` / `(width < N)`** — one spelling, no `767.98px` (also
   admitting `min-width:`) (B.1).
3. **`TmTheme` never persists; `provideTellmaUi({ theme })` seeds it; it writes the effective value;
   the emitter adds `color-scheme`** — 0025 owns the one writer of `tm.boot` (a storage port) (B.2).
4. **Live direction is a root `Directionality` watching `<html dir>`** — every root-injected surface
   follows a switch (`TmModalConfig.direction`: CDK then gives content a static `Directionality`; a
   `[dir]` wrapper: never reaches `.cdk-overlay-container`) (B.3, D.2).
5. **The translations seam is a loader function; activation is 0024's** — one owner of the language
   runtime (a library `use(lang)` service) (B.3).
6. **Multi-selects are sibling components** — a flag cannot change the model's type (a `multiple`
   input) (B.4, E.2).
7. **Row activation is opt-in and readonly-only; click and Enter open the row; F2 reaches a cell's
   link** — Search Q1, with APG's "enter the cell" key (Enter actuating the cell's link) (C.1).
8. **The highlight is the active row, driven by `activeRowId` and `input[tmGridDriver]`** — no list
   page rewrites arrow handling (page-side handling over a model) (C.2).
9. **The grid shows and edits sort state, never sorts** — the 0004 non-goal stands (C.3).
10. **The header row is navigable only with a sortable column or a header action** — zero change for
    other grids (header buttons in the tab order: 2N stops before row 1) (C.4).
11. **Select-all toggles the current rows and keeps foreign ids** — selection across pages (C.5).
12. **`loadChildren` takes a batch** — one signature for an expand and a restore (an additive
    `loadChildrenBatch`) (C.9).
13. **Bound `expandedIds` wins; unknown ids are never pruned** — remembered grandchildren arrive in
    later batches (C.9).
14. **Menus stay data-driven; new kinds are new union members; submenus one level** — `TmMenuItem` and
    `itemSelected` keep their types (optional `action`; a wider output) (C.10).
15. **The overlay helpers become public `@tellma/core-ui/overlay`, unchanged** — shell overlays share
    the one Escape stack (copies in `@tellma/core`) (D.1).
16. **The drawer is `TmModal` `placement: 'end'`, with no slide** — ruling 1; brief rule 2B (D.2).
17. **Popovers get fixed widths and `panelClass`** — they read alike and never resize (free width) (D.3).
18. **Instants format in an explicit zone; relative time takes `now`** — deterministic, golden-testable
    (the browser zone; an internal clock) (D.4).
19. **`clearAll({ keep })`; the library never learns the boot record** — Challenge 1 (D.5).
20. **The multi-picker composes the single picker (`ɵcommitMode: 'emit'`)** — the search state machine
    is not forked (a second state machine) (E.2).

## 3. Parts B–E: shared rules

- **Each part has its own Definition of done** and ships independently, in the order B, D, C, E
  (Part C's driver uses Part D's overlay entry point only through the menu; Part E needs 0023's
  `chips`).
- **Every changed entry point** updates its API golden (`client/api/*.api.md`), its `*.examples.ts`
  and `components.json` entry, its harness, its showcase story, its English strings in
  `i18n/strings-en.ts` and the Arabic twin in `@tellma/locale-ar` (the EN↔AR parity gate).
- **No public text cites a spec** (the `docs:build` gate): TSDoc, strings and test names stay

- **Budgets** are measured from `pnpm run size:check` after the change; every raise carries a
  `"tellma".budgetNotes` entry (the ratchet rule). Current measurements are from the 2026-10-20 `dist`.

# Part B — Component library foundation (spec 0002)

## B.1 Breakpoints (0002 §4, new subsection; §1 lint)

One closed set of min-width thresholds (00-architecture §9) for the whole platform.

```ts
// @tellma/core-ui (primary entry point, folder layout/)
type TmBreakpoint = 'xs' | 'sm' | 'md' | 'lg' | 'xl' | 'xxl';
declare const TM_BREAKPOINTS: { readonly sm: 576; readonly md: 768; readonly lg: 992; readonly xl: 1200; readonly xxl: 1440 };

@Injectable({ providedIn: 'root' })
declare class TmBreakpoints {
  readonly current: Signal<TmBreakpoint>;          // the widest breakpoint the viewport reaches
  atLeast(breakpoint: TmBreakpoint): Signal<boolean>; // memoized per breakpoint; atLeast('xs') is always true
}
```

- **How it measures.** Five `matchMedia('(width >= Npx)')` lists with `change` listeners feed one
  signal. No resize listener, no layout read, nothing on the main thread between changes.
- **What it is for.** Page-level structure only: grid vs tiles default, drawer vs popover, launcher
  full screen. Components adapt with **container queries in CSS**, never with `TmBreakpoints`, so a
  component behaves the same in a narrow card on a wide screen.
- **Container-query rule.** A component that adapts sets `container-type: inline-size` on an inner
  wrapper (or a `display: block` host whose width never depends on its content) and queries
  `@container (width >= 576px)`.

**Example —** the bell panel picks its surface (0028):

```ts
private readonly wide = inject(TmBreakpoints).atLeast('lg');
protected open(): void { this.wide() ? this.popover().open(this.bell()) : this.modal.open(TmBellPanel, { placement: 'end', title }); }
```

**The lint rule `tm/allowed-breakpoints`** (new stylelint plugin, `client/tools/stylelint/`):

- **Where it applies.** Every `@media` and `@container` prelude in `projects/core/**`,
  `projects/module/**`, `projects/locale/**` CSS. The showcase is exempt. Distributions get it through
  0024's `@tellma/core-tools` stylelint preset (request R-2).
- **Width features must use range syntax with `>=` or `<` and a value from the set:** `width`,
  `inline-size`; for example `(width >= 768px)`, `(width < 576px)`, `(576px <= width < 992px)`.
- **Refused:** `min-width`, `max-width`, `min-inline-size`, `max-inline-size`, `device-width`, the
  `<=` and `>` operators, any unit but `px`, any other value. The message names the nearest
  threshold and the canonical form.
- **Unrestricted:** `height`, `orientation`, `pointer`, `hover`, `prefers-*`, `forced-colors`.
- **One source.** The rule's set is a literal; a `lint:test` case imports `TM_BREAKPOINTS` and asserts
  the two are equal.

**Existing code that changes:** `modal/internal/tm-modal-shell.css` `@media (max-width: 600px)` becomes
`@media (width < 576px)` (Part D, D.2). No other width query exists in the library.

**Tests:** unit — `TmBreakpoints` at 390, 576, 767, 768, 1440 px (vitest browser viewport), memoized
signals, `atLeast('xs')`; `lint:test` — accepted and refused preludes, the parity case. **Budget:**
primary `.` +0.4 KB.

## B.2 `TmTheme` and the System theme (0002 §4)

The library resolves System to light or dark and writes the effective value; persistence is the
app's.

```ts
// @tellma/core-ui (primary, folder theme/)
type TmThemeSetting = 'system' | 'light' | 'dark';
interface TmThemeOptions { readonly initial?: TmThemeSetting | (() => TmThemeSetting) } // default 'system'

@Injectable({ providedIn: 'root' })
declare class TmTheme {
  readonly setting: Signal<TmThemeSetting>;
  readonly effective: Signal<'light' | 'dark'>;   // setting, or the OS preference under 'system'
  set(setting: TmThemeSetting): void;              // writes <html data-theme> in the same task
}
// TmUiOptions gains: readonly theme?: TmThemeOptions;
```

- **The DOM write.** `<html data-theme>` always holds `light` or `dark`, never `system`, so the
  emitted CSS stays two-state. `set()` writes synchronously; a theme click repaints in its frame.
- **System.** Under `system`, a `matchMedia('(prefers-color-scheme: dark)')` listener updates
  `effective` and the attribute; under `light`/`dark` the listener is detached.
- **Startup.** With `provideTellmaUi({ theme })`, an environment initializer constructs `TmTheme`
  with `initial`, so OS changes are followed from boot. Without the option, `TmTheme` is created on
  first inject with `system`. The seed must equal what `tm-boot.js` already painted, so the first
  write is a no-op (no flash).
- **`color-scheme`.** The tokens emitter (`core-ui-tokens/emit/emit-css.ts`) adds `color-scheme:
  light` to the `:root, [data-theme=light]` block and `color-scheme: dark` to `[data-theme=dark]`,
  so native scrollbars, form controls and autofill follow the theme.
- **Forced colors** stay untouched by `TmTheme`.

**Example —** `@tellma/core` wires the seed and the one persistence write (0024/0025):

```ts
provideTellmaUi({ theme: { initial: () => store.boot.read().theme } });
effect(() => store.boot.patch({ theme: inject(TmTheme).setting() })); // inside @tellma/core, not the library
```

**Compatibility:** apps that write `data-theme` themselves (the showcase) are unaffected until they
inject `TmTheme`. **Tests:** unit — set/effective, the media listener attached only under System
(emulated `prefers-color-scheme`), same-task write; tokens — the emitted sheet carries both
`color-scheme` declarations; e2e — the session-menu-like toggle repaints with no
`data-theme=system`; axe light and dark unchanged. **Budget:** primary +0.5 KB.

## B.3 Translations loader seam and live direction (0002 §5, §7)

`provideTellmaUi` keeps owning Transloco; the app fills the strings and flips `<html dir>`.

```ts
type TmUiTranslationTable = { readonly [key: string]: string | TmUiTranslationTable };
type TmUiTranslationsLoader = (request: { readonly lang: string; readonly scope: string | null }) => Promise<TmUiTranslationTable>;

interface TmUiOptions {                          // old: { forms?, availableLangs? }
  readonly forms?: TmFormsOptions;
  readonly availableLangs?: readonly string[];  // boot-time list; runtime changes via TranslocoService.setAvailableLangs
  readonly translations?: TmUiTranslationsLoader; // new: registered as the Transloco loader
  readonly theme?: TmThemeOptions;               // new (B.2)
}
```

- **What the loader returns is merged, never replaced.** Transloco merges a loaded table into the
  language's existing translation, so the library's `tmUi` English and a locale pack's `tmUi` Arabic
  (registered through `setTranslation(…, { merge: true })`) survive any load order. A root load
  (`scope: null`) carries the server pack at the root and the `tm` scope under `tm` (00-architecture
  §11 merge order).
- **Fallback loads.** With `useFallbackTranslation`, loading `ar` also loads `en` through the same
  loader; the app returns English server keys there.
- **The library never calls `load`.** `TM_UI_TRANSLATE` re-resolves on `translationLoadSuccess` and
  `langChanges$` (already implemented in `i18n/tm-ui-translate.ts`). The activation sequence (await
  `load(lang)`, then `setActiveLang(lang)`) is 0024's `TmLocalization`; a language switch is then one
  synchronous re-render.
- **No loader** keeps today's behaviour (English plus locale packs).

**Live direction.** `provideTellmaUi` provides `{ provide: Directionality, useClass:
ɵTmLiveDirectionality }` at the root:

- **What it watches.** A `MutationObserver` on the `dir` attribute of `<html>` and `<body>` (body
  first, as CDK's root does). On change it sets the inherited `valueSignal` and emits `change`.
- **The documented host is `<html dir>`.** The app flips `document.documentElement.dir` (and `lang`)
  and every library surface follows: open and future modals (D.2), connected overlays at their next
  attach, the grid's arrow mapping (`grid-base.ts` already subscribes to `change`), submenu sides.
- **`[dir]` islands** (CDK `Dir`) still override locally; the showcase's wrapper becomes optional.

**Compatibility:** additive. **Tests:** unit — a loaded table merges with a pre-registered `tmUi`
pack in both orders; `en` fallback load; `TM_UI_TRANSLATE` re-renders after a load; live
`Directionality` emits on `<html dir>` and `<body dir>` changes. e2e — flip `dir` with a modal open
and with a menu closed, then open it: both RTL. **Budget:** primary +0.5 KB (loader adapter +
observer).

## B.4 `tm-multi-select` and option groups (0002 §3.4)

A closed-list multi-select and option headings, on the same `tm-option` definitions.

```ts
// @tellma/core-ui/select — new
@Component({ selector: 'tm-option-group' })
declare class TmOptionGroup {
  readonly label = input.required<string>();     // visible heading; the group's accessible name
}

@Component({ selector: 'tm-multi-select' })     // implements TmFormFieldControl, FormValueControl<readonly T[]>
declare class TmMultiSelect<T> {
  readonly value = model<readonly T[]>([]);      // always in OPTION order, never click order
  readonly valueKey = input<((value: T) => string | number) | undefined>(undefined);
  readonly displayWith = input<((value: T) => string) | undefined>(undefined);
  readonly placeholder = input<string | undefined>(undefined);
  readonly size = input<TmControlSize | undefined>(undefined);
  // disabled, readonly, required, invalid, touched, dirty, pending, errors, aria-label,
  // aria-describedby, touch: exactly as TmSelect
  readonly selectionChange = output<readonly T[]>();
  readonly opened = output<void>(); readonly closed = output<void>();
}
```

```html
<tm-form-field label="Center type">
  <tm-multi-select [formField]="filter.types">
    <tm-option-group label="Operating">
      <tm-option value="Service">Service</tm-option>
      <tm-option value="Operation">Operation</tm-option>
    </tm-option-group>
    <tm-option value="Sale">Sale</tm-option>
  </tm-multi-select>
</tm-form-field>
```

**Behaviour (`tm-multi-select`):**

- **Panel.** The same combobox + listbox wiring as `tm-select`, with `ngListbox [multi]="true"`,
  `aria-multiselectable="true"` and a checkbox glyph per row (the `tm-checkbox` box, drawn with the
  grid's mask so it costs no component).
- **Toggle, stay open.** Click, Space and Enter toggle the active option and keep the panel open.
  Escape, Tab and outside press close. Home/End and typeahead work on the open panel.
- **Trigger.** One line, fixed height: the selected labels joined with `Intl.ListFormat(locale, {
  type: 'unit', style: 'narrow' })`, ellipsized; the placeholder when empty. The accessible value is
  the full list.
- **Values not in the options** are kept (never pruned) and shown through `displayWith`, else
  `String(value)`, with a dev warning, as `tm-select` does.
- **Not a grid editor.** Grid cells hold scalars; `tm-multi-select` implements no `TmCellEditor`.

**Behaviour (`tm-option-group`, both selects):**

- **Markup.** Each group renders `<li role="group" aria-labelledby>` holding a non-option heading row
  and its options. The heading has the option height, so the panel's measured height is stable.
- **Navigation** skips headings (they are not options); typeahead searches options only.
- **Nesting** is one level; a group inside a group is a dev error.
- **Definition directives.** Groups are content definitions like `tm-option` (aria's `ngOption`
  cannot be projected, f07 §2.12); `tm-select` reads `contentChildren(TmOption, { descendants: true })`
  for the flat order and `contentChildren(TmOptionGroup)` for headings.

**Keyboard and ARIA:** as `tm-select` (select-only combobox, active-descendant); options carry
`aria-selected`; the group's `aria-labelledby` names it. **RTL:** the check glyph sits at the inline
end, as in `tm-select`. **Compatibility:** `tm-select` without groups renders identically.
**Harness:** `TmMultiSelectHarness` (`open`, `toggle(label)`, `getValueText`, `isOptionSelected`);
`TmSelectHarness.getGroups()`. **Tests:** unit — option-order value, toggle keeps open, unmatched
values, group navigation skips headings; e2e + axe — both selects with groups, LTR/RTL, light/dark.
**Budget:** `./select` 6.04 → ≈ 8.4 KB; ceiling **8 → 9**.

## C.1 Row activation (0004 §8.3, §8.8; Decision 18 replaced)

Readonly list grids open a row with a click anywhere or Enter; ranges and copy keep working.

```ts
// ɵTmGridBase — new members
readonly rowActivation = input<'none' | 'row'>('none');   // 'row' requires a readonly grid (dev error otherwise)
readonly rowActivate = output<TmGridRowActivation<T>>();

interface TmGridRowActivation<T> {   // @tellma/core-ui/grid
  readonly row: T;
  readonly rowId: TmRowId;
  readonly via: 'pointer' | 'keyboard';
  readonly newTab: boolean;          // Mod held, or the middle button: the consumer opens a new tab
}
```

**What activates under `rowActivation: 'row'`:**

| Gesture | Result |
|---|---|
| Press and release on a data cell, no movement past 4 px, no modifier | the active cell moves on press (instant highlight); `rowActivate {via: 'pointer', newTab: false}` on release |
| The same with Mod (Ctrl, ⌘) or the middle button (`auxclick`) | `rowActivate {newTab: true}` |
| Press and drag | range selection (unchanged); no activation |
| Shift+click | extends the range (unchanged); no activation |
| Mod+drag | adds a range (unchanged) |
| Click on interactive cell content (`a[href]`, `button`, inputs, `[tabindex]`) | native behaviour only (the router link, the button); no activation |
| Checkbox cell, select-all header, expander, row header, resize handle | their own behaviour; never activation |
| Touch tap | activation (the tap path of `onTouchTap`) |
| Enter on the active cell | `rowActivate {via: 'keyboard', newTab: Mod held}` |
| F2 on the active cell | the old readonly Enter: actuates the cell's first interactive child (`activateCellLink`) |
| A second activation of the same row within 400 ms | ignored, so a double-click opens once |

- **`'none'` (default)** keeps every behaviour of today, Enter included.
- **Visual.** The active row carries `tm-grid__row--active`: a row tint (`--grid-active-row-bg`, new
  token, `surface.selected`) and a 2 px inline-start accent bar on the first painted cell (the
  sketch's highlight). The ring stays on the active cell. Rows show `cursor: pointer`.
- **Accessibility.** The scroller gains `aria-describedby` to a visually hidden hint
  (`tmUi.grid.rowActivationHint`: "Press Enter to open a row. Press F2 to reach a link in a cell.").
  Roles are unchanged (`grid`, `row`, `gridcell`).
- **Search Q1 (00-architecture §10.1).** The search page sets `rowActivation="row"` and renders the
  display-name and navigation cells as real `<a [routerLink]>` links in `*tmGridDisplay`, so
  open-in-new-tab, copy-link and other-entity links stay native.

**Example —** a list screen (0030 writes this inside its host; distributions write nothing):

```html
<tm-grid gridId="search.acme.Customer" [data]="rows()" [rowId]="byId" selectable rowActivation="row"
         [rowHeaders]="false" [(selectedIds)]="selected" [(activeRowId)]="active" [(orderBy)]="order"
         (rowActivate)="open($event)">
  …columns…
</tm-grid>
```

## C.2 External active row and the keyboard driver (0004 §5.1, §8.2)

The page drives the highlight while focus stays in its search field.

```ts
// ɵTmGridBase — new members
readonly activeRowId = model<TmRowId | null>(null);  // two-way: the active cell's row
moveActiveRow(by: number | 'first' | 'last'): void;  // clamped, never wraps; keeps the active column
activateRow(rowId?: TmRowId, options?: { newTab?: boolean }): boolean; // emits rowActivate {via: 'keyboard'}; false when absent

// @tellma/core-ui/grid — new directive and the face it drives (both grids implement it)
interface TmGridDriverTarget {
  readonly activeRowId: Signal<TmRowId | null>;
  moveActiveRow(by: number | 'first' | 'last'): void;
  activateRow(rowId?: TmRowId, options?: { newTab?: boolean }): boolean;
}
@Directive({ selector: 'input[tmGridDriver]' })
declare class TmGridDriver {
  readonly tmGridDriver = input.required<TmGridDriverTarget>(); // an interface, so TmGrid<Customer> binds without variance friction
}
```

- **The model.** Every change of the active cell's row writes `activeRowId` (click, arrows, data
  reconcile). A consumer write moves the active cell to that row (the current column, else the first
  data column), scrolls it into view (`nearest`) and never moves DOM focus. An id not in the data is
  ignored and the model is rewritten with the actual row, or `null` when the grid is empty.
- **The driver** handles keydown on its input, ignoring IME composition and other modifiers:

  | Key | Effect |
  |---|---|
  | ArrowDown / ArrowUp | `moveActiveRow(+1 / −1)`; with no active row, ArrowDown goes to the first row |
  | PageDown / PageUp | moves by the visible row count |
  | Enter | `activateRow()` when a row is active (Mod → `newTab`); otherwise the input's own Enter |

  Every other key (Home, End, Left, Right, Space, characters) stays with the input.
- **ARIA.** The driver sets `aria-controls` to the grid's scroller id and `aria-activedescendant` to
  the active row's element id. The active row is always rendered (0004 §4), so the reference never
  dangles. ARIA 1.2 lets a textbox or searchbox reference an element in the container it controls
  (§13).
- **Who seeds the first row.** The page: 0030 writes `activeRowId` to the first row id when new
  results land while focus is in its field.

**Example —** the search field: `<input tmInput type="search" [tmGridDriver]="grid" … />`.

## C.3 Sort state and `aria-sort` (0004 §6.1, §14; the Non-goals stand)

The grid shows and edits one sort; the consumer orders the data.

```ts
interface TmGridSort { readonly key: string; readonly direction: 'asc' | 'desc' }  // key = the column key
// ɵTmGridBase
readonly orderBy = model<TmGridSort | null>(null);
// TmGridColumn
readonly sortable = input(false, { transform: booleanAttribute }); // requires `key` (dev error)
```

- **Cycle.** A click on a sortable header (press and release, no drag, no modifier) cycles
  `asc → desc → null`; a click on another sortable column sets `{key, 'asc'}` (one column in v1).
  A drag across headers still selects columns; Shift/Mod+click keep their selection meaning.
  Non-sortable headers keep press-to-select.
- **Indicator.** Sortable headers reserve a 14 px slot after the label (`arrow-up` / `arrow-down`,
  Lucide-derived inline SVG, `aria-hidden`). The slot is always present, so sorting never shifts the
  label. Hover previews the next direction faintly.
- **ARIA.** The sorted column's `role="columnheader"` carries `aria-sort="ascending" |
  "descending"`; other headers carry none. A change announces `tmUi.grid.announce.sorted` ("Sorted by
  {column}, {direction, select, asc {ascending} other {descending}}") or `sortCleared`.
- **Nothing else happens on change.** No reorder, no selection change; the active cell follows its
  row when the consumer swaps the data (0004 §5.3).
- **RTL.** The arrows are vertical and never mirror; the slot follows the label in reading order.

## C.4 Header navigation and the header action slot (0004 §6.1, §8.2, §14)

A filter button per column header, reachable from the keyboard without adding tab stops.

```ts

interface TmGridHeaderEndContext { readonly $implicit: string; readonly key: string | undefined; readonly sort: 'asc' | 'desc' | null }

// @tellma/core-ui/grid: the header action button

  readonly active = input(false, { transform: booleanAttribute }); // accent styling + a hidden "Active" description

```

**Example —** a column filter button (0030's markup inside its column template):

```html

            [attr.aria-label]="filterLabel('Name')"><tm-icon name="funnel" /></button>
  </ng-template>

```

- **Layout.** Header content runs: label (or `*tmGridHeader`), sort slot, header-end content. The
  action is a 24×24 target (WCAG 2.2 AA) inside the header height. Every column declaring
  `tmGridHeaderEnd` reserves the slot, so toggling `active` moves nothing.
- **Header navigation turns on when any column is `sortable` or declares `tmGridHeaderEnd`:**

  | Key (focus on a header cell) | Effect |
  |---|---|
  | ArrowUp on the first data row | focus moves to the active column's header cell |
  | ArrowDown | back to the first data row, same column |
  | ArrowLeft / ArrowRight, Home / End | between header cells (direction-mapped) |
  | Enter or Space | cycles the sort (sortable columns); toggles select-all on its header |
  | Alt+ArrowDown | clicks the header's first `[tmGridHeaderAction]` (opens the filter) |
  | Tab | leaves the grid (the single tab stop stands) |

- **Focus mechanics.** Header cells carry a roving `tabindex` and `aria-describedby` to a hidden hint
  (`tmUi.grid.headerNavHint`: "Enter to sort. Alt+Down Arrow to filter."). Header actions get
  `tabindex="-1"` (the single-tab-stop sweep extends to header-end content). Focus inside a header
  action counts as header focus of that column, so a popover closing back onto its button continues
  header navigation.
- **Without sortable columns or header actions** headers behave exactly as today (no navigation into
  the header row; projected header content stays in the tab order).
- **Overlays opened from a header** render in place (CDK 22 inline top layer); the grid's existing
  `inOverlay()` filter already ignores their events.

## C.5 Select-all across pages (0004 §8.8)

- **The tri-state** counts only the current `data` rows (as `checkAllState` does today).
- **The toggle** (header click, Space on its header cell, Ctrl+Shift+Space): from `all` it removes the
  current rows' ids and **keeps every other id**; from `none` or `mixed` it adds every current row's
  id to the existing set. Old: the set was replaced by the current rows, or emptied.
- **Announcement.** With no foreign ids: unchanged ("3 of 20 selected"). With foreign ids:
  `tmUi.grid.announce.checkedCountAcross` ("{onPage, number} of {total, number} selected here,
  {selected, number} in all").
- **Compatibility.** Identical to today whenever `selectedIds` holds only current rows.

## C.6 `rowClass` and `rowHeaders` (0004 §4, §7)

```ts
// ɵTmGridBase
readonly rowClass = input<((row: T) => string | readonly string[] | null) | undefined>(undefined);
readonly rowHeaders = input(true, { transform: booleanAttribute }); // false: no row-number column, no corner
```

- **`rowClass`** runs per rendered row (the window only) and must be pure. Classes land on the
  `role="row"` element. Cells paint row backgrounds, so a class styles a row through inherited custom
  properties the cells read: `--tm-grid-row-bg`, `--tm-grid-row-ink`, `--tm-grid-row-weight`.
  Selection, checked and active states paint over them.
- **Two shipped modifiers** cover the platform's needs without consumer CSS: `tm-grid-row--muted`
  (secondary ink: a tree ancestor shown only because a descendant matched) and
  `tm-grid-row--emphasis` (weight 600 on `surface.subtle`: totals rows).
- **`rowHeaders: false`** drops the row-number column and the corner (the search page design has
  none). Mod+A and Shift+Space keep the selections those headers offered by pointer.

**Example —** a tree search marks ancestors: `[rowClass]="r => matched.has(r.Id) ? null :
'tm-grid-row--muted'"`.

## C.7 `scrollbar-gutter` (0004 §4)

- **`.tm-grid__scroller { scrollbar-gutter: stable; }`.** Rows arriving never re-flow `flex` columns on
  classic-scrollbar platforms (Windows, Linux). Overlay scrollbars (macOS default, mobile) reserve
  nothing and need nothing (§13).
- **The gutter's header band** paints the header colour (a two-stop background on the scroller), so the
  header row reads continuous.
- **Compatibility.** On classic-scrollbar platforms proportional columns lose one scrollbar width even
  with no overflow; fixed-width columns are untouched.
- **Test caveat.** Headless Chromium runs without scrollbars; the pinning e2e launches with
  `ignoreDefaultArgs: ['--hide-scrollbars']` and asserts a column's width is equal before and after
  rows load.

## C.8 `scrollToRow` with flash (0004 §4, §12)

```ts
// ɵTmGridBase
scrollToRow(rowId: TmRowId, options?: { flash?: boolean; activate?: boolean; align?: 'nearest' | 'center' }): boolean;
// defaults: flash false, activate true, align 'center'; false when the row is not in the data
```

- **Trees** expand the row's ancestors first (writing `expandedIds`, C.9), as find does.
- **`activate`** moves the active cell to the row without moving DOM focus; the caller focuses
  (`grid.focus()`) when it wants to.
- **Flash.** The row's cells pulse `--grid-flash-bg` (new token, `status.info.bg`) for

- **Timing.** Call it once the row is in `data` (0031 calls it from an effect on its child grid's

**Example —** the child-row deep link `?child=Lines:42` (0031): `grid.scrollToRow(42, { flash: true })`.

## C.9 Tree `expandedIds` and batched `loadChildren` (0004 §12, §13.3)

```ts
// TmTreeGrid
readonly expandedIds = model<ReadonlySet<TmRowId> | undefined>(undefined);    // new; undefined = unbound
readonly loadChildren = input<((rows: readonly T[]) => Promise<void>) | undefined>(undefined);
// old: loadChildren?: (row: T) => Promise<void>
```

- **Precedence at content bind:** a bound `expandedIds`, then the state store's expansion slice, then
  `defaultExpandedDepth`. While bound, the store's expansion slice is neither read nor written.
- **Two-way.** A user expand adds the id at request time (the spinner shows); a collapse removes it;
  collapsing an ancestor of the active cell removes that ancestor only. A failed load removes its
  batch's ids and announces once.
- **Unknown ids are kept, never pruned:** a remembered grandchild arrives with a later batch, and a
  search may hide rows the next query brings back.
- **Batching.** The grid collects every row that is in `expandedIds`, marked `hasChildren`, and has no
  loaded children, then calls `loadChildren` once with them, in model order:
  1. at content bind and restore (this replaces `collapseUnloadedLazyRows`, which collapsed them);
  2. after a batch resolves, for the rows it brought in that are themselves in `expandedIds` (level by
     level);
  3. for user expands landing in the same task (coalesced in a microtask).
- **Engine: no change.** A bound set seeds through the existing bulk `TmGridEngine.restoreExpansion(ids)`
  (one flatten for a 500-id restore); user toggles keep using `setExpanded`.
- **Lifecycle.** A content switch or destroy discards in-flight completions (the existing
  `lazyLoadGeneration` guard). The consumer appends rows to its own array, as today.

**Example —** the remembered Centers tree (0030 with 0025's `TmTreeExpansion`):

```html
<tm-tree-grid gridId="search.gl.Center" [data]="rows()" [rowId]="byId" [parentId]="parentOf"
              [hasChildren]="hasKids" [loadChildren]="loadMany"
              [expandedIds]="expansion()" (expandedIdsChange)="remember($event)">
```

- **Compatibility.** `loadChildren` changes signature; the showcase tree story and the tree-grid specs
  migrate to `rows => …`, and the API golden records it. No other consumer exists.

- **Submenus** use aria's `MenuItem.submenu` input with a second anchored overlay (`inline-end`, align

  in RTL) or Escape, one level per press; each level pushes its own entry on the shared Escape stack.
  An activation anywhere closes the whole tree. A submenu inside a submenu is a dev error.
- **Groups** render `role="group"` with `aria-labelledby` on a non-focusable heading, and a divider
  above every group but the first. Radio items must sit in a group (dev warning).
- **Checkable items** bind `role` and `aria-checked` (aria's `MenuItem` has a `role` input but no

- **Links** render `<a ngMenuItem [href] [attr.target] rel="noopener">`. A plain click or Enter runs
  `action()` with `preventDefault` when present, else follows the link; Ctrl, ⌘, Shift and
  middle-click stay native. The panel's `contextmenu` suppression skips links, so "Copy link address"
  works.
- **Header slot.** `ng-template[tmMenuHeader]` renders above the list, outside `role="menu"`; the
  menu's `aria-describedby` references it, so it is read on open. It holds no interactive content
  (dev warning).
- **Typeahead** reads the label only; `detail` joins the accessible name ("Language, English");
  `shortcut` stays `aria-hidden`.
- **RTL.** The submenu side and its arrow keys mirror through the live `Directionality` (B.3).
- **Compatibility.** Existing `items` arrays render identically; `TmMenuItem.action` stays required;
  `itemSelected` still emits `TmMenuItem` (links and submenu parents never emit it).

## D.2 `TmModal`: the drawer, live direction, the `sm` breakpoint (0005 §10)

```ts

```

**Placement `'end'` (ruling 1):**

- **Geometry.** Docked to the inline-end edge (right in LTR, left in RTL) through CDK's

## D.4 Date-time, time of day and relative time (0005 §2.2)

The closed cross-platform format set gains three formats over **instants**, each with golden rows.

```ts
// @tellma/core-ui/l10n — pure, DOM-free, DI-free
type TmTimeStyle = 'short' | 'medium';  // short: hour + minute; medium: + seconds; hour cycle per locale
interface TmDateTimeFormatOptions {
  readonly timeZone: string;             // IANA id, required
  readonly calendar?: TmCalendar;        // default Gregorian
  readonly dateStyle?: TmDateStyle;      // default 'numeric'
  readonly timeStyle?: TmTimeStyle;      // default 'short'
}
interface TmTimeFormatOptions { readonly timeZone: string; readonly timeStyle?: TmTimeStyle }
interface TmRelativeTimeFormatOptions {
  readonly now: number;                  // epoch ms; the caller's clock
  readonly timeZone: string;             // decides calendar days
  readonly calendar?: TmCalendar;        // for the absolute fallback
  readonly form?: 'relative' | 'age';    // default 'relative'
  readonly style?: 'long' | 'short' | 'narrow'; // default 'short'
}
declare function tmFormatDateTime(instant: string | null | undefined, locale: string, options: TmDateTimeFormatOptions): string;
declare function tmFormatTime(instant: string | null | undefined, locale: string, options: TmTimeFormatOptions): string;
declare function tmFormatRelativeTime(instant: string | null | undefined, locale: string, options: TmRelativeTimeFormatOptions): string;
```

- **Instants** are ISO 8601 strings with `Z` or a `±hh:mm` offset (the wire form of
  `DateTimeOffset`). A fraction longer than three digits is truncated to milliseconds before parsing
  (ECMAScript only defines three). `''`, `null` and `undefined` format as `''`; a string with no
  offset, or malformed, is returned as-is with a dev warning (the date codec's posture).
- **Date-time** uses the date style's fixed skeleton plus `hour: 'numeric', minute: '2-digit'`
  (`medium` adds `second`), `timeZone` and the calendar id, then strips the era like
  `tmFormatDate` (`ɵtmFormatWithoutEra`).
- **Relative time thresholds** (Δ = `now − instant`; truncation, never rounding up):

  | |Δ| | Unit | `relative` (`Intl.RelativeTimeFormat`, `numeric: 'auto'`) | `age` (`Intl.NumberFormat` unit) |
  |---|---|---|---|
  | < 60 s | — | "now" | "now" (the relative form's word) |
  | < 60 min | minutes | "2 min. ago", "in 5 min." | "2 min" |
  | < 24 h | hours | "3 hr. ago" | "3 hr" |
  | ≥ 24 h and < 7 calendar days in `timeZone` | days (calendar-day difference) | "yesterday", "3 days ago" | "3 days" |
  | otherwise | — | the absolute date, `tmFormatDate` style `medium` in `timeZone` and `calendar` | same |

  Strings shown are en-US with `style: 'short'`; every locale's output is CLDR's, pinned by the
  golden. `age` is for compact lists (the bell, the tray); future instants in `age` form format as
  the absolute date.
- **The facade.** `TmL10n` gains `timeZone: Signal<string>` and three reactive methods reading
  `locale`, `calendar` and `timeZone` first:

```ts
// @tellma/core-ui (primary)
declare const TM_TIME_ZONE: InjectionToken<Signal<string>>; // default: the browser's resolved zone; @tellma/core provides the user's
// TmL10n
formatDateTime(instant: string | null | undefined, options?: { dateStyle?: TmDateStyle; timeStyle?: TmTimeStyle }): string;
formatTime(instant: string | null | undefined, options?: { timeStyle?: TmTimeStyle }): string;
formatRelativeTime(instant: string | null | undefined, options: { now: number; form?: 'relative' | 'age'; style?: 'long' | 'short' | 'narrow' }): string;
```

**Example —** a dashboard caption (0035): `l10n.formatTime(widget.refreshedAt)` → "10:42 AM" for
`2026-10-20T07:42:00Z` in `Asia/Riyadh`, en-US; `l10n.formatRelativeTime(row.createdAt, { now:
clock(), form: 'age' })` → "2 min". The ticking `now` belongs to 0023's `tm-relative-time`.

- **The golden.** `l10n/format-golden.json` gains `dateTime`, `time` and `relative` arrays: rows of
  `{ locale, timeZone, calendar, dateStyle, timeStyle, instant, expected }` and `{ locale, timeZone,
  now, instant, form, style, expected }`, over the date rows' locales and the zones `UTC`,
  `Asia/Riyadh`, `Africa/Addis_Ababa` and `Asia/Beirut` (DST, for day-boundary rows). The server twin
  reads the same file; the formats widen the contract it must meet.
- **No wall-clock time type.** A time of day without an instant (a `TimeOnly`) has no consumer and
  stays out.
- **Budget:** `./l10n` 7.65 → ≈ 8.9 KB, ceiling 8 → **9**; primary facade and token within B's 7.

## D.5 `TmClientCache.clearAll` sweep (0005 §2.3)

`clearAll` deletes every `tm`-named browser store, except what its caller keeps.

```ts
type TmClientCacheArea = 'cache-storage' | 'indexeddb' | 'local-storage' | 'session-storage';
interface TmClientCacheClearOptions { readonly keep?: (name: string, area: TmClientCacheArea) => boolean }
declare class TmClientCache {
  clearAll(options?: TmClientCacheClearOptions): Promise<void>; // old: clearAll(): Promise<void> (CacheStorage only)
}
```

- **The naming rule** (00-architecture §11): CacheStorage caches and IndexedDB databases are named
  `tm-…`; `localStorage` and `sessionStorage` keys are named `tm.…`. The Angular service worker's
  `ngsw:…` caches never match.
- **What it deletes,** in parallel, minus `keep`:
  - CacheStorage `tm-*` (today `tm-images-v1`);
  - IndexedDB `tm-*`, enumerated with `indexedDB.databases()` (Baseline since May 2024; where absent,
    this area is skipped);
  - `localStorage` keys `tm.*`;
  - this tab's `sessionStorage` keys `tm.*` (other tabs clear their own on the sign-out broadcast,
    0025).
- **Blocked deletes never hang it.** A database delete resolves `clearAll`'s part on `success`,
  `error` or `blocked`. A blocked delete stays queued, and **later opens of that database wait behind
  it**, so the rule for every opener of a `tm-*` database is: close the connection on `versionchange`.
  0025's `TmClientStore` keeps `tm-app` out of `clearAll` (below), so the rule matters only for
  databases a future feature adds.
- **Best effort,** never throws, as today.
- **The library knows nothing of the boot record.** The caller keeps what it sweeps itself.

**Example —** the sign-out sweep in 0025 (the expiry path also keeps drafts):

```ts
await store.sweep('session-ended');   // key-range deletes in tm-app; tm.boot user fields cleared
await cache.clearAll({ keep: (name) => name === 'tm-app' || name === 'tm.boot' });
// expiry: keep: (name) => name === 'tm-app' || name === 'tm.boot' || name.startsWith('tm.draft:')
```

- **Tests:** unit (browser mode) — each area deleted, `keep` honoured per area, a blocked IndexedDB
  delete (a second open connection that ignores `versionchange`) resolves, a missing
  `indexedDB.databases` skips IndexedDB, `ngsw:` caches untouched.
- **Budget:** primary +0.3 KB (within B's 7).

## D.6 `TM_BLOB_FETCHER` cancellation (0005 §7.1, §7.2)

```ts
interface TmBlobFetchOptions {
  readonly ifNoneMatch?: string;
  readonly signal?: AbortSignal;   // new: aborts the request; a fetcher rejects with signal.reason
}
```

- **`tm-image`** aborts its wait when it is destroyed, its `src` or `etag` changes, or it leaves the
  `defer` viewport before the bytes arrive.
- **The blob cache's coalescing is reference-counted.** The shared request for a URL gets its own
  `AbortController`, aborted only when every waiter has aborted; a background revalidation is
  aborted when no instance of that URL remains. An aborted request writes nothing to `tm-images-v1`
  and shows no error placeholder.
- **The default fetcher** (over `HttpClient`) subscribes, unsubscribes on abort (which aborts the
  XHR or fetch backend) and rejects with `signal.reason`. 0024's fetcher over `fetch` passes the
  signal straight through.
- **Compatibility.** `signal` is optional, so custom fetchers that ignore it still work (without
  cancellation).
- **Tests:** unit — destroy mid-fetch aborts, two instances on one URL abort only when both go, a
  revalidation aborts when the last instance goes, no cache write after abort.
- **Budget:** `./image` 9.66 → ≈ 9.8 KB, ceiling 10 (unchanged; headroom 0.2).

## E.2 `tm-entity-multi-picker` (0006 §2, §3, §4, §6; the multi-select non-goal lifted)

Several entities chosen in one field, shown as chips, with the single picker's search lifecycle.

```ts
// @tellma/core-ui/entity-picker — new; implements TmFormFieldControl, FormValueControl<readonly Id[]>
@Component({ selector: 'tm-entity-multi-picker' })
declare class TmEntityMultiPicker<T, Id extends TmEntityId = TmEntityId> {
  readonly value = model<readonly Id[]>([]);                  // in pick order; never duplicates
  readonly search = input.required<TmEntitySearchFn<T>>();
  readonly itemId = input.required<(item: T) => Id>();
  readonly itemLabel = input.required<(item: T) => string>();
  readonly itemDescription = input<((item: T) => string | null) | undefined>(undefined);
  readonly displayWith = input<((id: Id) => string | null) | undefined>(undefined); // chip labels
  readonly advancedSearch = input<TmEntityPickerPage | undefined>(undefined);
  readonly create = input<TmEntityPickerPage | undefined>(undefined);
  readonly maxItems = input<number | undefined>(undefined);
  // placeholder, searchDebounce, createLabel, aria-label, aria-describedby, disabled, readonly, required,
  // invalid, touched, pending, errors, touch: as TmEntityPicker. No `edit`.
  readonly picked = output<TmEntityPicked<T, Id>>();          // each addition
  readonly removed = output<Id>();                            // each removal
  focus(): void; openDropdown(): void;
}
// TmEntityPickerPageData gains: readonly multiple?: true; readonly ids?: readonly Id[];
// a page opened with multiple may close with readonly TmEntityPick[] (each new id is added)
```

**Example —** the navigation `in:` column filter (0029 binds it inside its filter control):

```html
<tm-form-field label="Parent">
  <tm-entity-multi-picker [formField]="filter.parents" [search]="centers.search" [itemId]="byId"
                          [itemLabel]="centers.label" [displayWith]="centers.labelOf" [maxItems]="50" />
</tm-form-field>
```

**Composition.** The field holds a chip row (0023's `tm-chip`, request R-1) and an inner
`tm-entity-picker` in an internal `ɵcommitMode: 'emit'`:

- **`'emit'` changes only the post-commit step** of the single picker: a commit (list, auto-resolution
  on blur or Enter, create page) emits `picked` and returns the inner picker to empty and pristine; its
  own `value` stays `null`; the settled answer is retired; the panel stays open on the browse list.
  Search, debounce, abort, resolution and the footer rows are the single picker's, untouched.
- **Toggle.** The multi-picker passes its chosen ids in (`ɵchosenIds`): those rows show the check and
  `aria-selected="true"`, the listbox is `aria-multiselectable`, and picking a chosen row removes it.
- **Advanced search** opens with `{ multiple: true, ids }`; a page returning an array adds every id not
  yet chosen; a single pick adds one. Create adds the created entity. Edit is not offered.
- **`maxItems`** reached: further picks are refused with the status message
  `tmUi.entityPicker.maxItems` ("You can choose up to {max, number}"), announced politely.

**Field, chips and stable layout:**

- **One line, fixed height** (the size ladder). Chips sit before the input; when they overflow, the
  chip row scrolls horizontally (scrollbar hidden; wheel, trackpad and keyboard scroll it) and a
  fixed-width count badge at the inline end shows the total. The field never grows, so nothing below
  it moves.
- **Chip labels** follow the single picker's ladder: `displayWith(id)`, else the pick's label memo,
  else `String(id)` with a dev warning.

**Keyboard:**

| Key | Where | Effect |
|---|---|---|
| typing, ArrowDown, Alt+ArrowDown, Enter, Tab, Escape | input | as the single picker (0006 §4.3), with toggle semantics |
| ArrowLeft (ArrowRight in RTL) at caret start | input | focus moves to the last chip |
| ArrowLeft / ArrowRight, Home / End | chips | roving focus between chips (direction-mapped); past the last chip back to the input |
| Backspace | empty input | first press focuses the last chip; a second press removes it |
| Backspace / Delete | chip | removes it; focus moves to the next chip, else the input |

**ARIA:** the input stays the combobox; the chip row is `role="list"` of `role="listitem"`, each with a
remove button named `tmUi.entityPicker.removeChip` ("Remove {label}"); the input's
`aria-describedby` adds a hidden summary (`selectedSummary`: "{count, plural, one {# selected} other {#
selected}}: Jeddah, Riyadh"); additions and removals announce `announce.added` / `announce.removed`.

- **Grid.** No multi cell editor (grid cells hold scalar ids).
- **Compatibility.** `tm-entity-picker` without `ɵcommitMode` is unchanged; the entry point's budget
  rises, but apps that import only `TmEntityPicker` tree-shake the multi-picker (`sideEffects: false`).
- **Harness:** `TmEntityMultiPickerHarness` (`getChipLabels`, `removeChip(label)`, `search(text)`,
  `pick(label)`, `getCountBadge`).

## 11. Review flags

1. **Enter opens the row; F2 reaches a cell's link** (C.1). Alternative: Enter actuates a cell link
   when the active cell has one, else opens the row. Flips if keyboard users mostly follow
   navigation links from lists.
2. **Header navigation only when a column is sortable or has a header action** (C.4). Alternative:
   always navigable headers. Flips if consistency across grids proves more valuable than zero change
   for line-entry grids.
3. **Mod+click opens a new tab in row mode** (C.1), giving up Mod+click "add a range" (Mod+drag keeps
   it). Flips if users multi-range-copy from search results by clicking.
4. **The sort cycle includes "none"** (brief) rather than asc ↔ desc only. Flips if users find the
   third click surprising.
5. **`loadChildren` becomes batch-only, a breaking signature** (C.9). Alternative: an additive
   `loadChildrenBatch`. Flips if an external consumer of 0.x appears before Part C ships.
6. **Grid ceiling re-baselined to 42 KB with no split** (C.11). Alternative: the readonly/editable
   split pass now (≈ 8–10 KB off the search route). Flips if 0024's search route budget is exceeded.
7. **The multi-picker composes the single picker through `ɵcommitMode`** (E.2). Alternative: a
   separate state machine. Flips if emit mode destabilises the single picker's suite.
8. **Chips scroll in one line with a count badge** (E.2). Alternative: wrapping chips that grow the
   field. Flips if users miss chosen items hidden by the scroll.
9. **Sibling components (`tm-multi-select`, `tm-entity-multi-picker`)** rather than a `multiple` input
   (B.4, E.2). Flips only if Angular gains input-dependent model types.
10. **Relative-time thresholds and truncation; absolute date from 7 calendar days** (D.4). Flips with
    design feedback on "2 d" vs "Oct 18".
11. **Submenus one level deep** (C.10). Flips with a consumer needing a second level.
12. **Fixed popover widths 320/440/640** (D.3) and drawer widths 360/480/720 (D.2). Flips with design
    review of the filter, column editor and bell panels.
13. **Live direction by a root `MutationObserver` on `<html dir>`** (B.3). Alternative: an explicit
    `setDirection` call. Flips if a distribution needs per-region directions outside `[dir]` islands.
14. **`clearAll({ keep })` instead of a boot-record-aware sweep** (D.5). Flips if more callers than
    0025 need the same `keep` set (then a named preset).
15. **`TmTheme` constructed at startup only when `provideTellmaUi({ theme })` is passed** (B.2).
    Alternative: always. Flips if an app forgets the option and loses System tracking.
16. **CSS range syntax only** (B.1). Alternative: also `min-width:`. Flips if an embedded browser the
    customers use predates Safari 16.4 or Firefox 102.

## 12. Challenges to the architecture

1. **§6.4 Part D: "`clearAll` … sparing the boot record's device fields."** The library cannot know
   the boot record, and deleting every `tm-*` IndexedDB database would delete `tm-app` with its
   device partition and queue every later `open()` behind a delete another tab blocks (MDN, §13).
   Followed as: `clearAll({ keep })`; 0025 keeps `tm-app` and `tm.boot` and sweeps them itself (D.5,
   R-3).
2. **§6.4 Part D: "live `direction`" on `TmModal`.** A `direction` option would give dialog content a
   static `Directionality` (CDK `Dialog`), and every other global overlay would need the same patch.
   Followed as: a live root `Directionality` in Part B (B.3) that modals, overlays and grids all read.
3. **§9: "tokens" for breakpoints.** CSS custom properties cannot appear in media or container
   queries. Followed as: no breakpoint tokens; `TM_BREAKPOINTS` and the lint rule are the two homes,
   pinned equal by a test (B.1).
4. **§6.4 Part B cites "0002 §4, §8" for breakpoints.** 0002 §8 is the performance budget. The
   amendment targets §4 (a new subsection) and §1 (lint).
5. **Ruling 3 vs D.1.** `@tellma/core-ui/overlay` is a new entry point but holds existing code that
   §6.4 assigns to 0010. Ruling 3 should read "a new component is 0023's; promoting or changing
   existing code is 0010's".
6. **§2.3 still lists `drawer` and a "multi-select input" under 0023.** Ruling 1 removed the drawer;
   the multi-select input duplicates B.4 and E.2. Edit §2.3 (and see R-1).
7. **§5.3: "The platform provides `TM_BLOB_FETCHER` over `TmApi`."** `TmApi` has only POST verbs
   (`read`, `write`, `download`, `send`); blobs are GETs under `/{t}/blobs/`. 0024 needs a GET blob
   method on `TmApi` (with the user check, trace header and `signal`) or a fetcher over `fetch` that
   repeats those checks.
