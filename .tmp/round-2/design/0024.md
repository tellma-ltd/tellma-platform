## 2. Decisions

1. **Routes are derived from declarations** (§9.2) — rule 1. Alt: an `app.routes.ts` per
   distribution (drifts); runtime registration by features (order bugs).
2. **One check, `tmCheckAppConfig`, at dev startup and in the build** through the app's own
   unit-test builder (§3.6) — the builder already links Angular for Node. Alt: a TypeScript AST scan
   (pack declarations are compiled); headless Chromium inside `dotnet publish`.
3. **Metadata are hashed JSON files the client `fetch`es** (§3.2) — `JSON.parse` is faster than an
   object literal, metadata stay out of JS budgets. Alt: JSON `import()` chunks.
4. **`tm-boot.js` is generated** from a platform template plus a config literal (§4.2) — it must
   know the offered languages before Angular; CSP forbids inline script. Alt: a `<meta>` the
   distribution maintains.
5. **`tm-boot.js` rewrites a warm `/` to `/{lastTenantId}`** before Angular starts (§4.2) — the first
   route is the real page. Alt: only the Angular `/` route (an extra navigation per warm launch).
6. **Native lossless JSON** (`context.source`, `JSON.rawJSON`) with a fast path; browser floor
   Baseline 2025 (§10.4) — zero dependency, exact both ways. Alt: `lossless-json` (flag 1).
7. **`@tellma/core` registers the worker** with a `TrustedScriptURL` through a never-emitting
   `registrationStrategy` (§5.4) — Angular's own `register(string)` throws under Trusted Types. Alt:
   a `default` policy (every string sink passes through it).
8. **Read or write is the caller's method; reads require a signal by type** (§10.1) — rule 2C is
   compiler-enforced. Alt: per-route classes in the metadata (challenge 2).
9. **Write watchdog 60 s / 6 min** → `offline` `outcome-unknown` (§10.3) — a black-holed connection
   must not hold the save spinner forever; a sent persist completes server-side (E11). Alt: none.
10. **One error table** (`describe` → `TmErrorView`) serves inline states and dialogs (§11).
11. **Step-up asks once, then redirects** (§8.3). Alt: redirect at once (challenge 3).
12. **Sign-out needs the BFF's answer** (§8.4) — a local-only sign-out would hide a live session.
13. **English formats as `en-GB`** by default (§2.2) — the design's `19 Jun 2026`. Alt: `en-US`.
14. **In a tenant the preferred language wins when offered, even if not a content language**; the
    menu adds it to the content languages (§7.1) — 0013's two axes. Alt: force a content language.
15. **Tenant picker Q1 `/tenants`, Q2 `/{t}`** (note §4).
16. **My account is a stable identity route** `{authority}/account?client_id=&return_url=` (note §6)
    — the Razor page path is an implementation detail; the user returns to the page they left.
17. **`distribution.displayName` comes from `appsettings.json`** at emit time (§3.1) — boot pages and
    titles need it offline; `DistributionInfo` stays the runtime source (flag 10).
18. **The route host shows final-geometry skeletons in the click's frame** (§4.4) — rule 2B;
    `loadComponent` keeps the old page until the chunk resolves.
19. **Reserved words have one source**, C# `TellmaRoutes`, emitted and read by the router, the
    build, the worker config, the dev proxy and 0011's audit (§9.1).

- **`bootstrapTellma(appConfig)`** = `bootstrapApplication(TmApp, …)` with zoneless change

  distribution lists after `provideTellma(…)` in `appConfig` win (the "anything Angular" hatch).

#### §2.3 The merge rule

A§5.1 states it; the precise rules:

- **Order.** The implicit `core` feature, then `features` in array order.
- **Keys.** Entities by name (`gl.Center`), pages by path, reports by key, sections and entries by
  id, settings tabs by category, app-bar slots by id. The derived launcher entry of an entity, page
  or report has the declaration's key as its id.
- **`entities`, `pages`, `reports`, `sections`, `entries`, `settingsTabs`, `appBar`** add new keys;
  a key that exists is `duplicate-key`.
- **`overrides`** name an existing entity key and replace it member by member: a set member
  replaces the inherited one wholesale (arrays are replaced, never concatenated); an unset member
  inherits. A missing key is `dangling-override`.
- **`hide`** entries are kind-qualified: `entity:gl.Center` (removes routes, entry, picker),
  `entry:core.Role` (removes the launcher entry only), `page:`, `report:`, `section:`,
  `settingsTab:`, `appBar:`. A missing key is `dangling-hide`.
- **`home`**: the last feature that sets it wins; no problem is raised.
- **`appBar`**: more than three slots in total is `app-bar-overflow`.

**Example —** a distribution with one fixed role set hides the Roles launcher entry but keeps the
pages reachable by URL: `tmFeature({ key: 'acme', hide: ['entry:core.Role'], … })`.

#### §2.4 `tmPage`

- Path: one or more kebab-case segments (`^[a-z][a-z0-9]*(-[a-z0-9]+)*$` each), optionally ending
  with `:name` parameters (`bank-reconciliation/:accountId`). Its first segment must not be an
  entity segment or a reserved word (`reserved-path`).
- Route `/{t}/{path}`; the route host's skeleton is `blank`; it publishes a `custom` page context
  with the title from `titleKey` (0026 consumes).
- `section` adds a launcher entry (id = path). `securable` gates: when `TmPermissions.can` is false,
  the route renders the forbidden state (§11) rather than redirecting.
- Route parameters reach the component as inputs (`withComponentInputBinding`).

#### §2.5 Escape hatches owned here

| Need | Hatch |
|---|---|
| A page with no entity | `tmPage(path, …)` (§2.4) |
| A hand-mapped endpoint | `inject(TmApi).read(…)` / `.write(…)` (§10) |
| A calendar the platform lacks | `calendars: [{ code, load }]` in `provideTellma` |
| Branding | `public/manifest.webmanifest`, `public/icons/`, `public/brand/`, `@layer tm.theme` (§7.6) |
| Anything Angular | `providers` on `tmFeature`, or providers after `provideTellma` |

### §3 Client metadata

#### §3.1 The container

`TmClientMetadata`, `TmMetadataLoaders`, `TM_CLIENT_METADATA` are A§5.2; section shapes stay with
their owners. The container gains one member:

```ts
interface TmClientMetadata {                       // A§5.2's members, plus:
  routing: {                                       // TellmaRoutes (§3.2), emitted
    serverFirstSegments: readonly string[]; serverTenantSegments: readonly string[];
    spaFirstSegments: readonly string[]; spaTenantSegments: readonly string[];
  };
}
```

- **Order.** `languages[0]` is the distribution default; `features` keep composition order.
- **Versions.** `distribution.version` is the UI version (0026 owns its meaning): the composition
  library's informational version `X.Y.Z+<sha>`. `platformVersion` is `Tellma.Core`'s.
  `features[].version` is each feature assembly's informational version (the About dialog lists
  packs). One `Version` per distribution comes from `distributions/<slug>/Directory.Build.props`,
  so the Web host's `Tellma-Build` equals the emitted `version`; a Web test pins the equality.
- **`displayName`** is `Tellma:DisplayName` from the Migrator's `appsettings.json` (no environment
  file) (decision 17).

#### §3.2 The emit command (C#)

- **Determinism.** Sorted object keys, invariant culture, `\n`, no timestamps: the same composition
  gives the same bytes and the same names, so an unchanged build busts no cache.
- **`tmMetadataLoaders`** fetches through `fetch(url, { credentials: 'same-origin' })` and
  `JSON.parse`; a fetch failure rejects (boot shows the "Couldn't load Tellma" boot error, §4.3).

#### §3.3 Loading

- **At boot (awaited before first render):** Core, the active language's strings and English's
  (Transloco's fallback). **Before the first API call:** Contracts (`TmApi` awaits it once).
  **With `/entity`:** Entities. All sit in the worker's `shell` group, so a warm launch reads them
  from CacheStorage; on a cold launch the build's `preload` links start Core and the default
  language's strings with the JS.
- **`TM_CLIENT_METADATA`** resolves to the loaded Core chunk; injecting it before the boot
  initializer completes is a programming error (it throws in development).

#### §3.4 Contracts

- **Map keys** are 0016's route templates (`POST /{tenantId}/api/web/centers/query`); the map is
  the same one the test project snapshots as `contracts.json`.
- **Computation** moves to a framework-free `Tellma.Core` service (0016 §3.10 edit):

```csharp
// Tellma.Core.Api
public interface IContractFingerprints
{
    IReadOnlyDictionary<string, string> All { get; }    // route template → fingerprint, every projected web endpoint
    string? For(string routeTemplate);
}
```

- The projector stamps `ContractMetadata(For(route))`; the emit writes `All`. A parity test
  realises the Web host and asserts every endpoint's `ContractMetadata` equals the emitted value.

#### §3.5 Drift rules

`tellma-client build` fails (exit 3) on each `TmConfigProblemCode` of §2.2. The server-dependent
ones:

| Problem | Rule |
|---|---|
| `language-missing` | an offered language with no `TmLanguageDefinition` |
| `language-not-offered` | a definition for a language the server does not offer |
| `default-language-mismatch` | `languages[0].code` ≠ the server's distribution default |
| `calendar-missing` | a registered calendar with neither a platform entry point (`gc` built in, `uq` → `@tellma/core-ui/calendar-umalqura`, `et` → `calendar-ethiopic`) nor a `calendars` definition |
| `feature-not-composed` | a client feature key absent from `metadata.features` (the implicit `core` excepted) |
| `unknown-entity` | a declaration or override naming an entity absent from the metadata |
| `reserved-path` | a page path or coded-report key whose first segment is an entity segment, a `routing` word or `new` |
| `string-key-collision` | a server pack key beginning `tm.` or `tmUi.` (cannot happen with resx naming; checked anyway) |

#### §3.6 The config spec

`generated/tellma-config.spec.ts` (emitted, 6 lines) configures `TestBed` with
`appConfig.providers`, injects `TM_CONFIG_PROBLEMS` (a factory over `tmCheckAppConfig` and the
Core chunk, which the spec imports as JSON) and expects an empty list. `tellma-client build` runs
`ng test --include generated/tellma-config.spec.ts --watch=false`. The same token is checked by
`provideTellma`'s initializer in development (throwing a `TmConfigError` that lists every
problem) and logged as `tm.config.problem` telemetry in production.

### §4 Boot

#### §4.1 `index.html`

The file of §2.1. `tellma-client check` fails when `<script src="tm-boot.js">` is not the first
script in `<head>`, when `<tm-app>` or the manifest link is missing, or when any inline script
exists (CSP `script-src 'self'` would block it anyway).

#### §4.2 `tm-boot.js`

A blocking classic script, ≤ 3 KB gzip, generated by `tellma-client build` from
`@tellma/core/boot/tm-boot.template.js` by replacing one marker with a JSON literal:

```js
// the generated first line (the rest is the platform template)
var TM_BOOT = {"v":1,"languages":[{"code":"en","dir":"ltr"},{"code":"ar","dir":"rtl"}],"defaultLanguage":"en",
  "strings":{"en":{"Boot_Unsupported_Title":"Update your browser", …},"ar":{…}}};
```

The `Boot_*` strings are Core resx keys (0013 resources), copied from the emitted packs.

**Reads**

| Input | Use |
|---|---|
| `TM_BOOT` | offered languages, their directions, the default, boot-page strings |
| cookie `tellma.profile` | the v2 profile (§8.1); a value that fails to decode, has `v ≠ 2` or an empty `sub` counts as absent |
| `localStorage['tm.boot']` | 0025's boot record; invalid JSON or `v ≠ 1` counts as absent |
| `sessionStorage['tm.login']` | the sign-in loop guard (a timestamp) |
| `location.pathname`, `location.search` | the path to guard and to return to |
| `navigator.languages`, `navigator.cookieEnabled`, `matchMedia('(prefers-color-scheme: dark)')` | cold language, cookies, system theme |
| feature presence | `JSON.rawJSON`, `navigator.locks`, `BroadcastChannel`, `AbortSignal.any`, `indexedDB`, `structuredClone` |

**Writes**

| Output | When |
|---|---|
| `<html lang dir data-theme>` | always, before first paint (`data-theme` is `light` or `dark`; `system` resolves through `matchMedia`) |
| `tm.boot` `{ v: 1, theme, lang, dir, sub: null, lastTenantId: null }` | no record, or the record's `sub` differs from the profile's; never writes `sub` (the app does, §8.1) |
| `tm.boot.sub`, `.lastTenantId` → `null` | the expiry step (3c below) |
| the expired user's IndexedDB partitions and `tm-images-v1` deleted | the expiry step, time-boxed to 1 s, through 0025's frozen key layout |
| `sessionStorage['tm.login']` `{ at, expired }` | set before a sign-in redirect; removed when a valid cookie is seen |
| `history.replaceState(null, '', '/' + lastTenantId)` | warm launch at `/` (step 4) |
| `window.__tmBoot` `{ state: 'run' \| 'redirect' \| 'page', profile, record, cold, at }` | always; `bootstrapTellma` reads it |

**Decision steps**, in order:

1. A missing feature → boot page `unsupported` ("Update your browser" / "Tellma needs a current
   version of Chrome, Edge, Firefox or Safari."). State `page`.
2. Path `/signed-out` → apply `lang`, `dir`, `theme` (record, else the cold choice of step 4);
   state `run`. No cookie needed.
3. No valid cookie:
   - a. `navigator.cookieEnabled === false` → boot page `cookies` ("Turn on cookies to sign in").
   - b. `tm.login` set less than 60 s ago → boot page `sign-in-failed` ("We couldn't sign you in"
     with Try again, which clears the marker and repeats step 3d).
   - c. The record names a `sub` → the session expired: delete that user's stored data (above),
     set `sub` and `lastTenantId` to null.
   - d. Set `tm.login = { at: Date.now(), expired }` and `location.replace('/bff/login?returnUrl=' +
     encodeURIComponent(pathname + search) + '&ui_locales=' + lang)`. State `redirect`.
4. A valid cookie → remove `tm.login`. *Cold* = no record or `record.sub ≠ profile.sub`.
   - Language: warm → `record.lang`; cold → the profile's `locale` matched by language subtag
     against the offered list, else `record.lang`, else the first offered `navigator.languages`
     entry, else the default. `dir` follows the language.
   - Theme: `record.theme`, else `system`.
   - Warm at `/` with `record.lastTenantId` → `history.replaceState` to `/{lastTenantId}`.
   - State `run`.

- **Boot pages** render at `DOMContentLoaded` into `<tm-app>` through DOM APIs (no HTML string
  sinks, so Trusted Types needs nothing), styled by `@tellma/core/styles.css` (`.tm-boot-page`):
  a `main` landmark, an `h1`, one paragraph, at most one button; `lang` and `dir` set; focus on
  the `h1`. Text in the boot language, English fallback.
- **Testing seam.** The template is a pure function `tmBoot(env)` over an injected environment
  (cookie string, storages, location, navigator facts); the generated file calls it with the real
  globals. Unit vectors cover every row above (§13).

#### §4.3 The startup sequence

1. `bootstrapTellma` returns a never-settling promise unless `__tmBoot.state === 'run'`.
2. `bootstrapApplication(TmApp, …)`. Initializers, in parallel: load the Core chunk; load the
   active language's strings and English's (§7.3); `TmSession` parses the cookie; `TmClientStore`
   opens and, on a tenant path, runs its one `readAll` (0025). Then, when the cached settings name a
   calendar other than `gc`, its entry point is imported (a cache read).
3. Initial navigation, then first render: `tm-app` → shell (0027) → route host skeleton → page.
4. After first render: worker registration (§5.4); the Contracts chunk; idle preloads (pins,
   recents, home: 0027 calls `TmUrls.preload`).

- **No initializer, guard or resolver awaits `TmApi`** (A§7.2). The cold `/` launch redirect is
  the one network await, and the tenantless shell renders a skeleton meanwhile (§9.3).
- **Boot error.** A Core or strings load that rejects renders the boot page `load-failed`
  ("Tellma couldn't start" / "Check your connection and try again." / Try again = reload) and
  emits `tm.boot.load-failed`.

#### §4.4 `TmApp` and the route host

- **`tm-app`** (`TmApp`, primary entry point) renders `<div class="tm-app" [dir]="dir()">` around
  `<router-outlet>` (0010 Part D's live-direction host), the session-ended dialog (§8.6) and the
  signing-out overlay (§8.4). Shells are route components (0027).
- **`TmRouteHost`** is the component of every page route:

```ts
interface TmRouteData {
  readonly kind: TmPageKind;                      // 0026's closed list
  readonly skeleton: 'search' | 'details' | 'blank';
  readonly load?: TmLazyComponent;                // static pages; entity routes resolve theirs from the descriptor
  readonly titleKey?: string;
  readonly securable?: TmSecurableRef;
}
```

- It renders the skeleton in the click's frame: the 0023 `page-header` layout with a title bar,
  one toolbar row and a body block whose geometry the search and details hosts match (0030 and
  0031 assert zero layout shift from skeleton to chrome). Then `load()` resolves (a cache read once
  the worker is installed) and it creates the page through `NgComponentOutlet`.
- Entity routes: the host reads the `segment` parameter, takes the descriptor from `TmEntities`
  (0029) and loads the search host, the details host, or the declaration's `search` or
  `details.page` hatch (0030, 0031).
- A chunk that fails to load (offline cold, or a deployment removed it) → `TmUpdates.check()`,
  then the inline error view `client-outdated` or `offline` (§11).
- **Title and focus.** `TmTitleStrategy` sets `document.title` to `<page title> · <displayName>`
  (the page context's title, 0026, else `titleKey`). On a path change (never on a query-only
  change), focus moves to the page's `[tmPageTitle]` heading once it renders (`tabindex="-1"`),
  else to `main`, so screen readers announce the new page (WCAG 2.4.3).

#### §5.4 Registration

```ts
provideServiceWorker('ngsw-worker.js', {
  enabled: !isDevMode(),
  registrationStrategy: () => tmRegisterWorker(),   // registers itself, never emits
});
```

- `tmRegisterWorker()` waits for the first render and `ApplicationRef.whenStable()` (at most 30 s),
  then calls `navigator.serviceWorker.register(url, { scope: '/', updateViaCache: 'none' })` with a
  `TrustedScriptURL` for `/ngsw-worker.js` from the shared `tellma` policy (0010 Part B request),
  and returns `NEVER`, so Angular never calls `register()` with a plain string (decision 7).
- No `navigator.serviceWorker` → no registration; the app runs and every launch is cold.
  A rejected registration emits `tm.sw.register-failed`.

#### §5.5 `TmUpdates`

```ts
declare class TmUpdates {
  readonly enabled: boolean;                       // a worker controls this page
  readonly available: Signal<string | null>;       // A§5.13: the ready version (appData.version)
  check(): Promise<'ready' | 'none' | 'disabled'>; // asks the worker; settles when its check does
  reload(): void;                                  // location.reload(); drafts survive (0025)
}
```

- **Checks.** The worker checks `ngsw.json` at start and on navigations (Angular). `TmUpdates`
  also checks when the tab becomes visible after ≥ 1 h hidden, every 6 h while visible, and on
  demand (§5.6).
- **`VERSION_READY`** sets `available` and shows the update banner through `TmBanners` (0028,
  precedence 3): "A new version of Tellma is available." with Reload; dismissing hides it for
  that version in this tab. Running tabs keep their version; a reload or a new tab gets the new
  one.
- **`unrecoverable`** reloads at once (A§7.5); drafts are already in session storage.
- **`VERSION_INSTALLATION_FAILED`** emits `tm.sw.install-failed`; the next check retries.

#### §5.6 An outdated client (412 and route-not-found)

1. `TmApi` receives `412 client-outdated` or `404 route-not-found` and calls `TmUpdates.check()`.
2. The verdict:
   - `ready` → code `client-outdated`: a read shows the inline view "Tellma was updated" with
     Reload; a write shows the dialog "Tellma was updated. Reload to continue. Your changes are
     kept." with Reload.
   - `none` → code `server-outdated` (an N−1 instance during a slot swap): "Tellma is being
     updated. Try again in a minute." A read retries once after 30 s on its own; a write never
     retries.
   - `disabled` (no worker) → `Tellma-Build` on the 412 (0016 edit) ≠ own version means
     `client-outdated` (a reload fetches the new `index.html`), else `server-outdated`.
3. Telemetry `tm.api.client-outdated { verdict }`.

### §6 SPA hosting rules (implemented by 0011 `MapTellma`)

A§6.6's table is binding. 0024 completes it:

- **Static files** are endpoint-routed (`MapStaticAssets`: publish-time Brotli and gzip variants,
  ETags), stamped `TenantlessEndpointMetadata("spa-assets")` and anonymous. A file is
  `public, max-age=31536000, immutable` exactly when its name carries a build hash (`-` then at
  least eight `[A-Z0-9]` before the extension, Angular's and the emit's); everything else is
  `no-cache`. `tellma-client check` fails a JS, CSS, font or `tm-metadata` file without a hash.
- **The fallback endpoint** (lowest order) answers `index.html` only to `GET` or `HEAD` with
  `Sec-Fetch-Mode: navigate`, or without that header and with `Accept` containing `text/html`, and
  only when the first segment is not in `TellmaRoutes.ServerFirstSegments` and, under an integer
  first segment, the second is not in `ServerTenantSegments`. Anything else unmatched is a problem
  body: `404 route-not-found` under an integer first segment, else `404 not-found`.
- **`index.html`** (file or fallback): `no-cache` with an ETag; the A§6.6 headers plus
  `Cross-Origin-Opener-Policy: same-origin`. CSP `connect-src` adds the Azure SignalR service's
  `https://` and `wss://` origins taken from `Azure:SignalR:ConnectionString`; `form-action` adds
  the authority's origin only in Standalone mode. Trusted Types names: `angular`,
  `angular#bundler`, `tellma`.
- **Precompression matters**: Brotli JS is ~15–20 % below the gzip budgets of §12 on the slow links
  the brief names.

### §7 Localization and theme

#### §7.1 `TmLocalization`

A§5.4's sketch, completed:

```ts
declare class TmLocalization {
  readonly language: Signal<string>; readonly locale: Signal<string>; readonly dir: Signal<'ltr' | 'rtl'>;
  readonly calendar: Signal<TmCalendar>; readonly calendarCode: Signal<string>;   // 'gc' | 'uq' | 'et' | …
  readonly contentSlot: Signal<1 | 2 | 3>;
  readonly timeZone: Signal<string>;                     // IANA; the zone instants display in
  readonly languages: Signal<readonly TmSelectableLanguage[]>; // what the language switch offers here
  readonly calendars: Signal<readonly string[]>;         // what the calendar switch offers here
  setLanguage(code: string): void;
  setCalendar(code: string): void;
}
interface TmSelectableLanguage { readonly code: string; readonly nativeName: string; readonly dir: 'ltr' | 'rtl' }
```

| Value | Tenantless shell | In a tenant |
|---|---|---|
| `language` | `boot.lang` if offered, else the default | `me.PreferredLanguage` if offered → `boot.lang` if offered → tenant primary language → default |
| `languages` | the offered languages | the tenant's content languages, plus the active one when it is not among them |
| `locale` | the definition's `locale` (`ar` → `ar-SA` in Acme) | same |
| `calendarCode` | `gc` | `me.PreferredCalendar` if in the tenant's pair → tenant primary calendar |
| `calendars` | `['gc']` | the tenant's pair |
| `contentSlot` | 1 | the position of the content language whose language subtag equals the active language's, else 1 (0013 §9.2's rule) |
| `timeZone` | the browser's (`Intl.DateTimeFormat().resolvedOptions().timeZone`) | `me.PreferredTimeZone` → settings `TimeZone` (A§5.3: no `Tellma-Time-Zone` header) |

- **Inputs** come from the launch documents (0025) and follow them: when another tab changes the
  user's language, the stored `me` changes and this tab converges.
- **Providers**: `TM_ACTIVE_LOCALE` = `locale`; `TM_CALENDAR` = `calendar`; Transloco's active
  language = `language`.

#### §7.2 A language switch

1. `setLanguage(code)` refuses a code outside `languages()` (throws in development).
2. The language's strings load if absent (a cache read); nothing changes until they arrive, so no
   key ever flashes.
3. In one change-detection pass: Transloco's active language, `<html lang dir>`, the `tm-app`
   direction host, `locale`, `contentSlot`. Labels, messages, formats and display names re-render
   in place; open overlays follow through 0010 Part D's live direction.
4. `boot.patch({ lang, dir })` (0025).
5. In a tenant, `TmApi.write('users/me/locale', { language })` (0018 edit, 0027's). On failure the
   switch stands and the write is retried once when `TmApi.online` turns true.

`setCalendar` follows the same steps with the calendar entry point (§7.4) and `{ calendar }`.
Telemetry: `tm.l10n.language-changed { from, to }`, `tm.l10n.calendar-changed { from, to }`.

#### §7.3 Strings

- **Sources per language**: the emitted server pack (root keys, `PascalCase_Underscored`), the
  definition's `tmUi` and `tm` tables (`tmEnglish()` ships English for both; `@tellma/locale-ar`'s
  `tmArabic()` ships Arabic for both).
- **Through 0010 Part B's seam**: `provideTellmaUi({ translations })` receives a loader that, for a
  language, resolves the merged dictionary (server pack at the root, `tmUi`, `tm`), and
  `availableLangs` = the offered languages. The loader fetches the pack through `TmMetadataLoaders`
  and the tables through `strings()`.
- **Fallback**: per key to English (`fallbackLang: 'en'`); a server-originated code missing from
  every pack renders the server's `message` (§7.5); any other missing key renders its key and warns
  in development.
- **Boot load**: the active language and English (§4.3); other languages on first switch.

#### §7.4 Calendars

`gc` is built in; `uq` and `et` import `@tellma/core-ui/calendar-umalqura` / `calendar-ethiopic`
on first use; a distribution calendar comes from `TmAppConfig.calendars`. All of them sit in the
`shell` group. `Tellma-Calendar` carries `calendarCode` on tenant calls.

#### §7.5 Server text

```ts
declare class TmServerText {                       // renders server codes through the string packs (0013 §10.4)
  problem(problem: TmProblem): Signal<{ title: string; detail: string }>; // Problem_<code>[_Detail] + arguments
  error(error: TmProblemError, entity?: string): Signal<string>;          // <Code . → _> + arguments, else message
```

- Arguments are raw values formatted in the active locale and calendar; `arguments.property`

#### §7.6 Theme and branding

- **`TmTheme`** (0010 Part B) is seeded from `boot.theme` at startup without writing back; an effect
  writes `boot.patch({ theme })` when `TmTheme.setting` changes. `tm-boot.js` applies the theme
  before first paint, so there is no flash.
- **Styles**: `@tellma/core/styles.css` imports the tokens CSS, core-ui fonts, the directive

### §8 Session

#### §8.1 `TmSession` and the profile cookie

```ts
interface TmProfile { v: 2; sub: string; sh: string; name: string; email: string; locale: string | null } // A§5.4
interface TmStepUpChallenge { readonly acr: string; readonly maxAge: number | null }  // from WWW-Authenticate
declare class TmSession {
  readonly profile: Signal<TmProfile | null>;
  readonly state: Signal<'active' | 'expired' | 'signing-out'>;
  signIn(options?: { returnUrl?: string; stepUp?: TmStepUpChallenge }): Promise<never>;
  signOut(): Promise<never>;              // rejects with a TmApiError when the BFF could not be reached (§8.4)
  check(): 'same' | 'missing' | 'changed'; // reads the cookie now; used by TmApi, TmHub and the triggers of §8.8
}
declare const tmSessionGuard: CanActivateFn;
declare function tmParseProfileCookie(cookies: string): TmProfile | null;
```

- **Cookie v2** (the 0011 §5.5 edit): name `tellma.profile`, value `base64url(UTF-8 JSON)` without
  padding, `Path=/`, `Secure`, `SameSite=Lax`, not `HttpOnly`. Members `v: 2`, `sub`, `sh` (the
  22-character session handle, a name and never a credential), `name`, `email`, `locale`
  (the ID token's claim, or null). Example:

  ```text
  tellma.profile=eyJ2IjoyLCJzdWIiOiIwMDAwMDAwMC0wMDAwLTAwMDAtMDAwMC0wMDAwMDAwMDAwMDEiLCJzaCI6Ilk0…
  → { "v": 2, "sub": "00000000-0000-0000-0000-000000000001", "sh": "Y4kQ1x…", "name": "Farah Nasser",
      "email": "farah@acme.example", "locale": "ar" }
  ```

- **Lifetime**: `Expires` = the session's idle expiry, capped by its absolute expiry; re-issued
  whenever the session cookie is (sliding renewal, a refresh that replaced `name` or `locale`); a
  request carrying `Tellma-Activity: background` renews neither. So "cookie present" means "the
  server session is very likely alive" (A§7.2).
- **`sub` in the boot record**: `TmSession` writes `boot.patch({ sub })` after 0025's boot sweep
  decision (other users' partitions removed, A§5.5).

#### §8.2 The guard

`tmSessionGuard` sits on every route except `/signed-out`. `check()`: `same` → allow; `missing` →
the expiry path (§8.6), deny; `changed` → the changed-user path (§8.7), deny. It never awaits the
network; `tm-boot.js` already handled the page-load case.

#### §8.3 Sign-in and step-up

- **`signIn()`** sets `sessionStorage['tm.login']` and calls
  `location.assign('/bff/login?returnUrl=' + encodeURIComponent(returnUrl ?? current path and
  query) + '&ui_locales=' + language)`, adding `&acr_values=<acr>&max_age=<s>` for a step-up.
- **Step-up** (`401 step-up-required`, kind `step-up`) affects only the calling tab:
  1. `TmErrorPresenter` opens the step-up dialog: "Confirm it's you" / "This needs you to sign in
     again. You'll come back to this page, and your changes are kept." [Continue] [Cancel].
  2. Continue → `signIn({ returnUrl: current, stepUp })`. The page's draft is already in session
     storage (0025); the details host restores edit mode on return (0031).
  3. Back on the page, the user presses Save again: a failed write is never replayed.
- `TmPermissions.sensitive()` (0029) lets a page warn before the user starts.

#### §8.4 Sign-out (every tab)

1. The session menu (0027) calls `signOut()`.
2. Post `drafts.query` on the user channel; collect `drafts.reply` for 300 ms and add this tab's
   `TmDrafts.dirtyCount()`. If the total is above 0, confirm (0023 `confirm`): "Sign out and
   discard unsaved changes?" / "You have unsaved changes in {count, plural, one {# tab} other {#
   tabs}}." [Sign out] [Cancel]. Cancel ends here.
3. `state` = `signing-out`; post `session.signing-out`. Every tab of that `sub` aborts its reads
   and shows the blocking "Signing out…" overlay (0023 `busy-overlay`, rendered by `tm-app`);
   `TmApi` rejects new calls with `cancelled` until the overlay lifts.
4. `TmApi.write('/bff/logout', { scope: 'global' })`.
   - Network failure or a non-200: `state` = `active`; this tab shows "Couldn't sign out. Check your
     connection and try again."; `signOut()` rejects. Other tabs' overlays lift after 15 s without
     a `session.signed-out`, after re-checking the cookie.
5. `200 { redirectUrl }`; the server has cleared `tellma.profile` and sent `Clear-Site-Data:
   "cache"`.
6. `TmClientStore.sweep('session-ended')`, `TmClientCache.clearAll()` (0010 Part D), this tab's
   drafts for that `sub`, `boot.patch({ sub: null, lastTenantId: null })`.
7. Post `session.signed-out`. Each other tab clears its own drafts and calls
   `location.replace('/signed-out')`, dropping all memory state.
8. `location.assign(redirectUrl)`: the end-session endpoint, then `/signout-callback-oidc`, then
   `/signed-out`.

Telemetry: `tm.session.signed-out { origin: 'self' | 'other-tab' | 'elsewhere' }`.

#### §8.5 Signed out elsewhere

The hub's `session.ended { session-terminated }` reaches the leader (0025), which posts
`session.signed-out`. Every tab runs step 6 (sweep once, guarded by the store), deletes the stale
profile cookie (`document.cookie = 'tellma.profile=; Max-Age=0; Path=/; Secure'`), clears its
drafts and replaces to `/signed-out`.

#### §8.6 Expiry path

1. Trigger: `401 unauthenticated`, or `check()` returns `missing` mid-session.
2. The tab runs `sweep('session-ended')`, deletes a stale profile cookie (a revoked session can
   leave one), sets `state` = `expired` and posts `session.expired`.
3. Every tab of that `sub` keeps its drafts and shows the session-ended dialog (rendered by
   `tm-app`; `alertdialog`, focus on the button): "Your session ended" / "Sign in to continue. Your
   work is kept." [Sign in].
4. Sign in → `signIn()` from that tab. Back, the tab boots cold (the store was swept), restores its
   draft (0031) and posts `session.started`; the other tabs of that `sub` reload in place
   (`location.reload()`) and restore theirs.

Telemetry: `tm.session.expired { source: 'boot' | 'cookie' | '401' }` (`boot`: `tm-boot.js` marks
`tm.login` with `expired: true`, and the app reports it after the next sign-in).

#### §8.7 Changed-user path

A profile cookie with another `sub` than this tab's, seen by `check()` or as `session.started` /
`session.changed` naming another `sub` on the device channel: the tab drops what it was receiving,
clears its drafts, posts `session.changed`, and calls `location.replace('/')`; the boot sweeps
every other user's partitions (0025). Telemetry `tm.session.changed-user`.

#### §8.8 Re-check triggers

`check()` runs on `visibilitychange` to visible, on `pageshow` with `persisted` (the back-forward
cache gets no broadcast), on `cookieStore` `change` events naming `tellma.profile` where the Cookie
Store API exists (an accelerator, not a dependency), before every authenticated `TmApi` call and
on its response (§10.3), and before every hub negotiate (0025).

### §9 Routes and URLs

#### §9.1 Grammar rules

A§8's table is the route list. Rules:

- **Reserved words** have one source, `TellmaRoutes` (§3.2), emitted into `metadata.routing` and
  read by the router, `tellma-client` (collision check, proxy, worker config) and 0011's audit.
- **`{t}`** is a positive integer without leading zeros; `/017/centers` is the tenantless
  not-found page. **`{id}`** is a positive integer.
- **Canonical form**: lowercase literal segments, no trailing slash (`/17/` replaces to `/17`),
  no case folding (`/17/Centers` is not found).
- **No dots in paths** and kebab-case page paths and coded-report keys (A§8); a coded-report key
  contains a hyphen.
- **Edit mode and import are never in the URL** (A§8).

#### §9.2 Route assembly

`provideTellma` derives one route table at provider time from the declarations alone; segment
lookups happen at match time, after the boot initializers loaded the metadata:

```text
''               TmLaunchRedirect           canMatch runs the redirect (§9.3); renders nothing
'tenants'        tenantless shell → picker  0027
'signed-out'     tenantless shell → page    0027; the one route without tmSessionGuard
':t'             tenant shell (0027)        matcher: positive integer; tmSessionGuard
```

- Every page route's component is `TmRouteHost` (§4.4) with `TmRouteData`; core pages, `tmPage`
  and entity routes all go through it.
- **Platform entity pages** (`jobs`, `notifications`, `assignments`, `schedules`, `reports`,
  `dashboards`, …) are entity routes whose declarations set hatches (0028, 0032, 0034, 0035).
- **Under an entity segment**, before the generic entity routes: one `reports/{key}` route per coded
  report (0034), and the pages a feature declares under the segment of an entity it declares itself
  (`reports/:id/studio`, 0034). Any other page path starting with an entity segment is
  `reserved-path`.
- **Router options**: `withComponentInputBinding()`, `paramsInheritanceStrategy: 'always'`, the
  `TmTitleStrategy`, `withNavigationErrorHandler` (a chunk error → §4.4), no initial-navigation
  blocking.
- **`lastTenantId`**: entering a tenant route writes `boot.patch({ lastTenantId })` (0025);
  `404 tenant-not-found` from that tenant clears it (§11).

#### §9.3 The launch redirect (`/`)

`tm-boot.js` already rewrote a warm `/` (§4.2). Angular reaches `/` cold, on an in-app link to `/`,
or with no last tenant.

#### §9.5 The `TmSearchQuery` codec

A§8 gives the parameters; 0030 owns their meaning, precedence and history. The codec's syntax:

- **Order** (canonical; the same query always yields the same URL): `q`, `f.*` by path, `filter`,
  `inactive`, `x.*` by key, `order`, `cols`, `page`, `size`, `view`.
- **Defaults are omitted**: `page=1`, `inactive=0`, an empty `q`; `cols` only when 0030 says the set
  differs from the code default.
- **Encoding**: `encodeURIComponent`, then `,`, `:` and `@` restored for readability; spaces are
  `%20`, never `+`. Decoding accepts `+` as a space.
- **`f.{path}`** is `{op}:{value}`. `path` matches `^[A-Za-z][A-Za-z0-9]*(\.[A-Za-z][A-Za-z0-9]*)*$`.
  `op` is kebab-case (`contains`, `starts-with`, `ends-with`, `eq`, `ne`, `lt`, `le`, `gt`, `ge`,
  `between`, `in`, `before`, `after`, `is`; 0029 decides which apply to which type). Text ops take
  the whole remainder as one value; `in` and `between` split on `,`, where `\,` and `\\` escape.
- **Values are culture-free**: Latin digits, `.` decimals, ISO `yyyy-MM-dd` dates (whatever the
  user's calendar), `true`/`false`, ids for navigations.
- **`order`**: `Path` or `Path:desc`. **`cols`**: comma-separated paths. **`page`**: integer ≥ 1.
  **`size`**: integer ≥ 1. **`view`**: `grid | tiles | tree | list`.
- **Parsing is lenient**: an invalid entry is dropped (and reported in development); an invalid
  `filter` is kept (the server reports it inline, 0030).

| URL query | `TmSearchQuery` |
|---|---|
| `q=jed&f.Name=contains:a,b&order=Code` | `{ q: 'jed', columnFilters: { Name: 'contains:a,b' }, order: 'Code' }` |
| `f.CenterType=in:Service,Sale&page=2` | `{ columnFilters: { CenterType: 'in:Service,Sale' }, page: 2 }` |
| `f.CreatedAt=between:2026-01-01,2026-03-31` | `{ columnFilters: { CreatedAt: 'between:2026-01-01,2026-03-31' } }` |
| `page=0&view=cards` | `{}` (both dropped) |

#### §10.1 `TmApi`

A§5.3's sketch, completed:


- **Routes**: `'centers/query'` → `/{t}/api/web/centers/query`; a leading `/` is a tenantless path
  sent as is. Every method is `POST` except `read` with `method: 'GET'`.
- **Which method**: `read` for reads and `Idempotent` actions (0016 §2.2's retried class); `write`

#### §10.2 Headers

| Header | Value | On |
|---|---|---|
| `Tellma-Client` | `web/<metadata.distribution.version>` | every call |
| `Tellma-Contract` | the route's fingerprint from the Contracts chunk | tenant calls whose route is in the map |
| `Accept-Language` | `TmLocalization.locale()` (`ar-SA`) | every call |
| `Tellma-Calendar` | `TmLocalization.calendarCode()` | tenant calls |

| `Content-Type` | `application/json` | calls with a body |

- No `Tellma-Time-Zone` (A§5.3). The trace id is known before the response, so a cancelled or
  failed call still has a reference (0026's request log).

#### §10.3 One call, step by step

1. **User check.** For an authenticated call, `TmSession.check()`: `missing` → do not send, run
   the expiry path, reject `unauthenticated`; `changed` → do not send, run the changed-user path,
   reject `cancelled`.
2. **Offline write.** A write while `navigator.onLine` is false is not sent: reject `offline` with
   code `not-sent` ("You're offline. Your changes are kept. Save again when you're back online.").
3. **Send** through `fetch` with `credentials: 'same-origin'`, the caller's signal combined
   (`AbortSignal.any`) with the watchdog: 60 s, or 6 min with `long` (decision 9).
4. **Response check.** `check()` again: `missing` → expiry path, reject `unauthenticated`;
   `changed` → discard the body, changed-user path, reject `cancelled`. Only a checked response
   continues, so one user's data never lands in another's partition.
5. **Observers.** `Tellma-Version-Tags` → `TmCacheRefresher.observe(t, tags)` (0025, absent tags
   are no information); a record → `TmRequestLog` (0026: trace id, route template, start,
   duration, outcome, status, slow ≥ 3 s).
6. **Status** → §10.6. A success body is parsed by §10.4.

#### §10.4 Lossless JSON

- **Parse**: when the text contains a run of 16 or more digits (regex `\d(?:\.?\d){15}`), parse
  with a reviver that turns a number whose `context.source` has more than 15 significant digits
  into a `TmDecimal`; otherwise plain `JSON.parse`. Strings are never converted (`modifiedAt` stays
  the raw string; no `Date` objects). Absent members mean null (0016 omits nulls).
- **Stringify**: `JSON.stringify`; a `TmDecimal` writes itself raw through `JSON.rawJSON`.
- Vectors (§13): `9007199254740993` → `TmDecimal`; `123456789012.3456` (16 digits) → `TmDecimal`;
  `1234567890.12345` (15) → number; `-0.000000000000000001` (1 significant digit) → number;
  `"12345678901234567890"` → string.

#### §10.5 Cancellation by type and retries

| Request | Signal | Cancelled by | Retried (0016 §2.2 class) |
|---|---|---|---|
| page data (`resource()`) | its `abortSignal` | navigation away, a new query (text, filter, sort, page) | yes |
| keystroke reads (search field, picker, `queryex/discover`) | per keystroke | the next keystroke | yes, unless superseded |
| long reads (export download, report run) | the page's and a visible Cancel | Cancel, navigation | yes |
| background reads (polling, refresh) | the owner's lifetime | owner destroyed | yes |
| writes, persist round trips | none | never | never |
| `send` (preference flush at pagehide, telemetry) | none | never | never |

- **Retry schedule (reads only)**: network failure → up to 2 retries after 1 s and 3 s (±25 %
  jitter) while `navigator.onLine`; `429` → `Retry-After` capped at 10 s, up to 2; `503` with
  `Retry-After` → that delay capped at 30 s, up to 2. An abort ends any wait at once. The page stays
  in its loading state while waiting.
- **Path of an abort**: `abort()` → `fetch` aborted → Kestrel `RequestAborted` → the batch's token
  → SqlClient attention (0016 §8.3, 0012 edit). Client: kind `cancelled`, silent, logged as
  `cancelled`, never retried.
- **`online`**: false when `navigator.onLine` is false or a request failed at the network level.
  While false, a visible tab probes `GET /health/live` every 5 s, backing off to 30 s; any HTTP
  answer (even 429) or the next successful call sets it true. 0028's "Connection lost" banner
  follows it after 5 s.
- **`download`** streams the `.xlsx` body, reports bytes to `onProgress`, takes the file name from
  `Content-Disposition` (`filename*` first).
- **`send`** uses `fetch` with `keepalive: true`; bodies above 16 KB throw in development and are
  dropped in production (several closing tabs must fit the 64 KiB budget, A§5.7).
- **`TM_BLOB_FETCHER`** (default from `provideTellma`): a `GET` with `If-None-Match` and the
  caller's signal (0010 Part D), the user check of §10.3, no retry.

- **Every other component** sees only `TmApiError`; only `TmApi` and `TmErrorPresenter` know HTTP.

## 4. Open questions owned

- **Tenant picker Q1 — base URL or `/tenants`?** `/tenants` is the picker and never redirects; `/`
  is the launch redirect (§9.3). "Open the app" and "show me the picker" are then different URLs,
  and Switch tenant links to `/tenants` without fighting the redirect. 0011 §5.5 changes to
  `returnUrl ?? "/"` and its skip rule moves into the SPA (edit E8). Alternative: the picker at `/`
  with a `?pick=1` bypass (two meanings for one URL; the BFF and the SPA would both own the landing
  decision).
- **Tenant picker Q2 — `/{t}/home` or `/{t}`?** `/{t}`. The tenant root is shorter, is the
  wordmark's target, and invitations, welcome and notification emails already link there (0018
  §3.3, 0022 §4). Alternative: `/{t}/home` (a second spelling of an existing link, and `home`
  would become a reserved second segment).

## 11. Review flags

1. **Browser floor Baseline 2025** (decision 6). Alternative: `lossless-json` and no floor page.
   Flips if customers run browsers older than Safari 18.4 / Firefox 135 / Chrome 114 at scale.
2. **Config check through the unit-test builder in `tellma-client build`** (§3.6). Alternative:
   startup-only checks plus e2e. Flips if the extra 10–20 s per build hurts.
3. **Write watchdog 60 s / 6 min** (decision 9). Alternative: no client timeout. Flips if
   legitimate saves exceed 60 s.
4. **Step-up dialog before redirect** (§8.3). Alternative: redirect at once. Flips if users find
   the extra click noisy.
5. **Sign-out needs the BFF** (§8.4). Alternative: sign out locally and retry later. Flips if
   offline sign-out is a real need (kiosks).
6. **Custom worker registration for Trusted Types** (decision 7). Alternative: a `default` policy.
   Flips if Angular registers with a `TrustedScriptURL` itself.
7. **Updates by banner and natural reload; `unrecoverable` reloads at once** (A§12 #8). Flips if
   users ignore the banner for days.
8. **Profile cookie expiry tracks the idle session** (A§12 #16) and **the skip rule moves to the
   SPA** (#17).
9. **English formats as `en-GB`** (decision 13). Alternative `en-US`. Flips on a market preference.
10. **`displayName` emitted from `appsettings.json`** (decision 17). Alternative: runtime only
    from `DistributionInfo`. Flips if deployments rename a distribution without a rebuild.
11. **Session-menu languages = content languages plus the active one** (A§12 #11, decision 14).
12. **Display zone = `PreferredTimeZone ?? tenant zone`** (A§12 #12); **theme device-level** (#13).
13. **Session expiry deletes stored data in `tm-boot.js`** (A§12 #26). Alternative: keep data for a
    warm relaunch. Flips if the relaunch after a week away is judged too slow.
14. **Entity routes are API segments** (A§12 #18); **repo-root workspace** (#21); **no npm
    abstractions** (#22); **`ar-SA` digits everywhere** (#23); **whole app prefetched** (#29).
15. **Unverified hosting facts** (A§12 #24): abort propagation on App Service, Trusted Types with
    ECharts (0034), Azure SignalR and the raised client timeout — staging smoke decides.

## 12. Challenges to the architecture

1. **Trusted Types vs Angular's worker registration (A§6.6 CSP, A§7.1 step 6).** Angular calls
   `navigator.serviceWorker.register(script)` with a plain string, which throws a `TypeError` once
   `require-trusted-types-for 'script'` is enforced, so the skeleton's CSP and its
   `registerWhenStable:30000` cannot both hold. Followed: the CSP; resolved by decision 7 (custom
   registration through the `registrationStrategy` observable). Evidence: Angular's `provider.ts`
   and MDN `register()` (section 13).
2. **The Contracts chunk should carry the retry class** (A§5.2 types it `Record<string, string>`).
   With `{ fp, read, long }` per route, `TmApi` could refuse `read` on a non-retriable route in
   development and pick the watchdog without a `long` flag at call sites. Followed: the skeleton's
   shape plus `long?` options.
3. **"Only `TmApi` handles … step-up" (A§11) vs a confirm before leaving the page.** Followed with
   one deviation: `TmApi` classifies; `TmErrorPresenter` asks once, then redirects (§8.3).
4. **`hide` keys need a kind.** A§3.6 writes `hide: ['core.roles']`; entity names, page paths,
   report keys and entry ids can collide (`bank-reconciliation` vs `acme-aging` are both kebab), so
   this note requires `entry:core.Role`-style qualified keys (§2.3). 0027's examples change.
5. **`tm-boot.js` is generated, and `index.html` references it** (A§3.1 says both "index.html …
   tm-boot.js" and "build … injects tm-boot.js"). Resolved: the scaffolded `index.html` carries the
   tag; the build generates the file with its config literal and `check` verifies the tag.
6. **Warm-chrome timing is not a Lighthouse measure** (A§11 gates row): Lighthouse resets storage
   by default, so the worker cache is gone. Followed with the timing moved to a Playwright nightly
   with CPU throttling; Lighthouse keeps the cold run.
7. **`distribution.displayName` is runtime configuration, not a build fact** (A§5.2). Followed by
   reading `appsettings.json` at emit time (flag 10).
