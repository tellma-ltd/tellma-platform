## 2. Decisions

1. **One entry point per component family, all domain-free** (no tenants, entities, BFF or
   `@tellma/core`). Why: the library rule (0002) and per-route budgets. Alternative: one `layout`
   entry point for card, page header and description list (budgets lose resolution).
2. **Icons are Lucide icon data (`[tag, attrs][]` tuples) in a runtime registry, rendered with
   `createElementNS`; no raw SVG strings.** Why: string names come from data (`TmNavSection.icon`,
   `TmPageAction.icon`), tree-shaking needs per-icon imports, and building nodes needs no
   Trusted Types policy under the §6.6 CSP. Alternatives: an SVG sprite file (`<use href>`; the
   whole set downloads, a build step composes it); the Lucide font (DS forbids icon fonts); raw SVG
   strings (needs a TT policy and sanitizing).
3. **Icon size comes from a custom property the container sets.** `tm-icon` reads `--icon-size`;
   buttons, menus and panels re-point it. Why: one icon component fits every host without a size
   input per call site. Alternative: a required `size` input (every call site repeats the host's
   size).
4. **Radio and segmented controls are native radios with a component-owned arrow-key handler.**
   Native radios give form semantics, Tab-to-checked and Space; the group intercepts arrows and maps
   them through the live computed direction, so RTL behaves the same in every engine. Why:
   `@angular/aria` ships no radio-group pattern, and direction-aware native radio arrows are
   confirmed only for Chromium (§13). Alternatives: `ngToolbar` widget group (toolbar semantics are
   wrong for a form choice); `aria-pressed` toggle buttons (no single-choice semantics).
5. **Switch is a native checkbox with `role="switch"`.** Why: Space toggles natively; it is
   `FormCheckboxControl` like `tm-checkbox`. Alternative: `button[role=switch]` (re-implements
   keyboard and form state).
6. **Tree is `@angular/aria/tree` behind the definition-directive pattern, DOM-rendered, not
   virtualized.** Children render through aria's deferred `ngTreeItemGroup`, so an infinite path
   tree costs only what is expanded. Why: aria covers the APG tree keyboard model, typeahead and
   RTL; the consumers (column editor, studio field list, path picker) show tens to hundreds of
   expanded nodes. Alternatives: the grid engine's flat tree (a grid, not a tree); a bespoke
   virtualized tree (cost without a consumer that needs it).
7. **Drag and drop is native HTML5 drag and drop with a typed payload, and every drag has a
   non-drag equivalent.** Why: dropping a field into a text editor at the pointer needs the native
   `text/plain` drop, which inserts at the drop caret for free; native drag works in desktop
   browsers, iOS Safari 15+ and Chrome for Android (§13); WCAG 2.2 SC 2.5.7 requires a single-pointer
   alternative anyway. Alternatives: CDK drag-drop (pointer-based, cannot drop into a text caret, no
   keyboard model); a bespoke pointer engine (caret hit-testing by hand).
8. **Reorder list: native drag for pointers, a grab/move/drop keyboard model on a per-row handle
   button.** Why: the APG has no reorder pattern; the lift-move-drop model with live announcements is
   the established accessible one. Alternative: Alt+Arrow only (undiscoverable; kept as a shortcut).
9. **Tiles are a bespoke virtualized layout grid (`role="grid"`), a single-column `treegrid` in
   tree mode.** One tab stop, 2D arrows, Enter activates, Space selects, matching the data grid's
   readonly model; windowing reuses `tmComputeAxisWindow` over lattice rows. Why: a list of links
   would make every tile a tab stop and break with virtualization; aria `grid` is render-space only
   (0004 §2). Alternative: `role="list"` of links (rejected for those reasons).
10. **Tiles mirror the grid's amended API names** (`activeId`, `selectedIds`, `activate`,
    `itemClass`, `scrollToItem`, `expandedIds`, batched `loadChildren`). Why: 0030 swaps grid, tiles
    and tree with one page state. Alternative: tiles inside `tm-grid` as a view mode (couples two
    rendering engines in the largest budget).
11. **Toasts render in a top-layer `popover="manual"` host; announcements go through two persistent
    visually hidden live regions.** Why: the top layer paints above CDK modals with no z-index work,
    and persistent regions announce reliably (the `tm-alert` lesson). Alternatives: CDK overlay
    container (below or tangled with modals); `role="status"` on each toast (double or missed
    announcements).
12. **Toasts never take focus and have no enter animation;** timers pause on hover, on focus inside
    and while the page is hidden; errors are sticky. Why: rule 2B, WCAG 2.2.1, the design's toast
    rules. Alternative: slide-in (motion the user waits through).
13. **Busy overlay blocks input by making every other `<body>` child `inert`, at once; the scrim and
    spinner appear after a 200 ms delay token.** Why: keyboard and pointer are blocked from the first
    frame (no double save), while sub-200 ms saves do not flash a full-page spinner. Alternatives:
    instant scrim (flashes); pointer-only blocker (keyboard can still type and press Save).
14. **Confirm and error dialogs are `TmModal` contents opened by services that return promises.**
    Why: one modal shell, one focus model. Alternative: native `<dialog>` (a second modal stack
    beside CDK's).
15. **Skeletons are static.** No shimmer: nothing moves, nothing needs a reduced-motion branch.
    Alternative: pulse (motion on a surface the user waits on).
16. **Description list is a directive on a native `<dl>`** with a global stylesheet. Why: plain HTML
    is the simplest thing an agent writes and the native `dl`/`dt`/`dd` roles survive (a custom
    element child of `<dl>` breaks the content model). Alternative: a component with projected
    items (projection breaks the list structure) or an `items` input (no rich values).
17. **The pager reserves the width of its widest possible status text** for the current total, so
    paging never moves the arrow buttons under the pointer. Why: rule 2D. Alternative: natural width
    (arrows drift as `1–20` becomes `101–120`).
18. **`tm-chip-set` collapses to one line with a "+N" chip when `overflow="collapse"`**, recomputed
    on resize and content change, never on keystrokes. Why: multi-valued fields keep their height
    (rule 2D). Alternative: wrapping fields (the field grows as chips are added).
19. **`kbd` owns the key-combination grammar** (`'Mod+K'`, `'Shift+?'`) with format, match and
    `aria-keyshortcuts` helpers; 0027's registry and 0010's menu hints use it. Why: one grammar,
    domain-free. Alternative: the grammar in 0027 (the library's menu could not format it).
20. **No new semantic tokens;** one component token group per component (§3.9). Why: the brand
    roles already cover these surfaces.

**Vocabulary**

- **Size ladder:** `TmControlSize` `sm | md | lg` (heights 30/38/46, option rows 26/30/34);
  default `TM_FORM_FIELD_DEFAULTS.size` (`sm` in the workspace).
- **Definition directive:** a directive that only carries inputs and a template; the parent
  renders the real elements (the `tm-option`/`tm-tab` pattern, required wherever an aria directive
  is involved).
- **Lattice:** the rows × columns arrangement of tiles at the current width.
- **Active item:** the tile, tree node or row the keyboard acts on; it holds DOM focus when the
  component is focused.
- **Context item:** a tile or tree node shown only because a descendant matched a search.

### 3.2 Shared rules (spec §2)

Every new component follows one set of rules for sizes, keyboard, direction, motion and layout
stability; per-component sections state only their deltas.

**Sizes.** Components with a control height take `size` (default `TM_FORM_FIELD_DEFAULTS.size`);
the rest have fixed geometry from their token group.

| Takes `size` (ladder) | Fixed geometry |
|---|---|
| `segmented`, `search-field`, `date-range`, `pager`, `accordion` header, `tree` rows, `reorder-list` rows, `chips` (sm 20, md 24, lg 28) | `radio` and `switch` boxes (rows ride the option height), `badge` (20), `counter` (16), `avatar` (own scale), `tiles` (60 px tiles), `banner` (32 px row), `toast`, `kbd`, `progress`, `skeleton` (consumer sets box), `card`, `page-header` (rows ≥ the field height), `copy` (rides `tmButton` size), `splitter` |

**ARIA patterns and keyboard (summary; details in each section).**

| Component | Pattern | Behaviour layer | Tab stops |
|---|---|---|---|
| `tree` | APG tree view (single or multi-select) | `@angular/aria/tree` | 1 |
| `accordion` | APG accordion | `@angular/aria/accordion` | 1 per header |
| `card` (collapsible) | APG disclosure | own (`aria-expanded`, `aria-controls`) | 1 |
| `radio`, `segmented` | APG radio group | native radios + own arrow handler | 1 |
| `switch` | APG switch | native checkbox `role="switch"` | 1 |
| `tiles` | APG layout grid; treegrid in tree mode | own (index math, roving focus) | 1 |
| `reorder-list` | list + handle buttons (lift, move, drop) | own + `drag-drop` | 1 per handle |
| `chips` (removable) | list + roving remove buttons | own | 1 |
| `splitter` | APG window splitter | own | 1 |
| `toast`, `banner` | live regions (`status`, `alert`) | own | per button |
| `confirm` | APG alert dialog | `TmModal` (CDK dialog) | trapped |
| `error-dialog` | APG dialog | `TmModal` | trapped |
| `progress` | `progressbar` | — | 0 |
| `busy-overlay` | `status` live region over an inert page | — | 0 |
| `pager`, `copy`, `search-field` | native buttons, inputs, `tm-select` | — | per control |

- **Arrow keys follow the live direction.** Components that map Left/Right read
  `getComputedStyle(host).direction` at keydown, or the aria pattern's `Directionality` under the
  0010 Part B live-direction host, so a live EN→AR switch needs no reload.
- **Escape** goes through the shared Escape stack (`tmPushEscapeDismissal`, 0005 §2.1) wherever a
  component dismisses something (toast with focus inside, reorder grab, chip overflow tooltip).
- **Focus is visible** through `--focus-ring` on `:focus-visible`; no `outline: none` without the
  ring.
- **Targets** are at least 24×24 px (0002 §6); icon-only buttons carry an accessible name.

**RTL.** Logical properties only. Directional glyphs mirror (`tm-icon` `mirrorInRtl`, §3.3).
Numeric runs that read as expressions are isolated LTR (`dir="ltr"`): counter, pager status,
`tm-kbd`, `tm-reference` value. Progress bars fill from inline-start. The tiles lattice flows from
inline-start. Arabic digits follow the formatting locale (`ar-SA`) through `TmL10n`.

**Stable layout (rule 2D).**

- Overlays never displace content: toasts, busy overlay, counters in `overlay` placement, drop
  indicators.
- Reserved space: the search field's clear button slot, the tree's spinner slot beside a loading
  node, the pager status width (decision 17), the inline counter's two-digit minimum, the copy
  button's icon swap (its label never changes).
- Recompute on resize only: chip-set collapse, segmented label visibility, tiles column count.
- Tabular digits (`font-variant-numeric: tabular-nums`) for every changing number.

**Motion.** No enter or exit animation on any new surface. Allowed motion: the switch knob
(`--duration-fast`), the progress bar's indeterminate sweep and the ring's spin; all three are
static under `prefers-reduced-motion: reduce`.

**Forced colors.** Every state that a tint conveys (selected tile, active segment, switch on,
counter tone, drop target) also has a border or glyph that survives `forced-colors: active`.

**Strings.** Every built-in string resolves through `TM_UI_TRANSLATE` under `tmUi.<group>`
(table in §3.10); consumer-facing text (titles, messages, labels) is passed in already localized.

### 3.3 Foundations: `icon`, `kbd`, `copy` (spec §3)

**`icon` decides how every new and future consumer-supplied icon is named, registered and drawn.**

```ts
type TmIconNode = readonly (readonly [tag: string, attrs: Readonly<Record<string, string | number>>])[]; // Lucide's IconNode
type TmIconSource = TmIconNode | { readonly node: TmIconNode; readonly mirrorInRtl?: boolean };      // @lucide/icons data fits
declare function provideTellmaIcons(icons: Readonly<Record<string, TmIconSource>>): EnvironmentProviders; // multi; later wins per name
declare class TmIconRegistry {                       // root
  register(icons: Readonly<Record<string, TmIconSource>>): void;
  get(name: string): { node: TmIconNode; mirrorInRtl: boolean } | undefined;
}
declare class TmIcon {                                // tm-icon
  readonly name: InputSignal<string | undefined>;     // kebab-case registry name: 'chevron-right'
  readonly svg: InputSignal<TmIconSource | undefined>; // direct data, bypasses the registry (library-internal use)
  readonly size: InputSignal<'xs' | 'sm' | 'md' | 'lg' | 'xl' | undefined>; // 12/14/16/20/24; unset → var(--icon-size)
  readonly label: InputSignal<string | undefined>;    // set → role="img" + aria-label; unset → aria-hidden
}
```

- **Rendering.** The host is `display: inline-flex`, square, `var(--icon-size)`; the component
  builds one `<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-linecap="round"
  stroke-linejoin="round">` (CSS sets `stroke-width: var(--icon-stroke-width)`) with
  `document.createElementNS` children from the node data. No `innerHTML`, so no Trusted Types policy.
- **Unknown name.** Renders an empty box of the same size (no layout shift) and logs one dev-mode
  error naming the icon and the registration call to add.
- **Mirroring.** `mirrorInRtl: true` flips the glyph with `scale(-1, 1)` when the computed direction
  is RTL. Directional glyphs carry it (`chevron-left/right`, `chevron-first/last`, `arrow-left/right`,
  `log-in`, `log-out`, `undo`, `redo`, `panel-left-open/close`), in the library's internal data
  and in 0024's platform registrations; magnifier, check and x never mirror.
- **Registration.** The library registers nothing globally; its own components pass `svg`
  directly (tree-shaken). `@tellma/core` registers the platform's names (0024); a distribution adds
  its own in one line (§7 request to 0024 for `tmFeature({ icons })`).
- **Containers set the size.** `tmButton` and `tm-menu` re-point `--icon-size` to their icon-size
  tokens (0010 Parts D and C, §6), so `<button tmButton><tm-icon name="plus" />New</button>` is
  right in every size.

**Example —** a distribution's section icon:

```ts
import { HandCoins } from 'lucide';
providers: [provideTellmaIcons({ 'hand-coins': HandCoins })]   // then: sections: [{ …, icon: 'hand-coins' }]
```

**`kbd` decides the key-combination grammar and how combinations render.**

```ts
type TmKeys = string;  // '+'-joined: modifiers Mod | Ctrl | Alt | Shift | Meta, then one KeyboardEvent.key ('K', 'Enter', '?', 'ArrowDown', 'F2')
declare function tmIsApplePlatform(): boolean;                         // userAgentData.platform ?? platform
declare function tmFormatKeys(keys: TmKeys, apple?: boolean): readonly string[]; // ['Ctrl', 'K'] | ['⌘', 'K']
declare function tmKeysMatch(event: KeyboardEvent, keys: TmKeys): boolean;      // Mod = Meta on Apple, Ctrl elsewhere
declare function tmAriaKeyShortcuts(keys: TmKeys): string;               // 'Control+K' | 'Meta+K'
@Component({ selector: 'tm-kbd' }) declare class TmKbd { readonly keys: InputSignal<TmKeys> }
```

- **Matching** compares `event.key` case-insensitively for letters and requires exactly the listed
  modifiers; `Shift` is implied by printable symbols (`'?'` matches Shift+/ on a US layout because
  `event.key` is `'?'`).
- **Rendering.** One `<kbd>` per key, caps 18 px tall, `dir="ltr"`, Latin key names in every
  language (keyboards print them in Latin). Apple glyphs: ⌘ ⌥ ⇧ ⌃.

**`copy` decides the copy affordance and the reference chip.**

```ts
declare class TmCopyButton {                          // tm-copy-button
  readonly text: InputSignal<string | (() => string | Promise<string>)>;
  readonly label: InputSignal<string | undefined>;    // accessible name; default tmUi.copy.copy
  readonly showLabel: InputSignal<boolean>;           // false (default): icon-only with tooltip
  readonly size: InputSignal<TmControlSize | undefined>; readonly copied: OutputEmitterRef<void>;
}
declare class TmReference {                           // tm-reference: '8f2c41ae…' mono, ltr-isolated
  readonly value: InputSignal<string>; readonly label: InputSignal<string | undefined>; // label default "Reference"
}
```

- **Copy.** `navigator.clipboard.writeText` inside the click; success swaps the icon to a check for

### 3.5 Feedback surfaces: `toast`, `banner`, `empty-state`, `busy-overlay`, `confirm`, `error-dialog` (spec §5)

**Toasts are a root service with one top-layer host; policy is the caller's.**

```ts
type TmToastTone = 'neutral' | 'accent' | 'success' | 'warning' | 'error';

  readonly tone: TmToastTone; readonly title: string; readonly detail?: string; // text localized by the caller
  readonly icon?: string;                             // registry name; default per tone
  readonly action?: { readonly label: string; readonly run: () => void }; // runs, then closes
  readonly duration?: number | 'sticky';              // ms; default 6000; error defaults to 'sticky'
  readonly key?: string;                              // a show() with an open key replaces it in place
}

  readonly closed: Promise<'timeout' | 'dismiss' | 'action' | 'api' | 'replaced'>;
}
interface TmToastsOptions {

}

declare class TmToasts {                              // providedIn root; works with zero configuration
  show(toast: TmToast): TmToastRef; clear(): void;

- **Host.** Created on the first `show`, appended to `<body>` as a `popover="manual"` element shown
  once (top layer, above CDK modals). Position: block-start inline-end at

- **Anatomy.** Card, radius md, `--shadow-lg`; tone icon, title (13/600), detail (12), optional
  action button, close button (28 px). Region `role="region"` named "Recent messages".
- **Timers.** Only visible toasts run their timers. All timers pause while the pointer is over the
  stack, while focus is inside it, and while the page is hidden, and resume with the time left.
- **Announcements.** The host holds two persistent visually hidden regions (`polite`,
  `assertive`); on show and on replace it writes "title. detail" into the polite one, or the
  assertive one for `error`. Visible toasts are not live regions.
- **Focus.** Toasts never take focus. `focus()` (0027 binds a shortcut, §7) moves focus to the
  newest toast; Tab and Shift+Tab move through toast buttons; Escape closes the focused toast and
  returns focus to where it was.

  readonly index: InputSignal<number>; readonly count: InputSignal<number>; // item mode, index 1-based
  readonly size: InputSignal<TmControlSize | undefined>;
  readonly previous: OutputEmitterRef<void>; readonly next: OutputEmitterRef<void>; // item mode (range mode writes `page`)
}
```

- **DOM.** Status `<span dir="ltr">` (tabular, `TmL10n` digits) with a visually hidden full sentence
  ("Items 1 to 20 of 55"); previous/next icon buttons (mirrored chevrons, named "Previous page"
  etc.); a `tm-select` page-size control showing "20 per page". Previous is disabled on the first
  page, next on the last (unknown total: next stays enabled).
- **No blocking.** A click while the previous page still loads simply writes `page` again; the
  consumer's `resource()` supersedes the request (rule 2C).
- **Width reservation** (decision 17): `min-inline-size` in `ch` = the length of
  `"{total}–{total} / {total}"`; the size select reserves its widest option.

**`tree` renders hierarchical, lazily expanded, optionally selectable and draggable nodes.**

- **Rendering.** Nested `ul[ngTree]` / `li[ngTreeItem]` / `ng-template[ngTreeItemGroup]` built by

- **Drag sources.** With `dragData`, each row's content element (not the `li`, so nested items
  never double-fire) is a `tmDragSource`. Dragging never changes selection or focus.

**`drag-drop` is a typed layer over native drag and drop.**

```ts
interface TmDragPayload {
  readonly kind: string;      // 'tm.path', 'acme.widget'; matched by drop targets
  readonly data: unknown;     // in-memory, same document only
  readonly text: string;      // written as text/plain: what a text field inserts at the drop caret
  readonly label: string;     // announcements
}
declare class TmDragSource {                          // [tmDragSource]
  readonly tmDragSource: InputSignal<TmDragPayload | null>; // null: not draggable
  readonly dragEnded: OutputEmitterRef<{ dropped: boolean }>;
}
interface TmDrop { readonly payload: TmDragPayload; readonly event: DragEvent }
declare class TmDropTarget {                          // [tmDropTarget]: class tm-drop-target--over while an accepted drag hovers
  readonly accepts: InputSignal<readonly string[]>;   // payload kinds
  readonly dropped: OutputEmitterRef<TmDrop>; readonly over: Signal<boolean>;
}
declare class TmDragDrop { readonly current: Signal<TmDragPayload | null> } // the drag in flight; targets show "Drop to add" before hover
```

- **Transfer.** `dragstart` sets `text/plain` = `text`, `application/x-tellma-drag` = a drag id, and
  `effectAllowed = 'copyMove'`; the payload itself stays in `TmDragDrop` (dataTransfer content is
  unreadable during `dragover`). A drop whose id is not the current drag (another window, a file) is
  ignored by `tmDropTarget`; text fields accept the `text/plain` natively.
- **Accessibility rule.** Every consumer offers a non-drag path to the same result (WCAG 2.5.7):
  the reorder list's handle (below), the studio's "Add to…" action on a field (0034), the column
  editor's checkbox (0030). Each consumer spec names its path and tests it.

**`tiles` renders a virtualized lattice of fixed-size tiles: image and four corners, a divided
list below `sm`, and a single-column tree in tree mode.**

```ts
type TmTileText = string | { readonly text: string; readonly numeric?: boolean; readonly badge?: TmBadgeTone };
interface TmTileImage { readonly src: string | null; readonly etag?: string | null; readonly alt: string }
interface TmTileLayout<T> {
  readonly image?: (item: T) => TmTileImage;          // absent: no image column; src null: placeholder glyph
  readonly title: (item: T) => string;                // top-start, primary weight
  readonly href?: (item: T) => string | null;         // the title renders as <a href> (new tab, copy link)
  readonly topEnd?: (item: T) => TmTileText | null;
  readonly bottomStart?: (item: T) => TmTileText | null;
  readonly bottomEnd?: (item: T) => TmTileText | null;
}
interface TmItemActivation<T> { readonly item: T; readonly id: TmRowId; readonly newTab: boolean } // same shape as the grid's rowActivate
declare class TmTiles<T> {                            // tm-tiles: fills its host's height; scrolls inside
  readonly data: InputSignal<readonly T[]>; readonly itemId: InputSignal<(item: T) => TmRowId>;
  readonly layout: InputSignal<TmTileLayout<T>>; readonly ariaLabel: InputSignal<string>;
  readonly loading: InputSignal<boolean>; readonly selectable: InputSignal<boolean>;
  readonly selectedIds: ModelSignal<ReadonlySet<TmRowId>>; // every change a fresh Set; foreign ids kept
  readonly activeId: ModelSignal<TmRowId | null>;    // arrows move it; the page may move it while focus stays in its search field
  readonly itemClass: InputSignal<((item: T) => string | null) | undefined>;
  readonly parentId: InputSignal<((item: T) => TmRowId | null) | undefined>; // set: tree mode
  readonly hasChildren: InputSignal<((item: T) => boolean) | undefined>;
  readonly expandedIds: ModelSignal<ReadonlySet<TmRowId>>;
  readonly loadChildren: InputSignal<((items: readonly T[]) => Promise<void>) | undefined>; // batched; the consumer appends rows
  readonly activate: OutputEmitterRef<TmItemActivation<T>>;
  scrollToItem(id: TmRowId, options?: { flash?: boolean }): void; focus(): void;
}
// ng-template[tmTileContent] replaces the tile body (fixed size kept); [tmTilesEmpty], [tmTilesLoading] like the grid's
```

- **Geometry.** Tile block size 60 px (40 px image + 9 px padding + hairline), radius 0, card fill,
  `--border-subtle`. Columns = `max(1, floor((W + gap) / (220 + gap)))` with gap 10 at container width
  `W ≥ 576`; below 576 (`TM_BREAKPOINTS.sm`), and always in tree mode, one column with no gap,
  divided by `--divider`. Column count changes only on resize. `scrollbar-gutter: stable`.
- **Corners.** Title 13/500 primary (ellipsis); top-end tabular when `numeric` (physical right in
  RTL, the grid's rule); bottom-start 12 px secondary; bottom-end a `tm-badge` when `badge` is set.
  Text cells are static DOM; `tmTileContent` is the costlier embedded-view path (the grid's
  `tmGridDisplay` trade-off).
- **Virtualization.** Lattice rows window through `tmComputeAxisWindow` (row pitch = 60 + gap,
  overscan 3 rows); the active tile is always rendered; `@for` tracks by `itemId`.
- **Activation.** A click or tap anywhere on a tile except its checkbox emits `activate`
  (`newTab` for Ctrl/Cmd-click and middle click); a click on the title link with a modifier follows
  the native link instead. Selectable tiles show a checkbox at inline-start (always reserved while
  `selectable`); a click there toggles selection only.
- **ARIA and keyboard (flat).** `role="grid"` with `aria-rowcount`/`aria-colcount`; lattice rows
  `role="row"` with `aria-rowindex`; tiles `role="gridcell"` with `aria-colindex` and
  `aria-selected` when selectable. One tab stop on the active tile (roving tabindex; the title link
  is `tabindex="-1"`). Arrows move by cell (Left/Right direction-mapped; Up/Down keep the column,
  clamped on a short last row); Home/End to row ends; Ctrl+Home/End to first/last; PageUp/Down by
  visible rows; Enter activates; Space toggles selection; Ctrl+Shift+Space toggles all loaded items
  (the grid's binding). Selection changes announce "{count} of {total} selected".
- **Tree mode.** `role="treegrid"`, one cell per row, `aria-level`, `aria-expanded`,
  `aria-posinset`/`aria-setsize`; indent 14 px per level with a twisty. Right expands or moves to the
  first child; Left collapses or moves to the parent. Expansion calls `loadChildren` once with every
  node that needs rows (batched, so restoring N remembered parents is one call); a reserved spinner
  slot shows per loading node; a rejection collapses and announces.
- **States.** `loading` with no data → skeleton tiles filling the viewport; `loading` with data →
  `aria-busy` and the existing tiles stay; no data → `tmTilesEmpty` or "No items to display".
  `scrollToItem(id, { flash: true })` scrolls the tile into view and tints it for 1 s ("came back
  from this record"). Built-in classes for `itemClass`: `tm-tiles__item--context` (muted, secondary
  text) and `tm-tiles__item--marked` (selected tint with an accent border).

**Example —** 0030 maps the entity declaration `tile: { image: 'ImageId', title: 'Name', subtitle:
'Code', badge: 'IsActive' }` to a `TmTileLayout`:

## 9. Assistant seam, telemetry, reference distribution

- **Page context.** The library publishes nothing (it knows no pages). Its state is in models
  (`selectedIds`, `activeId`, `expandedIds`, `expanded`, `value`, `size`), so the page frameworks
  can publish it (0026) and an assistant's `propose` writes reach the controls through Signal
  Forms like any user edit.
- **Telemetry.** None: `@tellma/core-ui` has no telemetry dependency. Dev-mode console warnings
  only (unknown icon, missing accessible name on an icon-only segment, tree over 500 rendered nodes).
- **Reference distribution.** Nothing distribution-specific: Acme exercises the components through
  the platform pages, and its `tmFeature({ icons })` line registers one extra icon (§3.3 example).
  The showcase stays the components' story host (skeleton §2.4).
