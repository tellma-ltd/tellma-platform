## 2. Decisions

1. **One host, four modes** (§3): `tm-report-host` renders a stored, coded or draft report in `page`,
   `card`, `widget` or `assistant` mode. Alt: one component per placement (four lifecycles).
2. **Renderers read only `ReportResult`** (§3.5), so a coded report renders and exports with no client
   code; 0033 adds chart layout and pivot expansion to the result (R1(a)). Alt: read the document.
3. **The first run starts in parallel with the definition read** (§3.2); a missing required argument
   returns `422` and shows the "fill in" state. Alt: read, then run (a serial round trip per open).
4. **Arguments apply on commit, never per keystroke** (§4.3); the superseded run is aborted. Alt: a
   Run button only (Refresh stays, for unchanged arguments).
5. **The URL carries supplied and explicitly omitted values only** (§4.4), so a shared link
   re-evaluates `today()`. Alt: effective values (yesterday's link shows yesterday).
6. **Remembered parameters exclude defaulted ones** (§4.5). Alt: remember all (a stale "As of").
7. **`spinner` dims the held output; `run({ clear: true })` clears; `silent` swaps on arrival**
   (§3.4). Alt: always clear (the layout jumps on every parameter change).
8. **`tm-pivot` takes a pre-ordered member tree and a cell-text callback** (§6.1): no report
   knowledge, no aggregation, formatting only for rendered cells. Alt: feed it `ReportCube`.
9. **Compact row form; column subtotals after their children; four styles plus the phantom**
   (§6.2–§6.3). Alt: tabular form (one column per row dimension; trees do not fit).
10. **Members re-sort on the client after a language switch** (§6.6); cells stay the server's. Alt:
    re-run (the switch would wait on the network).
11. **`tm-chart` is a JSON `TmChartSpec` over `echarts/core`, canvas only, loaded lazily; `card`
    never loads it** (§7). Alt: `ngx-echarts` (single maintainer); the SVG renderer (no v1 need).
12. **No ECharts HTML component; tooltip and legend are Angular** (§7.5): ECharts' tooltip writes
    `innerHTML`, which Trusted Types refuses. Alt: a policy blessing ECharts' HTML (an XSS hole).
13. **The plot never mirrors in RTL; its text does** (§7.6), as the design, Excel and AG Charts do.
    Alt: reversed category axes (charting research Part 4 #10).
14. **Eight validated categorical tokens led by teal, a teal ramp, a teal–orange diverging pair, decals
    whenever colour alone separates series** (§7.7). Alt: the design's single accent.
15. **Charts are keyboard and screen-reader first class** (§7.8): arrows between points, Enter drills,
    a hidden table up to 500 points, a "Show as table" view at any size. Alt: the hidden table only.
16. **Visibility Q2: always the drill-through list**, child entities included, with "Open in
    {plural}" for top-level roots (§8, section 4).
17. **The drill list renders no URL text** (§8.4): chips come from the drilling report's navigation
    state or, for a bare link, from path labels found by `queryex/discover`.
18. **Export: one action per renderer, synchronous first, background on `413`** (§9). Alt: choose by
    count (pivots and charts have none).
19. **The reports page is the `core.ReportDefinition` search hatch; tabs are `x.tab`; coded reports
    lead page 1 of Shared with me and All** (§11), through a 0030 read hatch (R3). Alt: a bespoke page.
20. **Report page = details hatch; `/reports/new` and `?clone=` open the studio; `/reports/{id}/studio`
    edits** (§10, §12). Alt: edit mode on the report page (edit mode is never in a URL, A§8).
21. **The studio owns its lifecycle and saves through `reports/save`** (§12.9), reusing drafts, the
    leave guard and the concurrency dialog. Alt: 0031's host (a form over a JSON string column).
22. **The definition panel is a `data-theme="dark"` scope** (§12.2), in both app themes.
23. **Three feedback layers** (§12.7): client rules and the lexer per keystroke, discover at 250 ms,
    a preview run at 600 ms that validates the whole document.
24. **Every kind's block stays in memory; a new kind is seeded once; only the active block is saved**
    (§12.6). Alt: destructive conversion on every switch.
25. **One drop table** (§12.5): lists take the path, measures `sum(path)` (numeric) or
    `count(path)`, filter and having the text at the caret; "Add to…" is every drop's non-drag path.
26. **Share changes are staged and saved as one `share` and one `publish`** (§10.4). Alt: a request
    per click (partial states, notification noise).
27. **Coded reports declare `route`; `run` and `component` are hatches; defaults live in C#** (§2.2).
    Alt: A§3.4's closure and client `default` (challenge 1).
28. **A card is 360 px tall by default** (§3.6): a details page never moves when data arrives.
29. **No header sorting in report tables in v1** (§5.4); the drill list, a plain query, sorts. Alt: an
    order override on `run`.

### §1 Placement and vocabulary

| Entry point | Exports | Loaded | Budget (gzip) |
|---|---|---|---|
| `@tellma/core-ui/pivot` | `TmPivot` (`tm-pivot`), `TmPivotModel`, `TmPivotMember`, `TmPivotCell` | with the pivot renderer | 14 KB |
| `@tellma/core-ui/chart` | `TmChart` (`tm-chart`), `TmChartSpec` and parts, `TM_CHART_SPEC_SCHEMA`, `tmValidateChartSpec` | with the chart renderer | 9 KB + engine chunk ≤ 160 KB (A§11: 170 KB) |
| `@tellma/core` primary | `tmCodedReport`, `TmCodedReportDeclaration`, `TmCodedParameter`, `TmReportRef`, `TmReportArgs` | eager | 0.5 KB |
| `@tellma/core/reports` | `TmReportHost`, `injectTmReportHost`, `TmReportDrillEvent`, `TmShareDialog`, `tmReportArgsFromUrl`/`ToUrl`, wire types `TmReportResult`, `TmReportDocument` | lazy route | 24 KB |
| `@tellma/core/report-studio` | `TmReportStudio` | lazy route, `on-demand` group | 28 KB |

- **Imports.** `/reports` imports the primary, `/entity`, `/search` and both `core-ui` entry points;
  `/report-studio` imports `/reports`. `core-ui/chart` reaches ECharts only through a dynamic
  `import()`, so list, summary and pivot pages never fetch it and only that chunk is `on-demand`.
- **Folders** `client/projects/core/tellma-core-ui/{pivot,chart}/` and
  `client/projects/core/tellma-core/{reports,report-studio}/`. Harnesses: `TmPivotHarness`,
  `TmChartHarness` (`core-ui-testing`); `TmReportHostHarness`, `TmReportStudioHarness`,
  `TmShareDialogHarness`, `tmReportResultFixture` (`core-testing`).
- **Wire mirrors.** `TmReportDocument` and `TmReportResult` mirror 0033's records member for member;
  a conformance test validates fixtures against the JSON Schema 0033's records export.

**Vocabulary:** *report* (what the host renders: a definition, a coded report, a draft); *run* (one
`reports/run` or coded-route call); *arguments* (`TmReportArgs` sent) and *effective arguments* (the
run's echoed `Arguments`); *bound argument* (fixed by the embedding page, hidden from the bar);
*output* (the renderer region); *coordinate* (the members a click identifies); *member* and
*phantom* (0033 §8.6); *studio draft* (the unsaved definition).

### §2 What a distribution writes

Stored definitions need no code. A coded report is one declaration; a report in a details card is
three lines.

#### §2.1 A report in a details card

```html
<!-- customers/customer-details.ts: the customer's aging, bound to the record -->
<tm-details-card titleKey="Acme_Customer_Aging" flush>
  <tm-report-host [report]="{ key: 'acme-aging' }" [parameters]="{ Customer: details.entity()?.id ?? null }" />
</tm-details-card>
```

- A seeded definition embeds by code (ids differ per tenant): `[report]="{ code: 'acme.sales-by-center' }"`
  (R1(b)). `null` binds as omitted (0033 §4.4), so create mode shows the report unfiltered.

#### §2.2 `tmCodedReport`

```ts
// @tellma/core (primary)
declare function tmCodedReport(key: string, report: TmCodedReportDefinition): TmCodedReportDeclaration;
interface TmCodedReportDefinition {
  readonly titleKey: string; readonly descriptionKey?: string;
  readonly securable: TmSecurableRef;                     // gates the route, the launcher entry, the reports page row
  readonly section?: string; readonly order?: number; readonly icon?: string; readonly synonymsKey?: string; // 0027 §3.2
  readonly kind: 'list' | 'summary' | 'pivot' | 'chart';  // the skeleton before the first result
  readonly parameters?: Readonly<Record<string, TmCodedParameter>>; // bar order = declaration order
  readonly route?: string;                                // common case: the [ApiAction] route; run, retry, cancel, export
  readonly run?: (api: TmApi, args: TmReportArgs, signal: AbortSignal) => Promise<TmReportResult>; // hatch; no export
  readonly component?: TmLazyComponent;                   // hatch: replaces the output; reads injectTmReportHost()
}
interface TmCodedParameter {
  readonly type?: 'string' | 'number' | 'bool' | 'date' | 'datetime' | 'instant' | 'guid'; // 'number' with entity, else 'string'
  readonly entity?: string;                               // a picker
  readonly required?: boolean;                            // the bar's marker; the server owns defaults
  readonly labelKey?: string;                             // default `<titleKey>_<Key>`, else the key
}
type TmReportArgs = Readonly<Record<string, TmJson>>;     // 0033 §4.4 encoding; null = omitted
```

**Example —** Acme's aging report (A§3.4, reworded; 8 lines):

```ts
export const agingReport = tmCodedReport('acme-aging', {
  titleKey: 'Acme_Report_Aging', section: 'sales',
  securable: ['acme.AgingReport', 'Read'], kind: 'summary',
  parameters: { AsOf: { type: 'date', required: true }, Customer: { entity: 'acme.Customer' } },
  route: 'acme-reports/aging',                            // C#: AsOf ?? today, echoed as Default
});
```

- **Body.** `TmApi.read(route, args, { signal, long: true })` with members = the keys in camelCase
  (`{ "asOf": "2026-10-20", "customer": 1012 }`); the C# record names its properties after the keys
  (R1(e)). Export sends `{ route, arguments }` (0033 §12.1).
- **Defaults live in C#**, echoed with source `Default`; a required value the method cannot supply
  answers `422 Report.ArgumentRequired` (R1(e)), shown as "fill in" (§3.3).
- **Sources.** Exactly one of `route`, `run`, `component`, or `component` with `route` (the component
  then renders the host's result). Otherwise `tellma-client build` reports `coded-report-source`
  (R2(b)), beside 0024's key checks.
- **`component`** renders inside the report page chrome and reads `injectTmReportHost()` (`args`,
  `result`, `generation`, `signal`); without `route` it fetches through `TmApi` and Export is absent.
- **Derived:** `/{t}/reports/{key}`, the launcher entry, the reports page row, context, telemetry.

#### §2.3 The platform's declaration


### §3 The report host

`TmReportHost` runs one report and renders its bar, output, states and toolbar. Every placement is a
`mode`; components inside it read it through `injectTmReportHost()`.

#### §3.1 Contract

```ts
// @tellma/core/reports
type TmReportRef =                                        // primary, types only
  | { readonly id: number } | { readonly code: string }   // a report definition
  | { readonly key: string }                              // a coded report
  | { readonly draft: TmReportDraft };                    // the studio's or the assistant's document
interface TmReportDraft { readonly root: string; readonly kind: 'List' | 'Summary' | 'Pivot' | 'Chart'; readonly document: TmReportDocument }

@Component({ selector: 'tm-report-host' })
declare class TmReportHost {
  readonly report: InputSignal<TmReportRef>;
  readonly mode: InputSignal<'page' | 'card' | 'widget' | 'assistant'>;  // default 'card' (§3.6)
  readonly parameters: InputSignal<TmReportArgs | undefined>;           // bound arguments
  readonly showParameters: InputSignal<boolean | undefined>;            // default: page and assistant only
  readonly refresh: InputSignal<'spinner' | 'silent'>;                  // default 'spinner' (§3.4)
  readonly dashboardId: InputSignal<number | undefined>;                // read-through (0033 §8.2)
  readonly overlay: InputSignal<TmReportOverlay | undefined>;           // studio presentation edits (§12.8)
  readonly drill: OutputEmitterRef<TmReportDrillEvent>;                 // §8.2
  readonly ran: OutputEmitterRef<TmReportResult>;
  readonly status: Signal<'waiting' | 'loading' | 'ready' | 'error'>;   // waiting: a required argument is empty
  readonly args: Signal<TmReportArgs>; readonly result: Signal<TmReportResult | undefined>;
  readonly error: Signal<TmApiError | null>; readonly executedAt: Signal<string | null>; // "Last refreshed" (0035)
  readonly generation: Signal<number>; readonly signal: Signal<AbortSignal>;           // for a coded component
  setArgs(patch: TmReportArgs): void;                                   // the bar's commits; null = omitted
  run(options?: { clear?: boolean }): void; cancel(): void; export(): Promise<void>;
}
declare function injectTmReportHost(): TmReportHost;
```

- **One `resource()`** keyed by (report, bound arguments, `args`, generation): a new key aborts the
  run in flight and leaving aborts through `DestroyRef`; the server sends SqlClient an attention
  (0033 §8.9).
- **Transport.** `id`, `code`, `draft` → `reports/run { id | code | draft, arguments, dashboardId,
  take, includeCount }`; `key` → the declaration's `route` or `run`. Always `TmApi.read(…, { signal,
  long: true })`, a retried, cancellable long read (0024 §10.5).
- **Arguments sent** = bound ∪ `args`, bound winning. The bar renders the effective arguments, so
  defaults show their values.

#### §3.2 Opening a report page

1. The route host's `report` skeleton (header, bar row, output block, final geometry; R2(a))
   renders in the click's frame.
2. The page reads `reports/get` (title, document, the `permissions` extra, R1(c)) or the coded
   declaration; the host starts the run at the same time (decision 3). Until the definition lands
   the bar shows skeleton fields at final width.
3. The result renders, the page registers its context (§13.1) and records `tm.report.run`.

**Example —** `/17/reports/42?p.Customer=1012`: `get 42` and `run { id: 42, arguments: { Customer:
1012 } }` leave together; the result echoes `AsOf = 2026-10-20 (Default)`, which the bar shows.

#### §3.3 Output states

| State | When | Shows | Actions |
|---|---|---|---|
| first load | no result yet | the kind's skeleton (12 rows, a pivot block, a chart frame) | Cancel after 2 s ("Still running…") |
| reloading | a held result and a `spinner` run | the held output at 0.6 opacity, inert, `aria-busy`; a 2 px progress bar after 150 ms | Cancel after 2 s |
| waiting | a required argument is empty, or `422 Report.ArgumentRequired` | `sliders-horizontal`, "Fill in the required parameters" and their labels | focus the first |
| invalid argument | `422 Report.ArgumentInvalid` | the field's error popover and the waiting state | — |
| no data | an empty table, cube or series | `inbox`, "No data for these parameters" | — |
| too much data | `413` (`TooManyRows`, `TooManyPoints`, `TooManyCells`, `limit-exceeded`) | `circle-alert`, "This report returns too much data to show", "Add a filter or narrow the parameters." | Export |
| needs fixing | `400 query-invalid` | `wrench`, "This report no longer runs", "A field it uses has changed." | Edit (`permissions.save`) |
| forbidden | `403` | `lock`, "You don't have access to the data in this report" | — |
| not found | `404` | `search-x`, "This report doesn't exist or isn't shared with you" | Reports |
| offline, failed, outdated | as 0030 §5.3 | the same copy, `tm-reference` with the trace id | Try again / Reload |

- States render inside the output box (`tm-empty-state`, `live="polite"`), so the header and the bar
  never move. `cancelled` is silent and returns to the previous result.
- `cube.truncated` (0033 §9.3) adds an info `tm-alert` above the pivot: "Center shows 4 of 6 levels.
  Deeper values are included in their level-4 parents."

#### §3.4 Refresh modes

| Trigger | `spinner` | `silent` (dashboard auto-refresh) |
|---|---|---|
| first run | skeleton | skeleton |
| argument change, `run()` | held output dimmed with the progress bar | held output, no indicator; swapped on arrival |
| `run({ clear: true })` | cleared to the skeleton at once (the brief's force refresh) | same |
| failure with a held result | the error state | held output kept; a 16 px `circle-alert` beside "Last refreshed", the error in its tooltip |

- The swap is one change-detection pass, never animated. A `silent` run passes `background: true`,
  so it sends `Tellma-Activity: background` and stamps no activity (0033 §8.9).

#### §3.5 From result to renderer

- **The renderer follows `result.kind`**; before the first result, the declaration's `kind` or the
  definition's `Kind`, so the skeleton and the chart engine's `import()` start with the data request.
- **Column labels**, first that exists: the active slot's `label…` (fallback slot 1), `labelKey`,
  the slash label of `path` from the root's descriptor (0029 §11.4; root = `result.root`, R1(a)).
  Labels are content, so a language switch re-labels with no run (0033 §9.1).
- **Values** format through one function, `tmReportFormat(column, raw)`: navigations through
  `TmDisplayNames.of(entity, row)` built from 0033 §9.2's ordinals; text terms in the active slot;
  `display` and `format` over `TmFormats` (`percent` × 100, `integer`, `enum` through
  `TmEntities.enum(name)`, R4(c)); `month`, `quarter`, `year` through 0010 Part D's new styles in
  `format.calendar` (D.7, R1(d)); `date` in the viewer's calendar. Numbers stay physically right.
- **Renderers:** List and Summary (§5), Pivot (§6), Chart (§7); a coded `component` replaces them.

#### §3.6 Modes

| Element | `page` | `card` | `widget` | `assistant` |
|---|---|---|---|---|
| title, description | the page header (§10.1) | the card's heading | 0035's tile | a title line |
| parameter bar | shown | hidden unless `showParameters`; bound arguments never | hidden (brief) | compact |
| toolbar | the page header's (§10.2) | `…` menu in the card's actions: Refresh, Export, Open report | none (0035 calls `run`, `export`) | Open report, Export |
| footer | "1–200 of 1,214 rows · updated 10:42" and the pager | compact | none | compact |
| URL, page state | `p.*` and page state (§4.4, §3.7) | never | never | never |
| block size | fills `main` | 360 px (`--tm-report-height`), scrolls inside | fills the tile | 320 px |
| drill-through | navigates | navigates | navigates (0035 may prevent) | emits only |
| page context | `report` (§13.1) | in the details context's `visible` (R8(b)) | the dashboard's | the assistant overlay's |

#### §3.7 Page state

- `page` mode remembers `{ args, result, scroll, pivotExpansion, chartAsTable }` under the page key
  (`/17/reports/42`, 0025 §10) on destroy. A return within the SPA renders it with no request; an
  entry older than 5 minutes also re-runs `silent` (review flag 4). Results never touch disk.

### §4 Parameters and the parameter bar

The bar renders one typed control per declared parameter (document or coded declaration), applies a
value on commit, and keeps the URL and remembered values in step.

#### §4.1 Controls by type

| Type | Control (`tm-form-field`, 168 px; 44 px tall below `sm`) | Commit | URL text |
|---|---|---|---|
| `Numeric` + `entity` | `tm-entity-field [entity]` (0029 §14) | pick, clear | `p.Customer=1012` |
| `Numeric` | `input[tmNumber]` | Enter, blur | `p.Year=2026` |
| `String` | `input[tmInput]`, `dir="auto"` | Enter, blur | `p.Region=East` |
| `Bool` | `tm-select`: Any (optional only), Yes, No | selection | `p.Posted=true` |
| `Date` | `tm-date-picker`, viewer's calendar | pick, Enter, blur | `p.AsOf=2026-10-01` |
| `DateTime` | `tm-date-picker`; the day's `T00:00:00` | as `Date` | `p.Since=2026-10-01T00:00:00` |
| `DateTimeOffset` | `tm-date-picker`; the day's first instant in the display zone (0029 §13.2) | as `Date` | `p.Since=2026-09-30T21:00:00%2B00:00` |
| `Guid` | `input[tmInput]`, mono, `dir="ltr"` | Enter, blur | `p.Ref=…` |

- **Labels** follow §3.5's chain; required parameters carry the field's marker.
- **Clearing** an optional value sends `null` (no restriction); clearing a required one shows
  "Required" and the waiting state, and sends nothing.
- **Defaults show as values** from the effective arguments; the hint reads "Default" until changed.
  The bar's "Reset" restores every default. One id per entity parameter (no list parameters, 0008).

#### §4.2 Layout

- **Row.** Fields wrap in one row (12 px gaps) under the page header, ended by Refresh
  (`refresh-cw`). Its height depends only on field count and width: errors are focus popovers
  (0002), so nothing moves while typing.
- **Below `sm`:** one "Parameters" button and a one-line summary ("As of 20 Oct 2026 · Customer:
  Olive Inc."); it opens an end drawer (`TmModal` `placement: 'end'`) whose Apply commits all fields.

#### §4.3 Commit and run

1. A control commits; `setArgs({ Key: value })` replaces that key.
2. If a stored definition's required parameter has neither value nor `default`, the host shows the
   waiting state and sends nothing; otherwise it runs. A coded report always runs: its server decides.
3. The run in flight is aborted; the page writes the URL (§4.4) and remembered values (§4.5).

- **Refresh** (and Mod+Enter in a field) re-runs the same arguments with a new generation.

#### §4.4 The URL: `p.{Key}`

- **Codec.** `tmReportArgsFromUrl(params, declarations)` / `tmReportArgsToUrl(args, declarations)`
  read and write 0033 §4.4's culture-free text with 0024 §9.5's encoding. Keys match ignoring case;
  the declaration's spelling and order are written.
- **Written:** a supplied value as `p.Key=<text>`; an explicit omission of a defaulted parameter as
  `p.Key=`; a parameter at its default not at all (decision 5).
- **History:** argument changes `replaceUrl` (one entry per report). Invalid text or an unknown key
  is dropped from the arguments and the URL (`tm.report.arg-dropped`).

**Example —** `/17/reports/42?p.Customer=1012&p.To=` runs with `Customer = 1012`, `To` omitted and
`From` at its default.

#### §4.5 Precedence and remembered values

1. **URL:** any `p.*` defines every argument; absent keys take defaults (0030 decision 6).
2. **Page state** (§3.7), else
3. **`report.<id|key>.params`** (write-behind, R6(a)), else
4. **nothing:** the server applies defaults.

- **Remembered:** `{ v: 1, args }` with the supplied values of parameters that have no default (for a
  coded report: values whose last effective source was not `Default`); an empty object resets the
  key. Bound arguments never read or write it.

### §5 List and Summary renderers

Both render a `ReportTable` (0033 §9.2) in the readonly `tm-grid` with a frozen header. A list row
opens its record; a summary row drills through.

#### §5.1 Binding

- **Grid.** `gridId` `report.<id|key>`, `contentKey` the run's key, `rowActivation="row"`,
  `rowHeaders: false`, plain look, zebra, 30 px rows, `scrollbar-gutter: stable` (BE C.1, C.6, C.7).
- **Columns.** One per `ReportColumn`, cells from `Table.ColumnOrdinals[i]` through
  `tmReportFormat`. Widths never depend on data: text and navigation `flex 1.6` (min 160), numbers
  120, dates 110, booleans 72, images 56. List navigation cells link to the target's details when
  `TmPermissions.allows(target, 'details')` (0030 §7.2).
- **Footer.** "{shown} of {count} rows · updated {time}" (`count+` when capped) and, when the count
  exceeds a page, `tm-pager` (range mode, 200 per page, no size select); paging pushes no history.

#### §5.2 List

- **Activation** (click, Enter; Mod for a new tab) opens `Table.Identity`'s record: `TmUrls.details(
  entity, id)`, or for a child root `TmUrls.details(ownerEntity, ownerId, { collection, id })`, which
  0031 opens on the child tab, scrolled and flashed. Hover and focus preload the details chunk.

#### §5.3 Summary

- **Activation** drills through the row's coordinate (§8.1). Key cells are never links.
- **Totals** (`totals: true`) render `Table.Totals` as a footer row pinned at the block end
  (`footerRows`, C.13): 600, sunken fill, a 2 px `--border-strong` top rule, "Total" in the first key
  column; activating it drills with no condition.

#### §5.4 Not in v1

- No header sorting (decision 29), no column editor or filters: the definition decides; Edit opens
  the studio.

### §6 `tm-pivot` and the Pivot renderer

`tm-pivot` renders a two-axis member tree as an Excel-style pivot. It is domain-free: the Pivot
renderer maps a `ReportCube` onto it and formats the cells.

#### §6.1 Contract

```ts
// @tellma/core-ui/pivot
interface TmPivotMember {
  readonly id: number;                          // unique on its axis
  readonly parent: number | null;               // null: a root (the total, or a first level without totals)
  readonly kind: 'member' | 'phantom' | 'none' | 'total';
  readonly label: string;                       // display-ready; the pivot appends "(direct)" to a phantom
  readonly attributes?: readonly string[];      // rows only, parallel to attributeLabels
}
interface TmPivotModel {
  readonly rows: readonly TmPivotMember[];      // pre-order: a member, then its children in display order
  readonly columns: readonly TmPivotMember[];
  readonly measures: readonly string[];         // ≥ 1 label
  readonly rowLabel: string;                    // corner: the row dimension names, " / "-joined
  readonly columnLevelLabels: readonly string[];// one per column header level
  readonly attributeLabels: readonly string[];
  text(row: number, column: number, measure: number): string | null; // formatted; null = no facts
}
@Component({ selector: 'tm-pivot' })
declare class TmPivot {
  readonly model: InputSignal<TmPivotModel>;
  readonly expandedRows: ModelSignal<ReadonlySet<number>>; readonly expandedColumns: ModelSignal<ReadonlySet<number>>;
  readonly activatable: InputSignal<boolean>;   // default true: value cells are drill targets
  readonly ariaLabel: InputSignal<string>; readonly size: InputSignal<TmControlSize | undefined>;
  readonly cellActivate: OutputEmitterRef<TmPivotCell>;
  expandAll(axis: 'rows' | 'columns'): void; collapseAll(axis: 'rows' | 'columns'): void; focus(): void;
}
interface TmPivotCell { readonly row: number; readonly column: number; readonly measure: number; readonly newTab: boolean }
```

- `text` runs only for rendered cells: a 500,000-cell cube costs nothing until shown, and a language
  switch reformats only the window. Expansion sets are the caller's models.

#### §6.2 Layout

- **Rows (compact form):** one row-header column; 16 px indent per depth; a 13 px twisty (mirrored in
  RTL) on members with children; a parent's row carries its subtotal, its children follow; the
  `total` member renders last and never collapses.
- **Columns:** a leaf or collapsed member is one group; an expanded member's group is its children
  then its subtotal column "{label} total" (`tmUi.pivot.subtotal`); the `total` member comes last as
  "Total". A group holds one data column per measure.
- **Header rows:** one per column level, plus measure names when there are two or more measures (at
  least one row). A member's header cell spans its group; a leaf or collapsed member's cell spans
  down to the last level. Corner cells show each level's `columnLevelLabels` entry at the inline
  end, and `rowLabel` with the `attributeLabels` on the last header row.
- **Widths** depend on container and column count only: row header 280 px (resizable 160–600),
  attributes 96 px, data columns share the rest (min 96 px), else 112 px each with sideways scroll.
- **Frozen:** header rows sticky at the block start, row-header and attribute columns at the inline
  start, the corner on both; 30 px rows and header cells; `scrollbar-gutter: stable` on both axes.
- **Virtualized:** body rows through `tmComputeAxisWindow` (overscan 4), data columns likewise past
  40; the focused cell always renders. Flattening is O(members) per toggle; 0033 caps a cube at
  20,000 row and 2,000 column members.

#### §6.3 Styles

| Style | Applies to | Look |
|---|---|---|
| `total` | the grand total row and column | sunken fill, 600, a 2 px `--border-strong` rule on its block-start (row) or inline-start (column) edge |
| `subtotal-1` | depth-1 members with children | sunken fill, 600, `--text-strong` |
| `subtotal-2` | depth-2 members with children | card fill, 600 |
| `leaf` | every other member, deeper parents included | card fill, 400, `--text-body` |
| `phantom` | a phantom member | `leaf` in `--text-secondary`, italic label with "(direct)" |

- A data cell takes the stronger of its row and column styles; the ladder matches 0033 §12.3's
  workbook. Numbers are tabular, physically right, LTR-isolated; a blank cell is empty, never "0".
- **Drill affordance** (the design): a hovered or focused value cell shows the hover fill,
  `--color-primary` text, an underline at 3 px and a 1 px accent inset ring.

#### §6.4 Keyboard and ARIA

| Focus | Key or gesture | Effect |
|---|---|---|
| any cell | arrows (Left/Right direction-mapped), Home/End, Mod+Home/End, PageUp/PageDown | move, headers included |
| value cell | Enter, click (Mod: `newTab`) | `cellActivate` |
| expandable row or column header | Enter, Space, twisty or label click | toggle |
| any cell of a row | Alt+ArrowRight / Alt+ArrowLeft | expand / collapse the row (0004's tree-grid keys) |
| column header | Alt+ArrowDown / Alt+ArrowUp | expand / collapse the column |
| any cell | Mod+C | copy its text |

- One tab stop (roving tabindex, real focus). The root is `role="treegrid"`, `aria-readonly`,
  `aria-rowcount` (headers + visible rows), `aria-colcount`. Header cells are `columnheader` with
  `aria-colindex`, `aria-colspan` and, when expandable, `aria-expanded`. Body rows carry
  `aria-rowindex`, `aria-level`, `aria-posinset`, `aria-setsize`, `aria-expanded`; the first cell is
  a `rowheader`. Toggles announce politely: "Riyadh expanded, 3 rows".

#### §6.5 The Pivot renderer

- **Members** map from `cube.rowMembers` and `columnMembers` (0033 §9.3): `Member` labels through
  `tmReportFormat` (navigations from `display`), `None` "(None)", `Total` "Total", `Phantom` its
  parent's label. `rowLabel` joins the row dimension labels; `columnLevelLabels[j]` names the owning
  dimension on its first level only.
- **Cells** sit in one `Map` keyed `row × stride + column`; `text` formats `values[measure]` with
  the measure column.
- **Initial expansion:** members with children whose dimension has `expand` true (default;
  `ReportColumn.Expand`, R1(a)); kept in page state. Actions `report.expand-all`, `.collapse-all`.

#### §6.6 Member order

- Siblings follow 0033 §9.3: values by value (`order`), navigations and text by label with
  `Intl.Collator(locale, { numeric: true })`, "(None)" last and the phantom first in either direction.
- The renderer applies the rule on every build and when the slot or locale changes (decision 10);
  member ids, and the expansion sets, are stable.

### §7 `tm-chart` and the Chart renderer

The facade owns what users see and touch (spec, palette, RTL, text, tooltip, legend, keyboard,
table); ECharts draws marks on a canvas behind one internal adapter.

#### §7.1 Contract

```ts
// @tellma/core-ui/chart
type TmChartType = 'column' | 'bar' | 'line' | 'area' | 'pie' | 'doughnut' | 'heatmap' | 'treemap' | 'gauge' | 'card';
interface TmChartSpec {                                    // JSON; TM_CHART_SPEC_SCHEMA
  readonly type: TmChartType;
  readonly title: string;                                  // accessible name; hosts draw visible titles
  readonly dimensions: readonly { readonly label: string; readonly members: readonly { readonly label: string }[] }[]; // 0–2, display order
  readonly measure: { readonly label: string; readonly format?: { readonly minDecimals?: number; readonly maxDecimals?: number; readonly grouping?: boolean; readonly percent?: boolean } };
  readonly rows: readonly (readonly [d0: number | null, d1: number | null, value: number | null])[]; // member indexes
  readonly options?: TmChartOptions;                       // 0033 §3.1's chart options, unchanged
}
@Component({ selector: 'tm-chart' })
declare class TmChart {
  readonly spec: InputSignal<TmChartSpec>;
  readonly asTable: ModelSignal<boolean>;                  // the table view (§7.8)
  readonly activatable: InputSignal<boolean>;              // default true
  readonly pointActivate: OutputEmitterRef<{ readonly members: readonly [number | null, number | null]; readonly newTab: boolean }>;
  focus(): void;
}
declare function tmValidateChartSpec(spec: unknown): readonly { readonly pointer: string; readonly code: string }[];
```

- Rows index the member lists, so a spec is compact, ordered, and safe to log or hand an agent;
  labels are text, never markup. `tmValidateChartSpec` (schema plus §7.2's counts) serves the
  assistant and `@tellma/core-ui-mcp` before rendering.

**Example —**

```json
{ "type": "column", "title": "Monthly sales",
  "dimensions": [ { "label": "Month", "members": [ { "label": "Sep 2026" }, { "label": "Oct 2026" } ] },
                  { "label": "Customer type", "members": [ { "label": "Corporate" }, { "label": "Retail" } ] } ],
  "measure": { "label": "Sales", "format": { "maxDecimals": 0 } },
  "rows": [ [0, 0, 365000], [0, 1, 120000], [1, 0, 298000], [1, 1, null] ], "options": { "stack": "stacked" } }
```

#### §7.2 Types and dimensions

| Type | Dims | Drawn as | Notes |
|---|---|---|---|
| `column` / `bar` | 1–2 | vertical / horizontal bars over categories | d1 makes series; `stack`; `large` mode past 2,000 points |
| `line` / `area` | 1–2 | lines / filled lines; `markers` | `sampling: 'lttb'` past 2,000 points; `stack` (area) |
| `pie` / `doughnut` | 1 | disc / ring (inner 55 %), clockwise from 12 o'clock | `labels` shows member and share; empty centre |
| `heatmap` | 2 | d0 across, d1 down, colour by value | sequential (default) or diverging; a min–max scale |
| `treemap` | 1–2 | nested rectangles, d0 then d1 | colour by the d0 member |
| `gauge` | 0 | arc from `min` to `max` with threshold bands | `min` 0; `max` the largest of value and thresholds |
| `card` | 0 | the value 28/600 and the measure label; no engine | a threshold shows as a badge with its word |

- One measure, one value axis (0033). Empty rows render the host's no-data state, never empty axes.
- **Normalized stacks** plot each value's share of its category's plotted values: layout only, no
  computed total is displayed, and the tooltip shows share and value (review flag 7).

#### §7.3 The engine

- **Modules:** `echarts/core` with `use([BarChart, LineChart, PieChart, HeatmapChart, TreemapChart,
  GaugeChart, GridComponent, VisualMapComponent, AriaComponent, CanvasRenderer])`. Never the
  umbrella import or `ngx-echarts`; no SVG renderer; none of Tooltip, Legend, Title, Toolbox,
  DataZoom (decision 12).
- **Lazy:** engine and adapter are one internal chunk (≤ 160 KB gzip, `on-demand`), imported on the
  first non-`card` spec; the renderer starts the import with the run.
- **Adapter** (one internal file, the only ECharts importer): `render`, `update`, `resize`,
  `highlight(point | null)`, `pixelOf(point)`, `pointAt(x, y)`, `dispose`. An engine swap (uPlot for
  dense lines, research Part 5) rewrites that file.
- **Lifecycle:** `afterNextRender` creates the instance (zoneless); an `effect()` over spec, theme,
  direction and locale calls `setOption(option, { notMerge: true })`; one `ResizeObserver`, coalesced
  to a frame, calls `resize()`; a `matchMedia('(resolution: <dpr>dppx)')` change re-creates it;
  `DestroyRef` disposes. `animation: false` (A§11; deterministic visual tests).

#### §7.4 Text and formatting

- **Numbers** for tooltips, labels and the table use `tmFormatNumber` (0005 §2.2) with
  `TM_ACTIVE_LOCALE` and the spec's format; value-axis ticks use `Intl.NumberFormat(locale,
  { notation: 'compact' })` ("100K", "١٠٠ ألف"), so `ar-SA` shows Arabic-Indic digits throughout.
- **Labels** drawn on the canvas are wrapped in U+2068 … U+2069 (first-strong isolates).
- **Theme bridge:** on init and on every theme, direction or locale change the facade reads the
  `--chart-*` tokens (§7.7), `--text-body`, `--text-secondary`, `--divider` and `--font-ui` with
  `getComputedStyle`. No colour is written in code.

#### §7.5 Tooltip, legend, Trusted Types

- **Tooltip:** an Angular top-layer element with text bindings only, the page's `dir`, 12 px on
  `--surface-inverse`. Item types show the hovered item; axis types (`column`, `bar`, `line`,
  `area`) show every series at the hovered category, found by `pointAt` on zrender's `mousemove`.
- **Legend:** an Angular list (swatch, decal sample, label) on the logical side `legend` names;
  `auto` = bottom when there are two or more series, none for one (the title names it). Static in v1.
- **Trusted Types:** with no HTML component and the canvas renderer, ECharts assigns no `innerHTML`
  (its HTML tooltip's `setContent` is the sink); ECharts' `aria.label` is off (§7.8 describes the
  chart). The e2e runs under the production CSP and fails on any `securitypolicyviolation`, which
  settles A§12 #24.

#### §7.6 RTL

- **The plot does not mirror** (decision 13): value axis at the physical left, categories left to
  right (`bar`: top to bottom), pies clockwise; the plot container is `dir="ltr"`, as designed.
- **Text follows the page:** legend order and placement, tooltip, table, title, toolbar. Arrow keys
  on the plot are physical, matching what is drawn.

#### §7.7 Palette and tokens

One component token group, `chart`, joins the default preset (0023's rule for new entry points); a
distribution re-brands it in `@layer tm.theme`.

| Token | Light | Dark |
|---|---|---|
| `series1`–`series8` (fixed order) | `#118AA6` teal, `#EB6834` orange, `#6250D6` violet, `#C98500` amber, `#D55181` magenta, `#008300` green, `#2A78D6` blue, `#E34948` red | `#2AA5C2`, `#D95926`, `#9085E9`, `#C98500`, `#D55181`, `#008300`, `#3987E5`, `#E66767` |

  ΔE ≥ 8, normal-vision ΔE ≥ 15, ≥ 3:1; section 13); a token unit test recomputes it for any preset.
- **Assignment:** series take slots in member order (colour follows the member, never its rank);

#### §7.8 Accessibility

- **Structure:** a `figure` named "{title}, {type} chart"; the plot is one tab stop (`role="img"`)
  named by a summary ("12 points, from 120,000 to 365,000") and described by its keys ("Use the arrow
  keys to move between points. Press Enter to see the records.").
- **Keyboard:** Left/Right along categories (`bar`: Up/Down), Up/Down across series, Home/End, Enter
  or Space `pointActivate`, Escape clears; pie, doughnut and treemap in data order; heatmap in 2D. The
  point highlights, the tooltip shows at `pixelOf`, a polite region says "Oct 2026, Corporate:
  298,000".
- **Hidden table** (caption = title) up to 500 points; beyond, the description says "Use Show as
  table to read all 3,200 points."
- **Table view:** `asTable` swaps the plot for a readonly `tm-grid` (d0, d1, measure) in the same box.
- Marks meet 3:1 (WCAG 1.4.11); text uses text tokens, never series colours.

#### §7.9 The Chart renderer

- `type` and `options` from `result.chart` (R1(a)); dimensions from the dimension columns, members in
  first-appearance order, labels by `tmReportFormat`; rows from the table's ordinals.
- `pointActivate` drills (§8.1); a `card` or `gauge` drills with no condition.

### §8 Drill-through

A summary row, a pivot cell or a chart point opens the drill-through list of its rows; a list row
opens its record (§5.2). The host builds the URL from the result alone.

#### §8.1 From coordinate to filter

1. **Coordinate.** A summary row: every key column. A pivot cell: its row and column members with
   their ancestors, the deepest member of each dimension. A chart point: each dimension's member.
   Totals add nothing; the measure is ignored (0033 §9.4).
2. **One condition per member** as 0033 §9.4's table gives it, built with `tmQx` and `tmQx.literal`
   (`tmQx.raw(drill.terms[i])` for an expression member), never by concatenation.
3. **Filter** = `tmQxPrint(tmQx.and(tmQx.raw(drill.filter), …conditions))` (no raw node when
   `drill.filter` is null).
4. **URL** `/{t}/list/{drill.segment}?filter=…&cols={drill.columns}&from={id | key}` (no `from` for a
   draft). A result without `drill` has no drill affordance.

**Example —** 0033 §3.5's pivot, cell Riyadh × Q3, `Year` defaulted to 2026: filter `(year(Invoice.
PostingDate) = 2026) and descendantOf(Center.Id, 11) and (quarter(Invoice.PostingDate)) = 3`; chips
"Center: Riyadh · Quarter: 3 · Year: 2026".

#### §8.2 The drill event

```ts
interface TmReportDrillEvent {                                // @tellma/core/reports
  readonly url: string; readonly segment: string; readonly filter: string | null; readonly columns: readonly string[];
  readonly chips: readonly { readonly label: string; readonly value: string }[]; // members, then arguments, as displayed
  readonly newTab: boolean; preventDefault(): void; readonly defaultPrevented: boolean;
}
```

- **Default:** `router.navigateByUrl(url, { state: { tmDrill: { fromTitle, chips } } })` (kept in
  `history.state` across reloads), or `window.open(url, '_blank', 'noopener')` for `newTab`. Assistant
  mode only emits.
- **Long URLs.** Past 8,000 characters a cold reload would exceed Kestrel's 8 KB request line, so the
  host navigates to `?drill=state` with the filter in `history.state` only; that page offers no copy
  link or new tab (review flag 9).

#### §8.3 The drill-through list page

`TmDrillListPage` is the core page `/{t}/list/{segment}` (0024 §9.2).

| Part | Content |
|---|---|
| route | `TmEntities.bySegment`, child segments included (0029 §2.2); unknown → tenant not-found |
| parameters | `filter`, `cols`, `order`, `page` (0024's codec), `from`; others ignored |
| row 1 | crumb: the source report's title when `from` is readable (`reports/get-by-ids` or the coded registry); `h1`: the entity's plural label |
| row 2 | chips (§8.4; read-only `tm-chip`, "+n" overflow) · "Open in {plural}" (top-level roots with a search page), Export (§9.2), Refresh, `tm-pager` |
| body | `tm-grid` over `tmSelectPlan(descriptor, cols)`, sortable headers (BE C.3) writing `order` (`replaceUrl`); paging pushes; 50 per page |
| request | `{segment}/query { select, filters: [filter], orderBy, skip, take: 50, includeCount: true }`; `select` adds `Id` and a child's `{owner.parentKey}` |
| rows | open the record: a top-level root's details; a child's owner with `?child={collection}:{id}` (0031); a grandchild's top-level owner with the intermediate child |

- **Back:** `history.back()` when the previous entry is that report (`canGoBack` and
  `history.state.tmDrill`), restoring its arguments and page state; else a link to the report.
- **States** as 0030 §5.3; `400 query-invalid` reads "This link's filter is not valid", with no edit.
  Dropped columns are silent (0029 §6.4, `source: 'url'`). Not pinnable, not a recent (0027, 0025).
- **"Open in {plural}"** → `TmUrls.search(entity, { filter, cols })`, where the search toolbar edits
  the filter (A§12 #19's alternative, kept as a choice).

#### §8.4 Chips without URL text

- **From a report** (`history.state.tmDrill`): the event's chips and crumb title.
- **From a bare link:** one `queryex/discover` call (root = entity, `filters: [filter]`); each
  distinct path becomes a chip with its descriptor slash label ("Customer", "Invoice / Posting date")
  after "Filtered by"; values are not shown.
- The filter text and every other URL text are never rendered (A§8): a crafted link chooses rows,
  never words.

### §9 Export to Excel

`report.export` asks the server for 0033 §12's workbook: list and summary flat, pivot fully
expanded, chart as its data.

1. `TmApi.download('reports/export', { id | code | draft | route, arguments, dashboardId },
   { signal, long: true, onProgress })` with the shown result's arguments.
2. A sticky toast "Exporting…" with progress and Cancel (0028; leaving aborts too); the file saves
   through an object URL and `<a download>` with the server's file name.
3. `413 Excel.Export.RowLimitExceeded` → one retry as `export/start` → toast "Export started. You'll
   get a notification when it's ready." with Track (0028's Jobs page).
4. `413 Report.ExportTooWide` → error toast "This pivot is too wide for Excel. Collapse it with fewer
   column members."; others → `TmErrorPresenter` (`kind: 'read'`).

- **Where:** every mode but `widget` (0035 calls `export()`); a coded report only with `route`; the
  studio exports its draft.
- **The drill list** exports through the entity's `export` when `allows(entity, 'export')` (a
  top-level stack): 0030 §13.2's `ExportColumn` model, `filters: [filter]`, `orderBy`, 0030's sync or
  background rule. A child root has no export in v1 (0033 flag 10); the button is absent.

### §12 The report studio

#### §12.1 Routes, loading, drafts

- **Create and clone** are the details host's create mode, rendered by the declaration's

#### §12.4 Parameters: live inference

- **The list follows the draft:** `draft.parameters()` (0029 §10.1) names every `@Key` from the lexer
  on each keystroke, one card per name in order of appearance; types, conflicts and the compared
  entity merge in when the check returns.
- **A card:** `@Key` (mono 600), the type tag (a `tm-select` of compatible types, warning tone, when
  inference is unconstrained or conflicting), Required (`tm-switch`), Label per slot, Default

- **Confirmed types** feed `injectTmQueryexDraft({ parameters })`. A name that disappears keeps its

#### §12.5 Drops and "Add to…"

| Target | Takes | Becomes |
|---|---|---|
| List or Summary columns, Rows, Columns, Dimensions | `received` at the drop index | `{ path: node.key }` (a navigation shows its display name) |
| Measures, the chart's Measure, Summary's "Drop to add its sum" end zone | `received` | numeric `{ expr: 'sum(<path>)' }`, else `{ expr: 'count(<fk path>)' }` (0029's rule) |

- **Hints:** every accepting target shows "Drop to add" when a drag starts (`TmDragDrop.current`);

#### §12.6 Kind switching

- Each kind's block is kept; switching back restores it. Filter, parameters, drill-through columns
  and General are shared. Save writes the active block only (0033 rule 2).
- **The first visit seeds** the new kind: List → Summary: columns as keys, no measure. Summary →
  Pivot: rows = first key, columns = second key, the measures. Pivot → Summary: rows ∪ columns as
  keys, then the measures. Summary or Pivot → Chart: the first one or two keys, the first measure,
  type `column`. Aggregate → List: the key paths. Chart → Summary or Pivot: dimensions and measure.

#### §12.7 Validation feedback

1. **Per keystroke:** the lexer (0029 §8.1) and the structural rules mirrored from 0033 §3.4 (rule 3's
   counts, 7 attributes, 8 tree, 9 ranges, 10 chart dimensions) and §4.5 (keys, 20 parameters).
2. **250 ms:** one `TmQueryexDraft` over filter (`filters[0]`), having, order expressions and every
   expression term as a term list (R4(a)); path terms resolve locally and skip discover.
3. **600 ms:** with no problem left and Auto-preview on, the preview runs `reports/run { draft }`,
   which validates the whole document (0033 §8.3). A `422` maps by `pointer`: `/pivot/rows/0` → that
   item, `/filter` with `start`/`length` → the span, `/parameters/1/default` → that card, an unknown
   pointer → General.

- **Summary:** "2 problems" (`tm-badge`, error) in the panel header opens a list that focuses each
  item; sections show counts; F8 cycles within an editor. Save with known problems opens that list
  ("Fix 2 problems before saving") instead of sending.

#### §12.8 The preview

- **Query changes** (terms, filter, having, order, top, kind, totals, tree, levels, attributes,
  parameter types) re-run after 600 ms, aborting the previous run.
- **Presentation changes** (labels, display, format, expand, a chart type with the same dimension
  count, chart options) re-render the held result at once through `overlay`
  (`TmReportOverlay` = per-term presentation and the chart block, matched by document order). No
  request.
- Auto-preview off: only Refresh runs; "Preview is out of date" shows above the output.

#### §12.9 Save, Discard, Share

- **Save** posts `reports/save` with `[{ id?, modifiedAt?, code, title…, description…, root, kind,
  definitionJson: JSON.stringify(document), basedOnId? }]` and `returnEntities`. Success clears the
  draft, adopts the row and `ModifiedAt`, toasts "Report saved." and, when new, replaces the URL with
  `/{t}/reports/{id}/studio`.
- **Errors:** `422` on `[0].DefinitionJson` by `pointer` (§12.7), on other columns to General; `409`
  → 0031's concurrency dialog (R8(a)); others → `TmErrorPresenter` (`kind: 'save'`). A save is never
  aborted; the panel is inert while Save shows its pending state.
- **Discard** confirms "Discard your changes?" and restores the saved definition. **Share** opens
  §10.4 for a saved definition; unsaved, its tooltip says "Save the report to share it." Every studio
  control invokes a page action (§13.2).

## 12. Challenges to the architecture

1. **A§3.4's `tmCodedReport` example** (`run` closure, `default: 'today()'`): the closure hides the
   route, so the platform cannot export (0033 challenge 5), and no client evaluator exists for
   `today()` (0029 decision 8). Followed in name; `route` is the common case, `run` the hatch,
   defaults in C# (§2.2).
2. **A§8's `?tab=mine|shared|all`:** the search host canonicalizes its URL through the codec and reads
   `{segment}/query`, which cannot express the tabs. Followed as `x.tab` with 0030's read hatch (R3).
3. **A§8's "the filter shows as read-only chips; no free text from the URL is rendered"** cannot be
   met from the URL without a client parser. Followed with state-carried chips and, for bare links,
   discover's path labels (§8.4).
4. **A§5.13's `spinner | silent`** lacks the brief's force refresh that clears at once. Followed with
   `run({ clear: true })` (§3.4).
5. **A§2.3 and A§6.6 treat `core-ui/chart` as the ECharts boundary.** Refined: the entry point is small
   (card and table need no engine) and the engine is its dynamic chunk, alone in `on-demand`.
6. **A§8's whole drill filter in the URL** meets Kestrel's 8 KB request line on a cold reload.
   Followed with the state fallback (§8.2).
7. **A§12 #24 (Trusted Types with ECharts)** is settled by design (§7.5); no report-only mode.
