# Resolution of `arch-critique.md`

One line per finding: number, verdict (applied / adjusted / rejected), and what changed in
`design/00-architecture.md` or why not.

1. **Adjusted.** One `shell` prefetch group now holds every chunk except the `on-demand` ones (`core-ui/chart`, `/report-studio`, `/support`), and `tellma-client build` assigns chunks from the build metafile (§6.6). Calendar entry points are in that group, and the build fails on a calendar with no entry point. The real entry-point names are `calendar-umalqura` and `calendar-ethiopic`, not `calendar-uq` (§5.2). "Warm" is defined by what the cache holds, not by an "activated version": Angular's `driver.ts` shows that a first install caches its prefetch groups at idle after activation, and only updates wait for `initializeFully` (§7.2, Verified facts). `warmUp()` waits until CacheStorage holds every `shell` URL, and the test now covers every route family. Added a 1.5 MB `shell` budget (§11), decision 4's wording and risk 29.
2. **Applied.** Added a device channel `tm:<slug>` for `session.*` messages, plus a new `session.changed` message (§5.6). `TmApi` checks the user before sending and on each response; `TmHub` does the same before every negotiate (§5.3). Drafts are now keyed `tm.draft:<sub>:…` and cleared in every tab on sign-out or when the user changes (§5.8, §7.6). `TmClientStore.put` refuses a partition whose `sub` is not the cookie's (§5.5). §7.7 step 4 is now the "changed-user path", and a Playwright case covers it (§11).
3. **Applied.** `TmBanners` moved to the primary entry point and 0028 still owns it (§2.2, §4.1, §5.14). New import rule: the primary imports no other entry point, `/attention` imports only the primary, `/shell` imports the primary and `/attention`, and the package build fails on a cycle. Toast-policy consumers are corrected so the primary never uses it.
4. **Adjusted.** On expiry, all of the user's stored data is swept, not just the content documents (§5.5, §7.2, §7.7). A partial sweep would leave `me` (name, email, access summary, preferences) on disk, and the warm relaunch it saves comes after a full sign-in anyway. Drafts are exempt and stay in their tab, keyed by `sub`. Fix (a)+(b) would have deleted them on every 401, contradicting "your work is kept". `tm-boot.js` deletes the data before redirecting. Partition keys now begin with `sub`, so the delete is one key range. Documents older than 7 days are ignored, the "page data" wording is fixed, and risk 26 records the trade-off.
5. **Adjusted.** I removed the `reportMenu` and `home` launch documents and the `reports` tag entirely, instead of adding `reports/menu`, `dashboards/home` and a composite tag. The brief's launcher has one Reports item. Stored definitions are reached through the reports page and pins, coded reports come from the client registry, and home is one default plus the distribution's `home` hatch (finding 17). So nothing needs revalidating and report saves notify no other user (§5.7, §6.1, §6.2, §6.3, §4.2, §7.2). Fix (c) is applied: `/{t}/reports` is a `search` hatch body (§8). Risk 28.
6. **Applied.** Rewrote decision 8. Other tabs clear their drafts on `session.signed-out` (§7.6), and `tm-boot.js` exempts `/signed-out` (§7.1, §8).
7. **Adjusted.** I dropped heartbeats entirely, rather than deriving them from hub traffic. `@microsoft/signalr` has no public hook for received pings, so "post on every hub message" cannot be built cleanly. Instead a follower posts `leader.probe` when it starts and whenever it becomes visible, and the leader answers with `hub.status` (its event handlers run while hidden). A visible follower steals only when a probe goes unanswered for 5 s, or the leader has not been connected for 30 s, after 0–2 s of jitter. Kept: the 150 s timeout and the release on `freeze`/`pagehide`. Updated the §7.8 flowchart, decision 6, risk 5, the alternatives and Verified facts (Chromium flag comment).
8. **Applied, with a simplification.** While the page is alive, flushes go through `TmApi.write`, and the returned bag and tag are stored in the shared `me`, so no tab syncs for its own write. `send` is used only on `pagehide`, and a 16 KB cap applies (§5.7, §7.3). I removed the `…:prefs` lock instead of skipping it on `pagehide`: each tab flushes only its own keys and the server sets keys one by one (f03). The "ignore equal-or-older tags" fix is not applied: tags are opaque, and the stored tag already turns an equal header into a no-op.
9. **Applied.** 0030 owns the import dialog, built on the existing `tm-dropzone` (`@tellma/core-ui/files`), so 0023 adds nothing. A background import continues as a job (0028). Import is a dialog, not a route (§1, §4.1, §4.3, §8, §13).
10. **Applied.** Added a `TmSearchQuery` sketch and `TmUrls.parseSearch` (§5.13). 0024 owns the grammar and the codec; 0030 owns precedence and history (§1, §4.1, §8, §13).
11. **Adjusted.** The client `columns` is the one display default for every grid-like surface. A declaration without `columns` defaults to the display-name columns, the other natural keys and `IsActive`. It does not default to `DefaultSelect`, which carries `Id` and four audit columns. The SPA always sends an explicit select; `DefaultSelect` serves API and MCP callers only (§3.3, Visibility Q3).
12. **Applied.** Added `TmClientStore.boot { read, patch }` and its writer list (§5.5). Part B now states that `TmTheme` never persists and that `@tellma/core` seeds it and stores changes (§6.4).
13. **Applied.** Part E: multi-select is decided. Part D: added the 600 px → `sm` row, and §9 cites it. Part F: the new member is `QueryCompilationOptions.OmittedParameters`, because 0008's parameters live there, not on `QuerySpec`.
14. **Adjusted.** The design's push-down row stays. A banner enters or leaves only after 2 s without key, pointer or wheel input; the user's own dismiss is the exception (§9, `TmBanners`). An overlay is rejected because it would cover the page's title and toolbar. A permanent row is rejected because it costs 32 px on every page for a rare state. Risk 27.
15. **Applied.** The "Connection lost" banner follows the new `TmApi.online`. Hub loss shows only "Live updates paused" in the bell. Polling also starts when the hub has been down for over 60 s (§5.3, §7.8).
16. **Applied.** Added a `TmErrorRecord` sketch and the error-envelope rule (§5.9).
17. **Applied.** Added `home` to `TmFeatureDefinition` and `tile.component` to `tmEntity`, with rows in §3.6. The §1 and §13 deferral text is updated.
18. **Applied.** `?from={reportId|key}` replaces `?title=`. The heading is the entity's plural label, the subtitle is the source report's title, and the filter shows as read-only chips (§8, Visibility Q2).
19. **Applied, naming the exact hook.** In the 0011 cookie row, a background request renews neither cookie: `OnCheckSlidingExpiration` sets `ShouldRenew = false` (verified; listed in Verified facts).
20. **Applied.** Corrected the `Clear-Site-Data` row; the 0011 logout row now says "belt and braces". Reworded the §2.2 sentence on entry points and chunks so `@defer` stays valid and the budgets verify the initial bundle.
