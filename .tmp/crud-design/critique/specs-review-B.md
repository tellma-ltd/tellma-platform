# Cross-spec review B — specs 0015, 0016, 0017, 0018, 0019, 0020

Reviewed 2026-09-04 against `ledger.md`, `seams.md` (§0, §23, §24 and the owned seams 8, 10, 12, 13, 15, 19, 20, 21), `spec-style.md`, `notation.md`, `docs/AGENTS.md` and `crud-stack-specs.md`. Every spec in the group has the verbatim header, the 4 September 2026 date, and all mandatory sections (Context, Goals / Non-goals, Testing, Definition of done, Decisions record, Review flags); none contains XML doc comments, an `ARCHITECTURE.md` section pointer, a sibling-spec `§` reference, or a C# block longer than five lines. Every ledger §5 flag assigned to each spec is present with its alternative. Every "Owns:" item of the breakdown is specified (0017's settings edit API and 0018's natural-key metadata are correctly ceded to 0012/0011 and named as non-goals). Findings below are what departs from that baseline.

Severity: **blocking** (implementation cannot proceed as written) / **major** (two specs or a spec and seams.md disagree on a name, shape, number or rule) / **minor** (doubt, wording, a seams.md delta to absorb).

## Spec 0015 — `docs/specs/0015-crud-web-api.md`

1. **minor — §3.3 `IdsRequest` gains `Arguments: JSON?` not in seams.md §13.1.** seams.md's `IdsRequest` has `Ids`, `ReturnEntities`, `Select`, `Include`; the spec adds `Arguments` for `[EntityAction]` typed arguments (and §4.2 binds it). Owner extension, but every consumer restates seams.md. Fix: add the member to seams.md §13.1 (and to 0014 §… where `IdsRequest` is the action body), or route typed arguments through a separate body type.
2. **minor — §1.2 vs §11.1: which feature `AddMcp` requires.** §1.2 says the MCP feature "declares `Requires` on the stack feature of spec 0014"; §11.1 says `McpFeature … [Requires<CoreFeature>]`. 0014 defines no separate stack feature (the stack contributor lives in `CoreFeature`, seams.md §0.2). Fix: say `[Requires<CoreFeature>]` in §1.2.
3. **minor — §2.4 route list omits `notification-preferences/get`.** 0020 §4.3/§8 ship `NotificationPreferencesService.Get` (`[ApiAction("get", MemberOnly = true, Idempotent = true)]`; 0020 flag 10). Fix: add it to §2.4's Core route list (it is also absent from seams.md §13.1's route line).
4. **minor — §10.1/§10.2 "the round-trip ledger of spec 0014", "p95 above the ledger".** The word collides with design-process vocabulary the reader never sees; 0014 itself says "round-trip budget" in its test section. Fix: "round-trip budget" in both places.
5. **minor — §2.3 `all` row: body "`GetRequest` without `Id`".** `GetRequest(Id: long, …)` has a required `Id`; a body "without" it has no record. Fix: make `GetRequest.Id` optional (`long?`, required by `get`) or define `AllRequest(Select, Include)`.

## Spec 0016 — `docs/specs/0016-blob-storage.md`

1. **blocking — §4.4 relies on `ISaveEffect<T>` running on delete and action persists, which 0014 does not state.** §4.4: "The pipeline runs save effects for every persist batch that writes the owner table — save, delete by ids, delete by query, delete with descendants, and actions … on a delete persist `PersistContext.Entities` is empty". 0014's persist assembly (§1.6 step 2 "Capability statements … `BlobReferenceEffect<T>` — an `ISaveEffect<T>` like any other") and its `ISaveEffect`/`ContributeAsync` text cover the save path only; no delete or action path in 0014 invokes `ISaveEffect.ContributeAsync` (a search of 0014 for effects on delete finds nothing). Without it, deleting a user or an `Exports` row never releases the blob the emitter's capture recorded, and `core.file-retention` (0018 §12.1, 0019 §14.4) leaks every export file. Fix: 0014 must state that every `ISaveEffect<T>.ContributeAsync` runs for every persist batch on the stack's table (delete by ids / by query / with descendants, `activate`/`deactivate`, `Update` actions) with `PersistContext.Entities` empty on deletes — or 0016 must contribute a delete-time component through a contract 0014 defines. 0016 flag 20 should name the 0014 obligation.
2. **minor — §6.3 container name `{ContainerPrefix}t{tenantId}` (`tellma-t42`) vs seams.md §12.3 `tellma-<tenantId>`.** §9's DNS-label check (`ContainerPrefix` plus `t2147483647`) follows the spec's form. Fix: correct seams.md §12.3 to `tellma-t{tenantId}` (the spec's form is the better one: a plain number after the prefix is ambiguous once a slug-shaped prefix is configured).
3. **minor — seams.md §12.1/§12.3 deltas the owner introduced.** `BlobOptions` drops `SweepInterval` (the cadence moved to the built-in schedule; decision 21, flag 21); `BlobDownload` gains `State: BlobState` (flag 22); `IBlobStore` gains `EnsureTenantAsync(tenantId)` (needed by step `core.blob-container`, §6.4); the sweep claim's `OUTPUT` adds `deleted.[State]` (feeds `tellma.blobs.sweep.deleted{state}`); `BlobOptions.StagingTtl` stays. All are flagged or motivated; fix: absorb them into seams.md so 0018/0019 restate the right shapes.
4. **minor — §4.4 "the capability step of spec 0011's persist assembly".** The persist assembly is 0014's (0014 §1.6 and §13; seams.md §23 lists it under 0014). Fix: "spec 0014's persist assembly".
5. **minor — style: review flags 3, 15, 18 cite ledger ids `S16`, `S25`, `S36`.** The ledger does not exist to the spec's reader. Fix: delete the ids (the § pointers suffice).
6. **minor — style: flag 2 "Ahmad confirms the reading or buys the Boutique licence".** Names the author in the third person and states a to-do. Fix: "The licence reading must be confirmed, or the Boutique licence bought, before the first release; either way the swap is a package swap in the distribution."

## Spec 0017 — `docs/specs/0017-core-and-gl-reference-stacks.md`

1. **major — §3.3 `PartialFailureException(Results, RemainingIds, Cause)` and a 502 body carrying `remainingIds` depart from seams.md §10 and 0015 §7.1.** The closed set defines `PartialFailureException(Code: string, Results: object, Failed: list<string>)` and 0015 renders `errorDetails.results` and `errorDetails.failed[]`. 0014 §… restates the same shape. Fix: throw `PartialFailureException(Code = "identity-unavailable", Results = the prefix's InviteResults, Failed = the not-attempted ids as strings)`; drop `RemainingIds`/`Cause`; say the SPA reads `errorDetails.failed`.
2. **major — §3.3 cites "spec 0014's `ExecuteActionAsync` contract for `PartialFailureException`" (the pipeline executes the composed persist batch before the exception surfaces); 0014 states no such rule.** 0014's only mention of `PartialFailureException` is the exception list. Flag 2 admits the dependency. Fix: either 0014 §11 adds the rule (an action that throws `PartialFailureException` after appending to `context.Batch` has the batch executed, then the exception rethrown with the batch's outcome) or 0017 performs the prefix write-back through a second `IGuardedBatchRunner.Run(Persist, …)` and then throws. Until one is chosen the subjects created on the identity server are lost on a partial failure.
3. **major — §7 the initial *tenant* migration lists `TenantMembershipList` among the standalone types.** 0010 defines `TenantMembershipRecord` as `[TableType]` → `[catalog].[TenantMembershipList]`, a catalog-database type reconciled by the migrator. Fix: remove it from the tenant migration's list.
4. **minor — §5.5 `GlFeature.Contribute` = `Entity`, `ProvisioningStep`, `Model` ("exactly three items"; "the module registers none [securables] by hand") vs seams.md §21 listing `Securables` among its contributions.** The spec follows seam 3 (entity securables need no hand registration). Fix: correct seams.md §21.
5. **minor — §3.5 `SaveOptions(… Details = request.Details …)`.** `SaveRequest<T>` (0015 §3.3, seams.md §13.1) has no `Details` member; it has `Select` and `Include`. Fix: `Details = DetailsRequest(Select = request.Select, Include = request.Include)`.
6. **minor — §6.1 `TenantBootstrapRequest(AdminEmail, …)`.** 0013 defines `TenantBootstrapRequest(Email, Name, PreferredLanguage, Subject)`. Fix: `Email = context.AdminEmail`.
7. **minor — §4 the `members` extra is "restricted to `@tb{b}_main`".** No such reserved name exists in 0011 (seams.md §0.3) or 0014. Fix: name the identifier 0014's details plan exposes for the main ids, or bind an `IdList` TVP through `Loader.Rows`/`Tvp`.
8. **minor — §5.2 "`Center` is stored as spec 0011's enum-as-string convention: `varchar(12)`".** The column is `CenterType`. Wording fix.
9. **minor — §8.2 `tellma.data.tree.recomputes` "(tag `table = gl.Centers`)".** 0011 declares the tag `entity` on `tellma.data.tree.recomputes` and `tellma.data.tree.repairs`. Fix the tag name (and §5.3's mention of `tellma.data.tree.repairs` is correct).
10. **minor — §3.3 / §1.2 `core.user.added`: arguments and registration.** The request passes `{ tenantName }`; 0020 §2.3's catalogue (owner of the Core types) declares `{ tenantName, actorName }`. §1.2 also says `CoreFeature` "registers the notification type `core.user.added`" here, while 0020 §2.3/§11 declares it as 0020's own `CoreFeature` contribution and its registry rejects a duplicate key. Fix: pass `actorName`; cite the descriptor as 0020's and drop the registration line.
11. **minor — style: review flags 5, 6, 8, 9, 10 cite ledger ids `S22`, `S23`, `S14`, `S31`, `S7`.** Delete the ids.
12. **minor — §7 model-parity test project `Tellma.Distro.Acme.Web.Tests`.** Neither §1.1 nor §9 lists it (they name `distributions/acme/test/Tellma.Distro.Acme.IntegrationTests`). Fix: pick one project name.

## Spec 0018 — `docs/specs/0018-excel-codec.md`

1. **major — §1.3/§5.1 the `Stamp` column is "`ModifiedAt`'s wire string … `yyyy-MM-ddTHH:mm:ss.fffffffZ`".** 0015 §3.2 (seam 13 owner) defines the `DateTime` wire encoding as `yyyy-MM-ddTHH:mm:ss.fffffff` — seven fractional digits, no offset, no `Z` — and seams.md §19 says `Stamp` = `ModifiedAt`'s wire string. A trailing `Z` is not the wire string, so a same-source stamp parsed from the sheet and the `modifiedAt` a client echoes differ textually. Fix: drop the `Z` (state "UTC by convention, no designator").
2. **major — §1.4 `inspect-import` costs "0" round trips.** §7.1 resolves the staged file through `IBlobService.ResolveAsync`, which 0016 §3.1/§5.1 defines as one `Read` batch through `IGuardedBatchRunner` (two statements); §15 asserts the §1.4 table through `DataAccessScope`, so the test as written fails. Fix: the row is 1 (the prologue rides that round trip); delete the "prologue rides the file-open check only when cold" clause.
3. **minor — §12.1 retention "deletes rows … through `DeleteByQueryAsync` on both stacks" vs 0019 §14.4 (owner of `core.file-retention`): "selects expired `Export` and `Import` ids in pages of 500 and deletes them through `DeleteByIdsAsync`".** Fix: align to 0019's paged `DeleteByIdsAsync`.
4. **minor — §12.3/§12.6 notification arguments vs 0020 §2.3's catalogue.** `core.export.ready` passes `{ fileName, rows }` (catalogue: `{ fileName, rowCount }`); `core.import.completed` passes `{ inserted, updated }` (catalogue: `{ fileName, rowCount, errorCount }`); `core.import.failed` passes `…` (catalogue: `{ fileName, errorCode }`). The names are the ICU template arguments 0020 renders. Fix: pass exactly the catalogue's names (0020 owns the catalogue) or correct the catalogue.
5. **minor — §2.1 `service ExcelOperations<TEntity> where TEntity: Entity<TKey>`.** `TKey` is undeclared. Fix: `ExcelOperations<TEntity, TKey>` (matching `EntityService<TEntity, TKey>`) or `where TEntity: Entity`.
6. **minor — §12.5 "`ContributeAsync(context)` calls `context.Progress.Append(context.Batch, …)`".** `PersistContext` (0014 §13.1) has no `Progress` member; the holder does. Fix: `ImportCheckpoint.Progress.Append(context.Batch, …)`.
7. **minor — §3.3 plural sheet names through a `<Entity>_Plural` resource key.** 0012's resource conventions (seams.md §22: `<Entity>`, `<Entity>_<Property>`, `Setting_<key>`) define no `_Plural` key and `ILabelProvider.EntityLabel` has no plural form. Fix: 0012 adds the convention (and a `plural` argument on `EntityLabel`) or 0018 names sheets from `EntityLabel` alone.
8. **minor — §1.2 `ExcelOperations<TEntity>` "registered as an `[ApiRoute]`-less entity-service companion" hosting the four `[ApiAction]`s.** seams.md §19 and 0014 contribute the four operations "as `[ApiAction]`s on every stack", but 0015 §4.4's rule is "the method is public and instance on the service", and 0014 defines no mechanism for a companion type's methods to project under a stack's segment. Fix: 0014 (with 0015) must name the mechanism — e.g. an `ExcelOperationsContributionItem` the stack realizer projects, or the four methods on `EntityService` delegating to `ExcelOperations<T>`.
