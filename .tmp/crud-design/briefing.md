## 2. Fixed facts — do not re-decide these

- **Stack.** .NET 10 (`global.json` 10.0.300), EF Core 10.0.9, `Microsoft.Data.SqlClient` 6.1.1, SQL Server only (Azure SQL elastic pools in SaaS, full SQL Server on-prem, LocalDB/Testcontainers in tests), xUnit v3, central package management, warnings-as-errors with `EnforceCodeStyleInBuild` (block-bodied members, primary constructors, XML docs on every member, Apache-2.0 header). The `MessageFormat` 8.0.0 package (ICU MessageFormat) is already pinned. `Azure.Identity`, `Azure.Security.KeyVault.*`, `OpenTelemetry.*` 1.16, `Serilog.AspNetCore`, `Quartz.Extensions.Hosting` are pinned (Quartz is used by the identity server only).
- **Repo conventions.** `src/core/` for the Core family, `src/module/<m>/Tellma.Module.<M>[.Abstractions]/` for modules, `test/` mirrors `src/`, `*.IntegrationTests` only for suites that need external resources, two xUnit traits (`Category=Integration`, `Live=true`) select CI tiers. `Tellma.Module.<m>` never references `Tellma.Core`; cross-cutting Core services are reachable only through `Tellma.Core.Abstractions` interfaces. `Tellma.Core.Abstractions` stays EF-free and framework-free (BCL DataAnnotations only). Telemetry: `IMeterFactory` meters named after the package, instruments `tellma.<area>.<name>`, names as `const`s in the package's `.Abstractions`, no per-tenant tags on instruments.
- **Table types (spec 0001, implemented).** A table opts in with `[TableType]`; its UDTT is a row image (insertable/updatable columns minus exclusions, PK mirrored, rowversion as nullable binary(8), json as (n)varchar(max)); physical name `<Logical>_<hash8>`, addressed only through `model.GetTableTypes()`; no IDENTITY anywhere; per-table sequences `sq_<TableName>`; standalone shapes are plain `[TableType]` classes (the four bulk lists exist); seeds via `HasData` only in a reserved id band; runtime TVP binding must be metadata-driven (a Roslyn analyzer for hard-coded ordinals was deferred to the save-pipeline spec — i.e., to this exercise).
- **Queryex (spec 0008, implemented).** `QueryexEngine.CompileQuery(QuerySpec{Root, Select, Aggregate, Filter: FilterTree?, Having, OrderBy, Skip, Take}, QueryCompilationOptions{Schema, LanguageVersion (required), Parameters, HasUser, BatchOrdinal, Limits})` → `CompiledQuery{Sql, Parameters: QueryexParameterSlot[] (Origin ∈ Literal|Today|Now|UserId|TimeZone|Declared), Columns: QueryexColumn[] (Ordinal, Text, Type, Nullity, Path, IsGroupingKey)}`. `Validate` returns typed items without SQL; `Discover`/`DiscoverQuery` infer parameter types for authoring. `FilterTree.And/Or/Not/Leaf` (empty `Or` is false). `QueryexSchema` is built by `QueryexSchemaBuilder`: entities (logical `Name`, physical `Source` like `[gl].[Invoices]`, `Key`, scalar properties with `Column`, `QueryexType`, `IsNotNull`, `IsUnique`, structured `StoreType`, many-to-one navigations by FK, optional `TreeNode`). No collections, no `*` expansion, no computed properties; enum properties are declared by store type. `me()`/`today()`/`now()` are parameter slots the host binds (`today()` is documented as "the current date in the tenant's zone"). `descendantOf(key, k1..kn)`/`ancestorOf(...)` exist; `level()` does **not**; multi-valued parameters (`x in (@ids)`) and a TVP-backed list restriction do **not** exist. Engine names live in `@qx{b}_p{n}`/`@qx{b}_v{n}` so several compiled queries and raw SQL concatenate into one command walked with `NextResult()`. Every diagnostic is a code + arguments; the host localizes. Caches are keyed on schema **identity**; a host that changes its model builds a new schema. Amendments to the engine are in scope for this exercise (they are documented by spec 0011, since 0008 is frozen).
- **Identity (spec 0003, implemented).** Distributions are OIDC relying parties using the BFF pattern with an encrypted `HttpOnly` session cookie; the SPA holds no tokens; `sub` is the stable user id. The server exposes a **bulk invite** API (creates-or-gets by email, returns each `sub` with status `Invited|Reinvited|Active` or a per-user error; never the link) and a **bulk delivery-status** API scoped to the invitations that client raised; service accounts are created through the server; step-up is a `401 insufficient_user_authentication` challenge from the distribution; SignalR: cookie-authenticated at connect, thin events only, connections closed on session end, Azure SignalR Service in SaaS with a hub-only token; in-proc mode seeds `admin@localhost` and the distribution must seed a matching tenant admin on the same `sub`.
- **Email (spec 0007, implemented).** `IEmailSender.SendAsync(batch)`; `EmailAudience` required; `ISandboxContext` must be registered explicitly by every host (no default); `DeploymentIdentity(Application, EnvironmentName)` singleton; `IEmailOutbox`/`EmailEnqueueRequest` are a *reserved shape* to be shipped by the outbox spec, which becomes a consumer of the background-task machinery designed here.
- **Architecture decisions that stand unless a theme overturns them with reasons.** The entity class is the single source of truth for storage shape (no persistence DTO; a parallel `ForSave` hierarchy as the UDTT source was rejected); leaf-only mapping (pack abstract bases + non-abstract defaults + distro sealed leaves); child→parent navigations only, no parent→child **EF** navigations; every reference is a DB FK; capability interfaces are per-feature column gating, never a paired interface per entity; app-assigned ids from sequences with a buffered self-healing allocator; migrator is a separate job; one application DB per tenant; every tenant is Live or Sandbox; reports in three tiers; `SqlBuilder<T>` for tier-2 SQL; no logic in the database. Feature composition (`AddTellma`, declare/contribute, edges) exists in ARCHITECTURE.md but not in the brain dump; the breakdown says the first release builds it at minimal fidelity.

## 5. Orchestrator's critique hints — hints, not decisions

Weigh these; adopt, refine, or reject them with reasons.

- **Redundant columns.** `User` carries both `SavedAt` and the temporal period `ValidFrom` — one is redundant. `Center.IsLeaf` is derivable from `SubtreeCount = 1`; `Level` is derivable from the node. Every derivable column that is kept should be justified by a query it makes cheaper.
- **Audit vocabulary.** Temporal entities use `SavedById` + period; non-temporal use four audit columns. Consider one vocabulary: four audit columns on every top-level entity (creation is otherwise lost or expensive to derive from history), with system-versioning as an additive capability rather than a different base class.
- **Concurrency token.** `ModifiedAt` (datetime2(7)) can serve as the concurrency token if the rule is that user-visible mutations (save and actions) bump it and background bookkeeping never does (bookkeeping columns live in sibling tables) — no `rowversion`, no hash, and the guard can travel as a standalone `(Id, ExpectedStamp)` TVP checked inside the persist batch. Evaluate against `rowversion`.
- **Blobs.** Staged uploads (upload first through a blob endpoint, save the record with the returned token, sweep unconfirmed blobs after N hours) keep one JSON save endpoint, standard etag GETs, and remove "pre-commit non-transactional side effects" from the save pipeline entirely (blob writes precede the transaction, deletes follow commit). Evaluate against multipart save.
- **Round trips.** The connect call (subject→user, `LastActive`, tag reads) can ride the first business batch optimistically, using cached permissions; if the returned permissions tag differs from the cache, recompute and re-run. Common case: one round trip for a read, two for a save. State the failure modes (deactivated user, stale permissions, RLS pre-check ordering).
- **Validation context.** A DataLoader-style API: validators declare context requests against the batch builder (dedup by structural key), the pipeline executes, validators run, further rounds are allowed but bounded and metered.
- **Public permissions.** An `IsPublic` flag on `Role` (memberships rejected by validation) reuses the whole role UI and the securables validation; compare with a seeded well-known role and with a separate table.
- **Verbs and cardinality.** The web surface can be POST-everywhere (Queryex in bodies; the SPA never needs HTTP caching of queries) while the public `v1` surface keeps REST projection; ARCHITECTURE.md then changes. Save should take an array (the guiding principle); the UI sends an array of one; one endpoint for both details-page save and import.
- **Wire shape.** A single entity class with `[NotMapped]` child collections (so the EF model still has no parent→child navigation and Queryex has no collections) plus a declared editable/server-owned split may beat a parallel DTO hierarchy for distro-author simplicity. Name the risks (client-sent server-owned values must be overwritten by the pipeline; write-once columns).
- **Settings and languages.** Content languages (the tenant's up-to-three `Name` columns) and the UI/message language (any language the distro ships resources for) are different axes; formatting culture and calendar are user preferences. Decide whether a request's `Accept-Language` must be one of the tenant's content languages.
- **Version tags.** Prefer a dedicated non-temporal table for tenant-level tags (settings, each cacheable entity type, securables) and a sibling table for user-level tags; tags are opaque (`uniqueidentifier` or monotonic `bigint`?). The emitter can bump tags automatically because every batch statement declares which tables it writes.
- **Trees.** Prefer a SQL statement appended to the save batch that recomputes `Node`, `SubtreeCount`, `ActiveSubtreeCount` for the affected subtrees over in-memory recomputation; validate cycles in C# over the loaded ancestor chain before persisting.
- **MCP topology.** One MCP endpoint per tenant (`/{tenantId}/mcp`) with one code path; an agent needing two tenants configures two servers. Verify the current MCP authorization spec before sketching auth.
- **Search.** Keep a server-side `Search` parameter driven by an entity's declared searchable columns (one line in the distro) rather than pushing the burden to the client; no picker-vs-page hint.
- **Naming.** Singular vs plural table names must match ARCHITECTURE.md (`gl.Invoices`) or change it; `TenantConfigurationKV` needs a real name; `UserSettings` vs `UserPreferences`; `CenterType` vs `Type`; `Notification` vs `InboxItem`; "securable" as the term; "version tag" vs "etag" vs "fingerprint"; "metaversion".
- **Scheduler replay.** Per-schedule policy (`Coalesce` / `ReplayAll` / `Skip`) plus a global safeguard: a gap beyond X hours coalesces regardless and raises an alert (the year-old backup restore).
- **Credentials for tasks.** A seeded system user (reserved id, cannot sign in, full permissions) for built-in schedules; user-triggered tasks run as the user with permissions evaluated at run time; a schedule owned by a deactivated user pauses and notifies admins.
- **Drift.** A permission whose resource, action, or filter no longer resolves grants nothing (fail closed), is surfaced in diagnostics and in the role editor, and never blocks the user's other permissions.

## 6. Lenses (for designer agents)

Each theme is designed independently by three agents with different lenses. Every proposal must answer **all** of the theme's questions; the lens decides which trade-offs win when they conflict, and what you probe hardest.

- **Lens A — Distro-author simplicity and AI-native authoring.** Optimize for the distribution author (a coding agent) writing the least, most mechanical code; for the MCP consumer; for "common requirement → straightforward". Probe: how many lines does a distro write to add an entity with IsActive and a tree? Is every capability declared once?
- **Lens B — Tier-2 performance and operations.** Optimize for round trips, bulk shapes, plan-cache friendliness, lock duration, cache correctness, multi-instance safety, observability from day one. Probe: count the DB calls per operation; find the N+1s; find the lock held across I/O.
- **Lens C — Correctness, security, and long-term maintainability.** Optimize for fail-closed access control, no silent data loss, concurrency soundness, schema evolution (expand/contract, N−1 apps), testability, and clean seams between packages. Probe: where does a stale cache leak data? Which write path bypasses the tag bump? What breaks a distro on the next platform minor?

2. **Decisions** — numbered `D1…`, each with: the decision (concrete: names, types, signatures, statements), the rationale, the alternatives rejected and why, a confidence (high/medium/low), and a **review flag** when an equally plausible alternative exists that Ahmad should see.

4. **Schema** — every table and column with type, nullability, uniqueness, indexes, and constraints, in a fenced block per table.
5. **Answers** — a table mapping every brain-dump open question in this theme (quote it briefly) to the decision that answers it.
6. **Seams** — your position on each cross-cutting seam you touch (§4), with the contract you need.
7. **Departures** — every departure from ARCHITECTURE.md, with the reason.
8. **Verification** — facts you relied on from the research file or your own web search, and anything still unverified.

**Judge agents** write `.tmp/crud-design/themes/<theme-key>/decisions.md` in the same structure as a designer file (sections 1–8), synthesized from the three proposals — the winning design with the best ideas grafted from the others — plus section 9, **Review flags** (every judgment call with its plausible alternative, in one place), and section 10, **Conflicts** (positions that other themes must reconcile).

## 8. Research digest — cross-cutting facts every agent must respect (verified 2026-09-01; details and sources in `research/*.md`)

- **`MERGE` is out.** Two MERGE defects survive on SQL Server 2022 CU7 (temporal targets with a nonclustered history index error; MERGE with a DELETE action under an indexed view silently corrupts). The save emitter emits separate `UPDATE` / `INSERT` / `DELETE` statements; app-assigned ids remove the classic upsert race, so no `HOLDLOCK` is needed. `NEXT VALUE FOR` is banned inside `MERGE` anyway.
- **Retry is the executor's job.** SqlClient's built-in retry logic is skipped for any command enlisted in a `SqlTransaction` or ambient `TransactionScope`, and `SqlBatch` has no `RetryLogicProvider`. `SqlBatch` also sends a shared TVP once per command and exposes only the last statement to OpenTelemetry — concatenated command text walked with `NextResult()` (which spec 0008's `BatchOrdinal` was designed for) is the batch mechanism. Distributed transactions throw on Linux: one connection, one transaction, one batch. Prefer an explicit `SqlTransaction` (or `SET XACT_ABORT ON; BEGIN TRAN … COMMIT` inside the batch text) over `TransactionScope` (Serializable by default, async flow suppressed).
- **RCSI is ON by default only on Azure SQL Database** (OFF on-prem; the migrator should enable it). Under RCSI a bare `READPAST` is a silent no-op — lease statements must pair `READPAST` with `UPDLOCK` (and `ROWLOCK`). C#-side uniqueness checks are write-skew-prone; unique indexes are the guarantee and errors 2601/2627 must map to field-level validation errors.
- **`hierarchyid` cannot ride a TVP** without `Microsoft.SqlServer.Types`' `SqlHierarchyId` (Linux support undocumented): exclude `Node` from the tree UDTT (`[ExcludeFromTableType]`) and compute nodes in SQL (recursive CTE + `ROW_NUMBER` path build per affected root, not per-row `GetDescendant`). The EF hierarchyid package is still separate (`Microsoft.EntityFrameworkCore.SqlServer.HierarchyId` 10.0.11) and requires SqlClient ≥ 6.1.6 (repo pins 6.1.1; 6.1.5 fixed a transaction-zombie bug) — a pin bump is part of the design. `Level` is a computed `GetLevel()`; breadth-first index `(Level, Node)` or `ParentId` + unique `Node`.
- **Temporal tables.** Every `UPDATE` writes a history row even when nothing changed (the emitter should skip unchanged rows or accept the churn knowingly); period columns are shadow properties in EF 10; TPT roots cannot be temporal.
- **JSON columns stay `nvarchar(max)`**: the native `json` type is GA on Azure SQL but still preview on SQL Server 2025 per the docs, and EF 10 auto-switches only under `UseAzureSql()`/compat 170.
- **No first-party BFF and no automatic token refresh in .NET 10**; Duende.BFF is paid — the distribution owns its BFF code. CSRF for the cookie-authenticated JSON API: a required custom header plus an `Origin` check (the .NET 10 docs say JSON endpoints need no antiforgery token; BCP 212 wants the header and `SameSite`). Back-channel logout by `sid` cannot work with a stateless cookie: choose `ITicketStore` or a throttled `ValidatePrincipal` plus a revoked-`sid` list. Finbuckle.MultiTenant 10.x requires EF Core ≥ 10.0.11 and its per-tenant-DB recipe breaks pooled contexts — roll our own tenant resolution.
- **No tenant passwords on Azure**: managed identity + per-database `CREATE USER … FROM EXTERNAL PROVIDER`; the catalog stores server + database only (SqlClient 7.0 split Entra auth into `Microsoft.Data.SqlClient.Extensions.Azure`). Azure SQL: no cross-database queries or `USE`; 500 databases per General Purpose pool; connection pools are per connection string. `AsyncLocal` must not carry tenant context — use a scoped holder copied into job scopes.
- **MCP** current revision is **2026-07-28**: stateless (no `initialize`/sessions), per-request `_meta`, `Mcp-Method`/`Mcp-Name` headers, DCR deprecated in favour of **client ID metadata documents (CIMD)**. C# SDK 2.2.0 (`AddMcp`, `MapMcp(pattern)` with route parameters, RFC 9728 metadata and the 401 challenge, request filters seeing `HttpContext`). OpenIddict 7.6.1 has RFC 8707 resources but **no protected-resource metadata, no DCR, no CIMD** — Claude Code, hosted Claude, ChatGPT/Codex prefer CIMD (hosted Claude and Codex also require `token_endpoint_auth_methods_supported` to include `none`), Cursor is DCR-or-static. The MCP auth sketch must record what the identity server must add.
- **ASP.NET Core 10**: the fallback authorization policy applies only to endpoints with zero authorization metadata and `AllowAnonymous` is absolute — a securable-as-endpoint-metadata design plus a startup audit over `EndpointDataSource` is the "hard to forget" mechanism; cookie auth returns 401/403 on API endpoints via `IApiEndpointMetadata`; built-in validation (`Microsoft.Extensions.Validation` 10.0.11) is an endpoint filter, sync-only, shape-only — keep its attributes and the `Lines[3].Quantity` / RFC 9457 error shape, own the bulk engine; output caching cannot serve authenticated POSTs; STJ source generation excludes private members and custom converters from its fast path.
- **Caching**: `HybridCache` serializes every write even L1-only, shares the DI `IMemoryCache`, and its tag stamps are process-local — a poor fit for DB-tag-validated caches; a private `MemoryCache` with a single-flight guard is the recommended shape (review flag). `rowversion` bumps on any update (unsuitable as a tag); Guid v7 is not sequential in SQL Server byte order; an app-generated Guid tag is restore-safe.
- **Localization**: `-u-ca-` culture names are a trap on .NET 10/ICU (mixed calendar output, `Parent` collapses) — carry the calendar as a separate context value and strip extensions before negotiation; no Ethiopian calendar exists in .NET, Excel, or Windows NLS, and a custom `Calendar` cannot be assigned to `DateTimeFormatInfo.Calendar` — calendar-aware formatting is platform code (port the monolith's Ethiopian calendar); `UmAlQuraCalendar` ends at AH 1500; `MessageFormat` 8.0.0 supports plural/select/selectordinal/nesting with a thread-safe cache; no standard header conveys time zone or calendar (GitHub's `Time-Zone` header is the precedent).
- **Settings edit**: ASP.NET Core 10 has JSON Patch (`Microsoft.AspNetCore.JsonPatch.SystemTextJson`, in-place mutation, security caveats) and no maintained merge-patch package; a typed partial-settings DTO with an explicit field list (RFC 7396 semantics, field-mask style) is the compatible shape.
- **Excel**: only forward-only writers keep memory flat — Open XML SDK 3.5.1 (MIT, SAX `OpenXmlWriter`/`OpenXmlReader`) or MiniExcel 1.46.0 (Apache-2.0, streams both ways, but cannot write validation/protection/defined names/custom XML); ClosedXML is DOM-based (OOM reported near 350k rows); EPPlus needs a commercial license per developer (every distribution author); NPOI added a maintenance-fee EULA. Excel rewrites strings into a shared-string table on save (import must cap or disk-index it); export with inline strings; ids/codes as text cells (15-digit precision, leading zeros); Hijri/Um Al Qura expressible as number formats, Ethiopian not; row limit 1,048,576.
- **Blobs**: `Azure.Storage.Blobs` 12.29.2 targets net10.0; setting blob tags does not change the ETag; lifecycle rules are day-granular and Azurite supports neither lifecycle nor reliable tag queries — the app-side orphan sweep is mandatory; containers are unlimited and RBAC scopes to a container; accept a host-supplied `TokenCredential`; `Results.Stream` implements 304/412/206 from an ETag; `File.Move` is atomic only within one volume; ImageSharp 4.1.1's split license grants Apache-2.0 to open-source and transitive consumers (flag for Ahmad), SkiaSharp needs the `NoDependencies` Linux package. Every surveyed SaaS API stages uploads then attaches (Notion expires unattached uploads after 1 hour).
- **Background work**: the industry lease model is a sliding lease renewed at 1/5 of its length with a fencing token, poison after ~5 attempts; `ROWLOCK` does not prevent lock escalation (5,000 locks); `UPDATE TOP` is unordered (use an ordered CTE); `OUTPUT` without `INTO` is illegal on tables with triggers; App Service Linux drain default is 5 s (max 120), host `ShutdownTimeout` 30 s, Always On required; Cronos 0.13.0 is the only cron library with documented time-zone/DST semantics; every mature scheduler has an **overlap policy** (default skip) — design one alongside the replay policy; Azure SignalR 1.33.1 supports `CloseOnAuthenticationExpiration`, the hub user id must equal the `sub`, and self-hosted multi-instance needs a Redis backplane.
- **Identity invite API** (as implemented): statuses `Invited|Reinvited|Active`, free-text per-user errors, prefix results on abort; `Active` means no email was sent and does not mean signed-in-here; delivery states report sandboxed sends as `Sent`; `client_credentials` with `scope=tellma_identity` and `resource=<issuer origin>`; `sub` is a 36-char GUID string; the dev admin's fixed sub is `00000000-0000-0000-0000-000000000001`; no distribution-side client of this API exists yet.
