# PC-060: tm-multi-select, option groups, foundation glyphs through tm-icon

## Implementer notes

### What was built, and where

All paths are under `client/` unless stated.

- **Shared select shell.** `projects/core/tellma-core-ui/select/tm-select-base.ts`:
  `TmSelectBase<T, V>` (selector-less abstract `@Directive`, exported and marked `@sealed`, so
  the members both selects inherit stay in the `./select` API golden — the ɵ convention
  `ɵTmGridBase` uses would drop the selects' whole input surface from it). It holds everything both selects share: the
  form-control plumbing (state inputs, describedby/label/error wiring, `showsInvalid`), the size
  resolution, `valueKey`/`displayWith`/`placeholder`/aria inputs, `opened`/`closed`, the anchored
  overlay, the one-directional value bridge into aria's listbox (now generic over a key list via
  `selectedKeys()`), closed-trigger typeahead, the label-less typeahead fallback, `focus`/`open`.
  `tm-select.ts` now extends it and keeps only its model, its commit path and the
  `TmCellEditor` surface; behaviour is unchanged (the old unit and e2e suites pass untouched).
- **Option groups (§B.4).** `select/tm-option-group.ts`: `TmOptionGroup` (`label` required, a
  generated `headingId`, empty template — a definition like `tm-option`). A nested group throws in
  development (`inject(TmOptionGroup, { skipSelf: true })`). `TmOption` gains `group` (its
  enclosing group by DI). Both selects read `contentChildren(TmOption, { descendants: true })`
  for the flat order and derive `entries` (runs: a group's options, or an ungrouped run between
  groups) from each option's `group`. Each group renders
  `<li role="group" aria-labelledby><div heading/><ul role="none">options</ul></li>`; the heading
  is a block at the option height (`--tm-field-option-height`), secondary text, never an option.
  Run track keys are the group, or `ungrouped-<n>` (the run's place among the groups), so option
  insertion never re-creates neighbouring rows.
- **`tm-multi-select` (§B.4).** `select/tm-multi-select.ts` + `tm-multi-select.css` (the row
  checkbox; the trigger, panel, rows and group headings reuse `tm-select.css`, listed first in
  `styleUrls`). `ngListbox [multi]="true"` (`aria-multiselectable="true"`), `selectionMode`
  explicit. aria toggles on click/Space/Enter (and Shift-range, Ctrl/⌘+A); the component commits
  after every listbox `click`/`keydown` by rebuilding the value: selected options in option order,
  then every value no option matches (kept, never pruned — aria never sees them), keeping the
  caller's instances for keys already selected. Nothing is written or emitted when an interaction
  changed nothing. `mousedown` on the panel is `preventDefault`ed so focus never leaves the trigger
  (the combobox closes on blur; Escape/Tab are the trigger's keys). Trigger: one line, labels in
  display order joined with `Intl.ListFormat(TM_ACTIVE_LOCALE(), { type: 'unit', style: 'short' })`,
  ellipsized by CSS only (the DOM text, so the accessible value, is the whole list); the
  placeholder when empty. Unmatched values show through `displayWith`, else `String(value)` with one
  `console.warn` per key in dev mode. Row checkbox: `tm-checkbox`'s box on its tokens
  (`--checkbox-box-size`, `--checkbox-glyph-size`), at the row's inline end (§B.4 "Accessibility
  and RTL"), with disabled and forced-colors states. Not a `TmCellEditor`.
- **Foundation glyphs (§B.7).** `checkbox` (`Check`/`Minus`), `select` (`ChevronDown` caret,
  `Check` option tick, `Check` row-checkbox tick) and `form-field` (`CircleAlert`) draw through
  `<tm-icon [svg]>` with data imported from `lucide`. Each host re-points `--icon-size` at the token
  it used before (`--checkbox-glyph-size`, `--select-check-size`, `--field-error-icon-size`); the
  stroke is tm-icon's `--icon-stroke-width` (1.75), as before. The checkbox's transparent-until-
  checked mark moved from the path to the `tm-icon` host (`.tm-checkbox__glyph`).
- **Harnesses.** `projects/core/tellma-core-ui-testing/select-harness.ts`:
  `TmOptionGroupHarness` (`getLabel`, `getOptions`), `TmSelectHarness.getGroups()`.
  `multi-select-harness.ts`: `TmMultiSelectHarness` (`open`, `close`, `isOpen`, `toggle(label)`,
  `getValueText`, `isOptionSelected`, `isPlaceholderShown`, `isDisabled`, `getOptions`,
  `getGroups`, `sendTriggerKeys`).
- **Strings.** `multiSelect.placeholder` ("Select options") and its Arabic twin (gendered like
  `select.placeholder`).
- **Docs and showcase.** `tm-select.examples.ts` (+ `Grouped`), new `tm-multi-select.examples.ts`
  (`Basic`, `Grouped`), both compiled by `docs-examples.spec.ts`. Showcase: the select story gains
  a grouped `tm-select` and a grouped `tm-multi-select` (with a disabled option and a value readout);
  a new `glyphs` story holds every foundation glyph plus a selectable grid for the pixel
  comparison. READMEs of core-ui and core-ui-testing updated. ARCHITECTURE.md already states the
  glyph rule; no change needed.
- **Budgets.** `./select` 8 → 9 (spec'd), with notes for `./select`, `./checkbox`, `./form-field`.

### Deviations

1. **A readonly select no longer opens** (both selects). Pre-existing bug found while testing: a
   readonly `tm-select` opened on a trigger click or ArrowDown and committed the clicked option,
   although `open()` and closed typing already refused it. The shell now folds any aria open back
   while readonly (our signal and aria's model), and both commit paths also refuse while readonly.
2. **Headings come from each option's group, not from `contentChildren(TmOptionGroup)`.** §B.4
   says the select reads `contentChildren(TmOptionGroup)` for the headings; the runs are derived
   from the flat option list and each option's injected group instead, which gives the same
   headings in the right places with one query. An empty group (no options) renders nothing.
3. **Unmatched values in the multi-select sort after the matched ones**, in their own relative
   order: §B.4 says "always in option order" but such values have no option position.
4. **Extra keys on the multi-select:** Shift+arrows range selection and Ctrl/⌘+A toggle-all come
   from aria's multi listbox and are kept (APG listbox behaviour). Ctrl+A never clears values no
   option shows.
5. **tm-select's unmatched-value label stays the placeholder** (spec 0002 §3.4's chain). §B.4's
   "As in tm-select, they show … else String(value) with a dev warning" describes the
   multi-select's rule correctly but misdescribes tm-select; tm-select is unchanged.
6. **The shared shell is public.** `TmSelectBase` (`@sealed`) and `TmSelectEntry` are exported
   names, not ɵ ones, so the inputs both selects inherit stay in the `./select` golden.
7. The checkbox's mark opacity moved from the `<path class="tm-checkbox__mark">` to the
   `tm-icon.tm-checkbox__glyph` host (`.tm-checkbox__mark` no longer exists).

### Open risks

- The multi-select commits by reading aria's listbox value inside our own `click`/`keydown`
  listener on the same element; this relies on Angular registering directive host listeners before
  template listeners (the single select's existing Enter/Space commit relies on the same order).
- `TmSelectBase` and `TmSelectEntry` are new public names (the price of keeping the inherited
  API in the golden); `@sealed` documents that the base is not for extension outside the library.

- `TmMultiSelect.commitFromListbox` and the base's value bridge under option turnover, prunes,
  disabled-and-selected options and Ctrl+A.
- The readonly fold-back effect in `TmSelectBase` (it writes aria's `expanded` model directly).
- The markup golden (`tm-select-markup.spec.ts`) as the proof that a flat select renders as
  before.
- The glyph geometry spec's derivations, and that the pixel comparison clips whole pixels.

  - The public `@sealed` `TmSelectBase` keeps the selects' inputs in the golden. The `ɵ`

### Findings

**R1-1 (major) — a multi-select whose options have no `label` shows the placeholder while
values are selected.**
`client/projects/core/tellma-core-ui/select/tm-multi-select.ts:238-245`

`labels` drops every empty label (`.filter((label) => label !== '')`), and `showsPlaceholder` is
`labels().length === 0`. An option without an explicit `label` input has an `effectiveLabel` of
`''` until the panel first renders. `derivedText` is written only by the base's
`afterRenderEffect` over the rendered rows.

- **Failure scenario.** Take §B.4's own example (`<tm-option value="Service">Service</tm-option>`)
  with a prepopulated value, such as an enum filter restored from the URL (spec 0029 §13). The
  closed trigger shows "Select options" in placeholder styling while the filter is active.
- **Partial labels.** With some options labelled and some not, the unlabelled selections
  silently drop out of the trigger. A value that no option matches still shows as
  `String(value)`, so a matched value displays less than an unmatched one.
- **Suggested fix.**
  - Base `showsPlaceholder` on `value().length === 0`.
  - In `displayLabel`, fall back to `String(value)` for a matched option whose `effectiveLabel()`
    is still empty, with the same one-per-key development warning telling the author to pass
    `label` (or `displayWith`).
  - Add a unit test with label-less options and a prepopulated value, panel never opened.

**R1-2 (minor) — a readonly select is not announced as readonly.**
`client/projects/core/tellma-core-ui/select/tm-select.ts:69-84`,
`client/projects/core/tellma-core-ui/select/tm-multi-select.ts:77-93`

Neither trigger binds `aria-readonly`. `[softDisabled]="readonly()"` has no effect while
`disabled` is false, and aria's Combobox has no readonly input. Deviation 1 now makes a readonly
select do nothing on click, ArrowDown, Enter or Space.

- **Failure scenario.** A screen-reader user reaches what is announced as an ordinary, operable
  collapsed combobox. Every attempt to open it is silently ignored, with nothing to say why.
- **Suggested fix.** Add `[attr.aria-readonly]="readonly() ? 'true' : null"` to both triggers
  (`role=combobox` supports it). This is null when not readonly, so the flat-select markup golden
  is unaffected. Assert it in both readonly unit tests.

**R1-3 (minor) — new showcase members lack TSDoc (AGENTS.md).**
`client/projects/internal/showcase/src/app/select/select-story.ts:153-154`

`groupedValue` and `multiValue` were added without TSDoc. `centerGroups` beside them, and every
member of the new glyphs story, have it.

- **Suggested fix.** Add one-line TSDoc to each.
