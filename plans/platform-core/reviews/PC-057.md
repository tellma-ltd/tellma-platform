# PC-057: Two-line options, page context, grid cell options, picker glyphs

## Implementer notes

### What was built, and where

All paths are under `client/projects/core/` unless stated.

- **Two-line rows and label parts (§E.1)** — `tellma-core-ui/entity-picker/tm-entity-picker.ts`, `.css`.
  - New inputs `itemDescription` and `itemLabelParts`. The row template draws the label line as
    one `<bdi>` (unbound or `null`/empty parts) or one `<bdi>` per part joined by the plain text
    " - "; with a description bound, a second line holds the description in its own `<bdi>`.
  - Two-line mode is decided by the binding (`twoLine = itemDescription() !== undefined`), never
    by the data, so every result row of a two-line picker takes
    `--entity-picker-option-height-2line`, a `null` description included (its line keeps
    `min-block-size: 1lh`, so labels align across rows). Footer rows keep the one-line height.
  - Accessible name "label, description": a visually hidden ", " (`clip-path: inset(50%)`,
    inline, inside the label line) closes the label line only when a description exists. The
    accessible name's label part is the joined parts, i.e. `itemLabel` when the contract holds.
  - Both lines clip only along the line (`overflow: clip visible`) so the snug leading never
    shaves Arabic marks; the description is `--text-xs`, `--text-secondary`, regular weight;
    the check spans both lines at the inline end. Forced colors: a chosen row's description
    takes HighlightText too.
- **The token** — `tellma-core-ui-tokens/presets/tellma-default.ts`: `entityPicker.optionHeight2line:
  42px` (14px label + 12px description at the snug leading ≈ 35px, plus air).
  `emit/emit-css.ts`'s camel-to-kebab now also splits a letter→digit boundary so the token emits
  as `--entity-picker-option-height-2line` (the name the spec gives). `tokens:check` scans every
  stylesheet for dangling `var()`s and stayed green, so no existing variable changed name; a
  `tmRefToVarName` case pins the new split. `src/apps/Tellma.Identity/wwwroot/css/tokens.css`
  refreshed by `identity:copy-assets`.
- **Page context (§E.3)** — `tm-entity-picker-types.ts`: the object page form gains `context`;
  `TmEntityPickerPageData` gains `context`, `multiple`, `ids`, `maxItems`. `launchPage` copies
  `context` into the data only when the config carries one (the bare class form passes none —
  the key is absent, not `undefined`).
- **Grid columns (§E.4)** — `tellma-core-ui/grid/tm-grid-column.ts` gains `itemDescription`,
  `itemLabelParts`, `formatParts`; `grid/internal/grid-core.ts` carries them on the column and
  builds a `parts` field on the cell view model; `grid/internal/grid-view.ts` renders a parts
  branch; `grid-editing/editing.ts`, `editor-session.ts`, `editors.ts` hand the two item
  functions to the cell's picker.
- **Glyphs (§E.5)** — the picker's three inline SVGs (circle-alert, search, check) became
  `<tm-icon [svg]>` with Lucide data; sizes moved from `inline-size`/`block-size` rules to
  `--icon-size` on the glyph or its button, at the same tokens as before.
- **Harness** — `tellma-core-ui-testing/entity-picker-harness.ts`: `TmEntityPickerOptionHarness`
  gains `getDescription()` and `getLabelParts()`; `getText()` now reads the label line (excluding
  the hidden separator), so it keeps returning the label for two-line rows.
- **Showcase** — the entity-picker story gains a two-line Center picker (`picker-centers`: two
  Jeddahs told apart by parent, a Latin code beside an Arabic name, a Center without a parent);
  the grid-entity story gains a fifth column, Center (`centerId`), binding all three new column
  inputs.
- **Docs** — `TwoLineRows` (picker) and `EntityColumnWithParts` (grid) examples; the core-ui
  README's entity-picker row; `components.json` regenerated by `docs:build`.
- **Goldens** — `client/api/core-ui.entity-picker.api.md`, `core-ui.grid.api.md`,
  `core-ui-testing.api.md` approved (the picker golden gains `import * as lucide`, as the other
  glyph-bearing entry points' goldens already do).

### Deviations and rulings

1. **`maxItems`' message and "Done disabled" are the page's obligation, and no string ships
   here.** §E.3 says a page opened with `maxItems` keeps Done disabled above the cap "with §E.2's
   message". Pages are consumer components; the picker cannot enforce it. I documented the rule
   on `TmEntityPickerPageData.maxItems` and left the message string (`tmUi.entityPicker.maxItems`)
   to PC-058, which adds the multi-picker that sets `maxItems` and owns that string. Nothing in
   this checkpoint sets `multiple`, `ids` or `maxItems`.
2. **`formatParts` fallback rule.** The display cell uses the parts only when they join (by
   " - ") to exactly the cell's display text. Otherwise — `null` parts, an errored cell showing
   its raw text, a label still resolving, or parts that drift from `format` — it draws the
   display text as ONE `<bdi>` (the spec's "otherwise format's text in one `<bdi>`"). A column
   without `formatParts` keeps today's plain text span, so "unbound, cells render as today"
   holds literally. Copy, find and announcements keep using the display text.
3. **Unbound picker rows gain a `<bdi>` around the label.** §E.1 says one-line rows render in a
   `<bdi>` too; the row looks and reads the same, but the DOM is not byte-identical to before.
   The "unbound renders exactly as today" criterion is read as visual and accessible identity.
4. **Token-name emitter change** (above): needed to emit the spec's `-2line` name.
5. **The hidden separator is the literal ", "**, not a localized string: it only shapes the
   accessible name the spec fixes as "label, description".

### Open risks

- The two-line height (42px) is a design call; at the `sm` field size the one-line rows shrink
  but two-line rows do not (the token is not on the size ladder).
- `@angular/aria`'s `ngOption` derives nothing from content, so the accessible name depends on
  Chromium/AT name-from-content; Firefox/WebKit accname inserts spaces around block children,
  which the inline separator absorbs, but only Chromium is measured here.
- PC-051 re-baselines the gate on the linked measure (D-067); its integration will need these
  ceilings re-derived on that measure.

### What reviewers should examine hardest

- `grid-core.ts`'s `parts` rule: whether drawing the fallback as one `<bdi>` for a bound column
  is right for every cell state (pending, errored, empty).
- The `emit-css.ts` kebab change: any token a future preset adds with a letter-digit boundary
  now splits there.
- The picker template's whitespace: the " - " text node and the separator must produce no
  stray spaces (unit tests read `textContent` and accessible names to pin it).
