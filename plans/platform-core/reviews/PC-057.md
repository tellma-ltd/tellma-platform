# PC-057: Two-line options, page context, grid cell options, picker glyphs

## Implementer notes

### What was built, and where

All paths are under `client/projects/core/` unless stated.

- **Two-line rows and label parts (§E.1)** — `tellma-core-ui/entity-picker/tm-entity-picker.ts`, `.css`.
  - New inputs `itemDescription` and `itemLabelParts`. The row template draws the label line as
    one `<bdi>` (unbound or `null`/empty parts) or one `<bdi>` per part joined by the plain text
    " - "; with a description bound, a second line holds the description in its own `<bdi>`.
  - Two-line mode is decided by the binding (`twoLine = itemDescription() !== undefined`), never
    by the data, so every result row of a two-line picker takes
    `--entity-picker-option-height-2line`, a `null` description included (its line keeps
    `min-block-size: 1lh`, so labels align across rows). Footer rows keep the one-line height.
  - Accessible name "label, description": a visually hidden ", " (`clip-path: inset(50%)`,
    inline, inside the label line) closes the label line only when a description exists. The
    accessible name's label part is the joined parts, i.e. `itemLabel` when the contract holds.
  - Both lines clip only along the line (`overflow: clip visible`) so the snug leading never
    shaves Arabic marks; the description is `--text-xs`, `--text-secondary`, regular weight;
    the check spans both lines at the inline end. Forced colors: a chosen row's description
    takes HighlightText too.
- **The token** — `tellma-core-ui-tokens/presets/tellma-default.ts`: `entityPicker.optionHeight2line:
  42px` (14px label + 12px description at the snug leading ≈ 35px, plus air).

  as `--entity-picker-option-height-2line` (the name the spec gives). `tokens:check` scans every
  stylesheet for dangling `var()`s and stayed green, so no existing variable changed name; a
  `tmRefToVarName` case pins the new split. `src/apps/Tellma.Identity/wwwroot/css/tokens.css`
  refreshed by `identity:copy-assets`.
- **Page context (§E.3)** — `tm-entity-picker-types.ts`: the object page form gains `context`;
  `TmEntityPickerPageData` gains `context`, `multiple`, `ids`, `maxItems`. `launchPage` copies

  the key is absent, not `undefined`).
- **Grid columns (§E.4)** — `tellma-core-ui/grid/tm-grid-column.ts` gains `itemDescription`,
  `itemLabelParts`, `formatParts`; `grid/internal/grid-core.ts` carries them on the column and

### Deviations and rulings

1. **`maxItems`' message and "Done disabled" are the page's obligation, and no string ships
   here.** §E.3 says a page opened with `maxItems` keeps Done disabled above the cap "with §E.2's
   message". Pages are consumer components; the picker cannot enforce it. I documented the rule
   on `TmEntityPickerPageData.maxItems` and left the message string (`tmUi.entityPicker.maxItems`)
   to PC-058, which adds the multi-picker that sets `maxItems` and owns that string. Nothing in
   this checkpoint sets `multiple`, `ids` or `maxItems`.
2. **`formatParts` fallback rule.** The display cell uses the parts only when they join (by
   " - ") to exactly the cell's display text. Otherwise — `null` parts, an errored cell showing
   its raw text, a label still resolving, or parts that drift from `format` — it draws the
   display text as ONE `<bdi>` (the spec's "otherwise format's text in one `<bdi>`"), as an
   entity column without `formatParts` now does too (see 3). Copy, find and announcements keep
   using the display text.
3. **Unbound labels render in one `<bdi>`, in picker rows and in an entity column's display
   cell (corrected after review 1, R1-2).** A `<bdi>` takes its label's first-strong direction,
   so a label whose first strong character opposes the page direction now orders as the
   picker's `dir="auto"` input already did: "INV-0011 - نقد" in an RTL page reads code-left
   (name first) where a plain span read code-right. The original wording ("visual output
   unchanged") was wrong. Spec 0010 §E.1 says both "one-line rows do the same" (a `<bdi>`) and
   "unbound, rows render as today"; §E.4 says both "otherwise `format`'s text in one `<bdi>`"
   and "unbound, cells render as today". The orchestrator ruled the contradiction toward
   isolation, so the dropdown, the input and the cell agree; columns of other types keep their
   plain span.
4. **Token-name emitter change** (above): needed to emit the spec's `-2line` name.
5. **The hidden separator is the literal ", "**, not a localized string: it only shapes the
   accessible name the spec fixes as "label, description".

  but two-line rows do not (the token is not on the size ladder).
- `@angular/aria`'s `ngOption` derives nothing from content, so the accessible name depends on
  Chromium/AT name-from-content; Firefox/WebKit accname inserts spaces around block children,
  which the inline separator absorbs, but only Chromium is measured here.
- PC-051 re-baselines the gate on the linked measure (D-067); its integration will need these
  ceilings re-derived on that measure.

### What reviewers should examine hardest

  now splits there.
- The picker template's whitespace: the " - " text node and the separator must produce no

### Findings

**R1-1 (major) — Two-line rows keep the base rule's 8 px row gap, so 43.1 px of content sits in a
42 px row.**
`tm-entity-picker.css:133` sets `gap: var(--entity-picker-option-gap)` on every option. That
shorthand sets `row-gap` as well as `column-gap`. The two-line rule
(`tm-entity-picker.css:183-189`) overrides only `column-gap`, so an 8 px row gap stays between the
label line and the description line.
- The arithmetic: 14 px × 1.35 = 18.9 px for the label, 12 px × 1.35 = 16.2 px for the
  description, plus 8 px of gap, makes 43.1 px in a 42 px box.
- The token's own derivation (`tellma-default.ts:651-655`) assumes 35 px of content "with air
  above and below".
- The Chromium probe measured the label line starting 0.53 px above the row and the description
  ending 0.55 px below it.
- The failure gets worse in common cases:
  - an `lg` field (15 px): about 1.2 px past each edge;
  - Arabic fallback glyphs, whose mixed-font line boxes grow past 1.35 em.
- In each case the text runs into the active row's inset focus ring and the chosen row's accent
  bar.
- The e2e check "Both lines stay inside the row" (`e2e/specs/entity-picker.spec.ts:1163-1169`)
  allows 0.5 px of slack. It passed in the implementer's run (`.tmp/pc057-e2e.log`, test 240), so
  with the showcase fonts the overflow is at most 0.5 px. The lines still fill the row edge to
  edge, with none of the air the token was sized for, and the test cannot tell a correct row from
  this one.
- **Fix:** add `row-gap: 0` to `.tm-entity-picker__option--two-line` (or write
  `gap: 0 var(--entity-picker-option-gap)`), so the lines centre with about 3.5 px of air. Tighten
  the e2e to assert both lines sit inside the row by at least 1 px, at the default size and with
  the Arabic `DMM-01` row.

**R1-2 (minor) — Deviation 5 misstates the visible change, and the grid settles the same spec
tension the other way.**
`<bdi>` defaults to `dir="auto"`, so an unbound one-line row (`tm-entity-picker.ts:287`) now
takes its label's first-strong direction.
- Probe, RTL line, label "INV-0011 - نقد":
  - plain span (before): the code at x 342 and the name at x 314, so the code reads first (right);
  - one `<bdi>` (now): the code at x 315 and the name at x 394, so the name reads first.
- So an unbound picker no longer "renders exactly as today" (the Done-when). The deviation's
  "visual and accessible output are unchanged" is not true for any label whose first strong
  character opposes the page direction.
- The new rendering matches the input, which is already `dir="auto"` (`tm-entity-picker.ts:198`),
  so it is defensible.
- The display cell went the other way: `grid-view.ts:336` keeps a plain span for a column without
  `formatParts`, citing "unbound, cells render as today". §E.4's "otherwise `format`'s text in one
  `<bdi>`" reads at least as naturally as covering that case.
- The result: in an RTL grid, an unbound entity column now draws "INV-0011 - نقد" code-first in
  its display cell and name-first in its own dropdown.
- **Fix:**
  - Correct deviation 5 in the fix commit to say rows now take their first-strong direction, as
    the input does.
  - Resolve both spec tensions the same way: also draw an entity column's display text in one
    `<bdi>` when `formatParts` is unbound, or state why the cell keeps today's span.
  - Record for Ahmad the contradiction in §E.1 ("One-line rows do the same" against "unbound, rows
    render as today"), and the same one in §E.4.

**R1-3 (minor) — The picker trusts `itemLabelParts` where the grid checks it.**
`labelPartsOf` (`tm-entity-picker.ts:1214-1217`) draws any non-empty parts.
- If the parts drift from `itemLabel` (a stale code, a different separator), the row shows and
  names the parts, because the name is computed from content. A pick then commits `itemLabel`.
- That breaks §E.1's "The accessible name stays the plain label", and the visible row differs
  from the text the input receives.
- The grid's display cell guards exactly this case (`grid-core.ts:3251-3258`).
- **Fix:** use the parts only when `parts.join(' - ') === labelOf(item)`, falling back to the one
  `<bdi>` otherwise, ideally with a dev-mode warning. Add a unit case with drifting parts that
  asserts one run and the accessible name equal to `itemLabel`.

**R1-4 (minor) — The commit's suite list leaves out a touched integration suite.**
The commit changes `src/apps/Tellma.Identity/wwwroot/css/tokens.css`, so `Tellma.Identity` is a
changed project (PLAN §7.1 item 4).
- `Tellma.Identity.IntegrationTests` (46 `Category=Integration` traits) has it in its reference
  closure. The Tests line lists only `Tellma.Identity.Tests` under the unit filter.
- The risk is negligible: those tests never fetch the stylesheet, and `BrandingTests` is
  `Category=E2E`. The list is still incomplete against the rule.
- **Fix:** run `Tellma.Identity.IntegrationTests` with
  `--filter "Category=Integration&Category!=Nightly&Live!=true"` and list it, or have the
  orchestrator rule that refreshing the copied token CSS does not touch the project.

**R1-5 (minor) — Two new or rewritten declarations lack TSDoc (AGENTS.md).**
- `KEBAB` (`emit-css.ts:21`) was rewritten with a `//` comment in place of a TSDoc block.
- `ColumnInternal.entityItemDescription` and `entityItemLabelParts` (`grid-core.ts:407-408`) are
  new members with no doc comment. They follow the undocumented neighbours that share
  `entitySearch`'s comment.
- **Fix:** turn the `KEBAB` comment into `/** … */` and give the two new members one-line TSDoc.
