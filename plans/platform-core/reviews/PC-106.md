### Size (bundle rule)

The primary measured 38.49 KB before and 40.62 KB after on the linked measure (+2.13 KB). The
ceiling is 41, the measured figure rounded up to the next 0.5 KB, within 0027's 5 KB share. Every
part is on the first frame:

- `TmShortcuts` is the one listener:
  - the shell registers `Mod+K`, `Mod+/` and the pin key at its first render;
  - TmPageActions (primary, 0026 §9.4) and TmSupport's `Mod+Alt+Shift+D` register through it.
- `TmShellMain` is called by the primary error presenter.
- `TmShell` and `TM_SHELL_LAYOUT` are read by the shell and TmBanners (primary).

Savings taken:

- The refusal messages sit behind ngDevMode and fold away (verified in a production bundle: no
  "refused" text).
- The grid keys are a static copy: importing `TM_GRID_KEYS` would pull about 1.97 KB of the grid's
  binding table onto the first frame.
- The busy check uses a probe, not `TmBusyOverlay`.
- `tmSearchNormalize` moved to its own entry point: it is not needed on the first frame, and the
  static-graph check now proves the primary never reaches it.

### Deviations

1. **`tmSearchNormalize` is in `@tellma/core/search-normalize`, not the primary** (0027 §1 places it
   in the primary). Nothing on the first frame matches text. It is a `shared` entry point:
   - `/shell` (the launcher, the shortcuts filter) and the lazy pages (field tree, reports list) can
     import it;
   - the primary cannot.

   The importer should load it lazily if the launcher wants it off the first frame. `/shell` loads
   on every first frame, so a static import from `/shell` puts its 0.40 KB back on it.
2. **The frame CSS is global** (`@tellma/core/styles.css` → `styles/tm-frame.css`), not
   `@tellma/core/shell`'s `frame.css` (0027 §5.1's comment). The `:root` variables must hold
   before any shell renders (the toast host reads `--toast-offset-block-start`). An entry point's
   component styles are scoped, and the shell has no global stylesheet of its own.
3. **`Mod+Enter` is exempt from the grid refusal.** `TM_GRID_KEYS` lists it, but §4.3's page family
   names `Mod+Enter` explicitly. The grid prevents the event whenever it acts on it, and then the
   registry skips the key. This resolves the D-057 item 4 / watchlist lead.
4. **`Escape` is admitted only for the id `dashboard.exit-presentation`.** 0035 §12.4 does not name
   the id, so 0035's implementer must use this one.
5. **`ɵregisterInDialog(dialog, …)`** is the "dialog's own context" owner tag for §4.2 step 5. It is
   an internal method on the public class; the API golden leaves ɵ members out.
6. **`tm.shortcut.conflict` carries `reason`** besides `id`.
7. **An `input` that types nothing** (checkbox, radio, button, submit, reset, image, file, range,
   color, hidden) is not an editable target. §4.2 step 4 says `input`, but a page's `F2` should
   still work on a focused checkbox.
8. **The busy check reads a core-ui overlay probe** (`ɵtmIsBusy`) instead of injecting
   `TmBusyOverlay`, since injecting it would create its host.
9. **Conflicts compare on both platforms**: `Mod+Space` is refused against the grid's `Ctrl+Space`
   on every OS, as is a page shortcut whose keys equal a live one under either platform's `Mod`.

### Open risks / what to examine hardest

- **The dispatch order of the field and modal rules**, and the Option rule's character test
  (`[...key].length === 1 || key === 'Dead'`). A layout where Option+letter types the letter
  itself still runs the shortcut.
- **`TmShellMain.replace` during a navigation** ties the override to the navigation's target
  (tested from a guard). If that navigation then fails (the error presenter's likely case), the
  override belongs to a path that never landed: the next navigation that lands anywhere else
  restores the route host, and one that lands on that path keeps the override.
- **`TmShell`'s holds are keyed by `DestroyRef`.** Two calls with one `DestroyRef` are one hold, by
  design.
- **The `shared` entry-point generalisation in `tmAllowedImports`.** The rule test and the table
  test pass, but reviewers should confirm that no eager entry point should be barred from
  `./search-normalize`.
- **The 2.13 KB raise** shares the primary's ceiling with PC-105 and PC-F69, which run in parallel.
  Expect a merge in the budget note.
