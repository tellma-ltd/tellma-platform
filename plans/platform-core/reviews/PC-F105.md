# PC-F105: Reserve the wordmark's box, and root-cause the layout-shift cold-entry flake

## Implementer notes

### Root cause: the tenant shell's wordmark image, which had no box until its file decoded

A throwaway probe spec (not committed) recorded every `layout-shift` entry's sources in the
cold-entry scenario of `layout-shift.spec.ts:15`, under the PC-F86 delay harness (40 sites in 29
files of `projects/core`), eight runs, chromium and chromium-ar. Five of eight shifted, and each time the
one entry and its one source were the same:

| Project | Value | Source | Previous rect | Current rect |
|---|---|---|---|---|
| chromium | 0.000617225964864095 | `div.tm-app-bar__group` in the tenant shell's `tm-app-bar` | 24,5 440x30 | 73.53,5 440x30 |
| chromium-ar | 0.000617225964864095 | the same | 816,5 440x30 | 766.47,5 440x30 |

The value is CI's exactly (45709713144, 45717312412). The group moves 49.53 px toward the end
edge, which is 14 px x 736/208: the wordmark image is 14 px tall with `inline-size: auto`, so it
is 0 px wide until its SVG has loaded and decoded, which on a cold entry is a new document's
first load of the file and takes its own tasks. The harness makes the race likely by changing
when the bar first paints relative to the image's load; CI's Linux runners hit the same race
without it. Nothing else
shifted in any run. The PC-118 observation (0 to 93.75 px) is the same mechanism with a
different ratio.

### What was built

- `@tellma/core-tools` `checks/brand.ts`: `tmBrandRatios(files)` reads each resolved brand file's
  `viewBox` (the same parse the brand checks use, factored into `viewBoxSize`, which also rejects
  non-finite numbers) and returns width over height by file name; `tmBrandDefine(files)` formats
  it as the `--define` argument `TM_BRAND_RATIOS={...}`.
- `commands/build.ts` passes `--define TM_BRAND_RATIOS=...` to `ng build` from the brand files it
  already resolves; `commands/serve.ts` passes the same to `ng serve`. So each distribution's own
  files (its `public/brand/` overrides, else core's) give the numbers, measured at build time.
- `@tellma/core/shell` `frame/tm-shell-frame.ts`: `TM_SHELL_BRAND_RATIOS` (root token; its
  factory reads the replaced constant, `{}` when undefined) and `TmShellBrandWriter` (root
  service, created by the first frame of either shell), which writes `--tm-brand-{file}` on the
  root element. Neither is exported from the entry point.
- App bar and tenantless shell CSS: the wordmark image is `block-size: 14px; inline-size:
  calc(14px * var(--tm-brand-wordmark-on-dark))`, and below md the mark is 18 px by `18px *
  var(--tm-brand-mark-on-dark)`. The About dialog's wordmark is 20 px by its theme's file's ratio
  (bound through `--tm-about-dialog-wordmark-ratio`). Without the variable the declaration is
  invalid at computed-value time, so the width falls back to `auto`, which is the old behaviour.
- Tests: `brand.spec.ts` (core's ratios; an override's, with an odd viewBox; the define string),
  `build.spec.ts` and `serve.spec.ts` (the argument reaches `ng`), `build.fixture.spec.ts` (the
  fixture's 120x24 files become exactly one literal in the emitted JS), `tm-shell-frame.spec.ts`
  (writes and removes the variables; the image's box from the ratio alone at 1000 and 600 px,
  with no brand file served), `tm-tenant-shell.spec.ts` (the bar's wordmark and mark boxes), and
  two Acme e2e tests in `layout-shift.spec.ts` that hold `**/brand/*.svg` on a first visit, check
  the image is not complete and already has its width, then release the file and assert neither
  the image nor the next item in the bar moved (`/1/customers` and `/tenants`). Before the fix
  both failed 4 of 4 (width 0); after it they pass.

### Deviations

1. The row suggests emitting the ratios "with the brand metadata (or as width/height
   attributes)". The boot config is the brand metadata's home, but the English boot script was
   at its 3 KB gzip budget with almost no headroom, and the ratios pushed it over; width/height
   attributes cannot come from distribution files the library's templates do not know. So the
   numbers go in as a build-time define, read by the shell. Same effect: each distribution's own
   viewBoxes, measured at build time.
2. A definite width (`height x ratio`) rather than `aspect-ratio`: an `aspect-ratio` box with an
   auto width still takes the alt text's width while the file fails or is pending in some
   states (measured 38.2 px in the unit runner), and a definite width is final in every state.
3. The About dialog's wordmark gets the same treatment (it had the same `auto` width); it is not
   in the row.
4. The ratio is the viewBox's alone; an SVG's `width`/`height` attributes are ignored, as the
   brand checks already require a viewBox and the images are sized by CSS.

### Measurements

- `layout-shift.spec.ts`, `--repeat-each 20` on chromium and chromium-ar, against the Acme build
  of this tree: without the harness 120 passed (each of the three tests 20 of 20 per project),
  and with the harness (the same 40 sites) 120 passed, no retries. Before the fix the cold-entry
  test shifted in 5 of 8 probe runs under the harness, and the two wordmark tests failed 4 of 4.
- Initial JS (Acme, gzip level 9, the 24 files `index.html` loads): about 0.22 KB more than
  HEAD. The token and writer sit in `tm-shell-frame.ts`, which both shells already share; as a
  module of their own, esbuild split a new shared chunk (+0.29 KB). Acme's build total is 194,499
  bytes. `size:check`: `@tellma/core/shell` is 8.91 KB of its 9 KB ceiling (about 8.74 before).

### Open risks

- PC-F102 (pc-1) edits the same `ng build` argument list in `build.ts` and the same
  `@tellma/core-tools` row in ARCHITECTURE.md; the merge needs both changes.
- An app built without `tellma-client` (a plain `ng build` of a distribution, or the showcase)
  has no define, so its brand images fall back to `auto` width, as before.
- The define is a global identifier in library code; a consumer bundler that does not replace it
  gets `typeof` undefined and the empty map, never a reference error.

- `@tellma/core/shell` has 0.09 KB of headroom left under its ceiling; the next shell item may
  need to raise it or move code to a lazy chunk.

### What reviewers should examine hardest

- Whether the cold-entry shift has another source on Linux CI that the local probe did not see
  (the probe saw only the wordmark across eight runs; CI's value matches it to 15 digits).
- `TmShellBrandWriter`'s lifetime: root-provided, created once by the first frame, cleared on
  the app's destroy.
- The CSS fallback when the variable is missing (invalid at computed-value time, so `auto`).
