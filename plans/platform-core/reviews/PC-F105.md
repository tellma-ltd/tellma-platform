# PC-F105: Reserve the wordmark's box, and root-cause the layout-shift cold-entry flake

## Implementer notes

### Root cause: the tenant shell's wordmark image, which had no box until its file decoded

A throwaway probe spec (not committed) recorded every `layout-shift` entry's sources in the
cold-entry scenario of `layout-shift.spec.ts:15`, under the PC-F86 delay harness (40 sites in 29
files of `projects/core`), eight runs, chromium and chromium-ar. Five of eight shifted, and each time the
one entry and its one source were the same:

| Project | Value | Source | Previous rect | Current rect |
|---|---|---|---|---|
| chromium | 0.000617225964864095 | `div.tm-app-bar__group` in the tenant shell's `tm-app-bar` | 24,5 440x30 | 73.53,5 440x30 |
| chromium-ar | 0.000617225964864095 | the same | 816,5 440x30 | 766.47,5 440x30 |

The value is CI's exactly (45709713144, 45717312412). The group moves 49.53 px toward the end
edge, which is 14 px x 736/208: the wordmark image is 14 px tall with `inline-size: auto`, so it
is 0 px wide until its SVG has loaded and decoded, which on a cold entry is a new document's
first load of the file and takes its own tasks. The harness makes the race likely by changing
when the bar first paints relative to the image's load; CI's Linux runners hit the same race
without it. Nothing else
shifted in any run. The PC-118 observation (0 to 93.75 px) is the same mechanism with a
different ratio.

### What was built

- `@tellma/core-tools` `checks/brand.ts`: `tmBrandRatios(files)` reads each resolved brand file's
  `viewBox` (the same parse the brand checks use, factored into `viewBoxSize`, which also rejects
  non-finite numbers) and returns width over height by file name; `tmBrandDefine(files)` formats
  it as the `--define` argument `TM_BRAND_RATIOS={...}`.
- `commands/build.ts` passes `--define TM_BRAND_RATIOS=...` to `ng build` from the brand files it
  already resolves; `commands/serve.ts` passes the same to `ng serve`. So each distribution's own
  files (its `public/brand/` overrides, else core's) give the numbers, measured at build time.
- `@tellma/core/shell` `frame/tm-shell-frame.ts`: `TM_SHELL_BRAND_RATIOS` (root token; its
  factory reads the replaced constant, `{}` when undefined) and `TmShellBrandWriter` (root
  service, created by the first frame of either shell), which writes `--tm-brand-{file}` on the
  root element. Neither is exported from the entry point.
- App bar and tenantless shell CSS: the wordmark image is `block-size: 14px; inline-size:
  calc(14px * var(--tm-brand-wordmark-on-dark))`, and below md the mark is 18 px by `18px *
  var(--tm-brand-mark-on-dark)`. The About dialog's wordmark is 20 px by its theme's file's ratio
  (bound through `--tm-about-dialog-wordmark-ratio`). Without the variable the declaration is
  invalid at computed-value time, so the width falls back to `auto`, which is the old behaviour.
- Tests: `brand.spec.ts` (core's ratios; an override's, with an odd viewBox; the define string),
  `build.spec.ts` and `serve.spec.ts` (the argument reaches `ng`), `build.fixture.spec.ts` (the
  fixture's 120x24 files become exactly one literal in the emitted JS), `tm-shell-frame.spec.ts`
  (writes and removes the variables; the image's box from the ratio alone at 1000 and 600 px,
  with no brand file served), `tm-tenant-shell.spec.ts` (the bar's wordmark and mark boxes), and
  two Acme e2e tests in `layout-shift.spec.ts` that hold `**/brand/*.svg` on a first visit, check
  the image is not complete and already has its width, then release the file and assert neither
  the image nor the next item in the bar moved (`/1/customers` and `/tenants`). Before the fix
  both failed 4 of 4 (width 0); after it they pass.

### Deviations

1. The row suggests emitting the ratios "with the brand metadata (or as width/height
   attributes)". The boot config is the brand metadata's home, but the English boot script was
   at its 3 KB gzip budget with almost no headroom, and the ratios pushed it over; width/height
   attributes cannot come from distribution files the library's templates do not know. So the
   numbers go in as a build-time define, read by the shell. Same effect: each distribution's own
   viewBoxes, measured at build time.
2. A definite width (`height x ratio`) rather than `aspect-ratio`: an `aspect-ratio` box with an
   auto width still takes the alt text's width while the file fails or is pending in some
   states (measured 38.2 px in the unit runner), and a definite width is final in every state.
3. The About dialog's wordmark gets the same treatment (it had the same `auto` width); it is not
   in the row.
4. The ratio is the viewBox's alone; an SVG's `width`/`height` attributes are ignored, as the
   brand checks already require a viewBox and the images are sized by CSS.

### Open risks

- PC-F102 (pc-1) edits the same `ng build` argument list in `build.ts` and the same
  `@tellma/core-tools` row in ARCHITECTURE.md; the merge needs both changes.
- An app built without `tellma-client` (a plain `ng build` of a distribution, or the showcase)
  has no define, so its brand images fall back to `auto` width, as before.
- The define is a global identifier in library code; a consumer bundler that does not replace it
  gets `typeof` undefined and the empty map, never a reference error.

- `@tellma/core/shell` has 0.09 KB of headroom left under its ceiling; the next shell item may
  need to raise it or move code to a lazy chunk.

### What reviewers should examine hardest

- Whether the cold-entry shift has another source on Linux CI that the local probe did not see

- `TmShellBrandWriter`'s lifetime: root-provided, created once by the first frame, cleared on
  the app's destroy.
- The CSS fallback when the variable is missing (invalid at computed-value time, so `auto`).

- Acme e2e `layout-shift` under the PC-F86 delay harness (40 sites in 29 files), `--repeat-each 5

  and `git status` was clean.

What I checked and found sound:

- **The root cause.** 14 px x 736/208 = 49.54 px is the group's move. With the group at 440 x 30
  on a 1280 x 720 viewport, the impact and distance fractions reproduce 0.000617 to the digits CI
  reported. Nothing else in the change or in the bar has that geometry. Below md the mark is
  18 x 18 and the shift would differ, so the CI value points at the wordmark, not the mark.
- **The define reaches every build and serve path that renders the shells.**
  - `build` passes it to `ng build` (`build.ts:136`), and `serve` to `ng serve` (`serve.ts:185`).
    The dev-server copies `define` into the build options and into Vite's prebundle options
    (`@angular/build` `dev-server/vite/index.js:63-80`, `tools/vite/utils.js:62`). So it also
    reaches `@tellma/core` when a distribution installs it from npm and the dev server prebundles
    it.
  - Architect merges object options one level deep (`@angular-devkit/architect`
    `src/options.js:20-26`), so a distribution's own `define` in angular.json survives the
    command-line one.
  - Acme's `build`, `build:esproj` and `start` all run `tellma-client`, so the Acme e2e host and
    the published wwwroot both get it.
  - The showcase does not render either shell. The unit runner has no define, the factory
    returns `{}` there, and specs provide the token themselves.
- **It cannot go stale in a build.** Every `build` reads the files it resolves again. Angular's
  disk cache keeps compiler output, and esbuild applies `define` when it bundles.
  `TM_BRAND_RATIOS` has no other reader, and `typeof` of the replaced literal is `'object'`.
- **Parsing.**
  - Commas, mixed whitespace, tabs and newlines, leading dots, `e` exponents and negative origins
    all parse.
  - A missing viewBox, a zero or negative size, or `1e999` (now also rejected by the check) gives
    no ratio. The build then already fails with `brand-file-invalid`, and `serve`, which runs no
    brand check, falls back to `auto`.
  - Brand files are the four fixed `.svg` names, so a raster file cannot occur. An SVG's
    width/height attributes are ignored, which is deviation 4. An image's SVG takes the used box as
    its viewport, and `preserveAspectRatio` applies, so a ratio that differs from those attributes
    letterboxes the image and never distorts it.
- **The box.**
  - `inline-size` is logical, and the link never mirrors, so RTL is the same box at the inline
    start. The chromium-ar run above covers it.
  - The CSS media queries and the `<source media>` both use `(width < 768px)`, so the box and the
    file switch together.
  - Without the variable, the declaration is invalid at computed-value time and falls back to
    `auto`.
  - A failed load keeps the box. Only the broken image's alt text is clipped to it, and the link's
    accessible name is unchanged.
  - A wide wordmark is as wide as it was before (`flex: none` on the tenant bar's link), so no
    breakpoint gains clipping it did not have.
- **The writer's lifetime.** Both shells' frames inject it, in the constructor, before the bar's
  first style pass. It is root-scoped, and `DestroyRef` removes the variables. Writing them through
  the CSSOM needs no `unsafe-inline` under the production CSP. Nothing else writes or clears
  `documentElement.style`.
- **The new e2e tests.** `signInAs` only adds cookies, so the `goto` is a true first visit with no
  service worker, and `complete === false` is a sound precondition.
- **AGENTS.md and PLAN.md §7.1 items 4 and 5.** TSDoc and inline comments are present, and no TSDoc,
  error or test name cites a spec. The test list in the commit matches what I reproduced.

### Findings

**R1-1 (minor): the About dialog's wordmark box has no test.**
`client/projects/core/tellma-core/shell/src/dialogs/tm-about-dialog.ts:56-61` and `:141-145`
rewrote the image's `src` and added the indirection `[style.--tm-about-dialog-wordmark-ratio]` →
`var(--tm-brand-{file})`, but `tm-about-dialog.spec.ts` checks only the `src`.
Failure scenario: a typo in the bound property, in the `--tm-brand-` prefix, or in the theme-to-file
mapping (for example the dark file's ratio under the light theme) reverts the dialog's wordmark to
`auto`, so it is 0 px until its file loads. No test fails.
Fix: in `tm-about-dialog.spec.ts`, provide `TM_SHELL_BRAND_RATIOS` with different light and dark
ratios, and inject `TmShellBrandWriter`, since the spec renders the dialog without a frame. Then
assert the image's box is `[20 x lightRatio, 20]`, switch the theme, and assert
`[20 x darkRatio, 20]`.

**R1-2 (minor): `serve` measures the ratios once, so editing a brand override mid-session leaves
the old box.**
`client/projects/core/tellma-core-tools/src/commands/serve.ts:157` and `:185-186`. The dev server
serves `public/brand/` live, but `--define` is fixed when `ng serve` starts.
Failure scenario: a designer replaces `public/brand/wordmark-on-dark.svg`, changing its shape from
736x208 to 400x200, while `tellma-client serve` runs. The new file letterboxes into a 49.5 px box
until the server restarts, and the page looks like a sizing bug the built app does not have. The
built app cannot go stale, since `build` measures the files on every run.
Fix: watch the four resolved brand files and restart `ng serve` when one changes. At least, say in
the README's `serve` row that a brand file change needs a restart.

**R1-3 (minor): the shared viewBox parse rejects valid SVG number forms.**
`client/projects/core/tellma-core-tools/src/checks/brand.ts:63`. The regex has no leading `+`, no
`e+` exponent, and needs a separator between numbers, so `0 0 7.36e+2 208`, `+0 +0 736 208` and
the compact `-.5-.5 736 208` all fail. SVG's number grammar allows each of them.
The gap predates this change, but `viewBoxSize` now also decides the ratio.
Failure scenario: a distribution's exporter writes `viewBox="0 0 7.36e+2 208"`. `build` fails
with "no valid viewBox, so it cannot scale" on a file that scales. Under `serve`, which runs no
check, the image silently loses its reserved box.
Fix: tokenize with SVG's number pattern, for example
`/[+-]?(?:\d+\.?\d*|\.\d+)(?:e[+-]?\d+)?/gi` over the value after a check that only
numbers, commas and whitespace occur. Require exactly four numbers, and keep the positive,
finite checks. Add the three forms above to `brand.spec.ts`.

### Responses

- **R1-1: fixed in fix1.** `tm-about-dialog.spec.ts` provides `TM_SHELL_BRAND_RATIOS` with
  `wordmark-on-light: 4` and `wordmark-on-dark: 3`, injects `TmShellBrandWriter` (no frame renders
  there), and asserts the image's `src` and box under each theme: 80 x 20 under light, then
  60 x 20 under dark. It restores the theme setting afterwards. A swapped mapping, a wrong
  prefix or a wrong bound property fails it.
- **R1-2: fixed in fix1, by documentation; no restart.** The dev server reads `define` from its
  options once, when `ng serve` starts, and has no way to change it while it runs. A restart from `serve` would need a way to stop the child process, and
  the process seam (`TmProcessRunner.run`) only starts a process and waits for its exit code.
  Changing that seam, adding a file watcher that behaves the same on Windows and Linux, and
  testing the restart is more than a small fix. So the README's `serve` row now says that
  `serve` measures the ratios once, as it starts, and that adding, removing or replacing a file
  in `public/brand/` needs a restart of `serve`. `build` is unaffected. `serve.ts` has the same
  note inline. A watch-and-restart can follow if the dev loop needs it.
- **R1-3: fixed in fix1.** `viewBoxSize` now tokenizes with SVG's number pattern
  (`[+-]?(?:\d+\.?\d*|\.\d+)(?:e[+-]?\d+)?`, case-insensitive). It requires exactly four
  numbers, with only commas and whitespace between them, and keeps the positive and finite
  checks. `brand.spec.ts` reads `0 0 7.36e+2 208`, `+0 +0 736 208` and `-.5-.5 736 208`: each
  passes the check and gives 736/208. It now also rejects three numbers, five numbers, a unit
  (`32px`), a bare `1e` and `1e999`.
