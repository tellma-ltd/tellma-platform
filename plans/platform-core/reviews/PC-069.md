# PC-069: tm-boot.js, boot page, session and launch mark

## Implementer notes

### What was built, and where

All client paths are under `client/projects/core/`.

- **The boot decision** (`tellma-core/src/boot/`): `tmBoot(env)` in `tm-boot.ts`, a pure function
  over `TmBootEnv` (`tm-boot-types.ts`), implementing §4.2 steps 1–4 in order. `tm-boot.script.ts`
  is the generated script's entry: it reads each real global behind a try/catch and stores the
  result on `window.__tmBoot`. `tm-boot-expiry.ts` is the 3c delete over 0025 §2.2's frozen layout
  (open without a version, abort the upgrade at `oldVersion = 0`, delete
  `IDBKeyRange.bound(['u:<sub>/'], ['u:<sub>/\uffff'])`, delete `tm-images-v1`, all raced against a
  1 s box and every failure swallowed). `tm-boot-page.ts` builds the boot page with DOM calls only.
  `tm-boot-result.ts` is the internal `TM_BOOT_RESULT` token that reads `window.__tmBoot` once.
- **The template.** `client/tools/boot/boot-template.mts` bundles `tm-boot.script.ts` with esbuild
  (IIFE, minified, ES2017) behind the banner `var TM_BOOT=/*TM_BOOT*/null;`.
  `client/tools/boot/build-boot-template.mts` writes it to `tellma-core/boot/tm-boot.template.js`
  (generated, gitignored, eslint-ignored), and `client/scripts/build.mjs` runs it before the
  packages build. `ng-package.json` ships it as an asset, and `package.json` exports
  `./boot/tm-boot.template.js` and `./styles/tm-boot-page.css`.
- **Shared plain code** (no Angular imports, bundled by the script and used by the app):
  `src/state/tm-storage-json.ts` (guarded web-storage JSON access and `TmStorageLike`),
  `src/session/tm-profile.ts` (`tmParseProfileCookie`, `tmDecodeProfile`), `src/session/tm-login-mark.ts`
  (the mark, `tmIsLocalPath`, `tmLoginUrl`), `src/state/tm-boot-record.ts` (the boot record and
  `tmIsTenantId`), and `src/state/store/tm-store-layout.ts` with `tm-store-layout-vectors.json`
  (the frozen layout and its vectors: partition keys, 14 documents in IndexedDB order, 3 user
  deletes).
- **Session** (`src/session/`): `TmSession` (profile and state signals, `check()`, `signIn()` with
  step-up parameters, and the mark consumption at first injection), `tmSessionGuard`,
  `TmSessionPaths` (internal; interim tab-local bodies, see below), `TmSessionStatus` (internal
  writable state, so the paths and the session do not import each other) and `TM_SESSION_HOST`
  (internal browser seam: cookie, session storage, address bar, `<html lang>`).
- **Launch** (`src/launch/`): `TmLaunch`, `tmSingleLiveTenant` over the existing
  `launch-landing-vectors.json`, and `TmMembership`/`TmTenantCategory`/`TmTenantState`.
- `src/app/tm-now.ts`: `TM_NOW`, the app clock.
- **Styles:** `tellma-core/styles/tm-boot-page.css` (`.tm-boot-page`, tokens only).
- **§4.1 rules as data and the renderer** (`tellma-core-tools/src/build/`):
  `TM_INDEX_HTML_RULES` and `TM_INDEX_HTML_PROBLEM`, and `tmRenderBootScript(template, config)`,
  which checks the configuration (version, language tags, directions, default offered, string
  tables only for offered languages plus English, only boot keys, every English string present)
  and replaces the marker once, escaping U+2028/U+2029. PC-073 wires both into `build`.
- **C#:** the six `Boot_*` strings in `src/core/Tellma.Core/Resources/Strings.resx` with Arabic and
  Amharic translations, and `test/core/Tellma.Core.Tests/Localization/BootStringsTests.cs`.
- **Public API** (`tellma-core/public-api.ts`): `TM_NOW`, the boot result and config types,
  `TmBootRecord`/`TmBootTheme`, `tmParseProfileCookie`/`TmProfile`, `TmLoginMark`, `TmSession` and
  its option/check/state types, `tmSessionGuard`, `tmSingleLiveTenant`, the membership types and
  `TmLaunch`. `@angular/router` became a peer dependency of `@tellma/core`.

### Deviations

1. **3 KB holds with English strings only.** The template is about 2.85 KB gzip; rendered with the
   platform's English strings it is about 3.05 KB, under 3 KB (3,072 B). Each further language
   adds its strings: English plus Arabic is about 3.37 KB, plus Amharic about 3.70 KB. The test
   asserts the English-only figure. Getting here took deliberate size work (no `?.`/`??` in the
   bundled modules, which ES2017 would lower, shared JSON/storage helpers, reflected DOM
   properties). Spec 0024 §4.2 should say whether 3 KB covers the code with English strings or
   the whole file per distribution.
2. **`__tmBoot.showPage(reason, retry?)`** is added to the result, so the app shows the
   `load-failed` page (§4.3) in the boot language without bundling the page builder.
3. **3c clears the record's `sub` and `lastTenantId` before the delete starts**, not after: a
   delete cut short by the box or a closed tab still leaves a record naming no user, and the
   store's boot step then sweeps.
4. **A path no browser reads as local** (`//host/...`, or with a tab or line break) is treated as
   `/` in 3d and in `signIn()`. `tmIsLocalPath` also refuses tab, CR and LF anywhere.
5. **The profile cookie also needs a non-empty `sh`** (the spec lists only decode, `v` and `sub`):
   the session partition is named by it. A correctly padded value is accepted.
6. **`signIn()` keeps `location.hash` only when `returnUrl` is the current path and query**; a
   fragment belongs to the page it was on. It throws on a non-local `returnUrl` or a malformed
   step-up challenge (empty `acr`, `maxAge` not a non-negative integer).
7. **`check()` updates `profile`** when the same user's cookie carries new details (name, email,
   locale, `sh`).
8. **Interim paths.** `signOut()` is not here (§8.4 needs the tab bus, drafts and store, a later
   checkpoint). `TmSessionPaths.started` is a no-op (no tab bus), `expired` sets `state` to
   `expired` once and emits `tm.session.expired { source }` (no store clean-up, cookie deletion or
   broadcast yet), and `changedUser` emits `tm.session.changed-user` and replaces to `/` (no drafts
   clear or broadcast yet). `TmSession` does not write `boot.patch({ sub })` (the store owns the
   boot record's writer). The full paths replace these bodies, not their call sites.
9. **Language matching** uses the same rule everywhere: exact code, else the same primary subtag
   (for the record, the browser list and the profile locale).
10. **The mark and the record are validated, not rebuilt**, so an extra member written by this
    origin survives (size budget). The profile, which comes from the server, is rebuilt with known
    members only.
11. The renderer refuses a configuration the script would trust blindly (see above); the spec only
    describes the replacement.
12. **`@tellma/core` packaging:** `@angular/router` becomes a peer dependency (the guard and
    `TmLaunch`), and the `"."` entry point's size budget rises from 4.5 to 6.5 KB (measured 4.32
    before, 6.18 after), with the reason in `budgetNotes`.

### Open risks

- The size budget is tight: about 20 bytes of headroom with English strings. Any change to the
  bundled modules (`tm-profile`, `tm-login-mark`, `tm-boot-record`, `tm-storage-json`,
  `tm-store-layout`, `src/boot/*`) moves it; the node test fails first.
- ES2017 is a target, not a guarantee: a browser older than that sees a blank page instead of the
  unsupported page.
- `__tmBoot` holds the profile (name, email) on `window`; it is no more exposed than the cookie it
  came from.
- The session's interim paths do not yet broadcast or clean the store; until the tab bus lands,
  another tab of the same user learns of an expiry only through its own check.

### What reviewers should examine hardest

- `tmIsLocalPath` and every place a URL is built or followed: `tmLoginUrl`, 3d's `returnUrl`,
  the hash-restore `replaceState`, `signIn()`. The hash restore runs only when
  `path + search === mark.returnUrl`, so a stored `returnUrl` can only ever equal a real pathname.
- The mark and record validators (`isLoginMark`, `isBootRecord`) and the profile decoder against
  hostile stored or cookie values.
- The expiry delete: that it never creates `tm-app`, that its key range cannot reach another user
  whose subject starts with the same characters (the `/` after the subject), and that nothing it
  does can throw out of the boot.
- The boot page: DOM calls only, no `innerHTML`, strings set as `textContent`, so a hostile string
  table cannot inject markup (tested).
- The loop guard's window (`0 ≤ now − at < 60 s`) and that a refused mark write still redirects.
