# PC-051: Header navigation, header actions, row-end column

## Implementer notes

Scope: spec 0010 §C.4 (header navigation, `tmGridHeaderEnd`, `button[tmGridHeaderAction]`, the
header hints and Alt+ArrowDown) and §C.14 (the row-end column: `tmGridRowEndHeader`,
`tmGridRowEnd`), on `tm-grid` and, through the shared base and core, `tm-tree-grid`.
`scrollToRow` (§C.8), tree `expandedIds` (§C.9) and the popup editors (§C.15) are later
checkpoints.

### What was built, and where (all under `client/projects/` unless noted)

- **Public surface** (`core/tellma-core-ui/grid/`):
  - `tm-grid-templates.ts`: `TmGridHeaderEndDef` (`ng-template[tmGridHeaderEnd]`, context
    `TmGridHeaderEndContext` with `$implicit` header text, `key` and `sort`),
    `TmGridRowEndHeaderDef` and `TmGridRowEndDef<T>` (context `TmGridRowEndContext<T>`: `$implicit`
    row and `rowId`), each with a context guard.
  - `tm-grid-header-action.ts/.css`: `TmGridHeaderAction` on `button[tmGridHeaderAction]`. It is
    24 × 24 (`--grid-header-action-size`), has `tabindex="-1"` and `type="button"` unless one is
    authored, and an `active` input. That input gives the accent ink and an "Active" accessible
    description, added through the CDK `AriaDescriber` so it merges with other descriptions.
    In dev mode, an icon-only button with no name gets a warning.
  - `tm-grid-column.ts` gains `headerEndDef`. `tm-grid-base.ts` gains `rowEndHeaderDef` and
    `rowEndDef`.
  - Tokens:
    - `grid.headerActionSize` is 24px. It is an extra token; see deviation 3.
    - `grid.rowEndWidth` is 36px.
    - The Identity app's `tokens.css` is regenerated with both tokens.
  - Strings:
    - `grid.headerNavHint`, an ICU string with `filter` and `filterKeys`.
    - `grid.headerActionHint` and `grid.headerActionActive`.
    - `grid.keys.headerAction`.
    - English and Arabic both have all of them.
- **Key map** (`grid/internal/grid-keymap.ts`):
  - Header bindings:
    - arrows, Home and End;
    - Enter and Space activate;
    - Alt+ArrowDown runs `headerAction`;
    - Escape and Mod+F keep their row meanings.
  - `tmResolveHeaderKey` resolves header keys, matching the table's header row (Alt+ArrowDown)
    through `tmKeysMatch`. Chords, Tab and typing go to the page. The rows' resolver
    (`tmResolveGridKey`) has no header path: its context has no header flag.
  - In `TM_GRID_KEYS`, Alt+ArrowDown is listed twice: open the dropdown in cells, and run the action
    on headers (deviation 8).
- **Core** (`grid/internal/grid-core.ts`):
  - **Header navigation.** It is on when any header has a sort, an action, or a row-end header.
    - The slots are select-all, the data columns, then the row-end header.
    - The roving tabindex comes from `headerTabStop` and `headerTabIndex`.
    - ArrowUp from row 0 enters the header in the same column; ArrowDown returns.
    - Left and right are mapped through the reading direction and clamp.
    - Enter and Space sort, toggle select-all, or click the first action. On a header without a
      sort, they click the action. On a header with neither, they reach its first interactive
      content: a form field takes focus, and anything else is clicked.
    - A form field in a header keeps every key except a bare Escape, which returns to its header.
    - Alt+ArrowDown clicks the action.
    - Focus inside a header action counts as header focus (`trackHeaderFocus`), so a popover that
      closes back onto its button continues header navigation.
    - A grid with no rows keeps its tab stop on the first header, so header actions stay reachable
      over the empty state.
    - The single-tab-stop pass also neutralizes interactive header content while the header row
      navigates.
  - **Row-end column.**
    - It adds a track (`var(--grid-row-end-width)`) and one to `aria-colcount`.
    - It is never an engine column, so selection, copy, find, resize and the state store never see
      it.
    - **Keyboard.** End reaches the cell, and so does the inline-end arrow from the last data
      column. Vertical moves keep it. The inline-start arrow returns to the data cells. Enter and
      F2 reach the cell's link or button. Edit, clear, fill-down, the boolean toggle and
      column-select keys do nothing there.
    - **Pointer.** Clicks, taps, a right-click and a long-press treat it as its row's last data
      cell, minus range extension (deviation 6); a cell with a row-end template holds the ring
      itself. An empty cell activates its row.
    - **Selection paint.** While every data cell of its row paints the range fill, so does the
      row-end cell (`endSelected` on the row view model). It is paint only: the cell never takes
      `aria-selected`.
    - **Clipboard.** Copy, cut and paste are ignored while it is active (deviation 5).
    - **Find.** Matches never land on it.
    - **Reveal.** `revealInline` keeps a data cell clear of the sticky column.
- **View**:
  - The template stays inline in `grid-view.ts`.
  - `grid-view.css` gains the header focus rings, the header-end slot, the label clamps and the
    rows' `min-content` floor. It compiles to 13.35 kB, under the 13.5 kB `anyComponentStyle`
    error (it was already over the 12 kB warning, at 13.07). The room came from folding rules
    that said the same thing: the row checkbox and the boolean glyph share their box, checked
    fill and masked check; the column-header, row-header and cell selection tints share one
    rule; and two forced-colors border rules merged.
  - `grid-end-cell.ts/.css` is the new internal `ɵTmGridEndCell`. It is the row-end header or
    body cell: it binds its own role, indexes, tab stop and active and selected classes, paints
    the row's band over an opaque surface, and shows the hairline only while content scrolls
    under it. The view measures that in `endOverlap`.
  - The header hints render from `core.headerHints()`; `headerHintIds` picks one hint per column.
- **Testing harness** (`core/tellma-core-ui-testing/grid-harness.ts`): header-focus and row-end
  helpers.
- **Docs and showcase:**
  - `tm-grid.examples.ts` has a new `HeaderFiltersAndColumnEditor` example, and
    `docs-examples.spec.ts` has its markers.
  - The showcase `grid-search-page-story.ts` lays its readouts out two to a line, so the grid's
    lower rows stay on screen. It gains:
    - a region filter (a select in a popover);
    - a manager filter (a contains-input), on a filter-only column;
    - a column editor in the row-end header;
    - an empty state with a clear-filters button;
    - readouts.

### Deviations

1. `TmGridHeaderAction` is a `@Component`, not the spec's `@Directive`, so it can carry its
   styles. Emulated encapsulation would not reach a consumer's projected button otherwise. The
   selector and the inputs are as specified.
2. Select-all takes both Enter and Space, as §C.4's key table says. §C.5 names only Space and the
   click.
3. There is an extra token, `--grid-header-action-size` (24px), for the action's square target.
4. When only `tmGridRowEnd` is declared, the empty row-end header is `aria-hidden` and not a header
   stop.
5. Copy, cut and paste are ignored while the row-end cell is active, and the context menu's
   clipboard items are disabled then; the column never takes part in the clipboard. The ring
   stands for a lone cell: a selection grown from it (Mod+A, Shift+Space, a drag) returns it to
   the data cell, where the keys and the menu act on the selection.
6. A Shift or Mod press on a row-end cell acts as a plain press. It is never part of a range.
7. The row-end cells are an internal `tm-grid-end-cell` component, not plain markup in the grid
   view. Kept on its own merits after review 1: the column's sticky layering, band repainting,
   roles, indexes and tab stop live in one place, as the find bar's and the touch handles' do,
   and its stylesheet stays out of `grid-view.css`, which is close to its error budget.
8. Alt+ArrowDown appears twice in `TM_GRID_KEYS`: `openDropdown` in cells and `headerAction` on
   headers. Each entry is labelled for its context.
9. Withdrawn in review 1: the template is back inline in `grid-view.ts` with its comments.
10. Withdrawn in review 1: the row-end cell paints the selection fill too.
11. The size gate moved to the linked production measure, and every ceiling was re-baselined (see
    the budget section).
12. A header holding an active `tmGridHeaderAction` is described "Active" as well as the button
    (§C.4 names the button only): header navigation focuses the header cell, never the button.
    The action reports its state through an internal token the header templates' injector
    provides.

### Open risks

- `grid-view.css` compiled to 13.58 kB once merged with platform-core's forced-colors grid rules,
  over the 13.5 kB error. The header row's rules (the sticky header, its cells' focus ring, the
  sort indicator and the header-end slot) now live in `grid-header.css`, which the view loads
  before `grid-view.css`, so the cascade order is unchanged. Both sheets sit under the 12 kB
  warning.
- **Header focus tracking.** It relies on `focusin` and on `inOverlay`. A consumer popover that
  renders outside the CDK overlay container would not be recognized as an overlay.
- **The row-end hairline.** It is measured from the header geometry: is the last data header's
  inline end past the row-end header's inline start? It is re-measured on scroll, on resize (the
  scroller and the header row) and when the columns change. A layout change that does none of
  those would leave it stale until the next scroll. Scroll metrics were the first approach and
  failed in headless Chromium: a hidden scrollbar keeps its gutter in `clientWidth` but not in
  the scrollport, so the far end never reached zero.

**Deviations (1) and (2), judged.** Neither is a finding.
- **(1) `TmGridHeaderAction` as a component.** Accepted.

    `button[...]`, so nothing collides with it.
  - The costs: the public kind becomes `ɵcmp`, and a consumer can no longer put another component
    on the same button.
  - §C.4's sketch needs amending to match.
- **(2) Select-all on Enter and Space.** This follows §C.4's own key table ("Enter or Space …
  toggles select-all on its header"). §C.5's list of toggles is not exclusive, so it is not a
  deviation at all.

**Measurements (KB gzip, ./grid):**

| Measure | Parent (4fb84e2) | This commit | Delta |
|---|---|---|---|
| The gate's own method: the unlinked FESM through esbuild | 39.01 | 43.27 | +4.26 |
| The same, with every `ɵɵngDeclareClassMetadata` call removed | 37.29 | 41.23 | +3.94 |
| Linked by the Angular linker, with `ngDevMode=false` (what an app ships) | 35.58 | 39.98 | +4.40 |

**Why the template and styles ship twice.** The cause is not another entry point, a chunk or the
import graph. ./grid's FESM pulls in no other entry point's code: each sibling is an external
`@tellma/*` import, and every component selector appears once in a definition. ng-packagr's
partial compilation writes each component's decorator arguments, template and styles included,
twice into the same module: once in `ɵɵngDeclareComponent` and once more in
`ɵɵngDeclareClassMetadata`. No shared chunk or other import graph removes the second copy. The
app's Angular linker turns it into `ɵsetClassMetadata` behind an `ngDevMode` guard, and a
production build drops it.
- A probe confirms this. `.tm-grid__hdrend` appears twice in the gate's output and once in the
  linked output. The template comment "The row-end header." appears twice and zero times.
- So the duplicate is an artifact of how the gate measures, and nobody downloads it. It does not
  hide a duplicated module.
- The real cost is still about 4 KB on every measure (+3.94 to +4.40), against the 2.99 that
  D-057 and D-060 leave for §C.4, §C.8, §C.9 and §C.14 together.

### Findings

**R1-1 (blocking): ./grid's ceiling is raised to 43.5 against D-057 ruling 2 and spec §C.11, and
removing the duplicate does not bring it back under**
- **Where.** `client/projects/core/tellma-core-ui/package.json:50` (the ceiling) and `:84` (the
  note).
- **The rule broken.** D-057 ruling 2 says: no further ./grid raise without a re-split or real
  savings. This commit raises the ceiling and leaves the ruling to the orchestrator.
- **Measured.** The table above.
- **Would de-duplicating fix it? No.**
  - On the de-duplicated measure, ./grid is 41.23, under the spec's 42. But that measure also
    lowers the parent to 37.29. The same 2.99 allowance then ends at 40.28, and this commit alone
    overruns it by 0.95.
  - On the linked measure, it overruns by 1.41 (35.58 + 2.99 = 38.57, against 39.98).
  - On the gate's own measure, it overruns by 1.27.
  - On every measure, PC-054 (§C.8, §C.9) is left a negative budget.
- **The duplicate makes the gate fragile.**
  - Gzip folds the metadata copy only while it lies within 32 K of the first copy.
  - The first cut's 49.76 was this artifact. So is the open risk the notes give PC-054: about 1 K
    more of template or CSS costs about 5 KB on the gate, though nothing in the shipped app
    changes.
  - Deviations 7 and 9 were shaped to fit this artifact: the `ɵTmGridEndCell` component, the
    template file and the comments moved into TSDoc.
- **Inaccurate text.** The budget note (`package.json:84`) and `ɵTmGridEndCell`'s TSDoc
  (`grid-end-cell.ts:17-19`) both say the bundle carries the template and styles twice. That is
  true of the published FESM only, not of anything a user downloads.
- **Suggested fix. The orchestrator rules on each of these:**
  1. Make `scripts/bundle-size.mjs` measure the linked output: run
     `@angular/compiler-cli/linker/babel` over each FESM with `ngDevMode=false` (the probe
     script shows how), or at least strip `ɵɵngDeclareClassMetadata`. Re-baseline every ceiling
     in the same change. That removes the 32 K cliff before PC-054 meets it.
  2. Per D-057, find about 1.3 KB of real savings, or a re-split, before any raise. Candidates
     that a list grid rarely needs on first paint:
     - the find bar and its scan, opened only by Mod+F, loaded on demand as `./grid-editing` is;
     - the coarse-pointer touch handles, loaded only when `coarsePointer()`;
     - the paste parse and label resolution, run after the synchronous `clipboardData` read.
  3. Correct the two "carries twice" texts.

**R1-2 (major): a right-click or long-press on a row-end cell does not select its row, so the
context menu acts on whatever was selected before**
- **Where.** `grid/internal/grid-core.ts:3068`.
  - `selectMenuTarget` matches only `[data-tm-cell]`.
  - A right-button pointerdown never reaches the cell code, because `onPointerDown` returns at
    `:2583` when `button !== 0`.
  - So the press on a row-end cell that is not on a link changes nothing.
- **Failure scenario.**
  1. In an editable grid with a `tmGridRowEnd` template, the active cell is in row 3.
  2. The user right-clicks the row-end cell of row 7, either its empty space or its button, or
     long-presses it on touch.
  3. The menu opens at the pointer. Its Delete rows, Cut and Copy act on row 3, and closing the
     menu returns focus to row 3.
- The commit message says "Clicks, taps and the context menu treat it as its row", and no test
  covers it.
- **Suggested fix.**
  - Match `[data-tm-cell], [data-tm-endcell]` in `selectMenuTarget`.
  - Set `rowEndFocusSignal` from `isRowEndCell` there.
  - Add unit tests for a right-click and a long-press on a row-end cell, both with and without a
    `tmGridRowEnd` template.

**R1-3 (minor): the row-end cell does not paint the "selected" state that §C.14 lists
(deviation 10)**
- **Where.** `grid/internal/grid-end-cell.css:36-62` and `grid/internal/grid-core.ts:3897`.
- **The spec.** §C.14 says the cells paint "the zebra, selected, checked and active states, so a
  row reads as one band".
- **Failure scenario.** A whole-row selection (a row-header press, Shift+Space, Mod+A) fills every
  data cell, but the row-end cell shows the zebra or plain band. The band breaks in exactly the
  case the rule is for.
- "It is never part of a range" justifies keeping the cell out of copy. It does not justify
  dropping the paint.
- **Suggested fix.**
  - Add a row-level flag to `ɵTmGridRowVm`: every data column of the row is selected.
  - Tint the cell with the selection fill when it is set.
  - Or get a ruling that narrows §C.14.

**R1-4 (minor): turning header navigation on strands interactive header content that is not a
`tmGridHeaderAction`**
- **Where.** `grid/internal/grid-core.ts:5917`: the single-tab-stop pass now covers
  `[role="columnheader"]`. Also `:2321`/`:2332`: `activateHeader` and `clickHeaderAction` look
  only for `.tm-grid-header-action`.
- **Failure scenario.**
  1. A grid has one `sortable` column, and another column whose `*tmGridHeader` template holds a
     help button or link.
  2. Before this commit, that control was in the Tab order. Now it gets `tabindex="-1"`.
  3. Enter on its header does nothing (no sort, no action), and Alt+ArrowDown finds nothing. A
     keyboard user cannot reach it at all.
- The done-when protects only grids with no sortable or action columns.
- **Suggested fix.**
  - Let Enter on a header with neither a sort nor an action focus or click the header's first
    interactive content.
  - Or leave the content of such headers out of the neutralizing pass.
  - Flag the gap in §C.4's table to the orchestrator.

**R1-5 (minor): a second, dead header path in `tmResolveGridKey`**
- **Where.** `grid/internal/grid-keymap.ts:45` (`TmGridKeyContext.header`), `:308-309` and
  `:348-350`.
- **The problem.**
  - No production caller ever passes `header`. Header keys go through `tmResolveHeaderKey` from
    `onHeaderKeydown`, and only `grid-keymap.spec.ts:126` exercises the branch.
  - It is dead bytes in an entry point over its ceiling.
  - It is also a second resolver path that can drift: `tmResolveHeaderKey` hard-codes
    Alt+ArrowDown apart from the binding table, though the table is meant to be the source of
    truth.
- **Suggested fix.** Remove `header` from `TmGridKeyContext` and the ArrowDown branch, keeping
  the table row for the published key list. Alternatively, have `tmResolveHeaderKey` match that
  row through `tmKeysMatch`.

**R1-6 (minor): a spec reference in TSDoc**

- PLAN §7.1 item 5 bars spec and § references in TSDoc.
- **Suggested fix.** Drop the reference, or move it to an inline `//` comment.

**R1-7 (minor): a second view stylesheet that gets around the `anyComponentStyle` error

- **Where.** `grid/internal/grid-view-header-nav.css:8-11`. Its own words: "A sheet of its own so

  - `grid-view.css` already sits at 13.07 kB, over the 12 kB warning, against the 13.5 kB error.

**R1-8 (minor): test gaps for rules this commit claims**

**R2-5 (minor, accessibility): a header action's "Active" state is never announced on the keyboard

**R2-6 (minor): R1-4's Enter on a header's content clicks a non-field control without focusing it**
- **Where.** `grid/internal/grid-core.ts:2358-2366`.
- **The rule.** `activateHeaderContent` focuses only `input, select, textarea`. Anything else that
  `INTERACTIVE_CONTENT_SELECTOR` (`:209`) matches is `.click()`ed, with focus left on the header
  slot.
- **Failure scenario.** A header template holds a `tm-select`, whose trigger is a
  `div[ngCombobox][tabindex]` with an activedescendant listbox (`select/tm-select.ts:69-109`).
  1. Enter opens its panel, but focus stays on the header cell.
  2. ArrowDown then leaves the header for row 1, and the panel stays open with no keyboard owner.
  3. The single-tab-stop pass has already set the trigger's tabindex to -1, so Tab cannot reach
     it either.
- **The same gap elsewhere.** A `[contenteditable]` without a tabindex is not matched at all,
  though `headerSlotOf` treats it as a field.
- **Suggested fix.** Mirror the body's `activateCellLink` (`:5014-5029`): click only
  `a[href], button`, and `focus()` everything else. Add `[contenteditable]` to the candidate
  selector.

**R2-7 (minor): Escape that cancels an IME composition in a header field also leaves the field**
- **Where.** `grid/internal/grid-core.ts:2200-2208`. The bare-Escape branch has no
  `isComposing`/`keyCode === 229` guard. The body path has one (`:2092-2093`), but the header
  branch returns before it.
- **Failure scenario.** In Firefox, which reports `key: 'Escape'` with `isComposing: true`, the
  user is composing Japanese in a header's inline filter input and presses Escape to cancel the
  candidate. The grid moves focus to the header cell and calls `preventDefault`, so the
  composition is cut off and the field loses focus.
- **Suggested fix.** Return early from the field branch when `event.isComposing ||
  keyCode === 229`. Add a unit test.
