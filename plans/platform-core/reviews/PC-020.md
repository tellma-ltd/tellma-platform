# PC-020: Status and identity indicators

## Implementer notes

### What was built, and where

All paths are under `client/` unless stated. Seven new entry points in
`projects/core/tellma-core-ui/`, each with `ng-package.json`, `public-api.ts`, co-located
`*.examples.ts`, unit/harness specs, a budget, an API golden (`api/core-ui.<ep>.api.md`) and a
showcase story with the entry point's id.

- **`badge`**: `TmBadge` (`tone`, `icon`, `dot`; six tones; status tones tint the pill and keep
  body ink, `accent` is solid) and `TmCounter` (`value`, `max`, `tone`, `placement`, `showZero`;
  `dir="ltr"`, tabular digits, reserves two digits inline, `aria-hidden` and 16 px with a halo when
  overlaid; empty renders `display: none`; overflow through `counter.overflow` with `max`
  pre-formatted by `TmL10n.formatNumber`). Harness `TmCounterHarness`.
- **`avatar`**: `tm-initials.ts` (`tmInitials` with `Intl.Segmenter` graphemes, a per-locale
  segmenter cache and a malformed-locale fallback; `tmAvatarTone`, FNV-1a), `TmAvatar` (`name`,
  `src`, `etag`, `colorKey`, `size`, `decorative`): a `tm-image shape="circle" placeholderOnError`
  whose placeholder is the face (initials or the Lucide `User` glyph); without `src` the face alone.
  Host carries `data-size`/`data-tone`, `role="img"` + `aria-label` when named. A forced-colours
  edge is a transparent 1 px `::after` ring. Harness `TmAvatarHarness`.
- **`progress`**: `TmProgressBar` (`value`, `label`, `labelledBy`, `tone`, `active`): the hold
  stamps `TM_NOW` when the bar appears and, when `active` turns false, keeps it for the rest of
  `--progress-min-visible` (read from computed style, 250 ms fallback); a hidden bar is
  `display: none` with no role. Determinate fill from inline-start, no transition; the sweep
  travels the track with container units (`100cqi`) and has mirrored RTL keyframes.
  `TmProgressRing` (`value`, `diameter`, `decorative`): CSS-geometry SVG (`r: calc(50% -
  stroke/2)`), `pathLength="100"` dash, quarter-arc spin for `null`, hidden arc at 0; not decorative
  it is a progressbar named by the consumer's `aria-label` (dev warning when unnamed). Harness
  `TmProgressBarHarness`.
- **`skeleton`**: `TmSkeleton` (`shape`, `width`, `height`, `lines`, `columns`), `aria-hidden`,
  static. Table rows take `--grid-row-height[-sm|-lg]` for `TM_FORM_FIELD_DEFAULTS.size` (the grid's
  own default), header row in the grid's header colours.
- **`relative-time`**: `internal/minute-ticker.ts` (`TmMinuteTicker`, root, not exported): one
  `setTimeout` to the next minute boundary of `TM_NOW`, armed only while some instance subscribes
  and the page is visible; `visibilitychange` to hidden disarms, to visible ticks at once and
  re-arms. `TmRelativeTime` (`value`, `textStyle`): `<time datetime>` with `tmTooltip` showing
  `formatDateTime(value, { dateStyle: 'medium' })`; the text is a `computed` over the tick and a
  fresh `TM_NOW()` reading. Harness `TmRelativeTimeHarness` (reads the absolute text through the
  tooltip description).
- **`copy`**: `TmCopyButton` (`text`, `label`, `showLabel`, `size`, `copied`): a ghost `tmButton`,
  square icon-only with a tooltip by default; labelled, both labels share a grid cell so the width
  is fixed. A string is written with `writeText` in the click; a builder's promise goes to
  `clipboard.write` as a pending `ClipboardItem` (keeps the click's activation), else
  `writeText` after it resolves. Any refusal or synchronous throw brings up the manual fallback: a
  transparent read-only input over the button, focused with the text selected, named "Press
  Ctrl+C to copy" (`tmKeysText('Mod+C')`), with its own `ɵTmTooltipController` shown at once and
  a registration on the shared Escape stack above it; its `copy` event counts as success (focus
  returns to the button after the event), blur or Escape takes it down. A persistent visually
  hidden `role="status"` says "Copied" for 2 s. `TmReference` (`value`, `label`): label, a sunken
  mono `dir="ltr"` ellipsized chip, and an icon-only "Copy reference" button copying the full
  value. Harnesses `TmCopyButtonHarness`, `TmReferenceHarness`.
- **`empty-state`**: `TmEmptyState` (`heading`, `icon`, `tone`, `size`, `live`): centred column
  of icon, heading (`<p>`), detail (default slot) and actions (`[tmEmptyStateActions]` slot);
  empty slots collapse; `live="polite"` renders `role="status"` populated a microtask after
  insertion (as `tm-alert` does); `page` grows into the remaining height. Harness
  `TmEmptyStateHarness`.
- **Tooltip.** `ɵTmTooltipController.show()` (public on the `@internal` controller, so absent from
  the golden), used by the copy fallback.
- **Tokens** (`core-ui-tokens/presets/tellma-default.ts`): groups `avatar`, `badge`, `counter`,
  `emptyState`, `progress`, `skeleton`, colours on semantic roles only. `tokens.spec.ts` pins the
  emitted names and a 4.5:1 contrast check, both schemes, for the avatar accent pair, the three
  counter fills and the badge accent pair. Tokens README lists `--counter-halo` as consumer-settable.
  The identity server's `src/apps/Tellma.Identity/wwwroot/css/tokens.css` is regenerated.
- **Strings**: `copy.copy|copied|manual`, `reference.label|copy`, `counter.overflow` in English
  and Arabic (gendered imperatives through `{gender, select}`).
- **Docs/packaging**: core-ui README (entry-point rows; the inline-host convention now lists the
  new `inline-flex` hosts and `tm-relative-time`'s `inline`), core-ui-testing exports and README,
  budgets
  with `budgetNotes`, `docs-examples.spec.ts` (imports, placeholder template, suites, the icons the
  examples draw).
- **Showcase**: stories `badge`, `avatar`, `progress`, `skeleton`, `relative-time`, `copy`,
  `empty-state`; icons `inbox`, `search-x`, `circle-x` registered.
- **E2E** (`e2e/specs/`): `badge.spec.ts`, `avatar.spec.ts`, `progress.spec.ts`,
  `skeleton.spec.ts`, `relative-time.spec.ts`, `copy.spec.ts`, `empty-state.spec.ts`: axe in light
  and dark × LTR and RTL for every story (avatars in all eight tones, the copied state, the
  announced empty state); counter 9 → 10 and copy success bounding boxes; the copy fallback with
  `clipboard-write` denied through CDP (Chromium only, under the clipboard lock), keyboard copy and
  Escape; sweep and ring static under reduced motion; avatar edge and counter tone under forced
  colours; the hold and the minute ticks under `page.clock`, and no tick while hidden.

### Deviations (also in the commit message)

1. `TmRelativeTime`'s wording input is `textStyle`, not `style`: Angular routes a `style`
   attribute or `[style]` binding to the element's styling, so an input named `style` never
   receives a value (verified: both forms left the input at its default).
2. `TmSkeleton.lines` is `number | undefined`: the spec gives it two defaults (1 bar for `line`, 8
   rows for `table`), which one `InputSignal<number>` cannot express.
3. A lone `line` bar keeps the full width; the last-line 60 % applies from two lines up (a
   paragraph's last line).
4. `counter.overflow` stays "{max}+" and `max` is passed formatted by `TmL10n.formatNumber`: the
   in-house ICU interpreter (D-023) prints a bare `{max}` with `String()`, so locale digits need
   either a `{max, number}` key or a pre-formatted argument; the spec's key text is kept.
5. Budgets above the spec's §1 figures, each with a `budgetNotes` entry (as set after review 1,
   measured plus about 0.1 KB): avatar 2.75 (measured 2.63), badge 2.2 (2.08), copy 3.3 (3.20),
   empty-state 1.4 (1.30), progress 2.7 (2.56), relative-time 1.35 (1.21), skeleton 1.65 (1.53).
   Four entry points hold two components where the spec budgeted one; see R1-3 for the savings
   taken.
6. Badge text is body ink on every status tint (status ink on its own tint is under 4.5:1 for
   success, warning and info); the tone is the tint, border and dot/icon ink.
7. Reduced motion: the indeterminate bar and ring draw the full track/ring at half strength rather
   than a static partial segment, which would read as a determinate share.
8. `ɵTmTooltipController` gains a public `show()`; the copy fallback needs a tooltip shown on a
   programmatic focus, which the focus path only does for `:focus-visible`.
9. The copy fallback's Escape goes through the shared Escape stack (pushed above its tooltip), so
   one press returns focus to the button; a template `keydown.escape` never fired because the
   tooltip's stack listener captures the first Escape.
10. `tmInitials` elaborations the spec leaves open: words with no letter or digit are skipped;
    digits count as script-neutral ("3M Group" → "3G"); a name whose first or last word is in an
    uncased script gives one grapheme (never a mixed-script pair); a blank name is unnamed
    (`aria-hidden`) as well as glyph-drawn.
11. `TmProgressRing` has no label input: not decorative, it is named by the consumer's
    `aria-label`/`aria-labelledby`, with a dev-mode warning when missing.

### Open risks

- The copy fallback e2e denies `clipboard-write` through CDP `Browser.setPermission`; it is
  Chromium-only and skipped elsewhere. Firefox/WebKit fallback behaviour is covered only by the
  unit spec's rejected `writeText`.
- `TmProgressBar`'s hold relies on a component `effect` writing `holding` in the same change
  detection pass that `active` turns false; host bindings evaluated earlier in the pass re-run in
  the same tick (no paint between), which the fake-timer specs and the e2e hold spec cover.
- The inline counter's two-digit reservation rounds up to a whole pixel with CSS `round()`
  (Chromium 125, Firefox 118, Safari 15.4): without it, sub-pixel text snapping let "10" overshoot
  "9"'s box by 1/64 px. An engine without `round()` drops the declaration and the counter then
  grows with its digits.
- Relative-time text changes on wall-clock minute boundaries, so a text can be up to a minute
  behind its exact age (by design: one shared ticker).
- The avatar's photo request size comes from a TS map pinned to the `--avatar-size-*` tokens by a
  unit test; a theme that overrides the size tokens gets a mismatched rendition request.

### What reviewers should examine hardest

- `copy/tm-copy-button.ts`: the clipboard paths (string, builder string, builder promise with and
  without `ClipboardItem`, synchronous throws), the fallback's focus/selection/tooltip/Escape
  lifecycle and its teardown on destroy.
- `progress/tm-progress-bar.ts`: the hold's effect and `shownSince` bookkeeping across rapid
  toggles.
- `relative-time/internal/minute-ticker.ts`: subscribe/unsubscribe idempotence, visibility
  handling, and that no timer survives the last instance.
- `avatar/tm-initials.ts`: grapheme and case rules across scripts.
- The forced-colours and reduced-motion CSS in badge, avatar and progress.

### Findings

**R1-1 (major) — an overlay counter sits on the wrong corner in RTL.**
`client/projects/core/tellma-core-ui/badge/tm-counter.ts:45` puts `dir="ltr"` on the host, and
`badge/tm-counter.css:68` positions the overlay with `inset-inline-end`. Logical inset properties
resolve against the element's own direction, so the host's `ltr` turns `inset-inline-end` into
`right` in every direction. Measured in the showcase at `?dir=rtl`: the overlay button spans
x 991–1031 and its counter x 1017.7–1034, i.e. the physical right corner, which is the inline-start
corner in Arabic (a bare-HTML control without `dir="ltr"` lands on the left, as it should). Spec §4.1
says "the parent's block-start, inline-end corner"; every app-bar badge (spec 0028 §5.2) would sit on
the wrong side in Arabic. `e2e/specs/badge.spec.ts:60` checks the corner in LTR only, so nothing
catches it. Fix: keep the host in the inherited direction and isolate only the digits, e.g. render
`<span dir="ltr">{{ text() }}</span>` (or `unicode-bidi: isolate; direction: ltr` on an inner span)
and move the `dir` assertion in the e2e and unit spec to that span; add the overlay-corner test in
both directions (in RTL the counter overhangs the button's left edge).

**R1-2 (major) — badge labels clip their descenders, and Arabic letters lose their dots.**
`badge/tm-badge.css:37` sets `line-height: 1` on the host and `badge/tm-badge.css:92` sets
`overflow: hidden` on `.tm-badge__label` (for the ellipsis). The label's box is then 11 px tall while
its glyphs need 13 px (`scrollHeight` 13 vs `clientHeight` 11, measured for Latin and Arabic in
Noto Sans/Noto Sans Arabic). Screenshots at 4× show "Typing quietly gjpqy" with every descender cut
at the baseline, and "قيد المراجعة يجب" with the dots under ي, ج and ب removed, which changes which
letters are read (it renders like "ىحب"). The story's own "warning" badge already loses its g's
descender. axe does not detect clipping. Fix: give the label a line box that holds the font's
content area (e.g. `line-height: normal` on `.tm-badge__label`, still centred by the host's
`align-items: center` inside the 18 px content box), or clip only the inline axis
(`overflow-x: clip; overflow-y: visible`, which `text-overflow: ellipsis` accepts). Add a check that
an Arabic label with below-dots and a Latin label with descenders have
`scrollHeight <= clientHeight`. Check `tm-counter` and the avatar face too, which also use
`line-height: 1`, though neither clips today.

**R1-3 (major) — the seven raised budgets do not meet D-031's conditions.**
`client/projects/core/tellma-core-ui/package.json:30-36` and the notes at `:78-84` raise all seven
ceilings above §1 (8 KB in total by the spec, 15.5 KB as set). D-031 allows a raise only after
honest savings in the touched code, with a note that names the bytes and **the savings taken**.
D-042 applied the same rule at birth for ./menu ("the budget note must list the savings taken").
None of the seven notes names a saving taken or an alternative measured. Several notes also lean on
a claim the measurement does not support. The avatar note says the duplicated templates and styles
in the class metadata are "about a third of the weight". Stripping every
`ɵɵngDeclareClassMetadata` call and re-measuring the same way `bundle-size.mjs` does gives:

| Entry point | With metadata (KB) | Without (KB) | Share |
|---|---|---|---|
| avatar | 2.63 | 2.40 | 9% |
| badge | 2.17 | 1.86 | 14% |
| copy | 3.16 | 2.88 | 9% |
| empty-state | 1.32 | 1.13 | 14% |
| progress | 2.60 | 2.24 | 14% |
| relative-time | 1.21 | 1.07 | 12% |
| skeleton | 1.58 | 1.36 | 14% |

gzip folds most of the second copy. Some of these entry points (badge, avatar) are likely eager in
the shell and count toward spec 0024's initial-JS budget, so this matters beyond the gate.
Candidate savings to try and report:

- One `[attr.data-tone]` host binding, matched by attribute selectors, in place of six tone-class
  bindings on `tm-badge`, and the same for `tm-counter` and `tm-progress-bar` (as `tm-avatar`
  already does).
- In `tm-copy-button`, a single `<button>` whose `aria-label`, tooltip and inner label vary by
  binding, instead of two near-identical button templates (the template ships twice).
- Shorter dev-only text where it is not public API.

Fix: take what these yield. Rewrite each note with the measured feature weight, the savings taken
and the options measured and not taken. Correct or drop the "about a third" claim. Then put the
seven raises to the orchestrator as a D-031/D-019-style ruling, since §1 is now off by roughly 2×.

**R1-4 (minor) — the warning progress fill fails non-text contrast against its track in light.**
`progress/tm-progress-bar.css:31-32` fills the warning tone with `--warning` (#B7791F) over
`--progress-track` (`--border-default`, grey-200). Computed from the regenerated `tokens.css`, that is
2.45:1 in light, below WCAG 1.4.11's 3:1 for the part that shows the share. Accent 3.86, success 3.37,
error 3.67; in dark every tone is 3.29 or more. The token comment ("reads at 3:1 against the page")
only covers the accent against the card. Fix: point the warning fill at a darker warning role that
reaches 3:1 against the track in both schemes. Add the four fill/track pairs to the `tokens.spec.ts`
contrast test at ≥3:1, next to the counter pairs.

**R1-5 (minor) — a copy that settles after the button is destroyed still emits and arms timers.**
`copy/tm-copy-button.ts:246` and `:263` settle the clipboard promise with no destroyed check.
`succeed()` (`:273-277`) then sets a 2 s timer and calls `copied.emit()` on a destroyed
`OutputEmitterRef`, which logs Angular's "Unexpected emit for destroyed OutputRef" warning in
development. A rejection instead sets `manualText` on a dead view. `onManualCopy`'s `setTimeout`
(`:290`) is never cleared either. A realistic path is an error dialog's `tm-reference` copied just
before the dialog closes. Fix: keep a `destroyed` flag set in the existing `onDestroy` and return
early from `succeed`, `fallBack` and the manual-copy timeout (and clear that timeout there).

**R1-6 (minor) — the copy paths the notes flag as riskiest have no test, and one story state has no
axe run.**
`copy/tm-copy-button.spec.ts` covers the string write, a rejected `writeText`, a builder string and a
builder promise whose `clipboard.write` resolves. It does not cover:

- a rejected `clipboard.write` with a builder promise (`fallBackLater`, which must show the fallback
  only once the promise resolves);
- the no-`ClipboardItem` path (`:253`);
- a synchronous throw from `writeText` or `write` (`:247-249`, `:267-268`);
- a builder that throws (`:224-226`, which must not fall back).

Breaking any of these branches leaves the suite green. Spec §12 also asks for axe on every story
state, and `e2e/specs/copy.spec.ts` never runs `expectNoAxeViolations` with the manual fallback up:
the focused, transparent read-only input with its tooltip. Fix: add the four unit cases, and an axe
call in the fallback test after the input is focused.
