# PC-119: Generic entity picker binding, tm-entity-field and tm-entity-multi-field

## Implementer notes

### What was built, and where

All client, in `client/projects/core/`:

- **`tellma-core/entity/src/tm-entity-pickers.ts`**: `TmEntityPickers.binding(entity, { filter, create, multiple })`
  returns a plain object of getters (spec 0029 §14.1).
  - **Plan.** One plan per descriptor, held in a `WeakMap` as a `computed` (so the description columns
    follow the grants). It holds:
    - the key, the display name's twins (or scalar source) and the prefix as findable terms;
    - the select (`tmSelectPlan` over the description paths, plus `TmDisplayNames.select`);
    - the cached search's text columns: twins, source, prefix, natural keys and searchable;
    - the declared filter, the active flag, and the order: the declared `orderBy`, else the new
      `ɵtmDisplayNameOrder`.
  - **Server search.** `{segment}/query` with `select`, `search` (bidi-stripped, trimmed, capped at
    `limits.maxSearchLength`, omitted to browse), `filters` (declared and field filters as separate
    leaves), `orderBy` and `take: 21`. It returns 20 rows plus `hasMore`. Rows go through
    `tmRowsToObjects` and are remembered in `TmDisplayNames`.
  - **Cached search.** Applies to a cacheable target with no filter whose list is present in
    `TmLaunchCache.entitySet`. It is synchronous. It keeps the active rows that either
    contain-match the folded text over the text columns (memoized per row) or match the findable
    rule `ɵtmFindable(plan, text, ɵTM_SEARCH_MATCH)`, and sorts them by display name with the
    locale's `Intl.Collator`.
  - **Telemetry.** `tm.entity.picker-search {cached, outcome}` records the time. An abort reports
    nothing.
  - **Labels.** `itemLabel` is `names.of`. `itemLabelParts` is `[prefix, name]` or `[name]`.
    `displayWith` memoizes label signals per id and calls `resolve` while unknown.
  - **Description.** Built from the description columns:
    - value columns go through `TmFormats` in grid mode;
    - text groups use the active slot, else slot 1;
    - navigations use the related row's display name, or a label looked up by the foreign-key id.
  - **Pages.** Advanced search, Create and Edit each open `TmLazyPickerPage` at `size: 'lg'`.
    `context` is a getter, `{ entity, filter, kind }`, read at launch. Create's title is the
    `newLabelKey` text. `createLabel` is `tm.picker.newLabel` ("{label}…").
  - **Paste.** `ɵpasteResolver(entity, filter)` is used by `tmGridColumnFor`:
    - it builds one `in (…)` filter over every admitted string slot, a string prefix, integer
      source/prefix, `#id`, and each `prefix - name` split;
    - it splits the labels into groups that fit `maxFilterLength`, and runs one query per group;
    - it matches each label through `ɵtmPasteMatch`: exact, case-insensitive, accent-sensitive.
- **`tm-lazy-picker-page.ts`**: `TmLazyPickerPage`, `TmEntityPickerContext`, and the internal seam
  `ɵTM_PICKER_PAGES`.
  - The seam is a root token whose default loader resolves every page to `null`.
  - The page has four states: loading (a spinner), ready (`ngComponentOutlet` under the modal's
    injector, so the real page reads `TM_MODAL_DATA` and `TmModalRef` itself), unavailable (an
    empty state and Close), and failed (an error empty state, Close and Try again).
  - It emits `tm.entity.picker-page {page, outcome}` once, on close, and only when a page was
    shown.
- **`tm-entity-field.ts`**: `tm-entity-field`, a `FormValueControl<TmId | null>` that provides
  `TM_FORM_FIELD_CONTROL` as an `ɵTmFormFieldDelegate` over the picker.
  - **Bound and searchable.** The inner picker binds the same field with `[formField]`, so its
    unresolved-text parse error keeps the field invalid. The test shows `['parse', 'required']`.
  - **Unbound or unsearchable.** The value and the state inputs are forwarded by hand, read-only
    when the user may not query the entity. `[readonly]` cannot be bound beside `[formField]`.
- **`tm-entity-multi-field.ts`**: `tm-entity-multi-field` over `tm-entity-multi-picker`, forwarded
  by hand. Its required check is a `transformedValue` parse error (`requiredError()` on an empty
  list). An effect re-asserts it after a value change, a requirement change, or `reset()`.
- **`tm-value-editor.ts`**: new kinds `entity` and `entities` cover a navigation, or any value with
  a `target` (the §12.2 target row). The key property itself stays read-only, showing its id.
- **`tm-grid-column-for.ts`**: in an editable child grid, a root navigation becomes an `entity`
  column (§14.5). It is keyed by the foreign key's JSON name and spreads the binding, with the
  column's filter, `format` = `displayWith`, `formatParts` = memoized `labelParts`, and
  `resolvePastedLabels`. It is read-only when the user may not query the target or the key is
  server-owned, database-owned or derived. A write-once key is editable only in new rows.
- **`tm-select-plan.ts`**: the navigation-order helper is generalized into the exported
  `ɵtmDisplayNameOrder(target, entities, slot, path?)`. It also serves the root order.
- **`src/entity/tm-entity-descriptors.ts` and `tm-entity-model.ts`**: `TmNavigationDescriptor`
  gains `ownership`, the ownership of its key property. It is set in the lazy entity-model chunk.
- **Strings**: `ɵTM_PICKER_STRINGS_EN` is registered under the `picker` scope (`tm.picker.*`) by
  `TmEntityPickers` and `TmLazyPickerPage`. The Arabic twins are in `strings-tm-ar.ts`.
- **Harnesses**:
  - `TmEntityFieldHarness` and `TmEntityMultiFieldHarness` are in `@tellma/core-testing`. The
    package gains peer dependencies on `@angular/cdk` and `@tellma/core-ui-testing`, plus a
    `tsconfig.lib.json` path to the built `core-ui-testing`.
  - `TmEntityPickerHarness.isReadonly()` is in `@tellma/core-ui-testing`.
- **core-ui `tm-entity-picker.ts`**: the "no display text" dev warning now fires only when no
  `displayWith` is bound. A bound one that answers `null` is still loading.
- **Tests**:
  - new specs: `tm-entity-pickers.spec.ts`, `tm-entity-field.spec.ts` and
    `tm-lazy-picker-page.spec.ts`;
  - extended specs: `tm-value-editor.spec.ts`, `tm-grid-column-for.spec.ts` and core-ui
    `tm-entity-picker.spec.ts`;
  - a new `findable` section in `display-name-golden.json`, with 11 rows. Each row is checked
    twice, once for search and once for paste;
  - rig options `pickers` and `providers` in `tm-entity.testing.util.ts`, and an
    `Acme_Customer_New` string;
  - `tm-display-name-golden.testing.util.ts`, which re-exports the golden across the entry-point
    lint boundary.
- **Docs**: the tellma-core README (the entry-point row and an "Entity pickers" section), the
  core-testing README, and ARCHITECTURE.md's `/entity` description.
- **Budget**: `./entity` goes from 12.5 to 19 KB under D-031, with a budgetNotes entry. It
  measured 12.18 before and 18.58 after (+6.40 KB, rounded up to 6.5). As a savings attempt, a
  shared `@Directive()` base for the two fields was tried; it measured larger (18.65 KB) and was
  dropped. The primary stays at 44.87 of 45, and the entity-model chunk at 2.11 of 2.5.

### Deviations

1. The cached search contain-matches the searchable string columns as well as the admitted slots
   and natural keys. This lets the client find what the server's `search` finds (§14.2.3 names
   only slots and natural keys).
2. The cached search orders by display name even when `picker.orderBy` is declared. The order
   §14.2.3 states for the cached list is the display name's.
3. The paste resolver splits labels into as many queries as `maxFilterLength` requires, which is
   one in the normal case. §14.5 says "one query".
4. A paste matches `#{id}` but never a bare id, because pasted digits are names or codes, not ids.
   It also matches a string prefix with `in (…)`, as the display name's own column.
5. `itemDescription` is absent when the target has no description columns, so its rows show one
   line.
6. Create's modal title is the entity's `newLabelKey` text. The spec leaves it to the picker's
   default.
7. `TmEntityMultiField` adds inputs beyond §14.1's sketch, matching `TmEntityField`: `create`, the
   state inputs, `placeholder`, the aria inputs, and the `picked`, `removed` and `touch` outputs.
8. `TmNavigationDescriptor` gains `ownership`, the ownership of its key. Without it,
   `tm-value-editor` could not apply §12.2's ownership rule to a navigation: a `CreatedBy`
   navigation would have been editable.
9. The core-ui entity picker's missing-`displayWith` dev warning no longer fires for a bound
   `displayWith` that answers `null` while the label loads.
10. `navigationOrder` in `tm-select-plan.ts` is generalized into `ɵtmDisplayNameOrder` and reused for
    the picker's default order.
11. `@tellma/core-testing` now depends on `@tellma/core-ui-testing`, so its harnesses compose the
    picker harnesses.

### Open risks

- No C# check runs the golden's `findable` rows against `QuerySearch.cs`. The client mirrors its
  rules: Latin-only ids, native digits for integers, the split on a string source. The C# suite
  ignores the new section.
- Each descriptor's plan is a `computed` read untracked. A grant change rebuilds it on the next
  read, and the description's drops are reported each time.
- Until spec 0030 §17 and spec 0031 §15 provide `ɵTM_PICKER_PAGES`, every page says "not available".
- Inactive rows are left to the server's own exclusion, for both the search and the paste.
- Budget pressure. After this checkpoint `/entity` is at 18.58 KB against spec 0029's target of
  about 28 KB for the whole entry point. That leaves about 9.4 KB for the filters (PC-120) and the
  expression editor and path picker (PC-121).

- The grid column's read-only rules, and its `formatParts` memo.
