## Implementer notes

### What was built

Spec 0026 §10.1–§10.4, §12.1's facade and §8.4's panel, in the primary and a new lazy
`@tellma/core/support` entry point. The D-305 carry (the session menu's Report a problem row and
About's Diagnostics tab, in PC-118's files) is not built: PC-118 had not landed on
`origin/platform-core` at the end of this round (last fetch: 5e8337d1, PC-118 held at 1660f36a).

- **Facade, primary** — `client/projects/core/tellma-core/src/support/tm-support.ts`.
  - `TmSupport` (root): `canSend` (support enabled in the distribution document, a tenant route,
    an active session with the `me` envelope read, the membership not deactivated, `TmApi.online`
    and an `Active` tenant), `open({ error? })`, `copyDiagnostics(trigger)`, `downloadDump()` and
    `registerDumpSection(name, read, destroyRef?)`.
  - Sections: the name grammar `^[a-z][a-z0-9-]{0,31}$`, unique, `telemetry` and `sections`

    first registration keeps the name. A `DestroyRef` ends a section only while it is still the

    cache (the next press tries again) and goes to `TmTelemetry.error` with `where`

### Deviations

1. `copyDiagnostics(trigger = 'button')` takes the trigger, so the 5xx dialog's copy is counted
   as `dialog` in `tm.support.diagnostics-copied`.
2. `registerDumpSection` takes an optional `DestroyRef` rather than injecting one, so a root
   service can call it outside an injection context; without one the section lasts as long as
   the app. `telemetry` and `sections` are reserved, as the dump's own keys.
3. The worker's version shares the storage estimate's 200 ms box (§10.1 names the estimate as
   the only await): reading it needs `/updates`, which may not have loaded yet.
4. `truncated` names a step only when the step dropped something.
5. `TmSupportDialog` is interim: the Diagnostics panel over the snapshot, with Close. The six
   states of §12.2 are PC-210's.
6. The host chunk is preloaded at idle; a press before it lands opens the dialog when it lands,
   not in the press's frame. After the preload (the normal case) the open is synchronous.
7. `TmWorkerUpdates` gains `version`, so the panel and the dump read the worker's version
   through the existing seam.
8. A new `@tellma/locale-ar/support-strings` entry point; `./platform-strings` would have gone
   over its ceiling.
9. The downloaded file is pretty-printed (two spaces), for a human reader; the 2 MiB cap is
   measured on the compact form that is sent.
10. The panel shows request times in the device's local time, `HH:mm:ss`.
11. The dump names a failed section's error class with its own small rule (name, else type),
    not the telemetry pipeline's `tmErrorClass`: exporting that from the primary moved the
    pipeline's whole error capture into the first frame.
