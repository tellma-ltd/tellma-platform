# PC-103: Bootstrap, derived routes, URLs, query codec and route host

## Implementer notes

### What was built, and where

All paths are under `client/projects/core/tellma-core/` unless noted.

- **Bootstrap** (`src/app/`):
  - `bootstrapTellma(appConfig)` (`bootstrap-tellma.ts`) starts `TmApp` zoneless with the browser's global error listeners, only when `window.__tmBoot.state` is `run`. Otherwise its promise never settles; with no boot script at all, a development build logs why.
  - `provideTellma` (`provide-tellma.ts`) now derives:
    - the router over `tmBuildRoutes(pages)`, with component input binding, `paramsInheritanceStrategy: 'always'`, `canceledNavigationResolution: 'computed'` and a navigation error handler;
    - `TmUrlSerializer` (`src/routes/tm-url-serializer.ts`), which parses a path with trailing slashes as its canonical form;
    - the startup initializers (`tm-app-init.ts`, §4.3), in parallel: the Core chunk, the string packs and client tables of the document language and English, the session, and the store's boot step. None waits for the API. A failed chunk or string load emits `tm.boot.load-failed` and shows the boot page `load-failed`, and the app never starts. Before the first navigation, the initializer also replaces a trailing-slash address with its canonical form;
    - an environment initializer that creates `TmUrls`, starts `TmPageFocus`, and writes the boot record's `lastTenantId` on each `NavigationEnd` into a tenant;
    - every feature's `providers`, then `TitleStrategy` → `TmTitleStrategy`.
  - `TmApp` (`tm-app.ts`) is the `tm-app` root: a `<router-outlet>`, plus the navigation-failure view. `TmNavigationFailure` turns a `NavigationError` from a chunk into `TmUpdates.check` → `client-outdated` or `offline`, with retry.
  - `TmPlatformText` (`tm-platform-text.ts`, internal) holds the loaded packs and client tables until the localization service. It provides `text(key, fallback, params)` and the display name.
- **Route table** (`src/routes/tm-routes.ts`, §9.2): `/` (launch redirect), `tenants`, `signed-out`, and a tenant matcher (`t` is a positive integer with no leading zeros). Under the tenant, in order:
  - the home;
  - `settings` and `settings/{category}` as one route;
  - `me` with its four sections, as componentless children of one host;
  - `list/:segment`;
  - `reports/:key`;
  - the features' pages;
  - `:segment`, `:segment/new` and `:segment/:id`;
  - and `**`, the not-found page.

  The `canMatch` functions read `TmRouteRules` (`tm-route-rules.ts`), which uses `TmEntities.bySegment`:
  - search needs a stack;
  - list takes a stack or a child;
  - details and create need a stack whose API offers `details` and whose merged declaration has a `details` member;
  - a report needs a coded report's key;
  - an id is a positive integer.
- **Route host** (`tm-route-host.ts`, §4.4):
  - The skeleton (`tm-page-skeleton.ts`, on page-header geometry per kind) renders in the navigation's frame.
  - The page's chunk, the Entities chunk on an entity route, and `TmLaunchCache.ɵenter(t)` run in parallel. The page is created only once the launch documents are current; a failed cold sync waits for `warm()`.
  - A `securable` route renders `tm-route-error kind="forbidden"` when `TM_ROUTE_PERMISSIONS.can(...)()` is false. The seam allows everything by default; PC-105 provides the real one.
  - A chunk failure asks `TM_API_UPDATES.check()`: `ready` or `failed` → `client-outdated`, anything else → `offline`.
  - The host provides `provideTmPageScope()` and a `TmLeaveChecks` registry. The inputs it passes are only those the page declares.
  - `TmLaunchTimer` emits `tm.launch.cold|warm` at the first page render.
- **Title and focus**:
  - `TmTitleStrategy` (public) sets `{page} · {displayName}` from `titleKey`, a coded report's key, or the entity's (plural) label.
  - `TmPageFocus` moves focus to `main [tmPageTitle]`, else `[tmPageTitle]`, else `main`, after a path change once no host is loading. A query-only change keeps focus.
- **Launch redirect** (`src/launch/tm-launch-redirect.ts`, §9.3):
  - The `canMatch` replaces `/` with the last tenant (when `boot.sub` equals the profile's) or, with cached memberships, with `tmSingleLiveTenant`'s pick or `/tenants`.
  - Otherwise `TmLaunchRedirect` renders the picker's skeleton rows, awaits `revalidateUser()`, and replaces `/`.
  - Each tenant pick calls `TmLaunch.markAutomatic`.
- **URLs** (`src/urls/`, §9.4, §9.5):
  - `TmUrls` (public): builders of the routed tenant, `forTenant`, `target`, `blob`, `list`, `parseSearch`/`parseList`, `picker`, `signedOut`, `describe` (route-table order, with a template and `pinnable`) and `preload`. `preload` runs at idle, loads each chunk once, and runs no navigation and so no guard.
  - The internal `TmUrlResolver` behind the builders does the entity lookup, the defaults and the no-tenant rule. That rule throws in development; in production it emits `tm.urls.no-tenant` and returns `/tenants`.
  - `tm-search-query.ts` is the codec:
    - canonical print order, with defaults omitted;
    - `q` stripped of bidi controls through `tmStripBidiControls`, so ZWNJ is kept;
    - column filters with the `in`/`between` escapes;
    - the free filter as `#d=` base64url JSON;
    - a lenient parse in which the first occurrence wins and a malformed `d` gives a null payload.
- **Entities** (`src/entity/tm-entities.ts`, public): `summary` (name, ordinal-ignore-case), `bySegment` (exact), `declaration`, `label` and `load()` (once, retried after a failure).
- **`@tellma/core/shell`** (new entry point, `shell/`):
  - stand-ins for `TmTenantShell` (a `main` around the outlet), `TmTenantPicker` (the cached memberships as links) and `TmSignedOutPage`;
  - `ɵTmPagePlaceholder`, the one placeholder page for home, search, details, settings, me and reports, with an `h1 tmPageTitle` from `TmTitleStrategy.pageTitle`.

  The primary loads the shell only through `import('@tellma/core/shell' as string)` (`src/routes/tm-route-hosts.ts`), so neither TypeScript nor ng-packagr's cycle check follows it. The FESM keeps the literal specifier.
- **Acme** (`distributions/acme/src/Tellma.Distro.Acme.Client/`): `main.ts` is `bootstrapTellma(appConfig)`, `AcmeApp` is deleted, and the README is updated. The `@tellma/core-tools` fixture app likewise starts through `bootstrapTellma`; `TmFixtureApp` is deleted.
- **Other changes**:
  - `ɵtmMergeAppDeclarations` and `TmAppDeclarationMerge` take `Pick<TmClientMetadata, 'entities' | 'codedReports'>`.
  - `TmLaunchCache`'s idle read checks its abort signal; this fixed NG0205 when an app is torn down before idle.
  - The ESLint `bootstrapTellma` prefix exemption was added, and core's `*.testing.util.ts` rigs were added to the fixtures override.
  - `@angular/common` and `@angular/platform-browser` were added as peers.
  - `shell/public-api.ts` was added to `tsconfig.spec.json`.

### Planner-note ruling (report)

- **Placeholders.** One `ɵTmPagePlaceholder` in `/shell` stands in for the home, search and details hosts (0035-a1, 0030-b, 0031-b) and for settings, me and reports. The tenant shell, picker and signed-out page are stand-ins until 0027. `TM_ROUTE_HOSTS` is the single switch point.
- **canDeactivate.** The skip is narrower than "same route, same component": the leave checks are skipped only when the navigation reuses the same route config and the only changed parameters are ones the route declares in place (`ɵinPlace: ['category']`, the settings tabs).
  - A details record step (`/17/centers/5` → `/6`) reuses the host but still runs the checks. Skipping it would let Back or a link from a dirty record discard edits.
  - Query-only changes never reach `canDeactivate`, as Angular does not run it for them.

### Deviations

1. **`TmRouteMatch.hash`.** §9.4 has `describe` keep the `#d=` fragment, but its `TmRouteMatch` has no member for it. Added `hash?: string`. Obvious correction.
2. **`TmEntities` is created here.** It is a 0029 §4 member, built minimally: `summary`, `bySegment`, `declaration`, `label` and `load`. §9.2's `canMatch` and the route host need it before 0029-a lands, and 0029 extends it in place.
3. **The permission seam is internal `TM_ROUTE_PERMISSIONS`** (`can(resource, action): Signal<boolean>`), not a public `TmPermissions`. PC-105 provides 0029's service through it or replaces it.
4. **An interim text seam.** `TmPlatformText` reads the loaded packs and client tables (`tm.*`, `tmUi.*`, pack keys, `{name}` placeholders) until the localization service (PC-104) replaces it. Its titles and error views carry English fallbacks.
5. **The not-found page.** `TmNotFoundPage` (primary) renders §11's `not-found` view in place. No spec names its component. The tenantless one brings its own `main`.
6. **Error views.**
   - They carry no icons, to avoid unregistered icon names before 0027's set.
   - Reload is `location.reload()` until `TmUpdates.update()` exists.
   - The forbidden view shows the raw `resource · action`, not a localized permission label (0029).
7. **A failed cold sync keeps the skeleton** until the documents arrive. The shell's failure state belongs to 0027.
8. **Page context.** The route host provides `provideTmPageScope()` only; registering the page with `TmPageContexts` is left to 0026.
9. **Trailing slashes** are canonicalized in two places: `TmUrlSerializer` for in-app navigations, and `history.replaceState` in the app initializer for the document's own address.
10. **The `me` hub** routes with kind `settings` and skeleton `me`. Its sections are componentless children of one host, so a section change keeps the page.
11. **Launch timing** (`tm.launch.cold|warm`) is emitted by the route host at the first page render, since there is no shell render to time yet.
12. **The leave-check skip is narrower** than the planner note (see the ruling above).
13. **`ɵtmMergeAppDeclarations`** takes `Pick<TmClientMetadata, 'entities' | 'codedReports'>`, the only facts it reads.
14. **`@angular/common` and `@angular/platform-browser`** were added as peer dependencies of `@tellma/core`, which now imports them.
15. **The `TmUrls` builder internals** (entity lookup, defaults, no-tenant rule) live in an internal resolver rather than as `ɵ` members on `TmUrls`, which keeps the public class's API report clean.

### Budget

- `@tellma/core` (primary): measured 20.36 KB before and 30.20 KB after on the linked measure (+9.84 KB). The ceiling is raised from 20.44 to 30.3 under D-031: within the +10.0 KB that the rule allows when rounded up to 0.5 KB, keeping 0.10 KB of headroom. The budgetNotes entry names the weight and the savings.
  - Savings taken: the shell stand-ins and the placeholder live in `./shell` behind `import()`; the six family hosts share one loader; one builder class serves the routed tenant and `forTenant`; state is kept in private fields.
  - No dev-message stripping, per the existing note that development messages stay.
- **For the orchestrator:** spec 0024's own services now weigh about 22 KB, against their 14 KB share in §12. About 0.8 KB is `TmEntities`, which is 0029's. The primary's 50 KB total is not reached. Either the share grows, or later 0024 checkpoints must find savings.
- `@tellma/core/shell`: new, measured 1.19 KB, ceiling 1.28, with a note. `staticGraphExcludes` `{ ".": ["./shell"] }` guards the primary from statically reaching the shell.

### Open risks, and what reviewers should examine hardest

- **The leave-check skip rule.** `find(next.root, current.routeConfig)` and the in-place parameter comparison decide when the checks run. Check it against Back, a `/17/settings` ↔ `/17/settings/general` change, and a `me` section change: the `me` sections are child routes, so the host is not deactivated at all.
- **Cold entry that fails.** The host keeps the skeleton until `warm()` turns true. The shell's error state for a failed cold sync belongs to 0027, so until then a permanently failing sync shows the skeleton forever.
- **`describe` against the router.** `describe` re-implements the matcher order by hand rather than running the router's matcher. The route specs and the describe table cover the same URLs, but a later route added to one and not the other would drift.
- **Startup ordering.** The `history.replaceState` trailing-slash fix runs in the app initializer, before the router's first navigation. `tmRoutedTenant(location.pathname)` for the store's boot step reads the raw path, which is not yet canonical; a trailing slash does not change the tenant segment.
- **The `as string` dynamic import.** A literal `import('@tellma/core/shell')` makes ng-packagr refuse the build ("Entry point @tellma/core has a circular dependency on @tellma/core/shell", verified), so the specifier is cast. An installed package is unaffected, because the app's bundler resolves the FESM's literal import. Inside this repository, though, apps compile `@tellma/*` from sources through path mappings, and the Angular compiler then rejects shell files that are missing from its program.
  - So core's `tsconfig.spec.json`, Acme's `tsconfig.app.json` and `tsconfig.spec.json`, and the core-tools fixture's tsconfigs list `shell/public-api.ts`, each with a comment.
  - Every future in-repo app that starts through `bootstrapTellma` needs the same line. A better seam, such as the build adding the lazily imported entry points of the program, is open.
