# PC-000: Run infrastructure: PR and nightly test tiers in CI, tag conventions

## Implementer notes

### What was built, and where

- `.github/workflows/ci.yml` (the PR tier)
  - Workflow-level `concurrency`: group `ci-<event>-<PR head sha or push sha>`, `cancel-in-progress: false`.
    Every integration push gets its own run; only a second run of the same commit queues.
  - dotnet filters: build-test `Category!=Integration&Category!=E2E&Category!=Nightly&Live!=true`,
    integration `Category=Integration&Category!=Nightly&Live!=true`, identity-e2e
    `Category=E2E&Category!=Nightly`.
  - client job: installs Chromium only (the vitest browser suites are `chromiumHeadless` only, see
    `client/angular.json`), runs `node scripts/e2e.mjs --project chromium --project touch --grep-invert "@nightly|@perf"`,
    and uploads `client/.artifacts/e2e` on failure.
  - integration and client timeouts are 45 min.
- `.github/workflows/nightly-tier.yml` (platform-core version of the trampoline's file name):
  `workflow_dispatch` only, `permissions: contents: read`, a non-cancelling `nightly-tier`
  concurrency group, two jobs guarded by `if: github.ref == 'refs/heads/platform-core'`:
  - `dotnet`: Release build, the identity E2E project's Chromium, then
    `dotnet test Tellma.slnx -c Release --no-build --filter "Category=Nightly&Live!=true"`.
  - `client-e2e`: all three browsers, tokens CSS, `build:showcase`, then
    `node scripts/e2e.mjs --grep "@nightly|@cross-engine|@perf" --pass-with-no-tests` (all four
    projects in one invocation because `CI` is set).
- `client/scripts/e2e.mjs`: a Playwright child killed by a signal, or one that fails to spawn, now
  makes the script exit 1 (it used to resolve `code ?? 0`, i.e. green). Header doc points at the
  tier commands.
- `CONTRIBUTING.md`: the tag table, tagging rules, the PR-tier commands and the nightly-tier
  commands, verbatim (local form; CI adds `-c Release`).
- `.gitattributes`: `plans/** text eol=lf`, placed after the Windows-script CRLF rules (so it wins
  over them) and before the binary rules (so those still win).
- `ARCHITECTURE.md` (CI/CD & Quality Gates, repo layout): the two tiers, the tags, the trampoline,
  and `Category=Nightly` as a third trait value.

### Verification

- Both workflows parse (PyYAML); triggers, guards, timeouts and every test/e2e command were printed
  from the parsed tree and checked.
- dotnet selection, old against new filter, solution-wide `--list-tests` (the VSTest list honours
  `--filter`; checked first on one project): unit 2054 = 2054, integration 290 = 290, identity E2E
  37 = 37, sorted lists identical. No test carries `Category=Nightly` (the only trait attributes in
  the repo are `Trait("Category", "Integration"|"E2E")` and `Trait("Live", "true")`; there are no
  custom trait attributes), so identity is expected, not just observed.
- Empty dotnet nightly tier: `dotnet test Tellma.slnx --no-build --filter "Category=Nightly&Live!=true"`
  exits 0 in 70 s; every assembly prints "No test matches the given testcase filter"; no
  Testcontainers container started.
- Playwright selection, with a temporary probe spec (deleted, never committed) carrying title tags,
  a tagged `describe` and the `tag` option:
  - PR-tier command: only the untagged and `@cross-engine` probes ran on chromium; without the
    probe the selection (432 chromium + 8 touch = 440) is identical to the same projects unfiltered.
  - nightly command: chromium got every tagged probe (incl. the describe-inherited and `tag`-option
    ones), firefox and webkit got only the `@cross-engine` probes; 40 real `@cross-engine` tests per
    engine.
- Empty Playwright nightly tier: `CI=1 node scripts/e2e.mjs --grep "@no-such-tier-tag" --pass-with-no-tests`
  exits 0; the same without the flag exits 1 ("No tests found"). This also showed the web server
  starts even when nothing is selected (a few minutes of wasted build, harmless).
- `pnpm exec eslint scripts/e2e.mjs` clean. The PR-tier e2e command, run locally (Windows, dev
  server): 440 passed (432 chromium, 8 touch) in 6.6 min, exit 0.
- `git check-attr`: `plans/**` files (including a `.ps1`) resolve to `eol=lf`, a `.png` under
  plans/ stays binary, and a `.ps1` elsewhere stays CRLF. Every tracked plans/ file is already
  `i/lf w/lf`, so nothing renormalizes.
- No build or .NET source changed, so `dotnet build`/`format` were not re-run beyond the slot's
  warm-up build.

### Deviations (also in the commit message)

1. The PR-tier grep-invert is `@nightly|@perf`, not `@nightly|@cross-engine|@perf`. In this repo and
   in specs 0010, 0023, 0024 and 0030-0034, `@cross-engine` means "Chromium in full; Firefox and
   WebKit on the `@cross-engine` subset". Excluding it would have removed 40 existing Chromium tests
   from the PR tier. Firefox and WebKit leave the PR tier through `--project`, which is what the
   plan's "Firefox/WebKit `@cross-engine`" nightly content means.
2. The PR tier also runs `--project touch` (8 tests, Chromium engine, a Pixel 7 descriptor). The
   nightly command selects by tag, so untagged touch tests would otherwise run in neither tier.
3. The nightly dotnet filter is `Category=Nightly&Live!=true`: live suites need the credentials
   that only `nightly.yml` has.
4. The CI client job calls `node scripts/e2e.mjs` directly instead of `pnpm run e2e`, matching the
   documented command and avoiding a second shell parse of `|` by pnpm. The `pree2e` tokens hook is
   not needed there: `pnpm run build` writes the tokens CSS. The nightly job runs
   `tokens:build-css` explicitly.
5. `e2e.mjs` exit-code fix (signal kill or spawn failure is a failure).
6. Failure-only artifact uploads of the Playwright report in the PR client job and the nightly job.
7. The nightly Playwright run is one invocation over all projects, so Chromium also re-runs the
   `@cross-engine` tests the PR tier already ran. One run and one report seemed worth ~40 redundant
   tests.
8. The platform-core `nightly-tier.yml` has no `schedule` (GitHub ignores it off the default
   branch), and the CI concurrency group includes the event name.

### Open risks

- Merge into main: this `nightly-tier.yml` replaces the trampoline. The schedule must come back and
  the guards must point at `refs/heads/main`, or the nightly tier silently stops (all jobs skip,
  run green). The file's header comment says so. CONTRIBUTING.md's "runs each night on the
  `platform-core` branch" sentence and the `.gitattributes` `plans/**` line need the same pass.
- `retries: 2` on CI (existing Playwright config) turns a flaky test green with only a "flaky"
  count in the log, which the orchestrator's conclusion-only check cannot see. Not changed here.
- The CI verdict for this branch is only visible after integration (CI runs on the platform-core
  PR), and the nightly dispatch can only be checked after the push to platform-core.
- ARCHITECTURE.md says the client job runs on Ubuntu and Windows; it runs on Ubuntu only. That
  sentence is spec 0024's target state and was left alone.

### What the reviewer should examine hardest

- Deviations 1 and 2 (tier semantics of `@cross-engine` and the touch project) against PLAN.md §6
  and the specs' e2e rows.
- The concurrency expression for both `push` and `pull_request` events.
- That an empty nightly tier is green and a broken PR-tier pattern is red (no `--pass-with-no-tests`
  in ci.yml).
- Shell quoting of the grep patterns on Windows (PowerShell, cmd) and Linux in CONTRIBUTING.md.
