# PC-018: Entity contract, annotations, conventions, table-type binder and the TellmaDbContext model

## Implementer notes

### What was built, and where

- **`Tellma.Core.Abstractions.Entities`** (the contract): `Entity<TKey>` (`where TKey : struct,
  IBinaryInteger<TKey>`; only `int`/`long` survive model build), `TopLevelEntity<TKey>`,
  `ChildEntity<TKey>`, `TreeEntity<TKey>`, `ActivatableTreeEntity<TKey>` (each with its `int`
  non-generic form), `IActivatable`, `IJobEntity`; every annotation of 0012 §2.2 (`Temporal`,
  `TableType`, `ExcludeFromTableType`, `Collation`, `Tree`, `ParentKey`, `References`,

  `Unique`, `Searchable` + `SearchKind`, `PreserveWhitespace`, `JsonColumn`, `Multilingual`,

  `Sibling`) and the `TableTypeBinder` marker. `[BlobReference]`/`BlobPreset`/`BlobReadAccess`
  (PC-017) and the 0016 attributes (PC-015) are reused, not re-declared. Attributes validate
  nothing (the Abstractions rule); positional arguments are also settable properties so
  `[Tree(MaxDepth = 8)]` and `[Cacheable(MaxRows = 50)]` compile as the spec writes them.
- **`Tellma.Core.Abstractions.TableTypes`**: `DateList`, `IdStampList` (`datetimeoffset(7)` stamp
  through `[Column(TypeName)]`); `[TableType]` on `IdList`/`BigIdList`/`GuidList`/`StringList` and

- **`Tellma.Core.Abstractions.Data.ReservedSqlNames`** (0012 §1.4): the three prefixes, the
  `@tm_` names, `Statement(b, name)` and the `@tb{b}_` statement names, `IsReserved`

- **Composition seam**: `StackContributionItem` + `FeatureContribution.Entity<T>()` /
  `Entity<T, TService>()` (0011 §2.1 sketch) and `StackContributionRealizer`, which only records
  `ContributedEntity` rows on the composition record (validation: a closed class). PC-063 extends
  that realizer with the stack registry; nothing else existed to feed the model its leaves.
- **`Tellma.Core.Data`**:

    `[NotMapped]` children depth first, each → leaf; standalone types; model configurations closed
    over leaves via the type parameter's class constraint), `TellmaDbContext` (sealed, internal ctor
    over a definition; `Build`: platform collation, named defaults, entities, configurations,

  - `UseTellmaSqlServer(connectionString?, deployment, sweepScope = tellma.tenant)`:
    `UseSqlServer` + `UseHierarchyId()` + `UseCompatibilityLevel(160)`, `UseTableTypes(scope)`,

### Deviations (also in the commit message)

1. Enum string conversion is a finalizing convention over every enum and nullable enum property,
   not `Properties<Enum>().HaveConversion<string>()` in `ConfigureConventions`; all conventions ship
   with `UseTellmaSqlServer` (options extension + `IConventionSetPlugin`) so any context built
   through it gets them, and run at the head of model finalizing (after Core's configurations,
   before EF's key-generation/temporal/cleanup conventions and the table-type derivation).
2. Foreign keys are added as explicit configuration: EF's `ModelCleanupConvention` removes every
   navigation-less FK below Explicit, and the platform maps no navigations. An FK a Core
   configuration declared over the same column/principal is left alone.
3. EF's `ForeignKeyIndexConvention` is removed: only conventions or Core configurations create
   indexes. The audit FKs therefore carry no index (§1.3/§4.2 list IX only for child, reference
   and tree keys; `ModifiedById` changes on every save).
4. `[Flags]` enums are sized for every single-bit flag joined with `", "`, the string the
   conversion writes for a combination.
5. `UseTellmaSqlServer` takes the `DeploymentIdentity` (to set `Application Name`) and a sweep
   scope defaulting to `tellma.tenant`; the spec names neither the parameter nor any scope.
6. `StackContributionItem`, its sugar and a recording realizer ship here (0011 §2.1/0015 §2.1
   types) because the model's leaf input needs them; `TService` is constrained to `class` only.
7. Every table type, entity row image and standalone, grants `EXECUTE` to `tellma_app` (0011 §3.5
   "AddTellma sets tellma_app as the default principal set"); fixtures must create the role first.
8. A standalone type with no attribute schema is mapped in `dbo` explicitly (0012 §4.4 physical
   `[dbo].[<Name>_<hash8>]`), under its class name; its enums become `varchar(n)` and its
   `[ExcludeFromTableType]` properties are dropped, via the two new `TableTypeBuilder` methods.
9. The binder pins every text column's `SqlMetaData` to LCID 1033 with CI/AS options (the
   platform collation) instead of the thread culture SqlClient defaults to, and refuses a
   `varchar`/`char` column in a non-Latin1 or UTF-8 collation (cannot be encoded faithfully);
   `DateOnly`/`TimeOnly` are handed to the record as `DateTime`/`TimeSpan`.
10. Conventions throw `InvalidOperationException`, naming the class and declaration, for what the
    model cannot be built with: a `[References]`/`[Sibling]`/child target absent or mapped twice,
    a non-`int`/`long` reference or blob column, an unknown `[TableIndex]` property, a key neither
    `int` nor `long`, missing `core.Users`/`core.Jobs`/`core.Blobs`, a child carried by two parent
    types, a temporal TPT root or leaf. Everything else is left to PC-021's validation.
11. `dbo.__TellmaSchema`/`__TellmaProvisioning` are internal row classes with closed Core
    configurations; `CoreFeature` also registers `VersionTagList` (0012 §4.4 "registered by
    CoreFeature").
12. Model-wide `UseNamedDefaultConstraints()` beside the explicit `DF_` names; the period columns
    come out `HIDDEN` (EF's rendering of shadow period properties); EF omits `AS bigint` on a
    `long` key's sequence (the SQL Server default type).
13. Conventions shape root entity types only (leaf-only mapping); TPH/TPT derived types are not
    shaped, apart from the temporal TPT refusal.
14. `ReservedSqlNames` (§1.4 constants) and `DatabaseRoles` are names of this checkpoint's
    choosing: the spec gives the values, not a type.

Verified, not redone (planner note): the Abstractions → `Tellma.Core.Queryex` project edge and
ci.yml's design-e2e packing `Tellma.Core.Queryex` (PC-015).

### Open risks and seams for later checkpoints

- **The model builds lazily.** Nothing at startup resolves `IModel` until PC-021's metadata gate
  does; until then a model that cannot be built fails at first use, not in the gate. Forcing a
  build inside `core.model-contributors` would cost every composition test a model build, so it
  was left to PC-021 (the gate reports a throwing check as a problem).
- **`dotnet ef database update` without `tellma_app`.** The table-type migrations emit an unguarded
  `GRANT … TO [tellma_app]`; 0011 §6.1 says a design-time database "has no tellma_app", which would
  then fail with Msg 15151. PC-027 (fixture "role pre-creation") and PC-034
  (`TellmaDesignTimeDbContextFactory`) must create the role or guard the grant.
- **HierarchyId design-time services** are not injected into a migrator assembly (the package's
  `build/` targets are not transitive). The scaffold test runs without them and passes, so
  `migrations add` works; reverse engineering would not need them.
- **D-015 / Msg 468**: `StringList.Id` takes the database collation; key-set restrictions over a
  BIN2-collated natural key (e.g. a `Subject`) will need a collated list type (PC-033, 0010 §F.1).
- **§4.1 "every other timestamp `datetimeoffset(3)`"** has no convention in §1.3; non-audit
  `DateTimeOffset` columns stay `datetimeoffset(7)` unless declared.
- **No default-leaf naming**: a leaf's table comes from `[Table]` (inherited); a default without
  `[Table]` gets EF's class-name default (the leaf's name). PC-021 may want to require `[Table]`.
- The model cache keys on the definition instance, so each composition in a process builds its own
  model (tests compose many; a host composes one).

### What reviewers should examine hardest

1. `TellmaConventionSetPlugin` + `ConventionModel.AddForeignKey`: the ordering at the head of model
   finalizing, explicit FKs, and the removed FK-index convention (deviations 1-3), against EF 10
   source (`ModelCleanupConvention`, `ForeignKeyIndexConvention`, `SqlServerTemporalConvention`).
2. `TemporalConvention`: period properties are created before `IsTemporal`, because EF's temporal
   convention creates them only when the finalizing batch completes; check the TPT/TPH tests.
3. `TellmaModelDefinition.Close` and `ModelContributorsCheck`: open configurations closed over the
   leaf of the parameter's class constraint.
4. `TableTypeBinder`/`StoreTypeMetadata`: the column ↔ property match through table mappings on
   the runtime model, converters, the LCID choice, and the `DateTimeOffset` scale (EF puts a
   temporal precision in `Precision`).
5. The SQL in `DataModel.Sql` (`MigrationScaffoldTests`, `ConventionTests`): every name of §1.3.
