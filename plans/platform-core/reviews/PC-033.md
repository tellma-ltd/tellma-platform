# PC-033: Queryex host integration: schema provider, Rows/Count/constants, entity queries, materializer, display names

## Implementer notes

### What was built, and where

- **Schema provider** (`src/core/Tellma.Core/Data/Queries/`).
  - `QueryexSchemaProvider` (registered also as `IQueryexSchemaProvider`) builds one
    `QueryexSchema` per `MultilingualShape` from the entity metadata and the runtime model, plus a
    `QueryexSchemaMap` per shape that maps descriptors to metadata both ways and keeps each
    entity's declared properties and withheld JSON columns.
  - Store types come from `QueryexStoreTypes` (the relational type mapping parsed into
    `QueryexStoreType`). JSON, period and platform-secret columns are withheld; only the group
    twins a shape admits are properties.
  - References and parent keys are navigations; a sibling is an optional navigation on the
    owner's id. This needed an engine amendment: `NavigationDescriptor.IsOptional`
    (`QueryexSchemaBuilder` parameter `isOptional`), which `RelationalPlan` emits as a `LEFT JOIN`
    and `NullityAnalyzer` treats as possibly missing. Pinned by
    `Tellma.Core.Queryex.Tests/Emit/OptionalNavigationTests`.
  - `Fingerprint` is a SHA-256 of the model's queryable surface.
- **Batch query statements** (`src/core/Tellma.Core/Data/Batches/DataBatch.Queries.cs`).
  - `Rows`: `[keys twin] → page → [count] → [ancestors]`, each its own statement and ordinal.
    The keys twin is `DECLARE @tb{a}_keys TABLE ([Id] int|bigint PRIMARY KEY); INSERT … <body>`
    under the spec's filter, restrictions and paging (ordering dropped unless paged). The page then
    reads only the captured keys. The count is `SELECT COUNT(*) FROM (<keys body, Take = cap+1>)`.
    Ancestors are `@tb{d}_anc`: the nodes strictly above the page's nodes and not on it
    (`IsDescendantOf`), read with the spec's select and order under `AncestorsFilter`.
  - `Count`, `EvaluateConstant`, `Assert` (with an `OPTION (RECOMPILE)` variant that counts into
    `@tb{b}_count` first; number must be platform or distribution band; code is restricted to
    `[A-Za-z0-9._-]`).
  - `Query<TEntity>`: completion (root key, and per navigation prefix the owner's FK and the
    target's key), computed items refused, collections as a tree from dotted names, children
    restricted on captured parent keys (or the caller's own id restriction), grandchildren on
    their parents' captured keys, `AllProperties` adding JSON columns as `UndeclaredColumns`,
    ancestors through `AddWhole` into `Related` under the root's name.
  - `QueryPlan` compiles every statement of a call at its predicted ordinal and checks the
    parameter budget before appending any, so a refusal leaves the batch unchanged.
  - Dedup through `QueryStatementKey`, cleared at each declared write. Context values and the
    schema map are read once per batch.
  - `internal SqlIdentifier? KeysOf(object handle)` returns a handle's capture table.
- **Slots** (`QueryexSlots`): binding by origin (literal, today, now, user, time zone,
  declared), typed by store family; text slots sized to the family bound unless the value is
  longer; decimal facets only when the slot states them. `BatchParameter` gained precision/scale.
- **Materializer** (`EntityMaterializer`): depth-1 columns onto the statement's entity, deeper
  ones onto one related instance per id per prefix, JSON columns by column name, enums by name,
  `DateTime → DateOnly`, unknown columns refused; `Stitch` by parent key (every parent gets a
  list); `Build` narrows each set's projection to what every instance carries.
- **Display names** (`DisplayNames`, `DisplayNameRule`): spec 0029 §5.2's layout and render;
  `client/projects/core/tellma-core/src/entity/display-name-golden.json` is linked into
  `Tellma.Core.Tests` and pinned by `DisplayNamesTests` (client-only native-digit row skipped).
- **Composition**: `DataComposition` registers the engine, provider, materializer,
  `QueryServices` and `IDisplayNames`; `DataExecutor` carries `QueryServices`;
  `IBatchConnection` gained `Shape` (the factory handle throws, as for `Context`).
- **Fixture**: `fixture.Widgets` gained `OptionalKind varchar(8) NULL` (a nullable enum) and
  `DueOn date NULL`; the fixture migration was regenerated with `dotnet-ef`.

### Tests

- Unit: `Tellma.Core.Tests/Data/Queries/` (schema provider, golden SQL of every statement kind,
  dedup, refusals, omitted/null parameters, `Limits`, shape, slots, materializer routing,
  display names against the golden); `Tellma.Core.Abstractions.Tests/Data/QueryRowSetTests`
  (every held and refused (type, field type) pair); `OptionalNavigationTests`.
- Integration: `Tellma.Core.IntegrationTests/Data/DataQueryTests` over `DataQueryDatabase`
  (seeded once; its connections count `ServerRoundtrips` through `RetrieveStatistics`): grid
  page + count + ancestors in one round trip; cap + 1; assertion pass/fail; two pages one plan
  (`sys.dm_exec_query_stats`); details by id with children, related and an extra statement in
  one round trip; restrictions over `IdList`, `StringList`, `DateList`, `BigIdList`, a declared
  id table and a page's captured keys; omitted vs null `@Min`; `Via`; children and grandchildren
  stitch; sibling left join and cascade delete; related dedupe with projection; nullable enum;
  JSON via `AllProperties` only; the three shapes; `today()` equality; divide-by-zero and
  overflow; computed decimal facets; `level(Node)`.

### Rulings and open points for the orchestrator

- `KeysOf` is internal. Spec 0015's pipeline needs a public seam to restrict later statements on
  a `Rows(CaptureKeys)` handle's table.
- The `StringList` collation seam (Msg 468 against a column with an explicit collation) is not
  addressed; `StringList` restrictions work against default-collation columns.
- No startup check compares `QueryexSchemaProvider.Fingerprint` with anything yet.
- The golden's two date rows carry the .NET renderer's output (`3/15/2026`, `15/3/2026`); the
  client renderer must match them when it lands.
- Spec 0012 §13.2's fixture table lacks the two columns added to `fixture.Widgets`; §13.3's
  `DateList` restriction and nullable-enum assertion need them.
