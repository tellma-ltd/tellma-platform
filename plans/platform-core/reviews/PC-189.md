# PC-189: MCP server: host, authentication, request filter, read tools

## Implementer notes

### What was built, and where

- **`src/core/Tellma.Core.Mcp`** (new project, in `Tellma.slnx`; references `Tellma.Core.AspNetCore`
  and `ModelContextProtocol.AspNetCore` 2.2.0, pinned in `Directory.Packages.props`):
  - `McpTellmaBuilderExtensions.AddMcp(configure?)` is the entry point. It adds `McpFeature`
    (`FeatureName = "mcp"`, it only declares `McpOptions` at `Tellma:Mcp` through the gate). It
    registers the per-request services (`McpRequestAccess`, `McpCallState`), the singletons
    (`McpMetrics`, `McpEntities`, `EntityDescriber`, `DescribeCache`), the startup check
    `core.mcp-tool-names`, and the surface source. It attaches `McpBearerEvents` to `Tellma.Bearer`
    and registers the five read tools and the syntax resource. It then calls `AddMcpServer`
    (`ScopeRequests = false`), `WithHttpTransport(Stateless = true)` with `ConfigureSessionOptions`
    setting serverInfo and instructions, the request filters, and `WithTools(ToolTypes)` for the
    distribution's own tools. Calling `AddMcp` twice throws.
  - `Hosting/McpSurfaceSource` implements the new `ITenantSurfaceSource` seam in
    `Tellma.Core.AspNetCore` (`Routing/ITenantSurfaceSource.cs`). `MapTellma` maps its sources on the
    tenant group, so the route lives at `/{tenantId}/mcp`. It wraps `MapMcp` with `Tellma.Mcp`, the
    MCP rate and timeout policies, the body limit, and the hand-written Origin allow-list
    (`McpOrigins`). The SDK's stateless mapping serves only POST, so GET and DELETE answer 405.
  - `Authentication/McpBearerEvents` checks the audience in `OnTokenValidated`: the token must carry
    `{PublicOrigin}/{tenantId}/mcp` for the tenant in the route, or the request fails as 401
    `invalid_token`. Its `OnChallenge` writes `resource_metadata` naming that tenant's PRM, and
    `OnForbidden` writes 403 `insufficient_scope`.
  - `Hosting/McpRequestAccess` memoizes the access guard per request (`IsMutation = false`) and
    refuses service accounts. `McpServerIdentity` builds the instructions, naming the tenant only to
    an admitted caller, and a sandbox as a copy.
  - `Hosting/McpToolCallFilter`:
    - Call filter: guard, cultures (MessageLanguage, Calendar), exception to an `isError` result
      through `ProblemMapper` plus the JSON problem text, metrics and a log line.
    - List filter: platform tools first in the `McpToolNames` order, then the rest by name;
      `ttl` 5 min and `cacheScope` public.
  - Tools:
    - `tellma_whoami`: one guarded read round trip, then the access matrix over the visible entities;
      structured content plus its output schema.
    - `tellma_describe`: the catalogue with search, or one entity's Markdown description, gated by the
      tenant shape and cached.
    - `tellma_query` and `tellma_aggregate` (`RowTools`): rendered as a table or as objects, truncated
      row by row under the character cap; `includeInactive`; child entities through the child query.
    - `tellma_get`: the header first, child windows, and paging through one collection.
  - `Resources/QueryexSyntaxResource` serves `tellma://queryex/syntax` (embedded Markdown).
- **`Tellma.Core.AspNetCore`**:
  - `ProtectedResourceEndpoint` and `DistributionInfoEndpoint` give `resource_name` and the resource
    URL helpers.
  - `McpLimitOptions` is no longer bound from configuration. `AddMcp` sets it from `McpOptions`.
  - `ProblemWriter.Localize` became internal, so the filter renders problem text in the request's
    language.
  - The `composeWeb` docs now say the delegate may add a feature, but never an entity, a securable
    or a table.
- **Acme:**
  - `AcmeWebComposition` calls `tellma.AddMcp()`.
  - The Web project references `Tellma.Core.Mcp`.
  - The integration tests reference the SDK's client package.

### Deviations

1. **Integration coverage lives in Acme.** It is `McpTests` in
   `Tellma.Distro.Acme.IntegrationTests`, against the real composed host and SQL Server, not a new
   `Tellma.Core.Mcp.IntegrationTests`. PC-190 owns that suite. The trust in the test issuer is
   appended through `PostConfigure<JwtBearerOptions>`.
2. **"Lists 8 tools": five are listed.** This checkpoint ships the five read tools. save, delete and
   action are PC-190's.
3. **The bearer challenge and the audience check run through the `Tellma.Bearer` JwtBearerEvents**
   (`OnTokenValidated`, `OnChallenge`, `OnForbidden`), not the SDK's authentication handler. A wrong
   audience gets 401 `invalid_token`.
4. **The Origin check is hand-written** (`McpOrigins`) and answers 403 `forbidden`. An absent Origin
   passes, and so does a listed one, ignoring case.
5. **The describe cache is a private `MemoryCache`**, not a `VersionedCache`, because `CacheKinds` is
   a closed set. It holds 2048 entries with a 30-minute sliding expiration, and each hit is checked
   against the settings `VersionTag`. Its key adds the UI culture to (TenantId, Entity), because the
   description carries localized labels.
6. **Child entities.**
   - aggregate accepts them, as query does.
   - The catalogue lists each one under its owner.
7. **Service accounts are refused** with `individual-required` (ARCHITECTURE: individual users only
   this release).
8. **The guard runs once per request and is memoized.** serverInfo and the instructions name the
   tenant only after the guard admits the caller.
9. **`McpLimitOptions` is set from `McpOptions`**, not bound separately.
10. **The PRM document stays in `Tellma.Core.AspNetCore`.** Its `resource_name` is the display name
    alone.
11. **The distribution-info MCP surface is `/{tenantId}/mcp`.**
12. **Rendering choices.**
    - A full page with no count adds the hint "The page is full, so more rows may follow".
    - The objects format is a JSON array keyed by column.
    - get windows collections under a `$collections` member that gives total, returned and truncated
      for each collection.
13. **Whoami.**
    - The matrix covers only the entities the caller may see, and leaves out sensitive grants.
    - Language, calendar and zone come from the request context and the user's preferences.
14. **Argument errors are `bad-request`** with the argument's `path`.
15. **The list filter also orders the tools**, so the list is deterministic whatever order DI gives.
16. **describe refuses `entity` and `search` together** as a bad request.
17. **A second `AddMcp` call throws.**
18. **The `isError` problem text** is JSON holding status, code, title, detail, errors, errorDetails,
    arguments and retryAfterSeconds.
19. **`ProblemWriter.Localize` is internal** (it was private), shared with the MCP filter.

### Open risks, and what to examine hardest

- **`McpBearerEvents` is chained onto `Tellma.Bearer`'s existing events.** Check that the challenge
  for a non-MCP route is untouched. Check also that a cross-tenant token is refused before the guard
  runs.
- **`McpToolCallFilter` problem mapping.** Is the Denied/Error outcome classification right? And is
  a requested cancellation the only exception that propagates?
- **`EntityDescriber`** gating of Hidden and sensitive operations and of the secondary and tertiary
  language columns. Is the `VersionTag` check enough to invalidate the description when the tenant
  shape or the labels change?
- **SDK 2.2.0 stateless behaviour**: the per-request `ConfigureSessionOptions`, and
  `ScopeRequests = false` with scoped services resolved from the HTTP request scope.
