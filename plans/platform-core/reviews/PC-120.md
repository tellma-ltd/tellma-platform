# PC-120: Client Queryex (lexer, builder, printer) and column filter controls

## Implementer notes

### What was built, and where

**Server and tooling (C#)**

- **`src/core/Tellma.Core.Queryex/Lexing/Lexer.cs`.** `TryTokenize` now always returns the tokens it
  read, ending with end-of-input, even when a run is unreadable; it still returns `false` then, and
  every caller still stops. It also has an optional `unreadable` collection that receives each
  unreadable run's span. The engine's own behaviour is unchanged: the full Queryex unit project
  passes, 1,718 of 1,718.
- **`test/shared/Tellma.Queryex.Testing/Client/`.** This folder holds the engine's answers that the
  browser client is held to.
  - **`ClientLexerCorpus`.** 116 texts. They cover every rule of spec 0008 §4: ASCII-only keyword
    case folding (`ın`, `ſ`, `İ`, Kelvin K), surrogate pairs inside names and failed numbers,
    U+0085/U+FEFF/U+200B, Arabic-Indic digits, `@[`, `@1`, the 38-digit limit, and every QX1xxx
    code. For each text it records the tokens, the client's error tokens (the unreadable spans
    merged in by start), the parameters grouped case-insensitively, and the diagnostics.
  - **`ClientPrintGolden`.** 79 rows. Each is a tree, as the client's `TmQx` JSON, together with
    the engine's canonical text (`SyntaxPrinter`, Minimal). The rows cover precedence, names
    (keywords, supplementary-plane letters, combining marks), literals, calls, the spec's worked
    examples, and every §13.2 filter leaf over `LedgerFixture`'s `Invoice`.
  - **`ClientJson`.** A small deterministic JSON writer. It escapes every code unit a reviewer
    could not see in a diff.
  - **`ClientCorpusFiles`.** Writes both files.
- **`eng/queryex-client-corpus/Tellma.Queryex.ClientCorpus`.** Writes both JSON files beside the
  client code: `dotnet run --project eng/queryex-client-corpus/Tellma.Queryex.ClientCorpus`. They
  are UTF-8 with no BOM and LF endings, and it works on Windows and Linux. The project is added to
  `Tellma.slnx` under `/eng/`.
- **`test/core/Tellma.Core.Queryex.Tests/Client/ClientCorpusTests.cs`.** Five tests:
  - both files are current;
  - every golden text parses back to itself (`CanonicalText`) and means its tree (`AreEquivalent`);
  - every filter row discovers cleanly in filter mode against `LedgerFixture`, which is the "C#
    Discover check";
  - the corpus's parameters are the ones discovery reports.

**Client**

- **`entity/src/tm-qx-lex.ts`.**
  - The public API is `tmQxLex` and `tmQxParameters`, as in §8.1.
  - The token rules are written from spec 0008 §4 and held to the corpus. `call: true` marks a
    name whose next readable token is `(`.
  - Internal exports:
    - `ɵtmQxIsKeyword` and `ɵtmQxIsBareName`, used by the printer;
    - `ɵtmQxFold`, the engine's per-code-unit case fold;
    - `ɵtmQxPaths`, the dotted paths a text reads, call names excluded, used by `tmSelectPlan`.
- **`entity/src/tm-qx.ts`.** The `TmQx` union, the frozen `tmQx` builder, `tmQxPrint` (which
  reproduces `SyntaxPrinter`'s Minimal mode, held to the golden) and `tmQxInsert`.
  - **`num`** refuses a non-finite number or one with more than 15 significant digits
    (`RangeError`), and any text that is not `-?digits(.digits)?` (`TypeError`). It writes numbers
    without an exponent. A negative becomes `negate(number)`, because that is how the engine reads
    `-5`, and negative zero becomes `0`.
  - **`literal`** covers every type that has a literal:
    - dates are validated as real days;
    - date-times are normalised to `yyyy-MM-ddTHH:mm:ss`, keeping any fraction;
    - an instant is ISO text with an offset, or a `Date` or epoch number written in UTC as
      `+00:00`;
    - integers must be whole;
    - floats take the decimal rules;
    - `time`, `json` and `binary` throw.
  - **`raw`** lexes the text and requires no lexical problem, at least one token and balanced
    parentheses, then prints it parenthesised.
- **`entity/src/tm-filter.ts`.** The pieces of §13:
  - `TmFilterOp`, `TM_ENUM_PICKER_THRESHOLD` (50) and `TmFilterSpec`;
  - `tmParseFilter` and `tmFormatFilter`, where list operators escape `\` and `,`;
  - `tmFilterLeaf`, which builds a tree and prints it, never concatenating text;
  - `tmDescribeFilter`, a reactive description made of parts;
  - `tm-filter-description`, which puts each argument in a `<bdi>`.
- **`entity/src/tm-column-filter.ts`.** `tm-column-filter`, following §13.3:
  - **Operator.** An operator select appears when the column's kind has more than one operator.
  - **Controls by kind.**
    - Text: an input.
    - Number: a single `tmNumber`, or a labelled From/To group for `between`.
    - Date and instant: `tm-date-range` (inline), or `tm-date-picker`.
    - Enum: a checkbox group up to 8 values, `tm-multi-select` below 50, and a synchronous
      `tm-entity-multi-picker` over the enum's own values from 50 up (first 20, `hasMore`,
      `maxItems` 50).
    - Bool: a radio group.
    - Navigation: `tm-entity-multi-field` with `create` off and `maxItems` 50.
  - **Buttons.** Clear emits `null`. Apply is the form's submit and is enabled only while
    `tmFilterLeaf` accepts the value.
  - **Enter.** Enter in the control's own input applies the value. Enter inside a select, picker
    or field stays theirs.
- **Strings.**
  - `tm.filter.*` in English (`ɵTM_FILTER_STRINGS_EN`): operator, apply, clear, from, to, true,
    false, the operator names, and one whole-sentence `describe.<op>` message per operator.
  - The Arabic table in `@tellma/locale-ar/strings`.
- **`entity/src/tm-select-plan.ts`.**
  - Carried from PC-117 R1-4: an expression column is dropped as `unreachable` when a path it
    reads, and that the client resolves, is not reachable for the user. Paths the client cannot
    resolve are left to the server.
  - `ɵtmGroupSlots` is factored out, so the text filter reads the same slots the column selects.
- **`@tellma/core-ui/l10n`.**
  - `tm-zone-wall-time.ts` moved here from `date-time/internal/`. Its internal exports
    `ɵtmInstantOfWallTime`, `ɵtmWallTimeOf`, `ɵtmReadInstant`, `ɵtmFormatOffsetInstant` and
    `ɵTmWallTime` are now exported, so `/entity` can compute a day's first instant in a zone,
    DST gaps included.
  - `date-time` imports them from `/l10n`.
- **`@tellma/core-testing`.** `TmColumnFilterHarness`.
- **Test rig** (`tm-entity.testing.util.ts`).
  - New options: `language` now also takes `am`; `tmStrings` gives the platform's own Arabic and
    Amharic strings; `labels` gives extra server labels per language.
  - Amharic is a third app language.

### Deviations

1. **Bracketed keywords.** §8.2's example `[Order]` is wrong for the engine. `Order` is not a
   Queryex keyword, so the engine, and therefore the client, prints it bare. The golden pins
   `Order = 1` and `[not].[in] = [desc]`.
2. **Description list style.** `in` descriptions use `Intl.ListFormat` with `unit` and **`short`**,
   not `narrow`. English's narrow unit list drops the commas ("Retail Wholesale"), which
   contradicts §13.2's own example "Type: Service, Sale".
3. **Insertion spacing.** `tmQxInsert` adds a space on both sides of the insertion. It adds one
   where the insertion's end would touch a word on its right, as well as where its start would
   touch a word on its left. It also treats `]` as a word end, and `[` and `@` as word starts, so a
   bracketed name or a parameter is never glued to its neighbour. §8.2 names only "an identifier,
   a digit or `)`" on the left.
4. **Builder edge cases** the spec leaves open:
   - `tmQx.in(x, [])` stands for `false`;
   - `tmQx.num` of a negative builds `negate(number)`, and `-0` builds `0`;
   - `tmQxPrint` of an `in` node with no items throws.
5. **Engine lexer.** `Lexer.TryTokenize` hands out the readable tokens around an unreadable run,
   and takes an optional collection of the unreadable spans, so the corpus can record what the
   client should show. No engine behaviour changes, because callers stop at `false` as before.
6. **Unnamed navigation values.** A navigation filter's description shows a row's id with no digit
   grouping ("1012") while the row is not yet named, then its display name. §13.2 says display
   names only.
7. **Unknown display zone.** An instant filter in a display zone the platform does not know reads
   that zone as UTC, as every other instant formatter does. It is not an invalid value.
8. **Wall-time helpers moved.** `tm-zone-wall-time.ts` moved from `@tellma/core-ui/date-time`'s
   internals to `@tellma/core-ui/l10n`, with `ɵ` exports, so that `/entity` does not import
   `date-time`'s components to compute a day start.

### Open risks

- **Paste resolver.** `tm-entity-paste.ts` (PC-119) still builds its paste filter by joining
  strings. It is not one of §13's leaves and it escapes its own literals, but it could move to
  `tmQx` now that the builder exists. This was left alone as out of scope.
- **Arabic and Amharic lists.** Arabic and Amharic `unit` lists join with "and" (و, እና) in every
  style, so "Type: A و B" reads as a conjunction for an any-of filter. The message is the
  translator's to word, but the list format is not.
- **`/entity` weight.** The lexer lives in `/entity` because `tmSelectPlan` and `tmQx.raw` use it,
  so the whole entry point carries it.

### What to examine hardest

- `tmQxPrint`'s floors against `SyntaxPrinter`. The golden covers them, but check the `in`, `is
  null`, negate and not floors.
- `tmQxLex`'s failed-number and surrogate handling against `Lexer.FailNumber`, and the call-flag
  rule across error tokens.
- `dayStart` for instants in a DST gap, through `ɵtmInstantOfWallTime`.
- The column filter's Enter gating, and the linked drafts when `value` changes while the control
  is open.
