# PC-045: Grid key map through kbd and grid glyphs through tm-icon

## Implementer notes

### What was built, and where

All library paths are under `client/projects/core/tellma-core-ui/`.

- **One binding table** (`grid/internal/grid-keymap.ts`). `TM_GRID_KEY_BINDINGS` lists every key
  combination the grid handles with no editor open, each with its intent, its label key
  (`tmUi.grid.keys.*`) and the grid state it needs (`editable`, `searchable`, `selectable`,
  `tree`). It covers the navigation state, the tree's Alt+Arrow, F2 and Alt+ArrowDown (both
  already handled by the grid, so their entries land now) and the clipboard keys, which carry a
  `null` intent because the browser's clipboard events handle them.
  - Letter, digit and symbol bindings (Mod+A/C/X/V/D/Z/Y/F, Mod+Shift+Z, Mod+Alt+Plus/Minus/=)
    are filtered once into `CHARACTER_BINDINGS` and matched through `tmKeysMatch`, so they work on
    an Arabic layout and under Option on Apple.
  - Named keys keep direct `event.key` checks, now held to exactly the modifiers the table lists
    (see Deviations).
  - `TmGridKeyContext.isMac` became `apple`; the core passes `tmIsApplePlatform()`.
- **`TM_GRID_KEYS`** (`grid/tm-grid-keys.ts`), exported from `./grid`: the table without its
  intents and conditions, frozen, with a named `TmGridKeyEntry` interface.
- **Strings.** `grid.keys.*` in `i18n/strings-en.ts` (30 labels) and their Arabic twins in
  `locale/tellma-locale-ar/strings-ar.ts`, written as verbal nouns so they need no gender select.
- **Platform checks.** `IS_MAC_PLATFORM` (grid-core) and the find bar's `IS_MAC` are gone. The
  find bar's and the editing branch's Mod+F use `tmKeysMatch(event, TM_GRID_FIND_KEYS)`; the
  pointer Mod reads `tmIsApplePlatform()`.
- **`tm/no-platform-sniffing`** (`client/tools/eslint/no-platform-sniffing.mjs`, wired in
  `client/eslint.config.mjs` over `projects/core/**/*.ts` and `projects/module/**/*.ts`, ignoring
  `projects/core/tellma-core-ui/kbd/**`, specs included). It refuses `platform` and
  `userAgentData` read off `navigator` (directly, through `window`/`self`/`globalThis`, a type
  assertion, a non-null assertion, optional chaining or a string or template-literal bracket key)
  and destructured from it. Vectors and a workspace-scope test in
  `client/tools/tests/no-platform-sniffing.spec.mts`.
- **Glyphs through tm-icon.**
  - `grid/internal/icons.ts` (`ɵTmGridIcons` and `ɵTmGridIconTemplates`) is deleted. The context
    menu's entries carry Lucide data (`GRID_MENU_ICONS` in grid-core); `attachMenu` takes only the
    menu.
  - Find bar: ChevronUp, ChevronDown, X. Status bar: ChevronLeft and ChevronRight with
    `mirrorInRtl` (they now point along the reading direction in RTL), and CircleAlert in place of
    the `tm-grid__status-warn` mark, whose class is gone. The chip and the nav buttons set
    `--icon-size: var(--grid-status-icon-size)`, which replaces the old svg sizing rules.

    (collapsed), sized by `--grid-twisty-size`. The `rotate` rules and the
    `:host-context([dir='rtl'])` rule are gone, and so is the now unused `tm-grid__expander--open`
    class binding. The check and dash masks are untouched.
- **`TmGridBase`** (`grid/tm-grid-base.ts`, moved from `grid/internal/grid-base.ts`): the shared
  base is now public and `@sealed`, so its inherited inputs appear in the `./grid` and
  `./tree-grid` goldens, as the TmSelectBase precedent does.
- **Tests.**
  - Unit: `grid/internal/grid-keymap.spec.ts`. Every binding is pressed by a synthetic keydown on
    both platforms and resolves to its intent; every letter binding also resolves with the Arabic
    character and the Latin code; every gated binding does nothing when its condition fails; the
    row operations match under Option on Apple (`≠`, `–`); the browser zoom keys stay unhandled;
    a reverse sweep presses every bound key under all 16 modifier sets on both platforms and

  - e2e: `e2e/specs/grid-keyboard-layout.spec.ts` (Mod+A, Mod+D, Mod+Z, Mod+Y and Mod+F on an
    Arabic layout, dispatched as a synthetic key/code pair through `e2e/support/layout-keys.ts`);
    `e2e/specs/grid-glyphs.spec.ts` (find bar, status bar, expander and context menu geometry in

### Deviations

1. **Named keys match their modifiers exactly.** Before, a focused grid also took Alt+PageUp/Down,
   Mod+PageUp/Down, Mod+Enter, Mod+Shift+A, Mod+Shift+D, Shift+Delete, Shift+Escape and other
   combinations its reference does not list. Spec 0027 §4.3's registry refuses only what
   `TM_GRID_KEYS` lists, so a grid that swallowed more would break registered shortcuts (spec 0031
   uses Alt+PageUp/Down for record stepping, spec 0027 Mod+Enter). Now every non-null resolution is
   a table entry or a typed character, which the unit reverse sweep enforces. No existing e2e used
   the dropped combinations.
   - Type-to-edit (review 1 fixes) seeds the editor only with a typed character: no Ctrl, Alt or
     Meta; or AltGraph off Apple (Windows reports AltGr as Ctrl+Alt with AltGraph, Linux as
     AltGraph alone); or Option without Cmd or Ctrl on Apple. A bare Alt or Ctrl+Alt chord on
     Windows and Linux used to seed the editor, which swallowed spec 0027 §4.3's Alt+Shift+<letter
     or digit> and Mod+Alt+Shift+<key> platform family. It now stays with the page.
   - Unverified residue: whether Chromium on Windows reports AltGraph for a LEFT Ctrl+Alt chord on
     a layout that has AltGr (German, French). Synthetic events cannot show it and no such
     keyboard was available. If it does, Mod+Alt+Shift+<key> on those layouts still seeds the
     editor; this is recorded as a lead under 0027 in WATCHLIST.md for the shortcut registry's
     checkpoint (its manual release check already covers Appendix A on Windows).
   - On Apple, Option+Shift+<letter> types a character (∏, Í) and seeds the editor by design, so
     spec 0027's Alt+Shift+<letter> family cannot reach the page from an editable grid there. The
     same WATCHLIST lead names it.
2. **`TmGridKeyEntry`** is a named exported interface; the spec writes the element type inline.
   Additive.
3. **`ɵTmGridBase` is now the public `@sealed` `TmGridBase`**, which the spec's §C.14 sketch still
   calls `ɵTmGridBase`.
4. **The scroll probe is `@perf @quarantine`** (by the orchestrator's ruling on review 1, so it
   runs only in the non-blocking quarantine job until the grid's scroll budget is fixed), and runs
   on a new readonly `tree-grid-large` story rather than the 58-row `tree-grid` story, which is
   too short to scroll. It keeps the spec's 50 ms bar.
5. **Size ceilings raised** under the size rule (by at most what the change adds, rounded up to
   0.5 KB, each with a `budgetNotes` entry), both measured against a HEAD build:
   - `./grid` 38.5 → 39 KB (38.04 → 38.71 KB, +0.68 KB: the binding table, its matching loop and
     13 Lucide glyphs, net of the deleted icon component and platform sniffs).
   - `.` 8 → 8.5 KB (7.82 → 8.12 KB, +0.30 KB: the 30 English key labels).

### Open risks

- **The scroll probe fails its absolute 50 ms bar on this machine**, and the expander is a minor
  contributor, not the cause. Measured with 40 viewport wheel steps down and back, on the same dev
  server in the same session:
  - flat `grid-readonly` (100,000 × 12, no tm-icon in rows): 26–49 long tasks, up to 92 ms;
  - `tree-grid-large` (21,000 rows, 14,000 expanders): 0–2 long tasks of 50–51 ms in the probe,
    7 of 51–58 ms in the `@perf` test itself.
  - A production build was worse for the flat grid (46–58 long tasks, up to 111 ms) and gave the
    earlier, shallower tree 4 long tasks of 57–69 ms.

  - Like-for-like (review 1 fixes): the same `tree-grid-large` story with the expander
    temporarily swapped back to the old raw SVG, three runs each, back to back on one dev server.
    Long tasks over 50 ms, old SVG: [55], [51], []. tm-icon: [], [], []. The two are inside the
    run-to-run noise.
  - CPU share, from Reviewer 1's CDP profile of the same 40+40 wheel steps on `tree-grid-large`:
    tm-icon frames (the TmIcon factory, `draw`, `glyphTemplate`, `appendElements`,
    `resolveDirect`, `tmResolveIconSource`) took 156–188 ms of 1.57–1.80 s busy time, about 10%.
    That tenth can tip a borderline 52–55 ms task over the bar, but the rest of the frame is the
    grid's own row rendering, which the flat grid shows is over the bar without any icon.

  So the probe is quarantined, and the fix belongs to the grid's scroll budget as a whole. The
  expander's tm-icon draw is the place to look last, not first.

- Grid glyphs now size only through tokens. A host page that does not load the token sheet gets
  unbounded icons in the grid chrome, as unit fixtures without tokens do.
- The reverse sweep in the unit spec runs with every condition true. A gated binding's fallthrough
  (bare Space reaching type-to-edit without row checkboxes) is covered by the gated test, which
  accepts null or type-to-edit.
- `tmIsApplePlatform()` is called per keydown and per pointer gesture rather than cached at module
  load. It reads `navigator` each time, which is cheap, and it means a test that stubs the platform
  sees the change.

### Findings

**R1-1 (major) — type-to-edit still takes Alt+letter and Ctrl+Alt+key on Windows and Linux, so a
focused editable grid swallows spec 0027's platform shortcuts.**
`client/projects/core/tellma-core-ui/grid/internal/grid-keymap.ts:380-381`
(`printable = key.length === 1 && !event.metaKey && (!event.ctrlKey || event.altKey)`), and the
reverse sweep's exemption at `grid/internal/grid-keymap.spec.ts:250`.
Deviation 1's purpose is that the grid takes no combination outside `TM_GRID_KEYS`, because the
registry (0027 §4.2) listens in the bubble phase and skips `defaultPrevented` events, and refuses
only what `TM_GRID_KEYS` lists. But the platform family (0027 §4.3) is "every
`Alt+Shift+<letter or digit>`, every `Mod+Alt+Shift+<key>`" (Alt+Shift+P/J/U/Q/H/I,
Mod+Alt+Shift+D, Mod+Alt+Shift+1 in Appendix A). On Windows/Linux, Alt+Shift+P with a cell active
in an editable grid arrives as `key 'P'`, `altKey`, no Ctrl: no binding matches, `printable` is
true, the resolver returns `{ kind: 'edit', mode: 'enter', seed: 'P' }`, the core opens an editor
seeded with "P" and prevents the event, and the launcher shortcut never runs. Ctrl+Alt+Shift+D
does the same (`ctrlKey && altKey` counts as printable) and seeds "D". Alt never types a character
on Windows/Linux except as AltGr, so this is a pure swallow. The sweep skips every type-to-edit
resolution, so it cannot see the gap, and it only presses the table's own keys.
Fix: treat a keydown as printable when it carries no Ctrl/Alt/Meta (Shift allowed), or when
`event.getModifierState('AltGraph')` is true off Apple (Windows reports AltGr as Ctrl+Alt *with*
AltGraph; Linux reports AltGraph without Alt), or on Apple when Option is held without ⌘/Ctrl (the
Option-typed character rule). Add sweep vectors that press Alt+Shift+<letter>, Alt+Shift+<digit>
and Mod+Alt+Shift+<letter> on Windows/Linux and expect `null`, plus a unit case that an AltGr
keydown (`modifierAltGraph: true` with Ctrl+Alt) still seeds the editor. If Chromium on Windows
turns out to set AltGraph for a left Ctrl+Alt chord, say so in the implementer notes and route the
Mod+Alt+Shift residue to the 0027 registry checkpoint through WATCHLIST.md. The Alt+Shift+letter
family is freed either way.

**R1-2 (major) — the nightly `@perf` scroll probe fails as soon as it lands, and the
"pre-existing" claim was argued from a different surface.**
`client/e2e/specs/grid-glyphs.spec.ts:267-303`.
I ran it in the slot and it failed: in a 12-file Chromium e2e run, 18 long tasks over 50 ms (52–132 ms).
I also profiled the same 40+40 wheel steps with CDP on a dev server, with nothing else running: on `tree-grid-large`,
three runs gave long tasks [60,52,52], [65,53,55] and [55,53]. tm-icon frames (the TmIcon factory,
`draw`, `glyphTemplate`, `appendElements`, `resolveDirect`, `tmResolveIconSource`) accounted for
156–188 ms of 1.57–1.80 s busy time, about 10%. Flat `grid-readonly` with no tm-icon gave 46 and 48
long tasks of 50–94 ms. So the grid's scroll cost was already over the bar, and the claim largely
holds. But the expander does cost about a tenth of each frame, and that tenth is what pushes the
borderline 52–55 ms tasks over. The implementer notes compare against a 12-column flat grid,
not against the same tree with the old SVG expander, so they cannot show "the expander is not the
cause". Nightly runs the production build, where the notes already saw worse numbers. As committed,
the first nightly run after integration goes red and becomes an untracked stop-the-line triage item.
Fix: land the probe as `@quarantine`, or with the orchestrator's ruling, and add a LEDGER.md
"Flaky" entry that names the grid's scroll budget as the cause and queues a fix item. Record the
measured icon share (about 10% of scroll CPU on the expanded tree) in the implementer notes so the
fix item knows the expander is a minor contributor and not the root cause. Keep the 50 ms bar as
the spec writes it.

**R1-3 (minor) — the `./grid` budget note is stale and names no savings taken.**
`client/projects/core/tellma-core-ui/package.json:70`.
The measurement checks out: 38.71 KB under 39, a raise within D-031's round-up and within §C.11's
42. But the note's closing sentence still says the ceiling "has climbed 34 -> 35 -> 36 -> 37 -> 38
-> 38.5", which now omits 39. D-031 also asks the note to name the savings taken; the note only
nets out the deleted icon component and sniffs, which belong to the change itself. This is the
second raise of `./grid` under D-031 and the seventh overall. D-031's "revisit if a ceiling rises
three times" (re-split the entry point) is one raise away, and the orchestrator should see that
before PC-048. Fix: append "-> 39" to the history sentence and state the savings looked for and
not found (or taken). The primary note (8 -> 8.5, the 30 English labels, measured 8.12) is
accurate.
