# PC-043: Evaluation core: UserAccess.Decide, composition, owners, drift classification

## Implementer notes

### What was built, and where

- **Contracts** (`src/core/Tellma.Core.Abstractions/Access/`), the §5.1 set:
  - `AccessOutcome` (`Denied` is the default), `AccessProblemCode`.
  - The `AccessGrant` family: `RoleAccessGrant`, `BespokeAccessGrant`, `SystemAccessGrant`.
    `AccessGrant` is polymorphic JSON under `kind` (`role`, `bespoke`, `system`; an unknown kind
    fails), registered in `TellmaApiJsonContext`.
  - `AccessProblem`, `AccessDecision`, `AccessCriterion`, `IAccessCriteriaProvider`
    (`[CollectionService]`), `PermissionRow` (§7.1's shape).
  - Every record validates in its property initializers, so no shape can be built that
    contradicts the contract:
    - a filtered decision carries a filter and no other outcome does;
    - a denial lists no grant; an undefined outcome is refused;
    - a filtered role grant carries a supported stamp and an unfiltered one none;
    - a filter is never blank;
    - lists are copied and refuse null items.
  - Properties are get-only, so `with` cannot bypass the checks.
- **Evaluation**:
  - `AccessComposition` holds the §5.2 contract (steps 2–5) and §5.5's owner rule.
    - `Compose` is the stateless form for "who holds this".
    - `Matches`, `Direct` and `Finish` are shared with the set, so the two cannot disagree.
  - `UserAccess` is the cached set. Its members:
    - `Decide(securable, criteria, owner, now)` and `NextBoundary(now)`;
    - `MarkValidated`, a compare-and-swap max, ignored by `System`;
    - `ValidatedAt`, which defaults to `ComputedAt`;
    - `UserAccess.System`.
  - The direct side of each securable's decision is memoised until the next window boundary,
    keyed by securable and bounded at 4096 entries. Criteria and owner decisions are composed
    over the memo on every call.
  - Equality is identity, and a `with` copy gets a memo of its own.
- **Helpers** (Abstractions):
  - `AccessFilters`: `CurrentMembership` as a leaf, and `CurrentMembershipSql(alias)`, which
    refuses any alias that is not a plain ASCII identifier of at most 128 characters.
  - `QueryexProfiles`: `AccessLimits` and `PipelineLimits` (§12.2).
  - `AccessOptions` (§12.1), `AccessTelemetryNames` and `AccessEvents` (3100–3107).
  - `FilterTreeText` (internal) renders a criterion's tree for `BespokeAccessGrant.Filter`.
- **Build** (`src/core/Tellma.Core/Access/`):
  - `PermissionClassifier` runs the drift table in order. It validates each filter with
    `HasUser = true`, no parameters and `AccessLimits`, against the root's own entity, once per
    (root, text, stamp) per build.
  - `UserAccessBuilder.Build(tenantId, userId, tag, userTag, rows, schema)`:
    - classifies each distinct row shape once;
    - nulls public rows' windows;
    - drops memberships that have ended by `TimeProvider.GetUtcNow()`;
    - interns filters and role names (`AccessInterner`, bounded);
    - dedupes exact duplicates;
    - orders the grants (role, permission, start null-first, end null-last) and the problems
      (permission, code);
    - reports drift.
  - `AccessMetrics`: the set-build histograms and `permissions.unresolved` by `problem`.
  - `AccessLog`: `PermissionDrift` (Warning) and `AccessSetBuilt` (Debug).
  - `SecurableFilterRoots`: the root of a pair, or for `*` the root the resource's securables
    share.
  - `AccessRuntimeComposition` binds the options and registers the singletons. It is called
    from `CompositionPipeline`.
- **Registry and check**:
  - `ISecurableRegistry.FindResource` is new.
  - `core.securables` gains the shared-filter-root rule (see D3).

### Deviations

1. **D1: `AccessProblem` carries `Resource` and `Action`.** Spec §5.1 has
   `(PermissionId, RoleId, Code, Diagnostics)`. The pair is what lets a decision list the problems
   whose pair would have matched it. It is also what the drift log needs to name.
   - It holds the pair as far as it resolved: an alias resolved, the action's registered spelling
     once known, the stored text otherwise.
   - Problems are listed on every outcome, windows ignored.
2. **D2: `ISecurableRegistry.FindResource(resource)`.** It is alias-aware and returns the
   registered spelling. `Find(resource, action)` cannot resolve a `(FormerName, *)` row, and
   grants must carry the registered spelling so that matching and leaf dedup see one name.
3. **D3: New `core.securables` rule.** The securables of one resource that take a filter must
   share one filter root.
   - Spec §3.7 rule 2 binds an `(R, *)` filter against "the" root, which assumes one exists.
   - At run time, mixed roots classify `(R, *, filter)` as `FilterUnsupported`, which fails
     closed.
4. **D4: New `AccessProblemCode.WildcardResourceOnPublicRole`.** Spec §3.5 forbids `Resource = '*'`
   on a public role at save (`Permissions.WildcardResourceOnPublicRole`, which PC-078 owns). The
   build refuses such a row too, as defense in depth: a public role reaches every user, so a row
   saved before the rule, or written around it, would grant everyone everything.
5. **D5: `(*, A)` with an action no resource registers is `UnknownAction`.** §9's table speaks of
   `(R, A)` only. Without this, a misspelt action on `*` would still imply `Read` on every
   resource through the implied-read rule.
6. **D6: `AccessOptions` is validated by the `core.options` startup gate**
   (`OptionsRegistrar.Bind`, D-016), not `ValidateOnStart` as §12.1 says.
7. **D7: `PermissionRow` is declared here**, with §7.1's exact shape, because the builder consumes
   it. PC-050 should extend this declaration, not re-declare it.
8. **D8: Bespoke criteria and an owner's filter never reach a securable without a filter root.**
   §5.2 prunes only filtered role grants there. Extending the pruning fails closed: a filter that
   cannot bind must not become an unrestricted allow.
9. **D9: `UserAccess.IsSystem` has a private `init`.** §5.1 declares `{ get; init; }`. Only
   `UserAccess.System` and its `with` copies are system sets, so no code outside the type can mint
   a set that holds everything with an object initializer.

### Rulings worth a second look

- **A set without a user** (`UserId <= 0`) denies everything, criteria included. Since criteria
  grant on their own, PC-052 must short-circuit no-user callers before `Decide`.
  - Excluding inactive roles is the load's job (PC-050). `Decide` never sees an inactive role.
- **`Decide` throws** (`ArgumentException`) on programmer errors instead of denying silently:
  - a wildcard securable;
  - a null criterion;
  - an owner decision passed for a securable without an owner;
  - a missing owner decision for one with an owner;
  - an owner decision for another pair.
- **The evaluator passes a denial for an owner pair the registry does not hold** (the remark on
  `Decide`). The owner rule is then the direct side alone.
- **An engine exception during validation** (a defect, never bad input) classifies the row as
  `FilterInvalid`, carrying the exception on the drift log event.
- **The drift counter uses the same dedupe as the log**: once per (tenant, permissions tag,
  permission, code).
  - The memory is bounded at 16384 entries and clears when full, so a problem may be reported at
    most once more after a reset.
  - The interner clears the same way.
- **`BespokeAccessGrant.Filter`** is a rendering for display, not Queryex: each child is
  parenthesised, and `Via` and `Exists` print as `via(Nav, …)` and `exists(Entity, Nav, …)`.
- **The memo** is keyed by `SecurableDescriptor` value equality. Two descriptors that differ only
  in `IsSensitive` or `Feature` memoise separately, which costs space only.

### Open risks, and what to examine hardest

- **Fail-closed paths in `AccessComposition.Finish` and `Direct`**:
  - the `FilterRoot`-null pruning of grants, criteria and owner filters;
  - absorption only by an unfiltered candidate that is actually current;
  - the owner `Via` added only when the owner is `Filtered`.
- **`PermissionClassifier`'s order and the `*` cases**: `(*, *)`, `(*, A)`, `(*, A, filter)`,
  `(R, *, filter)` with mixed or no roots, and public rows.
- **The memo** (`UserAccess.DirectAt` and `IntervalAt`): a side memoised for `[From, Until)`
  must never serve an instant outside it, including instants before `From` after a later
  decision.
- **`AccessFilters.CurrentMembershipSql`**: the alias reaches SQL text.
- **JSON deserialisation of grants** goes through the constructors, so every invariant holds on
  the wire. Confirm that no grant arrives from a client in this checkpoint; the grants are
  server-produced.
- **Not covered**: the engine-exception path is not exercised by a test, because `QueryexEngine`
  is sealed and throws on no input this checkpoint can build. Stamp ordering across two versions
  is untestable while only version 1 exists.
