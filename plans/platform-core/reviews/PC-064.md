# PC-064: Row-set and related converters, key-typed entity envelope, route model and fingerprints

## Implementer notes

### What was built

- **Row-set converter.** `src/core/Tellma.Core.Abstractions/Api/QueryRowSetJsonConverter.cs`.
  - It writes `{ "columns": [...], "rows": [[...]] }`. `columns` is always present.
  - A column is `name`, `type`, `scale`, `nullable`, `path` and `groupingKey`. `type` is the `QueryexType` name without `Qx`. `scale` is omitted when null, `path` is omitted for a computed column, and precision is never written.
  - Cells are row-major. Each column's cell writer is chosen once from the buffer's element type, through `options.GetConverter(T)`. So `long[]` and `decimal[]` cells are strings, `int[]`, `short[]` and `byte[]` cells are numbers, and a hierarchy column's `string?[]` is its path. A null-masked cell is `null`.
  - An unknown buffer type is a `JsonException`.
- **Row-page converter.** `Api/RowPageJsonConverter.cs`.
  - It writes `{ rows, count, countCapped, ancestors }`. `count` is `min(Count, CountCap)` and `countCapped` is `Count > CountCap`. Both are absent when `Count` is null, and `ancestors` is absent when null.
  - `RowPage` gains `int? CountCap = null`, and `DataBatch.Rows` passes `options.CountCap` (deviation 1).
- **Related-entities converter.** `Api/RelatedEntitiesJsonConverter.cs`.
  - It writes entity name → array, with the sets in ordinal name order.
  - Each set takes one contract lookup. That contract is a fresh `JsonTypeInfo` over the type, holding copies of the projected members: JSON name, getter, custom converter and number handling are copied, and `ShouldSerialize` is always true, so a null projected member is written as `null` (spec 0016 §3.6's `"imageId": null`).
  - A member is matched to the projection by its CLR property (`AttributeProvider`), with a fallback through the naming policy. A projected column marked `[JsonIgnore]` is left out.
  - Contracts are cached per options instance (`ConditionalWeakTable`) by (type, sorted projection), up to 1024 per options.
  - `ProjectedMembers` is internal so the fingerprint describes exactly the members the converter writes.
- **Entities-result converter.** `Api/EntitiesResultJsonConverter.cs`, a factory and a generic writer.
  - The key type comes from the `Entity<TKey>` base. With an int key, ids are JSON numbers. With a long key, ids go through the options' `long` converter and become strings.
  - Entities are written by runtime type, so a derived leaf's members travel.
  - `related` goes through the related converter, and `extras` is written raw. Each extra was serialized under the same rules, so the `permissions` extra's `id` is already in the key type.
  - `related` and `extras` are absent when null.
  - A non-entity `TEntity` is refused with a `NotSupportedException` (deviation 3).
- **Registration.** All four converters are type-level `[JsonConverter]` attributes, on `QueryRowSet`, `RowPage`, `RelatedEntities` and `EntitiesResult<T>`. `TellmaApiJsonContext` lists `RowPage`, `QueryRowSet` and `RelatedEntities`, so the generated metadata carries each converter. `EntitiesResult<T>` is generic and resolves by reflection, as the context's remarks already state for generic records. All four are write-only: `Read` throws `NotSupportedException`. The options-level converter list is unchanged (deviation 2).
- **Problem-body display ids.** `Api/DisplayIds.cs`.
  - The public helper has `MaxSafeInteger`, `IsSafeInteger` and `Write`. An id is a number within ±(2^53 − 1), else a string.
  - Two internal converters, `DisplayIdJsonConverter` and `DisplayIdListJsonConverter`, read a number or a string back.
  - They are applied by attribute to `ConcurrencyConflict.Id` and `ConfirmationRequest.Ids`. This closes D-020's "strings until PC-064".
- **HierarchyId.** No CLR converter was added (deviation 4).
- **Route model.** It lives in `src/core/Tellma.Core/Api/`.
  - `IRouteContracts` and `RouteContract` are public, with the members spec 0016 §3.10 lists.
  - `RouteContracts` (internal, a lazy singleton over `IStackRegistry` + `IEntityMetadataProvider`) derives the routes in this order:
    - each stack's standard operations, as `Operations` and capabilities imply them: query, get-by-parent-ids for a tree, get, get-by-ids, all for a cacheable entity, save, delete, delete-by-query, delete-with-descendants for a tree;
    - then every one of the stack's `Actions`: built-ins, service actions and companions;
    - then each child surface's `query` and its `Actions`;
    - then each routed service's actions.
  - Bodies and results follow the 0016 §2.3 table. An entity action's body is `EntityActionRequest[<T>]` when it answers `EntitiesResult<leaf>`, `IdRequest[<T>]` when `SingleTarget`, else `IdsRequest[<T>]`. An API action's body is its `RequestType`.
  - Facts: the standard reads are idempotent non-mutations, the standard writes are non-idempotent mutations, and an action's facts are its descriptor's. `AllowWhenReadOnly` and `Long` are false for standard operations.
  - Securables: a standard operation's is (resource, Read/Save/Delete), an entity action's is (resource, `Action`), and an API action's is its `Securable`.
  - A duplicate template throws, since the registry's checks already prevent one.
  - `DescriptionOf(template)` is internal, for review and tests.
- **Fingerprint.** `Api/ContractDescriber.cs`.
  - It builds a canonical compact JSON: `{ request, response, revisions: { action, stack, surface } }`.
  - Types are described from `TellmaJson.Options` contracts:
    - scalars as kind:format (`integer:int32`, `string:int64`, `string:decimal`, …);
    - enums as sorted wire names, plus `flags`;
    - objects as members sorted ordinally, a nullable reference or value wrapped in `{ "nullable": … }`;
    - arrays, maps, polymorphic derived types by discriminator, and cycles as `{ "ref": n }`;
    - a member with its own converter, or a converter-only type, as `custom:<stable type name>`.
  - The platform envelopes are spelled out:
    - `RowPage` as its four members over `"row-set"`;
    - `EntitiesResult<T>` with ids in the key type and `related` as one projection per entity that the stack's `DetailsExpand` reaches. The projection is `StackDescriptorBuilder.RelatedSelect`, now internal, through the converter's `ProjectedMembers`.
  - Hash: SHA-256 of the UTF-8 description, base64url via `System.Buffers.Text.Base64Url`, first 12 characters. There are no assembly versions and no platform-dependent text.
  - The child surface revision is the root stack's `ContractRevision` plus the child type's own `[ApiResource].ContractRevision` (deviation 5).
- **Contributor.** `Api/ContractsClientAssetContributor.cs`. It writes the Contracts chunk's `fingerprints`, `long` and `idempotent` sections in route order. `CoreFeature` registers it, with the `IRouteContracts` singleton.
- **Docs.** The `Tellma.Core` README gains "The route model" and an `Api/` layout row. The `Tellma.Core.Abstractions` README's Api and Data rows are updated, and so are both test READMEs. ARCHITECTURE.md already agrees, so it is unchanged.

### Deviations

1. **`RowPage.CountCap`.** The converter has to write `count = min(Count, cap)` and `countCapped = Count > cap`, which needs the cap. Spec 0012's `RowPage(Rows, Count, Ancestors)` does not carry it, so a fourth positional member `int? CountCap = null` was added. `DataBatch.Rows` sets it from `RowQueryOptions.CountCap`. Without a cap, the count is reported as is and `countCapped` is false.
2. **Registration through type-level attributes.** The converters are `[JsonConverter]` attributes on the types themselves, not entries in `TellmaJson.Configure`'s converter list. The context lists the three non-generic envelopes, so "registered in TellmaApiJsonContext" holds through the generated metadata. A host's own options always pick them up, and the converter-order test is unchanged.
3. **`EntitiesResult<T>` over a non-entity is refused.** There is no key type to write its ids in. `CrudWireRecordTests`' old non-entity `Row` case now uses an entity.
4. **No HierarchyId CLR converter.** The planner note asked this checkpoint to own it. But no CLR `HierarchyId` can reach the wire:
   - the tree's `Node` is an EF shadow column, never a member;
   - the row-set builder buffers a `QxHierarchyId` column as `string?[]` (its path).

   So the row-set converter owns the path-string encoding, and a converter for `Microsoft.EntityFrameworkCore.HierarchyId` would be dead code that Abstractions could not register anyway. If a later checkpoint exposes a CLR hierarchy member, add the converter there.
5. **Child-surface revision.** `ChildQueryDescriptor` has no `ContractRevision`, and spec 0016 §3.10 names only the stack's and the action's revisions. A child surface's endpoints therefore take the root stack's revision, found by walking `OwnerResource` up through the surfaces, plus the child type's own `[ApiResource(ContractRevision)]`. The two are separate inputs (`stack`, `surface`).
6. **`get-by-parent-ids` response type is `RowPage`.** The service answers a bare `QueryRowSet`, and the wire wraps it in the rows envelope (§3.5). `RouteContract.ResponseType` is what the wire writes, so the projector (PC-080) must wrap the row set as `new RowPage(rows, null, null)`.

### Open risks

- **Every `query` route has one fingerprint.** A row set's columns describe themselves, so a stack's entity shape does not enter the `query` description; every stack's `query` route shares one fingerprint. A stale tab that queries a renamed column gets a 400 `query-invalid`, never a silent write. Spec 0016 §3.10 asks only for the request/response contracts, but the orchestrator may want the stack's queryable shape folded in.
- **Related projections in the fingerprint are derived statically.** They come from the stack's `DetailsExpand` and each target's `RelatedSelect`. The runtime set's projection is what the details pipeline (PC-033 and later) actually carries, so if that pipeline selects a different projection, the fingerprint will not move with it.
- **Excel routes.** There are no `export`/`import` routes yet. They appear automatically once `ExcelOperations<T>` companions add their actions to `StackDescriptor.Actions`, and child-surface exports once `ChildQueryDescriptor.Actions` is filled.
- **Out of scope here.** `ContractMetadata` stamping, `TellmaContractMiddleware` and the `contracts.json` snapshot test belong to PC-080 and the distribution suites.

### What reviewers should examine hardest

- The canonical description's completeness and stability: `ContractDescriber.Write` and `WriteMembers`. Check the nullability source (`JsonPropertyInfo.IsGetNullable`), the enum wire names, the cycle refs and the `custom:` naming.
- The related-projection contract copy in `RelatedEntitiesJsonConverter.Build`: is anything a member carries lost (an ignore condition, a number-handling override, a converter)?
- The route derivation against spec 0016 §2.3 and spec 0015 §2.3: operation gating by capabilities, entity-action body selection, securables and facts.
- The display-id rule's boundary, and the read side's refusals.

No change to the shared fixture entities, the Acme tenant model or any migration. `RowPage` gains a member (Abstractions), and `CoreFeature` registers two new singletons, so any host composition now resolves `IRouteContracts`.
