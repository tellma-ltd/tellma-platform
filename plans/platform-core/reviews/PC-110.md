# PC-110: Service worker updates, error presentation and session paths

## Implementer notes

### What was built, and where

All client-side; no C# changes. Paths are under `client/projects/core/` unless noted.

- **`@tellma/core/updates`** (new lazy entry, spec 0024 §5.4, §5.5; spec 0028 §9.5),
  `tellma-core/updates/src/`:
  - `tm-worker-registration.ts`: `tmRegisterWorker` registers `/ngsw-worker.js` at the root with
    `updateViaCache: 'none'` through a `TrustedScriptURL`. The `tellma` Trusted Types policy is
    created once per document, only when the browser has Trusted Types, and admits exactly the
    same-origin worker script (anything else throws). Registration waits for the app to settle,
    at most 30 s, and reports a refused registration to telemetry.
  - `tm-updates.ts`: `TmUpdates` (`enabled`, `version`, `available`, `checking`, `check`,
    `update`, `reload`). `check()` reads the event that arrives during Angular's
    `checkForUpdate()` (ready / none / failed / unreachable / disabled), joins a check in
    progress, and answers `ready` at once while a newer version waits. `VERSION_READY` sets
    `available`, emits `tm.sw.update-ready { fromVersion }` once and shows the `tm.update` banner,
    dismissible per version, with Reload; `unrecoverable` reloads at once; install failures emit
    `tm.sw.install-failed`. Checks run when the tab comes back after an hour hidden and every 6
    hours while visible. `SwUpdate` comes from `provideServiceWorker` in a child environment
    injector with registration disabled, since `tmRegisterWorker` registers itself.
  - `TM_API_UPDATES` (primary, `src/api/tm-api-seams.ts`) now loads this entry on the first
    `check()`/`update()` and gained `update()` and `reload()`. `reload()` needs nothing loaded.
    `TM_UPDATES_LOAD` is the loader the startup and the seam share; `tmStartup` starts
    `TmUpdates` after the first render beside the recents and the leader election.
- **`@tellma/core/errors`** (new lazy entry, spec 0024 §11), `tellma-core/errors/src/`:
  - `tm-error-view.ts`: `TmErrorView`, `TmErrorAction`, `TmErrorContext`, and the WeakMap from a
    view to its error (so the state component can run a step-up without importing the
    presenter, which would be a cycle).
  - `tm-error-presenter.ts`: `describe()` (the §11 table: forbidden reasons with the
    permission's label and the raw pair, a refused path named from the query root, read-only and
    frozen with the tenant's name, items, the problem's own title) and `present()` (cancelled and
    unauthenticated stay silent; step-up asks via `TmConfirm` then signs in with the call's
    challenge; tenant-not-found sweeps `{ tenant }`, clears `lastTenantId`, takes the automatic
    entry and goes to the picker with a notice unless the entry was automatic, once per tenant;
    tenant-unavailable replaces the routed page with the tenant-state page; reads return for the
    page to render inline; everything else reports when reportable, registers an overlay page
    context, and opens the 5xx or the 400 dialog, one at a time). Reload in the 5xx dialog runs
    `update()`, busy as "Getting the update…", says when the download fails, and offers
    "Reload anyway" (primary/secondary) from the second failure.
  - `tm-error-state.ts`: `tm-error-state`, the inline view (empty state, items, the raw pair in a
    left-to-right `bdi`, `tm-reference`, actions with the same Reload flow).
  - `tm-error-strings.ts`: the `errors` scope's English strings; Arabic in
    `projects/locale/tellma-locale-ar/strings/strings-tm-ar.ts`.
  - `TM_SYNC_ERRORS` (primary, `src/state/sync/tm-cache-refresher.ts`) now loads this entry and
    hands the error to the presenter as a read of the partition's tenant.
- **Session paths** (spec 0024 §8.4-§8.8):
  - `src/session/tm-session-paths.ts` (primary): the state signal, bus routing from the start,
    the expiry entry (once per tab, guarded during sign-in), changed user, signed out elsewhere,
    sign-out, and fallbacks that reload or replace to `/` when the flows chunk fails to load.
  - `src/session/tm-session-flows.ts` (lazy chunk of the primary, preloaded after the first
    render): sign-out (busy overlay at once, `drafts.query` every second while any tab saves, at
    most 60 s, one confirm about what is still at risk, telemetry flush,
    `session.signing-out`, `/bff/logout`, clean-up, `session.signed-out`, a failure toast that
    restores the session); the other tabs' signing-out overlay lifted after 15 s without a
    `signed-out`; the signed-out page; signed out elsewhere (the leader's hub
    `session-terminated`, wired in `leader/src/tm-leadership.ts`); the expiry path (clean-up with
    the 1 s sweep box, the stale cookie, the broadcast, the session-ended alertdialog, or the
    sign-in-failed page right after a sign-in); the changed-user path; the re-checks on
    `visibilitychange`, `pageshow` and the 15 s lift.
  - `drafts.reply` (D-216, D-218): answered from `TmDrafts` when it exists (its dirty count and
    busy flag), else from the session-storage keys. `TmStateDump` lists those keys too while
    `TmDrafts` is not loaded (`src/state/tm-state-dump.ts`, `src/state/memory/tm-draft-keys.ts`).
  - `TmSession.signOut()` is public; `TmFakeSession` gained `signOut()` and `signOuts`.
  - The session unit specs' providers (`tmSessionTestingProviders`) now record the flows
    (`TmRecordingSessionFlows`). The real flows need the whole app, and their own spec runs them
    in the test app. So the guard and HTTP specs assert the hand-off (`expired`, `changedUser`)
    rather than the interim bodies' sign-in or replace.
- **Route errors** (`src/routes/tm-route-error.ts`): Reload runs `TM_API_UPDATES.update()` with
  the busy, failure and "Reload anyway" flow, in the primary because it is a first-frame view.
- **Error dialog** (`tellma-core-ui/error-dialog`): a detail may be a `code`, shown mono and
  left-to-right in a `bdi` (the raw permission pair in the 400 dialog).
- **Tooling**: `scripts/bundle-size.mjs` starts the static-graph walk at the output built from
  the entry's FESM (it picked an arbitrary output before, which reported a false
  "'.' reaches './leader'"). `tellma-core-tools`' `TM_CORE_ENTRY_POINTS` lists `./updates` and
  `./errors` as lazy entries. `tsconfig.lazy-entry-points.json` and the `package.json` budgets
  cover both entries and the flows chunk.
- **Docs**: `tellma-core/README.md` (entry table, session paragraph, seams, new "Service worker
  updates" and "Error presentation" sections) and `ARCHITECTURE.md` (the two lazy entries and the
  flows chunk).

| `.` chunk `tm-session-flows` | 3.03 | 3.5 (new) |

Every ceiling change has its `budgetNotes` entry.

The candidates I considered for the primary, with their approximate gzip cost (measured by ablation
on the built FESM):

- **Taken lazy** (each a deviation from spec 0024 §1):
  - the session flows (about 3 KB), into the `tm-session-flows` chunk;
  - the error presenter, table, dialogs and tenant-state view, into `./errors`;
  - TmUpdates, the worker registration, the Trusted Types policy and the update banner, into
    `./updates`;
  - the re-check triggers, moved into the flows chunk (-0.05).
- **Kept in the primary**, each because a first-frame caller needs it:
  - the route error view's Reload flow (about 0.20): a route fails exactly when chunks may not
    load, and the busy state must show in the click's frame.
  - The `TM_API_UPDATES` seam with `update`/`reload` (about 0.08): the outdated-client verdict
    and the route error view call it.
  - The three update strings (about 0.06): Reload's busy label and failure must read even when
    `./errors` cannot load.
  - The `TM_SYNC_ERRORS` loader (about 0.04): every sync's tenant errors.
  - The paths' fallbacks and the once-per-tab expiry guard: without them, a failed chunk load
    leaves an expired tab rendering data.
  - The drafts session-storage fallback of the dump: required by D-218.

**The honest minimum does not fit.** With about 1.8 KB reserved for PC-115, PC-119 and PC-F78,
"." projects to about 50.5 KB, over the 50 KB cap. Under D-252, PC-115 now has to find about
0.97 KB of savings rather than 0.49 to reach 49.5. I did not cut spec behaviour to avoid this. The
outdated-client verdict machinery in TmHttpApi (0.3 to 0.4 KB by PC-F78's reviewer's estimate) is
the largest candidate outside my code that I left alone.

### Deviations

1. **Placement.** TmUpdates, the worker registration and the Trusted Types policy live in the
   lazy `@tellma/core/updates`. TmErrorPresenter, `tm-error-state` and the step-up dialog live in
   the lazy `@tellma/core/errors`. The session flows live in a lazy chunk of the primary. Spec 0024
   §1 places all of them in the primary; they moved for the primary's 50 KB cap.
2. **The update banner's source is in TmUpdates (`./updates`), not in `tmPlatformBanners()`.** Its
   `refresh-cw` icon registers there rather than in TM_PLATFORM_ICONS, and its message is
   `tm.updates.banner` rather than under `tm.attention.banners`. The banner still shows from the
   app's first settle, with the id `tm.update`, level 3, dismissible per version, and Reload
   running `reload()`.
3. **The error views' icons** (circle-alert, clock, lock, refresh-cw, search-x) register in
   `./errors` when no feature drew its own, not in TM_PLATFORM_ICONS.
4. **`SwUpdate` comes from `provideServiceWorker` in a child environment injector**, with Angular's
   registration disabled. `tmRegisterWorker` registers itself through a TrustedScriptURL, because
   Angular's registration passes a plain string, which the CSP's Trusted Types refuse.
5. **`NO_NEW_VERSION_DETECTED` naming a version other than the running one reads as `ready`.**
   The `VERSION_READY` that announced it may have reached the worker before this tab listened.
6. **TmUpdates runs no check of its own at start.** The worker checks `ngsw.json` itself at
   registration and on navigations (§5.5's first row).
7. **`TmErrorView` gains `permission`**, the raw pair rendered in a left-to-right `bdi`, and
   **`TmErrorContext` gains `tenantId`**, so a background sync of a tenant other than the routed
   one is handled for its own tenant. **`TM_SYNC_ERRORS.present` takes that tenant id.**
8. **The error dialogs' support actions (Copy diagnostics) are not wired.** They wait for the
   support service of spec 0026.
9. **The tenant-state page is `tm-error-state` itself**, replaced into the shell's main area for
   `tenant-unavailable`.
10. **The `errors` strings scope merges into the existing `tm.errors`.** Reload's three strings
    stay in the primary's English table.
11. **Order of the expiry path.** The session turns `expired` before the clean-up runs, not after,
    so nothing renders the user's data while the flows chunk loads.
12. **The session-ended alertdialog ignores Escape and has no close button.** Only Sign in leaves
    it, because the session is gone. This departs from the Done-when's "Escape" for this one
    dialog.
13. **The 1 s sweep box also bounds sign-out's clean-up**, not only the expiry's. A sign-out
    clears the boot record's user and last tenant whether or not the sweep applied, so the next
    launch sweeps again when it did not.
14. **A tab that hears `session.signed-out` runs its own tab-local clean-up** before it shows
    the signed-out page: its session storage and the user's drafts. The signing-out tab already
    swept the shared stores.
15. **The changed-user path keeps its telemetry flush** before it leaves.
16. **`session.started` for the same user reloads only the tabs whose session is not active.**
17. **`pageshow` re-checks without looking at `persisted`.** After the chunk has loaded, any
    `pageshow` is a return from the back-forward cache.
18. **Tooling.** `scripts/bundle-size.mjs` starts its static-graph walk at the output built from
    the entry's FESM. It had picked an arbitrary output before, which reported a false
    "'.' reaches './leader'".

### Open risks

- The primary budget (see above): the reserved 1.8 KB no longer fits under 50 KB.
- `TmUpdates` against a real worker is covered only by the scripted `SwUpdate` fake here; the
  e2e updates flow (PC-114) is the first real-worker run. Angular's `NO_NEW_VERSION_DETECTED`
  carrying another version than the running one is read as ready, which relies on Angular's
  current event semantics.
- The flows chunk is preloaded after the first render; an expiry or a bus message before it
  loads waits on the import (the state turns `expired` first, so nothing renders stale data).
- `pageshow` re-checks without looking at `persisted`, so an ordinary load also re-checks once;
  this is cheap (one cookie read) but worth a glance.

### What reviewers should examine hardest

1. `tm-session-flows.ts` `#signOut` and `#wait`: the drafts loop, the 60 s cap, the confirm
   variants, and that a cancel or failure leaves every tab usable (the lift, the toast, the
   restored state).
2. `#cleanUp`: what is kept for expiry versus sign-out, and the `sub: null` rule when the sweep
   does not apply (the PC-075 carry).
3. `TmUpdates.check()`: the event-during-check detection, joining a running check, and the
   `NO_NEW_VERSION_DETECTED` tie with another version.
4. `TmErrorPresenter.present()` tenant-not-found and tenant-unavailable: the per-tenant guard,
   `replaceUrl` only when routed, and the sweep.
5. The lazy placements against spec 0024 §1's entry list, and whether any first-frame caller
   now waits on an import it should not.
