# PC-058: tm-entity-multi-picker

## Implementer notes

### What was built, and where

All paths are under `client/projects/core/` unless stated.

- **Emit mode in the single picker** (`tellma-core-ui/entity-picker/tm-entity-picker.ts`). The seam
  §E.2 calls "the inner picker in emit mode" did not exist (PC-057 shipped no `ɵcommitMode`), so it
  is built here, as internal inputs and outputs that bind in templates but stay off the public
  surface:
  - inputs `ɵcommitMode` (`'value'` default | `'emit'`), `ɵchosenIds`, `ɵmaxItems`, `ɵnotice`;
    outputs `ɵdeselect` and `ɵmultiPick`.
  - **Commit.** In emit mode `applyPick` retires the settled answer, empties the text, keeps
    `value` null and emits `picked`. A list pick or Enter keeps the panel open and re-browses
    quietly (no result-count announcement); blur, Tab and create commits close it.
  - **Toggle.** A list pick or Enter on a chosen row emits `ɵdeselect` instead; auto-resolution
    and Tab on a chosen id never remove (the host ignores the duplicate).
  - **Listbox.** `[multi]` in emit mode (aria-multiselectable), and effect 5 bridges the whole
    `ɵchosenIds` array into the listbox selection so chosen rows show the check and
    `aria-selected`.
  - **Notice row.** `ɵnotice` renders as an aria-hidden hint row (the cap message while full).
  - **Advanced search.** In emit mode the page data gains `{ multiple: true, ids, maxItems? }`. A
    `TmEntityMultiPick` outcome emits `ɵmultiPick`; in value mode it is ignored. A single
    `TmEntityPick` from the page still adds.
  - **Required.** Native `required` is off in emit mode (chips can satisfy it); `aria-required`
    carries it instead.
  - **Anchor.** `originElement()` also accepts `[data-tm-field-box]`, so a standalone
    multi-picker's panel aligns to its own box.
- **`TmEntityMultiPick<Id, T>`** (`tm-entity-picker-types.ts`): `{ ids, picks }`.
- **`TmEntityMultiPicker`** (`tm-entity-multi-picker.ts`, `.css`).
  - `FormValueControl<readonly Id[]>` with the aliased state inputs, `TM_FORM_FIELD_CONTROL`
    (`ownsChrome=false`, the inner picker's id, error glyph and describedby), standalone box
    chrome on the size ladder.
  - `tm-chip-set overflow="scroll"` of removable `tm-chip`s sized from the field, then a
    fixed-width `tm-counter` badge (a hidden "99+" probe in the same grid cell holds its width),
    then the inner picker in emit mode. One line at the field's fixed height for any count.
  - Labels: `displayWith`, then a memo of pick labels, then `String(id)` with one development
    warning.
  - `picked` / `removed` outputs; `maxItems` refusal with `entityPicker.maxItems`, announced
    and shown as the panel's notice row; the hidden `selectedSummary` in the input's
    `aria-describedby`; polite announcements `announce.added` / `announce.removed`
    (`Intl.ListFormat` for several), spoken through the inner picker's live region (its new
    internal `ɵannounce`, ungated by the popup state) so one control has one region.
  - Keyboard (a host capture-phase listener, because aria's combobox stops the arrows'
    propagation while the panel is open): backward arrow at caret 0 and Backspace in the empty
    input call `focusLast()`; the chip set's `exit('end')` returns to the input; held
    Backspace/Delete repeats on chips are swallowed.
- **Strings**: `maxItems`, `selectedSummary`, `announce.added`, `announce.removed` in
  `strings-en.ts` and `strings-ar.ts` (Arabic plurals with `zero`).
- **Public surface**: `TmEntityMultiPicker` and `TmEntityMultiPick` from
  `@tellma/core-ui/entity-picker`; `TmEntityMultiPickerHarness` from `@tellma/core-ui-testing`.
- **Docs**: `tm-entity-multi-picker.examples.ts` (InField, WithAdvancedSearch, Standalone)
  registered in `docs-examples.spec.ts`; core-ui and testing READMEs.
- **Showcase** (`internal/showcase/src/app/entity-picker/entity-picker-story.ts`): a "Several
  suppliers" section (field-wrapped picker with advanced search and create, a bare capped one,
  fill 30 / fill 1 / clear buttons, a removed counter) and `DemoMultiSearchPage`, a checklist
  page that adds and removes in one visit and keeps Done disabled over the cap.
- **Tree-shake gate** (`client/scripts/bundle-size.mjs`, `client/tools/bundle-measure.mjs`,
  core-ui `package.json` `"tellma".treeShakes`). `size:check` now bundles an app module that
  imports only `TmEntityPicker` from `./entity-picker` and fails if `tm-entity-multi-picker`
  survives. That bundle runs `@angular/build`'s own advanced optimizations (pure top-level
  marking, metadata elision, enum and static-member wrapping) after linking, loaded by file path
  from the installed package: without the static-member wrapping no linked component can ever
  be dropped (its `static ɵcmp = ɵɵdefineComponent(...)` is a side effect to a bundler), so the
  plain measure pipeline kept the multi-picker (58,774 B raw) and the optimized one drops it
  (43,861 B). The size measure itself is unchanged (D-067's linked measure).
- **ARCHITECTURE.md**: one sentence on the tree-shake check beside `staticGraphExcludes`.

### Deviations

1. **The emit-mode seam is built here.** §E.2 assumes the single picker already has it; PC-057
   did not ship it.
2. **The count badge sits after the chips** (inline end of the chip row) and is hidden at 0,
   with the summary also left out of `aria-describedby` at 0.
3. **A refused pick at the cap still empties the input**, like an accepted one; the refusal is
   announced and shown as the panel's notice row while the selection is full.
4. **Native `required` is off on the input in emit mode**; `aria-required` replaces it.
5. **Advanced-search ids are deduplicated**, and a result over `maxItems` is accepted with a
   development warning (the page owns the cap; the picker never drops ids silently).
6. **A single pick from an advanced page adds in emit mode**; a multi pick reaching a
   value-mode picker is ignored.
7. **The browse list after an emit-mode commit is quiet** (no result-count announcement), so
   the "added" announcement is not talked over.
8. **Held Backspace/Delete repeats on chips are swallowed** (one press, one removal).
9. **Touched includes leaving the input for a chip** and leaving a chip for outside the host.
10. **Several additions or removals are announced as one list** (`Intl.ListFormat`, unit/short),
    and a page result that both adds and removes announces the summary.
11. **The chip set stays mounted (display: none) while empty**, so `exit('end')` and
    `focusLast()` always have a target.
12. **Leaving the input for the chips resolves its typed text**, exactly as any departure does:
    ArrowLeft at caret 0 with "Bo" typed adds the unique match after focus has moved.
13. **Signal Forms' `required()` treats `[]` as a value.** It sets `aria-required` but never
    raises an error for an empty selection; a form that needs at least one entity adds a
    length validator returning `requiredError()`. Documented on the `required` input; the unit
    test's required host does exactly that.
14. **Examples live in `tm-entity-multi-picker.examples.ts`**, beside the single picker's.
15. **Development warnings in both pickers sit behind `ngDevMode`**, not `isDevMode()`, as
    `l10n/tm-instant.ts` already does: a production build folds the flag and drops the warnings'
    text (-0.49 KB), while `isDevMode()` is a call into @angular/core no bundler can fold. Same
    semantics in every Angular build. This touches the single picker's three existing warnings.
16. **One live region.** The multi-picker announces through the inner picker's region instead
    of its own (-0.05 KB, and a result count and an addition never compete in two regions).
17. **The tree-shake check loads `@angular/build` internals by file path** (see above). An
    upgrade that moves them fails the check loudly.

### Open risks

- Emit mode threads through the single picker's resolution machinery (settled answers, quiet
  browse, keep-open). The single-picker suite passes unchanged and its search-lifecycle block
  re-runs in emit mode, but every future change to `applyPick`/`resolveText` must consider both
  modes.
- The fixed-height line relies on `tm-chip-set` scroll mode; very narrow fields keep the search
  region (input plus magnifier) at `--space-20` and scroll the chips to nothing visible.
- Signal Forms' empty-array `required` gap (deviation 13) will surprise consumers; PC-119's
  `tm-entity-multi-field` should wire the length validator itself.

### What reviewers should examine hardest

- `tm-entity-picker.ts` `resetForNextPick`, `applyPick` and the `activateActive` toggle: the
  panel open/closed state after each commit kind, and that value mode is untouched.
- The capture-phase keydown in `tm-entity-multi-picker.ts`: aria's `KeyboardEventManager` stops
  the arrows' propagation while the panel is open (its default `stopPropagation: true`), so a
  bubbling `(keydown)` on the inner picker never heard ArrowLeft there; the capture listener
  must not interfere with the inner picker's own key handling.
- The tree-shake check's use of `@angular/build`'s Babel plugins with the options a production
  build gives a `sideEffects: false` package (`topLevelSafeMode: true`, `wrapDecorators: true`).
- The badge's fixed width (value and "99+" probe in one grid cell) and the one-line height
  with 30 chips (e2e).
