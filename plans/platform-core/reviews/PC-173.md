# PC-173: Excel contracts, cell codec, number formats and the workbook/table writer

## Implementer notes

### What was built

- **Package.** `DocumentFormat.OpenXml` 3.5.1 (MIT, Microsoft) pinned in `Directory.Packages.props` and referenced by `Tellma.Core` only. It is the licence and package spec 0019 names. No other package was added.
- **Abstractions contracts** (`src/core/Tellma.Core.Abstractions/Excel/`, all public, golden updated):
  - The wire records of §2.1: `ExportSourceRequest`, `ExportRequest` (`MaxColumns = 100`) with `ExportColumn` (`MaxHeaderLength = 255`), `ExportForImportRequest` with `ExportCollection`, `ExportKind`, `ExportOutcome`; `InspectImportRequest`, `ImportRequest`, `StartImportRequest`, `ImportMode`, `ImportSheetMapping`, `ImportColumnMapping`; `ImportPlan`, `ImportPlanSheet`, `ImportPlanColumn`, `ImportSheetStatus`, `ImportColumnStatus`, `ImportOutcome`.
  - The records with invariants guard them with `field`-backed init accessors (counts non-negative, sheet and column names non-blank, lists copied with null entries refused). The request classes stay plain bindable DTOs; the stacks validate them (PC-175/177).
  - `ExcelOptions` (§14.1): `SectionPath = "Tellma:Excel"`, `MaxWorksheetDataRows = 1,048,575`, the defaults, and `IValidatableObject` with every rule of §14.1. Each failure names the setting and its bound.
  - `ExcelErrorCodes` (Appendix A, plus one new code, deviation 3) and `ExcelTelemetryNames` (§14.3, with the shape tag values).
  - `TellmaApiJsonContext` now lists the five Excel requests, `ImportPlan`, `ImportOutcome`, and `ImportError` and `RowRange` (which ride a problem body). The context-metadata theory covers them.
- **Runtime contracts** (`src/core/Tellma.Core/Excel/`, public): `ExcelContext`, `ExcelColumnSpec` (+ `ExcelColumnRole`, `ExcelKeyKind`), `ExcelDateEncoding`, `ExcelSheetPlan`, `ExcelWorkbookPlan` (shape Display or ForImport, the parent sheet first and only first, the manifest kept in order), `ExcelTableSpec`, `ExcelTableRow` (`MaxIndent = 250`), `ExcelRowStyle`, `IExcelExporter`, and `ImportCheckpointState`. All are validated records.
- **Cell codec** (internal):
  - `ColumnEncoding` resolves each column once: its value kind (from the property's CLR type, else the Queryex type), its number format, width, validation list, text length check, and what the manifest records of a date column.
  - `CellCodec.Encode` covers every §3.1 row:
    - An editable `long` is text. An editable decimal beyond 15 significant digits is text, counted on the normalised value so a scale's trailing zeros are not digits.
    - A non-finite double is text.
    - An enum or value set is its label in display and its stored value when editable.
    - A date is a serial. A date before 1 March 1900 is ISO text (deviation 6).
    - A `DateTimeOffset` is a display-zone serial in display, and ISO text with its offset when editable.
    - A time is its fraction. A GUID is "D" text. Binary is blank. A stamp is its wire string.
    - Text is cut to 32,767 characters in display and refused when editable (deviation 3).
  - `CellCodec.Decode` reads by the mapped type:
    - Blank cells are null and error cells are refused. Strings are trimmed unless whitespace is preserved, and numbers render invariant (`R` for doubles, plain for integers).
    - A choice matches its stored value ignoring case, else a label. A boolean reads the words, a boolean cell, 0/1, or a label.
    - A decimal is a number cell taken through `(decimal)double`, so it keeps 15 digits, or invariant text without thousands separators. A scale overflow is refused.
    - An integer is exact up to 2^53, with overflow refused. A double is read as it is.
    - A date reads a whole serial (1900 or 1904 system, refused at 60 and below), ISO text (including a `t="d"` midnight), text in the manifest's calendar and culture, and then the request calendar's short pattern.
    - A date and time reads a serial with its fraction (rounded to the millisecond), ISO forms, or a calendar date.
    - A `DateTimeOffset` reads ISO with an offset or `Z`, else a wall clock in the display zone. A time the zone skips is refused.
    - A time reads a fraction or `H:mm[:ss]`. A GUID reads "D" or "B".
    - Every refusal carries `expected` and `value`, the value cut to 100 characters without splitting a surrogate pair.
  - `CellReader` maps an Open XML `Cell` to a raw cell. It handles shared strings through a callback (for PC-176's store), inline strings including rich runs (phonetic runs are skipped), `str`/`b`/`d`/`e`/`n`, a formula without a cached value as blank, and `_xHHHH_` unescaping.
  - `XmlStrings` writes `_xHHHH_` escapes for characters XML forbids and lone surrogates, and `_x005F_` for an underscore that would read as an escape.
- **Number formats** (`NumberFormatBuilder`):
  - Numbers are `#,##0` / `#,##0.0…` in display and `0` / `0.0…` when editable. Booleans and doubles are `General`, text is `@`, and a time is `hh:mm:ss`.
  - A date is the culture's cleaned short pattern (deviation 7), translated token by token, behind `[$-CCLLLL]`. A Gregorian request has no `CC`; an Umm al-Qura one has `17`. A culture without an LCID gets `0000` (deviation 5).
  - A date and time appends the long time pattern, with `tt` → `AM/PM`.
  - A calendar without a Windows id (`et`) writes text with `@`, and the manifest records the calendar's short pattern.
  - Literals are quoted. Built-in formats take their ids.
- **Stylesheet** (`StylesheetBuilder`):
  - Each distinct style is one `cellXfs` entry, and each distinct custom code one `numFmt` from id 164.
  - Fonts are regular, bold and italic. Fills are none, `gray125`, and the lightest solid fill. Borders are none and a double top.
  - An indent is aligned from the edge text starts at: right on an RTL sheet.
- **Package and sheets:**
  - `XlsxPackage` writes a `ZipArchive` in create mode, forward-only, with hand-written content types and relationships. Entries are stamped with `context.Now`, never the clock.
  - `WorksheetWriter` streams through `OpenXmlWriter`, reusing element instances. Each sheet gets:
    - a frozen pane with its selection, `rightToLeft` and `tabSelected`;
    - column widths, styles and hidden columns;
    - inline strings with `xml:space="preserve"` when the text has whitespace at either end;
    - in schema order: sheet protection, the auto filter, and data validations (lists, or `textLength ≤`) from the first data row to row 1,048,576.
- **Writer** (`WorkbookWriter`, internal; the engine `IExcelExporter.WriteAsync`/`WriteTableAsync` will call in PC-175):
  - Data sheets go in plan order.
    - The parent sheet streams into its part as pages arrive.
    - Each child sheet spools to its own delete-on-close scratch file and is copied in after the parent.
    - Child sheets are mapped by reference to the parent query's dependents at any depth. A stray or shared query is an `ArgumentException`.
  - The hidden `_tellma` manifest comes last and is sheet-protected. It holds the header block in order, a blank row, then the column table (12 columns, the written sheet names, `KeyKind` on `Reference` rows only).
  - The workbook part is written with `date1904` false, `activeTab` 0, and a `_xlnm._FilterDatabase` per sheet. Every data sheet has a bold frozen header and an auto filter.
  - Editable sheets get validation lists (booleans, and choices when the joined list is at most 255 characters with no comma or quote) and `textLength` checks for declared lengths. The stamp column is hidden. Sheets are right-to-left for an RTL culture.
  - Caps:
    - The parent's cap is `CountCap ?? Take − 1 ?? MaxExportRows`, capped at 1,048,575.
    - The first page's `Count > cap` throws before any row.
    - The row past the cap throws, and every child sheet is capped at `MaxExportRows`.
  - A page whose dependents are not parallel, or a row not as wide as its sheet, is an `InvalidOperationException`. Every spool is released on success and on failure.
- **`WriteTableAsync`** (static):
  - Header rows are bold, with every cell its own. The pane freezes below the header rows and after `FrozenColumns`, and the filter sits on the last header row.
  - Row styles map as follows: Phantom italic, Subtotal1 bold on the lightest fill, Subtotal2 bold, Subtotal3/Normal regular, Total bold with a double top border. A styled row writes its blank cells too, so its band is unbroken.
  - The indent goes on the first cell. Cells encode as display cells with the spec's formats.
  - There is no manifest. A row not parallel to the columns is an `ArgumentException`, and rows beyond a worksheet are a `LimitExceededException`.
- **Helpers:**
  - `SheetNames` scrubs `/\?*:[]` and control characters, trims apostrophes, cuts to 31 characters without splitting a pair, reserves `History`, and makes names unique ignoring case with ` (n)`.
  - `ExcelFileNames.Compose(stem, fallback, now, zone)` builds `<ascii stem> yyyy-MM-dd HHmm.xlsx`; the stem falls back to `report` for tables and to the entity's technical name, which PC-175 passes.
  - `ExcelSerial` handles the 1899-12-30 epoch, the first reliable serial (61), the 1904 shift and millisecond rounding.
  - `ColumnLetters` maps between column indexes and letters.
  - `ExcelManifest.Header(...)` builds the §5.3 header block, ready for PC-175's planner.
- **READMEs** cover both projects and both test projects, and the `Tellma.Core` csproj description is updated. ARCHITECTURE.md already lists `DocumentFormat.OpenXml` under Tellma.Core, so it needed no change.

### Deviations

1. **`IExcelExporter.WriteAsync` takes `ExcelContext` and a `CancellationToken`.** The spec sketch (§4.1) passes neither, but the writer needs the request culture, calendar, zone, labels and `Now` to encode cells and stamp entries, and a plan does not carry them. `WriteTableAsync` also gains a `CancellationToken`.
2. **Implementation, binding and wiring of `IExcelExporter` are deferred to PC-175**, per CHECKPOINTS: PC-175 owns the planner, `ExcelOperations`, the `Tellma:Excel` binding with startup validation and the singletons of §1.2. `WorkbookWriter` is the internal engine that PC-175 will wrap. It takes the scratch directory (`Tellma:ScratchPath`, §4.2) as a constructor argument, so PC-175 binds it.
3. **New error code `Excel.Export.CellTooLong`.** Appendix A has no code for an editable export's text beyond 32,767 characters, which Excel cannot hold. Display cuts the text. Editable refuses it, with `LimitExceededException(Excel.Export.CellTooLong, length, 32767)`, because a silent cut would corrupt the round trip.
4. **`LimitExceededException`'s message cannot name the sheet** (§4.2 says it does). The exception's message is fixed by its contract (limit, actual, maximum).
5. **A culture without an LCID gets `0000` when a calendar id is present** (`[$-170000]`). §3.2 says to omit `LLLL` for custom cultures, but the tag's grammar needs both fields once `CC` is present; `0000` is "the viewer's locale". Gregorian with no LCID writes no tag at all.
6. **Dates before 1 March 1900 are written as ISO 8601 text** (both shapes). The 1900 system's phantom 29 February makes every earlier serial a day off, and the importer refuses serials of 60 and below (§3.1). Text keeps the value exact.
7. **The date format is the culture's cleaned short pattern** (`CalendarCultureData.Short`, as the calendar systems render dates), not the raw `ShortDatePattern`. The raw ar-SA pattern carries RLM marks and an era (`d‏/M‏/yyyy g`), which would leak into Excel. The year is always `yyyy`, because the cleaned pattern is complete.
8. **An editable `DateTime` in a calendar without a Windows id is ISO 8601 text**, and the manifest records `IsoDateTimePattern`. §3.1 says "the same as DateOnly", but calendar text has no time part, so ISO is the exact form.
9. **Widths:** DateTime and DateTimeOffset columns are 18 wide. Text without a declared length is 30. §3.3 gives no figure for either.

### Open risks

- **Rendering in Excel is unchecked.** I could not confirm, in a real Excel, that `[$-0401]` (Arabic LCID, no calendar id) renders a Gregorian date for an ar-SA user whose Windows default calendar is Hijri. The spec's own example only covers `[$-170401]`. The files pass the validator.
- **Memory measurement.** The flat-memory test samples `GC.GetTotalMemory(true)` twice; an allocator change could make it noisy. The 8 MB margin is about 40 times the expected noise.
- **Decoding before the planner exists.** The decoder's `TextCalendar`/`TextCulture` and the label dictionaries are filled by PC-176/177 from the manifest and the label provider. Until then only the tests exercise those inputs.

### What reviewers should examine hardest

- `CellCodec.Encode`/`Decode` against §3.1 row by row, especially the decimal 15-digit rule (normalised digits), integer exactness up to 2^53, and the `DateTimeOffset` display-zone conversion on both encode and decode.
- `NumberFormatBuilder.LocaleTag` and `TranslateDate`/`TranslateTime` against §3.2.
- `WorkbookWriter` caps, ordering and cleanup: the parent part stays open while child spools fill; every path disposes the parts and spools; the package is disposed after them.

None touched. No migrations.
