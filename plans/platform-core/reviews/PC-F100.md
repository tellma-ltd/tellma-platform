# PC-F100: Route skeleton on first tenant entry

## Implementer notes

### Root cause (confirmed)

The tenant route's `loadComponent` is `tmShellRoute('TmTenantShell')`. It returns the component
itself only once `loaded.TmTenantShell` is set, and before this change only the `TmTenantShell`
loader set it. On `/tenants` the shell module is in memory (the picker came through it), but
nothing had called that loader. So the click's navigation waited on `import('@tellma/core/shell')`
and its `.then` hops, and the tenant shell with its route host and `tm-page-skeleton` activated a
task later, in frame 2 or 3.

### What was built (fix1; commit 1's preloads replaced)

Commit 1 warmed the tenant shell through `TmUrls.preload` (a `TM_TENANT_SHELL` loader in
`#loadersOf`) and an idle preload from the picker. Review 1 showed that is a race with the click
(R1-1), so fix1 removes both and makes the first entry synchronous by construction:

- `client/projects/core/tellma-core/src/routes/tm-route-hosts.ts`: whenever the shell's module
  arrives, for any name, `tmShellComponent` sets `loaded.TmTenantShell` from the module's own
  `TmTenantShell` export, synchronously in the module's `.then`, before it runs the named loader.
  The picker comes through that import, so by its first frame the tenant route returns a `Type`:
  no idle wait, no network, nothing a click can beat. `tmShellRoute` now calls
  `tmShellComponent(name)()` inline (a few bytes fewer than hoisting it).
- `tm-urls.ts`, `tm-tenant-picker.ts` and its spec: back to platform-core. Hover and focus
  preloads are unchanged. So `tm-urls.ts:617` no longer differs from platform-core, and PC-123's
  `!!load` merges in cleanly.
- Equal savings for `"."` (R1-2), both behavior-neutral:
  - `tm-search-query.ts`, `tmPrintListPayload`: one object literal instead of a conditional;
    `JSON.stringify` drops the undefined `cols`, so the fragment is the same string.
  - `tm-http-api.ts`, the GET-body development check: `body != null` for
    `body !== undefined && body !== null` (the form `tm-urls.ts:163` already uses).
- Tests:
  - `src/routes/tm-tenant-route.spec.ts` (new, own file because the shell's `loaded` map persists
    for a file): after `tmShellComponent('TmTenantPicker')()`, the app's tenant route's
    `loadComponent()` is the tenant shell itself, not a promise, and `/17`, `/17/settings`,
    `/17/centers` and `/17/centers/5` all reach that one route while `/tenants` does not. With the
    settle line removed it fails ("expected Promise{…} to not be an instance of Promise").
  - `src/urls/tm-urls-preload.spec.ts` (commit 1) is gone with the preload it pinned.

### Deviations

None. Commit 1's two (spec 0024 §9.4's preload list, spec 0027 §6.2's extra idle preload) are
withdrawn with the preloads.

### Open risks

- `TmShellModule.TmTenantShell` reads the shell's public export, which the shell's build does not
  check against the primary's interface the way `ɵTM_SHELL` is checked. A rename there would leave
  the route asynchronous on first entry, not broken; the new spec fails on it.
- Local Windows only: `automatic-entries.spec.ts:107` is the known service-worker flake, fixed on
  pc/PC-123, not yet on platform-core. It was not in fix1's runs.

### What reviewers should examine hardest

- That the settle runs before any tenantless page can render: it is in the import's first `.then`,
  ahead of the named loader's own chunk import.
- The `"."` figures on the merged tree (below), and whether the two savings are acceptable as
  unrelated cleanups.

R1-1 (major). **The first entry still meets §4.4 only if an idle callback wins a race with the
click.** `client/projects/core/tellma-core/src/routes/tm-route-hosts.ts:74-80`,
`client/projects/core/tellma-core/shell/src/tenantless/tm-tenant-picker.ts:520-527`,
`client/projects/core/tellma-core/src/urls/tm-urls.ts:484-498`.

- The route is synchronous only once `loaded.TmTenantShell` is set. On the picker, that waits for
  this chain: the `#rendered` microtask, the next change detection that runs the effect,
  `requestIdleCallback` (no timeout), then `import('@tellma/core/shell')` and its two `.then`s.
- The import of an already evaluated module is not microtasks only, as the Open risks say. The
  implementer's own root cause and the PC-F100 ledger probe show it: with the shell module in
  memory and the tenant shell's loader not run, the skeleton showed in frame 2, 2, 2; with the
  loader run, 1, 1, 1. So the import costs at least a task.
- A click inside that window takes the promise path and paints the skeleton in frame 2 or 3.
  Production has this window, only narrower than the harness's:
  - a cold landing on `/tenants` (a multi-tenant user at `/`, a typed `/tenants`, or a
    tenant-not-found redirect), where the stored list is in the first frame precisely so the user
    can click at once;
  - the post-boot burst on a slow device (the revalidation, worker registration, the Contracts
    chunk, the telemetry pipeline, the other idle chunks), which postpones a timeout-less idle
    callback;
  - a keyboard user who tabs to Connect and presses Enter: the focus preload is idle-queued too.
- This is not D-395's case. There, the harness adds waits on a path that has no race in production,
  and the plain figure is far under budget. Here the harness widens a real race, by 300 ms, and the
  3 misses in 14 are that race being lost. The plain 6 of 6 shows that the window is usually short
  in Playwright, not that it is closed.

Suggested fix: make the route's first entry synchronous by construction. The tenant shell is eager
in `/shell`'s own chunk (`shell/src/tm-shell-components.ts:24`, `Promise.resolve(TmTenantShell)`),
and every tenantless page reaches the picker through `tmShellComponent`'s
`import('@tellma/core/shell')`. So in `tmShellComponent` (`tm-route-hosts.ts:59-64`), whenever the
shell's module arrives for any name, also settle the tenant shell, for example
`.then((shell) => { void shell.ɵTM_SHELL.TmTenantShell().then((component) => (loaded.TmTenantShell ??= component)); return shell.ɵTM_SHELL[name](); })`.
The tenant shell's loader resolves in a microtask, before the picker's own chunk import, so by the
picker's first frame the tenant route returns a `Type`. That needs no idle wait and no network, and
the harness cannot reach it, since it shares the one wrapped import. Then:
- the picker's effect, and with it the spec 0027 §6.2 deviation, can go (it also saves
  `tm-tenantless` bytes);
- `TM_TENANT_SHELL` in `#loadersOf` becomes redundant for this path. Drop it, or keep it for §9.4's
  wording, but mind R1-2's bytes;
- `tm-urls-preload.spec` becomes vacuous (its `TmPagePlaceholder` load would already settle the
  tenant shell). Replace it with a `tm-route-hosts.spec` case: after
  `tmShellComponent('TmTenantPicker')()` resolves, `tmShellRoute('TmTenantShell')()` is the
  `TmTenantShell` type, not a promise, with no preload. It needs its own file for the reason the
  current spec's header gives.
