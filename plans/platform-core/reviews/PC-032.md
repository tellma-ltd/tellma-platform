# PC-032: Web host: pipeline, route groups, tenant middleware, audit, CSRF and tenantless surfaces

## Implementer notes

### What was built, and where

- **New `src/core/Tellma.Core.AspNetCore`** (README at its root):
  - `TellmaWebApplicationBuilderExtensions.AddTellma(WebApplicationBuilder, slug, compose, composeWeb)`:
    the versions reader, `services.AddTellma`, then the internal `AddTellmaAspNetCore`. That call
    binds the ten host options (owner `host`) and three validators, registers the exception
    handler, the endpoint audit as a startup check, the `apiVersion` constraint, the schemes and
    policies, forwarded headers, Data Protection, Serilog and OpenTelemetry, the three
    readiness checks and the SPA seam.
  - `TellmaApplicationBuilderExtensions.UseTellma`: the spec 0011 §3.1 order, installed once.
    0016's slots are comments.
  - `TellmaEndpointRouteBuilderExtensions.MapTellma`: refuses a pipeline `UseTellma` did not
    install, then maps the platform endpoints, admin v1, the five groups and the SPA, and audits
    what is mapped (throws `TellmaCompositionException`). The audit also runs as the
    `host.endpoint-audit` startup check over everything mapped afterwards.
  - `Authentication/`: `Tellma.Session` cookie (`__Host-tellma.session`, Lax, sliding idle
    lifetime, 401/403 problems in place of redirects). `Tellma.Bearer` (`at+jwt` only, no inbound
    claim mapping, audience checked by the policies). Policies Web, Api, Mcp and ControlPlane,
    and the session fallback. `BearerRequirementHandler` checks scope and audience; MCP's
    audience is the route's tenant resource. `PrincipalBinding` derives `PrincipalKind`.
  - `Csrf/`: `CsrfRules` (Sec-Fetch-Site, Origin/Referer, Tellma-Client, JSON or opt-in binary)
    and `TellmaCsrfMiddleware`. The middleware takes its scope per endpoint: exempt for anonymous
    and non-session policies, provenance-only for safe methods and the hub, full otherwise.
  - `Tenancy/`: `TenantMiddleware` resolves the tenant, binds the principal through the holder,
    sets the activity tag and logger scope, and fronts the hub. `TenantAccessFilter` is the
    guard as an endpoint filter plus the `Wrap` backstop. `RequestInputs` and `TenantLogScope`
    support both.
  - `Routing/`: `TellmaEndpointAudit` (every spec rule plus three extras; see Deviations),
    `TenantGroupConventions.Complete`, `MappedEndpoints`, `EndpointPolicies` and
    `ApiVersionRouteConstraint`.
  - `Surfaces/`: `/api/distribution-info`, `/health/live`, `/health/ready` (catalog, Data
    Protection and authority checks), the PRM document, admin v1 (info, tenants, register,
    state, members), and SPA hosting per spec 0024 §6 (static assets, cache rules, index headers
    and CSP, navigation fallback).
  - `Problems/`: `ProblemWriter` and `TellmaProblemExceptionHandler`, the minimal tenancy and

  - `Observability/`: `HostMetrics` (`csrf_rejections`, `stepup_challenges`) and

### Deviations

1. **The tenant middleware resolves only endpoints that carry `TenantEndpointMetadata`.** It does
   not resolve every route with a `tenantId` value. The audit refuses a tenant route without the
   metadata, so no tenant endpoint escapes. A tenantless route that happens to take an integer
   segment is never resolved.
2. **`TenantAccessFilter.Wrap` is a group `Finally` convention on every guarded group, on top of
   the endpoint filter.** Endpoint filters reach route handlers only. An endpoint from another
   data source on the group (static assets, a hand-built `EndpointDataSource`) would otherwise
   run unguarded. An `HttpContext.Items` marker makes the guard run once per request.
   `GuardBackstopTests` was verified to fail without the backstop.
3. **The Api group gets the access filter as well.** The spec lists the filter on Web and Blobs.
   Without it the public API would bind a principal but never check membership or tenant state.
4. **`IsMutation` defaults from the HTTP methods** (anything but GET, HEAD and OPTIONS) when an
   endpoint does not state it. `WithMutation` overrides the default.
5. **`TellmaEndpoints` properties are get-only.**
6. **An `apiVersion` route constraint is added** (`v1`, `v1.2`). It is registered with
   `PostConfigure` + `TryAdd`, so an API-versioning library's constraint wins.
7. **Three extra audit rules:**
   - `TenantEndpointMetadata` on a route that does not begin with `{tenantId}`;
   - an endpoint on the Tenantless group without `TenantlessEndpointMetadata`;
   - a tenant endpoint whose policy authenticates another scheme. The tenant-surface rules
     require one scheme per surface.
8. **`Tellma-Client` version** is 1–64 visible ASCII characters, so a header cannot carry a log
   injection or an unbounded value.
9. **The admin state route refuses `Provisioning` as well as `Frozen`.** Registration alone
   enters `Provisioning`.
10. **Admin info and state answers are flattened objects:** the info document plus
    `tenantCounts`, and the descriptor plus `effectiveWithinSeconds`. They are not wrappers.
11. **Forwarded headers forward only `For` and `Proto`**, from the configured proxies and
    networks. Defaults are cleared. The framework's `ForwardedHeaders_Enabled` switch fails startup.
12. **Traceparent adoption applies to every request, not only the SPA's.** The trace id is
    kept and the sampled flag dropped. `tracestate` and baggage are ignored. The `00` flag and
    the root sampler on remote parents mean a caller cannot force or suppress sampling.
13. **The `mcp` surface is `null` in the info document** until `Tellma.Core.Mcp` maps it. The
    `api` surface is `null` until the web API feature announces it.
14. **Deferred:**
    - the Azure Monitor exporter (no package referenced; PC-085);
    - webhook endpoint stamping (`Tellma.Core.Webhooks` maps outside `MapTellma`; PC-085);
    - `ProtectKeysWithCertificate`;
    - the PRM `401` challenge's `resource_metadata` parameter (MCP feature);
    - the BFF and in-proc identity (`UseTellmaIdentity` is a slot comment);
    - support-request routes (§5.9).
15. **`ITenantProvisioningTrigger` and `NotConfiguredProvisioningTrigger` are created here.**
    PC-034 lists them, but admin v1's `501` needs them now. PC-034 replaces the registration.
16. **Tests use a TestServer-hosted `WebApplication`, not `WebApplicationFactory`.** There is no
    entry-point assembly to point a factory at, and this runs the real `AddTellma`, `UseTellma`
    and `MapTellma` unchanged. Authentication is real: a static OIDC configuration with a test
    key, and cookies protected with the scheme's own ticket format.
17. **`Microsoft.IdentityModel.JsonWebTokens` is pinned at 8.19.2 (was 8.19.1).** JwtBearer
    10.0.11 requires it (NU1109).
18. **Serilog forwards to the other providers (`writeToProviders: true`)**, so OTel log export
    receives the tenant scope's members as attributes.

### Known issues for later checkpoints

- **The SPA catch-all `{*path}` fallback matches every method.** An unmatched method on a mapped
  route therefore answers `404` (from the fallback), not `405`. This needs to be revisited when
  PC-081 adds the full problem mapping.
- **`TestServer` leaves `RemoteIpAddress` null.** The forwarded-headers middleware treats a null
  peer as trusted, so forwarding behaviour is not exercised by the suite beyond the startup
  refusal.
