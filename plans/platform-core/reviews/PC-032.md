### Deviations

1. **The tenant middleware resolves only endpoints that carry `TenantEndpointMetadata`.** It does
   not resolve every route with a `tenantId` value. The audit refuses a tenant route without the
   metadata, so no tenant endpoint escapes. A tenantless route that happens to take an integer
   segment is never resolved.
2. **`TenantAccessFilter.Wrap` is a group `Finally` convention on every guarded group, on top of
   the endpoint filter.** Endpoint filters reach route handlers only. An endpoint from another
   data source on the group (static assets, a hand-built `EndpointDataSource`) would otherwise
   run unguarded. An `HttpContext.Items` marker makes the guard run once per request.
   `GuardBackstopTests` was verified to fail without the backstop.
3. **The Api group gets the access filter as well.** The spec lists the filter on Web and Blobs.
   Without it the public API would bind a principal but never check membership or tenant state.
4. ~~**`IsMutation` defaults from the HTTP methods**~~ Withdrawn in Review 1 (R1-4): every
   hand-mapped Web, Api and Blobs endpoint states `WithMutation`, or the audit fails startup. A Hub
   endpoint is always a read.
5. **`TellmaEndpoints` properties are get-only.**
6. **An `apiVersion` route constraint is added** (`v1`, `v1.2`). It is registered with
   `PostConfigure` + `TryAdd`, so an API-versioning library's constraint wins.
7. **Three extra audit rules:**
   - `TenantEndpointMetadata` on a route that does not begin with `{tenantId}`;
   - an endpoint on the Tenantless group without `TenantlessEndpointMetadata`;
   - a tenant endpoint whose policy authenticates another scheme. The tenant-surface rules
     require one scheme per surface.
8. **`Tellma-Client` version** is 1–64 visible ASCII characters, so a header cannot carry a log
   injection or an unbounded value.
9. **The admin state route refuses `Provisioning` as well as `Frozen`.** Registration alone
   enters `Provisioning`.
10. **Admin info and state answers are flattened objects:** the info document plus
    `tenantCounts`, and the descriptor plus `effectiveWithinSeconds`. They are not wrappers.
11. **Forwarded headers forward only `For` and `Proto`**, from the configured proxies and
    networks. Defaults are cleared. The framework's `ForwardedHeaders_Enabled` switch fails startup.
12. **Traceparent adoption applies to every request, not only the SPA's.** The trace id is
    kept and the sampled flag dropped. `tracestate` and baggage are ignored. The `00` flag and
    the root sampler on remote parents mean a caller cannot force or suppress sampling.
13. **The `mcp` surface is `null` in the info document** until `Tellma.Core.Mcp` maps it. The
    `api` surface is `null` until the web API feature announces it.
14. **Deferred:**
    - the Azure Monitor exporter (no package referenced; PC-085);
    - webhook endpoint stamping (`Tellma.Core.Webhooks` maps outside `MapTellma`; PC-085);
    - `ProtectKeysWithCertificate`;
    - the PRM `401` challenge's `resource_metadata` parameter (MCP feature);
    - the BFF and in-proc identity (`UseTellmaIdentity` is a slot comment);
    - support-request routes (§5.9).
15. **`ITenantProvisioningTrigger` and `NotConfiguredProvisioningTrigger` are created here.**
    PC-034 lists them, but admin v1's `501` needs them now. PC-034 replaces the registration.
16. **Tests use a TestServer-hosted `WebApplication`, not `WebApplicationFactory`.** There is no
    entry-point assembly to point a factory at, and this runs the real `AddTellma`, `UseTellma`
    and `MapTellma` unchanged. Authentication is real: a static OIDC configuration with a test
    key, and cookies protected with the scheme's own ticket format.
17. **`Microsoft.IdentityModel.JsonWebTokens` is pinned at 8.19.2 (was 8.19.1).** JwtBearer
    10.0.11 requires it (NU1109).
18. **Serilog forwards to OpenTelemetry's logger provider alone (`writeToProviders: true` after
    the framework's default providers are removed)**, so OTel log export receives the tenant
    scope's members as attributes and no event is written twice (R1-7).
19. **The host's Serilog logger is not the static `Log.Logger` (`preserveStaticLogger: true`), and
    request logging is given the host's logger.** Found while testing R1-7: with the static
    logger, every host's `ILoggerFactory` writes through whichever host was built last, and a
    disposed host closes the others' sinks. Distributions that log through the static `Log` get
    nothing from the host's configuration.
20. **`IStackRouteSource` gains `Routes`**, so the endpoint audit can check every stack's resource
    segment (R1-9). PC-063's stack registry implements it.
21. **The MCP surface's front-door marker.** The audit accepts a tenant endpoint outside the groups
    only when its surface is `Mcp` and it carries the internal `TenantFrontDoorMetadata(Mcp)`.
    `Tellma.Core.Mcp` gets `InternalsVisibleTo` to stamp it beside the access filter, and its
    checkpoint must do so, or startup fails once it maps (R1-1).
22. **The audit recognizes `ShortCircuit()` by the framework's internal marker's full type name**
    (`Microsoft.AspNetCore.Routing.ShortCircuit.ShortCircuitMetadata`), the only signal it has
    (R2-4). The suite exercises the real `ShortCircuit()`, so a rename fails it.

### Known issues for later checkpoints

**R1-1 (blocking): the audit accepts a tenant endpoint that no guard reaches, so any signed-in
user can reach any tenant's endpoint unchecked.**
`Routing/TellmaEndpointAudit.cs:165-202`, `Tenancy/TenantMiddleware.cs:85`,
`TellmaEndpointRouteBuilderExtensions.cs:95-107`, `Routing/TenantGroupConventions.cs:27`.
The access guard runs in three places only. The filter and the `Wrap` backstop run on the Web,
Api and Blobs groups. `TenantMiddleware` runs it only when `TenantEndpointMetadata.Surface == Hub`.
The audit checks a tenant endpoint's metadata, policy, anonymity and grant metadata. It never
checks that the endpoint sits where one of those guards runs. `TenantEndpointMetadata` is a
public record, and `Complete` keeps any metadata that is already stamped. Three shapes pass the
audit and run without the guard:
- **Off-group endpoint.** `app.MapGet("/{tenantId:int:min(1)}/reports", h).RequireAuthorization(TellmaPolicies.Web).WithMetadata(new TenantEndpointMetadata(TenantSurface.Web, false, false)).AllowMember()`
  passes. It is the shape of the suite's own `tenant-second-segment` violation without the
  reserved word. `TenantMiddleware` resolves the tenant and binds the principal. No filter, no
  `Wrap` and no hub door runs. A non-member, or a member of a `Suspended` tenant, is served with
  `UserId` null, and every tenant-scoped service resolves against that tenant.
- **Hub-group endpoint stamped `Surface = Web`.** The Hub group has no filter, and the middleware
  skips the hub door because the surface is not `Hub`. The endpoint is unguarded in the same way.
- **Web-group endpoint stamped `Surface = Hub`.** The endpoint is guarded, but
  `TellmaCsrfMiddleware.ScopeOfAsync` gives it `Provenance` scope. A cookie mutation then loses
  rules 3 and 4.

Suggested fix: in `AuditTenantEndpoint`, require the surface to match the platform group
(`Web`↔`Web`, `Api`↔`Api`, `Blobs`↔`Blobs`, `Hub`↔`Hub`). Allow an endpoint outside the groups
only for `Surface = Mcp`, and later require a marker that the MCP feature stamps when it installs
its request filter. A more robust option: have `Wrap` stamp a guard marker, and have the audit
require that marker on every tenant endpoint whose surface is not `Hub` or `Mcp`. Add one audit
violation per shape above.

**R1-2 (major): touched integration suites were not run, and the commit's suite list is wrong.**
The commit changes `Directory.Packages.props` (`Microsoft.IdentityModel.JsonWebTokens` 8.19.1 →

**R1-3 (major): the guard on the Blobs and Api groups, and the hub's non-member verdicts, have no
test that fails if they break.**
`TellmaEndpointRouteBuilderExtensions.cs:69,71`. Spec 0011 §5.2 puts the filter on Blobs.
Deviation 3 puts it on Api too. No test sends a non-member or a refusing tenant state to
`/{id}/blobs/...` or `/{id}/api/v1/...`:
- the CSRF blob test asserts status codes only;
- `A_bearer_request_binds_the_principal_its_token_names` asserts kind, subject and client, which
  `TenantMiddleware` binds before any guard.

Flipping `guarded: true` to `false` on either group leaves the suite green. The spec also pins
the hub negotiate to "the same verdicts" as the web surface, including "a non-member receiving
the state's refusal on a suspended, frozen or read-only tenant" (§10). The hub theory has only
an `Active` stranger row. Suggested fix: add stranger rows and `Suspended` rows for a Blobs GET
and an Api bearer GET (one service-account token included), assert `UserId` on the served rows,
and add `Suspended`/`ReadOnly`/`Frozen` stranger rows to the hub theory.

**R1-4 (major, decision for the orchestrator): deviation 4 drops a spec audit rule instead of
implementing it.**
`Routing/TenantGroupConventions.cs:32-35`. Spec 0011 §3.3 says hand-mapped endpoints state
`WithMutation(bool)`, and "the audit (§5.3) refuses a tenant endpoint without it". The checkpoint
instead derives `IsMutation` from the HTTP methods, and the audit never sees an unstated
endpoint. The default is safe for POST/PUT/DELETE. It is wrong for anything mapped as GET that
writes: such an endpoint becomes a read, is served on a `ReadOnly` tenant, and on a `Frozen`
tenant fails inside SQL against the `READ_ONLY` database instead of answering
`403 tenant-frozen`. The spec's rule exists to force a stated decision. The deviation gives no
reason to drop it beyond convenience. Suggested fix: have `Complete` record that nothing was
stated (a `MutationStamp` is absent), and have the audit refuse such an endpoint unless its
`TenantEndpointMetadata` was stamped explicitly (as spec 0016's projection will). Alternatively,
the orchestrator rules the default in, records it in DECISIONS.md and amends the spec.

**R1-5 (minor): hub endpoints default to `IsMutation = true`, contradicting the hub door and
probably failing the audit once `MapHub` lands.**
`Routing/TenantGroupConventions.cs:32-35,45-51`. The hub front door always asks for a read
(`TenantMiddleware.cs:88`). `Complete` still derives a mutation from the methods. The suite's
`POST /negotiate` probe is therefore stamped `IsMutation = true`. SignalR's `MapConnections`
maps its connection endpoint through `endpoints.Map(pattern, …)`, which carries no
`HttpMethodMetadata`. If so, `MethodsMutate(null)` is true and `AnswersGet(null)` is true, and the
audit refuses the real hub as "a cookie-authenticated GET stamped as a mutation". Suggested fix:
have `Complete` stamp `IsMutation = false` for `TenantSurface.Hub`, and pin it with a hub endpoint
mapped through `Map` (no methods) in the audit-pass test.

**R1-6 (minor): `WithMutation` keeps a stamped `AllowWhenReadOnly`.**
`TellmaEndpointConventions.cs:50` uses `stamped with { IsMutation = isMutation }`. That keeps
`AllowWhenReadOnly = true` when an endpoint already carries it. Spec 0011 §3.3 and §5.1 say
hand-mapped endpoints "are never `AllowWhenReadOnly`" and that with `WithMutation`
"`AllowWhenReadOnly` stays false". Suggested fix: `stamped with { IsMutation = isMutation, AllowWhenReadOnly = false }`,
with a unit test.

**R1-7 (minor): `writeToProviders: true` sends every Serilog event to all the framework's default
providers.**
`Observability/ObservabilityComposition.cs:73`. With `writeToProviders`, Serilog's
`AddSerilog` adds every registered `ILoggerProvider` to its factory.
`WebApplication.CreateBuilder` registers Console, Debug and EventSource, plus EventLog on
Windows, and those receive every event Serilog admits, without the `Logging` section's
per-provider filters. A distribution whose `Serilog` section has a console sink logs each line
twice, and a Windows host writes Information events to the EventLog. Suggested fix: keep only the
OpenTelemetry logger provider, for example by calling `ClearProviders()` before
`WithLogging` / `AddSerilog`, or use a Serilog OpenTelemetry sink. Add a test that a host logs
each event once to a capturing provider.

**R1-8 (minor): nothing verifies that SqlClient spans actually lose their query text.**
`Observability/ObservabilityComposition.cs:97`; `ObservabilityTests.A_database_span_keeps_no_query_text`.
The test calls `RemoveQueryText` on a hand-built `Activity`. The real requirement depends on
`OpenTelemetry.Instrumentation.SqlClient` 1.16 doing two things:
- invoking `EnrichWithSqlCommand` for `Microsoft.Data.SqlClient` 6.1;
- invoking it after it sets `db.query.text` and `db.query.summary`.

WATCHLIST (0011) flags this as unverified. Removing the `EnrichWithSqlCommand` assignment leaves
the suite green. Suggested fix: add a test that runs one command through the real
instrumentation (the integration suite has SQL) with an in-memory exporter, and asserts that the
exported span carries neither tag.

**R1-9 (minor): one §5.3 audit rule is neither implemented nor listed as deferred.**
Spec 0011 §5.3 refuses "a stack's `ResourceSegment`" that is a word of `ServerTenantSegments` or
`SpaTenantSegments`. `AuditRouteWords` checks only the second segment of off-group tenant routes.
The stack-route seam (`IStackRouteSource`) already exists. Suggested fix: check the registered
stacks' segments through that seam, or list the rule under Deviations as deferred to the stack
registry's checkpoint.

### Findings

**R2-1 (major). The compressed `index.html` is served without the CSP and the other security
headers.**
`src/core/Tellma.Core.AspNetCore/Surfaces/SpaHosting.cs:225`

`StampAsset` decides whether an asset is the SPA shell with
`string.Equals(asset.AssetPath, IndexFile, ...)`. In the static web assets manifest a compressed
variant is its own row: the same `Route` (`index.html`), an `AssetFile` of `index.html.br` or
`index.html.gz`, and a `Content-Encoding` selector. For those rows `isIndex` is false, so the
`OnPrepareResponse` branch at line 231 that adds `Content-Security-Policy`,
`X-Content-Type-Options`, `Cross-Origin-Opener-Policy`, `Referrer-Policy` and `Permissions-Policy`
never runs. Spec 0024 §6 builds Brotli and gzip variants at publish, and every browser sends
`Accept-Encoding: br`, so in a published deployment the header-bearing row is the one no browser
ever receives: the shell, and every deep link the fallback rewrites to it, ships with no CSP.

Reproduced against the real `AddTellma`/`UseTellma`/`MapTellma` with a manifest carrying the
compressed row: `GET /index.html` with `Accept-Encoding: br` answers `200`,
`Content-Encoding: br`, `Cache-Control: no-cache`, and none of the five headers; the same request
without `Accept-Encoding` carries all of them. `SpaHostingTests`' manifest has no compressed row,
which is why the suite is green.

Fix: key the decision on the route, not the file (`asset.Route` equal to `index.html`, which every
variant shares). Add a compressed row to the test manifest and assert the headers on a request
that negotiates `br`, on `/index.html` and on a deep link.

**R2-2 (minor). A tenant segment the route constraint accepts and the middleware cannot parse
answers `500`.**
`src/core/Tellma.Core.AspNetCore/Tenancy/TenantMiddleware.cs:107-109`

The route's `int:min(1)` constraint parses with `NumberStyles.Integer`, which accepts a leading
sign and surrounding white space. `TenantIdOf` parses the same route value with
`NumberStyles.None` and throws `InvalidOperationException` when it fails. So `/+1/api/web/...`,
`/1%20/api/web/...` and `/%201/api/web/...` match a tenant endpoint and then throw.

Reproduced with a member's session cookie: each answers `500 internal` and writes an Error-level
"An unhandled exception has occurred" event. Any signed-in user can produce an Error log line and
a 5xx at will, which pollutes error-rate alerts; no data is exposed. (`/01/api/web/...` serves
tenant 1: a non-canonical spelling of the same tenant, harmless, mentioned for completeness.)

Fix: treat a value the strict parse rejects as an unknown tenant and answer the `404
tenant-not-found` problem (the spec's answer for a tenant that does not exist), or tighten the
route so it never matches (a `regex(^[1-9][0-9]*$)` constraint, which also retires `/01/`). Add
the three spellings to the middleware's tests.

**R2-3 (minor). The public `Hub` group serves any handler mapped on it as an unguarded-by-audit
read, and discards `WithMutation(true)`.**
`src/core/Tellma.Core.AspNetCore/Routing/TenantGroupConventions.cs:32-34`,
`src/core/Tellma.Core.AspNetCore/Routing/TellmaEndpointAudit.cs:287`

`Complete` stamps every Hub-group endpoint `IsMutation: false` and returns before it looks at the
endpoint's `MutationStamp`. The audit's Hub case checks nothing. The CSRF middleware gives the Hub
surface the Provenance scope alone. `TellmaEndpoints.Hub` is public, so a distribution (or a later
checkpoint) can map an ordinary handler there.

Reproduced: `endpoints.Hub.MapPost("/write", ...).WithMutation(true).AllowMember()` starts, is
stamped `{ IsMutation = False, Surface = Hub }`, and a `POST` with a form body and no
`Tellma-Client` header is served `200` on a ReadOnly tenant and on a Frozen one. The author stated
a mutation and the platform silently made it a read, with neither the write gate nor the full
CSRF rules. Nothing in the platform maps such an endpoint today, hence minor; the audit exists to
catch exactly this class of mistake at startup.

Fix: have the audit refuse a Hub-group endpoint that carries a `MutationStamp` with
`IsMutation: true`, and preferably any Hub-group endpoint that is not a SignalR connection
endpoint (`HubMetadata` present, or the negotiate endpoint's metadata). A test per refusal.

**R2-4 (minor). An endpoint with `ShortCircuit()` passes the audit and bypasses authentication,
the fallback policy and CSRF.**
`src/core/Tellma.Core.AspNetCore/Routing/TellmaEndpointAudit.cs:97-121`

For a tenantless endpoint the audit requires a reason and, unless `AllowAnonymous` is stated,
relies on the fallback policy to demand a session (line 121 checks authorization on tenant
endpoints only). Short-circuit metadata makes routing invoke the endpoint at once, before
authentication, authorization, the CSRF middleware and the tenant middleware, and the audit does
not look for it.

Reproduced:
`endpoints.Tenantless.MapGet("/short", ...).AsTenantlessEndpoint("test").ShortCircuit()` passes
the audit and answers `200` with no cookie; the same endpoint without `ShortCircuit()` answers
`401`. The audit's promise that anonymous access is always an explicit `AllowAnonymous` is
therefore not complete. On a tenant group the same call skips the tenant middleware, so the guard
runs with no tenant bound (not probed; at best it fails closed with an unhandled error).

Fix: one more audit row refusing `ShortCircuitMetadata` on every audited endpoint (or, at the
least, on every endpoint without `IAllowAnonymous`), with the fix text naming `AllowAnonymous` as
the way to state an anonymous endpoint. A test for the tenantless and the tenant case.

**R2-5 (minor). The SPA fallback leaves `Request.Path` rewritten, so every deep-link navigation
is logged as `/index.html`.**
`src/core/Tellma.Core.AspNetCore/Surfaces/SpaHosting.cs:289`

`IndexDelegate` sets `context.Request.Path = "/" + IndexFile` so the static asset endpoint serves
the shell, and never restores it. The Serilog request-completion event and the framework's
"Request finished" event read the path after the endpoint has run.

Reproduced: `GET /1/documents/7` is logged as `HTTP "GET" "/index.html" responded 200`. The
request log, the one place an operator sees which URLs users open and which links are broken,
loses the path of every navigation; the tenant segment goes with it.

Fix: restore the original path in a `finally` after the asset delegate returns, or serve the file
without mutating the request (invoke the index asset's delegate over a path feature scoped to the
call). Assert the logged path in a test.

**R2-6 (minor). The request-completion log event carries no tenant or user member.**
`src/core/Tellma.Core.AspNetCore/TellmaApplicationBuilderExtensions.cs:73`,
`src/core/Tellma.Core.AspNetCore/Tenancy/TenantMiddleware.cs:82`

Spec 0011 §9 puts `TenantId`, `TenantCategory`, `Subject` and `UserId` on a tenant request's log
events through the logger scope. The scope opens inside `TenantMiddleware` and closes when it
returns; `UseSerilogRequestLogging` sits earlier in the pipeline and writes its event after the
scope has closed, and it is registered without `EnrichDiagnosticContext`.

Reproduced: events written inside the handler carry the four members; the completion event for
`GET /1/api/web/probe` (status, elapsed, path: the line operators filter by tenant most often)
carries none. R1-7's test asserts the event exists and is not duplicated, not what it carries.

Fix: in `TenantMiddleware`, after the context is bound (and again once the guard has resolved the
user), set the members on Serilog's `IDiagnosticContext`; or pass an `EnrichDiagnosticContext`
callback that reads the request context holder. Extend the R1-7 test to assert the members.
