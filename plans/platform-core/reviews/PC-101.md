# PC-101: Printer-based entry points and discovery additions

## Implementer notes

### What was built, and where

All in `src/core/Tellma.Core.Queryex` unless noted.

- **`BindParameters`** (0010 §F.10): `QueryexEngine.BindParameters(text, ParameterBindingOptions)`
  returning `QueryexResult<string>`.
  - `ParameterBindingOptions` (in `QueryCompilationOptions.cs`): `Mode`, `QueryexVersion`
    (validated), `Parameters`, `Values`, `Omitted`, `Limits`.
  - `Pipeline/ParameterArguments.cs` resolves and checks the arguments (caller errors), then
    applies them to a parsed list: it folds first, through the same `OmittedParameterFolder` a
    compilation uses (predicate shape for Filter/Having, value shape otherwise), then substitutes
    every valued parameter.
  - `Syntax/LiteralSyntax.cs` writes one literal per declared type. Numbers are written from the
    `decimal` magnitude, with a `-` as a unary node. Dates, datetimes, offsets and guids are
    `cast('…','<type>')`. Null is `cast(null,'<type>')`.
  - `Pipeline/ParameterBinder.cs` parses (diagnostics are returned, not thrown), applies the
    arguments and prints with `SyntaxPrinter`. A whole text that folds prints as `true`.
- **`MeasureCondition`** (§F.20): `QueryexEngine.MeasureCondition(measure, options)` returning
  `QueryexResult<MeasureRows>` (`MeasureRows.cs`). It collects the aggregations in pre-order. Each
  condition argument is folded and bound like a filter. A null `Condition` means every row: there
  is no aggregation, one aggregation has no condition, or a condition is `true`. Conditions that
  are `false` are dropped. The rest are deduplicated by printed text and joined as
  `(c1) or (c2)`. If nothing remains, the result is `false`.
- **`ParameterUse.ComparedWith`** (§F.13): built in `Pipeline/Discoverer.cs` (`ReadComparedWith`,
  `Meet`, `Rooted`). It reads the bound tree in reporting scopes and covers:
  - comparisons, either way round;
  - `in` lists with a path value;
  - `descendantOf` and `ancestorOf` keys.

  When the same parameter is compared with two different paths, the conflict sets it to null.
  Paths under `Via` keep the navigation prefix.
- **`QueryDiscoverySpec.Conjuncts`** (§F.21): `DiscoveryResult.Conjuncts`, `FilterConjunct` and
  `FilterConjunctOperator` (`DiscoveryResult.cs`), read by `Pipeline/ConjunctReader.cs`. The
  discoverer passes a `conjunctive` flag through `ReadFilter`/`ReadChildren`, and only `And` keeps
  it. A leaf reached that way contributes the operands of its top-level `and`.
- **Inspection tool** (`eng/queryex-inspection`): a "conjuncts" checkbox and a "measure" input,
  with two new panes. `InspectAsync` was split into itself and `CompileAsync`.
- **Testing support**:
  - `test/shared/.../Corpus/BindingCases.cs` is the generator.
  - `Probe/ProbeParameterBinding.cs` checks the round trip on the tree.
  - One reference-interpreter fix: `cast(string, 'datetime')` called `AsInstant` on a string and
    threw. It now parses the ISO text.
- **Tests**:
  - `Syntax/ParameterBindingTests.cs` and `Syntax/MeasureConditionTests.cs`.
  - `Binding/ComparedWithTests.cs` and `Binding/ConjunctTests.cs`.
  - `Properties/ParameterBindingPropertyTests.cs` (450 generated binds, 300 measure checks against
    the interpreter).
  - `IntegrationTests/ParameterBindingDifferentialTests.cs` runs on SQL Server:
    - 120 binds, original vs bound;
    - 40 measure drills.

### Deviations

1. `MeasureCondition` returns `QueryexResult<MeasureRows>`, not `QueryexResult<string?>`.
   `QueryexResult<T>` requires `T : class` and defines success as `Value is not null`, so a null
   "every row" answer would read as failure. `MeasureRows.Condition` carries the nullable text.
2. Conjunct literals also accept bare `null` and `cast(null, '<type>')`, giving `Value = null`. An
   `is [not] null` atom gives `Equal`/`NotEqual` with a null value. The spec's literal list leaves
   null out, but the drills of spec 0033 (`CenterId = null`) need it.
3. A `cast('…', '<type>')` counts as a conjunct literal only for date, datetime, datetimeoffset and
   guid targets, and for a string target over a string. A numeric or boolean cast of a string is
   skipped, because the server's conversion (for example numeric rounding) could differ from the
   CLR value reported.
4. `FilterConjunct.Expression` covers any non-literal compared side that is free of parameters,
   printed canonically. It is not limited to parenthesized expressions.
5. `descendantOf` gives a conjunct only with exactly one key. `ancestorOf` gives none, since there
   is no operator for it.
6. Without a schema, a request for conjuncts gives an empty list, the same way paths are empty.
7. Caller errors beyond those listed:
   - the same name given twice in different case;
   - a CLR value that cannot be written as its declared type (`double`, a `DateTime` for a date,
     and so on).

   Both are `ArgumentException`.

### Open risks

- The reference interpreter converts a `datetimeoffset` to `datetime` through `UtcDateTime`.
  SQL `CAST` keeps the local wall time instead. Nothing in this checkpoint exercises that path,
  and the interpreter was left as it was.
- The `ComparedWith` conflict rule compares segments ignoring case. Two spellings of one path
  agree.
- Folding a measure's condition reuses the predicate fold, and that fold only ever produces
  `true`. So "false drops" is reachable only for a condition the author wrote as `false`. This
  follows the fold semantics (omission admits every row under either polarity), but the spec's
  wording suggests that folding could produce `false`.

### What to examine hardest

- `LiteralSyntax.TryWrite`:
  - numeric precision and scale, including negative zero and `decimal.MaxValue`;
  - fraction trimming for datetime and offset;
  - precedence placement of a negative literal, for example `-5` as an operand of `-` or `^`.

  The probe's round trip covers the generated cases, and the unit vectors cover the edges.
- `ParameterArguments.Apply`: the order is fold, then substitute. Check that
  `ReferencedParameters` drops exactly the substituted names.
- `ConjunctReader`: mirroring an operator when the literal is on the left, the `SqlDecimal` to
  `decimal` cutoff, and the site spans in nested `And` nodes.
- `Discoverer`: the `conjunctive` flag has to turn false under every `Not`, `Or`, `Via`, `Exists`
  and `Having`.

## Review 1

### Findings

Reviewed b11e206. The touched unit tests pass when filtered (`ParameterBinding|MeasureCondition|ComparedWith|ConjunctTests`,
190 passed on a fresh build). Two behaviours were reproduced with a scratch harness against that
build. Integration tests were not rerun.

Rulings asked about:

- **MeasureCondition's result type.** Right. `QueryexResult<T>` has `where T : class` and
  `Succeeded => Value is not null`, so with `QueryexResult<string?>` the null "every row" answer
  would read as a failure. `MeasureRows(string? Condition)` is the smallest fix that keeps one
  result type.
- **Null literals as conjuncts.** Right for `=` and `!=`. Under 0008 §9.2 comparison is total:
  `x = null` is an absence test and `x != null` a presence test. So `CenterId = null` reported as
  `Equal`/null describes 0033's "(None)" drill exactly. It breaks nothing for equality. It is wrong
  only under the ordering operators and `descendantOf` (R1-2).
- **Folding to true.** The reading is right. Over `FoldPredicate`, a node that settles at polarity
  `p` always has the value `!p`:
  - an atom settles to `!negated`;
  - `not` flips both the polarity and the value;
  - `and`/`or` either pass the other operand through or return the settled one.

  A bare text starts un-negated, so it can only settle to `true`. §F.10's "true or false" applies
  to `CompileQuery` under a `FilterTree.Not`, and §F.20's `false` comes only from an authored
  `false`, or from a valued Bool parameter bound to `false` (`sum(x, @Flag)`), which the
  `BooleanSyntax` check also catches.
- **The DateTimeOffset open risk.** The divergence is real in the reference interpreter:
  `AsMoment` uses `UtcDateTime`, while `CAST(dto AS datetime2)` keeps the wall time. No vector this
  checkpoint ships reaches it, though:
  - every `@Instant` atom compares at `datetimeoffset` (`ApprovedAt`, `PostedAt`);
  - the interpreter change only adds the string to `datetime` path.

  It belongs in WATCHLIST for whichever checkpoint first casts an offset to a datetime.
- **What checked clean:**
  - The printing table: `decimal`/`int`/`long` are written invariant, with a unary minus. Scale
    is kept, negative zero folds to zero, and the precision matches the lexer's count.
  - Strings: `'` is doubled, and the lexer accepts every other character verbatim, so no
    injection is possible. A marker inside a string is never replaced.
  - Dates, datetimes, offsets and guids: date is `yyyy-MM-dd`; datetime has up to seven trimmed
    fraction digits; offset is the wall time plus `±hh:mm`; guid is lowercase `D`. Every format
    call uses InvariantCulture.
  - The round-trip probe and the `--12.5` and `-12.5 * 2` placements.
  - Substitution covers every syntax kind the printer knows.
  - `ReferencedParameters` drops exactly the substituted names.
  - `conjunctive` turns false under `Not`, `Or`, `Via`, `Exists` and `Having`.
  - In `DiscoveryResult.Paths`, Via paths are prefixed and Exists paths are excluded (D-027).
  - The caller errors.
  - The AGENTS.md doc and comment rules.
  - The property test (unit) and the differential (integration). Both would catch a wrong
    literal, a missed fold or a misplaced sign, since values sit on fixture boundaries and the
    datetime draws carry 7-digit fractions.

**R1-1 (major) — A long number literal makes `DiscoverQuery` throw when conjuncts are asked for.**
`src/core/Tellma.Core.Queryex/Pipeline/ConjunctReader.cs:262` and `:267`.

- **The bug.** `TryNumber` guards only `Scale > 28` and `|value| > decimal.MaxValue`. A literal
  can still have a mantissa wider than 96 bits while its value is in range and its scale is at
  most 28. `SqlDecimal.Value` then throws `OverflowException`.
- **Reproduced on this commit's build** (`Conjuncts = true`, root Invoice):
  - `Amount = 99.999999999999999999999999999` (29 digits) throws `OverflowException: Conversion
    overflows`;
  - so does `Amount = 12345678901234567890.1234567890`.

  Both are legal: the lexer accepts up to 38 digits.
- **Impact.** Neither discovery nor the inspection tool catches it, since the inspection tool
  catches only `ArgumentException`. The discover endpoint (0029 §9) would answer 500 to a user's
  filter where it should answer 200 and pass the atom over. That passing over is what the doc
  comment promises.
- **Fix.** Also pass over when `number.Data[3] != 0`, that is, when the mantissa needs more than
  96 bits. The magnitude comparison can then go.
- **Tests.** Add vectors to `AnAtomThatIsNotARestriction_YieldsNone` for a scale-29 literal, a
  29-digit literal above 2^96, and a 38-digit literal. Today no test covers the cutoff at all.

**R1-2 (minor) — `null` under an ordering operator or `descendantOf` is reported as a conjunct.**
`src/core/Tellma.Core.Queryex/Pipeline/ConjunctReader.cs:92-99`, `:116-124` with `:185-186`.

- **The bug.** `TryValue` accepts `TypedNull` and `cast(null, …)` under every operator.
- **Reproduced:** `Amount < null` yields `Less` with a null value.
- **Impact.** Under 0008 §9.2 an ordering comparison against absence is false, so the atom admits
  no row. A chip reading "Amount < (empty)" misdescribes the list. Every consumer (0029's
  `QueryexConjunct`, 0034's chips) would have to know to drop it. The same applies to
  `descendantOf(path, null)`.
- **Fix.** Report a null value only with `Equal`/`NotEqual`, which cover `=`, `!=` and
  `is [not] null`, and pass the rest over.
- **Tests.** Add `Amount < null`, `Amount >= cast(null, 'numeric')` and
  `descendantOf(Account.Concept, null)` to `AnAtomThatIsNotARestriction_YieldsNone`.

**R1-3 (minor) — A null value for a parameter declared `IsNotNull` is accepted, so the bound text
can disagree with compiling with the arguments.**
`src/core/Tellma.Core.Queryex/Pipeline/ParameterArguments.cs:89` and
`src/core/Tellma.Core.Queryex/Syntax/LiteralSyntax.cs:48`.

- **The bug.** 0008 §6.3 omits the null guards on the strength of `IsNotNull`.
- **Example.** Take `IsApproved != @Posted`, where `Posted` is declared NotNull and bound to null:
  - compiled with the argument, the SQL `<>` against NULL excludes every row;
  - `BindParameters` prints `IsApproved != cast(null, 'bool')`, which admits every row whose
    `IsApproved` is present.
- **Impact.** A drill would list rows its number never counted, against the §F.10 property.
  `ParameterBindingTests.cs:336` feeds exactly this case (`["Posted"] = null`, declared
  `IsNotNull: true`).
- **Fix.** Make null for an `IsNotNull` declaration a caller error. It is not a value of the
  declared type, which fits the spec's "value whose CLR type does not match the declared type".
  Add it to `ACallerMistake_IsRefused` and change the round-trip vector.
- **Alternative.** If refusing is too strict, state in the XML docs that the bound text follows
  the two-valued rules where the compiled query does not, and record the deviation.

**R1-4 (minor) — The printed text can exceed the ceilings that the source text met.**
`src/core/Tellma.Core.Queryex/Pipeline/ParameterBinder.cs:52-54` and `:122-131`.

- **The bug.** Each valued parameter grows from one token and a few characters into a literal:
  - a guid or offset becomes `cast('…', '<type>')`, six tokens and about 50 characters;
  - an omitted parameter in a value position becomes `cast(null, '<type>')`.
- **Example.** `ExternalId in (@k1, …, @k128)` is about 700 characters. Bound, it prints at about
  6.9k characters. Joined with 0033's document filter and terms, it passes `MaxInputLength`
  (8192), so the drill fails with a ceiling diagnostic although the report itself ran.
- **Precedent.** `CompileQuery` already deducts the fold surplus (`OmittedParameterFolder.Surplus`)
  so that "a query that fits its ceilings fits them whatever is left out". Nothing does the same
  for bound text.
- **Fix.** Either:
  - check the printed result against `options.Limits` and return the ceiling diagnostic from
    `BindParameters`/`MeasureCondition`, so it surfaces at bind time and not at drill time; or
  - state in both members' XML docs that the result may need larger limits than the source, and
    flag it for 0033.

**R1-5 (minor) — The README names an operator the language does not have.**
`src/core/Tellma.Core.Queryex/README.md:89` lists the conjunct operators as `=`, `<>`, `<`, …. The
lexer has no `<>` token; inequality is `!=` (`OperatorTable.cs:120`, `Lexer.cs:536`).

- **Fix:** write `!=`.

**R1-6 (minor) — Nothing would catch a lost InvariantCulture in literal printing.**
`test/core/Tellma.Core.Queryex.Tests/Syntax/ParameterBindingTests.cs:87`.

- **The gap.** The printing table's culture invariance is asserted only under the test host's own
  culture, which is invariant on the Linux CI. Suppose the `CultureInfo.InvariantCulture` argument
  were dropped at `LiteralSyntax.cs:55`, `:87` or `:124`. Under th-TH the dates would then print
  Buddhist years (2569); under ar-SA they would print Hijri dates or Arabic-Indic digits; under
  de-DE a decimal would print with a comma. Every vector would still pass.
- **Fix.** Add a theory that sets `CultureInfo.CurrentCulture` and `CurrentUICulture` to th-TH,
  ar-SA and de-DE, restoring them in `finally`, and re-asserts a date, a datetime with a fraction,
  an offset and a decimal vector.

### Responses

- **R1-1: fixed.**
  - `ConjunctReader.TryNumber` now passes a literal over when its scale is above 28 or when
    `SqlDecimal.Data[3] != 0` (a magnitude wider than 96 bits). The magnitude comparison and the
    `MaxDecimal` field are gone.
  - Vectors added to `AnAtomThatIsNotARestriction_YieldsNone`:
    - scale 29 (`0.00…01`);
    - the two reproductions, `99.999999999999999999999999999` and
      `12345678901234567890.1234567890`;
    - 2^96 (`79228162514264337593543950336`);
    - a negated 38-digit literal.
  - Two positive vectors pin the cutoff from the other side in `EachLiteralForm_ReadsAsItsValue`:
    `79228162514264337593543950335` reads as `decimal.MaxValue`, and
    `-7.9228162514264337593543950335` (scale 28) reads as itself.
- **R1-2: fixed.**
  - `ConjunctReader.Conjunct` returns no conjunct for a null value under any operator other than
    `Equal`/`NotEqual`. That covers `=`, `!=` and `is [not] null`.
  - Vectors added: `Amount < null`, `Amount >= cast(null, 'numeric')`, the mirrored
    `null > Amount`, and `descendantOf(Account.Concept, null)`.
  - The README states the rule.
- **R1-3: fixed (refused).**
  - `ParameterArguments.Resolve` throws `ArgumentException` when null is given for a parameter
    declared `IsNotNull`.
  - The XML docs of `BindParameters` list it.
  - The test declarations now make `Posted` nullable, so the round-trip vector with
    `Posted = null` stays meaningful. A new never-absent `Settled` backs the caller-mistake vector
    `null-for-never-absent`, which also checks `MeasureCondition`.
  - The new deviation is listed in the fix commit.
- **R1-4: fixed (checked).**
  - `ParameterBinder.Fits` re-reads the printed text, or the joined measure condition, through
    `compiler.TryParse` under `options.Limits`. If that fails, the ceiling diagnostics are
    returned with each span replaced by the whole source text, because printed positions mean
    nothing to the caller.
  - This covers `MaxInputLength`, `MaxTokens`, `MaxSyntaxDepth` and `MaxListItems`.
  - A successful parse lands in the parse cache, ready for the compilation that usually follows.
  - `MaxTypedNodes` needs a schema, so it is still applied only when the printed text is compiled.
    The XML docs on both members say so.
  - Tests: `ATextThatOutgrowsItsCeilings_IsReported` covers QX5001 and QX5002 and checks that the
    same text, unbound, fits. `AMeasureWhoseConditionOutgrowsItsCeilings_IsReported` covers
    QX5001.
- **R1-5: fixed.** The README now spells inequality `!=`.
- **R1-6: fixed.**
  - `ALiteral_PrintsAlikeUnderEveryCulture` runs under th-TH, ar-SA and de-DE and restores both
    cultures in `finally`.
  - It re-asserts the decimal, negative decimal, date, datetime-with-fraction, west-offset and
    guid vectors.
  - It first checks that the culture really formats a date or a number differently from the
    invariant culture, so the test cannot pass vacuously.
- **The DateTimeOffset interpreter risk.** It is now a WATCHLIST line under `## 0010-F`, for the
    first checkpoint that casts an offset to a datetime.
