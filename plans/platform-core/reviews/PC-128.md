### What was built

Spec 0030 §6.1–§6.4, §5.2's anchor and 500 ms announcement rule (the D-290 carry), §3.2's field
widths, §7.2's one tab stop and F2 (the grid's, unchanged) and §19's `tm.search.open` and `tm.search.type-to-search` events.

- **The field** — `TmSearchPageField` in
  `client/projects/core/tellma-core/search/src/tm-search-page-field.ts` and its stylesheet
  (fix1 moved it out of the host's template and `tm-search-host.css`); the host renders it in its
  header and binds its text, its emitted searches, its keys and its blur.
  - `input[tmSearch][tmGridDriver]` in a box of the host's own that draws the form-field chrome
    from the field tokens: magnifier, the input, a square clear button that keeps its slot while
    hidden. Size from `ɵtmControlSize` (`sm`/`md`, `lg` below sm). Width 240 px from sm, 320 px
    from xxl, filling row 1 after the title (at least 160 px) below sm.
  - `type="search"`, `dir="auto"`, `maxlength` = the entity's `maxSearchLength`, placeholder and
    `aria-label` "Search", `aria-describedby` = the h1 then a hidden hint ("Arrow keys move
    through the results. Enter opens one."); `aria-controls`/`aria-activedescendant` come from
    `tmGridDriver`.
  - `fieldText` is the field's own text (a `linkedSignal` reset per entity); the query's `q` is
    its stripped, trimmed, capped form (`tmSearchText`). A query change from elsewhere (an address,
    Back, Clear search, the `search.query` page action) syncs the field only when the field's text
    no longer carries the query, so typed spaces survive.
  - Clear button and Escape go through `TmSearch.clear()`, an undoable `execCommand('delete')`.
- **The stale rule and the bar** — `stale` is true while a read runs or the field's text differs
  from the text the result on screen answers; the progress bar's `active` is `stale()` (plus the
  hatched body's load), so it shows from the first key through a burst and the bar's own 250 ms
  hold applies after.
- **The driver** — the host's `TmGridDriverTarget` (`driver`) forwards every member to the grid,
  falls back to the region's id for `controlsId`, and wraps `activateRow` with the stale rule
  (`#enter`): fresh → the grid opens the highlighted row (Mod+Enter in a new tab); stale →
  `TmSearch.flush()` and arm a pending open. Tiles slot in here later.
- **Highlight seeding** (`#seed`) — a result that lands while focus is in the field highlights its
  first row; an anchor restore's result does not re-seed.
- **Pending Enter** (`#pending`, `#settle`) — settled by the first fresh result: opens its first
  row (after a restore too, since fix2, whatever the restored highlight: §6.3), reports `open` with
  `via: 'pending'`; an empty result disarms it, and the no-matches state says "No matches"
  through the 500 ms rule; a failure just disarms. Disarmed by any other key in the field (`fieldKey`), blur, a pointer press anywhere
  (capture-phase `pointerdown` on the scope), type-to-search, and a navigation through history or
  to another page (`NavigationStart`); the page's own address writes do not disarm.
- **Type-to-search** — `search/src/tm-search-typing.ts` (pure functions) and
  `TmSearchKeys.listen` in `search/src/tm-search-keys.ts`, which the host's `#listen` starts. Bubble-phase `keydown` and `paste` on the document (page, list) or the picker
  modal's `.cdk-overlay-pane` (picker). The five conditions: untouched (not default-prevented, not
  composing, not a repeat), one printable grapheme (`Intl.Segmenter` for multi-unit keys; controls,
  format characters and spaces refused), no Ctrl/Meta/Alt (AltGr allowed via
  `getModifierState('AltGraph')`), the target not editing (text inputs, textarea, select,
  contenteditable, an open grid editor anywhere in the scope; checkbox, radio and button inputs
  qualify as buttons do), the page on top (page/list: no `TmPageContexts` overlay and no
  `ɵtmOpenModals()`, and no attached CDK popup pane other than a tooltip; picker: no popup attached
  inside its pane). Insertion (`tmSearchInsert`) focuses and selects the field and replaces its
  text with `execCommand('insertText')` (one undo step, fires `input`), falling back to
  `setRangeText(…, 'end')` plus a synthetic `InputEvent`; the text is cut to `maxlength` without
  splitting a surrogate pair; pasted newlines become spaces and a blank paste is ignored.
  `TmShortcuts` is injected before the listener is added so the app's shortcuts see a key first.
- **The anchor** (`#anchor`, `#snapshot`, `#restore`, `#prefilled`) — the first text change of a run
  snapshots the query, its read key, the result if it answers that key and no read runs, and the
  highlight. A text that returns to the anchor's `q` restores the whole query with a replace
  (`tmSearchApply`, source `typing`), puts the result back through `#prefilled`, which `#key`
  reuses (unless `tmSearchRereads` says the rebuilt request needs a read) and `#load` answers from
  memory with timing source `anchor` and no request; the highlight is set back, and the grid's
  store restores scroll and the active cell by the content key. Dropped by any non-typing
  transition (`#apply`), Refresh, a re-planned column set, a descriptor change without a language
  change (permissions or settings), and a navigation that changes the query; a language switch
  keeps it.
- **Row menu** — `rowMenu` passes "Open in new tab" (`window.open(url, '_blank', 'noopener')`) and
  "Copy link" (absolute URL via `Location.prepareExternalUrl` and `baseURI`, written synchronously
  in the gesture by `TmSearchKeys.copyLink`; "Link copied" or "The link couldn't be copied"
  announced) as the grid's `extraMenuItems`. They act on the row the menu was opened on (the
  grid's new `menuRowId`), and a menu opened on a column header, on the row-end cell or with no
  rows offers neither; none when rows do not activate.
- **Announcements** (`TmSearchKeys.speak`) — every live-region message (counts, offline, and,
  since fix1, each state of the results region) waits until 500 ms after the last key on the page;
  a later key or message replaces the pending one. The states render no live region of their own.
  Since fix2 the region's state is the held answer's (built from the query that answer was read
  for, and unchanged while it is equal), so typing over an empty result or an error view rebuilds
  and says nothing until the next answer lands. `#announce` says the state once per settled
  answer; the error view is said once its chunk lands; a drill-through link with no valid filter,
  which reads nothing, is said as it shows.
- **Telemetry** — `tm.search.open { via: pointer | keyboard | link | pending, newTab }` (a link
  click and an auxiliary click are reported from the region's `click`/`auxclick`) and
  `tm.search.type-to-search`, both sampled.
- **Strings** — `tm.search.search`, `searchHint`, `openInNewTab`, `copyLink`, `linkCopied`,
  `linkCopyFailed` in English (`tm-search-strings.ts`) and Arabic (`strings-queryex-ar.ts`).
- **Component library**
  - New entry point `@tellma/core-ui/search-input` holding the `input[tmSearch]` directive
    (moved from `search-field`, history kept with `git mv`), so the search page takes the
    directive without `tm-search-field`'s chrome. `search-field` now exports `TmSearchField`
    only and imports the directive from the new entry point. README, docs globalStyles, docs
    examples and the showcase story follow.
  - `TmSearch`: a write to `value` from outside (a reset, a restored query) now counts as searched
    and ends the open burst, so a pending trailing edge never re-emits replaced text and editing
    back to the previous text still emits.
  - Grid: a grid that cannot be edited leaves every paste to the page (`grid-core.ts`
    `onPaste`), so the search page's paste capture sees it.
  - Page header: row 1's end slot grows (`flex: 1 0 auto`) while packing its items at the end, so
    a growing item (the field below sm) fills the row after the title; nothing else moves.
- **Testing** — `TmSearchPageHarness` gains `getSearchText`, `getSearchPlaceholder`,

### Route saving

- `tm-pager` (`client/projects/core/tellma-core-ui/pager/tm-pager.ts`, `tm-pager.css`) renders
  `tm-select` inside `@defer (when sizeSelectWanted())`. The select entry point is referenced
  only inside the block, so the compiler loads it with `import()`. `staticGraphExcludes` now keeps
  `@tellma/core-ui/select` off `@tellma/core-ui/pager`'s and `@tellma/core/search`'s static
  graphs.
- The select is wanted at idle after the first render (`afterNextRender`, then
  `requestIdleCallback`, or `setTimeout` without it). It is also wanted on the first
  `pointerenter`, `focus`, press or key on the stand-in.
  - The pager asks for idle itself. With the block's own `on idle` trigger, Angular's idle
    scheduler joined the framework code in Acme's main chunk, which put +0.56 KB on `initialJs`
    (224.83 in a measured build).
- The stand-in, `.tm-pager__proxy`, sits in the size cell's grid area, the same one the select
  and the sizer share:
  - It has the trigger's chrome at each size step: height, padding, border, radius, background,
    text, caret, hover, `:focus-visible` glow and disabled colours, all from the field tokens on
    the pager's size ladder (`--tm-pager-block-size` is new).
  - It shows the current size's label, or the select's placeholder when no size matches.
  - It is a collapsed `role="combobox"` named "Page size" in the same tab stop
    (`tabindex` −1 and `aria-disabled` while disabled).
- Handover runs in an `afterRenderEffect`. Once the select has rendered (inert under the stand-in
  for one pass), the effect retires the stand-in. A focused stand-in that nothing was asked of
  stays until it loses focus (fix1); one that was asked for something hands focus straight to the
  select's trigger before it leaves, so focus never stops on the body. On the next pass the
  select replays what the stand-in received:
  - typed text goes to `seed(text)`, the select's typeahead;
  - a click, Enter, Space, ArrowDown or ArrowUp goes to `open()`.
  - A press keeps the stand-in until it ends in a click (or leaves or is cancelled), so the
    select never lands under a pointer that is still down and takes the click itself.
- `TmPagerHarness.getSizeSelect()` points at the stand-in to load the select, then waits (bounded)
  for it to land.
- Tests:

    sm, md and lg, the stand-in's box equals the select's box once it lands, the pager's box

- The search field's own chrome, rather than `tm-form-field` with `input[tmInput]` (R1's

  - `@tellma/core/search`'s `staticGraphExcludes` already bars `@tellma/core-ui/input` (and

### Deviations

1. The field is `input[tmSearch][tmGridDriver]` in its own chrome, not `input[tmInput]` in
   `tm-form-field`. The D-289 guard keeps `@tellma/core-ui/input` and `@angular/forms` off the
   search route's static graph, and the two would put about 5 KB on a route whose remaining room
   (about 12 KB) is wanted for the Filters popup's trigger, the selection bar and the tiles. The
   chrome reads the form-field tokens (height, padding, border, radius, glow), and since fix1 a
   unit test pins its box, type and focus glow to a `tm-form-field` with an `input[tmInput]` at
   sm, md and lg.
2. `TmSearch` moved to `@tellma/core-ui/search-input` (a new entry point); `search-field` no longer
   re-exports it.
3. A non-editable grid no longer handles paste at all (before, a data cell's paste was taken and
   dropped), so §6.2's paste reaches the field.
4. `TmSearch` treats an external `value` write as already searched.
5. The page header's row-1 end slot grows to the row's free space.
6. §7.2's return highlight (the opened row highlighted on return) is not built here: the host
   is a new component on return, and the opened row reaches it through §15.1's page-state
   snapshot (`highlight`), which is PC-132's. The pending open sets the highlight before it opens.
7. Scroll restore after an undo relies on the grid's content-key store; the host test asserts the
   page, the rows, the highlight and zero requests, not the scroll offset (the test bed gives the
   grid no height).
8. The first commit measured `searchRoute` at 112.84 of 110. The route saving (D-364) brings it
   to 97.95.
9. Ceilings (D-031):
   - `@tellma/core` `./search` raised 18.5 → 22.5 (measured 18.15 → 22.27);
   - `@tellma/core-ui` `./search-input` born at 1.2 (1.10);
   - `./search-field` lowered 2.5 → 1.75 (1.65);
   - `./pager` raised 2.8 → 4.1 (measured 2.70 → 4.01) for the stand-in, the idle load and the
     replay; the spec's cap is 2 KB.
   - Notes in each `budgetNotes`.
10. The pager's size select is not in the pager's first render: it loads at idle or on first use
    (D-364). A stand-in of the same geometry and name holds its place.
11. Type-to-search treats the input types that take no typed text (`checkbox`, `radio`,
    `button`, `submit`, `reset`, `image`, `file`, `range`, `color`, `hidden`) as buttons: a key
    pressed on one is typed into the field. Spec 0030 §6.2 condition 4 excludes every `input`.
    None of these takes typed text, and Space, which toggles a checkbox or a radio, is never typed
    in. Flagged for spec alignment.
12. Spec 0030 §5.2 and §5.3 disagree on the live region: §5.2 has one region that speaks only
    after 500 ms without a key, while §5.3 makes each state a `live="polite"` region of its own,
    which speaks as it renders, mid-burst. Fix1 follows §5.2 (the D-290 carry): the states render
    silent, and the page's one region says each state, heading then detail, after the pause.
    `TmErrorState` gains a `live` input (default `polite`) so the search page can silence the
    error view and say it itself. Flagged for Ahmad, to bring §5.3 in line.
13. Fix1 re-splits `@tellma/core/search` (D-031: its ceiling had risen three times). The new
    `@tellma/core/search-view` holds the field with its keys and its chrome, the type-to-search
    rules, the results region's states and a refused query's diagnostics. The host imports it
    statically, so it loads with the route; nothing in it is fetched after the first paint, so no
    key typed early can be lost. The field itself is first-paint code; it moved with its keys
    because the keys reach the field's input and the field is the keys' only user. The new entry
    point is absent from spec 0023 §1's and spec 0030 §1's entry-point lists; flagged so they
    can name it. Review 2 (R2-2) showed the split takes nothing off the route, and D-384 parks
    that for a ruling on spec 0030 §1's route-chunk budget. Fix2 describes `./search-view` in
    ARCHITECTURE.md as it is, an eager sibling of `/search` that the search route loads, with a
    budget line of its own, and notes it as the one entry point that is not a lazy boundary.
    Withdrawn by fix3: D-394 folds `./search-view` back into `./search` and retires it, and
    `./search`'s measure becomes the figure for spec 0030 §1's route-chunk budget.
14. The grid gains a public `menuRowId` signal (the data row the context menu was last opened
    on), which `extraMenuItems` read to act on that row and to leave a header's or a row-end
    cell's menu.

### Open risks

- `execCommand` is deprecated; every engine still supports `insertText`/`delete` on inputs, and the
  fallback keeps search working without undo.
- Type-to-search's "on top" check reads the DOM for CDK panes on every captured key; cheap, but
  a pane left attached and empty is skipped by its child count.
- A key typed while the page is still loading (before the field renders) is not captured.
- The pager's stand-in copies the select trigger's chrome in its own rules. A later change to the
  trigger's look must follow in `tm-pager.css`; the unit test that compares their computed
  chrome at each size step catches a drift.

### What reviewers should examine hardest

- `#key`'s prefilled branch and `#load`'s anchor answer: a restore must never send a request,
