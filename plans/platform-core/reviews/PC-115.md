# PC-115: Navigation registry, core entries and the pins model

## Implementer notes

### What was built

Spec 0027 §3, §8.2–§8.3, §9.6 and §2, in `client/projects/core/tellma-core/`.

- **Navigation registry** (`src/nav/tm-navigation.ts`, primary). `TmNavigation` with `sections`,
  `items`, `byHref` and `resolve`.
  - Candidates come from `TM_APP_DECLARATIONS` after `hide`: stacks with a `query` operation and
    a segment (plural label, `file-text`, `createHref` when `allows(name, 'save')` and the entity
    has a details page), pages without a path parameter (`square-dashed`, behind `securable`),
    coded reports with their patches (`chart-column`, behind `securable`) and feature entries
    (`link`, any one of `requires`).
  - `visibleWhen`: hidden while `TmLaunchCache.distribution()` is absent; a predicate that throws
    hides its entry and reports `tm.nav.visible-when` once per entry (written through `untracked`,
    since the state is a `computed`).
  - Order: `order` (default 100), then the label in the active language (`Intl.Collator`), then
    the id. Sections without a visible entry drop out; an entry naming no shown section is
    search-only and follows the section entries in `items`.
  - The declarations are read only once `TmClientMetadataStore.current()` is set, because
    `TM_APP_DECLARATIONS` injects `TM_CLIENT_METADATA`, which throws before the Core chunk loads
    and stays failed once it has.
  - `resolve`: `unavailable` when `describe` finds no tenant route, when the URL's path is the
    `href` of an entry `visibleWhen` hides, or when `visibleWhen` hides the route's owner (the
    entity, page or coded report); `no-access` per §8.3's checks; stored reports and dashboards
    (`core.Report`/`core.Dashboard` details) are `ok`. A core route is gated by its core entry's
    `requires`, falling back to the core feature's own declaration when a distribution hides it.
- **Core navigation** (`src/nav/tm-core-nav.ts`, wired in `src/declarations/tm-core-feature.ts`).
  Sections `analysis` (800) and `administration` (900); entries `core.settings` (administration,
  40) and the search-only `core.me`, `core.me.profile`, `core.me.region`, `core.me.display`,
  `core.me.notifications`. `core.settings` has no `requires`: the registry shows it with `Read` on
  any `metadata.settingCategories[].resource` (that is, any `core.Settings.<category>`), unless a
  distribution gives it `requires`. Strings: `tm.nav.*` in `TM_STRINGS_EN` and the Arabic table
  (`tm.admin.settings.title` and `tm.admin.me.title` already existed).
- **Pins model.**
  - Primary (`src/nav/tm-pins.ts`): `TmPinsDoc`, `TmPinItem`, `TmPin`, `TmPinFolder`, `tmPinsKey`
    (`nav.pinned`, curated, fallback `{ v: 1, items: [] }`, validate = shape) and
    `tmPinnedBarVisibleKey` (`nav.pinnedBarVisible`, curated, `true`).
  - Shell (`shell/src/pins/tm-pin-rules.ts`, not exported yet): `TM_PIN_LIMITS`, `tmPinsView` (ids,
    lengths in code points, the 30/10 caps, one level, duplicate ids; returns the document itself
    when nothing drops), `tmPinUrl` (capture minus `page`, `#d=` kept), `tmPinHref`, `tmCurrentPin`,
    `tmPinLabel`, `tmNewPinId`. `TmPins` (spec 0027 §8.4) will consume them.
- **Launcher seam** (`src/nav/tm-launcher-providers.ts`, primary): `TM_LAUNCHER_PROVIDERS` (root
  factory `[]`), `TmLauncherProvider`, `TmLauncherItem`, `TmLauncherSearchContext`.
- **Launcher terms** (`shell/src/launcher/tm-nav-terms.ts`, not exported yet): `TmNavTermsReader`,
  an entry's label and synonyms in a language, split on `,` and `،`.
- **Recents** (`recents/src/tm-recents.ts`): the `TM_RECENTS_NAVIGATION` seam is gone; `TmRecents`
  injects `TmNavigation` (`byHref` for title and icon, `resolve` for the filter). The edit is
  limited to the seam swap.
- **Budgets.** `.` raised 45 → 47 (44.81 → 46.63 linked, +1.82 KB; note in `package.json`);
  `@tellma/locale-ar/strings` raised 6.5 → 7 (6.47 → 6.66, +0.19 KB). `./recents` dropped to 1.47.
  `./recents` added to `staticGraphExcludes["./shell"]`.
- **Test rig** (`src/routes/tm-app.testing.util.ts`): `tmAppRig` takes `features`, `languages` and
  `strings`.

### Deviations

1. `TmNavItem` adds `label` (the active language's) and makes `icon`, `order` and `synonymsKey`
   required with their defaults applied; `TmNavSectionView` adds `label`. The launcher, pins and
   recents need the resolved values, and resolving them once in the registry keeps them sorted by
   the same labels.
2. The pins key's `validate` checks the shape only (`v: 1`, an `items` array). The item rules (ids,
   lengths, caps, one level) live with the pinned bar in `/shell`. §8.2 says a failing item leaves
   the view but stays stored, which a boolean `validate` cannot express (it would turn the whole
   value into the fallback), and §1 places only the pins types and keys in the primary.
3. The synonyms split (§3.3 "the registry splits it") lives in the shell's `TmNavTermsReader`,
   next to the launcher index that reads it, not on `TmNavigation`. It keeps the primary to the
   §3.1 contract. This and deviation 2 took 0.89 KB off the primary.
4. Entity entries come from stacks only. A child entity with a segment (`acme.SalesInvoiceLine`)
   has no search page: its segment routes only to drill-through lists, so an entry would not
   route.
5. Strings are platform `tm.*` keys in `TM_STRINGS_EN` and the Arabic table, not resx. The
   `ɵregisterStrings` seam is not on platform-core yet.
6. No icon glyphs registered for the default or core icon names (`file-text`, `square-dashed`,
   `chart-column`, `link`, `settings`, `user-cog`, `user`, `globe`, `sun-moon`, `bell`), to keep
   them off the first frame. The launcher and pinned bar chunks must register them.
7. `byHref` also finds a feature entry whose own `url` has a query (`/17/customers?f.X=…`); the
   spec describes path-only lookups. Callers that pass a path get exactly the spec's behaviour.

### Open risks

- `#state` recomputes the candidates on any change to access, language, tenant, metadata or the
  distribution document. It reads `allows`/`can` memo signals per entity and securable, so the
  cost is one pass over the declarations.
- Labels resolve through `TmLocalization.ɵtext`, memoized per key and fallback in the registry. In
  development a missing key warns once, as §3.3 asks.
- PC-111 also raises `.` (to 47) and edits recents. Whichever integrates second re-measures.

### What reviewers should examine hardest

- `resolve` against §8.3's table, especially the `#ownerShown` lookup for entity, page and report
  routes, and the core-route fallback to `TM_CORE_ENTRIES` when `core.settings` is hidden.
- The guard that reads `TM_APP_DECLARATIONS` only after the Core chunk loads.
- `tmPinsView`'s cap counting (pins in folders count against 30; a dropped folder drops its pins)
  and `tmCurrentPin`'s fallback (same path, the pin having no query or fragment).
- The `.` budget note's figures and the savings claimed.
