# PC-129: Layout kit: cards, fields, tabs, aside, audit, extras and validation schemas

## Implementer notes

### What was built, and where

All client paths are under `client/projects/core/` unless noted.

**`@tellma/core/details` (`tellma-core/details/src/`)**

- **`tm-details-card.ts`.** `TmDetailsCard` (`tm-details-card`) and `TmDetailsCardSection`
  (`tmDetailsCardSection`):
  - The field grid (one column, two from 768 px of the main column), `half`, `collapsible` with
    `collapsed` and the remembered state (`view.cards`), `scrollable`, `flush`, `preserveContent`.
  - The error dot on a collapsed card, and `focus()` from a field that opens it first.
- **`tm-details-scope.ts`.** The scope class the card, the card section and the tab share: the
  fields' error reports and the reveal chain.
- **`tm-field.ts`, `tm-field-cell.ts`, `tm-field-group.ts`.** `TmField` (`tm-field`),
  `TmFieldEdit` / `TmFieldView` (`ng-template[tmFieldEdit]` / `[tmFieldView]`) and `TmFieldGroup`
  (a host directive that forwards registration):
  - The path's resolution per end kind (value, text slots, navigation, dotted path), one cell per
    admitted slot, and unadmitted slots hidden.
  - View mode: a description list in the form field's geometry.
  - Edit and create mode: the read-only lock and the hint.
  - The two-state skeleton rule: while the record loads with nothing held, a skeleton and neither
    template.
  - Registration with the record, error reports to the card and tab, and `focus()`.
- **`tm-details-tabs.ts`.** `TmDetailsTabs`, `TmDetailsTab` and `TmDetailsTabContent` on
  `tm-tab-group`: `preserveContent`, the `collection` counter, error dots, the `selected` model and
  the remembered selection (`view.tabs`).
- **`tm-details-aside.ts`.** `TmDetailsAside` and `ɵTmDetailsAsideContent`: the layout registers
  the aside's template on the record, and the frame renders it in the sticky column.
- **`tm-details-audit.ts`.** `TmDetailsAudit`: a collapsed `audit` card with CreatedBy,
  CreatedAt, ModifiedBy and ModifiedAt, as far as the descriptor has them.
- **`tm-details-extra.ts`.** `*tmDetailsExtra` (a declared extra's slot, with a development error
  for an undeclared key) and `tmDetailsTitleExtra` (registered on the record, rendered after the
  badges).
- **`tm-details-kit.ts`.** `TmDetailsKit`, the import array.
- **`tm-details-schema.ts`.** `tmDetailsPlatformSchema(p, descriptor, options)`:
  - Required for what is not nullable, never for a flag or a defaulted member.
  - maxLength, and precision (the digits before the decimal point, leading zeros not counted).
  - Read-only for server, database and derived members, and for write-once members outside
    create mode.
  - Upload pending, and the recorded server errors per node.
  - Every child row gets its entity's rules, minus its parentKey.
- **`tm-details-model.ts`.** `tmDetailsComplete`: completes the working copy with `null` for every
  client-written member the read or the defaults left out, so Signal Forms builds a node (and
  its validators) for each.
- **`tm-details-record.ts`.**
  - Registers the details strings itself, so the kit resolves them outside the frame too (tests,
    a layout rendered on its own).
  - Provides `TmUploads` in every mode, and holds the aside and title-extra registrations.
- **`tm-details-frame.ts`.**
  - The band's grid: the main column as an inline-size container, the cards' grid, and the aside
    column from the band's lg width (272 px; 320 px from xxl), sticky with its own scroller.
  - Title extras after the badges.
  - No longer encapsulated: the layout host is `display: contents` through a descendant rule.
- **`tm-details-strings.ts`.** Read only, `{label}, has errors`, Audit info and Related
  information. The Arabic is in `locale/tellma-locale-ar/details-strings/strings-details-ar.ts`.

### Deviations

1. **Each field cell renders its own `dl`.** axe's `dlitem` / `definition-list` rules refuse a
   `dt`/`dd` pair whose `dl` is a card's grid with other elements in it.
2. **The working copy is completed with `null`** for client-written members the read omitted, on
   land and on create, so `entity()` is the completed copy.
   - Without this, an omitted member has no node, so a required member the read left out is never
     required.
   - A save now sends `null` for those members (see the open risks).
3. **`tmDetailsPlatformSchema` takes a third `options` argument**: the child descriptors, the
   mode, the uploads and the recorded errors. With none it applies the context-free rules.
4. **Tabs sit in a card section, not directly in a card.** Spec 0031 §6.6's example puts
   `tm-details-tabs` directly in a card, which §6.1's development error ("tabs inside a field
   grid") forbids. The rule wins: tabs go in a `tmDetailsCardSection` or outside a card.
5. **`TmUploads` moved from `/entity-editing` to `/entity`.** The record provides it in every
   mode, and `/details` may not statically reach the edit side.
6. **Upload pending is reached only once the sync rules pass**, as Signal Forms runs async
   validators after the sync ones.
7. **The new error kind `precision`** adds `errors.precision` to the core-ui table (English and
   Arabic) and raises the core-ui primary's ceiling by 0.02 KB.
8. **The field's edit mode lives in `@tellma/core/entity-editing`** as `ɵTmFieldEditor`, not in a
   `/details` chunk of its own. `tm/core-import-boundary` forbids `/details` from importing
   `/entity-editing` statically, even from a file only `import()` reaches. A dynamic import of
   the entry point is allowed and keeps the edit stack out of the details route.
9. **The aside and title extras are registered on the record and rendered by the frame**, so the
   layout never renders them in place.
10. **The frame is not encapsulated**, so the layout's host is `display: contents` through a
    descendant rule and the cards sit on the frame's grid.
11. **A navigation field registers under its foreign key's name** (`Currency` registers as
    `CurrencyId`), the member the server's errors name.
12. **Child rows skip the rules on their parentKey**, which the server writes.
13. **Acme's layout omits the Contacts child grid card.** `tm-child-grid` belongs to the next
    checkpoint, so the layout is the customer card and the audit.
14. **The aside's lg and xxl breakpoints read the band's container width**, not the viewport,
    because the shell's navigation narrows the band.
15. **Budgets raised** (below). `/details` stays within spec 0031's 23 KB for the whole entry
    point.
16. **Acme does not ship spec 0031 §7.2's corporate credit-limit rule.** It puts Signal Forms in
    initialJs (below).

### Open risks

- **Null completion on save.** A save sends `null` for every client-written member the read
  omitted. That is the same value the server holds when the member was absent because it was
  null, but a server that treats an absent member as "unchanged" and `null` as "clear" would now
  clear it. Read plans that omit members on purpose would need the completion narrowed to what
  the layout shows.
- **The frame is not encapsulated.** Its rules are all under `.tm-details`, but a layout's own
  styles can now meet them.
- **The edit side is one entry point.** The first edit loads all of `/entity-editing` (12 KB),
  not just the field editor. It is prefetched once `can.edit()` holds.
- **The `CurrencyId` registration key.** A layout that calls `focus('Currency')` or reads
  registrations by the navigation's name finds nothing.
- **Upload pending only after the sync rules pass.** A form with a sync error and a running
  upload shows the error, not the pending state.
