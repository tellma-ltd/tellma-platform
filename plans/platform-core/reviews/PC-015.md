# PC-015: Cross-spec contract seed (wire seed, CRUD/validation contracts, endpoint and asset contracts)

## Implementer notes

### What was built, and where

All in `src/core/Tellma.Core.Abstractions/`, under the owners' exact names and namespaces. Every type
carries full XML docs and its owner's semantics, and none needs later machinery.

- **The Queryex edge.** `Tellma.Core.Abstractions.csproj` now references `Tellma.Core.Queryex`
  (ARCHITECTURE.md and specs 0014/0015/0016/0017/0021 already state the edge; PC-018 listed it as
  its own deliverable but is gated on this checkpoint). It is needed by `InvalidQueryException`
  (`IReadOnlyList<QueryexDiagnostic>`). CI's design-e2e package flow now packs `Tellma.Core.Queryex`
  before `Tellma.Core.Abstractions` (`.github/workflows/ci.yml`); I ran the package flow locally
  (pack the four libraries, build the package-flow host against an isolated NuGet cache): it restores
  and builds.
- **`Tellma.Core.Abstractions.Api`** (spec 0016 §1.1, §3.1–§3.4, §4.1, §10.1):
  - `TellmaJson` (`Options`, read-only; `Configure(options)`, idempotent, platform converters first,
    `TellmaApiJsonContext.Default` first in the resolver chain, a `DefaultJsonTypeInfoResolver` last).
    Rules: camelCase, case-insensitive, `WhenWritingNull`, `Strict` numbers,
    `AllowDuplicateProperties = false`, unmapped `Skip`, `MaxDepth = 16`, enums as strings.
  - The scalar converters (`ScalarJsonConverters.cs`, internal): `long` and `decimal` as strings
    (read from a string or a number), `DateTime`/`DateTimeOffset`/`TimeOnly` with seven fractional
    digits, plus property-name support for each so dictionary keys keep working. Their grammars are
    hand-parsed in `ScalarText.cs` (culture-free, no whitespace). `DateOnly`, `Guid`, `byte[]`,
    `double`, `int`, `bool` keep the framework's converters, whose forms already match the §3.2 table
    (pinned by tests).
  - `TellmaApiJsonContext` (metadata mode): every non-generic request/result record seeded here, the
    two problem-detail records (`ConcurrencyConflict`, `ConfirmationRequest`) and the scalar types.
  - Request records: `QueryRequest`, `GetRequest`, `AllRequest`, `IdsRequest`(+`<TArguments>`),
    `IdRequest`(+`<TArguments>`), `GetByIdsRequest`, `EntityActionRequest`(+`<TArguments>`),
    `ParentIdsRequest`, `DeleteByQueryRequest`, `AccessHoldersRequest`. Result records:
    `AffectedResult`, `JobAccepted`, `SecurableSummary`, `QueryDiagnostic`. Plus `TellmaHeaders`,
    `WireIds`, `ApiTelemetryNames`, `McpTelemetryNames`.
  - Projection attributes `ApiResourceAttribute`, `DefaultSelectAttribute`,
    `RelatedSelectAttribute`, `DetailsExpandAttribute` and `McpExposure`.
- **`Tellma.Core.Abstractions.Crud`** (0015 §2.2–§2.3, §11.2): `StackOperations`, `StackAttribute`,
  `EntityActionAttribute`, `ApiActionAttribute`, `DetailsExtrasAttribute`, `ApiRouteAttribute`,
  `EntityRefAttribute`.
- **`Tellma.Core.Abstractions.Validation`** (0015 §7.3): `ValidationPath`, `PathSegment`,
  `IndexSegment`, `PropertySegment`, `ValidationErrors`, `ValidationErrors<TEntity>` (thread-safe; the
  typed `Add` reads the member name off `x => x.Prop`, through a boxing convert or an interface cast,
  and refuses anything deeper), `ValidationCodes`.
- **`Tellma.Core.Abstractions.Errors`** (0015 §7.3, §14.1): `TellmaException`, `CodedError`,
  `ValidationError`, the twelve sealed members (`ValidationException`, `NotFoundException`,
  `ForbiddenException`, `ConcurrencyException`, `ConfirmationRequiredException`,
  `CountMismatchException`, `LimitExceededException`, `InvalidQueryException`,
  `BadRequestException`, `IndividualRequiredException`, `DependencyUnavailableException`,
  `PartialFailureException`), `ForbiddenReason`, `ConcurrencyConflict`, `ConfirmationRequest`,
  `LimitNames`. Each exception exposes its constructor arguments as properties, puts its display
  values in `Arguments` (`resource`, `ids`, `action`, `reason` in kebab-case, `path`, `expected`,
  `actual`, `limit`, `maximum`, `dependency`) and renders a bounded English log message.
- **`Tellma.Core.Abstractions.Access`** (0014 §4.1/§4.5): `SecurableEndpointMetadata`,
  `MemberEndpointMetadata`.
- **`Tellma.Core.Abstractions.Notifications`** (0021 §2.3, §4.1, named by 0011 §2.1):
  `NotificationTypeDescriptor`, `NotificationChannelDescriptor`, `NotificationSeverity`. Plain
  records; the grammar and the `Inbox = false` rule are the registry's startup check (PC-035).
- **0024 §3.2** (`IClientAssetContributor`, `ClientAssetContext`, `ClientMetadataChunk`,
  `TellmaRoutes`): already built by PC-001; I checked them against §3.2 and changed nothing. None of
  the new types is a multi-registration interface, so no new `[CollectionService]` marks.
- **Internal helpers**: `Internal/ReadOnlyCopies.cs` (defensive read-only copies),
  `Internal/ArgumentBags.cs` (content equality of argument bags), `Errors/LogText.cs` (bounded lists
  in log messages).
- **Tests** (`test/core/Tellma.Core.Abstractions.Tests`, new folders `Api/`, `Crud/`, `Validation/`,
  `Errors/`, `Access/`, `Notifications/`; 341 tests in the project, all green).
- **Docs**: the Abstractions README (new namespaces, the Queryex edge, the "declarations are data"
  and "closed exception set" rules) and the test project's README. ARCHITECTURE.md already describes
  everything settled here (Abstractions → Queryex only, the annotations), so it is unchanged.

### Deviations

1. **`StackAttribute` has no `DefaultSelect`.** 0015 §2.3's sketch gives `[Stack]` a `DefaultSelect`
   parameter, while 0016 §4.1 declares `[DefaultSelect]`, 0015 §2.2's member table and §2.6's startup
   check name `[DefaultSelect]`, and every consumer (0019, 0020, 0021, 0022, 0026, 0028) writes
   `[DefaultSelect(...)]`. Two declarations of one fact break "nothing is declared twice"; the
   attribute serves every consumer, so `[Stack]` keeps only `DefaultOrderBy`. A test pins it.
2. **Attribute parameters are settable named properties**, with the name/route/resource/select as
   the one positional argument. The sketches use primary-constructor notation, but every spec usage
   (`[Stack(Operations = …)]`, `[EntityAction("post", LoadChildren = true)]`,
   `[ApiResource(Segment = …)]`) is named-property syntax, which only properties allow.
3. **Attribute usage settled where the sketches are silent.** Every annotation is sealed and
   inherited. `[EntityAction]`/`[ApiAction]` target methods with `Inherited = true`, so a
   distribution's override of a pack's action method stays the action (with `false` it would vanish
   silently). `[DetailsExtras]` has `AllowMultiple = true`, so reflection's inherited lookup returns
   the names on the class and its bases, as 0015 §2.3 states. `[EntityRef]` targets properties
   (`[property: EntityRef(…)]` in every usage). Attributes validate nothing: the startup checks
   report problems with the entity named.
4. **The closed set is closed by construction.** `TellmaException`'s constructor is
   `private protected`; every owner of a member (0011 Tenancy, 0013 Errors, 0017 Blobs, 0019 Excel)
   is in this assembly.
5. **`TellmaException.Code` is documented as "the outcome's code", kebab-case for most members.**
   0015 §14.1 calls it "kebab-case problem code", but 0017 §8.2's `BlobRejectedException(Code, …)`
   carries a dotted `Blob.*` code whose problem code is the fixed `blob-rejected`. The base does not
   validate the code's grammar, so both shapes fit; the edge maps by type (0016 §7.1). Reported.
6. **`BadRequestException(Detail, Arguments = null)`**: an optional argument bag added, so a refusal
   names its path or parameter structurally (`WireIds` puts `path` there, 0016 §3.2 "naming its
   path"; 0015 §4.3 "naming the parameter"). The problem body's `arguments` already exists for every
   exception (0016 §7.2).
7. **Constructors validate the outcome they describe**: a validation, concurrency, confirmation or
   invalid-query exception needs at least one item and no null; a `ForbiddenException` needs a path
   exactly for `RestrictedPath` and a defined reason; a negative `RetryAfter` is refused; blank codes,
   resources and limit names are refused. Collections are copied read-only.
8. **Content equality**: `ValidationPath` compares by segments (0019 keys a dictionary by path, which
   record equality over a list reference could not do); `CodedError`/`ValidationError` and
   `ConfirmationRequest` compare arguments name by name and ids in order. A `PropertySegment` name may
   not hold `.`, `[` or `]`, so the bracket form stays unambiguous. `ValidationPath.Root` renders as
   the empty string.
9. **JSON clarifications**: an enum read from an integer is refused (`allowIntegerValues: false`),
   since an integer admits undefined values; `ForbiddenReason` declares its kebab-case wire names
   (`[JsonStringEnumMemberName]`). Inbound grammars: `DateTime` is `yyyy-MM-ddTHH:mm:ss[.f{1,7}]` and
   refuses any offset (a wall-clock value cannot carry one; the framework would silently convert to
   local time); `DateTimeOffset` requires `Z` or `±HH:mm` (within ±14:00); `TimeOnly`
   `HH:mm:ss[.f{1,7}]`; `long` strings `-?[0-9]+`. A `decimal` is never rounded: a JSON number may use
   an exponent, a string may not, and a value a decimal cannot hold exactly (more than 29 significant
   digits, non-zero digits past scale 28, beyond range) is refused; trailing zeros are dropped only
   when needed to fit. A token longer than 128 bytes is refused unread. Timestamps are written with
   `WriteRawValue` so the `+` of an offset is not escaped to `+` by the default encoder.
10. **Unknown-member counting is the web host's.** 0016 §3.1 counts every skipped member on
    `tellma.api.unknown_members` (meter `Tellma.Core.AspNetCore`). `TellmaJson.Options` also serves the
    migrator and stored JSON, where that meter does not exist, so the counter belongs on the web host's
    HTTP copy (a type-info modifier added after `Configure`), with `Tellma.Core.AspNetCore` (0016-e).
    The rule itself (`Skip`) is in place.

  `ValidationPath` rendering, `ValidationErrors<T>` member inference and exception argument shapes.
  Its API golden will include them.
- **PC-064 (0016-b)**: under `TellmaJson`, `ConcurrencyConflict.Id` and `ConfirmationRequest.Ids`
  serialize as strings (they are `long`); 0016 §3.2's problem-body display rule (a number within
  ±(2^53−1), else a string) is PC-064's helper.
- **`MeResult` family** has no owner checkpoint.
- **`ApiOptions.ClientNames`** is read by PC-032's CSRF rule 3 (0011 §5.4) before 0016-e (which owns
  §1.3) lands; PC-032 creates `Tellma.Core.AspNetCore` and should create `ApiOptions` there.
- `[Stack]` ceilings are documented as positive, but 0015 §2.6 lists no startup check for a
  non-positive one; PC-063 should add it.

### What reviewers should examine hardest

1. `Api/ScalarText.cs`: the decimal exactness rules (exponent, scale > 28, 29-digit significand,
   trailing-zero dropping) and the date/time grammars, against 0016 §3.2.
2. `TellmaJson.Configure`: converter precedence over a host's converters, idempotence, and that the
   source-generated context still honours the runtime converters (`WireRecordTests` pins the long
   members of a generated record).
3. Initializer order in the primary-constructor exceptions: member initializers (validation) run
   before the base call that renders the log message; `ValidationException(null!)` is pinned to throw
   `ArgumentNullException`, not a `NullReferenceException`.
4. Deviations 1, 3, 4 and 5 (shape decisions later checkpoints build on).
