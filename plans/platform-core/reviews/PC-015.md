### Deviations

1. **`StackAttribute` has no `DefaultSelect`.** 0015 §2.3's sketch gives `[Stack]` a `DefaultSelect`
   parameter, while 0016 §4.1 declares `[DefaultSelect]`, 0015 §2.2's member table and §2.6's startup
   check name `[DefaultSelect]`, and every consumer (0019, 0020, 0021, 0022, 0026, 0028) writes
   `[DefaultSelect(...)]`. Two declarations of one fact break "nothing is declared twice"; the
   attribute serves every consumer, so `[Stack]` keeps only `DefaultOrderBy`. A test pins it.
2. **Attribute parameters are settable named properties**, with the name/route/resource/select as
   the one positional argument. The sketches use primary-constructor notation, but every spec usage
   (`[Stack(Operations = …)]`, `[EntityAction("post", LoadChildren = true)]`,
   `[ApiResource(Segment = …)]`) is named-property syntax, which only properties allow.
3. **Attribute usage settled where the sketches are silent.** Every annotation is sealed and
   inherited. `[EntityAction]`/`[ApiAction]` target methods with `Inherited = true`, so a
   distribution's override of a pack's action method stays the action (with `false` it would vanish
   silently). `[DetailsExtras]` has `AllowMultiple = true`, so reflection's inherited lookup returns
   the names on the class and its bases, as 0015 §2.3 states. `[EntityRef]` targets properties
   (`[property: EntityRef(…)]` in every usage). Attributes validate nothing: the startup checks
   report problems with the entity named.
4. **The closed set is closed by construction.** `TellmaException`'s constructor is
   `private protected`; every owner of a member (0011 Tenancy, 0013 Errors, 0017 Blobs, 0019 Excel)
   is in this assembly.
5. **`TellmaException.Code` is documented as "the outcome's code", kebab-case for most members.**
   0015 §14.1 calls it "kebab-case problem code", but 0017 §8.2's `BlobRejectedException(Code, …)`
   carries a dotted `Blob.*` code whose problem code is the fixed `blob-rejected`. The base does not
   validate the code's grammar, so both shapes fit; the edge maps by type (0016 §7.1). Reported.
6. **`BadRequestException(Detail, Arguments = null)`**: an optional argument bag added, so a refusal
   names its path or parameter structurally (`WireIds` puts `path` there, 0016 §3.2 "naming its
   path"; 0015 §4.3 "naming the parameter"). The problem body's `arguments` already exists for every
   exception (0016 §7.2).
7. **Constructors validate the outcome they describe**: a validation, concurrency, confirmation or
   invalid-query exception needs at least one item and no null; a `ForbiddenException` needs a path
   exactly for `RestrictedPath` and a defined reason; a negative `RetryAfter` is refused; blank codes,
   resources and limit names are refused. Collections are copied read-only.
8. **Content equality**: `ValidationPath` compares by segments (0019 keys a dictionary by path, which
   record equality over a list reference could not do); `CodedError`/`ValidationError` and
   `ConfirmationRequest` compare arguments name by name and ids in order. A `PropertySegment` name is
   any non-blank text, a dotted setting key included (`Entries` then `gl.posting.autoNumberOnPost`,
   0013 §6.5). `ValidationPath.Root` renders as the empty string.
9. **JSON clarifications**: an enum read from an integer is refused (`allowIntegerValues: false`),
   since an integer admits undefined values; `ForbiddenReason` declares its kebab-case wire names
   (`[JsonStringEnumMemberName]`). Inbound grammars: `DateTime` is `yyyy-MM-ddTHH:mm:ss[.f{1,7}]` and
   refuses any offset (a wall-clock value cannot carry one; the framework would silently convert to
   local time); `DateTimeOffset` requires `Z` or `±HH:mm` (within ±14:00); `TimeOnly`
   `HH:mm:ss[.f{1,7}]`; `long` strings `-?[0-9]+`. A `decimal` is never rounded: a JSON number may use
   an exponent, a string may not, and a value a decimal cannot hold exactly (more than 29 significant
   digits, non-zero digits past scale 28, beyond range) is refused; trailing zeros are dropped only
   when needed to fit. A token longer than 128 bytes is refused unread. Timestamp values are written
   with `WriteRawValue`, so the `+` of an offset is not escaped to `\u002B`; a dictionary key
   goes through the encoder, which does escape it, and still reads back the same.
10. **Unknown-member counting is the web host's.** 0016 §3.1 counts every skipped member on
    `tellma.api.unknown_members` (meter `Tellma.Core.AspNetCore`). `TellmaJson.Options` also serves the
    migrator and stored JSON, where that meter does not exist, so the counter belongs on the web host's
    HTTP copy (a type-info modifier added after `Configure`), with `Tellma.Core.AspNetCore` (0016-e).
    The rule itself (`Skip`) is in place.
11. **The encoder writes every basic-plane script as itself** (orchestrator ruling, review 1):
    `JavaScriptEncoder.Create(UnicodeRanges.All)`, so Arabic and Amharic are not six-fold `\uXXXX`
    escapes on the wire, in stored JSON or in agent results; the HTML-sensitive characters (`<`, `>`,
    `&`, quotes, `+`) stay escaped. Never the unsafe relaxed encoder. The spec names no encoder.

## Review 1

### Findings

Scope checked: every seeded type against each spec that names it (0011, 0012, 0013, 0014, 0015,
0016, 0017, 0019, 0021); the 11 deviations; both spec-conflict rulings; the Queryex edge and the
`design-e2e` pack step. Confirmed correct, with no finding: names, namespaces, members and member
types of the request and result records, the attributes, the closed exception set,
`ValidationCodes` (all 22), `LimitNames`, `TellmaHeaders`, both telemetry classes, the endpoint
metadata and the notification descriptors. Deviation 1 ([Stack] has no `DefaultSelect`) matches
every `[Stack(...)]` usage in the specs: none passes `DefaultSelect`. The ruling that
`TellmaException.Code` is not grammar-checked is needed for 0017 §8.2's dotted `Blob.*` codes,
since the edge maps by type. The `private protected` base fits, because every owner (0011
Tenancy, 0013 Errors, 0017 Blobs, 0019 Excel) is in this assembly. Member initializers run before
the base call, so validation runs before `Describe`. The decimal exactness rules hold for every
edge I probed: 29 nines at scale 28 refused, a trailing zero dropped only to fit, exponent
saturation, zero's scale clamped. The date grammars and offset range hold too. The CI pack order
is right. Re-run here: `dotnet build Tellma.slnx` succeeded with 0 warnings, `dotnet format
--verify-no-changes` reported no changes, and the PR-tier unit filter passed in all 15 assemblies
(`Tellma.Core.Abstractions.Tests` 341/341). I did not re-run the integration suites. The edge adds
no code to them, and the commit lists all of them as run.

**Blocking:** none.

**Major**

- **R1-1 — `PropertySegment` refuses `.`, `[` and `]`, which breaks spec 0013's settings error
  paths.** Location: `src/core/Tellma.Core.Abstractions/Validation/PathSegment.cs:71-77`
  (`ValidateName`), and deviation 8.
  - *What 0013 needs:* 0013 §6.5 puts settings-save errors at "the patch member or
    `entries.<key>`". A setting key is dotted by grammar: 0013 §5.3 requires at least two
    segments, as in `gl.posting.autoNumberOnPost`. For `Settings.KeyUndeclared` the key is
    whatever the client sent.
  - *Failure:* the settings validator (PC-079, `SettingsService` save) writes
    `ValidationPath.Root.Property("Entries").Property(key)`. That throws `ArgumentException` from
    inside validation, so the user gets a 500 `internal` instead of a 422 `validation`. This
    happens for every entry error, and a client can trigger it at will with any undeclared key.
  - *Why the rule buys nothing:* 0015 §7.3 places no character rule on property names. The only
    beneficiary is the bracket `ToString()`, which is for logs and tests only. The edge (0016
    §7.3) and the Excel codec (0019) render segments themselves and never parse a path.
  - *Fix:* refuse only a null or blank name. Drop the `.[]` check, its `<exception>` text, the
    README/deviation sentence, and the `"Lines.Quantity"`/`"Lines[0]"` cases in
    `ValidationPathTests.A_property_name_is_one_plain_name`. Add a test that
    `Root.Property("Entries").Property("gl.posting.autoNumberOnPost")` builds and compares by
    value.

**Minor**

- **R1-2 — A missing `ids` binds to null on the positional records, and becomes a 500 later.**
  Location: `src/core/Tellma.Core.Abstractions/Api/IdsRequest.cs:19` and `:32`, and
  `Api/GetByIdsRequest.cs:17`.
  - *Failure:* a body of `{}` binds `Ids` to null, although `Ids` is declared non-nullable. The
    probe confirmed this. `EntityActionRequest` instead defaults `Ids` to `[]`. The binder's
    `WireIds.ToKeys(request.Ids, "ids")` then throws `ArgumentNullException`, so the client gets
    a 500 rather than 0016 §3.3's 413 `limit-exceeded`. Every later binder would have to remember
    the null.
  - *Fix:* normalise in the records, as `EntityActionRequest` does:
    `public IReadOnlyList<long> Ids { get; } = Ids ?? [];`. Add a `WireRecordTests` case that `{}`
    binds an empty list for all three.
- **R1-3 — `WireIds.ToKeys` allocates a path string for every id, not only for a bad one.**
  Location: `src/core/Tellma.Core.Abstractions/Api/WireIds.cs:49`.
  - *Failure:* `string.Create(..., $"{path}[{i}]")` runs before `Narrow`. Every int-key call
    with up to `MaxIds` (10,000) ids therefore allocates 10,000 strings that are never used.
  - *Fix:* pass `path` and `i` to `Narrow`, and format the indexed path only when throwing.
- **R1-4 — Non-ASCII text is written escaped under `TellmaJson`.** Location:
  `src/core/Tellma.Core.Abstractions/Api/TellmaJson.cs:77-84` (no `Encoder` is set).
  - *Failure:* the default encoder writes every non-ASCII character as `\uXXXX`. The probe wrote
    `"مركز"` as `"مركز"`. For an Arabic or Amharic tenant, every response,
    stored JSON column and MCP text block grows about sixfold for its text. 0016 §11.7's
    `MaxToolResultChars` (60,000) then truncates `tellma_query`/`tellma_get` results about six
    times sooner.
  - *Status:* the spec does not mention an encoder, so this is a decision, not a deviation.
  - *Fix:* set `options.Encoder = JavaScriptEncoder.Create(UnicodeRanges.All)` in `Configure`.
    It still escapes HTML-sensitive characters. Pin it with a test.
- **R1-5 — No test covers the property-name paths of four converters, and one is inconsistent.**
  Location: `src/core/Tellma.Core.Abstractions/Api/ScalarJsonConverters.cs:95-108, 151-164,
  206-219, 259-272`.
  - *Gap:* `ReadAsPropertyName`/`WriteAsPropertyName` of the decimal, `DateTime`,
    `DateTimeOffset` and `TimeOnly` converters are untested; only the `long` key round trip is
    pinned. A broken key grammar, such as one accepting an exponent or an offset on a
    `DateTime`, would pass.
  - *Inconsistency:* a `DateTimeOffset` key is written through `WritePropertyName`, which
    escapes `+`. The probe got `{"2026-01-01T00:00:00.0000000+03:00":1}`, unlike the raw
    value form that the implementer notes and deviation 9 describe.
  - *Fix:* add key round-trip and refusal tests for the four converters. Either document that
    keys keep the encoder's escaping, or have R1-4's encoder setting cover it.
- **R1-6 — The `HierarchyId` row of 0016 §3.2 is neither seeded nor listed as not seeded.**
  Location: the review file's "Not seeded, and why" section and the commit's deviations.
  - *Gap:* the entry's test line is "every scalar of 0016 §3.2 round-trips". The `HierarchyId` →
    path-string row cannot live in Abstractions, which has no EF reference, but nothing names its
    owner. PC-018 pins `HierarchyId`, and PC-021/PC-064 handle the row-set cell.
  - *Fix:* add it to "Not seeded" with its owner, so the entity-property converter is not lost
    between PC-018 and PC-064.
