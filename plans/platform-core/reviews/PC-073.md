# PC-073: tellma-client CLI: emit, serve, build and checks

## Implementer notes

### What was built, and where

All paths are under `client/projects/core/tellma-core-tools/` unless stated.

- **The command line** (`src/cli/tellma-client.ts`): `tmRunCli(argv, streams, environment)` parses
  `emit [--configuration c|-c c] [--no-dotnet-build]`, `serve [--port n]` and
  `build [--configuration c] [--no-dotnet-build]`, with per-command help. Exit codes: 0 success,
  1 usage (unknown command or option, missing value, bad port), 2 failure (any `TmBuildFailure`
  or unexpected error, printed as `tellma-client <command>: <message>`), 3 problem. The third
  argument injects the working directory and the process runner, which every spec uses.
- **Shared plumbing** (`src/common/`): `problems.ts` (`TmBuildProblem`, `TmBuildFailure`, the
  one-line format `code key feature - message`, spaces in a field become `_`), `process.ts` (the
  `TmProcessRunner` seam and the real runner: no shell except Windows' `pnpm`/`npm`/`npx` shims; a
  program that cannot start is a `TmBuildFailure`), `files.ts` (posix relative paths, recursive
  listing, the Migrator's content hash, gzip-9/Brotli-11 sizes), `html.ts` (parse5 document and
  fragment parsing, element walk including `<template>` content).
- **The project** (`src/project/app-project.ts`): reads `package.json` (`tellma.migrator`,
  `tellma.budgets`) and the one application in `angular.json` (outputPath string or object, index,
  tsConfig, a `serve` target); fixed layout `src/app.config.ts`, `public/`, `generated/`,
  `dist/<slug>/{browser,sourcemaps,stats.json}`. `tmFindPackageDir` finds a package by Node's
  `node_modules` walk (ignoring `exports`, since `@tellma/core` does not export its
  `package.json`), else through the tsconfig `paths` (resolved with the TypeScript API, so
  `extends` chains work) up to the folder whose package.json carries the name.
- **Emit** (`src/emit/`): `tmRunEmit` runs `dotnet run --project <Migrator> --no-launch-profile
  [--configuration c] [--no-build] -- emit-client-assets <absolute generated/>` in the Migrator's
  folder (PC-034's command reads `appsettings.json` from its content root and resolves the folder
  against its working directory). `tmReadEmittedMetadata` reads `generated/assets/` back by
  PC-034's naming pattern, refuses a name whose hash is not the content's, a missing or doubled
  chunk, a malformed Core chunk (slug, display name, versions, languages, plain routing words) or
  a string pack that is not a flat string table.
- **Source checks** (`src/checks/`): `config-check.ts` + `config-check-runner.ts` (a child Node
  process: tsx `register({ namespace, tsconfig })`, `@angular/compiler` first, then
  `src/app.config.ts`, `@tellma/core` and `@tellma/core/config-check` imported in that one
  namespace so `tmAppConfigOf` finds the config; the string packs are passed, so
  `string-key-collision` is reported; the answer goes through a temp file; `label-missing` stays a
  warning); `index-html.ts` (the six `TM_INDEX_HTML_RULES` evaluated on a parse5 tree; the boot
  script must be the first `<script>` in `<head>`, `src="tm-boot.js"`, classic, no async/defer);
  `manifest.ts` + `png.ts` (members, grapheme-counted short names including the localized ones
  from the packs, PNG IHDR size vs `sizes`, `prefer_related_applications`); `brand.ts` (override
  over default, viewBox with positive size, no `<script>`, no `on*`, no `javascript:` href; a name
  neither folder provides is `brand-file-invalid`); `budgets.ts` (levels, raises from package.json
  with `budget-note-missing`, measuring, report table); `hashed-names.ts`.
- **Output steps** (`src/output/`): `stats.ts` (`TmBuildGraph` from the esbuild metafile: JS
  outputs only, static and dynamic edges; `tmEntryPointModule` matches an entry point by its
  fesm bundle name or its workspace source folder; `tmEchartsModule`); `boot.ts` (`TM_BOOT` from
  the Core chunk's languages and the packs' boot strings, English always, display name filling
  English's `Distribution_DisplayName`, a language with no boot string of its own left out;
  English missing a boot string is a failure); `preloads.ts`; `worker-config.ts`
  (`tmNavigationUrls`, `tmOnDemandChunks`: everything the initial scripts reach minus what they
  reach without entering an on-demand root by a dynamic import; `tmWorkerGroups`: explicit file
  lists; `tmWorkerConfig`); `source-maps.ts`.
- **Commands** (`src/commands/`): `build.ts` (the six steps; a source error returns before
  `ng build`), `serve.ts`, `context.ts`.
- **Fonts** (`src/fonts/index.ts`, new export `@tellma/core-tools/fonts`, golden
  `client/api/core-tools.fonts.api.md`): the fragment map moved from
  `client/scripts/inject-font-preloads.mjs`, now keyed by ISO 15924 script (a language's script
  from `Intl.Locale(code).maximize()`), `tmIsFontForFragments` (never an `-ext` subset),
  `tmBuiltFontUrls`, `tmInjectFontPreloads`. `client/scripts/inject-font-preloads.mjs` is a thin
  wrapper over it for the showcase build and `scripts/serve.mjs --prod`.
- **Fixture** (`fixtures/`): `app/` (a minimal distribution client: the §4.1 index.html, manifest,
  three real PNG icons, favicon, four brand SVGs, one feature with one lazy page, en+ar fonts,
  build and serve targets), `migrator/` (the stand-in Migrator's JSON: Core, Entities,
  Contracts, en and ar packs with the platform's real boot strings) and `fake-emit.ts` (writes
  what the emit writes, a recording runner that answers `dotnet run … emit-client-assets`, and
  `copyFixtureApp` to `fixtures/run-<name>/`, gitignored and ESLint-ignored).
- **Dependencies**: `@angular/service-worker` 22.0.5 (catalog, client), `parse5` 8.0.1 and `tsx`
  (catalog) as runtime dependencies of `@tellma/core-tools`.
- **Docs**: core-tools README (commands, steps, problem lines, budgets), fixture READMEs,
  core-ui README pointer, ARCHITECTURE.md's worker-group sentence (fonts and on-demand members).

### Deviations

1. **`ng build` runs with `NG_BUILD_OPTIMIZE_CHUNKS=false`.** Angular 22's chunk optimizer (on by
   default once a build has three lazy chunks) re-bundles the chunks with Rollup after esbuild has
   written the metafile. Measured on the fixture: `stats.json` then names chunks the output does
   not hold, an orphan chunk stays in the output importing chunks that no longer exist, and the
   merged chunks get base64url hashes (`chunk-Ci8p4wIT.js`) that fail §6's hashed-name rule. With
   the optimizer off the metafile is the true graph and every name is `[A-Z0-9]{8}`. Cost: a few
   more, smaller chunks.
2. `navigationUrls` also exclude the bare `/*/<w>` for each tenant word (§5.3 lists only
   `/*/<w>/**`); §6's fallback gives the server `/<int>/<w>` itself too.
3. `build` accepts `--configuration c` as `emit` does, so an esproj build of a Release Migrator
   with `--no-dotnet-build` finds the Release output.
4. Budgets: a `bootScript` row is added (3 KB + 0.4 KB per further table, the boot-template
   test's rule); the `@tellma/core` primary's 50 KB row is not measured in the app build (the
   package's `size:check` budgets its entry points); the route rows measure the closure of the
   chunks holding `@tellma/core/search|details` and `/entity` beyond the initial set, without the
   distribution's layout chunks, which the metafile cannot tell from other lazy chunks;
   `@defer`red chunks get no line of their own. Rows whose entry points do not exist yet measure
   zero files and print `-`.
5. Budget settings: an unknown budget name or a non-positive level is a build failure (exit 2);
   lowering a level, or setting a level the platform leaves empty, needs no note.
6. Fonts: `-ext` subsets (`latin-ext`, …) are never preloaded and are in neither worker group;
   fonts of scripts not offered are in neither group either, so the browser fetches them when a
   page needs them. The spec's shell lists "the Latin and offered-script fonts".
7. The localized short names (`Distribution_ShortName`) are checked in the source step, before
   `ng build`, rather than on the output manifest.
8. A brand name neither `public/brand/` nor `@tellma/core/brand/` provides is
   `brand-file-invalid`; a `javascript:` href is refused alongside `<script>` and `on*`.
9. `serve` requires a `serve` target on `@angular/build:dev-server` (§2.1's angular.json lists only
   build and test); a dev server that exits non-zero is exit 2. The certificate is exported once to
   `%APPDATA%/ASP.NET/https` (Windows) or `~/.aspnet/https` as `<slug>.pem`/`<slug>.key`, as
   ASP.NET Core's SPA templates do. The tenant-word proxy matches an integer first segment
   (`^/[0-9]+/…`), §6's fallback rule. In-repo detection: the nearest `pnpm-workspace.yaml` whose
   `package.json` has a `tokens:build-css` script.
10. Problem lines carry the message after the three fields: `code key feature - message`.
11. The worker groups list files by name rather than by glob; `ngsw-config.json` is written to
    `dist/<slug>/`, outside the deployable output.
12. An English string pack missing a boot string is a build failure (exit 2): the boot script
    embeds English as every language's fallback, and the renderer refuses an incomplete table.
13. The source maps step stays where §2.6 puts it (after the worker config): the explicit file
    lists never include a `.map`, so the hashes are unaffected.

### Open risks

- **No real string packs yet.** PC-034's emit writes `strings: {}` and no `strings-*.json`; the
  packs come with PC-046. Until then a real Migrator's emit makes `build` exit 2 ("The English
  string pack lacks …"), because the boot script needs every English boot string. Acme (PC-094)
  is gated on PC-046, so nothing real builds before then.
- **No default brand SVGs yet** (`@tellma/core/brand/`, PC-094): until they land, a distribution
  must override all four in `public/brand/`.
- `/shell`, `/attention`, `/search`, `/details`, `/entity`, `/report-studio`, `/support` and the
  ECharts engine do not exist yet: the modulepreloads, route budgets and on-demand group are
  covered by synthetic-graph unit specs only; the fixture build exercises the empty case.
- The fixture's real `ng build` took 4-12 minutes on this loaded machine (about a minute
  unloaded); `build.fixture.spec.ts` allows 20 minutes for its `beforeAll` and runs in `lint:test`.

### What reviewers should examine hardest

1. `tmOnDemandChunks` (`src/output/worker-config.ts`) and the initial/modulepreload sets in
   `src/commands/build.ts`: the reachability rules decide what the worker prefetches.
2. The config-check runner's tsx namespace and its failure paths
   (`src/checks/config-check-runner.ts`), on Windows and Linux.
3. `tmFindPackageDir`'s tsconfig-paths fallback against a real distribution layout (node_modules
   first).
4. The budget-raise rules and the `bootScript` row against D-048.
5. Path handling on Windows: `ngsw-config` is run with paths relative to the output (it joins its
   arguments to its working directory), the emit's absolute output folder, `copyFixtureApp`.
