# PC-026: Dialogs and layout

## Implementer notes

### What was built, and where

All paths are under `client/` unless stated. Six new entry points in
`projects/core/tellma-core-ui/`, each with `ng-package.json`, `public-api.ts`, unit and harness
specs, a budget with a `budgetNotes` entry, an API golden (`api/core-ui.<ep>.api.md`) and a
showcase story with the entry point's id. The four component entry points also have co-located
`*.examples.ts` files, compiled by `docs-examples.spec.ts` and published through docs:build
(`@tmGroup layout`). The two services are not components, so the docs extractor does not list
them, as for `TmToasts` and `TmBusyOverlay`.

- **`confirm`** (spec 0023 §5.5).
  - `TmConfirm` (root) has `ask<K>(options)` and `confirm(options)`. Types: `TmConfirmChoice`,
    `TmConfirmOptions`, `TmConfirmVariant`, `TmConfirmIcon` and `TmConfirmYesNoOptions` (the
    spec's inline `confirm()` argument, named so it can carry TSDoc).
  - The shell is `TmModal` size `sm`, `role: 'alertdialog'`, `describedBy` pointing at the
    message `<p>`. The content is `internal/tm-confirm-content.ts`: an optional 26 px tinted disc
    (TriangleAlert, CircleX, Info) beside the message, and one `tmButton` per choice in
    `[tmModalFooter]`, in the given order.
  - The icon defaults to `warning` when a choice is `danger`, else none; `null` means none.
  - Initial focus: `initialFocus`, else the `primary` choice, else the first non-danger one,
    else the first. It is marked with a `cdkFocusInitial` attribute, which the CDK focus trap
    honours on open.
  - `ask` resolves the key on a click, and `null` on Escape, the close button and the backdrop.
    `confirm()` asks Cancel (secondary) then confirm (primary, or danger when `destructive`),
    with focus on Cancel and the warning glyph when `destructive`.
  - The message keeps line breaks (`white-space: pre-line`).
- **`error-dialog`** (§5.6).
  - `TmErrorDialog` (root) has `show(options)`, resolving `'primary' | 'secondary' | 'close' |
    'replaced'` (`TmErrorDialogResult`). Types: `TmErrorDialogOptions`, `TmErrorDialogAction`,
    `TmErrorDialogButton`.
  - Same alert-dialog shell as confirm, with `backdropDismiss: false`.
  - Content (`internal/tm-error-dialog-content.ts`), in order: the message (the description), the
    items as a `<ul>` capped at ten with an "and N more" `<p>` (`errorDialog.more`), the
    `tm-reference` row, and the Details disclosure (closed; a native button with `aria-expanded`
    and `aria-controls`; the region renders only while open) holding the details as an inline
    `dl[tmDescriptionList]` and then the actions as ghost `tmButton`s with an optional
    registry icon.
  - Footer: primary, secondary, Close. Close is primary-styled when no primary is given. Initial
    focus is on the first footer button.
  - A click without `run` closes with the key. With `run`, the button turns `pending` in the
    click's own change detection, with `aria-label` = `pendingLabel ?? label`. The label cell
    stacks the label and an `aria-hidden`, `visibility: hidden` copy of `pendingLabel` in one
    grid cell, so the button is as wide as the wider of the two. `true` closes; `false` returns
    to idle; a rejected or throwing run returns to idle and goes to `ErrorHandler`.
  - The pending state is a `linkedSignal` on the state signal, keyed by a generation counter, so
    a replacement drops it and a late result from an earlier show is ignored. Close and Escape
    stay live during a run; a result after the dialog closed changes nothing.
  - Replacement: a `show` while one is open resolves the earlier promise `'replaced'`, retitles
    the modal in place (`TmModalRef.ɵsetTitle`), and swaps the content signal. The disclosure
    closes again. Footer buttons are tracked by index, so the focused position survives; when the
    focused element is removed (a shorter footer, or an action inside Details), an
    `afterRenderEffect` moves focus to the footer position that last held it, clamped to the
    footer's length.
  - A footer close goes through the service, which stops taking replacements at once, so a
    `show` in the same task opens a new dialog instead of replacing a closing one.
- **`card`** (§7.1, §9 card).
  - `TmCard`: `heading`, `headingLevel` (2–6, native `h2`–`h6` through one shared template),
    `count` (`tm-counter` outside the heading element, so it is not in the heading's name),
    `collapsible`, `expanded` (model, default true), `preserveContent`, `invalid`, `flush`.
    Slots `[tmCardSubtitle]`, `[tmCardActions]`, body, `[tmCardFooter]`.
  - Collapsible: the heading holds a native button with `aria-expanded`, `aria-controls` (only
    while the region exists) and a chevron mirrored in RTL. Collapsed, the region leaves the DOM,
    or with `preserveContent` stays `hidden` and `inert`.
  - `invalid` reserves a 6 px dot box whenever it is bound (a custom transform keeps
    `undefined` as "not bound"), painted only while true. While invalid the visible title is
    `aria-hidden` and a visually hidden span reads `card.hasErrors` ("{heading}, has errors").
  - Header 8×11 px padding, 13 px semibold 17 px line, divider (dropped while collapsed),
    actions at the inline end. The subtitle is 12 px secondary: its first child ellipsizes, the
    rest keep their width; plain text ellipsizes as one run. Empty header, subtitle, actions and
    footer are hidden by CSS.
- **`page-header`** (§7.2, §9 pageHeader).
  - `TmPageHeader`, no inputs. Row 1: `[tmPageBack]` plus an `aria-hidden` mirrored chevron (the
    pair hidden without a link), `[tmPageTitle]` (16 px semibold, ellipsis), `[tmPageTitleExtra]`,
    then `[tmPageHeaderEnd]` packed against the inline end. Row 2: `[tmPageToolbar]` and
    `[tmPageToolbarEnd]` on one clipped line, absent while both are empty. Then
    `[tmPageHeaderBand]`, wrapping, absent while empty.
  - The host is the container; an inner column carries the 12×14 px padding, 10 px below 576 px
    by container query.
- **`description-list`** (§7.3, §9 descriptionList).
  - `dl[tmDescriptionList]` with `columns` (1 default, 2, `'auto'`) and `layout` (`'stacked'`
    default, `'inline'`), exposed as `data-columns` and `data-layout`.
  - Global stylesheet `styles/tm-description-list.css`, registered in `"tellma".docs.globalStyles`,
    the showcase `angular.json` styles and the README's Consuming list. Pairs are `<div>`s in a
    flex-wrap list; two columns give each pair half the line less half the gap; `auto` makes the
    `dl` a size container and switches at 576 px; inline pairs are a two-track grid whose label
    track is at most 40 %.
- **`splitter`** (§7.3, §9 splitter).
  - `TmSplitter`: `orientation`, `primary`, `size` (model), `defaultSize` (required), `min`,
    `otherMin`, `maxFraction`, `step`, `ariaLabel`. `TmSplitterPane`: `tmSplitterPane` (`start`
    or `end`), projected by static attribute.
  - The clamp `max(min, min(size ?? defaultSize, maxFraction×W, W − otherMin − separator))` is
    the primary pane's flex basis in CSS, so the first frame and every container resize are
    clamped without script; `size` is never written back. `internal/tm-splitter-clamp.ts` holds
    the same clamp for the keyboard, the drag and the ARIA values.
  - The bar: `role="separator"`, `tabindex="0"`, `aria-orientation` perpendicular to the split,
    `aria-valuenow/min/max` as shares (0–100) of the measured container (a ResizeObserver),
    `aria-controls` = the primary pane's id (its own, else generated), name "Resize panels".
    Arrows move by `step` (Shift ×4), mapped so the bar moves the way the arrow points in RTL;
    an `end` primary grows as the bar moves toward the start; Home and End jump to the clamp's
    ends. Each move starts from the rendered (clamped) size.
  - Drag: pointerdown (primary button) captures the pointer, records the primary pane's rendered
    size and the live direction; pointermove clamps; pointerup, pointercancel and
    lostpointercapture end it. `touch-action: none`, `user-select: none`, col-/row-resize cursor.
    7 px bar, 3×28 px grip, 24 px hit layer, accent while hovered or dragged.
  - Panes are `box-sizing: border-box` with zero minimums, so `size` is the pane's outer size.
  - A dev-mode `console.error` unless there is exactly one start and one end pane.
- **Modal** (`modal/`): `TmModalRef.ɵsetTitle(title)` (internal) and a title signal the shell
  reads, so the error dialog can retitle in place. The title element is kept, so
  `aria-labelledby` stays valid; an untitled modal stays untitled and an empty title is ignored.
- **Strings**: `confirm.ok/cancel`, `errorDialog.close/details/more`, `card.hasErrors`,
  `splitter.label`, in `i18n/strings-en.ts` and `locale/tellma-locale-ar/strings-ar.ts`.
- **Tokens** (`core-ui-tokens/presets/tellma-default.ts`): groups `card`, `pageHeader`,
  `descriptionList`, `splitter`, plus `modal.alertIconSize/alertGlyphSize/alertGap/
  messageFontSize`. `tokens.spec.ts` pins the geometry; `src/apps/Tellma.Identity/wwwroot/css/
  tokens.css` is regenerated by `identity:copy-assets`.
- **Harnesses** (`core-ui-testing/`): `TmConfirmHarness`, `TmErrorDialogHarness` (with
  `TmErrorDialogButtonState`), `TmCardHarness`, `TmSplitterHarness` (with `TmSplitterKey`).
- **Showcase**: stories `confirm`, `error-dialog`, `card`, `page-header`, `description-list`,
  `splitter`.
- **E2E** (`e2e/specs/`): `card`, `page-header`, `description-list`, `splitter`, `confirm`,
  `error-dialog`, and `splitter-touch` (added to the touch project's `testMatch` and chromium's
  `testIgnore` in `playwright.config.ts`).

### Deviations (also in the commit message)

1. `TmConfirm.confirm()`'s `confirmLabel` is optional and defaults to `confirm.ok` ("OK"). §5.5
   makes it required, which left §10's `confirm.ok` with no consumer.
2. The `confirm()` argument is a named interface, `TmConfirmYesNoOptions`, and the module also
   exports `TmConfirmVariant` and `TmConfirmIcon`, so every member carries TSDoc.
3. `TmModalRef` gained the internal `ɵsetTitle` and the shell reads the title as a signal. The
   modal golden changes only in internal members and the constructor's new optional argument.
4. The error dialog sets `backdropDismiss: false`. §5.6 lists Escape and the close button as the
   dismissals of a failure the user must acknowledge.
5. While one caller button's `run` is pending, the other caller button is natively `disabled`
   (Close stays live, as §5.6 requires). Two concurrent runs would race to close the dialog.
6. A rejected or throwing `run` counts as `false` and is reported to `ErrorHandler`; an action
   that throws is reported the same way and still honours `closes`.
7. `errorDialog.more` is "and {count, number} more" (ICU number), as D-058 did for PC-023's
   counts.
8. `TmErrorDialogResult` names the `show()` result union, and the details disclosure resets to
   closed on every replacement.
9. `defaultSize` is required (`input.required`): §9 gives no default and `size` starts `null`.
   `min` and `otherMin` default to 0, `orientation` to `horizontal`, `primary` to `start`.
10. `dl[tmDescriptionList]` defaults to one column, stacked. §7.3 gives no defaults.
11. Splitter panes are border-box, so `size` includes a pane's own padding and border.
12. Tokens beyond §9's list: `modal.alertIconSize/alertGlyphSize/alertGap/messageFontSize` for
    the confirm disc, and the card's chevron size, dot gap and body padding.
13. Budgets above the §1 figures, each measured + ≈0.1 KB rounded up to 0.05, with notes:
    confirm 2.2 (§1: 2; measured 2.09), error-dialog 3.8 (2; 3.66), card 3.35 (1; 3.21),
    page-header 1.7 (1; 1.60), splitter 3.5 (2; 3.39). description-list measures 0.53 under its
    §1 ceiling of 1. The primary `.` measures 8.79 with the eight new strings, under its 8.81
    ceiling, so it is not raised.

- Lucide glyph data is bundled with each entry point (confirm three, card and error-dialog two,
  page-header one).
- **Savings taken.** Tone, columns and layout are attribute bindings; the card renders one
  heading template into the five heading elements; the page header's empty-slot rules are all
  CSS (no content queries); the splitter clamps in CSS rather than on resize; the error dialog's
  pending width is a grid-cell reserve rather than a measurement.
- The duplicated class metadata in the FESM output is the build's, not a lever.

### Open risks

- **The description-list stylesheet.** Apps must add `styles/tm-description-list.css` (the
  error dialog's Details list depends on it too). `@tellma/core/styles.css`, which spec 0024 §7.6
  owns, does not exist yet; when it lands it should include this sheet. Unit tests cannot load
  global sheets, so the list's geometry is covered in e2e only, as is the pending button's width
  (it rests on `styles/tm-button.css`).
- **Initial focus via `cdkFocusInitial`.** The CDK reads the attribute when it traps focus after
  the first render. Confirm content binds it in its first change detection, which is before that,
  and the unit and e2e suites cover it, but it couples to a CDK attribute name.
- **Focus restoration on replacement** acts only when focus has fallen to `<body>`; focus that
  moved to another layer is left alone.
- **Splitter ARIA values** are shares of the container measured by a ResizeObserver; before the
  first observation the value attributes are absent.
- **`aria-controls` on the card and the Details button** is present only while the controlled
  region exists.
- The showcase build prints its two existing budget warnings (initial bundle, grid-view.css).

### What reviewers should examine hardest

- `error-dialog/internal/tm-error-dialog-content.ts` and `tm-error-dialog.ts`: generation and
  `linkedSignal` handling of pending runs across replacement, late results after close, the
  synchronous `active` reset on a footer close, and `restoreFocus`.
- `splitter/tm-splitter.ts`: the CSS clamp expression versus `ɵtmSplitterClamp`, the RTL and
  `end`-primary delta mapping, pointer capture teardown, and the ARIA shares.
- `card/tm-card.ts` and `card/tm-card.css`: the `invalid` transform (bound vs unbound), the
  hidden error name versus the visible title, and `preserveContent`'s hidden and inert region.
- `page-header/tm-page-header.css`: the `:empty`/`:has` hiding with projected control flow, the
  end-slot packing, and the toolbar row's clip with focus-ring compensation.
- The Arabic strings.
