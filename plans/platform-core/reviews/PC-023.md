# PC-023: Chips and feedback surfaces

## Implementer notes

### What was built, and where

All paths are under `client/` unless stated. Four new entry points in
`projects/core/tellma-core-ui/`, each with `ng-package.json`, `public-api.ts`, unit and harness
specs, a budget with a `budgetNotes` entry, an API golden (`api/core-ui.<ep>.api.md`) and a
showcase story with the entry point's id. The two component entry points also have co-located
`*.examples.ts` files.

- **`chip`** (spec 0023 §4.3).
  - `TmChip` takes `label`, `tone` (the badge tones), `icon`, `href`, `removable` and `size`, and
    has the outputs `activate` and `remove`, plus `focus()`.
  - The label renders in a `<bdi>`, and projected content replaces it. It renders as an `<a>` when
    `href` is set, as a `<button>` while something listens to `activate`, and as text otherwise.
  - The remove button is named "Remove {label}". Delete or Backspace (no modifiers) on the chip's
    own controls emits `remove`.
  - Every control takes the pointer 24 px square through a transparent `::after` layer.
  - Host: `data-tone` and `data-size` (`ɵtmControlSize`), and `role="listitem"` inside a set.
  - `TmChipSet` takes `overflow` (`wrap`, `collapse` or `scroll`) and `ariaLabel`, and has the output
    `exit` and the method `focusLast()`. It is `role="list"` with one roving tab stop.
  - Keys: Left and Right are mapped by the live direction; Home and End move to the ends; an arrow
    past either end emits `exit`.
  - When the focused chip is destroyed, focus moves to the next chip, else the previous, else the
    set emits `exit('end')`. `internal/tm-chip-set-ref.ts` gives chips the `TM_CHIP_SET` seam.
  - Collapse mode measures the chips' natural widths inside a ResizeObserver. It runs when the set
    or a chip resizes, or when the chips change, never on input. The chips that do not fit get
    `tm-chip--collapsed`, which takes them out of the line and hides them.
  - Collapse mode then shows a "+N" list item. Its button is named
    `chip.more` with an `Intl.ListFormat` unit list, and has the same tooltip. Its digits are in
    the locale's numbering. A hidden "+{total}" probe sits in the same grid cell, so the item's
    width never changes with the count.
  - Scroll mode keeps one line with a hidden scrollbar. The focused chip is brought into view with
    a manual `nearest` `scrollBy`, focusing with `preventScroll`, so nothing outside the set
    scrolls.
- **`toast`** (§5.1).
  - `TmToasts` (root) exposes `show`, `clear` and `focus`, configured by
    `provideTellmaToasts({ maxVisible, overflow })`.
  - `TmToastRef` has `close`, `update` and `closed`, which resolves `timeout`, `dismiss`, `action`,
    `api` or `replaced`.
  - The host is `internal/tm-toast-host.ts`, a `popover="manual"` element on `<body>`, created on
    the first show and attached to the ApplicationRef.
  - It holds a `role="region"` stack, the cards newest first, the pill, and two persistent live
    regions (`status` and `alert`). Each region is emptied, then filled 100 ms later; messages that
    arrive in that window are joined.
  - Timers use `TM_NOW`. Only toasts on show run; every timer pauses on hover, on focus inside the
    stack and while the page is hidden, and keeps the time it had left.
  - Keyed `show` replaces a toast in place. `update` restarts the timer and re-announces only a
    changed text or tone.
  - An action runs inside a try/catch that reports to the ErrorHandler, then closes the toast.
  - Focus: `focus()` focuses the newest card's first button. Focus entering from outside records
    where it came from and pushes an entry on the shared Escape stack. Escape or closing the
    focused toast returns focus there, else to another toast.
  - Above modals: a MutationObserver on the CDK OverlayContainer's children re-shows the host
    (hide, then show, keeping focus), so a toast stays above a modal opened after it.
- **`banner`** (§5.2). `TmBannerBar` takes `tone`, `message`, `icon`, `actionLabel`,
  `dismissible` and `position`, and has the outputs `action`, `dismiss`, `previous` and `next`.
  - It is exactly 32 px tall, border-box, with the message on one ellipsized line.
  - The tone glyphs are Info, TriangleAlert and CircleX. A visually hidden tone prefix reuses the
    `alert.<tone>` keys.
  - The pager is mirrored chevrons with "{index} of {count}" between them.
  - The buttons are 24 px. The bar has no live role.
- **`busy-overlay`** (§5.4).
  - `TmBusyOverlay` (root) exposes `active` and `run(work, { label, immediate })`. The host is
    `internal/tm-busy-overlay-host.ts`, a full-viewport `popover="manual"` created with the
    service.
  - The first run blocks in the calling task. It records and blurs the focused element, and makes
    every `<body>` child except the host inert, leaving already-inert children alone.
  - While blocked, a body `childList` MutationObserver makes new children inert and re-raises the
    host. A window capture listener cancels every keydown, keyup and keypress.
  - Over the overlay the cursor is `progress`. The scrim, spinner and label follow after
    `--busy-overlay-delay` (parsed from computed style, 200 ms fallback), or at once with
    `immediate`.
  - The `role="status"` label is filled only once the region has been in the page for a task, and
    shows the latest run's label (a Signal is read live).
  - When the last run settles, the page is unblocked synchronously, before the caller's
    continuation, and focus returns to the recorded element with `preventScroll`.
- **Tokens** (`core-ui-tokens/presets/tellma-default.ts`): groups `chip`, `toast`, `banner` and
  `busyOverlay`.
  - `tokens.spec.ts` pins the emitted geometry.
  - The tokens README lists `--toast-offset-block-start` and `--busy-overlay-delay` as
    consumer-set, and the `--chip-*` group as public to read.
  - `src/apps/Tellma.Identity/wwwroot/css/tokens.css` is regenerated.
- **Strings**: `chip.remove|more`, `toast.region|close|more`, `banner.dismiss|previous|next|position`
  and `busyOverlay.label`, in English and Arabic.
- **Harnesses** (`core-ui-testing`): `TmChipHarness` (with a `label` filter), `TmChipSetHarness`,
  `TmToastHarness`, `TmToastStackHarness` (root loader), `TmBannerBarHarness` and
  `TmBusyOverlayHarness` (root loader). The README and exports are updated.
- **Docs and packaging**:
  - core-ui README: entry-point rows, and `tm-chip` added to the inline-flex host list.
  - `docs-examples.spec.ts`: imports, suites and host members.
  - Budgets: four new ceilings, and the primary raised for the strings (see Deviations).
- **Showcase**: stories `chip`, `toast`, `banner` and `busy-overlay`.
- **E2E** (`e2e/specs/`): `chip.spec.ts`, `toast.spec.ts`, `banner.spec.ts` and
  `busy-overlay.spec.ts`. Every story gets axe in light and dark × LTR and RTL, and the busy scrim
  gets axe too.
  - Chip: roving keys in both directions and one tab stop; Delete and Backspace moving focus on;
    collapse refitting on a width change, at constant height; the "+N" tooltip; scroll into view
    with no page scroll; the input hand-off with `exit` and `focusLast`; 24 px remove targets.
  - Toast: the corner in both directions; the narrow width; the six-second timer and sticky error,
    pause on hover and on focus, all under `page.clock`; `focus()` plus Escape returning focus;
    the cap and pill; keyed replacement; the action; `clear()`; both live regions; above a modal,
    and `focus()` from inside a modal.
  - Banner: 32 px for every variant; ellipsis; the pager wrapping; mirrored chevrons in RTL;
    outputs.
  - Busy overlay: pointer and keys held, with the progress cursor; focus returned; the scrim at
    200 ms, never for fast work, and at once with `immediate`; nested labels, under `page.clock`.

### Deviations (also in the commit message)

1. `TmChip.activate` is an `OutputRef<void>` (from `outputFromObservable`), not an
   `OutputEmitterRef<void>`. The chip must know whether anything listens, because §4.3 renders
   the label as a button only when `activate` is bound. `OutputEmitterRef` gives no subscriber
   count, while the observable's subscribe and teardown keep one exactly.
2. The collapsed set's visible "+N" text has no key: it is "+" followed by
   `TmL10n.formatNumber(hidden)`, isolated with `dir="ltr"`. §10 gives only the accessible name a
   key (`chip.more`), and §2.2 requires locale digits.
3. A new key, `toast.more` ("{count, number} more"), is the default pill label. §5.1 says the pill
   counts the hidden toasts even without `overflow`, but §10 lists no key for it.
4. Count placeholders use the ICU `number` format (`{count, number}`, `{index, number} of
   {count, number}`), so digits follow the locale. §10 writes `{count}` and `{index} of {count}`,
   and the in-house interpreter prints a bare argument with `String()`.
5. The banner's buttons are its own 24 px icon buttons, not `tmButton`. `tmButton`'s smallest step
   is 30 px (`--field-height-sm`), and §5.2 fixes 24 px buttons in a 32 px bar. The `button` dependency in §1 is unused.
6. The banner's hidden tone prefix reuses `alert.info|warning|error` ("Info:", "Warning:", "Error:"). §5.2 gives no tone wording, and a tone carried only by colour fails WCAG 1.4.1.
7. `TmToastRef.update()` re-announces only when the title, detail or tone changes. Otherwise a
   progress toast's timer restart would re-read the same text.
8. The busy overlay blurs the focused element and holds every key at window capture while it
   blocks, on top of inert. §5.4 says only that Escape does nothing. Inert alone still lets keys
   reach the document's listeners (the shared Escape stack, the shortcut registry), and
   blurring takes focus off the trigger in every engine. Focus returns to the recorded element after the
   work.
9. The toast host re-raises itself above modals by watching the CDK OverlayContainer. §5.1 says
   the top layer keeps the host above modals. It does so only while the host is the latest
   top-layer element, and CDK 22 dialogs are top-layer popovers too.
10. Budgets above the §1 figures, each measured + ≈0.1 KB with a note: chip 5.7 (§1: 2),
    toast 5.4 (4), banner 2.6 (2), busy-overlay 2.5 (1). The primary `.` rises from 8.5 to 8.7
    for the ten new English strings (8.48 → 8.58). The measurements and savings are in the notes
    and below.
11. Tokens beyond §9's list: the remove-button inset and end gap, and a `--chip-target-size`
    (24 px), which the target rule needs. The stylesheet linter refuses literal sizes.

- **Saving taken.** Tone and size are attribute bindings (`data-tone`, `data-size`) matched by
  attribute selectors, not per-value classes.
- **Measured and not taken.** In `tm-chip-set`, one `visibleChips` computed plus a `#moreButton`
  view query, replacing the repeated slicing and `querySelector` calls. It measured 0.03 heavier
  (5.63), so it was reverted.
- **Nothing else to fold.** The touched code has no development diagnostics. It has no duplicated
  templates beyond the chip's three label element kinds, which §4.3 requires.
- **The chip's token change.** Replacing the remove button's literal sizes with tokens, which the
  stylesheet linter requires, is part of the 5.60.

### Open risks

- **Busy overlay and dialogs.** The overlay re-inerts only new `<body>` children. A CDK dialog
  opened during a run inside an OverlayContainer that already exists is drawn above the scrim (it
  is a later top-layer popover) but stays inert, because its container is inert. Nothing in the
  specs opens a dialog during a busy run.
- **Toasts with a modal open.** `focus()` reaches the toast and Escape closes only the toast, as
  covered in e2e. Tab from the last toast button leaves the top layer for the document in DOM
  order. The CDK focus trap does not pull focus back, so Tab is not scoped to the toasts while a
  modal is open.
- **Collapse measurement.** Measuring briefly gives every chip `position: absolute` (the
  `tm-chip--measuring` class) inside the ResizeObserver callback, then applies the fit and runs
  `detectChanges` in the same frame. A consumer that styles chips with a different width when
  out of flow would measure wrong.
- **Chip focus tracking.** Chrome can fire `focusout` for a focused node that is being removed.
  `onFocusout` therefore waits a microtask before forgetting the focused chip. `chipDestroyed`
  reads the index from the chips as last rendered, because `contentChildren` has already dropped
  the destroyed chip.
- **Key blocking.** Keys are blocked at window capture only while a run is active. A listener
  registered at window capture before the overlay's own listener still sees the event; Angular
  and CDK listen on the document, so in practice nothing does.
