# PC-193: tm-pivot core-ui entry point

## Implementer notes

### What was built, and where

- **The entry point** `client/projects/core/tellma-core-ui/pivot/` (`@tellma/core-ui/pivot`): `TmPivot` (`tm-pivot`) and the types `TmPivotModel`, `TmPivotMember`, `TmPivotMemberKind`, `TmPivotCell`, `TmPivotWidths` and `TmPivotAxis` (spec 0034 §6.1). The contract is the spec's: `model`, the `expandedRows`/`expandedColumns`/`widths` models, `activatable`, `ariaLabel`, `size`, `cellActivate`, and `expandAll`/`collapseAll`/`focus`.
- **Pure layout** in `pivot/internal/`, each with its own spec:
  - `pivot-layout.ts`: the axis index (depths, children, the total; duplicates, unknown and self parents, cycles and a second total are tolerated and listed for a dev-mode `console.error`), compact row flattening (a parent's row carries its subtotal, the total last at level 1), the column layout (an expanded member's group header over its children, its subtotal column after them, the total last; header rows = column levels + a measure row for two or more measures), the five looks and the stronger-look rule for intersections, and a binary-searched header lookup. Everything is iterative, so a 20,000-deep chain is fine.
  - `pivot-widths.ts`: §6.2's width rules. The row header defaults to clamp(round(0.4W), 120, 280), or 120 below 300 px. An attribute defaults to 96. A measure is max(96, fit) with the slack shared equally per column while the table fits, else max(112, fit). User widths are clamped to their ranges and never changed. The sticky prefix is decided on default widths, then cut to the part that still leaves the data 112 px (a user width set at a wider host, or restored from page state). A sticky column's resize stops at W − 112 − the other sticky widths.
  - `pivot-window.ts`: segments (the window, plus the active row or column kept rendered, with gaps), and the header pieces over them (cells placed over rendered columns, spacers over runs no cell occupies).
  - `pivot-nav.ts`: the logical grid (header rows first; row header, attributes, data columns), the covering cell of a position, and the moves. A spanning header is stepped past, and the column the user came along is kept.
- **The component** (`tm-pivot.ts`, `tm-pivot.css`):
  - **DOM.** A `table role="treegrid"` with `table-layout: fixed` and a `colgroup`, inside a scroller with a stable gutter. Headers stick to the top, and the sticky prefix sticks to the inline start. Labels sit in `<bdi>`. Values sit in a `dir="ltr"` span with tabular figures, right-aligned physically. A null text renders an empty cell.
  - **Windowing.** Body rows window through `tmComputeAxisWindow`. Past 40 data columns, the columns window by whole column groups. Gap rows and spacer columns hold the extent.
  - **Lazy text.** `text` is called only for rendered cells. Each value is read once while its cell stays rendered (a cache rebuilt per render pass, dropped on a new model). `widest` is asked once per measure per model.
  - **Measuring.** Fits are measured in a hidden probe styled like a value cell at the strongest weight, padding and rule included. The probe runs in an `afterRenderEffect` early-read on the model's first render, so widths settle before paint. Fits are keyed by measure index, as the user widths are, and only widen while the measure count holds. They are re-measured, without asking `widest` again, when web fonts finish loading and, for a pivot first rendered inside `display: none`, when it first shows (the probe reports "unmeasured" instead of 0). A `ResizeObserver` on the host and the scroller feeds W and the viewport.
  - **ARIA.** The table carries `aria-readonly`, `aria-rowcount` and `aria-colcount`. Header cells have `aria-colindex`, `aria-colspan`, `aria-rowspan` and `aria-expanded`. Body rows have `aria-rowindex`, `aria-level`, `aria-posinset`, `aria-setsize` and `aria-expanded`, and start with a `rowheader`. There is one roving tab stop.
  - **The active cell.** It is kept by identity: a header row or a row member, and a lead column or a column member with its measure. It falls back to the nearest visible ancestor, so a collapse keeps focus in place.
  - **Keys** (via `kbd`). Arrows (left and right follow the direction), Home/End, Mod+Home/End and PageUp/PageDown move. Enter and Mod+Enter activate. Enter or Space toggles an expandable header. Alt+ArrowRight/Left toggle a row from any of its cells, and Alt+ArrowDown/Up a column from its header. Mod+C copies.
  - **Pointer.** A twisty or label click toggles. A value-cell click activates, with Mod for a new tab. Clicks on handles are ignored.
  - **Announcements** are polite. "{label} expanded, {n} rows" and "{label} expanded, {n} columns" count what the expansion reveals. "{label} collapsed".
  - **Cut values.** A value cut by the ellipsis gets its full text in a tooltip. Its accessible text and the copy are always the full text.
  - **Refused cells** (the model's `activatable`) get no link class and so no hover look, a tooltip and an `aria-describedby` with "Only the finest cells open their rows in this report.", and the same announcement on Enter. They still take focus.
  - **Resizing.** Pointer handles sit on the row-header corner, the attribute corners and every header reaching the last header row. With one measure, member, subtotal and total headers resize it; with two or more, the measure-name cells resize their own measure. A drag freezes every other measure's width and writes `widths` on release. A double-click fits: a measure by the probe, the row header and attributes by canvas measurement of every visible row's label at its weight, windowed-out rows included.
- **Tokens.** The `pivot` group in `presets/tellma-default.ts`, after `grid`, has the grid's row ladder (34/30/38; 30 at the default `sm`), indent 16, twisty 13, the paddings and font sizes, and each look's fill, ink and weight. The total rule is `border.strong` at 2px. Hover, link and ring are `surface.hover`, `action.primary` and `action.accent`. The Identity `tokens.css` is regenerated. There is a tokens emit test.
- **Strings.** `pivot.subtotal`, `pivot.direct`, `pivot.notActivatable`, `pivot.rowExpanded`, `pivot.columnExpanded` and `pivot.collapsed` ship in English with ./pivot (`TM_PIVOT_STRINGS_EN`), and in Arabic in `@tellma/locale-ar` with full plural categories (rows reuse `rowsCounted`). The pivot registers its table through `ɵtmRegisterUiStrings` in "." (D-098): `tmEnglishString` walks one root seeded from the core table, and a registration fills only a top-level key the core does not have. A registered key resolves through the same Transloco path and fallback as a core one, and a `tmUi.pivot.*` translation overrides it.
- **Harness.** `TmPivotHarness` and `TmPivotCellHarness` live in `tellma-core-ui-testing/pivot-harness.ts`: counts, row and header labels, cells by text, role or position, value cells by row label and data column, looks, expansion, drill and refusal state, handles and fit, sticky count, tab stop and keys.
- **Docs and showcase.**
  - `tm-pivot.examples.ts` is registered in `docs-examples.spec.ts`.
  - The README has an entry-points row and a harness line.
  - Two stories: `pivot` (centers × periods, two measures, a code attribute, a phantom, "(None)"; leaves drill, the rest refuse) and `pivot-large` (1,000 × 500 cells, counting `text` calls).
- **Budgets** (`tellma-core-ui/package.json`): see deviation 10.
- **Tests.**
  - Unit: the four internal specs and `tm-pivot.spec.ts` (vitest browser mode). They cover compact layout, spans, subtotal and total columns, the measure row, empty cells, isolation, every look and intersection, computed paint from tokens (fills, weights, 2px rules, row height and size ladder), ARIA, windows on both axes (the active row kept rendered, past-40 columns windowed), every key, activation and Mod, toggles and their announcements, expandAll/collapseAll/focus, copy, the default widths from `widest`, slack sharing, widen-only and never over a user width, a per-measure drag (live, then written), RTL drag direction and range clamps, double-click fit, the sticky cap, the sticky table at its thresholds and on resize, a cut value's tooltip, text and clipboard, and the refusal's tooltip, description and announcement.
  - **The 500,000-cell proof.** A 1,000 × 500 model asserts that the set of `text` calls equals the set of rendered value texts, with no duplicates. After a scroll, every new call is for a newly rendered cell, and `widest` was asked once. A 100,000 × 5 model asserts the same.
  - E2e `e2e/specs/pivot.spec.ts`: the axe floor (light/dark × LTR/RTL, collapsed, expanded and collapsed again), the looks as computed in light/dark × LTR/RTL (fills, inks, weights, italics, the row rule on block-start, the column rule on the inline-start edge per direction, physical right alignment, the row header on the reading side), the hover look versus a refused cell, keys per direction with activation, Mod+Enter, header navigation and Alt+ArrowUp, the refusal's tooltip and announcement, a twisty's announcement, the real clipboard, the sticky set at 1280/1024/768/375 px viewports (by behaviour under a sideways scroll), and the large cube's text-call counter.
  - Nightly: `@perf @nightly` wheel-scroll frame-time probe on the large cube.

### Deviations

1. **The phantom's rank in intersections.** §6.3's strength order leaves out `phantom`. It ranks just above `leaf`, below `subtotal-2`. A phantom is a muted leaf, so it wins only over a leaf: a phantom row crossing a subtotal column takes the subtotal's look.
2. **A collapsed parent keeps its subtotal look.** A depth-1 or depth-2 member with children paints as `subtotal-1`/`subtotal-2` while collapsed too. §6.3's "members with children" reads as the tree, not the current expansion, so the looks do not flip on a toggle.
3. **§14's pixel baselines are deferred, not replaced.** §14 asks for the pivot's styles "in light, dark and RTL". The repo has no screenshot-baseline infrastructure, so `e2e/specs/pivot.spec.ts` asserts the resolved paint per look in light/dark × LTR/RTL: fills, inks, weights, italics, the 2px rules and their edges, and alignment. That cannot see z-order, the twisty's mirroring or how the ellipsis renders. **Tracked deferral (for LEDGER, which this checkpoint may not edit):** the pivot's light, dark and RTL pixel baselines land with the repo's baseline infrastructure, next to the chart's visual suite (WATCHLIST c10 #7 proposes nightly baselines in a pinned Linux container).
4. **Mod+C goes through the native `copy` event.** The keydown marks a copy pending, the browser's `copy` event sets `text/plain`, and `navigator.clipboard.writeText` is the fallback where no copy event follows. A text selection the user made inside the pivot is left to the browser: the keydown arms no fallback, and the copy event clears the pending flag before it yields.
5. **Strings the spec only exemplifies are library strings.** The refusal sentence, "{label} total", "(direct)" and the three toggle announcements are under `pivot`: in English in ./pivot's `TM_PIVOT_STRINGS_EN`, in Arabic in `strings-ar`. A column expansion announces "{label} expanded, {n} columns", counting the column groups it reveals, by analogy with §6.4's row example.
6. **Focus after a column toggle follows the member's header.** After an expansion, focus moves to the member's new group header; after a collapse, to its member header. The spec is silent, and the cell under the old position changes meaning.
7. **The subtotal header's label sits in its own `<bdi>`.** "{label} total" is formatted around a private-use sentinel and split, so the label is isolated inside the translated phrase.
8. **Alt+ArrowRight/Left on a body row are physical**, as spec 0004's tree-grid keys are in the grid: Alt+ArrowRight expands and Alt+ArrowLeft collapses in both directions. Plain arrows follow the direction.
9. **A drag freezes the other measures.** While one measure is dragged, every other measure holds the width it had at the press, so the slack-sharing rule does not shift its neighbours under the pointer. Widths are written to `widths` on release.
10. **The primary entry point grows by the string seam only (D-098).** The pivot's English strings live in ./pivot as `TM_PIVOT_STRINGS_EN` and register through `ɵtmRegisterUiStrings`, so "." carries the seam and not the strings. "." is set to 9.17 from 9.14: measured 9.13 before and 9.16 after (+0.03 KB) on the linked measure. `./pivot` is set to 14.1, the measured 14.00 plus 0.1 KB, under the spec's 15.
11. **The row header always sticks from 300 px.** The prefix rule applied literally drops it at hosts where `round(0.4 × W)` rounds above 0.4 × W (344 px, for example). §6.2's table has the row header sticky across 300–939 px, so the table wins. Attributes still join only while they fit in 40%.
12. **No touch e2e.** The touch project runs only touch specs, and the pivot has no touch-only behaviour in this checkpoint. Pointer resizing is unit-tested; the wall-clock scroll probe is `@perf @nightly`.

### Open risks

- **`bodyRows` is a `computed` with a side effect.** It swaps the text cache, so a value is read once per rendered lifetime. The cache is keyed by member indices and the model identity. Angular may run the computed more than once per frame (it does on the first frame, before and after measurement). That only reuses the cache, never asks twice, which the unit proof pins.
- **The fit is measured in an `afterRenderEffect` early-read that writes the probe's text.** That is a write in a read phase. It forces one synchronous layout per measure per model, on a hidden probe. Moving it to `write` would let a frame paint with the 96/112 px minimums first.
- **Sub-pixel cell widths.** In one drag test, Chromium reported a 152.015625 px cell for a 152 px column, so that test rounds. I did not find the source. The table's width equals the sum of its `col`s.
- **A drag's listeners live on the handle**, which holds the pointer capture. A header handle that leaves the DOM mid-drag would leave the drag open until the next one. That could happen to a header the column window drops while its column is dragged past the window. The row-header and attribute handles sit on corners that never window.
- **Column windowing assumes equal group widths** (true by construction: one width per measure). A future per-column width would need offsets.
- **The tooltip is attached lazily on `pointerover`/`focusin`** and replays a synthetic `pointerenter` for the hover delay. A real `pointerenter` usually follows too, which only restarts the same timer.

### What reviewers should examine hardest

- **`resolve()`/`refAt()` in `tm-pivot.ts`**: the active cell's identity across expansion, collapse, a new model, and header rows versus body rows. Also `toggleColumn` moving focus to the member's new header.
- **`ɵtmPivotColumns` and `ɵtmPivotHeaderPieces`**: the spans and spacers must add up to the same table columns on every header row under any window, or the table's columns shift. One test sums them, but the case space is large.
- **The width plan's fit/no-fit switch at the boundary**, and that `frozen` during a drag really keeps everything else still.
- **The lazy-text proof** in `tm-pivot.spec.ts` ("renders a 500,000-cell model…"). Check that it cannot pass vacuously.

**R1-1 (major): Mod+C overwrites a text selection the user made inside the pivot.**
`client/projects/core/tellma-core-ui/pivot/tm-pivot.ts:1143-1151` with `:1203-1207`.
Scenario: the user drags across two value cells to select "12,345.00 67,890.00" and presses Ctrl+C.
The keydown sets `copyPending = true` (1144) and queues the fallback. The native `copy` event then
reaches `onCopy`, which returns at 1206 because the selection lies inside the host, without clearing
`copyPending`. The browser copies the selection. Then the `setTimeout` callback (1145-1150) still sees
`copyPending` and calls `navigator.clipboard.writeText(this.activeText())`. That replaces the user's
selection with the active cell's text: Chromium grants clipboard-write to the focused page, and
Firefox allows it inside the keydown's activation. Deviation 4's "a text selection the user made is
left to the browser" does not hold. Neither unit copy test catches this (`tm-pivot.spec.ts:638-649`,
`:832-834`): both dispatch a synthetic `copy` event straight at a cell, so the keydown, pending and
fallback path never runs, and neither does the selection branch.
Fix: clear `copyPending` before the selection early return, or test the selection in the keydown and
arm no fallback. Add two unit tests. In the first, select text across two cells, press Mod+C through
the harness, flush timers, and assert a `navigator.clipboard.writeText` spy was not called. In the
second, assert that the fallback writes the active text when no `copy` event follows.

**R1-2 (major): a pivot first rendered while hidden keeps zero fits, so values are cut after it is shown.**
`tm-pivot.ts:974-990`: the fit's `earlyRead` tracks only `model()` and `resolvedSize()`. `tm-pivot.ts:1638-1646`:
the probe is measured with `getBoundingClientRect()`. `tm-pivot.ts:1009-1021`: only a font
`loadingdone` measures again.
Scenario: a report card sits in a `tm-tab-group` panel whose content `instantiate()` renders
unselected (hidden, `display: none`, per `tabs/tm-tab-group.css:149-151`; the details page uses it to
reach fields on unvisited tabs). A preserved collapsed `tm-card` (`[hidden]`) is the same case. The
card then receives its first model, or a model whose measure labels changed. Inside `display: none`
the probe's rect is 0 for every measure, so `fitState` stores 0 and each measure falls to
`max(96, 0)` or `max(112, 0)`. When the panel is shown, the ResizeObserver corrects W, but nothing
measures the fits again. Every value wider than 96 or 112 px stays cut with an ellipsis until the
next model arrives. That breaks §6.2 ("max(96 px, fit)"), §15's "pivot widths fixed before first
paint", and the spec's decision 24 ("a number is not cut by default").
Fix: when the probe is not rendered (`probe.getClientRects().length === 0`, or the host width is 0),
mark the fits unmeasured instead of storing 0. Measure again (`widest` is cached, so the model is not
asked again) from the ResizeObserver callback the first time the host has a non-zero size. Add a
unit test that renders the pivot inside a `display: none` wrapper, removes the `display: none`, and
asserts the value column reaches the fitted width (as `getWidth()` reports in the existing
"fits a measure's columns" test).

**R1-3 (major): the "." raise is the seventh raise on a ceiling D-031 says to re-split after three, for strings ./pivot has room for.**
`client/projects/core/tellma-core-ui/package.json:28` and `:89`; `i18n/strings-en.ts:367-380`.
The measurement is right: size:check gives "." 9.23 against 9.33 and ./pivot 13.80 against 13.9.
D-057(2), D-067(2) and D-094 bar raises without real savings or a re-split. Those rulings name
./grid. For ".", D-057(3), D-067(4) and D-072 have each accepted a string raise. But D-031's
"revisit if a ceiling rises three times; then re-split" has long since tripped for "." (8→8.5→9,
then 8.6→8.75→8.85→9.14→9.33). Each recent raise was for strings that only lazy entry points read,
and "." is now about 4.2 KB over spec 0005 §16's 5 KB.
Could the strings live in ./pivot? Yes. ./pivot measures 13.80 against the spec's 15 KB, so the six
English messages (about 0.10 KB) fit there with about 1.1 KB to spare. "." is eager and paid by every
app, including apps that never show a pivot. The only obstacle is the i18n seam. `tmEnglishString`
(`i18n/tm-ui-translate.ts:68-77`) and `provideTellmaUi` (`providers/provide-tellma-ui.ts:115-121`)
read only the single `TM_UI_STRINGS_EN` table, so no entry point can bring its own English strings.
Arabic is unaffected: it lives in `@tellma/locale-ar`, which neither measure counts.
Fix: either of these.
- (a) Add a small internal seam in ".". For example, `ɵtmRegisterUiStrings(scope, table)` merges a
  table into Transloco's `en` when Transloco is provided, and into the static English lookup
  otherwise. `tm-pivot` registers `pivot` on first construction, and "." returns to 9.14. The same
  seam lets grid.keys, pager, tree and reorderList move later, which is the re-split D-031 asks for.
- (b) Obtain an explicit orchestrator ruling that string raises on "." are exempt from D-031's
  re-split clause, and cite it in the budget note.
As committed, the raise follows local precedent but not the binding rule.

**R1-4 (minor): fits are keyed by measure label, so a renamed measure can narrow at the swap.**
`tm-pivot.ts:615-621`, `:983-988`, `:1012-1016`.
Scenario: a language switch gives a new model whose measure labels are translated (for example
"Amount" becomes "المبلغ"; §6.5 labels read the active slot). Then `previous.labels[i] !== next.labels[i]`,
so the widen-only `Math.max` is skipped and the measure takes the fresh measurement. If the new
widest string is narrower, the columns shrink at the swap. That goes against §6.2's "a later result
only widens a measure" and §15's `pivot-geometry`/`report-geometry` boxes across a language switch.
The user widths are kept by index (`pivot-widths.ts:145`), so the two keys disagree. The existing
widen-only test (`tm-pivot.spec.ts:679-694`) keeps the label "Amount" throughout, so it cannot see this.
Fix: key the fit by measure index, as the widths are, and reset only when the measure count changes.
Add a test that swaps to a model with renamed measures and a narrower widest value, and asserts the
width holds.

**R1-5 (minor): the grand-total row's 2 px rule skips the attribute cells.**
`tm-pivot.ts:875-884`: attribute cells get no `tm-pivot__rule-block`. The row header gets it
(`:925-927`) and so do the value cells (`:909-911`).
Scenario: any pivot with an attribute (the story's code column). The total row's block-start rule
runs along the row header, breaks across every attribute column, then resumes at the values. §6.3
puts the rule on the row's block-start edge.
Fix: add the class to attribute cells (and the spacer cells) when `row.style === 'total'`. Extend
`tm-pivot.spec.ts:320-342` to check an attribute cell's `::before`.

**R1-6 (minor): the model's callbacks run inside the `bodyRows` computed's reactive context.**
`tm-pivot.ts:898` (`model.text`) and `:905` (`model.activatable`).
Scenario 1: a renderer's `text` formats through a signal-backed formatter (an active-locale or
format-settings signal). `bodyRows` then depends on that signal. When the signal changes, `bodyRows`
runs again but serves the stale cached text for every retained cell, because the cache is keyed only
on model identity.
Scenario 2: a `text` that memoizes into a signal throws NG0600 (signal write in a computed). The
large story already defers its counter with `queueMicrotask` (`showcase/src/app/pivot/pivot-large-story.ts:64-66`) to dodge
this.
Fix: call both callbacks through `untracked()`. The documented "give a new model when the
formatting changes" contract then becomes the only trigger.

**R1-7 (minor): a user or restored width can make the sticky block cover the whole viewport after the host shrinks.**
`internal/pivot-widths.ts:168-173`. `ɵtmPivotResizeLimits` (`:205-217`) applies only during a drag.
Scenario: the user widens the row header to 600 px at a 1,280 px host. Later the window or a splitter
narrows the pivot to 500 px. Alternatively, page state (§3.7) restores `{ rowHeader: 600 }` into a

width unchanged. Add a plan test with `{ rowHeader: 600 }` at a 500 px host.

**R1-8 (minor): Safari throws on a large expansion count.**
`tm-pivot.ts:1391`: `stack.push(...axis.children[child])`.
JavaScriptCore rejects a call with more than 65,536 spread arguments (RangeError).

### Responses

Fix commit "PC-193: review 1 fixes". Each changed rule has a test that fails when the rule is removed. For R1-1 (the keydown guard), R1-2 (the show-time re-measure) and R1-6 (`untracked`), I checked this by running the spec against a mutant with that fix reverted.

- **R1-1 (fixed).** `onKeydown` arms the Mod+C fallback only when the user has no text selection inside the pivot (`hasUserSelection()`). `onCopy` clears `copyPending` before it yields to a user selection. Two unit tests drive the real keydown path through the harness, `press('c', Mod)`, with a `navigator.clipboard.writeText` spy.
  - "writes the focused cell's text through the clipboard API when no copy event follows Mod+C": with a copy event after the keys, nothing is written. Without one, the fallback writes exactly the cell's text.
  - "leaves a text selection the user made inside the pivot to the browser on Mod+C": the selection spans two cells. Nothing is written before or after a copy event, and the copy event is not prevented. With the keydown guard reverted, this test fails.
- **R1-2 (fixed).** `measureWidest` returns `null` and marks the fits unmeasured while the probe has no client rects (`display: none` anywhere above it). An unmeasured result never overwrites the fits. The host's ResizeObserver measures again (`widest` stays cached) once the pivot has a box.
