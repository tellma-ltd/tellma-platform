## Implementer notes

### What was built, and where

All paths are under `client/projects/core/tellma-core-ui/` unless stated.

- **§D.1 public overlay.** New entry point `overlay/` (`public-api.ts`, `tm-anchored-overlay.ts`,
  `tm-dismiss-stack.ts`, moved with `git mv` from `private/`). The two rules (one Escape stack,
  inline top layer) are in the `@packageDocumentation` and in the TSDoc of
  `tmPushEscapeDismissal` and `popoverHost`. `private/public-api.ts` now exports only
  `ɵTmErrorPopover`. Every importer moved: date-picker, entity-picker, form-field, grid

- **§D.2 TmModal.** `modal/tm-modal.ts`: `placement`, `role`, `describedBy`; dev warning for an
  alert dialog without `describedBy`; the drawer uses
  `createGlobalPositionStrategy(injector).end('0').top('0')`, the pane classes
  `tm-modal-panel--end` + the size class, and `tm-modal-backdrop--end`. CSS in
  `modal/internal/tm-modal-shell.css` (drawer widths, 100dvh, full width below 576 px via
  `inline-size: 100%`, square corners, no container animation, no backdrop fade). The shell host
  carries `tm-modal--end` (from the payload's new `placement`) so `TmModalHarness.getPlacement()`
  can read it. Tokens `--modal-drawer-width-sm|md|lg` (360/480/720). **Verified, not
  re-implemented:** PC-008's "no direction passed" and live `setDirection` + `updatePosition`;
  with the drawer's global strategy that re-apply is what moves an open drawer's edge (unit test
  and e2e pin it). The `sm` media query was already `(width < 576px)`.
- **§D.3 tm-popover.** `popover/tm-popover.ts`: `size` (`TmPopoverSize`, exported) and
  `panelClass` inputs; panel classes `tm-popover__panel--<size>`. `popover/tm-popover.css`:
  border-box panel, fixed widths from `--popover-width-sm|md|lg`, every size capped at
  `100vw − 2 × --popover-viewport-margin`, `max-block-size: var(--tm-popover-block-cap)` with
  `overflow: auto`. The block cap is written on `(positionChange)` from the side the CDK chose
  (pure helper `popover/internal/fit.ts` → `tmPopoverBlockRoom`); fixed sizes on block sides also
  get an inline offset (`tmPopoverInlineShift`) handed to the CDK as `offsetX`, so a `lg` panel on
  a phone is full width with 8 px on both sides. Tokens `--popover-width-sm|md|lg` (320/440/640),
  `--popover-viewport-margin` (8). `TmPopoverHarness.getSize()`.
- **§D.9 tm-image.** `image/tm-image.ts`: `placeholderOnError`; a new `fallback` display state
  renders the `tmImagePlaceholder` template inside `.tm-image__fallback` (absolute inset 0, so it
  lays out like the loading placeholder), `role="img"` named by `alt` (or `aria-hidden` for a
  decorative `alt=""`), and the load failure posts no notice. Without a template the glyph shows.
- **§D.10 tm-icon in buttons.** `styles/tm-button.css`: `.tm-button { --icon-size:
  var(--button-icon-size) }`; `flex: none; pointer-events: none` covers `> tm-icon` as `> svg`.
- **§D.12 tmButton.** `button/tm-button.ts`: selector `button[tmButton], a[tmButton]`; a link gets
  variant and size only (no `type`, `pending` ignored). `disabledReason`: `aria-disabled`, focus
  kept, the existing capture-phase guard swallows activation (renamed `suppressActivation`), the

  warning for `disabled` + reason. The tooltip: `tooltip/internal/tm-tooltip-controller.ts`
  (`ɵTmTooltipController`, exported ɵ from `./tooltip`) now holds all tooltip behaviour; `TmTooltip`

  `TmButtonHarness.getDisabledReason()` (reads the describer's message element) and `isLink()`;

- **§D.13 TmTabGroup.instantiate(ids?).** `tabs/tm-tab-group.ts`: `instantiatedIds`; such a tab's

### Deviations

1. `--popover-max-inline-size` 320 → 346 px: the panel is now border-box (so fixed widths and the
   block cap are whole-panel sizes), and the token became the whole-panel cap; `auto` panels
   render exactly as wide as before (320 content + 24 padding + 2 border).
2. Fixed-size popovers on a block side are shifted inward (CDK `offsetX`) to keep the 8 px
   margin; the spec states only the width clamp, but a full-width panel anchored mid-screen would
   otherwise hang off the edge. `auto` and inline sides keep their alignment.
3. The block cap and the viewport width clamp apply to `auto` too ("every size"); an `auto`
   popover that fits is unchanged.
4. Drawer: the scrim appears without its fade as well ("no motion").
5. `placeholderOnError`: the fallback is `role="img"` named by `alt` and the failure posts no
   status notice — my reading of "the error stays announced through alt" (an avatar list must
   not announce and paint a notice per failed photo).
6. Tooltip internals moved into `ɵTmTooltipController`; `TmTooltip` gained an internal `ɵreason`
   so a `tmButton` that also carries `tmTooltip` shows the reason in its place (the spec is silent;
   two tooltip directives on one element are impossible, and two tooltips would fight).
7. A reason on a link is a `console.error` in dev mode and is ignored (the library's dev-error
   convention, as `tm-icon`), not a throw.
8. "A docs page" for `./overlay`: components.json covers components and directives only, so the
   overlay's docs are its `@packageDocumentation` (in the golden) and the README row.
9. Harness/DOM hooks added for the required harness methods: `tm-modal--end` on the shell,
   `data-tm-tab` on tab panels; `TmButtonHarness.isLink()` added.

### Open risks / what to examine hardest

- **Budget pressure:** popover 9 B, grid 3 B, image 53 B, button 171 B, tooltip 164 B headroom.
  The next change to any of these needs a ceiling decision.
- **Popover geometry:** the cap is recomputed only when the CDK reports a position change; after
  a viewport resize or a scroll that keeps the same side, the cap and the inline offset are stale
  until the next open. An open popover does not follow a live direction flip (as before; §B.3
  says connected overlays follow at their next attach).
- **Tap detection** uses pointerdown/pointerup (the click is swallowed); check it against
  real devices' pointer sequences and the long-press interplay.
- **`instantiate()`** relies on aria 22.0.3 rendering an empty deferred view for an instantiated
  tab when selected; the visited-`preserveContent` tracking is ours, not aria's.
- **The tooltip refactor** moved host listeners to `addEventListener`; behaviour should be
  identical (the tooltip suites pass unchanged), but review the teardown order.
- **`injector.get(ViewContainerRef)`** after construction (lazy reason tooltip) — works in
  Angular 22's NodeInjector; it inserts the container's anchor comment only on first show.
