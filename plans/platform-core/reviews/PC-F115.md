# PC-F115: Shell-frame skip-link focus flake

## Implementer notes

PC-F115 has no CHECKPOINTS.md entry. It is a fix item, scoped by its LEDGER row, the flaky-tests
row for the skip-link test, D-406 to D-410 and the brief. No spec section is in scope, and no
product code changed.

### Root cause

`moves focus to main from the skip link, leaving the URL alone` calls
`HTMLAnchorElement.prototype.click()` on the skip link. Two core specs replace that method with a
`vi.spyOn(...).mockImplementation(...)` and never restore it:

- `client/projects/core/tellma-core/support/src/tm-support-dump.spec.ts`, "downloads through a
  temporary link and an object URL revoked later, and records whether it holds page data";
- `client/projects/core/tellma-core/support/src/tm-diagnostics-panel.spec.ts`, the last test of its
  first `describe` (the support dialog's "Download diagnostic file").

The unit-test builder runs a browser project with `isolate: false`: each worker is one Playwright
page whose one tester iframe runs its share of the files one after another. Vitest's Node runner
calls `vi.restoreAllMocks()` after every file ("mocks should not affect different files",
`vitest/dist/chunks/base.*.js`), but its browser tester (`@vitest/browser` `executeTests`) does
not, and the workspace preset did not set `restoreMocks`. So when either support spec ran earlier in
the same page as the shell-frame spec, with no file in between whose own `afterEach` happened to
call `vi.restoreAllMocks()`, the skip link's `click()` was the leftover mock: no click event was
dispatched, `skip()` never ran, focus stayed on `body` (id `''`), and the URL was unchanged, so
only line 60 failed. Exactly the CI signature.

That explains every observation in the evidence: the failure follows the file schedule (CI orders
by size with no results cache, so any spec's size change moves files between workers), it never
reproduced in serial orders that did not put a support spec first, PC-123's diagnostics in the
spec or a setup file changed the schedule or wrapped `click` themselves, and the first local
failure (2026-11-25) came in PC-154's own fix run, the checkpoint that added both support specs.

Reproduction, one worker, files in a forced order (scratch config, not committed):

- `tm-support-dump.spec.ts` then `tm-shell-frame.spec.ts`: fails 1/1, deterministic; the silent
  focus recorder shows no click event and no focus call at all, `activeElement` `body`,
  `hasFocus()` true.
- `tm-diagnostics-panel.spec.ts` then `tm-shell-frame.spec.ts`: fails 1/1, the same.
- Both pairs with the fix: pass.

### The fix

`@tellma/core-tools/vitest` (the preset every client workspace's `vitest-base.config.mjs`
re-exports, the platform's and Acme's) now sets `restoreMocks`, `unstubGlobals` and `unstubEnvs`.
Vitest then restores every `vi.spyOn` spy and every `vi.stubGlobal`/`vi.stubEnv` stub before each
test, so no test inherits a mock from an earlier test or an earlier file in its page, whichever
worker the schedule gives it. This closes the class, not just the two specs: a spec that forgets to
restore a spy can no longer reach another file. The two support specs need no change, and the
shell-frame spec is unchanged (D-011: no retry, quarantine, loosened assertion or timeout).

- `client/projects/core/tellma-core-tools/src/vitest/index.ts`: the three options, TSDoc on why.
- `client/projects/core/tellma-core-tools/src/vitest/watchdog.spec.ts`: "the Vitest preset" pins
  the three options.
- `client/projects/core/tellma-core-tools/README.md`, `client/README.md`, both
  `vitest-base.config.mjs` comments: what the preset now does, and that a spy several tests share
  must be made in `beforeEach`.

### Deviations

None from a spec. The fix is in shared test tooling rather than in the shell frame, because the
shell frame and its spec were correct.

### Open risks

- A leaked spy is restored before the next test, not at the end of its file, so for the time
  between one file's last test and the next file's first test (the next file's module evaluation
  and its `beforeAll` hooks) it is still in force. Nothing in the client depends on a patched
  prototype there today. Closing that window too would need a setup file shipped with the preset
  that restores at each file's end, which the builder's setup-file merge makes fiddly; I judged it
  not worth it.
- Spies or stubs made in `beforeAll` or at a file's top level are now restored before the first
  test. None exists in the client today (checked by inspection and by the full unit run); the
  README states the rule for new ones.
- The explicit `vi.restoreAllMocks()`/`vi.unstubAllGlobals()`/`vi.unstubAllEnvs()` calls in
  existing specs' `afterEach` hooks are now redundant but harmless; they were left in place to keep
  the change to the cause.

### What reviewers should examine hardest

- Whether the root cause is fully established: the two forced-order reproductions, and whether any
  other leaked mock (for example `vi.useFakeTimers` without `useRealTimers`) could also reach the
  skip test. Fake timers would not stop a synchronous `click()`/`focus()`, so I found no other
  candidate for this signature.
- That no spec relied on a spy surviving into a later test (the full client unit run below).
