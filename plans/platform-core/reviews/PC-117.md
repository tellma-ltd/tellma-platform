# PC-117: /entity entry point: select plans, formats, typed values and blob checks

## Implementer notes

### What was built, and where

All new code is in the lazy entry point `@tellma/core/entity`
(`client/projects/core/tellma-core/entity/`), which `package.json` budgets and lists in the
primary's `staticGraphExcludes`. The lint graph (`core-entry-points.ts`) already placed it.

- `src/tm-select-plan.ts`: `tmSelectPlan` (spec 0029 §6.1, §6.2), `TmColumnPlan` and the plan's
  `rows`. Column kinds value / text / navigation / image / file / expression; the root key first;
  terms de-duplicated case-insensitively; order terms per active slot (`coalesce(NameS, Name)` when
  the active slot is not the first); a navigation orders by its display name's prefix, then its
  name; `extra` paths and a key's custom `select` paths are terms only, never columns. Each term
  is checked with `TmPermissions.reachable`, and a key is dropped as `unknown` (no resolution) or
  `unreachable` (any term refused), with `tm.entity.column-dropped { reason, source }`. An
  expression column takes its type from the response's column type (`ɵtype`). `rows()` builds
  one `TmPlanRow` subclass per call, with a getter per column key; `get(term)` matches the exact
  term, then case-insensitively.
- `src/tm-formats.ts`: `TmFormats` (§12.1, §12.2): `text` (zone mode `'auto'`), `cell` (mode
  `'column'`; group, navigation and file cells), `zoneSuffix`. Decimals and longs format from
  their decimal text through `Intl.NumberFormat.prototype.format` (the ES2023 string input), so
  28 digits survive; no bidi control in any output.
- `src/tm-value.ts`: `tm-value`: text (mono for guid and time, a slot in its `contentDir`),
  "—" or empty by surface, enum badges, related rows as links when `allows(target, 'details')`,
  with `tm-avatar` keyed `{entity}:{id}` when the target's related projection carries an image,
  thumbnails asking for `thumb` only when `Variants` lists it, file names as download links. An
  id with no known name is resolved in the background.
- `src/tm-value-editor.ts` and `src/tm-form-field-delegate.ts`: `tm-value-editor`, one control per
  type inside the caller's `tm-form-field` (it provides `TM_FORM_FIELD_CONTROL` and forwards the
  label, description and error wiring to the inner control). Ownership rules, write-once by the
  `create` input, instants / datetime / float / json / binary read-only, a related row read-only
  (the planner's seam until 0029-e), `tmNumber` bound by hand for exact decimals and longs, the
  image editor (`tm-image` edit mode, cover-square crop) and the file picker with its chip, both
  uploading on pick through `TmApi.upload`, with size / type / upload-failed errors and a retry.
- `src/tm-uploads.ts`: `TmUploads` (`running`, `staged`, plus `start`, `cancel`, `stage`); a new
  upload at a path aborts the previous one, and the host's destruction aborts all.
- `src/tm-grid-column-for.ts`: `tmGridColumnFor` (§12.2's last column): plan rows by key with
  `sortable` from `orderBy`; model rows (`editable`) by JSON names, a group in its active slot;
  exact display and parse for decimals and longs (15-digit `tmNumber` envelope enforced at
  parse); enum options in order; read-only rules per ownership and write-once per new row.
- `src/tm-blob-check.ts`: `tmCheckBlobFile` (§16) and the internal cover-square crop.
- Strings: `tm.value.*` in `tm-english.ts` and the Arabic pack.
- README: an entry-point row and a "Select plans, formats and typed values" section.
  ARCHITECTURE.md: the `/entity` line names what it holds.

### Deviations

1. `tm-value`'s `property` also takes a `TmColumnPlan` (its `value` is then the row), and it has a
   `surface` input (`'details' | 'grid'`). The spec's contract has neither, but §12.2's text column
   differs per surface, and a search grid's custom cells need the plan's row.
2. `tm-value-editor` has a `create` input: §12.2's write-once rule needs to know create mode, and
   the contract names no source for it.
3. `tmGridColumnFor` takes `rows: 'plan' | 'model'` and `injector` besides `editable`, and returns
   `Partial<TmGridColumnConfig>`, an interface declared in this entry point (the grid's inputs by
   name), since `@tellma/core-ui/grid` exports no column-config type. `rows` defaults to `'model'`
   when `editable` is given, else `'plan'`.
4. A related row's key property (for example `CurrencyId`, `foreignKeyOf` set) is read-only in
   `tm-value-editor` and shows its id: the property descriptor does not name its target entity.
   Callers pass the navigation for a display name.
5. The primary's ceiling rises from 42.5 to 43 KB and the Arabic strings' from 6.5 to 7 KB, both
   for the `tm.value` strings. The platform's English table is one object that the primary ships
   whole, and no mechanism exists for a lazy entry point to add strings of its own.
6. The image editor's picker cap for a cover-square kind is `max(policy.maxSize, 20 MB)`: the crop
   re-encodes the picked image, so the policy's cap applies to what uploads. `tmCheckBlobFile`
   runs on the cropped image before the upload.

### Open risks

- Expression columns are not checked for reachability on the client; the server's Queryex refuses
  an unreachable path. A key column's terms are checked.
- `tmNumber` holds a `number`, so decimal editing is exact only within 15 significant digits; the
  editor and the grid parse refuse more.
- A stored image cannot be re-framed (the editor does not pass the original to `tm-image`).
- An existing file's name is unknown to the editor without the row's `FileName`, so its chip reads
  "File" until it is replaced.
- A browser that cannot encode webp falls back to png for the crop (`convertToBlob` behaviour).
- Budgets. `./entity` is born at 11.30 KB, ceiling 11.5 (the spec targets about 28 KB for the
  whole entry point). The primary went from 42.39 to 42.50 KB for the eight `tm.value` strings in
  the English table, raised from 42.5 to 43 (the measurement rounded up to the next 0.5 KB). The
  Arabic strings went from 6.47 to 6.59 KB, raised from 6.5 to 7. Each raise has its note. The
  primary was measured before PC-106's +2.13 KB lands, so whoever integrates second re-measures it.

### What reviewers should examine hardest

- `tmSelectPlan`'s reachability: every term of a key goes through `TmPermissions.reachable`,
  which mirrors the server's QueryTraversalRule; confirm nothing is more permissive.
- `TmFormats` zone handling in `'column'` mode across Asia/Beirut's DST change, and the exactness
  of decimals and longs.
- `tm-value-editor`'s form-field delegation (`tm-form-field-delegate.ts`): label `for` versus
  `aria-labelledby`, described-by forwarding, error state for local upload errors.
- `TmUploads` races: a second upload at one path, a late answer from an aborted one, and the
  host's destruction.
