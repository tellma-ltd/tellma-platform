# PC-117: /entity entry point: select plans, formats, typed values and blob checks

## Implementer notes

### What was built, and where

All new code is in the lazy entry point `@tellma/core/entity`
(`client/projects/core/tellma-core/entity/`), which `package.json` budgets and lists in the
primary's `staticGraphExcludes`. The lint graph (`core-entry-points.ts`) already placed it.

- `src/tm-select-plan.ts`: `tmSelectPlan` (spec 0029 §6.1, §6.2), `TmColumnPlan` and the plan's
  `rows`. Column kinds value / text / navigation / image / file / expression; the root key first;
  terms de-duplicated case-insensitively; order terms per active slot (`coalesce(NameS, Name)` when
  the active slot is not the first); a navigation orders by its display name's prefix, then its
  name; `extra` paths and a key's custom `select` paths are terms only, never columns. Each term
  is checked with `TmPermissions.reachable`, and a key is dropped as `unknown` (no resolution) or
  `unreachable` (any term refused), with `tm.entity.column-dropped { reason, source }`. An
  expression column takes its type from the response's column type (`ɵtype`). `rows()` builds
  one `TmPlanRow` subclass per call, with a getter per column key; `get(term)` matches the exact
  term, then case-insensitively.
- `src/tm-formats.ts`: `TmFormats` (§12.1, §12.2): `text` (zone mode `'auto'`), `cell` (mode
  `'column'`; group, navigation and file cells), `zoneSuffix`. Decimals and longs format from
  their decimal text through `Intl.NumberFormat.prototype.format` (the ES2023 string input), so
  28 digits survive; no bidi control in any output.
- `src/tm-value.ts`: `tm-value`: text (mono for guid and time, a slot in its `contentDir`),
  "—" or empty by surface, enum badges, related rows as links when `allows(target, 'details')`,
  with `tm-avatar` keyed `{entity}:{id}` when the target's related projection carries an image,
  thumbnails asking for `thumb` only when `Variants` lists it, file names as download links. An
  id with no known name is resolved in the background.
- `src/tm-value-editor.ts` and `src/tm-form-field-delegate.ts`: `tm-value-editor`, one control per
  type inside the caller's `tm-form-field` (it provides `TM_FORM_FIELD_CONTROL` and forwards the
  label, description and error wiring to the inner control). Ownership rules, write-once by the
  `create` input, instants / datetime / float / json / binary read-only, a related row read-only
  (the planner's seam until 0029-e), `tmNumber` bound by hand for exact decimals and longs, the
  image editor (`tm-image` edit mode, cover-square crop) and the file picker with its chip, both
  uploading on pick through `TmApi.upload`, with size / type / upload-failed errors and a retry.
- `src/tm-uploads.ts`: `TmUploads` (`running`, `staged`, plus `start`, `cancel`, `stage`); a new
  upload at a path aborts the previous one, and the host's destruction aborts all.
- `src/tm-grid-column-for.ts`: `tmGridColumnFor` (§12.2's last column): plan rows by key with
  `sortable` from `orderBy`; model rows (`editable`) by JSON names, a group in its active slot;
  exact display and parse for decimals and longs (15-digit `tmNumber` envelope enforced at
  parse); enum options in order; read-only rules per ownership and write-once per new row.
- `src/tm-blob-check.ts`: `tmCheckBlobFile` (§16) and the internal cover-square crop.
- Strings: `tm.value.*` in this entry point (`src/tm-entity-strings.ts`), registered through a new
  `TmLocalization.ɵregisterStrings(scope, table)` seam in the primary when `TmFormats` is first
  created, and in the Arabic pack (review 1).
- `src/tm-exact-number.ts`: the shared reader of a decimal's or long's edit text (`ɵtmParseExact`)
  and the `tmExactBinding` field binding that carries a refusal into the field (review 1).
- README: an entry-point row and a "Select plans, formats and typed values" section.
  ARCHITECTURE.md: the `/entity` line names what it holds.

### Deviations

1. `tm-value`'s `property` also takes a `TmColumnPlan` (its `value` is then the row), and it has a
   `surface` input (`'details' | 'grid'`). The spec's contract has neither, but §12.2's text column
   differs per surface, and a search grid's custom cells need the plan's row.
2. `tm-value-editor` has a `create` input: §12.2's write-once rule needs to know create mode, and
   the contract names no source for it.
3. `tmGridColumnFor` takes `rows: 'plan' | 'model'` and `injector` besides `editable`, and returns
   `Partial<TmGridColumnConfig>`, a type this entry point derives from `TmGridColumn`'s own inputs
   (so a renamed or retyped input fails the build), since `@tellma/core-ui/grid` exports no
   column-config type. `rows` defaults to `'model'` when `editable` is given, else `'plan'`.
4. A related row's key property (for example `CurrencyId`, `foreignKeyOf` set) is read-only in
   `tm-value-editor` and shows its id: the property descriptor does not name its target entity.
   Callers pass the navigation for a display name.
5. The Arabic strings' ceiling rises from 6.5 to 7 KB for the `tm.value` block (6.47 to 6.59 KB);
   that chunk loads only on a switch to Arabic. The English strings moved to this entry point after
   review 1, through the new registration seam, so the primary's ceiling is not raised.
6. The image editor's picker cap for a cover-square kind is `max(policy.maxSize, 20 MB)`: the crop
   re-encodes the picked image, so the policy's cap applies to what uploads. `tmCheckBlobFile`
   runs on the cropped image before the upload.
7. Expression columns skip the client reachability check that key columns get. A preference holding
   an expression over a path the user can no longer read fails the whole query with a 403 rather
   than dropping the column. Carried to PC-120, whose expression lexer can extract the paths
   (review 1, R1-4).
8. In a form's child grid, a multilingual group edits its active language's slot under that slot's
   JSON name, and shows the slot's own value there (no fallback to slot 1). A read-only model
   column keeps the fallback. Spec 0029 §6.1's column keys allow it with no spec change (review 1,
   R1-3).
9. An id (a property with `foreignKeyOf`, or the column entity's key) formats ungrouped but in the
   locale's digits, so Arabic writes "١٢٨٤". Spec 0029 §5.2 and spec 0010 §D.15 say "the digits stay
   the locale's"; the orchestrator's ruling asked for Latin digits, and I followed the specs
   (review 1, R1-6).

### Open risks

- `tmNumber` holds a `number`, so decimal editing is exact only within 15 significant digits; the
  editor and the grid parse refuse more. In the editor, each keystroke's reading is written, so
  a typed "12abc" leaves the field at 12 (the last text that read) and invalid; a paste of text
  that reads as no number keeps the previous value.
- A stored image cannot be re-framed (the editor does not pass the original to `tm-image`).
- An existing file's name is unknown to the editor without the row's `FileName`, so its chip reads
  "File" until it is replaced.
- A browser that cannot encode webp falls back to png for the crop (`convertToBlob` behaviour).
- Budgets. `./entity` is born at 11.30 KB and measures 12.18 after review 1 (its English strings,
  the exact-number reader and field binding, the flag's check icon, the child grid's group slot),
  ceiling raised from 11.5 to 12.5 with its note (the spec targets about 28 KB for the whole entry
  point). The primary went from 42.39 to 42.45 KB, the registration seam's own cost (one method and
  a set of scopes); its ceiling stays 42.5. The Arabic strings went from 6.47 to 6.59 KB, raised
  from 6.5 to 7 with its note. The primary was measured before PC-106's +2.13 KB lands, so whoever
  integrates second re-measures it.

### What reviewers should examine hardest

- `tmSelectPlan`'s reachability: every term of a key goes through `TmPermissions.reachable`,
  which mirrors the server's QueryTraversalRule; confirm nothing is more permissive.
- `TmFormats` zone handling in `'column'` mode across Asia/Beirut's DST change, and the exactness
  of decimals and longs.
- `tm-value-editor`'s form-field delegation (`tm-form-field-delegate.ts`): label `for` versus
  `aria-labelledby`, described-by forwarding, error state for local upload errors.
- `TmUploads` races: a second upload at one path, a late answer from an aborted one, and the
  host's destruction.

DECISIONS.md. What I ran myself on cbc8dd0a: the `/entity` unit and harness suites (`ng test core

  destruction all behave correctly, in `TmUploads.start` and in the editor's own controller.
- **Crop.** It runs on what `tm-image` hands over, which has already passed tm-image's 20 MB and

### Findings

**R1-1 (major): an invalid or over-precise decimal or long silently becomes `null`, and the form
stays valid.**
`client/projects/core/tellma-core/entity/src/tm-value-editor.ts:159-175` (the `exact` case) and
`:482-491` (`setExact`).

The `exact` control binds `tmNumber` by hand (`[value]` / `(valueChange)`), not through
`[formField]`. tmNumber's `parseText` answers unparseable text, and the 15-digit envelope, with
`{ value: null, error }`. Angular's `createParser` (forms/signals `signals.mjs:661-668`) always
writes `value: null` to the model. The error reaches the field only through
`_FORM_CONTROL_INTEGRATION`, which `transformedValue` injects `{ self: true }`, and only the
`FormField` directive provides it.

So `setExact(null)` writes `null` into the field, and the field has no error. tm-form-field shows
no message, because the delegate's `invalid` and `localizedErrors` read the bound field's state.
Save is not held.

Failure scenario: an Arabic user pastes `1,234,567,890,123,456.78` (19 digits) into `CreditLimit`,
or leaves `12abc`, and saves. The input shows its text, but the customer's credit limit is cleared
on the server.

No test types invalid or 16-digit text into the editor. The grid's `parseDecimal` refuses both, so
the two surfaces disagree.

Fix: carry tmNumber's parse result into the field. Two ways to do that:
- bind `[formField]` on a proxy `FieldTree<number | null>`, so the integration exists, and convert
  through `TmDecimals` at the proxy, as spec 0024 §10.4's "converts at the binding" describes;
- or, at minimum, read the inner control's parse errors, keep the field's previous value on a
  parse error, and surface the error both as a local error and as a validation error on the field,
  so the 0031 schema holds Save.

Add harness tests for garbage text, a 16-digit value, and an untouched 28-digit stored value that
survives focus and blur.

**R1-2 (major): the `.` raise holds strings that only `./entity` reads, contrary to D-098; deviation
5 is avoidable.**
`client/projects/core/tellma-core/src/l10n/tm-english.ts:52-61` and
`client/projects/core/tellma-core/package.json` (`"."`: 43).

The eight `tm.value.*` strings are on the first frame, because the English table loads with `.`.
Their only readers are in `./entity`.

D-098 ruled that strings only a lazy entry point reads never raise `.`, and that "later entry
points with strings that only they read follow the same seam". The implementer says no such
mechanism exists in `@tellma/core`. It is cheap to add: core-ui's `ɵtmRegisterUiStrings`
(`tm-ui-translate.ts:79`) is the model. In `@tellma/core`, the Transloco dictionary can take an
entry point's English table as a merged `en` translation the first time `/entity` injects
`TmLocalization`. `ɵtext`'s `fallback` argument is not enough on its own, since it returns the
fallback unformatted and `fileTooLarge` has `{max}`.

This matters beyond 0.11 KB. PC-119, PC-120 and PC-121 add the `tm.entity` picker, `tm.filter` and
`tm.queryex` strings, all read only by `/entity`. Without a seam, each one raises `.` again on top
of PC-106's +2.13 KB.

Fix:
- add the registration seam in `@tellma/core`, move `TM_STRINGS_EN.value` into `./entity`, and
  withdraw the 42.5 → 43 raise;
- keep the Arabic block in `@tellma/locale-ar/strings` (that 6.5 → 7 raise is honest: the chunk
  loads only on a switch to Arabic);
- re-measure `./entity` with its new strings.

**R1-3 (major, an unlisted deviation): a multilingual group is never editable in a child grid, so
slot 1 cannot be edited there at all.**
`client/projects/core/tellma-core/entity/src/tm-grid-column-for.ts:156-182`.

Only a `value` end at the row's own level edits (`:174`). A group anchor in model mode gets a
read-only `value` reader (`:156-166`, `:169-170`), and the spec pins this
(`tm-grid-column-for.spec.ts:86`).

Spec 0029 §6.1 gives no column key for slot 1 verbatim: `Name` is always the group. So a child
grid (spec 0031 §6.4, which takes its columns from `tmGridColumnFor(column, { editable })`) can
edit `Name2` and `Name3` as twins, but never slot 1. In a one-language tenant it cannot edit a
child row's name at all.

§12.2's `string` row gives an editable `text` grid column, and §12.2's ownership rules make no
exception for groups. The commit's Deviations do not mention it.

Fix: in model mode, let a `text` column edit its shown slot. Use the key of the active slot's
`json`, with the config re-derived on a slot change, and the slot property's ownership deciding
`readonly`. In a one-slot shape, treat the group as its slot-1 value. If the read-only choice is
kept, record it as a deviation and flag the consequence for spec 0031's child grids.

**R1-4 (minor): expression columns skip the reachability check, and the commit does not record it
as a deviation.**
`client/projects/core/tellma-core/entity/src/tm-select-plan.ts:410-418`.

Spec 0029 §6.4 says "a stale preference never `403`s the page", and §6.1 lets expression columns
live in preferences. `query` refuses an unreachable path with a 403 (spec 0015 §5.2, "The traversal
rule"). A preference holding `Manager.CreatedAt * 1` therefore fails the whole search page once
the user's `Read` on users becomes filtered.

The implementer lists this under Open risks only. PLAN §7.1 item 1 wants it under Deviations,
with a carry.

Fix: record the deviation. Carry the check to PC-120: tmQxLex can extract the identifier paths of
an expression and run each through `TmPermissions.reachable`, dropping the column as
`unreachable`.

**R1-5 (minor): removing a file or image leaves its blob staged.**
`client/projects/core/tellma-core/entity/src/tm-value-editor.ts:549-557`.

`clear()` aborts the upload in flight and nulls the field, but never calls
`TmUploads.stage(path, null)`. `staged(path)` keeps returning the removed blob, which TmUploads
documents as "for previews and drafts … until the path is cleared". A draft saved after a removal
(spec 0031) then holds a stale staged blob for a field that is now empty.

Fix: in `clear()`, call `this.#uploads?.stage(path, null)`, and add an assertion to the "uploads a
picked file" harness test after `chip.remove()`.

**R1-6 (minor): a key property's id shows grouped and in native digits.**
`client/projects/core/tellma-core/entity/src/tm-value-editor.ts:382` and
`client/projects/core/tellma-core/entity/src/tm-formats.ts:222-223`.

Deviation 4 shows a `foreignKeyOf` property's id. It formats as an `integer`, with grouping, so
`CurrencyId` 1284 reads "1,284", or "١٬٢٨٤" in Arabic. The same applies to a `value` column keyed
`ParentId`. Spec 0029 §5.2 and spec 0010 §D.15 show integer keys ungrouped, and the fallback is
`#1284`.

Fix: format a property with `foreignKeyOf`, or the entity's key property, ungrouped (`grouping:
false`). Add a test with an id of at least 1000.

**R1-7 (minor): a flag in `tm-value` on the grid surface renders "Yes"/"No", not the check glyph.**
`client/projects/core/tellma-core/entity/src/tm-value.ts:310-326`.

Spec 0029 §12.2's `bool` row reads "'Yes' / 'No'; a check glyph in grids". The `surface="grid"`
input exists so that search-grid custom cells can use `tm-value`, but it changes only "—" and the
thumbnail size.

Fix: on `surface === 'grid'`, render a check glyph for `true` (and nothing, or a muted glyph, for
`false`), with "Yes"/"No" as its accessible name. Add a test.

**R1-8 (minor): `TmGridColumnConfig` is a hand copy of `tm-grid-column`'s inputs and can drift
silently.**
`client/projects/core/tellma-core/entity/src/tm-grid-column-for.ts:26-55`.

The `/entity` → core-ui layering itself is clean: only `TmGridColumnAlign` and `TmGridColumnType`
are imported, both as types. But the interface re-declares each input's type by name. If the grid
renames `optionValue` or changes `parse`'s signature, this file still compiles, and every host
that binds the config by name breaks only at run time.

Fix: derive the type from the component, for example
`{ [K in TmGridColumnInputs]: TmGridColumn[K] extends InputSignal<infer V> ? V : never }` over the
listed input names. That makes drift a compile error at zero bytes, and keeps deviation 3 a
naming deviation only.

**R1-9 (minor): test gaps on paths that bypass the tested facades.**
- `tm-formats.ts:234-242`. A `datetime` calls `tmFormatDateTime` directly with its own calendar
  and `timeZone: 'UTC'`, but the only test runs in `en` with Gregorian. Spec 0029 §17's "plans,
  filters, formats" row and the orchestrator's point (5) ask for `ar` and calendars. A dropped
  `calendar` argument would pass today. Add `ar` with `uq` and with `ar-SA-u-nu-latn`. Also
  replace `date`'s self-comparison against `l10n.formatDate`, which cannot fail, with a fixed
  expected string under `uq`.
- `tm-blob-check.ts:79`. The EXIF path of the crop (`imageOrientation: 'from-image'`, with the fit
  framed on the oriented image) has no test. Add one JPEG fixture with orientation 6, cropped
  through `ɵtmCropCoverSquare`, and assert which half lands in the square.
