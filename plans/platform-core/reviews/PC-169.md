### Deviations

1. Acme client budget: initial warning 237 KB raised to 237.5 KB (237.47 KB measured), within
   D-414, with a note in `package.json`.
2. "Revoked pin after role change": a role change needs step-up in the dev host, so the flow
   stores a pin to a page the principal's role does not grant (`settings`). It covers the same
   locked state and unpin.
3. Bell badge 9 to 10: driven across two launches with the inbox read routed, not live. The
   leader polls every 60 s and a fake clock did not trigger the re-read.
4. The Financials section is a stand-in that holds the pages Acme has. The credit-exposure report
   is not wired; the credit-review page's queue waits for it (spec 0033).
5. Installed mode: the `--app` window needs a display, so the test skips on Linux without
   `DISPLAY`. iOS is a `navigator.standalone` stand-in.
6. About "without Distribution_About": Acme sets no such key, so the test reads Acme's default.
7. Responsive: 390 and 1200 run on PR; 576/768/992/1440 are `@nightly`. `launcher-perf` and
   `shell-feedback` are `@perf`.

### Findings (failing specs left strict, per D-011)

1. **Pin popover folder select, mouse click closes the popover** (core-ui popover/select
   outside-click interplay). The keyboard path works. Pinned by `pins.spec.ts`, "a click on a
   folder in the pin popover keeps the popover open" (`test.fail`).
2. **First launcher open paints in frame 2**, not the key's frame, even after the prefetched
   panel has landed. Later keys paint in frame 1, and an open after another overlay paints in
   frame 1. Pinned by `launcher-perf.spec.ts` (`@perf`); local frames `2, 1, 1, 1, 1`.
3. **Sandbox marker popover paints in frame 3.** Pinned by `shell-feedback.spec.ts` (`@perf`);
   local frames `{"session menu":1,"theme":1,"launcher":1,"pin":1,"marker popover":3}`.
4. **A language switch sometimes reads `client/sync`** after the `me/locale` write. It happened
   ar to en in each of the last three runs, and en to ar once, after the launch's own sync and
   network idle. Pinned by
   `pins.spec.ts`, "a language switch writes the locale once and reads no sync". The adopt path in
   `tm-locale-write.ts`/`TmCacheRefresher` is the place to look.
5. **Held preference writes leak at page close.** A held write is kept dirty, and the
   pagehide flush re-sends it as a keepalive request. Once a test drops its routes, that request
   reaches the server. Earlier local runs stored pins for the shared admin principal this way;
   they were deleted. Fixed on the test side: `closeHeld` closes the page before dropping the
   routes. Specs that pin as admin also serve their pins through the sync. This is not a product
   defect, but every future e2e that holds writes needs the same care.

### Open risks

- The frame probe counts `requestAnimationFrame` callbacks after the input's capture listener.
  Headless Windows may differ from CI Linux. The perf specs stay in the `@perf` tier.
- `servePins` rewrites the sync response, and the device keeps what it saw. A spec that warms
  up before serving can show the server's pins on the warm render.
- Pins principals are shared between `pins.spec.ts` runs of different slots against the same
  dev database. The spec is serial within a project, but two slots running it at once would race.
