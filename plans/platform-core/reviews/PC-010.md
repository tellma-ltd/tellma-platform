# PC-010: Omitted parameters and constant statements

## Implementer notes

### What was built, and where

Paths are under `src/core/Tellma.Core.Queryex/` unless stated.

**Omitted parameters (0010 §F.8).**

- `QueryCompilationOptions.OmittedParameters` (`QueryCompilationOptions.cs`): declared names,
  matched ignoring case, null-refusing, default empty.
- `Syntax/OmittedParameterFolder.cs`: the folder. A pure syntax-to-syntax transform that knows
  nothing about queries, binding or caches, so §F.10 and §F.20 can call it as it is.
  `FoldPredicate(list, negated)` folds a text read as one predicate along its skeleton (parentheses,
  `not`, `and`, `or`); `FoldValues(list)` folds a select or ordering list. It returns the same
  instance when nothing changed, and every rebuilt node keeps the span of the node it replaces, so
  diagnostics about what is left still point into the text as written.
  - Step 1: bare omitted elements (through their own parentheses) leave the list of an `in` test
    and the key list of `descendantOf` / `ancestorOf`, only when that test is itself the skeleton
    atom.
  - Step 2: an atom that still mentions an omitted parameter, or whose list is now empty, settles
    to `true` at even polarity and `false` at odd.
  - Step 3: absorption. Only constants folding produced are absorbed; a `true` or `false` the
    author wrote stays where it was written.
  - The condition (second) argument of `count`, `sum`, `avg`, `min`, `max` is folded as a predicate
    of its own, at even polarity, wherever the aggregation sits, and before the atom around it is
    asked whether it "still mentions" anything.
  - Everywhere else an omitted parameter becomes `cast(null, '<type>')` (`CastRules.TargetName`
    supplies the name).
- `Pipeline/OmittedParameters.cs`: resolves the names against the declarations (caller error for a
  name that is null or not declared), normalizes the set (declared spelling, sorted, deduplicated),
  owns the folder, and reports per text which omitted declarations it refers to (`AppliedFolding`),
  which is what the L2 key needs.
- `Pipeline/FilterBinder.cs`: with a non-empty set the tree is folded whole before anything binds
  (`TreeFolder` over `Reduced*` records), then what is left is bound. `FilterTree.Not` flips the
  polarity handed to the leaves beneath it; `Via` and `Exists` are one atom each (any leaf inside
  that refers to an omitted parameter settles the whole node); a whole tree that folds to true
  yields no predicate at all. With an empty set the old path runs untouched.
- `Pipeline/QueryClauses.cs`, `Pipeline/QueryCompiler.cs`, `Pipeline/ExpressionCompiler.cs`: select
  and ordering lists fold as values before the grouping keys are derived; filter and having pass
  the set to `FilterBinder`.
- `QueryexEngine.CompileQuery`: resolves the set on every call, before the cache lookup.

**Constant statements (0010 §F.9).**

- `ConstantItem.cs`, `ConstantCompilationOptions` (in `QueryCompilationOptions.cs`),
  `QueryexEngine.EvaluateConstant`.
- `Pipeline/ConstantCompiler.cs`: each item is its own input at `Constant[<i>]`
  (`DiagnosticLocation.Constant`). A path is found syntactically and reported as QX4009 once per
  item with `name` = the first path as written; binding continues so an aggregation (QX4002), a
  parameter (QX3007), a list (QX2009), a direction (QX2007) and a type mismatch (QX3200) are all
  reported in the same pass. `Binder.BindSingle` checks the one expression against the item's type,
  which is what coerces a string literal.
- Emission reuses the query pipeline with no root: `Lowerer` takes a nullable root
  (`Lowerer.cs`, `Lowerer.Leaves.cs`, `Lowerer.Structure.cs`, `RelationalPlan.Root` nullable),
  `StatementEmitter.WriteFrom` writes nothing without one, and every item is lowered with
  `bindingsAllowed: false`, which is the existing switch for the single-emission guard forms (the
  ones a `HAVING` uses). No new emission code was needed for the guards.
- `DiagnosticCodes`: QX4009 `PathNotPermitted` added; QX2009 renamed `ListNotPermitted` with the
  widened summary.

**Cache keys** (`Caching/CacheKeys.cs`): `QueryKey.Of` includes the resolved omitted set;
`QueryKey.OfConstant` keys a statement on a kind marker, every item's text and type in order, and
every option; `BindKey` gains the omitted declarations the text refers to and the polarity it was
folded under.

**Interpreter** (`test/shared/Tellma.Queryex.Testing/Semantics/`): `InterpreterContext.Omitted`;
`Interpreter.Omitted.cs` applies the rule at evaluation time (`Decides` / `Holds`) over the tree
bound from the text *as written*, with nothing omitted. It never sees a folded tree and shares no
code with the folder. `ReferenceConstants` evaluates constant items with a rowless interpreter.

**Inspection tool** (`eng/queryex-inspection/Tellma.Queryex.Inspection/`): inputs for declared
parameters, omitted parameters and constant items; README updated. Smoke-tested by hand against the
running host (both paths, the caller errors, the page).

**Tests.**

- Corpus (`test/shared/Tellma.Queryex.Testing/Corpus/`): `QueryCorpus.Omitted.cs` (18 compiling
  cases, 3 refusals), `ConstantCorpus.cs` / `ConstantCase.cs` (5 compiling, 11 refusals).
- Unit (`test/core/Tellma.Core.Queryex.Tests/`): goldens for all of the above
  (`Goldens/omit-*.sql`, `Goldens/Constants/*.sql`; `Corpus/Snapshots.cs` is the snapshot code
  shared by `GoldenTests` and the new `ConstantGoldenTests`); `Emit/OmittedParameterTests.cs` pins
  the rule as text through the new `Probe/ProbeFolding.cs`, plus what is never bound, the caller
  errors, the keys and the empty set; `Emit/ConstantStatementTests.cs`; the coverage suites now
  count the constant corpus.
- Integration (`test/core/Tellma.Core.Queryex.IntegrationTests/`): the existing differential runs
  the omit cases with a value supplied for every parameter, omitted ones included;
  `ConstantDifferentialTests.cs` is new.

### Deviations from the spec

1. **L2 key carries more than "the omitted set".** One text can bind three ways under one context:
   unfolded, folded where it is asserted, folded where it is denied. `BindKey` therefore includes
   the omitted declarations the text refers to and a polarity flag. Without it the three share an
   entry.
2. **Aggregation conditions fold first.** `count(Id, CustomerId = @Customer) > 2` becomes
   `count(Id, true) > 2`, not `true`: the condition is a skeleton of its own, and the atom around
   it is asked whether it "still mentions" an omitted parameter only afterwards. The spec's wording
   allows either reading.
3. **A filter that folds to true is no filter**: no `WHERE` is emitted, rather than a constant
   predicate.
4. **Absorbed siblings are not bound either.** In `CustomerId = @Customer or Nothing = 1` nothing
   is reported about `Nothing`. The spec says only that folded atoms are not bound; this follows
   from absorbing on the syntax tree, and matches what one text holding the same connectives does.
5. **Only folded constants absorb.** `true and CustomerId = @Customer` leaves the author's `true`,
   which is then bound like any other text.
6. **`Via` / `Exists` as one atom** lifts every restriction composed inside the node together with
   the one that mentions the parameter (corpus `omit-via`).
7. **"Counts as referenced for 0008 §6.3" has nothing to attach to.** The engine has no rule about
   unreferenced declarations, so nothing was implemented for it.
8. **`HasUser = false`**: a bare `me()` still reads the `UserId` slot, which the host binds no
   value to, exactly as in a query. "Absent" is carried by the column's nullity (`Null`) and by
   comparisons folding at compile time.
9. **Statement layout** is the engine's own (`SELECT` and one indented item per line, then `;`),
   not the spec example's single-line layout. The expressions and slot names are the example's.
10. **The `'uq'` constant test is not here.** §F.11 is not implemented yet, so
    `startOfMonth(today(), 'uq')` does not bind. That test belongs to the checkpoint that lands
    §F.11.
11. **Constant statements share the query cache** and its bound
    (`QueryexEngineOptions.MaxCachedQueryTemplates`, doc updated). The spec says only that they are
    cached on items, types and options.
12. **Table row 3** is pinned with `Code = 'INV-1' or …` because the fixture has no `Region`.
13. **A folded ordering term that repeats an earlier one is dropped, not QX4008** (added with the
    review 1 fixes). 0008 makes two structurally equal ordering terms QX4008, and §F.8 does not
    say what happens when folding is what made them equal. Reporting it would refuse, at run time,
    a definition that was valid when it was saved, because of what a reader left out. So a later
    term is left out of the statement when folding rewrote it or the term it repeats; two terms
    that stand as written are still QX4008.

### Open risks

- **A whole tree never folds to false.** By the parity rule everything folding settles at the root
  is `true`. `FilterBinder` still binds a root-level `false` as a literal rather than assuming it
  away; that branch is unreachable today and has no test.
- **Rootless `Lowerer`.** `Base` throws `InvalidOperationException` if anything asks for the root
  while lowering a constant statement. Paths are refused before lowering, and
  `AnyText_AtAnyType_IsCompiledOrRefused` pushes every expression-corpus text through
  `EvaluateConstant` at every type without tripping it, but the guarantee is by construction, not
  by type.
- **Item types `QxHierarchyId` / `QxGeography`** are accepted; only `null` satisfies them. `null` at
  `QxBool` is QX3200, which is the engine's existing rule for a bare absent value where a truth
  value is required.
- **Typed-absent strings** are `CAST(NULL AS nvarchar(4000))`, the engine's existing rendering.
- **`sum(x, true)`** emits `SUM(CASE WHEN (1 = 1) THEN x END)` and reports `Nullable`, as a written
  `sum(x, true)` always did. Correct rows; not the tightest SQL or nullity.

### What reviewers should examine hardest

1. `Syntax/OmittedParameterFolder.cs`: polarity through `not`, the "mentions" test (it must ignore
   what is inside an aggregation condition and nothing else), bare-element detection, and that no
   path returns a constant of the wrong polarity.
2. `Pipeline/FilterBinder.cs` `TreeFolder`: parity across `FilterTree.Not`, absorption in
   `ReduceJunction`, the `Via` / `Exists` rule, and that a leaf which fails to parse is reported
   exactly once whether or not the node around it folds away.
3. `Caching/CacheKeys.cs`: that no two different compilations can share a key (omitted set,
   polarity, statement kind, item boundaries).
4. Independence of `Interpreter.Omitted.cs` from the folder: it is the only thing standing between
   a wrong folding rule and a green differential.
5. The rootless path through `Lowerer` and `StatementEmitter`.
6. The goldens under `Goldens/omit-*.sql` and `Goldens/Constants/`, read against §F.8 and §F.9.

**Deviations judged.**

1. L2 key with the referred omitted declarations plus a polarity flag: **accept, and it is needed.**
   §F.0's "the omitted names a text refers to" is not enough on its own. Probed:
   `(CustomerId = @A or IsPosted) and Amount > 0` folds to `Amount > 0` where asserted and to
   `IsPosted and Amount > 0` where denied, and both bind in one compile. The folded tree is a
   function of the text, the referred omitted declarations with their types, and the parity. No
   other input enters, so the key is complete and two texts that must compile differently cannot
   share an entry. The spec should be brought in line (flag for the orchestrator).
2. Aggregation conditions fold first, so `count(Id, X = @P) > 2` becomes `count(Id, true) > 2`:
   **accept. This reading is right.** §F.8 lists "the condition argument of every aggregation,
   wherever the aggregation sits" as a folding site of its own, row 5 of the table shows the
   aggregation surviving with its condition lifted, and §F.20 treats each condition as an
   independent predicate. The other reading would also drop the `> 2` threshold, which no omitted
   parameter governs. The interpreter implements the same reading independently
   (`Mentions(…, everywhere: false)` plus `Decides` inside `Aggregate`).
3. A filter or having that folds to true emits no clause: **accept** (lowering would fold `1 = 1`
   away anyway; restrictions still form `WHERE` on their own, probed).
4. Absorbed siblings are not bound: **accept.** It follows from absorbing on the syntax tree, and
   spec 0033 §3.4's save-time validation compiles with nothing omitted.
5. Only folded constants absorb: **accept.** It is semantically identical, and it keeps what is
   reported independent of which parameters happen to be omitted.
6. `Via` and `Exists` lift everything composed inside them: **accept as the literal spec.** Probed:
   `Via("Customer", Leaf("Id in (@A, @B)"))` with only `@B` omitted drops the whole filter, which
   lifts the supplied `@A` too, while the same leaf without the rebase keeps
   `Customer.Id in (@A)`. Production `Via` and `Exists` trees carry host access criteria
   (0014 §5.5, 0033 §10, 0033's sharing `Exists`) rather than optional report parameters, so the
   exposure is small. It is still a spec ambiguity worth an orchestrator note: step 1 could be
   read as applying inside the node.
7. "Counts as referenced" has nothing to attach to: **accept.** 0008 §6.3 has no
   unreferenced-declaration rule; its caller error is about names no expression could spell.
8. `HasUser = false` keeps the `UserId` slot: **accept.** This matches 0008 §10.6 for queries.
   Spec 0012's `QueryexContextValues.UserId` is `int?`, so the host binds NULL, and the
   differential runs this with `UserId = null`.
9. Statement layout: **accept.** §F.0 says the SQL blocks show the layout shortened.
10. `'uq'` constant test deferred: **accept.** PC-012's tests list "scalar-form goldens (SELECT,
    HAVING, a constant statement)".
11. Constant statements share the query cache bound: **accept.** The XML doc on
    `MaxCachedQueryTemplates` says so, and `AStatementAndAQuery_NeverShareAnEntry` pins the key
    separation.
12. Table row 3 pinned with `Code = 'INV-1'`: **accept.**

**R1-1 (major): QX4008 is raised by folding, so a definition that validates with nothing
omitted fails at run time.** `src/core/Tellma.Core.Queryex/Pipeline/QueryClauses.cs:337` folds
the ordering list, and `CheckOrdering` (`QueryClauses.cs:376-393`) then reports any two
equivalent terms as QX4008. Two terms that differ only in which omitted parameter they mention
become identical after folding.
- *Failure scenario (probed):* an aggregate report with `Select = "Centre.Name, sum(Amount,
  CustomerId = @A), sum(Amount, CustomerId = @B)"` and `OrderBy = "sum(Amount, CustomerId = @A)
  desc, sum(Amount, CustomerId = @B)"`. It compiles with nothing omitted, which is the save-time
  validation of spec 0033 §3.4. With both `@A` and `@B` left blank it fails with QX4008 at
  `OrderBy` (35, 28). `OrderBy = "coalesce(@A, Amount), coalesce(@B, Amount)"` fails the same
  way. The user gets a diagnostic for a report the author cannot fix.
- *Fix:* when the ordering list was folded (`folding` is not null), drop a later term that is
  equivalent to an earlier one instead of reporting it. It cannot change the order, and the
  backend refuses the repeat, as the comment at `QueryClauses.cs:388` says. Alternatively, run the
  duplicate check on the unfolded list. Add a corpus row (golden plus differential) with two
  measure terms, both parameters omitted.

**R1-2 (minor): the corpus row `refuse-omitted-operand` does not omit the parameter it is about.**
`test/shared/Tellma.Queryex.Testing/Corpus/QueryCorpus.Omitted.cs:251-259` omits `["Customer"]`,
but the select is `Amount + @Root`. QX3201 at (13, 5) comes from the declared, un-omitted
`String` parameter, so the row passes with or without folding. Its stated purpose ("the absent
value an omitted parameter becomes carries the parameter's own span") is not exercised through
compilation.
- *Fix:* omit `["Root"]` instead. Probed: it yields the same QX3201 at `Select` (13, 5), `type =
  String`, so only the omitted list changes.

**R1-3 (minor): `OneEngine_KeepsTheCompilationsApart` does not do what its comment says.**
`test/core/Tellma.Core.Queryex.Tests/Emit/OmittedParameterTests.cs:443-471` says "the one leaf
text binds three ways here". But `CustomerId = @Customer or Amount > 0` settles to a constant
where it is asserted, so it is never bound. Only the denied binding reaches the L2 cache.
Removing `Negated` from `BindKey` would still pass this test. Only the key-level probe
(`DistinguishesFolding`) would catch it, and nothing pins the polarity flag through the engine.
- *Fix:* use a text that stays bound under both polarities with different trees, such as
  `(CustomerId = @Customer or IsPosted) and Amount > 0` in `And([Leaf(t), Not(Leaf(t))])`.
  Assert `WHERE (([T].[Amount] > @qx0_p0) AND NOT ((([T].[IsPosted] = 1) AND ([T].[Amount] >
  @qx0_p0))))`, and the mirrored statement with the children swapped, both on one engine (both
  probed and correct today).

**R1-4 (minor): QX4009's `name` argument is the raw text, brackets and all.**
`src/core/Tellma.Core.Queryex/Pipeline/ConstantCompiler.cs:142-146` passes
`item.Text.Substring(path.Span…)`. For `[Posting Date]` the argument is `"[Posting Date]"`
(pinned by `constant-refuse-bracketed-path`), and any whitespace the parser accepts inside a path

gets a differently shaped value than it does for QX3001 or QX3002, and the shape becomes a public

- *Fix:* pass `string.Join('.', path.Segments.Select(s => s.Name))` and update the two QX4009
  corpus sites (`[Posting Date]` → `Posting Date`).

### Responses

- R1-1: fixed in the "PC-010: review 1 fixes" commit (child of 36c28a9), the preferred way.
  `QueryClauses.BindOrderBy` records which ordering terms folding rewrote (the folder hands back
  the very item it was given where it changed nothing, so identity tells). `CheckOrdering` then
  treats a later term equivalent to an earlier one in two ways: if folding rewrote either of the
  pair, the later term is left out of the statement and nothing is reported; if both stand as
  written, it is QX4008 exactly as before, even when other terms of the same list were folded.
  The second half is deliberate and narrower than "a folded list never reports QX4008": what is
  reported about a text should not depend on what was omitted beside it, and a term written twice
  is refused with nothing omitted too. The dropped term is skipped in `LowerOrdering` by position,
  so item locations keep their indices and the cached bound list is never mutated. The first
  term's direction wins: a later term only settles ties the earlier ones leave, and equal values
  leave it nothing to settle.
  Corpus rows `omit-ordering-repeated` (two measures, both parameters omitted, the scenario of the
  finding) and `omit-ordering-repeated-values` (the `coalesce` form), each with a golden and each
  run by the differential suite; unit tests `AnOrderingTerm_RepeatedOnlyByFolding_IsDroppedNotReported`
  (also the one-sided case, a folded term equal to an untouched one) and
  `AnOrderingTerm_WrittenTwice_IsStillReported`.
  Beyond the finding: `EveryCorpusQuery_SurvivesLeavingItsParametersOut` used to tolerate a
  refusal, which is how this got through. It now asserts that every corpus query that compiles
  with nothing omitted compiles with each parameter omitted in turn and with all of them omitted.
  I also looked for other places where folding could make two things equal that were not: the
  remaining equivalence checks (an ordering term against the grouping keys, against the select
  list, and the root key against the ordering) only ever look for a match, never object to one, and
  the select list has no duplicate rule, so the ordering list was the only site.
- R1-2: fixed in the "PC-010: review 1 fixes" commit (child of 36c28a9). `refuse-omitted-operand`
  omits `["Root"]`; same QX3201 at Select (13, 5) with type String, now actually through the
  absent value the comment talks about.
- R1-3: fixed in the "PC-010: review 1 fixes" commit (child of 36c28a9). The test uses
  `(CustomerId = @Customer or IsPosted) and Amount > 0`, asserts the statement given in the
  finding, and then compiles the mirrored filter (children swapped) on the same engine and asserts
  its statement, so the denied binding is asked for first once and second once. The comment says
  what the test now does.
- R1-4: fixed in the "PC-010: review 1 fixes" commit (child of 36c28a9). `ConstantCompiler` passes
  the segment names joined by `.`. `constant-refuse-bracketed-path` pins `Posting Date`, and
  `constant-refuse-path` is now written `[Customer] . Name` (span 4, 17) and pins `Customer.Name`,
  so brackets and the whitespace the parser accepts around the dot are both covered.
