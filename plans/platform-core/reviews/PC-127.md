# PC-127: Details host, sources, context, form, modes, loading and the header

## Implementer notes

### What was built

The lazy entry point `@tellma/core/details` (`client/projects/core/tellma-core/details/`), its
route wiring in the primary, the testing pieces in `@tellma/core-testing`, the Arabic part in
`@tellma/locale-ar/details-strings`, and Acme's customer layout.

- `details/src/tm-details-source.ts`: `TmDetailsSource` (kind, entity, id, titleKey, draftKey,
  saveSecurable, writeRoute, read, write, can), `TmDetailsRecord`, `TmDetailsChange`,
  `TmDetailsAbilities`, `TmValidationProblem`, and `tmEntitySource(descriptor, id)`: reads
  `{segment}/get` with `include` naming every declared extra, writes `{segment}/save`, takes its
  abilities from `TmPermissions` (Save for edit and create, Delete, and the activate action), and
  keys its draft as `TmDrafts` does.
- `details/src/tm-details-model.ts`: `tmDetailsCreateModel` (every child collection `[]`, every
  non-nullable boolean the client writes `false`, then `declaration.defaults()`),
  `tmDetailsCloneStrip` (structuredClone, the key and every server-owned member removed at every
  level, blobs nulled, child rows renumbered `-1, -2, …` across the record, then
  `declaration.clone(copy, source)`), `tmDetailsRouteId` (a safe positive integer, or the digits of
  a `long` key beyond it) and `tmDetailsRefused` (the record's row of the `permissions` extra).
- `details/src/tm-details-record.ts`: `TmDetailsRecordState`, one per record key, owning its own
  injector: base and working copy (dirty by reference), the Signal Forms form over the working
  copy, `update(recipe)`, the field and collection registrations, the refusals, the abilities
  narrowed by them, and `land()` / `start()` for the controller.
- `details/src/tm-details-controller.ts`: `TmDetailsController`, provided by each host. One
  `resource()` keyed by record key plus generation, held record versus empty record, the quiet
  refresh, the error, the layout's load, Edit / Cancel (with the Discard changes question) /
  an interim Save / Refresh, the leave of a new record, the document title and the status line.
- `details/src/tm-details-frame.ts`: the header (crumb, title or skeleton, the badges in fixed
  boxes, the toolbar with the pager slot), the band with the progress bar and `aria-busy`, the
  status strip container and the error state with its way out. The toolbar's buttons are views of
  page actions registered with `TmPageActions`.
- `details/src/tm-details-host.ts` (`TmDetailsHost`, routed) and `details/src/tm-details-page.ts`
  (`tm-details-page`, `TmDetailsPage`, for source pages).
- `details/src/tm-details-context.ts`: `TmDetailsContext`, `injectTmDetails()` and the internal
  `TM_DETAILS_CONTEXT`.
- `details/src/tm-details-strings.ts`: the English `tm.details` table, registered through
  `TmLocalization.ɵregisterStrings` when the first controller is created.
- Primary (`.`): `TM_ROUTE_HOSTS.details` now loads `@tellma/core/details`; `TmTitleStrategy`
  gains `ɵsetPageTitle(owner, title)` so the page titles the document with its record's name; the
  route host fills its slot's height (`block-size: 100%`).
- `@tellma/core/errors`: `TmErrorState` gains a `link` input, the primary way out a details page's
  read failure shows ("Customers").
- `@tellma/core-testing`: `TmDetailsPageHarness` and `tmFakeDetails()`.
- `@tellma/locale-ar`: a new `./details-strings` part with `TM_DETAILS_STRINGS_AR`, which
  `tmArabic()` loads beside the other three and merges under `tm`.
- Acme: `src/app/customers/customer-details.ts`, a markup-only layout over the descriptors' Code,
  Name, CustomerType and CreditLimit (labels from the descriptors, values as the record holds
  them), declared as the customers' `details`.
- Acme e2e: `cold-deep-link.spec.ts`'s `fixme` is now a test. It finds C-001's id in another
  context, then goes cold to `/1/customers/{id}` and checks the title (the display name), the crumb
  and that no other heading showed first. In English (the administrator), Edit then Cancel sends no
  `customers/` request and focus returns to Edit. In Arabic (the sales representative, who only
  reads customers), Edit is disabled.

### Non-obvious rulings

1. **"Nothing instantiated while loading with nothing held"** is read through spec 0031 §6.2 and §14:
   what must not be instantiated are the field templates of the layout kit (PC-129). The layout
   itself renders over an empty, not-landed record (status `loading`, `entity()` undefined, model
   `{}`), so its cards can draw their skeletons. The harness test asserts that: the layout renders,
   busy, no bar, a title skeleton, "Loading" in the status line and Edit disabled.
2. **Save is interim.** §10.1 here is registration only; Save writes through the source, lands the
   result, leaves edit mode and replaces `new` by the record's URL. The concurrency, confirmations,
   422 landing and leave guard are PC-133's.
3. **The Actions menu is a disabled placeholder** and the pager is an empty slot. They are the
   later checkpoints' contents.
4. **Cancel in create mode leaves the page**: Back when the router's history state shows an earlier
   in-app navigation (`navigationId > 1`), else the search page.
5. **A refresh that fails in edit mode keeps the edit** and only presents the error. A refresh that
   fails in view mode replaces the body with the error state.
6. **A layout chunk that fails to load** shows as an offline error state in the band.
7. **The document title** comes from the page through a new internal seam on the title strategy in
   the primary (`ɵsetPageTitle`), since the route's title is the entity's singular and spec 0024
   §4.4 titles the document by the page.

### Deviations

1. Create defaults set only the booleans the client writes. A server-owned flag such as IsActive is
   left out, since the save would drop it.
2. No Active badge shows in create mode, since a new record has no state yet.
3. Responsive labels follow the header's width through a ResizeObserver, not container queries.
   Below `lg`, New stays an icon button rather than moving into the Actions menu, because the menu
   is a placeholder.
4. The interim Save (ruling 2).
5. The Actions menu is a disabled placeholder (ruling 3).
6. The escape hatch's `page` renders inside the band, under the platform's header.
7. A failed refresh in edit mode keeps the edit (ruling 5).
8. A layout chunk that fails to load shows as an offline error (ruling 6).
9. Spec 0031 §1's import list should also admit `@tellma/core/errors` (loaded with `import()`),
   `@tellma/core/memory` (`TmDrafts`) and `@tellma/core-ui`.
10. The document-title seam in the primary (ruling 7).
11. The `link` input on `TmErrorState`.
12. The route's id is read as `TmUrls` writes it: a number when safe, else the digits of a long key.
13. The leave guard on a param change (a step with unsaved changes) is left to PC-133.
14. `tmEntityRig` returns its `RouterTestingHarness` (`rig.router`), so one harness serves a test.
    This is a shared test composition, so the whole core unit project ran once.
15. Acme's interim layout shows the raw values, unformatted, until the layout kit (PC-129) arrives.
    It does not use `tm-value`: importing `@tellma/core/entity` puts that entry point's whole
    closure on the details route (see "For the orchestrator").

### For the orchestrator

- **The details route budget cannot hold once a layout imports `@tellma/core/entity`.** With Acme's
  layout on `TmValue`, the Acme build failed on both route budgets: `detailsRoute` and
  `searchRoute` each measured 121.01 KB gzip (18 files), against 80 and 110. The figure is the
  static closure of every chunk that holds an entity module. That closure includes the entity
  pickers and multi-select with `tm-value-editor` (46.9 KB), image, aria menu and form-field
  (15.2 KB), `@angular/forms` (16.2 KB), the action, confirmation and paste chunks, and, through
  the layout's own chunk, the details chunks. Without the import, `detailsRoute` is 29.11 KB
  (3 files) and `searchRoute` is empty. PC-129's `tm-field` will need `tm-value`, so this needs a
  decision first: split entity's view-mode pieces from its edit and picker pieces, or measure the
  route without the entity entry point's lazy chunks.

- ARCHITECTURE.md already describes `/details` as a lazy page family; nothing in it changed.
- The parity test for the Arabic details strings lives in core
  (`details/src/tm-details-strings.spec.ts`), not in the locale-ar spec. The locale-ar unit build
  cannot compile `@tellma/core/details`'s components, and core specs already import locale-ar
  parts.
