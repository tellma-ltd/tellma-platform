# PC-086: Server emit: client entity model, enums, labels, action fields, .d.ts

## Implementer notes

### What was built

Spec 0029 §2 (all), §15, §16 (policy emission) and §5.1 (the display-name rule in each summary).

- **Abstractions** (`Tellma.Core.Abstractions/Client/`). `IClientEntityModel` (`Entities`, `Enums`,
  `Find`) and the part records: summary, full metadata, key, owner, property, navigation, child,
  action, action field, value descriptor, enum and enum value, display-name rule, limits, blob and
  image policy, multilingual slot, and their kebab/camel enums. Every record is in
  `TellmaApiJsonContext`. `SafeIntegerJsonConverter` writes `maxSize` as a JSON number and refuses
  one past 2^53 - 1.
- **Label chains** (`Localization/LabelChains.cs`). One pure function per label kind: entity,
  plural, create, property, navigation, collection, action, action field, enum value, plus
  `Resolve` (first declared key, else the chain's first key with a humanized fallback).
  `LabelProvider`, `ConventionalStringKeys` and the client model all walk these chains, so the
  server's labels, the resource audit's derived keys and the emitted keys cannot drift.
- **Named enums** (`Localization/NamedEnums.cs`). Each C# enum gets one name, `<schema>.<Type>`,
  from its first site: entity properties in model order, then setting keys, then stack and
  child-query action arguments. Every site's schema adds a key prefix. The `core.value-sets` check
  reports two enum types of one name under one schema.
- **The model** (`Client/ClientEntityModel.cs`). It is built lazily, once, from
  `QueryexSchemaProvider.Map(MultilingualShape.All)`. It covers every root (stacks, children,
  read-only roots) with:
  - kinds, segments, operations, capabilities, owners and siblings;
  - multilingual slots, foreign keys, ownership, defaulted, long, precision and scale, value sets;
  - extras, limits (with Queryex's `maxFilterLength`) and blob policies;
  - actions, with argument fields and a JSON Schema (`ActionArguments`, through
    `GetJsonSchemaAsNode` with a transform that writes the wire's text forms of decimal and long).

  Entities and enums are sorted by ordinal name.
- **The contributor** (`Client/EntityClientAssetContributor.cs`). It writes the Core chunk's
  `entities` (summaries), the Entities chunk's `entities` and `enums`, and `tellma-entities.d.ts`
  (`EntityTypesWriter`). Every member of a summary comes before the full metadata's other members.
- **Client** (`@tellma/core`). `TmEntityTypes` and `TmEntityShapes` (empty augmentation targets) and
  `TmEntityType<N>`. Acme's three tsconfigs include `generated/*.d.ts`.

### Rulings worth a second look

- One name per C# enum type, from its first site. A type carried by two schemas is labelled by both
  schemas' keys (`Acme_CustomerType_Retail`, then `Gl_CustomerType_Retail`).
  `SettingKeyDescriptor.EnumType` now carries that qualified name (`acme.Cadence`).
- An `[EntityRef]` argument's key name drops `Id` (`AssigneeId` → `Assignee`), in the conventional
  keys too. Child-query actions' fields are included.
- Read-only roots have no CLR type:
  - their properties are server-owned and `excel: true`, with json names in camelCase and types
    from the store family;
  - hierarchy and geography columns are `binary`.
- `maxSize` is the smaller of the kind's limit and the emitting machine's
  `Tellma:Blobs:MaxUploadSize`.
- The .d.ts includes read-only roots. It leaves navigations out of the wire interfaces, because the
  wire carries related rows apart; `TmEntityShapes` lists them.
- An action's schema has no `$schema` keyword.
- A child whose query surface opted out still carries `owner` from the metadata.
