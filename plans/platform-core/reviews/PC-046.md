# PC-046: String pack, label provider and resource audit

## Implementer notes

### What was built, and where

- **String packs** (`src/core/Tellma.Core/Localization/`):
  - `StringResourceSource` reads one neutral `*.Resources.Strings.resources` manifest per composed feature assembly through a `ResourceManager` with `tryParents: false`, so a satellite yields only its own language's entries. `ServerStrings` never matches the suffix.
  - `StringPackComposer` (singleton) merges the sources into one dictionary per language: English first, then every offered language. It composes lazily, once. It keeps a conflicting key from the first source and records one `StringKeyConflict` per key and pair of sources. Each pack is flat JSON, keys in ordinal order, written with the platform encoder, `Version = DeploymentVersions.DistributionVersion`. `Get` matches the language without regard to case. The composer also answers `INeutralStringKeys` (`Declares`), which replaced the old `NeutralStringKeys` reader (same assemblies, same manifests).
  - `StringPackCheck` (`core.string-pack`, composition-only) turns each conflict into a `CompositionProblem`, so a conflict fails startup and the emit.
  - `StringPackClientAssetContributor` (registered in `CoreFeature`) hands every pack to the new `ClientAssetContext.StringPack`. `ClientAssetBundle` writes `assets/strings-<lang>-<hash>.json` (canonical bytes) and lists them in the loaders module's `strings` map, ordinal by language, quoting hyphenated codes. This is the layout `tellma-core-tools` already reads.
- **Labels**:
  - `LabelProvider` (singleton `ILabelProvider`) walks every §7.6 chain against the merged dictionaries, in the reader's language and then English: entity singular and plural, property, navigation (via the reference's FK), collection, action, enum value (over the schemas of the entities carrying the enum), setting, and value-set value.
  - Multilingual twins read their primary's label. The suffix ` (Symbol)` is added only when the tenant has two or more content languages. A twin beyond the tenant's shape reads its humanized name.
  - The key-resolving twins return the first chain key that English declares, and null when none is.
  - The content languages come from the new `LocalizationContext.ContentLanguages`, which `RequestContext.Localization` and the negotiator fill from the tenant's settings.
- **Key conventions**: `StringKeyConventions` holds the prefix, segment and suffix rules. They are shared with `SecurablesClientAssetContributor`, which now uses them rather than its own copies.
- **Conventional keys**: `ConventionalStringKeys.Of(IServiceProvider)` (public) lists every key the composed model derives: entities, members, references, children and enum values; securables, features and the platform's actions; stacks; settings; notifications and channels; job handlers; calendars and months; value sets; the brand.
- **Audit helper** (`test/shared/Tellma.Testing.Resources`, BCL-only, no references, not a test project):
  - `ResxFile`, `SourceLiterals` (C# and TypeScript tokenizers), `LiteralKeyRules` (verbatim, dotted, problem code, query diagnostic), `RepositoryRoot` (walks up to `Tellma.slnx`) and `ResourceAudit`.
  - The audit's findings are `Orphan`, `SatelliteOnly` and `StalePending`.
- **Core's audit**: `test/core/Tellma.Core.Tests/Localization/CoreResourceAuditTests`. It covers Core's `Strings.resx` and `ServerStrings.resx`, takes literals from `src/` and `client/projects/`, and holds a pending list of keys shipped ahead of their features. Each pending entry is cited to its spec.
- **Tests**: `StringPackComposerTests`, `LabelProviderTests`, `MultilingualLabelsTests`, `ConventionalStringKeysTests`, `ResourceAuditTests`, `StringKeyConventionsTests` and `CoreResourceAuditTests`, plus additions to `ClientAssetBundleTests`, `ClientAssetContextTests` and `StartupGateTests`.
  - The labels are tested over `Tellma.Testing.Entities`' fixture model. The keys live in `Tellma.Core.Tests`' own resources, so an entity from one assembly resolves keys from another, in `en` and `ar`.
  - Fixtures: `FixtureLabelsComposition` composes once per class. A test `ServerStrings.resx` proves exclusion.
  - Two existing tests changed because of this work:
    - `TellmaMigratorTests`: the emit now writes four assets, the English pack among them.
    - `RequestContextHolderTests`: the writer scan now skips `Tellma.Testing.*`, since the suite references `Tellma.Testing.Entities` and its `FixtureTenant` writes the context the way a test host does.

### Deviations

1. `LocalizationContext` gained `ContentLanguages`, the tenant's languages in position order. §7.6 needs the tenant's language symbols to build the twin suffix, and nothing reachable from `ILabelProvider` carried them.
2. The English pack is always composed and emitted, even when the distribution does not offer English. The client boot and the composer's fallback both need it. `IStringPackProvider`'s documentation now says so.
3. New `ClientAssetContext.StringPack(StringPack)` and `ClientAssetBundle.Create(sections, stringPacks, files, out problems)`. The contributor needed a channel for packs, since sections are chunk-scoped.
4. `StringPackComposer` implements `IStringPackProvider` and `INeutralStringKeys` itself and is registered in `LocalizationComposition`, not `CoreFeature`. `NeutralStringKeys` is removed.
5. New startup check `core.string-pack`. The spec's "conflict → CompositionProblem" needs a check to surface it. It is composition-only, so the emit runs it too.
6. A missing plural label falls back to the singular label, never to a pluralized humanization. The securables contributor still humanizes; the server label avoids inventing English plurals.
7. An action's fallback label is the humanized PascalCase action segment.
8. `ConventionalStringKeys` goes beyond §12's list. It adds `Feature_`, `JobHandler_`, every platform action's `Action_` key, stack action and argument keys, `SettingCategory_general`, and the four `Distribution_` keys. Without them Core's own resources fail the audit.
9. `Problem_` and `Queryex_` keys are accepted through literal rules (kebab code → `Problem_x` and `_Detail`; `QX####` → `Queryex_`), not as derived keys. Their codes are source literals, not model items.
10. The audit also scans `client/projects/` TypeScript (`Boot_*` is looked up there), excluding `*.spec.ts`. The spec says "under src/".
11. The audit has a `Pending` map (with a `StalePending` finding). Core ships keys for features that have not landed: stacks, tree entities, the permissions editor, reports and dashboards, settings validation codes, and a few problem codes. Without the map the audit would have to wait for them, or the keys would be deleted and re-added.
12. `RepositoryRoot` locates the root by `Tellma.slnx` rather than `.git`. A git worktree's `.git` is a file, and a source archive has none.
13. `DisplayName_PrefixSeparator` is kept. It is a validation code (`DisplayName.PrefixSeparator`), not the separator itself, so the spec's "the separator is never a resource" does not reach it.

### Open risks

- `LabelProvider.ReaderLanguage` reads the language subtag of the innermost scope's culture, else `CurrentUICulture`. A language the distribution does not offer falls through to English. That is right for packs, but a reviewer should confirm it matches the negotiator's notion of "offered".
- The tokenizers are heuristics. The TypeScript regex-versus-division rule uses the previous significant character or keyword. It errs toward reading too many literals, which keeps keys alive and never fails a sound one.
- The emit now writes real packs. Distribution builds that go through `tellma-core-tools` will see non-empty packs, and the English pack must hold every `Boot_*` key (it does for Core). No client code changed, so the client gates were not run.
- The enum-value chain uses the schemas of every entity that carries the enum, in model order. An enum shared across schemas resolves to the first schema's key.

### What reviewers should examine hardest

- `LabelProvider`: the twin rules per shape (`MultilingualLabelsTests`), and the FK lookup for navigation labels.
- `StringPackComposer` conflict semantics: first source wins, one problem per key and pair, satellites never conflicting with neutral values.
- `ConventionalStringKeys`: every derived family should match a key the client or server really looks up. An over-broad family would hide orphans.
- `CoreResourceAuditTests.Pending`: each entry should be real future work, not a dead key.
- The C# raw and interpolated string scanner (`CSharpLiteralScanner`), especially `$$"""` holes.
