# PC-131: Tiles view, view toggle, tabs, column filters and the Filters popup

## Implementer notes

### What was built

Spec 0030 §2.3, §2.4, §3.2, §3.4, §8, §9 and §10 on the search host
(`client/projects/core/tellma-core/search/src/`).

- **Tiles** (`tm-search-tiles.ts`, `ɵTmSearchTiles`).
  - The host renders it in the grid's place while the view is tiles, in an `@defer (on immediate)`
    block with skeleton lines as its placeholder, so it is a lazy chunk of `/search`.
  - The layout maps the declaration's `tile` (or the undeclared default: the first image
    navigation, the display name, the first natural key not shown, and Active on an activatable
    entity) onto `tm-tiles`. The title is the display name, with its prefix and name parts. The
    top end is numeric for integer, decimal and float values. A boolean badge shows Active or
    Inactive for `IsActive`, and other booleans show their label when true.
  - Image thumbnails come through `TmUrls.blob(..., { variant: 'thumb' })` only when the blob
    policy has thumbnails and the row's variants include `thumb`.
  - A `{ component }` tile renders its component through `tmTileContent` with `value` (the id)
    and `row`.
  - The region's states render in the tiles' empty template. The field drives the tiles through
    the same `TmGridDriverTarget` it drives the grid with, and hover preloading reads a tile's
    `data-index`.
  - An undo anchor snapshots the tiles' scroll offset and restores it once the restore's rows
    land.
- **View toggle.** A `tm-segmented` (Grid `table-2`, Tiles `layout-grid`) after a separator at the
  toolbar's end. It writes `view` and the current width class's preference half through the
  existing `tmSearchUpdate` rule, re-renders the held rows with no request, and reports
  `tm.search.view-changed { view, list }`. `tm.search.query` timings and the page context now
  report the effective view.
- **Tabs.**
  - From `lg`: a segmented control after the title.
  - At `sm` and `md`: a menu button (`tm-search-tabs-menu.ts`, `ɵTmSearchTabsMenu`). All the
    labels are stacked in one grid cell, so the button is as wide as the widest. The button and
    its `tm-menu` are one `@defer (on immediate)` block over a stand-in of the control's height,
    so they are a lazy chunk of `/search`. The button registers itself as the menu's trigger,
    and ArrowDown and ArrowUp open the menu on its first or last row.
  - Below `sm`: a radio group in the Filters popup, counted by the Filters button when it is not
    the first tab.
  - Each change reports `filter-applied { kind: 'tab' }`.
- **Column filters.** Each filterable column's header carries a funnel button (`tmGridHeaderEnd`,
  `tmGridHeaderAction`) named by `tm.search.filterButton` and active while the column's filter
  applies or its panel is open. It opens a `tm-popover` (size sm) holding `tm-column-filter`.
  Apply closes the panel and returns focus to the button.
- **Filters popup** (`tm-search-filters-form.ts`, size md, end-aligned). Below `sm` both panels
  are end drawers (`TmModal`, placement end).
  - The sections are the tab (below `sm`), the filter expression (`tm-expression-editor`, clause
    filter; Mod+Enter applies), Active only, the custom filters, the applied column filters and an
    order on a hidden column as chips, and Add column filter, which opens a column's filter in
    place with Back.
  - The footer has Clear all and Apply. Edits are staged; Apply makes one `tmSearchUpdate`, so one
    URL write and one read on page 1, and reports `filter-applied` once per kind that changed. A
    dismissal destroys the body and discards what it staged.
  - Apply is disabled only when the draft's status is `checked` and the filter clause has
    problems.
  - The Filters button shows its label from `md`, keeps room for a two-digit count, and takes the
    error tone and an extended name while the held failure is the invalid filter's. Edit filter,
    in the invalid-filter and calculation states, opens the popup with the editor focused.
- **The panels are one lazy chunk** (`tm-search-filters.ts`, `ɵTmSearchFilterPanels`). The host
  loads it with `import()` on the first click of a filter button, creates it in a view container,
  and holds a `PendingTasks` task while it loads, so the app is not stable until the panel is
  there. The route therefore never carries `/column-filter` or `/expression-editor`.
  `tm-search-filters-host.ts` holds only the types the host and the chunk share.
- **`f.IsActive` on an activatable entity** is dropped by the canonical query as an invalid value,
  and that column has no filter button. Active only stands for it (`tmSearchFilterable`).
- **Strings.** New `tm.search.*` keys, in English and Arabic. Two select messages put their words
  around the select rather than inside it (`Filter {label}{active, select, …}`), which renders the
  same text as the spec's ICU and keeps the strings' argument-parity test meaningful.
- **Harnesses.** `TmSearchPageHarness` gained tiles, view, tabs, the Filters button, the column
  filter buttons and panels. The new `TmSearchFiltersHarness` is exported from
  `@tellma/core-testing`.
- **ARCHITECTURE.md.** The `@tellma/core` row now says that the tiles view and the filter panels
  are lazy chunks of `/search` with their own budgets.

### Deviations

1. **A `{ component }` tile selects the display name.** The model used to select nothing for a
   component tile. §2.3 does not say what it selects, but the tiles' checkbox and each tile's
   accessible name need the row's display name, so the select now carries its paths (`Code` and
   `Name` for customers).
2. **Options filters show an Any option first.** §10.1 item 4 asks for a radio group. A radio
   group cannot be cleared, so "Any" (`tm.search.any`) is its first option and stands for no
   value.
3. **The calculation state offers Edit filter but not Columns.** §5.3's table lists both. The column
   editor lands with the Columns work, which this checkpoint does not include.
4. **The tiles' first load uses `tm-tiles`' own skeleton** (its `loading` input) rather than a
   `tmTilesLoading` template. While the tiles' chunk loads, the placeholder shows skeleton lines.
5. **On return from a row, the tiles do not restore their offset.** §8 says the tiles apply the
   remembered offset on return and on an anchor restore. Only the anchor restore is done here. On
   return the highlight is the opened row, and the tiles start at the top. Remembering the offset
   across a navigation is left for the page-memory work.
6. **The `./search` route chunk is over budget.** Spec 0030 §1 gives the route chunk 16 KB of its
   own weight, and a product-owner ruling had already replaced that with 23.5. This checkpoint
   measures 26.41 KB after every cut, and the product owner ruled the budget raised (D-419). The
   ceiling is now 26.5. The figures and the savings are set out under Budgets below. This needs
   Ahmad's sign-off against the 16 KB.

### Budgets

All figures are gzip KB on the linked measure of a clean build (`rm -rf client/dist`, then
`npm run build` and `npm run size:check`).

| Budget line | Before | Measured | Ceiling | Spec |
| --- | --- | --- | --- | --- |
| `@tellma/core/search` (own weight, lazy chunks excluded) | 23.16 | 26.41 | 23.5 → **26.5** | 16 (replaced by 23.5) |
| `./search` › `tm-search-tiles` chunk (new) | – | 2.62 | 3 | 6 |
| `./search` › `tm-search-filters` chunk (new) | – | 5.51 | 6 | 6 |
| `./search` › `tm-search-tabs-menu` chunk (new) | – | 1.37 | 1.5 | 6 |
| `@tellma/locale-ar/queryex-strings` | 1.21 | 1.75 | 1.5 → **2** | none stated |

- **`./search`, raised from 23.5 to 26.5 (D-419, deviation 6).** The +3.25 KB is the host's own
  part of this checkpoint:
  - the view toggle and its separator;
  - the tabs' placement by width;
  - each column header's filter button, with its name and active tone;
  - the Filters button, with its count and invalid tone;
  - loading the filter panels, and the page object they read;
  - the effective view in the timings and the page context;
  - their strings, styles and glyphs.
- **Savings taken: 27.45 down to 26.41, −1.04 KB.**
  - The tiles view, the tabs' menu button with its menu, and the filter panels are each a lazy
    chunk on its own budget line.
  - The Filters popup's strings ship with their chunk under `tm.searchFilters`, and the tiles'
    badge strings under `tm.searchTiles`.
  - The panels derive what they read of the page from a small page object, rather than the host
    deriving it.
  - Both segmented controls (the tabs and the view toggle) are deferred, so the route reaches
    neither `@tellma/core-ui/segmented` nor `/form-field` statically. That also keeps the
    fixture's `searchRoute` under 110 KB.
  - No cut is left that keeps the header's controls in the first frame.
- **The three chunks.** Each is born at its measurement rounded up to the next 0.5 KB, under
  spec 0030 §1's 6 KB for a deferred chunk. Each has its part of the `./search` budget note.
- **`queryex-strings`, raised from 1.5 to 2 (D-031).** It carries the Arabic of the new strings:
  - the Filters button's name, with its Arabic plural forms;
  - the column filter button's name;
  - the view and tab labels, and Edit filter;
  - `tm.searchFilters` and `tm.searchTiles`.

  No spec states a figure for this part, so no deviation is flagged. The raise has a budget note.
