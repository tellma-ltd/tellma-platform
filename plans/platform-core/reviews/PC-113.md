# PC-113: TmRequestLog, TmAppVersion, Copy diagnostics text and platform measurements

## Implementer notes

### What was built

Spec 0026 §5, §7 and §8.1–§8.3 in the `@tellma/core` primary and three of its lazy chunks
(`client/projects/core/tellma-core/src/`).

- **`TmAppVersion`** (`requests/tm-app-version.ts`, primary). `ui`, `display`, `label`, `commit`,
  `platform`, `features` are getters over `TmClientMetadataStore.peek()` (empty before the Core
  chunk loads); `server` and `serverNewer` are signals; `compare(build)` is SemVer 2.0 precedence
  ignoring build metadata, `null` for the same version from another commit. `tmCompareBuilds`
  moved here from `api/tm-api-verdict.ts`; `tmBuildVerdict` now takes the order, and
  `TmHttpApi.#verdict` gets it from `TmAppVersion.compare`, so the order ships once.
- **`TmRequestLog`** (`requests/tm-request-log.ts`, primary). The quiet default is replaced by
  `TmAppRequestLog` (root `useFactory`): a signal ring of 100, newest first; `begin` adds a pending
  record and a 3 s timer that marks it slow; `end` (second call a no-op) records duration,
  outcome, status, code, keeps `slow` sticky, and hands `serverBuild` to `TmAppVersion.ɵserver`.
  Timers clear on the root `DestroyRef`. `diagnosticsText(count = 10)` and `copy(trigger =
  'button')` delegate to the lazily loaded diagnostics; `ɵstart()` memoises the `import()` and
  forgets a failed load so the next copy retries.
- **Copy diagnostics** (`requests/tm-diagnostics.ts`, lazy chunk `tm-diagnostics`, loaded at
  idle from `tmStartup`). `tmDiagnosticsInput(injector)` reads every source untracked;
  `tmDiagnosticsText(input, count)` is a pure formatter (English, Latin digits, device local time
  with the offset in the header, `tmStripBidiControls` over the result). `tmStartDiagnostics`
  registers the `tm.diagnostics` strings (`copy`, `copied`, `copyFailed`), the global shortcut
  `tm.support.copy-diagnostics` (`Mod+Alt+Shift+D`, `inFields`, `overModals`) and returns the
  copy: `navigator.clipboard.writeText` synchronously inside a try, then one toast (success 4 s,
  failure sticky, shared toast key) and, on success, `tm.support.diagnostics-copied { via }`.
  Arabic strings added to `@tellma/locale-ar/platform-strings` (`strings-tm-ar.ts`).
- **Page visits** (`observe/tm-page-visits.ts`, primary, started in `tmStartup` before the first
  navigation). One sampled `tm.page.visit` timing per routed page, ended at the next
  `NavigationStart` or `pagehide`: `ms` to the context's first status away from `loading`,
  `chromeMs` to `afterNextRender` + one rAF after the context registers, `visitS` in tenths,
  `entry` `load|navigation`, `outcome` `ready|error|left`.
- **Load metrics** (`observe/tm-load-metrics.ts`, lazy chunk `tm-load-metrics`, loaded at idle).
  Buffered `PerformanceObserver`s for `paint` and `largest-contentful-paint`; finalised once at
  the first `keydown`/`pointerdown` or `visibilitychange` to hidden (with `takeRecords`); emits
  sampled `tm.vitals.load` with only the metrics the browser exposes.
- **Request outcomes** (`requests/tm-request-measures.ts`, statically imported by the pipeline, so
  inside the `tm-telemetry-pipeline` chunk). The pipeline's host gains `requests()`; an effect in
  `tmStartTelemetry` calls `pipeline.measure()` on every change of the log; each `flush()` first
  records the window's `tm.api.requests` (20 busiest routes); slow requests become `tm.api.slow`
  as they settle (20 per tab per 10 min, the rest counted as `throttled` drops); `pipeline.pagehide()`
  records slow requests still pending before flushing. Both events are unsampled and go through the
  pipeline's reserved-property guard.
- **Docs.** `tellma-core/README.md` (entry-point table row, the HTTP layer's chunks, a platform
  measurements list, a new "The request log and Copy diagnostics" section, the Seams paragraph);
  `ARCHITECTURE.md` `@tellma/core` row (the new chunks and what stays in the primary).
- **Budgets** (`tellma-core/package.json`). Primary 50.17 → 51.6 (51,364 B before, 51.59 KB
  after, gzip 9 cap 51.49 of 55); `tm-telemetry-pipeline` 5 → 5.5 (4.50 → 5.31); new
  `tm-diagnostics` 2 (1.77) and `tm-load-metrics` 1 (0.81); `tm-api-verdict` lowered 1 → 0.5
  (0.51 → 0.17). Arabic `./platform-strings` 3.45 → 3.54 of 4, no raise.

### Deviations

1. Copy diagnostics (text, copy, toasts, shortcut, strings) is a lazy chunk loaded at idle after
   the first render, not primary code (§1, §8.3): saves 1.77 KB of the primary. Until it loads,
   `diagnosticsText()` is empty and `copy()` loads the chunk first, so that write runs outside the
   gesture and may be refused (then the failure toast says where to look).
2. `TmRequestLog.copy(trigger?)` takes what triggered it (`TmDiagnosticsTrigger`, default
   `button`) for the event's `via`; the spec's `copy()` has no parameter.
3. `TmAppVersion.commit` accepts 7–40 hex digits (lowercased) rather than exactly 40; `label`
   shows the first 7. Members are getters over the metadata store, empty before it loads.
4. The SemVer order moved from the `tm-api-verdict` chunk into `TmAppVersion.compare`;
   `tmBuildVerdict` takes the order instead of the two builds.
5. Request outcomes live in the telemetry pipeline's lazy chunk. `tm.api.requests` is per tenant
   and route (a batch carries one tenant); `api` is the route without its query; `failed` is an
   error the server answered (a status), `network` one with no status. A slow event's `at` is the
   request's settle time.
6. A slow request reported `pending` at `pagehide` is not reported again if the page comes back
   and it settles.
7. Page visits: a `left` visit's `ms` is how long it was waited for (the visit's length); a
   visit that registered no context (the launch page's redirect) is not reported and passes its
   start and entry to the next; a navigation that keeps its page (a reused route) adopts the kept
   context one render after the navigation ends.
8. Diagnostics text beyond the spec's example: a `Features` line when there are features,
   `Dialog` lines for overlays, `session <state>` when not active, `No tenant`/`Page none`/
   `No requests`, an `error` flag, and the error code after the status.
9. `controlled` in `tm.vitals.load` reads `navigator.serviceWorker.controller` when the event is
   built.

### Open risks

- The pipeline reads the log through an effect; more than 100 requests settling between two
  effect runs would lose the oldest from the summaries (not seen in practice; the ring is 100).
- Page visits run in every app rig, so a spec asserting an exact telemetry list may see
  `tm.page.visit` items; the core suite passed in full.
- Before the diagnostics chunk loads (the first idle), the shortcut is not registered.

### What reviewers should examine hardest

- `TmPageVisits` boundaries: the `kept`/`#settled` adoption for reused routes, the fold of
  context-less visits, and the first visit starting at the time origin.
- `TmRequestMeasures.collect`'s seen/reported bookkeeping against the ring, and the flush
  re-entrancy when the drained summaries push the queue to 50.
- The size decision: the primary rise of 1.43 KB (page visits 0.51 KB of it) and whether page
  visits should be lazier.
