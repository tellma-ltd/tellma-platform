### Deviations

1. **Primary ceiling 8, not 7.** The planner-mandated eval-free ICU interpreter costs ~1.4 KB gz
   in the primary (the old compiler sat in an external `@jsverse` package, outside the
   measurement); the B seams cost ~1.1 KB (spec estimate 1.5). Measured 7.04 KB after slimming.
   App bundles shrink overall (no `@messageformat/core` + plural data). Headroom for Part D's
   primary additions is ~0.96 KB — likely not enough (orchestrator decision).
2. **In-house interpreter rather than `intl-messageformat`.** Keeps the exact previous dialect
   (verified by the parity run), adds no dependency, and is ~1.4 KB where intl-messageformat with
   its parser would have counted ~8–10 KB against the primary.
3. **Interpreter behaviour changes vs the old engine:** a malformed message renders its raw text
   with a one-time dev warning instead of throwing; a missing argument renders `{name}`, not
   `undefined`; Transloco's `{{param}}` pre-pass is no longer applied (ICU only, so a parameter
   value is never re-parsed as syntax and the parse cache stays bounded); `{x, date|time, …}` and
   other non-number types render the raw value with a dev warning (calendar-unaware date
   formatting in messages would bypass `TM_CALENDAR`); plural categories of negative numbers follow
   CLDR via `Intl` (absolute value), where make-plural answered `other`; `currency:XXX` uses the
   currency's own fraction digits instead of always 2.
4. **Open-modal live direction pulled forward from §D.2.** Part B's own e2e ("flip dir with a
   modal open … right-to-left") cannot pass without `setDirection` on open modals; it is ~10
   lines in `TmModal.open`. PC-011 should verify rather than re-implement.
5. **`TM_BREAKPOINTS` is typed `Readonly<Record<'sm'|…|'xxl', number>>`,** not literal types: the
   value comes from the JSON, so literal types would be an unchecked cast.
6. **A `tm-select` editing a grid cell keeps the workspace default below `sm`,** extending "not
   the grid" to the grid's built-in enum editor (otherwise its option rows would jump to `lg`
   inside a grid row).
7. **Showcase `<html data-theme>` is now always present** (`light` by default); two smoke
   assertions that expected an absent attribute were updated.

### Findings

**R1-1 (minor): ICU arguments resolve inherited `Object.prototype` members.**
`client/projects/core/tellma-core-ui/i18n/tm-icu.ts:316` reads `params[node.name]`. For a
message such as `{constructor}` or `{toString}` with the parameter absent, the value is the
inherited function rather than `undefined`. The message then renders
`function Object() { [native code] }` instead of the documented `{name}` placeholder. Plural and
select reads go through the same lookup. A translator's or a server pack's argument name thus
leaks engine text into the UI.
Fix: `const value = Object.hasOwn(params, node.name) ? params[node.name] : undefined;`, plus one
vector in `tm-icu.spec.ts`.

**R1-2 (minor): `{x, date|time}` renders `String(value)` with no formatter seam.**
`client/projects/core/tellma-core-ui/i18n/tm-icu.ts:323-327` handles date and time arguments
like any other unsupported type.
- **What renders.** A `Date` comes out as the engine's verbose local string, e.g.
  "Sun Nov 08 2026 04:00:00 GMT-0800 (Pacific Standard Time)": English, and it exposes the
  device zone name. The old engine rendered "Nov 8, 2026".
- **No regression today.** No shipped en, ar or showcase message uses date or time (grep).
- **Why it still matters.** Spec 0013 §10.2's server strings use `{d, date, medium}`, and spec
  0024 §7.5's `TmServerText` formats such arguments client-side in the active locale, calendar
  and zone. `ɵtmFormatMessage` has no extension point for that, so whoever lands it must reopen
  the interpreter.

Fix: one of the following.
- Give `ɵtmFormatMessage` an optional argument formatter for non-number types now. The
  transpiler would pass `undefined` until 0024 wires `TmL10n`/`TM_CALENDAR`.
- Leave the code, and record an owner for date/time formatting on the checkpoint that builds
  `TmServerText`.

Either way, the interim fallback for a `Date` should be `toISOString()`, not `String()`.

### Responses

R1-1: fixed in 2161a0b. Argument, select and plural reads use
`Object.hasOwn(params, name)`, so `{constructor}` / `{toString}` render their placeholder and a
choice on an inherited name takes `other`. Vectors added to `tm-icu.spec.ts`.

R1-2: fixed in 2161a0b, per the orchestrator's ruling. New public seam
`TM_UI_ARGUMENT_FORMATTER` (`TmUiArgumentFormatter`, `TmUiArgumentType`,
`tmDefaultUiArgumentFormatter`) in `i18n/tm-ui-argument-formatter.ts`. Every `{x, number|date|time,
style}` argument and a plural's `#` go through it, from the Transloco transpiler and the static
English path alike. The default formats numbers with `Intl.NumberFormat` (moved from the
interpreter), and renders dates and times as ISO 8601 (`toISOString()` for a valid `Date`, the
raw value otherwise). Spec 0024's TmServerText provides the calendar-aware formatter by
overriding the token. The shared `Intl` cache and dev warning moved to the internal
`i18n/tm-intl.ts`. Tests cover the default (Date, text, invalid Date, number styles), the
interpreter's `format` argument (with call order and styles), and the token override through
`TM_UI_TRANSLATE`.
