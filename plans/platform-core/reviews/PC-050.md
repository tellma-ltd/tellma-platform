# PC-050: Connect prologue, caches, guarded runner and the Order-100 initializer

## Implementer notes

### What was built

The user connection of spec 0014 §6.2-§6.3, §7.1-§7.6, §7.8 and §13, with the runner cases of spec 0013 §2.10, §5.7 and §9.3.

- **Contracts** (`Tellma.Core.Abstractions/Access`):
  - `ConnectPremises`, a closed set: `ForSubject`, `ForUser` and `ForSystem`, plus the `Cold` and `For` factories.
  - The records `ConnectExpectations`, `ConnectResult`, `ConnectedUser` and `UserProfile`.
  - The interfaces `IUserConnector` and `IGuardedBatchRunner`.
  - New entries in `ReservedSqlNames` and `AccessTelemetryNames`.
  - `RequestContextInputs.SuppressActivityStamp`. The ASP.NET Core `RequestInputs.Of` sets it from `NoActivityStampMetadata` or a background request.
- **`ConnectPrologue`** (Core/Access) holds the three §7.3 texts:
  - Each text is built once, so every batch of a variant carries the same text and binds the same parameters with the same SQL types.
  - The settings cold load (§5.7) is absorbed under `IF @tm_SettingsStale = 1 OR @tm_LoadSettings = 1`.
  - The reader reads set 0, set 1 (the prelude), and then sets 2 and 3 and the settings sets only when the connect row announces them.
  - It reports the guard verdict, the tenant tags, and the caller's user tags.
- **Caches**:
  - `ConnectCache`: keyed by tenant and subject, compared byte for byte. It has its own bounded MemoryCache and single-flights cold connects. If a starter's connect is cancelled, a joiner runs a connect of its own.
  - `PermissionsCache` and `ProfileCache`: versioned-cache kinds keyed by `TenantUserCacheKey`.
- **`UserConnector`** (scoped):
  - Implements `IUserConnector` and the internal `IScopeConnection` the runner drives.
  - Supports connect by subject, by id (`ConnectAsUserAsync`) and as the system. Builds the premises for the next batch, applies prologue results, runs the cold re-connect, and drops a deactivated caller's entries.
  - Activity-stamp throttling uses an in-process memo against `ActivityStampInterval`. Frozen tenants and background requests never stamp; Frozen tenants never flip.
  - Metering and `ConnectRejected` logging happen in `Apply`.
- **`GuardedBatchRunner`** (scoped):
  - Each call composes, executes and applies.
  - It recomposes once after any one of: a failed guard, a `50412` (after a cold re-connect), or an executor `StaleContextException`.
  - A second failure is a `StaleContextException`: the result is counted as `guard_thrash`, exhaustion is metered, and `GuardThrash` (3102) is logged.
  - A `50401` drops the caller and throws `TenantNotFoundException`.
  - When a round trip brings newer settings, the initializers after Order 100 run again.
- **`ConnectInitializer`** (Order 100):
  - A system scope connects as the system and binds `UserId = 1`.
  - A user or service-account scope connects by id when the context carries one (background), else by subject.
  - An anonymous caller gets `TenantNotFoundException`.
  - `ConnectedUserPreferences` implements `IUserLocalePreferences` for the Order-200 negotiation.
- **DataBatch and DataExecutor**:
  - Statements begun with `BeginConnectPrologue` record their writes in `_connectWrites`. Those writes are excluded from `WrittenTables` and included in the new `AuditedWrites`, which the executor's audit now uses.
  - A batch in `Explicit` mode that carries such writes is refused.
  - `AttemptStarted` (set by the executor per attempt) times the prologue round trip.
- **Composition**: `AccessRuntimeComposition` registers the caches, `ConnectorServices`, the connector (one instance behind both interfaces), the runner, the initializer and the preferences.
- **Test hosts**:
  - `CatalogHost`, `TellmaTestHost` and `TenantContextHarness` remove the real `ConnectInitializer`, because they bind users through their own stand-ins.
  - `RequestContextHolderTests` admits the runner as the third context writer.
- **Tests**:
  - Unit, in `Tellma.Core.Tests/Access`:
    - `ConnectPrologueTests`: all 16 presence combinations of the reader, plus the texts and bindings.
    - `GuardedBatchRunnerTests`: fakes over `BatchScript`.
    - `ConnectCacheTests` and `ConnectInitializerTests`.
  - Integration, in `Tellma.Core.IntegrationTests/Access`:
    - `UserConnectionTests` over the new `ConnectDatabase`: two tenant databases in one composition, with no stand-in.
- READMEs are updated (Core, Core.Tests, Core.IntegrationTests). ARCHITECTURE.md needed no change: its tenant-state paragraph already says `ReadOnly` keeps the bookkeeping writes and `Frozen` writes nothing.

### Deviations

1. **`ConnectPremises.For` takes two more parameters.** `expectedSettingsTag` and `reloadPermissions` are needed because the premises carry the settings tag the batch composes under.
2. **`@tm_callerIds` is declared by the user variants.** The caller's id is inserted in the active branch, because `PersistChecks`' user-level bumps and the caller re-check source from it.
3. **The `ForUser` text resolves by id.** It omits the stamp and flip statements entirely rather than binding them to 0, and nulls `@tm_UserId` when no row matches, so that "no user" reads the same as an unknown subject.
4. **New input `RequestContextInputs.SuppressActivityStamp`.** It carries the "background request stamps nothing" rule from the ASP.NET Core front door to the connector.
5. **Connect writes are excluded from `WrittenTables`.** They are included in `AuditedWrites`, and an `Explicit` batch carrying them is refused: the stamp must stay autocommit, outside any caller transaction. The existing frame test was updated to match.
6. **User tags are reported only for the caller.** That means `ForSubject`, or `ForUser` of the scope's own user, so an `EvaluateFor` load of another user never overlays the caller's snapshot.
7. **An unbindable subject is refused without a round trip.** An unbindable subject is empty, longer than 255 characters, or not printable ASCII.
8. **`ConnectAsSystemAsync` makes a round trip only when the settings are missing.** It returns the synthetic system user when the expected settings tag is known. `ConnectAsUserAsync` always makes a round trip. The system profile is synthetic: `AccessSeeds.SystemUserName` and `SeededAt`.
9. **`Apply` never writes the request context.** The initializer returns the context with `UserId`, and only the runner's refresh writes through the holder. That makes `GuardedBatchRunner` a third holder writer, admitted in `RequestContextHolderTests`.
10. **The runner's settings refresh re-runs every initializer with `Order > 100`,** not just the locale negotiation, and only when the context's settings tag differs from the round trip's.
11. **A cached subject that now resolves to a different user than the one the scope is bound to is refused as `unknown_subject`.** The result is `TenantNotFoundException`.
12. **The permission-set witness is deferred to PC-052,** as its analysis assigns.

### Open risks

- **The `50412` and `50401` re-checks are not driven against a real database.** A tag would have to move between the autocommit prologue and the persist transaction's head inside one round trip, and no fixture can inject that. They are covered by the runner's unit tests with fakes and by the existing `PersistChecks` tests.
- **The flip-once test cannot reach the database race.** Single-flight in one process collapses the concurrent connects before they get there. The test proves a single history row across concurrent and later connects; cross-instance once-ness rests on the `AND [JoinedAt] IS NULL` predicate.
- **The ×1000 stamp test exercises the in-process throttle,** not the SQL 60-second predicate. That predicate is covered only by its text.
- **No test runs a `Frozen` tenant against a `READ_ONLY` database.** The Frozen test asserts that nothing is stamped or flipped.

### What reviewers should examine hardest

- **`UserConnector.Apply` (security-bound).**
  - The deactivated, unknown and mismatched-user refusals and what they drop.
  - The fallbacks when a result brings no rows or profile (the basis set, else a peek, else `InvalidOperationException`).
  - The `aged` flag on the permission set.
- **The prologue texts.**
  - The guard formula per variant.
  - Set 2 is never returned for an inactive user or the system.
  - The tags are read before the permission rows.
  - The stamp and flip predicates.
- **`GuardedBatchRunner`'s single recompose budget** shared across the three failure kinds, and the `Stale()` dependencies reported on thrash.
- **`ConnectCache.ConnectOnceAsync`'s flight removal and cancellation semantics.**
- **The `Explicit` refusal and the `AuditedWrites`/`WrittenTables` split** in `DataBatch`.
