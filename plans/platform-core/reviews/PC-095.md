### Deviations

1. **Classes run one at a time** (`[assembly: CollectionBehavior(DisableTestParallelization = true)]`).
   In parallel, a role or membership save moves the tenant's permissions tag. Any save in flight
   across that move is then answered `503 stale-context` (by design), and security writes queue on
   the tenant's security app lock (`lock_timeout` retries). The first parallel run failed five
   cases that way.
2. **The abort-and-commit case and the drain case run on Kestrel at a loopback port**, not on the
   in-process test server. When its client cancels, `TestServer` ends the request scope, and with
   it the scope's SQL connection. A persist that was already sent then dies, which a real server
   never does. Over Kestrel the persist commits, as spec 0016 §8.3 requires. Since review 1 the
   aborted-read case runs on Kestrel too (R1-3).
3. **ReadOnly tenant `export/start`** is checked with `users/me/locale`, an `AllowWhenReadOnly`
   action, because export lands with PC-175.
4. **"Version-Tags omits preferences/permissions after a batch without a connect prologue"** stays
   pinned by the unit suite. No projected reference route ends on such a batch. This suite pins
   that refusals before any batch carry no tags.
5. **Blob and hub chains, timeouts and output caching** are not duplicated here. The Acme
   integration suite pins them over the same composed host (`BlobTests`, `RealtimeHubTests`,
   `LimitsTests`).
6. **The round-trip alert compares the hour's worst unit with a ceiling, not p95 with the budget.**
   Application Insights' `customMetrics` keeps sums, counts, minimums and maximums of a histogram,
   not buckets. Review 1 replaced the hour's mean with the maximum (R1-5).
7. `Tellma.Core.AspNetCore` gains `InternalsVisibleTo` for the suite: the session ticket's
   `SessionProperties`, `TellmaClaimTypes` and `ApiMetrics` are internal.
8. **Every entity action shares one round-trip tag, `{resource}:action`** (added in review 1, as
   ruled). The budget test tells those operations apart by route, and the alert holds the shared
   `action` kind to one ceiling. Per-action tags are a platform change, left to the orchestrator.

### Open risks

- `web.json` and `contracts.json` will change when PC-F67 (OpenAPI schema depth) and PC-175
  (export actions) integrate. The integration step regenerates them with `TELLMA_UPDATE_GOLDENS=1`.
- **Round-trip tags are coarse for entity actions.** Every entity action records its unit of work
  as `{resource}:action`: activate, deactivate, invite, issue-credentials, and the `[ApiAction]`s
  that run through the pipeline's action path, such as `users/preferences/set`. The self-service
  actions record their own names (`core.User:me/save`). The budget test therefore tells operations
  apart by route, and the alert holds the shared `action` kind to a ceiling of 4. A per-action tag would
  sharpen both; that is a platform change, not made here.
- **Measured round trips (warm).** Every operation sits exactly at its spec 0018 §8.1 / 0015 §16.2
  budget, none below and none above:
  - centers: save 2, activate and deactivate 1, delete 2;
  - roles: every write 2;
  - users: save, invite, issue-credentials, preferences set and delete, activate and deactivate,
    and delete 2 each; `me/save` 3;
  - every read, `me/locale`, and `me/preferences` set and delete: 1.
- The suite runs on Windows LocalDB only in the nightly tier. I ran it locally on Testcontainers
  alone.

### Findings

**R1-1 (blocking): the `web.json` snapshot contains Windows line endings inside its description
strings, so the OpenAPI gate fails on the Linux PR tier.**
`distributions/acme/test/Tellma.Distro.Acme.Web.Tests/Snapshots/web.json` holds 151 escaped
`\r\n` sequences, for example at lines 12925, 12943 and 13059. The source files are LF
(`git ls-files --eol` gives `i/lf w/lf`). The CRLF comes from the build platform: the compiler
writes XML documentation with the platform newline, and the OpenAPI XML-comment generator copies
those newlines into `description`.

I reproduced this in the scratchpad with one LF source, a two-line `<summary>` and
`Microsoft.AspNetCore.OpenApi` 10.0.11:
- on Windows the description is `"...wrap\r\nonto a second line."`;
- in the `mcr.microsoft.com/dotnet/sdk:10.0` Linux container it is `"...wrap\nonto a second line."`.

`WireSnapshotTests.Normalized` (WireSnapshotTests.cs:131) normalizes only the JSON text's own line
breaks, not escaped newlines inside string values. So
`The_development_openapi_document_matches_its_snapshot` fails in ci.yml's `ubuntu-latest` unit job
(`Category!=Integration…` includes this test). Regenerating the snapshot after PC-F67 or PC-175 on
Windows brings the CRLF back.

Fix: canonicalize string values before comparing and writing. Parse the document into a
`JsonNode`, walk it, and apply `ReplaceLineEndings("\n")` to every string value. A
`written.Replace("\\r\\n", "\\n")` on the serialized text is the minimal alternative. Then
regenerate `web.json`. A short inline comment should say why.

**R1-2 (major): the round-trip budget test can attribute another request's measurement to the
operation under test, which is a silent false pass.** RoundTripBudgetTests.cs:155, 159, 176-187.
`AwaitAsync` returns the first measurement whose tag starts with `"{resource}:"` and discards the
rest of the snapshot. A measurement is recorded when the request's DI scope ends, after the client
already holds the answer.

Several requests are never awaited:
- `RootAsync` and the `RT-WARM` create (line 50);
- the `RT-SUB` create (line 63);
- the `doomed` save (line 107);
- the `account` save (line 110).

Their measurements stay in the collector. Take `users/delete`. The warming `users/me`'s
`AwaitAsync("core.User")` can return the stale `core.User:save` from the doomed save. If
`users/me`'s own measurement arrives after that snapshot, the measured `users/delete` gets
`core.User:me = 1` and passes whatever the delete costs. The same race can hand
`centers/delete-with-descendants` the `RT-SUB` save's 2, and `users/issue-credentials` the
account save's 2.

My detailed run attributed every tag correctly (for example `users/delete (core.User:delete): 2`),
so the race is latent, not observed. Even so, a regression in those operations can pass when it
hits.

Fix:
- pass the expected tag (`gl.Center:delete_with_descendants`, `core.User:delete`,
  `core.User:action`, …) to `MeasureAsync`;
- match it by equality, and fail when the first unit of work on the resource carries a different
  tag;
- make the warming read wait for `core.User:me` exactly.

Alternatively, route the four unmeasured setup calls through a helper that awaits their own
measurement.

**R1-3 (major): the aborted-read case would stay green if reads stopped honouring
`RequestAborted`.** CancellationTests.cs:28-44 and SqlLock.cs:20, 112-120.
- After the cancel, `AwaitNoWaiterAsync` allows 30 s (`Patience`) for the waiter to leave. The
  executor's `DataOptions.CommandTimeout` is also 30 s (DataOptions.cs:20), and it started earlier,
  when the read reached the lock. A read whose cancellation was broken would leave the lock at its
  command timeout, inside the patience window, unless a timeout retry re-queues it.
- By deviation 2's own account, a TestServer client cancel ends the request scope and its SQL
  connection, which takes the statement off the server whatever the executor does with the token.

Either effect alone means the case does not pin spec 0016 §8.3's "reads are cancelled".

Fix:
- run the aborted read on the same Kestrel instance as the save case, where only `RequestAborted`
  can end it;
- bound the disappearance well below the command timeout: a `within` parameter on
  `AwaitNoWaiterAsync`, around 5 s, asserted from the cancel;
- optionally assert that the read's statement is gone while the lock is still held.

**R1-4 (major): rows of the spec 0018 §8.1 budget table that are projected on this host are not
measured.** RoundTripBudgetTests.cs:42-123. The spec says "The integration suite asserts each row".
These routes are projected (`contracts.json`) but never measured:
- `access/check`: 0 for self, 2 for another user;
- `access/holders`: 1;
- `notification-preferences/get`: 1;
- `notification-preferences/save`: 2.

`ProjectedRouteTests` cannot catch the gap, because it filters to the five stack resources and
these are `[ApiRoute]` services. The done-when ("tellma.data.roundtrips per operation at or under
0015's budget") is therefore unproven for four 0018 operations.

Fix: add the five measurements. A zero-trip `access/check` self needs `AwaitAsync` to accept a
0-valued unit of work; the recorder records zero. Either add the service routes to
`ProjectedRouteTests`' driven set, or state in the class summary that it covers stack routes only.

**R1-5 (minor): the round-trip alert silently leaves out every operation whose kind is not in its
table, and budgets saves at their ceiling.** infra/monitoring/api/roundtrip-budget.kql:15, 27-28.
The measured tags show the platform emits these kinds:
- `invitation-status`, `preferences/get`, `me`, `me/save`, `me/locale`, `me/preferences/set` and
  `me/preferences/delete`;
- presumably the service routes' own kinds as well.

`lookup kind=inner` drops all of them, including `users/me`, the most-called route, so the
alert does not cover "any operation" (spec 0016 §10.2). `save` is budgeted at 4, the dependent-round
ceiling. Combined with an hourly mean (deviation 6), a 2-trip save drifting to 3 never alerts.

Fix:
- use `lookup kind=leftouter` with a default budget, or list the self-service and service kinds
  explicitly;
- consider budgeting `save` at its common 2 plus a cold-path margin (for example 2.5 on the mean),
  or alert on `worst` above the ceiling beside the mean;
- record the choice in the README.

**R1-6 (minor): two of the four version tags are checked for presence only.**
HeaderTests.cs:33-51. The case asserts the header's `preferences` and `permissions` items against the
envelope. `settings` and `entities` are only required to exist, so a filter writing a stale or
wrong settings or entities tag passes, although the class summary says the tags agree with the
envelope.

Fix: compare `settings` and `entities` with what the tenant serves, for example the
`settings/client` or `settings/entity-tags` answers in the same case. At minimum, assert that a
center save moves `entities` in its own response header.

**R1-7 (minor): the harness move was exercised against four of the Acme integration suite's
classes.** Every class of `Tellma.Distro.Acme.IntegrationTests` now runs on the moved
`AcmeMigrator`/`AcmeHost`, with the assembly fixture re-registered in
`Infrastructure/SqlServerAssemblyFixture.cs`:
- the commit ran `LimitsTests|SelfServiceTests|TenantStateTests|WebHostTests`;
- `MigratorTests`, `ProvisioningTests`, `SampleDataTests`, `BlobTests`, `RealtimeHubTests` and
  `UserIdentityTests` were not run, and the pc CI run was skipped.

Fix: run at least `MigratorTests|ProvisioningTests|SampleDataTests` locally, the classes that
drive the migrator path the move touched, or record explicitly that CI on pc/PC-095 is the
evidence.

**R1-8 (minor): two log events of spec 0016 §10.1 that this host emits on paths the suite already
drives are not asserted.** Surface/ObservabilityTests.cs.
- `ApiRequestRejected(reason)`: the case already sends a 412, and the 429 is in `DrainTests`.
- `ApiChildSurfacesProjected(surfaces)`: logged at the deployment host's startup, which
  `deployment.Logs` captures.

Spec 0016 §14 asks for every instrument and log event of §10.1 to be asserted by the integration
suites. Only `ApiProblem` is. The `rate_limited` reason of `tellma.api.requests.rejected` is not
observed either.

Fix: assert both events from `deployment.Logs` in the existing cases (`Reason = client_outdated`,
and a `Surfaces` value naming `role-memberships`/`permissions`). `ApiUnhandledException` and
`ApiSecurableAuditFailed` can stay with the unit suite, which needs a 500 path and a failing
composition, and that should be stated in the README.
