# PC-194: tm-chart core-ui entry point (ECharts facade)

## Implementer notes

### What was built

`@tellma/core-ui/chart` (`client/projects/core/tellma-core-ui/chart/`), spec 0034 §1 (chart row),
§7.1–§7.8 and §14.

- **Public surface.**
  - `TmChart` (`tm-chart`): inputs `spec`, `asTable` (model), `gridId`, `activatable`; output
    `pointActivate`.
  - `TmChartSpec` and its parts (`tm-chart-types.ts`).
  - `TM_CHART_SPEC_SCHEMA` and `tmValidateChartSpec` (`tm-chart-schema.ts`). A golden
    (`tm-chart-spec.schema.json`) is generated from the schema and compared in the schema spec.
  - `TM_CHART_STRINGS_EN`, registered beside the core table through `ɵtmRegisterUiStrings`.
    `@tellma/locale-ar` translates it under `chart`.
- **Four views.**
  - **No data**: the projected content.
  - **Card**: one value and its label, and a badge for the reached threshold. It is a `button`
    when activatable.
  - **Table**: a `tm-grid`, with one column per dimension and a value column, and row activation
    when activatable. It shows when `asTable` is set, when the type cannot be drawn, or when the
    engine fails to load or render.
  - **Plot**: a `<figure dir="ltr">` around a `div role="img"`, whose name is "title, type" and
    whose description is the ICU point summary.
- **Engine boundary.**
  - `internal/chart-engine.ts` is the only module that imports ECharts values. A lint block
    enforces this in `eslint.config.mjs`.
  - The component loads the engine with `import()` on its first plot. A card, a table or no data
    never downloads it. The e2e "the engine" test checks this.
  - `internal/chart-option.ts` is a pure option builder (ECharts types only).
  - `internal/chart-theme.ts` reads the `--chart-*` tokens and normalizes each colour through a
    1×1 canvas readback.
  - `internal/chart-text.ts` adds the canvas-text LRM/RLM marks.
- **The four canvas-text guards (§7.5).**
  - The canvas renderer only.
  - `tooltip.renderMode: 'richText'`.
  - `aria.label.enabled: false`. Decals stay on.
  - Clicks resolve by `seriesIndex`/`dataIndex`. Series, categories and slices are named by
    private ids, so no label text is ever used as a key.
- **Tokens.** A `chart` group in the default preset holds:
  - `series1-8`, `sequential1-7` and the diverging poles;
  - the grid, axis and label inks;
  - the positive, warning and negative tones;
  - the surface, tooltip, decal, font size and height;
  - the card metrics.

  `tokens.spec.ts` validates the palette in both schemes and in every preset:
  - opaque, chroma ≥ 0.1;
  - adjacent normal-vision ΔE ≥ 15, protan/deutan ΔE ≥ 8;
  - series and tones ≥ 3:1 against the card surface.

  The identity server's `tokens.css` copy is regenerated.
- **Size gate.** `scripts/bundle-size.mjs` and `tools/bundle-measure.mjs` gain
  `"tellma".lazyChunkBudgetsInKb`:
  - A lazy chunk is found as `<entry>-<module>-<hash>.mjs`.
  - It is kept out of its entry's measure, then measured alone, with ECharts bundled in and the
    entry point external. "The entry point" here is the FESM plus every chunk the FESM imports
    statically, because the build splits out the code the entry and the engine share.
  - A budget naming an unknown entry point or chunk fails.
- **Testing and showcase.**
  - `TmChartHarness` in `@tellma/core-ui/testing`.
  - Showcase stories `chart` (the gallery), `chart-bidi` (the canvas-text battery) and
    `chart-lazy`.
  - Usage examples in `chart/tm-chart.examples.ts`, compiled by `docs-examples.spec.ts`.
- **ECharts 6.1.0.** Added to the pnpm catalog and to `@tellma/core-ui`'s dependencies and
  `allowedNonPeerDependencies`.

### Deviations

1. **A Trusted Types shim, against §7.5's claim that ECharts makes no policy-relevant assignment.**
   - zrender's canvas painter runs `root.innerHTML = ''` in its constructor and in `dispose()`.
   - Under the host's Trusted Types CSP that throws.
   - The engine defines an own `innerHTML` accessor on the chart's root element only: `''`
     becomes `replaceChildren()`, and any other value goes to the native setter, where Trusted
     Types still refuses it.
   - `tm-chart.csp.spec.ts` fails without the shim and passes with it.
   - ARCHITECTURE.md now says this.
2. **Engine chunk budget is 200 KB, not 170.**
   - Spec 0024 §12 sets 170 KB.
   - The chunk measures 199.74 KB gz (level 9), with the entry point and the code it shares
     external.
   - ECharts 6.1.0 alone, with the modules the chart draws, weighs 194.38 KB under the same
     minify and gzip. That set is bar, line and pie; grid, tooltip, legend, markLine and aria;
     and the canvas renderer.
   - Core plus the canvas renderer plus one chart type alone is 122.03 KB.
   - Dropping any one module saves 1.1–16.9 KB, and each module is a feature the chart draws.
     The adapter is the remaining 5.4 KB.
   - Measurements: `.tmp/pc194-echarts-weight.log`. The note is in `package.json` `budgetNotes`.
   - The `./chart` entry is 6.56 KB, so its ceiling is 6.6, under the spec's 9.
3. **Extra chart tokens** beyond the series and ramps:
   - `positive`/`warning`/`negative`;
   - `surface`, `tooltipBg`, `tooltipBorder`, `decal`;
   - `fontSize`, `height`, and the `card*` metrics.

   The canvas cannot read `var()`, so every colour the engine paints is a token the theme bridge
   resolves.
4. **The holder div carries `role="img"`, not the canvas.** ECharts owns the canvas and recreates
   it on init, so the accessible name and description live on the stable holder. The figure is
   `dir="ltr"` so the plot never mirrors, and a class gives the canvas the page direction for its
   text.
5. **The canvas-text marks are refined for Arabic-Indic signs.** Inside an LTR run that holds
   Arabic-Indic digits, a sign gets an LRM on each side. The bidi algorithm treats a sign beside Arabic-Indic digits
   by their AN class, not the run's LTR embedding. Without the marks, the sign drifts to the other
   side of the number in a right-to-left base. The `chart-bidi` cases `negative-arabic` and
   `percent-arabic` compare this pixel for pixel.
6. **A local `TmChartJsonSchema` type.** `@tellma/core-ui` cannot import `@tellma/core`'s JSON
   Schema type.
7. **One `point` template serves both** tooltip lines and pie labels ("{label}: {value}"), and
   `share` serves percent labels. They are the same sentence, so I used one key rather than two.
8. **The diverging palette applies to a single non-pie series only.** It colours by sign. With
   several series or a pie it falls back to categorical, because sign colour would collide with
   series identity.
9. **Percent ticks** for percent measures and for normalized stacks. A normalized stack plots
   shares of the absolute total.
10. **The table view stands in when a plot can't be drawn**: for an unknown type, or when the
    engine fails to load or render. Render errors are also written to `console.error`.
11. **Pies drop slices whose value is ≤ 0.** The table still lists them.
12. **Lines take no decals; an area's fill does.** Line identity comes from symbols and dashes
    (8 symbols, with the dash per cycle). Where decals do not apply, the style carries no `decal`
    key. ECharts 6.1.0 types allow `decal: 'none'`, but its style visual assigns `.dirty` to the
    value, which throws on a string. That bug sent every single-series column or bar to the table
    until the render-matrix unit test caught it.
13. **`ɵtmCanvasText` / `ɵTmCanvasPiece` are exported** (ɵ-prefixed) so the showcase's bidi
    battery draws exactly what the engine receives.
14. **The table view imports `@tellma/core-ui/grid` statically.** It is a sibling entry point the
    app usually already has, and the table is the accessible fallback that must not wait on a
    chunk.
15. **'chart' is classified in `OLDER_FOLDERS`** in `additions-axe.spec.ts`, as pivot was.
16. **The visual check uses pixel-colour assertions** per type and theme, not screenshot goldens:
    - a token colour must paint more than 40 px;
    - the first column must not move in RTL;
    - the canvas computed direction is checked.
17. **`chart-lazy` story added** for the engine-loading test.
18. **The size gate's lazy-chunk extension** (`lazyChunkBudgetsInKb`) is new tooling that no spec
    names. Spec 0024 §12 budgets the engine chunk at the app level; this gate holds it per package.

### Tests

- **Unit (vitest browser, Chromium).**
  - `chart/` specs, 61 tests:
    - canvas text;
    - option builder (palettes, decals, legends, thresholds, stacks, locale ticks);
    - schema;
    - the component's views, table grid id, no data, and no bidi marks in DOM text;
    - a render matrix that draws every type with one and two series, and each palette, stack,
      legend side and threshold, through the real engine. It fails on any fallback to the table
      or any `console.error`.
  - `tm-chart.csp.spec.ts` under Trusted Types.
  - `tokens.spec.ts`: chart emit and palette validation.
  - `locale-ar.spec.ts`: the chart table is covered.
  - `docs-examples.spec.ts`: five chart examples.
- **E2e (PR tier).** `e2e/specs/chart.spec.ts`:
  - axe on plot, card and table in light and dark × LTR and RTL;
  - the plot's name and description;
  - token colours per type and theme;
  - the theme switch, no mirroring, canvas direction;
  - drilling from a slice (Mod opens a new tab), a table row and the card;
  - no bidi characters in DOM text and attributes;
  - the clipboard (Chromium);
  - lazy engine loading.
- **Nightly (`@cross-engine`).** `e2e/specs/chart-bidi.spec.ts`:
  - "together" equals "apart" pixel for pixel in both directions;
  - "plain" differs for `name-code` and `negative-arabic` in RTL, which proves the marks matter.
    In RTL, `code-name` ("1100 - Cash") resolves the same with or without marks, so it
    cannot show this.
  - Both also run on Chromium in the PR tier and pass.

### Open risks

- **Pixel equality in `chart-bidi`** may need tolerance on Firefox or WebKit if kerning across a
  mark differs from drawing runs apart. It ran on Chromium only here.
- **The Trusted Types shim** depends on zrender writing `innerHTML` to the element passed to
  `init`. A zrender upgrade that writes elsewhere would surface as a CSP spec failure, not
  silently.
- **The 200 KB engine ceiling** leaves 0.26 KB headroom. Any ECharts upgrade will need a
  re-measure.

### What reviewers should examine hardest

- `internal/chart-engine.ts`:
  - the TT shim's scope and its restoration on dispose;
  - font readiness before the first draw (zrender caches widths per font);
  - pointer handling (middle-button auxclick, Mod).
- `internal/chart-option.ts`:
  - decal and palette assignment;
  - legend layout in RTL;
  - normalized stacks with negative values;
  - the threshold markLine axis widening.
- `internal/chart-text.ts`: the mark rules, especially the Arabic-Indic sign refinement.
- `scripts/bundle-size.mjs`: the static-closure walk that keeps the shared chunk external.
