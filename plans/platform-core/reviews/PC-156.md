### Open risks

- The assignments document is still unregistered (PC-207), so the tray shows skeletons until a copy
  exists, and the footer link is hidden while the server routes no `core.Assignment`.
- The dump section registers when the panels' chunk loads (at idle after the first frame), not with the
  eager model; a dump taken before that idle moment has no `attention` section.

### Examine hardest

- The `TmPopover` change (`tellma-core-ui/popover/tm-popover.ts`): `modalsBelow` is captured when the
  popover opens; any modal opened later is "above". Check nested popovers and a popover opened from

  action `attention.stop-job` is declared destructive with a confirm, so the dispatcher always asks;
  the panel calls the model directly rather than invoking its own page action (spec 0026 §9.5).
- The bell's arrival hold (`#shown`/`#atTop`) and the focus recovery when a focused row is withdrawn.
- The size split: what stays eager in `/attention` versus the panels' chunk, and the new ceilings.

**R1-3 (major). A verb that removes its own focused control drops focus to `body`. From lg up,
that closes the bell's popover. When the last row of a list leaves, focus never reaches the
heading.**
- *Where.* `attention/src/tm-bell-panel.ts:177-179` ("Mark all as read" renders only while
  `unread > 0`), `:218-230` (Stop renders only until `cancelRequestedAt`), `:187`/`:248-261` (the
  jobs `ul` and the notifications `ul` are replaced when they empty), and
  `attention/src/tm-tray-panel.ts:56-58`. `attention-rows/src/tm-roving-rows.ts:132-144` recovers
  focus only while the `ul` still exists. `tellma-core-ui/popover/tm-popover.ts:498-509`,
  `:519-530` closes when focus lands on `body`.
- *Failure scenario.* At lg, the user clicks "Mark all as read". The read-all overlay sets
  `unread` to 0 in the same frame, so the focused button is removed. Chromium fires `focusout`
  with no `relatedTarget` (probe above), `onPanelFocusOut`'s microtask finds `body` active, and
  the popover closes. The panel the user was working in vanishes, and focus is on `body`, not the
  bell. The same happens on Stop of any job that is not `commitsInSteps` (an export): the stop
  overlay removes the focused Stop button. Only the confirmed path refocuses the row first
  (`:691`). It also happens when Delete or Clear removes the last notification row, or a
  withdrawal does, while the list switches to the empty state. The roving directive is destroyed
  with the `ul` and never focuses `fallback`, against §6.2's "else the heading". Below lg the
  drawer stays open, but focus is still lost. No test clicks Mark all as read, stops an export by
  keyboard, or empties a list.
- *Fix.*
  - Move focus before a verb removes its own control: Mark all as read → the More options button;
    Stop → the row's title link, as the confirmed path already does.
  - Keep each list's `ul` rendered while empty, with the empty state beside it, so the roving
    directive can focus `fallback`. Alternatively, have the panels move focus to their heading
    when a list empties while it held focus.
  - Add harness cases for each path: the panel stays open with focus on the next control.

**R1-4 (major). The tray marks nothing "New" for a user whose `seenAt` is null, though the badge
says some are new.**
- *Where.* `attention-rows/src/tm-assignment-list.ts:416-425` (`seenAt !== null` is required),
  `attention/src/tm-tray-panel.ts:104` (passes `seenAt ?? null`) and `:235`, the page-context
  state, where `> NaN` is always false.
- *Failure scenario.* Spec 0028 §4.2 counts a row as new when it was assigned "after

  opened with has no `seenAt`, and captures `seenAt` from the first copy it sees when it opened on
  skeletons. Pin both cases in `tm-assignment-list.spec.ts` and in the tray's harness test.
