# PC-080: Endpoint projection, binding, endpoint metadata, contract middleware, audit rules

## Implementer notes

### What was built

Spec 0016 §1.2 (projection), §2.1-§2.4, §3.7-§3.8, §4.2-§4.6, §5.1, §5.2, §5.4, §6.1
(`Tellma-Confirm`) and §8.1 (`MaxEntitiesPerSave`), in `src/core/Tellma.Core.AspNetCore`. Before
this checkpoint the web group carried probes only; nothing mapped the route model.

- **Projection** (`Api/WebApiProjection.cs`). `MapTellma` calls `WebApiProjection.Map` before the
  SPA and the audit. It walks `IRouteContracts.Routes` (and nothing else) and maps one `POST` per
  route on the `Web` group. It returns no problems and maps nothing when the stack registry is
  missing or failed (the registry's own check reports that) or when the route model throws (one
  `host.endpoint-audit` problem). Each route's owner (stack, child query surface or routed service)
  is found by reference from the registry, and its delegate is a closed generic method:
  - standard operations: `Api/StandardEndpoints.cs` (query, get, get-by-ids, all, save, delete,
    delete-by-query) and `Api/TreeEndpoints.cs` (get-by-parent-ids, delete-with-descendants);
  - entity actions: `Api/EntityActionEndpoints.cs`, one instance per action, chosen by
    (entities result, `SingleTarget`, arguments): `EntityActionRequest(<T>)`, `IdsRequest(<T>)`,
    `IdRequest(<T>)`. Activate and deactivate go through `ExecuteActionAsync` like any action;
  - API actions: `Api/ApiActionEndpoint.cs`, through `IApiActionInvoker`, with or without a body;
  - child query surfaces: `Api/ChildQueryEndpoint.cs`, through `IChildQueryService`.
  The delegate's `[FromBody]` type is checked against `RouteContract.RequestType`; a mismatch is a
  startup problem, so the projection cannot silently drift from the Contracts chunk.
- **Endpoint metadata.** `TenantEndpointMetadata(Web, IsMutation, AllowWhenReadOnly)`, the one grant
  (`RequireSecurable` or `AllowMember`), `ContractMetadata(fingerprint)`, `ProjectedRouteMetadata`
  (route, kind, segment; tests and the audit read it), `NoActivityStampMetadata` on the six polling
  routes of §4.3, `RequireAssuranceMetadata` from `StepUpBar` when the securable is sensitive,
  `ProducesProblem` for the nine statuses, `Produces` for the answer (204 void, 202 `JobAccepted`
  through `ActionAnswers`, the xlsx type for `ExportOutcome`), and `tellma-long` on a long route.
  Every tenant group now carries `DisableCookieRedirect()` (the API-endpoint marker); the `Web`
  group's finally-convention stamps `JsonBodySizeMetadata` (8 MB, `Tellma:Api:MaxJsonBodyBytes`)
  unless the endpoint states a size or accepts binary.
- **Binding** (`Api/WireBinding.cs`, `WireIds` from Abstractions). Ids narrow to the key type with
  `400 bad-request` naming the path (`ids[1]`, `id`). `SettledAsync` re-applies the request's
  cultures after the call, also when it throws. A save above
  `min(Tellma:Api:MaxEntitiesPerSave, Limits.MaxSaveCount)` throws `LimitExceededException`
  (`413 limit-exceeded`, limit `entities`) before the service runs; a web save is
  `SaveSource.Web`.
- **Filters.** Group order: tenant access → `WebRequestFilter` (Web only: `Tellma-Confirm`, at most
  16 keys of 1-100 visible ASCII, else 400; seeds `Confirmations` once; applies cultures) →
  `AccessWitnessFilter` (Web, Api, Blobs: a 2xx without a recorded evaluation becomes
  `500 internal`, logged and counted). No filter evaluates a securable.
- **Contract middleware** (`Api/TellmaContractMiddleware.cs`, `UseTellma` step 14, after CSRF and
  before the tenant middleware). A `Tellma-Contract` header that differs from the endpoint's
  `ContractMetadata` answers `412 client-outdated` before the body is read or the tenant
  resolved; an absent header passes. Always installed; a no-op on endpoints without the metadata.
- **`Cache-Control: no-store`** on every Web/Api/Mcp answer that states no caching of its own,
  refusals included (`Api/TenantJson.cs`, set in the header stamp's `OnStarting`).
- **HTTP JSON options** follow `TellmaJson.Configure` (`ConfigureHttpJsonOptions` in `AddTellma`).
- **Problems.** `BadRequestException` → 400 and `LimitExceededException` → 413 are mapped in
  `TellmaProblemExceptionHandler` now, because the projection raises them; titles added for
  `limit-exceeded` and `client-outdated`. The full mapping stays with the later checkpoint.
- **Audit** (`Routing/TellmaEndpointAudit.cs`, `Routing/ApiContractsAudit.cs`):
  - every Web/Api/Hub/Blobs endpoint carries the API-endpoint marker and no `AllowCookieRedirect`,
    `DisableAntiforgery`, `DisableRateLimiting` or `DisableRequestTimeout`;
  - two tenant endpoints on one method and route fail startup;
  - a child query surface's segment taking a reserved SPA/platform word fails startup (stack
    segments were already audited; descriptor-level uniqueness of stack, child, route and action
    segments is the registry's existing check);
  - realised gate only: every entity, child, request and result type the web surface reads or
    writes resolves a `JsonTypeInfo` under the host's HTTP JSON options (walked transitively), and
    an editable or write-once mapped property marked `[JsonIgnore]` fails;
  - `ApiChildSurfacesProjected` is logged once at Information when child surfaces exist.

Tests: `test/core/Tellma.Core.AspNetCore.Tests/Api/` (new: `WebApiProjectionTests`,
`ProjectionModel`, `RecordingPipeline`, plus a `Resources/Strings.resx` for the model's
confirmation messages) and five new violation rows in `Routing/EndpointAuditTests`.
`TellmaTestHost` gained `Compose`, and its connect initializer records the member witness as the
real one does.

### Deviations

1. Spec 0016 §3.1 says a mapped `[JsonIgnore]` property that is not `[ServerOwned]` fails the
   realised gate. The gate fails only editable and write-once properties; `Derived` and
   `DatabaseOwned` properties pass too. They are never read from the wire either, so ignoring them
   in JSON loses nothing; failing them would forbid a legitimate "never on the wire" computed
   column. Spec §3.1 should say "that a save writes".
2. Spec 0016 §4.6 says no tenant-group endpoint carries `DisableRequestTimeout`. SignalR's `MapHub`
   stamps it on the hub's connection endpoint, and a hub connection is long-lived by design, so a
   SignalR hub endpoint on the `Hub` group is exempt from that one rule. Every other rule still
   applies to it.

### Rulings (not obvious from the spec)

- The witness filter runs on Web, Api and Blobs (every guarded group), not on Web alone; the Hub is
  witnessed by its front door's member check.
- A void `[ApiAction]` answers 204; `JobAccepted` answers 202; `ExportOutcome` streams the file.
- A routed service's OpenAPI resource tag is its route.
- `Tellma-Confirm` keys are capped at 100 characters, per the §6.1 header table.
- Cache-Control is set only when absent, so an endpoint (or a later output-cache policy) that states
  its own caching keeps it.

### Open risks

- `tellma-long` is stamped with `WithRequestTimeout`, but no policy of that name is registered
  until the rate/timeout checkpoint lands; until then the metadata is inert. If the timeout
  middleware is installed before the policy exists, requests to long routes throw.
- The witness on the Blobs group: blob endpoints that land later must evaluate through the access
  evaluator or record the member witness, or every success turns into a 500.
- `JsonBodySizeMetadata` skips endpoints with `AcceptsBinaryMetadata` or their own size limit; a
  blob upload that forgets both gets the 8 MB JSON ceiling.
- The exception handler maps only the two exceptions the projection raises; any other
  `TellmaException` from a service still answers 500 until the full mapping lands.

### What reviewers should examine hardest

- `WebApiProjection.Map`'s method selection (the `(entities, SingleTarget, ArgumentsType)` switch
  and the body-type check) against `RouteContracts`' `RequestOf`: a mismatch fails startup, but a
  shape no test exercises would only be caught at startup in a distribution.
- `TellmaEndpointRouteBuilderExtensions.TenantGroup`: the filter order (tenant → web → witness) and
  the finally-convention order (complete, body size, wrap), since the audit's "delegate the guard
  wraps" rule depends on `Wrap` running last.
- `ApiContractsAudit.Resolve`'s transitive walk (cycles, generic parameters, `object`,
  `ExportOutcome`) and which exceptions it treats as "no contract".
- `TellmaContractMiddleware` placement: it must refuse before any body is read or tenant resolved,
  and the 412 must still carry `no-store` and the trace headers.
