### The first-frame guarantee

`tm-icon` draws in a component `effect`, which Angular runs inside the change-detection pass that
creates the component. Two tests pin it:

- unit: one `fixture.detectChanges()` and the `<svg>` with all its paths is there, no awaiting;
- e2e: an init script's `MutationObserver` checks every inserted `tm-icon` when the insertion is
  observed (the end of the task that inserted it) and again in the next `requestAnimationFrame`
  callback (before that frame paints), on page load and for twenty rows inserted by a click.

### Deviations (also in the commit message)

1. `TmIconNode`'s attribute values admit `undefined`, and an element may carry a third member with
   nested children. Lucide's own `IconNode` types values as `string | number | undefined`, so the
   spec's `string | number` would reject `icons: { 'hand-coins': HandCoins }`, and `@lucide/icons`
   v1 types its nodes with optional children, so its objects would not fit the object form either
   (the spec says both must). Undefined values are not drawn; children are drawn recursively and
   validated like their parents.
2. The guard is stricter than the spec: besides the three refused attribute prefixes, only the SVG
   shape and group elements are accepted (an `<animate>`/`<set>` can write a link onto its parent,
   and `<script>`, `<use>`, `<image>`, `<foreignObject>`, `<style>` load or run things), attribute
   names must be ones `setAttribute` accepts (so drawing can never throw mid change detection), and
   names must be kebab-case. Every Lucide glyph passes. Direct `[svg]` data goes through the same
   guard; refused data is reported to the `ErrorHandler` and draws an empty box.
3. The `key` attribute of `@lucide/icons` data (a framework list key) is accepted and not drawn.
4. Mirroring keys on CSS `:dir(rtl)` (the element's HTML directionality, live, no script) rather
   than on a script read of `getComputedStyle().direction`. Every direction in the platform comes
   from `dir` attributes, so the two agree, and `:dir()` also flips in place on a live switch and
   honours a nearer `dir="ltr"` island, which a one-off read at render time would not. A page that
   sets `direction: rtl` in CSS alone, without a `dir` attribute, would not mirror.
5. `tmKeysMatch` and `tmAriaKeyShortcuts` take the same optional `apple` parameter as
   `tmFormatKeys`/`tmKeysText` (default `tmIsApplePlatform()`), and `TmKbd` has an optional `apple`
   input (unset: the current platform). The story shows both platforms' labels, and tests pin both
   platforms without stubbing `navigator`.
6. Budgets: `./icon` 3 (spec 2, measured 2.74) and `./kbd` 2.5 (spec 1, measured 2.22, 2.37 after review 1), each with a
   `budgetNotes` entry. The spec's figures were estimates below the real logic: the registry, the
   guard and the draw path for icon; the parser, the matcher and the label writers (about 1.5) plus
   `tm-kbd` itself (about 0.75) for kbd. The duplicated decorator metadata in the measured FESM costs
   only about 0.1 of each (corrected in review 1; the first version of this note blamed it). I
   shortened what could go (one grammar error message, no template comments, a loop for the `<svg>`
   attributes) before raising.
7. On Apple platforms the AltGr rule does not cancel the Option fallback: Apple has no AltGr key and
   some engines report Option as `AltGraph`, which would otherwise disable exactly the case the
   spec's third fallback exists for.
8. Two matching details the spec leaves open: a match on `event.key` is always accepted, the
   `event.code` fallback is tried only when it fails (so the numpad `+` matches `Mod+Alt+Plus` with
   Option held on a Mac, where the code `NumpadAdd` is not a US punctuation code); and the digit
   fallback reads the main-row `Digit0-9` codes only, never `Numpad0-9` (with Num Lock off, numpad 1
   is End).
9. Named keys display and announce as written (`'PageUp'`, `'F2'`); only Escape (`Esc`), the
   arrows (`↑ ↓ ← →`) and Space have their own labels. Modifiers always display in the fixed order
   Ctrl/⌃, Alt/⌥, Shift/⇧, Meta/⌘ whatever the written order (the spec states the order for Apple
   only), and Meta reads "Meta" off Apple platforms.
10. `tm-kbd`'s host is `inline-flex`, not `display: block`: it sits in sentences and menu rows (the
    core-ui README records the exception, with `tm-icon`'s, which the spec states).
11. The spec's `<button tmButton><tm-icon name="plus" />New</button>` example is not shipped: the
    button points `--icon-size` at its icon token only in spec 0010 §D.10 (PC-011). Until then a
    `tm-icon` in a button is 16px, not 14px. The examples show a container setting `--icon-size`
    instead.
12. `lucide`, not `@lucide/icons` (Review flag 2). Its flip condition ("`@lucide/icons` v1 shipping
    stable") has happened, but so has `lucide` itself: both are 1.x, semver-stable, same data. The
    flag's concern was v0 instability, which no longer applies, and `lucide`'s nodes are smaller
    (no per-element `key`), which counts against the 4 KB of icon data in the `@tellma/core`
    budget. The registry accepts `@lucide/icons` objects, and a compile-time test proves it against
    their published type shape. Pinned at 1.66.0 (a week old), not 1.70.0 (a day old).
13. The docs group set is made closed (deliverable "the new `collection` docs group"): there was no
    list to add `collection` to, since `group` was a free string.
14. (Review 1, orchestrator ruling.) The grammar refuses Shift beside a symbol key: the matcher
    never compares Shift there, so `'Mod+Shift+/'` could never fire on a US layout (the keydown is
    `?`). The error names the binding to write instead: the US shifted symbol for an unshifted
    punctuation key (`'Mod+?'`), else the symbol without Shift. The spec is silent on the case.

### Findings

**R1-1 (major): the grammar accepts Shift beside a symbol, but the matcher ignores that Shift, so
the binding can silently never fire.**
`client/projects/core/tellma-core-ui/kbd/tm-keys.ts:103-116` accepts `Shift` with any key.
`tm-keys.ts:331-336` then skips the Shift comparison for `punctuation` and `symbol` keys.

- *Failure scenario.* A page registers `'Mod+Shift+/'`, or `'Mod+Shift+.'` or `'Shift+='`. Spec
  0027 §3 admits any `Mod+Shift+<key>` except `Mod+K` and `Mod+/`. `tm-kbd` shows
  "Ctrl Shift /", but on a US layout the keydown is `key: '?'`, `code: 'Slash'`, ctrl and shift.
  The key comparison fails (`'?'` is not `'/'`), and the code fallback does not run because `'?'`
  is ASCII. The shortcut never matches, and nothing reports it.
- *The reverse.* On a layout where `/` itself needs Shift (German Shift+7), the same keydown
  matches both `'Mod+/'` and `'Mod+Shift+/'`.
- *Why the spec does not catch it.* Spec §3.2 says only that Shift is never compared beside a
  symbol, so the contradiction is a gap in the spec, not in the code alone.
- *Suggested fix.* Make `parse` refuse `Shift` (written or implied through `Mod+Shift`) when the
  key's kind is `punctuation` or `symbol`. The one grammar error message could add "write the
  shifted symbol, e.g. 'Mod+?'". Add a `tmFormatKeys` refusal test and a `tmKeysMatch` test for
  `'Mod+?'` from Ctrl+Shift+/. Record it as a deviation.

**R1-2 (minor): the `./icon` and `./kbd` budgetNotes give the wrong reason for the raise.**
`client/projects/core/tellma-core-ui/package.json:57-58` (and deviation 6 in the commit message
and the notes) put the excess down to the FESM carrying each component's template and stylesheet
twice. Under gzip the second copy costs almost nothing:

- With the `ɵɵngDeclareClassMetadata` statement removed, `./kbd` drops from 2,275 to 2,167 gzipped
  bytes (about 0.1 KB). `./spinner` drops by 61 bytes.
- All of `tm-kbd` (its `ɵcmp`, factory, metadata, template and styles) is about 0.75 KB. The
  matcher, parser and label writers are about 1.5 KB.
- So the weight is real logic, and the raise itself is justified.

*Failure scenario.* These notes are what the "ratchets, never loosened silently" process reads.
A later tightening pass would chase a packaging artefact that is not there, and the spec's
under-estimate would not be recorded as such.

*Suggested fix.* Reword both notes. Say the measured self-weight is the guard and registry (icon),
and the parser and matcher (kbd), above §1's estimate. Say the duplicated decorator metadata
accounts for about 0.1 KB gzipped. Update deviation 6 to match.

**R1-3 (minor): TSDoc is missing on several declarations (AGENTS.md: every class, interface, type
and member).**

- `client/projects/core/tellma-core-ui/icon/tm-icon.ts:146-148`: the private `host`, `registry`
  and `errorHandler` fields.
- `tm-icon.ts:193`: the constructor.
- `client/projects/core/tellma-core-ui/kbd/tm-keys.ts:37-42`: the `kind` TSDoc does not explain the
  `'other'` member.
- `client/projects/internal/showcase/src/app/kbd/kbd-story.ts`: `bindings`, `apple`, `last`,
  `text` and `aria`.
- `client/projects/internal/showcase/src/app/icon/icon-story.ts:164-167`: `names`, `checkIcon`,
  `rows` and `inserted`.
- `client/projects/core/tellma-core-ui/icon/tm-icon-registry.spec.ts:20-29`:

Older stories and components skip private members the same way, but this checkpoint adds new
