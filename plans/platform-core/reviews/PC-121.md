# PC-121: Expression editor and path tree picker

## Implementer notes

### What was built

Spec 0029 §10 and §11, as two new lazy entry points of `@tellma/core`, with their fakes and
harnesses in `@tellma/core-testing` and their Arabic in `@tellma/locale-ar`.

- **`@tellma/core/expression-editor`** (`client/projects/core/tellma-core/expression-editor/`).
  - `src/tm-qx-text.ts`: `tmQxParameters` and `tmQxInsert`, moved out of `/entity` with the name
    fold (`ɵtmQxFold`), plus `ɵtmQxPlanInsert`, which returns where the insertion lands and the
    text it adds so the editor can apply it as one native edit. The lexical result type is
    `TmQxParameterSites`.
  - `src/tm-queryex-wire.ts`: the `queryex/discover` request and result types (camelCase, null
    members optional).
  - `src/tm-queryex-draft.ts`: `injectTmQueryexDraft` / `TmQueryexDraft`. Six clause texts; a
    computed request (the permission profile sends `filters[0]` alone; a query sends every
    non-blank clause, `having`/`measures` only when aggregating, confirmed parameter types the
    server takes, once per folded name); an effect that restarts a 250 ms wait and aborts the call
    in flight on every change of the request; `status` idle/checking/checked/offline/failed;
    `retry()`, and a retry when `TmApi.online` returns. `diagnostics(clause)` merges the lexer's
    problems with the server's while the clause's text equals what was sent, deduped and sorted,
    each message `Queryex_<code>` (or the dotted code with underscores) through `TmServerText`,
    falling back to the code. `parameters` merges names from every clause with the confirmed type,
    else the answer's, conflicts and the compared entity. Telemetry `tm.queryex.discover` timing
    `{ clauses (capped at 4), problems: none|some }`.
  - `src/tm-expression-editor.ts` + `.css`: `tm-expression-editor`. A `pre` mirror under a
    transparent `textarea` (both `dir="ltr"`, mono, same metrics, the box `rows` lines tall via
    `--tm-expression-editor-rows`); token, wavy-problem and 1.2 s insertion-tint segments; a 20 px
    status line ("No problems", "Checking…", "Line N: message" with "+N more", or the offline or
    failed reason with Retry and an "N problems" list) whose list is a `tm-popover` (`md`) of
    buttons that select the span; an optional 24 px chip row (`@From · Date`, warning-toned when
    untyped or conflicting); F8/Shift+F8 (wrapping); Mod+Enter emits `submit` outside a grid cell
    and is left to the grid inside one; `insertAtCaret` (the last caret, else the end) as one
    `execCommand('insertText')` edit, selected and tinted, telemetry `tm.queryex.insert {via}`;
    `insertFromDrop` re-spaced with one more native edit; `TmFormFieldControl` and
    `TmCellEditor<string>` (registered through `TM_CELL_EDITOR_HOST`), with TmInput's
    self-write/baseline pattern for cancel; a polite region that announces a check's outcome only
    while the editor has focus. Without a `draft` input it makes its own over `root`. Strings
    `tm.queryex.*`, registered by scope.
- **`@tellma/core/path-picker`** (`client/projects/core/tellma-core/path-picker/`).
  - `src/tm-path-tree.ts`: `ɵTmPathTree`, built branch by branch and cached per key. Scalars;
    each multilingual group as one `text` node (labelled through `TmEntities.resolve`, so without
    a language symbol); navigations as branches with the target's pill; `core.Blob` navigations as
    `image`/`file` by their blob policy, branches only in `fields` mode; with `dateParts` in
    `fields` mode, date/datetime/instant fields branch into the eight parts (Day only for
    date-times and instants, an instant wrapped in `local()`), the calendar-taking ones given
    `'uq'`/`'et'`, or labelled "(Gregorian)" under any other non-Gregorian calendar. Hidden:
    non-queryable fields, foreign keys, twins as roots, navigations whose foreign key is not
    queryable, and every path `TmPermissions.reachable` refuses. Order: `Intl.Collator` by label,
    `Id` and the audit fields last. `text(node)`: the path, a navigation's foreign-key path, or a
    part's expression. `search(query)`: `tmSearchNormalize` on label and last segment, depth
    first, entity branches walked to three navigation steps, 200 matches, with muted ancestors and
    their expansion.
  - `src/tm-path-picker.ts` + `.css`: `tm-path-picker` over `tm-search-field` and `tm-tree`. The
    tree is rebuilt when the root, mode, inputs, shape, access, calendar or UI language change;
    the search's expansion overrides the reader's while it runs; icons per type and kind; drag
    payload `{ kind: 'tm.path', data: node, text, label: pathLabel }` for accepted nodes; `activate`
    only for accepted nodes; `selected` drops refused keys; a polite count. Strings
    `tm.pathPicker.*`.
- **`/entity`**: `tmQxParameters`, `TmQxParameter`, `tmQxInsert` and the fold removed (with their

### Deviations

1. Spec 0029 §1 places the editor and the picker in `/entity`; they are lazy entry points of their
   own (orchestrator instruction: `/entity` was at 24.96 of 25). `tmQxParameters` and `tmQxInsert`
   moved with the editor. The "within the 28 KB" done-when is met as three budgets: `/entity`
   24.55 of 25, the editor 7.90 of 8, the picker 4.56 of 5.
2. The `/entity` ceiling is not lowered: 24.55 rounds up to 25, the current ceiling.
3. The Gregorian label is `tm.pathPicker.gregorian`, not `tm.entity.datePartGregorian`:
   `ɵregisterStrings` registers a scope once, and `entity` belongs to `TmEntityActions`, so a
   second registration under it would be dropped.
4. In `columns` mode a multilingual group's children are its twins only (`Name2`, `Name3`); the
   group's own key stands for slot 1 (the column key of the active slot, §6.1), so it is not
   repeated as a child. In `fields` mode the group is a leaf (Queryex reads `Name`).
5. "(Gregorian)" is added only to the parts that take a calendar (Year, Quarter, Month, Quarter of
   year, Month of year). Week, Day and Day of week are the same in every calendar.
6. The lexical result type is `TmQxParameterSites`, since §10.1's `TmQxParameter` is the draft's
   merged parameter.
7. Undo of a re-spaced drop takes two steps (the spaces, then the drop). `insertAtCaret` is one
   step, and focuses the editor, because a native undoable edit needs focus.
8. `accept` hides refused leaves; a refused branch still shows (it may hold accepted fields) but
   neither drags, activates nor selects.
9. The draft drops confirmed types the server refuses (`HierarchyId`, `Geography`) and repeats of
   a name, client-side.
10. The Arabic is in a new `@tellma/locale-ar/queryex-strings` entry point that `tmArabic()` loads
    with the other two on the first switch to Arabic, not with the editor. In `./platform-strings`
    it measured 4.01 against 4 after two raises. A part that loads with the editor needs a
    `TmLocalization` seam in the primary, which may not grow (49.89 of 49.89).
11. Spec §10.4's three-engine e2e of undo is not added: no page hosts the editor before specs
    0030 and 0032. A Chromium unit test pins the single undo step.

### Rulings taken (spec silent)

- `mode` defaults to `fields`. Telemetry `clauses` is capped at 4.
- Offline or failed with lexical problems: the status line shows the reason, Retry and a
  "N problems" list button.
- The chip row shows the editor's own clause's parameters, typed from the shared draft.
- An editor clears its clause from a shared draft on destroy, when the text is still its own.
- `submit` keeps the spec's name under an `no-output-native` disable, as `tm-search-field` does.
- The parameters' corpus test imports the engine corpus beside the lexer, under a commented
  `tm/core-import-boundary` disable: a fixture, not a code dependency.

### Open risks

- The mirror and the textarea must keep identical metrics. They share every font, padding,
  wrapping and scrollbar-gutter rule, and the scroll is mirrored. Parameters are bold in the
  mirror only, which is safe in a monospace face but would drift in a proportional fallback.
- `document.execCommand('insertText')` is deprecated but remains the only undoable script edit;
  the fallback (`setRangeText`) works but is not undoable.
- `TmFakeDiscover` folds names with `toUpperCase`, close to but not exactly the engine's fold.
- The search walks up to three levels of every navigation. On a wide model this builds many
  nodes on the first keystroke (each cached), bounded by the 200-match cap only once that is
  reached.

### What reviewers should examine hardest

- The draft's stale-answer and abort logic (`#request` equality, `#schedule`, `#check`) and the
  online-retry effect.
- `#respaceDrop`'s diff and single replacement, and the `#editing` guard around native edits.
- The tree's node rules against §11.2, especially the twins, blobs, reachability and date parts.
- The re-split of the Arabic table (deviation 10) and the missing Arabic-loads-with-the-editor
  seam.
