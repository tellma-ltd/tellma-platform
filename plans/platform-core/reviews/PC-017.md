### Deviations

1. **The kind grammar also refuses the Windows device names** (`con`, `prn`, `aux`, `nul`,
   `com0`–`com9`, `lpt0`–`lpt9`). The file-system store makes each kind a directory, and Windows
   reserves those names in every directory. No kind any spec names is affected.
2. **The Windows root cap is 153, not 160.** The deepest object path is root + 106 characters
   (`\t2147483647\` + a 40-character kind + `\xx\` + a 32-character key + `.` + a 16-character
   variant); staying within 259 (MAX_PATH less its terminator) allows 153. A test pins the
   arithmetic.
3. **Read streams share `FileShare.Read | FileShare.Delete`** (spec: `FileShare.Read`), so the sweep
   can delete an object on Windows while a download of it is still streaming; the open handle keeps
   reading to the end.
4. **A write's content must yield exactly its declared length**; fewer or more bytes fail the write
   with `BlobStoreException` and leave no object (contract addition, pinned by the conformance
   suite), so a row's `Size` can never disagree with its bytes.
5. **Listing prefixes are whole segments**, validated by a new `BlobName.IsValidPrefix` (a kind, or
   a kind and a two-digit fan-out segment); a kind never lists a longer kind that starts with it,
   and entries come in ordinal name order (Azure's order). Also new on `BlobName`: `IsValidKey`,
   `IsValidPrimary` and the length constants. The Azure adapter must list `prefix + "/"`.
6. **Content sniffing is broader than §3.3's minimum**: HTML is any WHATWG MIME-sniffing HTML
   signature (`<head`, `<script`, `<iframe`, `<body`, `<p`, `<br`, a leading comment, …), not only
   `<!DOCTYPE html`/`<html`, with a tag-name terminator rule so `<brand>` is text; markup is
   recognised behind a UTF-8 BOM and in BOM-marked UTF-16; SVG is also caught behind a leading
   `<!doctype`; the Mach-O universal container (`CA FE BA BE`, which Java class files share) counts
   as an executable; zip archives are recognised by all three `PK` record signatures.
7. **The file-name sanitiser also** replaces bidirectional controls (U+200E/F, U+061C,
   U+202A–202E, U+2066–2069) and unpaired surrogates, normalises to NFC, and **shortens** a name
   over 255 characters (keeping an extension of up to 16 characters, never splitting a text
   element) rather than refusing it: §8.2 has no error code for a long name, and the service is
   also called by jobs.
8. **Options validation runs on first resolution** (an `IValidateOptions` plus the same rules in the
   store constructor), not through a startup check: the `blobs` startup check belongs to the
   kind-registry checkpoint, which can call `FileSystemBlobStoreOptionsValidator.Describe` or resolve
   the options and collect the `OptionsValidationException`. The "`.tmp` crosses a volume" rule needs
   no check: `.tmp` sits inside the tenant directory by construction, so only a mount point inside a
   tenant directory could split them.
9. **The resolved root is logged when the store is created** (`BlobFileSystemRoot`), which is the
   first resolution of the singleton rather than host start; once the `blobs` check resolves the
   store, that is startup.
10. **Two log events beyond §10.2**: `BlobFileSystemRoot` (Information) and
    `BlobTenantMissingOnWrite` (Warning, a write that found the tenant directory missing).
11. **Additions to the contract types**: `BlobContentTypes`, `BlobTelemetryTagValues`, the unit
    constants on `BlobTelemetryNames`, `ThumbnailPolicy.VariantName`,
    `ImagePolicy.DefaultMaxInputPixels`, `BlobKindPolicy.For(BlobPreset)`,
    `BlobReferenceAttribute.CreatePolicy()`, and `ImageRejectedException`'s reason constants and
    its refusal of a missing `reason`.
12. **`BlobReferenceAttribute.MaxSizeBytes` replaces the preset's size when above 0** (§2.3 says
    "narrows"). Clamping a larger value to the preset's would be a silent clamp; replacing honours
    the declaration, and §9's `MaxUploadSize` rule still bounds it. Reported to the orchestrator.

### Open risks

- **Durability of the rename.** The part file is flushed to the device before the move, but the
  directory entry is not fsynced (.NET has no API for it). After a power loss on Linux a just-moved
  object may revert to its `.part` file: the purge removes it and the row's `GET` answers 404. A
  blob store on a journalling file system makes this unlikely, not impossible.
- **Symlinks inside the root** are not detected: the containment check is lexical. An operator who
  plants a link under a tenant directory can redirect reads; the grammar keeps a client from doing
  so.
- **Purge vs. a long write**: a `.part` older than the cut-off (24 h) is assumed abandoned; on
  Windows an in-flight one cannot be deleted anyway (`FileShare.None`), which the purge reports as a
  failure.

### Seams left for later checkpoints

- The kind-registry/staging checkpoint: build kind policies with `BlobReferenceAttribute.CreatePolicy()`;
  stage through `BlobContentSniffer.Determine` (first 8 KiB, `SniffLength`) and
  `BlobFileNames.Sanitize`; report the store count and `FileSystemBlobStoreOptionsValidator.Describe`
  from the `blobs` check; map `ContentTypeRefusal` to `Blob.UnsupportedType` with
  `ContentTypeDecision.ContentType` as the `contentType` argument.
- The Azure adapter: derive `BlobStoreConformanceTests` with `BlobStoreCapabilities.None`; list
  `prefix + "/"`; enforce the exact declared length; emit the store instruments on
  `BlobTelemetryNames.StoreMeterName` with `BlobTelemetryTagValues`.
- `BlobRejectedException` is not created here (it is seeded contract-first elsewhere).

### What reviewers should examine hardest

  single retry), and that no path leaves a part file or a partial object.
- `ResolveContainedPath` and `BlobName.IsValid`/`IsValidPrefix` together: can any string pass both
  and resolve outside `t{id}`, on Windows or Linux?
- `BlobContentSniffer`: the order of the rules (always-rejected before signatures, signatures before
  zip and text), and whether the broadened HTML set refuses legitimate text a tenant would upload.
- `BlobFileNames.Shorten` and the surrogate handling.
- The conformance suite as a contract: is every case one the Azure adapter can and should meet?
