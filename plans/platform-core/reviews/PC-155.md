# PC-155: /attention model: TmAttention, TmArrivals, TmAttentionText, banner host

## Implementer notes

### What was built

Spec 0028 §5.2–§5.4, §8.1–§8.3, §9.4 and §11, in `client/projects/core/tellma-core/attention/`
(the eager `@tellma/core/attention` entry point and two lazy chunks of it).

- **Attention model** (`src/tm-attention.ts`, eager). `TmAttention`, root.
  - `inbox` and `assignments`: the routed tenant's stored copies (`TmCacheRefresher.ɵpartition` +
    `TmClientStore.doc`), the inbox with this tab's overlays applied.
  - `bell`/`tray` badges: the count capped at 100 (`99+` through core-ui's `counter.overflow`
    string and `TmL10n.formatNumber`), the bell's `attention` tone for an unseen Warning/Error, the
    jobs that are `Pending`/`Running` (not `Held`/`PendingConfirmation`), and each accessible name
    joined with the language's separator (`, ` / `، `).
  - Verbs `read`, `readAll`, `clear`, `clearRead`: guarded by `writable` (not Frozen and online),
    an overlay `{ id, verb, ids, version: null }` in the same frame, then the write; the answer's
    version is stamped on the overlay, which is released (and pruned by an effect) once a copy's
    version is ≥ it by `TmDecimals.compare`. A copy read before the verb committed but saved after
    its response therefore keeps the overlay. A failure drops the overlay at once and toasts sticky
    (`tm.attention.toasts.failed`, key `tm.attention.failed`, Try again re-runs the verb).
  - `stopJob`: a stopping overlay (`cancelRequestedAt` = now) until a copy shows the request or no
    longer lists the job; a failure drops it.
  - Read-only and capped counts: `lower()` never lowers a count at the cap, whose true value is
    unknown.
  - `toggle(panel, via)`: closes the open panel (aborting its read), emits `tm.attention.panel-opened
    { panel, via, badge: 0 | 1-9 | 10+ }`, and opens. Opening with something new and `writable`
    sets a `pending` seen hold in the same frame, sends `inbox/seen` / `assignments/seen`, then
    holds by the answer's version (bell) or seenAt (tray). Not writable, or a failed seen: an `own`
    hold that lifts with the panel's own read (its send time) or when the panel closes. Then the
    panel reads its registered document once, stamped with the send time.
  - `refresh(document)`, `live` (paused after 5 s neither connected nor disabled), `writable`, `open`.
  - A tenant change aborts the reads and drops the overlays, the holds and the open panel.
- **Server calls** (`src/tm-attention-calls.ts`, lazy chunk `tm-attention-calls`). The writes with
  `tm.attention.verb { verb, outcome }` telemetry and the failure toast, the seen, and the panel's
  read. The model imports it with its first call; every overlay stays in the eager model, so the
  same-frame rule holds before the chunk loads.
- **Arrival engine** (`src/tm-arrivals.ts`, eager). `TmArrivals`, root, created by the tenant shell.
  - Watches `inbox`, `assignments` and `tenant` per routed tenant. The baseline is the first copy
    with `savedAt` ≥ the tab's start; every copy moves `previous` on, in every tab, and only a
    visible, focused tab (`visibilityState === 'visible' && hasFocus()`) hands a copy on, so a tab
    that gains focus replays nothing.
  - `tmNotificationToastsKey` (`notifications.toasts`, curated, `true`) switches notification and
    assignment toasts off; tenant-state toasts ignore it.
  - Installs the toasts' overflow pill through `TmToasts.ɵsetOverflow`: inside a tenant
    "{n} more · Open notifications" navigating to `TmUrls.search('core.Notification')`; outside,
    it declines and the configured pill shows. Uninstalled on destroy.
- **Arrival toasts** (`src/tm-arrival-toasts.ts`, lazy chunk `tm-arrival-toasts`), loaded with the
  first copy handed on; registers `tm.arrivals` strings and the lucide `inbox` icon.
  - Notifications: newer `createdAt` than the previous copy's newest, unread, of a `toast: true`
    type, shown oldest first; tone by severity, Error sticky else 6 s, key `n:<id>`; Download (an
    anchor click on `blob('export-file', fileId, { download: true })`) for `core.export.ready`,
    else View (`notifications/<id>/open`) when the row has a target.
  - Assignments: newer `assignedAt`, `assignedById` not the user. One: accent, icon `inbox`, title
    "{caption} assigned/returned to you", key `a:<id>`, Open to `TmUrls.target`. Several: "{n}
    documents assigned to you", key `a:many`, View opens the tray (`toggle('tray', 'toast')` unless
    it is open).
  - Tenant: a change to ReadOnly or Frozen toasts warning with the tenant's name in the content
    slot, key `t:state`.
  - `tm.attention.toast { kind, outcome }` on every close but `api`.
- **Server text** (`src/tm-attention-text.ts`, eager). `TmAttentionText`, root, every result a
  signal that follows the language and content slot with no request.
  - `notification(type, json)`: `Notification_<type>` / `_Detail`; a missing title renders the
    type's key, a missing detail `null`.
  - `job(source)`: the job's own label key, then the handler's metadata `labelKey`, its
    `labelFallback`, its key; an `entity` argument naming an entity renders as its plural label.
  - `jobMessage(key, json)`.
  - `caption(row)`: title from `tm.attention.assignment.title` with the code split out into
    `titleSegments` for a `<bdi>`, `#<targetId>` without a code; detail from
    `Assignment_<Resource>_Detail` only when both the key and the caption's detail exist; amount
    exact at its own scale through Intl with `currencyDisplay: 'code'`, bidi controls stripped.
  - `isolate(key, args, isolated)`: any platform message split around its isolated arguments
    (private-use placeholders, then `split`).
  - Stored arguments follow the server's ICU rules (`src/tm-icu-arguments.ts`): booleans → `true`
    / `false`, a 3-element LocalizedText passes for `TmServerText` to resolve, other arrays and
    objects → JSON text, non-object JSON → no arguments.
- **Outcome toasts** (`src/tm-outcome-toasts.ts`, eager). `TmOutcomeToasts.jobStarted(jobId)`
  (accent, 4 s, key `job:<id>`, Track to `target('core.Job', id)` when the job has a page) and
  `exporting(cancel)` (neutral, sticky, Cancel).
- **Banner host** (`src/tm-banner-host.ts`): a dismiss that empties the row while focus was in it
  moves focus to `main` (with `tabindex="-1"` added when absent, `preventScroll`) after the render.
- **Strings**: `src/tm-attention-strings.ts` registers `tm.attention` (bell, tray, separator,
  assignment title, overflow pill, failure toast, outcomes) through `ɵregisterStrings`; Arabic in
  `locale-ar/strings/strings-tm-ar.ts` under `attention` and `arrivals`.
- **Shell stand-ins** (`shell/src/tm-tenant-shell.ts`, `tm-tenant-picker.ts`): render
  `<tm-banner-host />` above `main`; the tenant shell creates `TmArrivals`.
- **Core-ui** (`tellma-core-ui/toast/tm-toasts.ts`): `ɵsetOverflow(overflow | null)`, an installed
  pill that wins over the configured one and may decline (`null`) per count.
- **Core** (`src/l10n/tm-server-text.ts`): a LocalizedText argument falls back to slot 1 when its
  slot is empty, not only null, as the server's `LocalizedText.In` does (0 bytes on the primary).
- **Size gate** (`client/scripts/bundle-size.mjs`): the static-graph check walked from the first
  esbuild output with an `entryPoint`, but with splitting every `import()` target is an entry
  output too, in no fixed order. After this build the first was `/recents`' dynamic entry, so the
  primary falsely "reached" `/recents`. The walk now starts from the output built from the entry
  point's own FESM, and fails if there is none.
- **Testing** (`tellma-core-testing`): `TmBannerHostHarness` (`getBar` through core-ui-testing's
  `TmBannerBarHarness`, `isOpen`, `isEmpty`, `getAnnouncement`, `getPoliteness`); peers
  `@angular/cdk` and `@tellma/core-ui-testing` added; the attention specs' app rig is
  `src/attention/tm-attention.testing.util.ts`.

### Deviations

- The overflow pill is installed by `TmArrivals` through a new core-ui seam
  `TmToasts.ɵsetOverflow`, not configured in `provideTellma`'s `provideTellmaToasts` (spec 0028
  §8.1, spec 0024 §2.2): the primary has 0.60 KB left of its 50 KB cap, and the pill's label and
  action need the attention strings and `TmUrls.search`.
- The `inbox` icon is registered by the arrival toasts' chunk, not in the primary's icon set.
- The server calls and the arrival toasts are lazy chunks of `/attention`, and the arrival
  toasts' strings live under their own scope `tm.arrivals` (the eager `tm.attention` keeps the
  pill, the failure toast and the outcomes), to bring `/attention` under the spec's 6 KB.
- `TmAssignmentCaption` adds `titleSegments`, and `TmAttentionText.isolate` is public, for the
  `<bdi>` rendering §11.3 asks of rows and toasts.
- `notifications.toasts` off does not silence the tenant-state toast: it is a change the system
  made, which §8.1's outcome rule keeps.
- A failed `seen` toasts nothing and falls back to the panel's own copy lifting the overlay; a
  panel that closes with no `seen` sent lifts its overlay.
- An assignment toast without a comment shows the caption's detail and amount, else "Assigned by
  {assigner}" (§8.1 only gives "{assigner}: {comment}").
- A capped count stays capped under an overlay.
- The tenant-state toast has a key (`t:state`), so a second change replaces the first.
- The banner host moves focus to `main` when a dismiss empties the row (§9.4 says the host never
  takes focus; this only rescues focus that would fall to the body).
- `TmServerText` resolves an empty-string LocalizedText slot to slot 1.
- Toast texts are rendered once, as plain strings: an open toast keeps its language across a
  switch.
- `0027`'s shells are still PC-116/PC-118's to build: the stand-ins render the banner host and
  create `TmArrivals` now, and the real shells take them over.

### Open risks

- `/attention` has 0.07 KB left under the spec's 6 KB, which also has to hold the bell and tray
  buttons and the assignment list still to land; their checkpoints will need the figure raised or
  more of the entry point split out.
- The `assignments` leader document is not registered yet (PC-207), so the tray's panel read and
  `refresh('assignments')` do nothing until it is; the tests pin that.
- `TmJobHandlerMetadata` has no `commitsInSteps` yet (PC-156); `stopJob` leaves the confirmation
  to its caller.
- A chunk that fails to load: a verb fails with telemetry but without the failure toast (its code
  is in the chunk), and the copy's arrivals go untoasted; both load again next time.
- Two pre-existing specs failed once in a full `core` run under load and pass in isolation and on
  the rerun: `TmNavigation` "labels and re-sorts the entries when the language switches" and
  `TmHttpApi` "blames the client when the server is newer, and asks the worker to update". This
  checkpoint's own language-switch waits until the language applies.

### What reviewers should examine hardest

- The overlay and seen-hold release rules in `tm-attention.ts` (`holds`, the release effects,
  `#overlaid`) against §5.2–§5.4, especially the copy read before a verb committed but saved after
  its response, and the `own` hold's `sentAt` against copies stamped by other tabs.
- The baseline and previous-copy logic in `TmArrivals.#watch` across a tenant switch and across
  copies arriving while the tab is unfocused.
- That moving the server calls into a chunk kept every same-frame guarantee (overlays, stopping,
  seen holds are all set before the first `await`).
- `TmAttentionText.caption`'s amount formatting at the string's own scale and its isolate split
  with translations that reorder the arguments.
- The `ɵsetOverflow` seam in core-ui: install, decline, uninstall, and the pill's run.
- The size gate's static-graph fix: that it still catches a real static path from each entry
  point.
