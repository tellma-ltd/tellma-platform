# PC-059: Client-cache sweep, blob cancellation, basics glyphs

## Implementer notes

### What was built, and where

All paths are under `client/` unless stated.

- **`TmClientCache.clearAll({ keep })` (§D.5).** `projects/core/tellma-core-ui/cache/tm-client-cache.ts`.
  New exports `TmClientCacheArea` (`'cache-storage' | 'indexeddb' | 'local-storage' |
  'session-storage'`) and `TmClientCacheClearOptions` (`keep?(name, area)`). The four areas are
  swept in parallel under `Promise.allSettled`, each best effort: CacheStorage `tm-*`; IndexedDB
  `tm-*` enumerated with `indexedDB.databases()` (area skipped when `indexedDB` or `databases` is
  absent), each delete settling on `success`, `error` or `blocked`; `localStorage` `tm.*`; this
  tab's `sessionStorage` `tm.*` (keys collected first, then removed). `ngsw:` caches never match
  the `tm-` prefix. `keep` is asked once per matching name; a throwing `keep` is reported to the
  `ErrorHandler` and that name is deleted (see Deviations). The TSDoc states the naming rule, the
  ngsw exclusion and the versionchange obligation. The only caller, the showcase image story,
  calls `clearAll()` unchanged.
- **The versionchange obligation.** The only `tm-*` IndexedDB opener today is the boot script's
  expiry delete (`projects/core/tellma-core/src/boot/tm-boot-expiry.ts`, database `tm-app`); its
  connection now closes (and settles) on `versionchange`. The boot script was at exactly its
  3 KB gzip budget (3072/3072 B) before this change; the handler cost 12 B, so the open's
  `upgradeneeded` handler was simplified to `request.transaction!.abort()` (a versionless open
  upgrades only a database that does not exist, so the old `oldVersion === 0` test was always
  true, and the upgrade always has its transaction), and the transaction's two end handlers share
  one assignment. Now within budget (boot-template spec passes).
- **Blob cancellation (§D.6).** `image/tm-blob-fetcher.ts`: `TmBlobFetchOptions.signal`. The
  default HttpClient fetcher rejects at once with `signal.reason` for a pre-aborted signal (no
  request), and on abort unsubscribes (cancelling the request) and rejects with the reason; the
  listener is attached before subscribing and removed on settle; a 304 still resolves as not
  modified. `image/internal/blob-cache.ts`: `getImage(url, version, { onRefresh?, signal? })`
  (internal options object replaces the positional `onRefresh`). One shared request per URL with
  its own `AbortController` and a holder count: a caller's abort rejects only its wait with its
  `signal.reason`; the request aborts when the last holder leaves (a caller without a signal holds
  for good); an abandoned entry leaves the in-flight map so a later caller starts afresh; the
  fetcher's answer is checked against the shared signal before `put`, so an aborted request writes
  nothing even from a fetcher that ignores the signal. Background revalidation is shared and
  ref-counted the same way: each instance showing the URL holds it (and its refresh callback)
  until its signal aborts; it aborts when no holder remains, and a late answer is neither written
  nor swapped in.
- **tm-image (§D.6).** `image/tm-image.ts`: each view load is an `ActiveLoad` (src, etag,
  `AbortController`, `awaitingBytes`). The load aborts on destroy, on a `src` or `etag` change, and
  on leaving the defer viewport while the bytes are still awaited (the IntersectionObserver now
  observes for the component's life, not just until first sight); the load restarts when the box
  returns. The controller stays alive after the bytes land, so the instance holds its background
  revalidation until it leaves. An aborted load shows no error glyph and announces nothing. The
  re-fit fetch of the original passes a lifetime signal aborted on destroy.
- **Basics glyphs (§D.11).** alert (`Info`, `CircleCheckBig`, `TriangleAlert`, `CircleX`),
  date-picker (`CircleAlert` invalid mark, `Calendar` toggle; popup `ChevronLeft`/`ChevronRight`
  with `mirrorInRtl`), file-preview (`CircleX`, `FileText`), files (`Upload`), image (`ImageOff`,
  `Image`, `Camera`, `Crop`, `Trash2`; edit pane `Check` at stroke 2.25), modal (`X`), private
  error popover (`CircleAlert`) all draw through `<tm-icon [svg]>` with Lucide data; each host
  re-points `--icon-size` at its old size token, so no box moves. The popup's old
  `:host-context([dir='rtl'])` scale rule is gone (tm-icon mirrors through `:dir(rtl)`). Button
  and input docs examples use `<tm-icon [svg]>`; `docs-examples.spec.ts` provides `searchIcon`.
- **Date popup live flip.** `date-picker/tm-date-picker.ts` subscribes to the root
  `Directionality.change`; while the popup is open it re-stamps the CDK pane with the live
  `Directionality` (`overlayRef.setDirection`), re-reads the origin's text edge and re-anchors.
  Before this, the CDK stamped the pane's `dir` only at attach, so after a live flip the popup
  kept its old layout while arrow keys followed the new direction (and the old
  `:host-context` chevron rule mirrored the chevrons against that stale layout, so they pointed
  inward). Measured: the live-flip e2e fails on the pre-change sources.
- **Showcase.** New `basics-glyphs` story (`projects/internal/showcase/src/app/glyphs/basics-glyphs-story.ts`)
  with every glyph above in the state that draws it.

### Deviations

1. **`./image` ceiling 10 → 11** (the checkpoint's "./image stays ≤10" is not met). The entry
   point had 0.05 KB of headroom at the start (9.95; spec 0010 §D.6 assumed 9.66 → ≈9.8), and the
   Lucide data of its six spec'd glyphs alone is 0.64 KB in place. Measured 10.69 (+0.74); raised
   under D-031 (rounded up to the next 0.5 above what it adds) with a budgetNotes entry; the
   savings taken are listed there. Ruled to stand by D-053.
2. **`./alert` ceiling 2 → 2.25** (D-053; first raised to 2.5 under D-031): 1.98 → 2.14
   (+0.16), the four tone glyphs' Lucide data less the inline SVG they replace; budgetNotes
   entry added.
3. **A throwing `keep` deletes the name** and reports the error to `ErrorHandler`; the spec only
   says `clearAll` never throws. A sweep ends a session, so it never keeps what it was not clearly
   told to keep.
4. **The defer observer lives for the component's life.** Needed to abort on leaving the
   viewport; consequences: a `src`/`etag` change while the box is off-screen now waits until the
   box is near the viewport again (it used to fetch at once), and a failed load is not retried on
   every pass back into view (only a new `src`/`etag` retries).
5. **Date picker live flip (not in §D.11's text).** The open popup is re-stamped with the live
   `Directionality` and re-anchored on a direction change; without it the spec'd e2e ("the popup
   chevrons after a live direction flip") cannot pass, because the CDK stamps the pane's `dir`
   only at attach (a pre-existing layout/keyboard mismatch, now fixed).
6. **Boot expiry squeezed to fit its budget.** The versionchange handler (spec'd by §D.5's "every
   opener") pushed the English boot script from exactly 3072 B to 3084 B; the `upgradeneeded`
   handler was simplified (the `oldVersion === 0` test was always true for a versionless open) and
   the transaction's end handlers share one assignment, which brings it back within 3 KB.
7. **Glyph drawings follow lucide 1.66.** The boxes come from the same size tokens and the stroke
   is unchanged, but some inline copies predated the current Lucide data (calendar, upload,
   camera, file-text, for example), so those glyphs draw the current Lucide paths.
8. **Internal `getImage` signature.** The blob cache's positional `onRefresh` became an options
   object `{ onRefresh, signal }` (internal API, ɵ-prefixed).

### Open risks

- The deferred-scroll e2e relies on the 200px IntersectionObserver margin and the story's spacer
  keeping the deferred box out of range at scroll 0.
- `keep` throwing deletes the name: chosen as the safer default for a session-ending sweep, but a
  spec reading of "never throws" alone would also allow keeping it.

### What reviewers should examine hardest

- `blob-cache.ts` holder accounting: the per-caller wrapper promise, the map removal on the last
  abort, and that an abandoned shared promise never surfaces as an unhandled rejection.
- `tm-image.ts` pipeline effect: identity change vs visibility vs `src === ''` ordering, and that a
  failed load does not refetch on every scroll pass.
- The date-picker live-flip subscription (passing the `Directionality` object, not its value, so
  later opens stay live).

## Review 1

### Findings

**R1-1 (major): the `./alert` ceiling is 2.5 KB, but D-053 rules 2.25 KB.**
`client/projects/core/tellma-core-ui/package.json:29` sets `"./alert": 2.5`, and its budgetNote
(`package.json:64`) says "Raised from 2 to 2.5". D-053 rules `./alert` at 2.25 KB (measured 2.14 +
about 0.1, as in D-049) and `./image` at 11 KB (which the commit already has). At 2.5 the entry
point keeps 0.36 KB of unexplained headroom, so a later growth of up to 0.36 KB would pass
`size:check` without the raise-and-note step D-031 requires. Fix: set `"./alert": 2.25`, reword the
note to "Raised from 2 to 2.25 …", re-run `pnpm run size:check` (2.14 fits), and correct the
Bundle measurements table in the implementer notes.

**R1-2 (minor): the boot expiry now settles on `versionchange` before its delete has committed.**
`client/projects/core/tellma-core/src/boot/tm-boot-expiry.ts:52` sets `db.onversionchange = done`,
and `done` both closes the connection and resolves. The readwrite `docs` transaction was created
before any `versionchange` can fire, so it is still running when `done` resolves.
`tm-boot.ts:172` then runs `go()`, which leaves for sign-in at once. The scenario: an expired tab
boots while another tab opens a newer `tm-app` version or deletes it (spec 0025's store upgrade, or
another tab's sign-out `clearAll`). This tab reports the expiry delete as done and navigates
before the transaction commits, and an unload aborts an uncommitted transaction. In the upgrade
case the expired user's documents survive until the store's own boot sweep. The function's
`@returns` (line 30, "settles when the delete commits or fails") is also no longer true.
Fix: close without resolving, `db.onversionchange = () => db.close();`. A closing connection lets
its running transaction finish and fire `complete`/`abort`, which still call `done`, and the
blocked delete or upgrade proceeds right after. Measured with the commit's esbuild settings and the
English platform strings: 3066 B as committed, 3067 B with this change, both within D-048's
3072 B. The new `tm-boot-expiry.spec` test ("yields its connection … instead of blocking it")
still passes as written, since the delete is not reported `blocked` once `close()` is pending.
