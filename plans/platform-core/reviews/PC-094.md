### Deviations

1. **Interim bootstrap.** `main.ts` calls `bootstrapApplication(AcmeApp, …)` and does not call
   `bootstrapTellma(appConfig)`.
   - It adds `provideBrowserGlobalErrorListeners()`, gates on `window.__tmBoot.state === 'run'`,
     and uses a minimal `tm-app` root component.
   - `bootstrapTellma` and `TmApp` are not in `@tellma/core` yet, and that work is gated on this
     checkpoint.
   - The root component keeps the `tm-app` selector, which the boot rules require. It has a
     justified `eslint-disable` for the `acme` prefix rule.
   - Adding `bootstrapTellma` here would also not fit the `@tellma/core` primary budget, which has
     about 0.08 KB of headroom.
2. **Interim languages.** `app.config.ts` defines English and Arabic locally, with empty client
   tables, instead of `tmEnglish()` and `tmArabic()`, which do not exist yet.
3. **Interim styles.** `angular.json` lists the platform stylesheets before `src/styles.css`: the
   tokens, the core-ui fonts, the directive styles, the boot-page styles and the locale-ar fonts.
   The spec instead has `styles.css` import `@tellma/core/styles.css` and
   `@tellma/locale-ar/styles.css`, which do not exist yet.
4. **No `tmGlFeature()`.** `features` is `[acmeFeature]`, because module-gl is not built yet.
5. **The `AcmeFeature` server class is created here, empty**, so the client feature names a
   composed feature. This work is otherwise spec 0018 §1.4's. The checkpoint that builds it should
   extend this class rather than add a second one.
6. **BuildCommand passes `--configuration $(Configuration)`.** The spec has the bare
   `pnpm run build:esproj`, but `--no-dotnet-build` then runs `dotnet run --no-build` in the
   default Debug configuration. That fails, or runs a stale Migrator, under
   `dotnet publish -c Release`.
7. **`ShouldRunBuildScript` defaults to false**, as in the ASP.NET Core Angular template.
   - A solution build needs no Node and runs no production `ng build`. The CI build-test job has
     no Node.
   - `dotnet publish` still runs the build, because the SDK's publish target ignores the flag.
   - `-p:ShouldRunBuildScript=true` builds the app on `dotnet build`.
   - The spec says "the esproj's build then runs `tellma-client build`".
8. **The distribution version comes from the composition library**, not the entry assembly.
   - Spec 0011 §2.2 says "the entry assembly". Spec 0024 §3.1 says "the composition library's
     informational version", and `AddTellma`'s own comment already said so.
   - With one `Version` per distribution the two agree in production. Only test hosts differed.
9. **The SPA proxy's target is computed by MSBuild**, from `.dev-ports.local`, in the Web csproj.
   - Spec 0011 §1.2 says `AddTellma` makes "the SPA proxy target the client port".
   - That is impossible at runtime: SpaProxy reads only its build-written `spa.proxy.json`, and
     its options type is internal.
   - A change to `ACME_CLIENT` therefore needs a rebuild.
10. **Acme's `package.json` lists the packages the platform sources import**: `@angular/aria`,
    `@angular/cdk`, `@angular/forms`, `@jsverse/transloco`, `lucide` and `@internationalized/date`.
    - `@tellma/*` resolve to their sources through tsconfig `paths`, so their peers and
      dependencies must be resolvable from the app.
    - Without them, Vite's dependency pre-bundling in `ng test` warns.
11. **Two devDependencies the spec does not list**: `@vitest/browser-playwright` and
    `@playwright/test`, for the `test` target's Chromium runner.
12. **The esproj's Migrator reference sets `SkipGetTargetFrameworkProperties=true`.** The spec's
    reference has only `ReferenceOutputAssembly=false`, but the JavaScript SDK declares `net6.0`,
    and MSBuild's framework check then fails a solution build against the Migrator's `net10.0`.
13. **`distributions/acme/Directory.Build.props` sets `Version` 0.1.0.** The spec does not name
    where the distribution's version lives. Without it every Acme assembly reports the SDK's
    default `1.0.0`, and `distribution.version` would not be Acme's own.

      suite references the Migrator itself.

        deps.json and runtimeconfig.json). With it restored, it passes, and an incremental build
        removed the stale copies.
    - A new CI step after the `acme-client` publish fails on any `Tellma.Distro.Acme.Migrator.*` in
