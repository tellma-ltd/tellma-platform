# PC-116: /shell entry point: frame, tenantless shell, tenant picker, signed-out page

## Implementer notes

### What was built

The shared shell frame, the tenantless shell and its two pages, their page contexts and a harness,
all in `@tellma/core/shell` (spec 0027 §1, §5.2–§5.4, §6, §14).

- **Frame** — `client/projects/core/tellma-core/shell/src/frame/tm-shell-frame.ts`.
  - `tm-shell-frame`: the skip link (first focusable, shown on focus, moves focus to `main`
    without a router navigation), a `header` with `[tmShellBar]`, `tm-banner-host` and
    `[tmShellPinnedBar]` rows, `main#tm-main` (the one scrolling region, stable gutter), and an
    empty hidden `aside`. Print hides the chrome; nothing animates.
  - An immersive frame (`TmShell.immersive`) renders no `header`.
  - A root `TmShellRowsWriter` writes the newest live frame's `--tm-app-bar-height`,
    `--tm-banner-height` and `--tm-pinned-bar-height` on the root element, so two frames that
    overlap during a navigation never fight, and removes them when the last frame ends. The grid
    and the defaults stay in `styles/tm-frame.css`, as before.
  - The frame registers `tm.shell.skip` and `tm.shell.tenants` (the picker route's document
    title, which the title strategy reads before the picker's chunk loads).
- **Tenantless pages, a lazy chunk of `/shell`** — `shell/src/tenantless/`.
  - `tm-tenantless.ts` is the chunk's entry (`tellma-core-shell-tm-tenantless-*.mjs`, budgeted at
    8 KB in `lazyChunkBudgetsInKb`); `tm-shell-components.ts` maps the route names to loaders.
  - `tm-tenantless-shell.ts`: the 40 px ink bar: wordmark (mark below `md`) linked to `/`, the
    language menu (only with two or more languages; globe below `md`; switching sends no
    request), the account menu (name over email, avatar below `md`; My account to
    `identity.accountUrl` with `return_url` and `ui_locales`, only while the distribution
    document holds it; Sign out). `signedOut` shows the wordmark alone.
  - `tm-tenant-rows.ts`: pure row model. Name slot by language subtag (D-269 keyof typing on
    `NAME_SLOTS`), live tenants by shown name in the active language's collation with their
    sandboxes nested beneath, unattached sandboxes last, retired tenants dropped, badges and
    unavailable reasons (removed > suspended > provisioning), search over every name folded by
    `tmSearchNormalize` and the id exactly, dimmed live parents of matching sandboxes.
  - `tm-tenant-picker.ts`: stored list in the first frame, `revalidateUser()` in
    `afterNextRender` (no request before the first render — the held PC-114 stand-in's rule
    kept); skeleton (four rows) while nothing is stored; the error state, from a lazily imported
    `@tellma/core/errors`, when the read fails with nothing stored, with Try again; the empty
    state with Sign out; search from seven memberships with `?q=` (replaceUrl), Enter following
    the only enabled match, Mod+K (`tm.launcher.open`) focusing it; the no-match line; the
    tenant-not-found notice (named, or by id when the list no longer holds it) with Dismiss
    dropping `notice` and `from`; Connect links to `TmUrls.forTenant(id).home()` with preload on
    hover and focus, or a disabled button with its reason; `tm.shell.picker-shown` once; the
    `/tenants` custom page context (count, query, the Name/Id rows shown, up to 200).
  - `tm-signed-out-page.ts`: no API call of its own, Sign in to `/`, and with a profile cookie
    "signed in as" plus Continue; `/signed-out` custom page context.
  - Strings: `tm-tenantless-strings.ts` (`tm.tenantless.*`) and the Arabic pack's mirror.
- **Core changes**
  - `TmShellComponents` members are loaders (`() => Promise<Type>`); `tmShellComponent` calls them.
  - `TmLaunchCache.revalidateUser()` settles with the tenants read's `TmApiError` or `null`.
  - `/tenants` route title key `tm.shell.tenants`; `tm.shell.signedOut.signIn` kept in English
    for the error state and the session flows.
- **Build tooling** — `client/projects/core/tellma-core-tools/src/output/preloads.ts` and

- **Harness** — `client/projects/core/tellma-core-testing/src/tm-tenant-picker-harness.ts`:
  `TmTenantPickerHarness` and `TmTenantPickerRowHarness`, exported from `@tellma/core-testing`.
- **Tests** — `tm-tenant-rows.spec.ts` (unit, name slots, order, collation, badges, search),
  `tm-tenant-picker.spec.ts` (harness, every bullet of the checkpoint's test list),
  `tm-tenantless-shell.spec.ts` (bar and signed-out page), `frame/tm-shell-frame.spec.ts`.

- **Docs** — `@tellma/core` README (`/shell` row, frame and tenantless paragraph),

### Deviations

1. The tenantless pages are a lazy chunk of `/shell`, so `TmTenantPicker`, `TmSignedOutPage` and
   `TmTenantlessShell` are exported as types only (spec 0027 §1 lists them as `/shell` exports).
   Reason: they keep `/search-normalize` out of `/shell`'s static graph and out of every tenant
   first frame, within the 1.35 KB budget's spirit.
2. `TmLaunchCache.revalidateUser()` returns `Promise<TmApiError | null>` rather than
   `Promise<void>` (spec 0025 §3.1), so the picker can tell a failed read from a stored list.
3. The tenant-shell stand-in renders inside the frame with `appBar=false`, so the tenant layout is
   now the 100dvh grid with only `main` scrolling.
4. The picker's title string is `tm.shell.tenants` in the frame's scope, not in the chunk's.
5. The modulepreload rule changed (see Build tooling): `/attention`'s lazy chunks are no longer
   preloaded in a workspace build either, which the spec already called lazy.
6. Budgets: `"."` 49.89 → 49.9 (51,091 B against the 51,087 B ceiling, +4 B for the route
   title, the loader map and the `revalidateUser` result; cap line 49.79 of 50 at gzip 9);
   `./shell` 1.35 → 2.35 (1.32 → 2.00 KB, +0.68 KB, rounded up to the next 0.5 KB per D-031)
   with the 8 KB `tm-tenantless` lazy budget (7.69 KB); `locale-ar` `./platform-strings`
   3 → 3.5 (+0.51 KB of Arabic strings).
7. Added in review 1: `tellma-client build` prefetches (`rel="prefetch"`) the tenantless pages'
   chunk and its own static imports, outside the initial JavaScript, so a launch to `/tenants`
   or `/signed-out` fetches it beside `/shell` rather than after it.
8. Added in review 1: the `tm-tenantless` lazy budget is 8.5 rather than 8 (7.69 → 8.04 KB,
   +0.35 KB, rounded up to the next 0.5 KB per D-031) for the review's loading status, the
   failure line with Try again, and the single live region.
9. Added at integration (D-272): the shell's Arabic moved from `@tellma/locale-ar/platform-strings`
   to a new `@tellma/locale-ar/shell-strings` (0.99 of 1), which `tmArabic()` loads beside the
   other two, instead of a third raise of `./platform-strings` (3.45 of 4 after).
10. Added at integration (D-281), **for Ahmad: a new public entry point.** `TM_BLOB_FETCHER` and
    its types moved from `@tellma/core-ui/image` to a new `@tellma/core-ui/blob-fetcher`
    (0.66 of 1), which `@tellma/core-ui/image` re-exports, so no import breaks. Reason: the
    primary imported the seam from `./image`. That made `tm-image`'s file reachable from the
    first frame, so the bundler put the image code the tenantless shell's avatar uses into the
    initial chunks. The same was true of the menu, which the tooltip reached for its long-press
    observer; that observer moved from `@tellma/core-ui/menu` to `@tellma/core-ui/overlay` (ɵ,
    no golden change). Together these put about 19.7 KB gzip into the fixture app's first
    frame. `"tellma".staticGraphExcludes` now names `@tellma/core-ui/menu` and
    `@tellma/core-ui/image` for the primary, and size:check fails when any static import chain
    reaches either file, whether or not the primary uses it. The new rule needed `"."` to rise
    from 50.16 to 50.17 (+1 B, the longer import specifier).

**Counts: blocking 0, major 1, minor 6.**

**R1-1 (major). The tenant picker and the signed-out page now load in series after `/shell` on a
cold launch. The spec keeps that path parallel, and deviation 1 does not mention it.**
- *Where.* `shell/src/tm-shell-components.ts:19-26` (the tenantless loaders), and
  `tellma-core-tools/src/output/preloads.ts:118-119`, which no longer reaches the chunk.
- *Spec.* Spec 0024's entry-point table makes `/shell` "eager, modulepreloaded". Spec 0027 §1
  ("Loading") and Decision 1 say "the preload keeps the cold path parallel". Before this change,
  the picker stand-in sat in the preloaded `/shell` chunk.
- *Failure scenario.* A user with two live tenants opens the app for the first time, with no
  service worker and an empty HTTP cache.
  1. `main` and the preloaded `/shell` arrive, and the launch decides `/tenants`.
  2. Only then does the router fetch the tenantless chunk: 13.90 KB gzip in Acme, one more round
     trip.
  3. Only after that chunk renders does the picker's `afterNextRender` send `GET /bff/user`.

  The skeleton therefore waits on two serial round trips instead of one. `/signed-out` pays the
  same extra trip after every sign-out on a device without the worker. A tenant user's first
  Switch pays it too, from the worker's cache once one is installed.
- *Suggested fix.* Keep the chunk lazy; the reason (smaller tenant first frames) is good. Restore
  the overlap in one of two ways:
  - (a) `tellma-client build` adds a `<link rel="prefetch">` for the chunk holding
    `shell/src/tenantless/tm-tenantless` (or the built `tellma-core-shell-tm-tenantless-*`). A
    prefetch is low priority and does not count in initialJs.
  - (b) The boot and launch path start the chunk as soon as the target is known: a boot URL of
    `/tenants` or `/signed-out`, or `TmLaunchRedirect` choosing `/tenants`. This can go through
    `TmUrls.preload('/tenants')` or a `ɵTM_SHELL` warm-up, while the route resolves.

  Either way, state the cost and the mitigation under Deviations. If neither is wanted, record the
  serial fetch as an accepted deviation for Ahmad.

**R1-2 (minor). On a launch with no stored list, the picker's page context says `ready` while the
skeleton shows.**
- *Where.* `tm-tenant-picker.ts:521`. `status` is `loading` only while `#reading` is true, which
  `afterNextRender` sets (`:462`, `:603`).
- *Failure scenario.* A cold `/tenants` with no stored list registers its context in the first
  frame as `status: 'ready'` with `visible: undefined` and `count: 0`. It then flips to `loading`.
  - A reader (the support dump, a future assistant) takes the skeleton for "no tenants".
  - Spec 0026 §9.1 has `status` "tell 'still loading' apart from 'empty'".
  - Spec 0026 §5.1's data time ends at the first change away from `loading`.
- *Suggested fix.* Derive `status` from the state: `loading` while `#reading()`, or while
  `#rows() === undefined && #failure() === null`. Assert it in the skeleton test.

**R1-3 (minor). If the error views fail to load, the picker renders an empty region with no way
out.**
- *Where.* `tm-tenant-picker.ts:477-485`: `void import('@tellma/core/errors').then(...)` has no
  rejection path.
- *Failure scenario.* The error state shows exactly when the read failed with nothing stored. The
  usual cause is being offline, or a tab left open across a deploy whose old chunk hashes are gone.
  If the `@tellma/core/errors` chunk is not cached:
  - the import rejects;
  - the `@else if (failure())` branch renders an empty `ng-container`;
  - the skeleton is gone, and there is no message and no Try again;
  - the rejection goes unhandled.
- *Suggested fix.* Catch the rejection. Render a minimal inline message with Try again calling
  `#read()`, or reuse the route host's chunk-failure path (`client-outdated`, which
  `tm-route-host.spec` covers). Report it through `TmTelemetry.error`. Add a test with the import
  rejecting.

**R1-4 (minor). In RTL the tenantless app bar takes its safe-area insets from the wrong sides.**
- *Where.* `tm-tenantless-shell.ts:101`:
  `padding-inline: max(var(--space-4), env(safe-area-inset-left)) max(var(--space-4), env(safe-area-inset-right))`.
- *Failure scenario.* In Arabic, `padding-inline-start` is the right edge, yet it gets the left
  inset. On an installed iPhone in landscape with the notch on the left, the account menu sits
  under the notch, because in RTL the inline end is on the left. Spec 0027 §5.1 says the insets pad
  the app bar, and §14 says "Logical properties" for RTL.
- *Suggested fix.* Use physical `padding-left` and `padding-right` with their matching insets.
  Alternatively, swap the two `env()` values under `:host-context([dir='rtl'])` or `:dir(rtl)`.

**R1-5 (minor). The no-match and loading announcements are live regions inserted with their text
already in them, which screen readers often skip.**
- *Where.* `tm-tenant-picker.ts:196`: `<p ... role="status">{{ noMatch() }}</p>`, which the `@if`
  creates. And `:215`, the skeleton's `role="status"` paragraph.
- *Failure scenario.* A screen-reader user types a query that matches nothing. The status element
  enters the DOM already holding "No tenants match …", and NVDA and VoiceOver commonly announce
  nothing.
  - `TmAlert` in this repository documents the same pattern and gates its content for this reason
    (`tm-alert.ts:33-36`, `:96-99`).
  - Spec 0027 §14 requires WCAG AA.
- *Suggested fix.* Keep one `role="status"` element rendered for the page's life and change only
  its text: the loading line, the no-match line, or empty. Or use the library's live announcer.

**R1-6 (minor). The Arabic Connect button fails label-in-name.**
- *Where.* `strings-tm-ar.ts:138-139`. The visible label is `دخول`, and the accessible name is
  `الدخول إلى {name}`.
- *Failure scenario.* WCAG 2.5.3 wants the visible label inside the accessible name. A speech user
  saying "دخول" matches only a substring of the word `الدخول`, which many engines do not treat as
  the label. The English pair ("Connect", "Connect to {name}") is right.
- *Suggested fix.* Use `connectTo: 'دخول إلى {name}'`, or make the visible label `الدخول`.

**R1-7 (minor, test). The frame's newest-frame-wins rule, and the rows the tenant-shell stand-in
writes, are untested.**
- *Where.* `tm-shell-frame.spec.ts:52-57` covers one frame's write and the reset only. The
  implementer asks reviewers to examine `TmShellRowsWriter` hardest.
- *Failure scenario.* Either of these breaks fails no spec:
  - `TmShellRowsWriter.hold` stops taking the newest frame (`#frames().at(-1)`);
  - a destroyed frame's filter drops the wrong entry.

  The root variables would then stay at the picker's values (40/0/0) after a navigation into a
  tenant, where the stand-in wants 0/0/0.
- *Suggested fix.* Add a spec that:
  1. opens `/tenants`;
  2. navigates to `/17` (the stand-in, with `appBar=false`) and asserts `0px`/`0px`/`0px`;
  3. navigates back and asserts `40px`/`0px`/`0px`.

  A unit test of the writer with two overlapping holds, destroyed in either order, would also pin
  the overlap case.
