# PC-031: Pager, tree, drag-drop and reorder list

## Implementer notes

### What was built, and where

Four new entry points of `@tellma/core-ui` (all under `client/projects/core/tellma-core-ui/`):

- `pager/` — `TmPager` (spec 0023 §8.1). Range and item modes, lower-bound totals (`1,000+`),
  `maxPage`, long or short labels, and a size select in range mode. The status reserves its widest
  width in `ch` (pure helpers in `pager/internal/tm-pager-status.ts`), and the size select reserves
  its widest option with a hidden sizer. The status is a visual fraction (`aria-hidden`, `dir=ltr`)
  plus a sentence for screen readers.
- `drag-drop/` — `TmDragDrop` (the service holding the drag in flight), `TmDragSource`,
  `TmDropTarget` (spec 0023 §8.3). A source writes `text/plain` and a drag id
  (`application/x-tellma-drag`); a target accepts a drag only when the id is the one in flight and
  its kind is in `accepts`, so files and drags from other windows go to the browser. The over tint
  is a global sheet, `styles/tm-drop-target.css`, because the directive has no template.
- `tree/` — `TmTree` and `TmTreeNode` over `@angular/aria/tree` (spec 0023 §8.2). Lazy
  `children` with a reserved spinner slot, `none`/`single`/`multiple` selection, typeahead,
  `context` nodes, `dragData`, `activate`, and a dev warning above 500 open nodes. The internal
  `ɵTmTreeClicks` (`tree/internal/tm-tree-clicks.ts`) adapts aria's click, focus and drag handling.
- `reorder-list/` — `TmReorderList`, `TmReorderItem`, `TmReorderEmpty` (spec 0023 §8.4). The handle
  grab model (Space/Enter, arrows, Home/End, Space to drop, Escape to cancel, Tab drops), Alt+Up and
  Alt+Down, assertive LiveAnnouncer strings, pointer drags on the insertion line, and external
  drops of accepted kinds (`received`).

Around them: harnesses in `tellma-core-ui-testing` (`pager-harness.ts`, `tree-harness.ts`,
`reorder-list-harness.ts`); tokens in `presets/tellma-default.ts` (`pager`, `tree`, `reorderList`,
`dropTarget`); English and Arabic strings; showcase stories `pager`, `tree`, `reorder-list`,
`drag-drop`; e2e specs `client/e2e/specs/{pager,tree,reorder-list,drag-drop}.spec.ts`; budgets and
the global sheet in `tellma-core-ui/package.json`; README rows.

### Deviations

1. **Tree `children` runs when a node first renders**, not on first expansion, so a known leaf shows
   no twisty before anyone opens it. A failed prefetch is silent and is retried on expansion; a
   failure while the node is open collapses it and announces. Risk: an async loader is called for
   every visible branch (one level ahead), not only for opened ones.
2. **Only the twisty toggles expansion on a single click.** A click on the content selects
   (`single`), toggles (`multiple`, Shift for a range) or only focuses (`none`); a double-click
   toggles a branch and activates a leaf. aria's own click selects and toggles anywhere on the row,
   which would make a double-click open and close a branch.
3. **Enter in `multiple` mode toggles and does not emit `activate`**, matching spec 0029 §11.3 (the
   path picker), which 0023 §8.2 leaves open.
4. **Typing-only inputs `tmTreeNodeOf` and `tmReorderItemOf`** were added so the templates' context
   is typed; they are not in the spec's API.
5. **Changing the pager's page size rewrites `page`** so the first row in view stays in view
   (source: spec 0030 §14); 0023 §8.1 only says the size is a model.
6. **The drop target's look is a global stylesheet** (`styles/tm-drop-target.css`, registered as the
   entry point's global sheet), since an attribute directive has no styles of its own.
7. **The tree's twisty is a 24px target** around the 13px glyph the spec names, and the token set
   gains names the spec does not list (`tree.spinnerSlot`, `tree.twistyTarget`, `tree.checkSize`,
   `reorderList.handleIconSize`, `reorderList.indicatorSize`, `dropTarget.borderWidth`, …).
8. **Reorder announcements are assertive**: each one answers a key press the user is waiting on.
9. **Programmatic focus syncs aria's active item**, so keys that follow a `focus()` act on the
   focused row (aria otherwise keeps acting on its stale active item).
10. **`ɵTmTreeClicks` replaces aria's `_pattern.onClick`** with an own property, following the
    precedent of `ɵTmMenuList` in menu-rows. This leans on aria 22.0.3's private pattern; an aria
    upgrade must re-check it (the tree specs fail loudly if it breaks).
11. **A drop without its drag id is accepted when it carries the in-flight drag's text.** The
    WebKit build Playwright drives delivers only `text/plain` to the drop (the
    `application/x-tellma-drag` type is gone, `effectAllowed` reads `all`), so the id check of
    spec 0023 §8.3 alone made every WebKit drop onto a `tmDropTarget` a no-op. The fallback matches
    only the one drag in flight, and only by its exact text; a file or a foreign drag carries a
    different text or arrives with no drag in flight. (Tightened after review 1: no fallback for a
    drop carrying `Files` or the drag type, or for an empty text.)
12. **A click on a reorder handle opens a move menu** (Move up, Move down, Move to top, Move to
    bottom), added after review 1 (R1-1): spec 0023 §8.3/§8.4 name only the handle's keys as the
    non-drag path, which meets WCAG 2.1.1 but not 2.5.7's single-pointer alternative, and a screen
    reader's activation sends a click, not a key.

### Open risks

- aria internals: the click override (deviation 10) and `activeItem` writes depend on aria's
  pattern API, which is private.
- Native drag-and-drop in WebKit under Playwright is the least deterministic engine; the
  `@cross-engine` tests were repeated to check for flakes (see Tests in the commit).
- The tree's eager `children` (deviation 1) changes load traffic for consumers whose loaders fetch.
- Deviation 11: a foreign text drag dropped while one of ours is in flight with the same text
  would be taken as ours. Only one drag runs at a time, so this needs a drag from another window to
  arrive while ours is recorded (an orphaned record is cleared at the next pointer move).
- Reorder-list refocus after a move restores focus only when the re-render lost it (focus on the
  body or inside the moved row), and a focusout to another element while the refocus is pending
  cancels it. Without both, a Tab pressed before the render was pulled back to the handle (a
  1-in-2 flake under `--repeat-each 10`); two unit tests pin the two paths (focus leaving the list,
  and focus going to the next handle whose row the render then moves).

### What reviewers should examine hardest

- `tree/tm-tree.ts` lazy-load cache: generations across `nodes`/`children` identity changes,
  failed-then-retried entries, and the collapse-and-announce path.
- `tree/internal/tm-tree-clicks.ts`: focus and active-item restore when a drag starts, especially
  when nothing had focus before the press.
- `reorder-list/tm-reorder-list.ts`: the grab model's exits (Tab, focusout, Escape, an outside
  change to `items`) and the insertion index for pointer drops at row boundaries.
- `drag-drop/tm-drop-target.ts`: the enter/leave depth counter, the innermost-target-wins rule,
  and the id-less fallback in `droppedDrag`.
- Bundle ceilings: pager, tree and reorder-list are raised above the spec's 2/4/3 KB at birth
  (linked 2.70/4.99/4.37 plus 0.1 KB; reorder-list raised to 4.8 after review 1 for the move menu, linked 4.70), and the root by 0.29 KB for the English strings; the notes
  in `tellma-core-ui/package.json` itemize each.

## Review 1

Reviewed commit 646fde1. I re-ran the four new unit files (66/66 green), `build` and `size:check`.
The measured sizes match the budget notes: `.` 9.04, pager 2.70, tree 4.99, reorder-list 4.37 and

### Findings

**R1-1 (major): a pointer user cannot reorder without dragging, so the handle is not a non-drag
path under WCAG 2.5.7.** `reorder-list/tm-reorder-list.ts:115-125`. The handle reacts only to
`keydown` (Space or Enter, then arrows) and has no `click` handling. WCAG 2.5.7 asks for a
*single-pointer* alternative to every drag. A keyboard path meets 2.1.1, not 2.5.7. So a mouse,
touch or switch user without a keyboard can reorder only by dragging, and phones and Firefox for
Android have no native drag. The same gap reaches assistive technology. VoiceOver or TalkBack
activation (double-tap) and NVDA or JAWS browse-mode Enter/Space send a `click`, not a `keydown`,
so those users cannot even pick an item up. Spec 0023 §8.3 names "the reorder handle (§8.4)" as the
WCAG 2.5.7 path, and §2.1 gives only keys, so this is a spec gap as much as a code gap. It should
be flagged for Ahmad. Suggested fix: activating the handle by click (pointer, or a click with
`detail === 0` from assistive technology) opens a small menu: Move up, Move down, Move to top, Move
to bottom. Each entry runs the same `commitMove` and announcement as Alt+Arrow. Add a pointer-only
test and a `click()`-only harness test. At minimum, make a click toggle the grab, so screen-reader
activation can pick an item up.

**R1-2 (minor): the id-less drop fallback trusts any in-flight record, including a stale one.**
`drag-drop/tm-drop-target.ts:149-154`, `drag-drop/tm-drag-drop.ts:101-106`, `:161-186`. A record
is cleared only by its own source's `dragend` or, for a destroyed source, by `ɵorphan`. If a
`dragend` is lost, `current()` stays set until the next `ɵbegin`. Two ways that can happen: a
synthetic `dragstart`, as the forced-colors e2e does, or a source node moved in the DOM in Firefox.
From then on:
- every foreign drag over a target that accepts that kind is answered by `answer()`, which checks
  only `current()`. It gets the over tint and `preventDefault`.
- a foreign drop with the same `text/plain` is emitted as that stale payload.
- a payload with empty `text` matches every file drop, since both read `''`.

Suggested fix:
- take the fallback only when `data.types` lacks `ɵTM_DRAG_TYPE` and `'Files'`, and when
  `current.text !== ''`;
- at `ɵbegin`, register the window-level `dragend` and `drop` (bubble) end listeners that
  `ɵorphan` uses today, so every drag ends however its source fares;
- unit-test a stale record that a window `dragend` clears.

**R1-3 (minor): the pager's width reservation does not hold past a lower-bound total.**
`pager/internal/tm-pager-status.ts:56-57` and `:68-80`, `pager/tm-pager.ts:199-206`. With
`totalIsLowerBound`, `to` is `page × size`, uncapped. But the reservation is "{total}–{total} /
{total}+". Spec 0030 §14 sets `maxPage` from `maxSkipWindow`, which is independent of the count cap.
Take a cap of 1,000+, `maxSkipWindow` 10,000 and size 20: page 51 reads "1,001–1,020 / 1,000+" and
page 500 reads "9,981–10,000 / 1,000+". Each needs one more digit than was reserved, so the buttons
move. Suggested fix: under a lower bound, reserve for `max(total, to of maxPage)`. With
`maxPage === null`, reserve one extra digit or say in the TSDoc what is guaranteed. Add a unit
vector for this.

**R1-4 (minor): the 500-open-node dev warning runs one render behind expansion.**
`tree/tm-tree.ts:328-346`. aria's `DeferredContent` creates an opened group's view in its own
`afterRenderEffect` write phase. The rows inside it, from the `ngTemplateOutlet` and `@for`, render
only at the next change detection. This effect's read phase runs in between and counts the old
DOM. It then does not re-run, because `cacheVersion`, `expanded` and `nodes` do not change again.
So the expansion that crosses 500 does not warn; the next unrelated expansion does. This is
reasoned from aria 22.0.3's `_deferred-content-chunk.mjs`, not reproduced. The only test,
`tm-tree.spec.ts:367`, puts 501 nodes at the root, which renders in the first pass. Suggested fix:
count in `afterEveryRender` behind the `warned` flag (dev only), or count rendered keys after
render. Add a test that expands one branch holding 501 children.

**R1-5 (minor): no test pins the main reason `ɵTmTreeClicks` exists.** `tree/tm-tree.spec.ts:189-244`,
`e2e/specs/tree.spec.ts:100-112`. Without the override, aria toggles expansion on every click. Both
double-click tests pass either way: click opens, click closes, then `dblclick` opens, so the branch
ends expanded. The only runtime guard is "does not select when the twisty is clicked". Renames are
caught at compile time, because `_pattern.onClick` and `treeBehavior` are typed in aria's d.ts. But
a moved listener, say `(click)` to `(pointerup)`, would still leave single-click toggling
unpinned. Suggested fix: add "a click on a branch's content does not expand it" in `none` and
`single`. Also assert that `onClick` is an own property of `_pattern` and that one click calls it.

**R1-6 (minor): a grab can outlive its handle and swallow a later Escape.**
`reorder-list/tm-reorder-list.ts:421-436`. When focus moves from a grabbed handle into its own row
(`staysInRow`), the grab is kept. For example, the user clicks a button or checkbox in a custom row
template. Once focus then leaves the row from that control, nothing ends the grab:
- the preview order stays on screen and the row stays tinted;
- the Escape-stack entry consumes the next Escape anywhere on the page, such as a dialog's or a
  search field's, and turns it into "Move cancelled".

Suggested fix: drop, or cancel, whenever focus leaves the handle while `moving` is false. Or watch
`focusout` on the list, not on the handle, and end the grab when focus leaves the list.

**R1-7 (minor): an expansion the host writes never retries a failed load.** `tree/tm-tree.ts:449-466`,
`:386-405`. A failed entry, for example a quiet prefetch failure, retries only in `setExpanded`,
which aria's keys, the twisty and a double-click reach. When the host writes `expanded` itself,
the node renders open with an empty group: no spinner, no announcement, no retry. Examples are a
restored expansion set and the 0029 §11.3 search expanding ancestors. Suggested fix: on each render,
retry `failed` entries whose key is in `expanded()`, out of the template pass (an effect over
`expanded`). Add a harness test that writes `expanded` over a rejected prefetch.

**R1-8 (minor): a reorder row's lifted state can stick.** `reorder-list/tm-reorder-list.ts:108-112`.
`draggingKey` is cleared only by `(dragEnded)`. If a row is destroyed mid-drag, for example because
`items` changes from outside, its `tmDragSource` cannot emit. `ɵorphan` ends only the service's
record. The re-created row with the same key then keeps `--dragging` (`--shadow-sm`) until the next
drag. Suggested fix: derive it as
`computed(() => current()?.kind === ownKind ? keyOf(current().data) : null)` from
`TmDragDrop.current`, and drop the signal and the two listeners.

**R1-9 (minor, process): the gate evidence does not show green PR-tier runs on the final code.**

PLAN.md §7.1 item 4 and the CI rule count a retry pass as red. Suggested fix: rerun the PR-tier
e2e, `lint:test`, and `@cross-engine` on Firefox and WebKit on the final sha. Record the fonts and

### Rulings on the implementer's decisions

1. **Budgets over spec: accepted.** I reproduced the figures: pager 2.70, tree 4.99,
   reorder-list 4.37 and `.` 9.04 linked. Each ceiling is its measure plus 0.1, as with PC-026's
   at-birth raises. I found no real fat. The sibling entry points are external. The one duplication,
   `nodeOfRow` against `ɵTmTreeClicks.itemOf`, is a few dozen bytes. The strings cannot be lazy,
   because §10 puts English in `TM_UI_STRINGS_EN` in the primary. The `budgetNotes` trail is
   adequate. The orchestrator should tell Ahmad that 0023 §1's 2/4/3 KB caps are superseded again.
2. **WebKit drop fallback: accepted, with the tightening in R1-2.** A drag from another Tellma
   tab carries its own id and is still refused. A foreign drop can be mistaken only while the
   receiving document holds an in-flight or stale record, and the fallback runs only when the id
   is absent. Embedding a nonce in the text is rejected: `text` is what editors insert at the
   caret (a Queryex path, 0029 §11.3), so a nonce would corrupt every text drop.
3. **Tree prefetch: accepted as a recorded deviation; flag it for Ahmad to amend 0023 §8.2.**
   The spec's API makes leafness knowable only by calling `children`, and §8.2 wants an empty slot
   on a leaf. The cost is one loader call per rendered branch, re-run whenever `nodes` changes
   identity. That means once per keystroke for a search that rebuilds `nodes` (0029 §11.3). It is
   cheap for every named consumer (0029 §11, 0030 §11, 0034 §12 are local, synchronous
   descriptors), but N requests at once for a fetching loader. An optional `hasChildren` hint
   would let async consumers opt out. Prefetch adds no rows to the 500-node count, because aria
   destroys collapsed groups, though the count itself lags (R1-4). Stale settles are ignored by
   generation, consistent with D-077's intent.
4. **Click semantics: accepted.** Twisty-only toggling matches §8.2 ("the twisty … expands and
   collapses") and makes 0029 §11.3's double-click rules work. Enter toggling in `multiple`
   follows 0029 §11.3, and its only `multiple` consumers go through the path picker. Ask Ahmad to
   add "Enter toggles in `multiple`" to 0023 §2.1.
5. **`ɵTmTreeClicks` over `_pattern.onClick`: accepted.** aria's d.ts types `_pattern`, `onClick`,
   `treeBehavior.goto/toggleExpansion`, `hasBeenInteracted` and `activeItem`, so a rename fails
   typecheck loudly. The behavioural guard is partial; add the test in R1-5.
6. **Other deviations: accepted.**
   - `tmTreeNodeOf` and `tmReorderItemOf` are typing-only inputs, with goldens approved.
   - The page-size rewrite follows the formula in 0030 §14.
   - `styles/tm-drop-target.css` follows the `tm-button.css` precedent. It contradicts 0023 §1's
     "one global stylesheet", and 0024 §7.6's `@tellma/core/styles.css` must import it. Flag both.
   - The 24px twisty is required by §2.1's 24px targets, and the extra tokens fall within §9.
   - Assertive announcements answer the user's own key press.
   - The focus sync of the active item is right.
