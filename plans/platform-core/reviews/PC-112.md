# PC-112: TmTelemetry pipeline, TmErrorHandler and redaction

## Implementer notes

### What was built, and where

All client-side; no C# changes. Paths are under `client/projects/core/` unless noted.

- **The front** (`tellma-core/src/observe/tm-telemetry.ts`, primary, eager). `TmTelemetry` stays
  the abstract API (spec 0026 §3) and its root default is now `TmTelemetryFront`, which replaces
  the old quiet default. The front stamps each call with `TM_NOW`, holds at most 200 calls until
  the pipeline starts, logs every `error()` to `console.error`, and records the event the browser
  is dispatching at an `error()` call (`globalThis.event`) so the pipeline can tell `global` from
  `render`. `start(injector)` loads the pipeline chunk with `import()` and hands it the held calls.
  `TmTelemetryOptions` gains `traceId`.
- **The error handler** (`tellma-core/src/observe/tm-error-handler.ts`, primary, eager).
  `TmErrorHandler` (one call to `TmTelemetry.error`), `TmErrorSource`, `TmErrorRecord` (§4).
  `provideTellma` provides it as Angular's `ErrorHandler`; it is exported from `@tellma/core`.
- **The pipeline** (`tellma-core/src/observe/tm-telemetry-pipeline.ts`, lazy chunk
  `tm-telemetry-pipeline`, 4.42 KB against a 4.5 ceiling). `TmTelemetryPipeline` over a
  `TmTelemetryHost` (the app's services in an app, a fake in its spec):
  - the guard: name grammar and 64 characters, keys, values, 16 properties with the reserved ones,
    reserved keys, finite `ms`, trace ids; development throws `TmTelemetryError`, production
    drops the item (bad name) or the property (bad value) and counts it;
  - the envelope: `version`, `tabId`, `tenantId` per batch (one tenant per batch), `sentAt`, and
    per item `kind`, `name`, `at`, `traceId`, `properties` with `route`/`pageKind` from
    `TmPageContexts.current`, `ms` for timings, `sampleRate` for sampled items;
  - per-tab sampling (one `Math.random()` draw), sampled by default `tm.page.*`, `tm.vitals.*`,
    `tm.action.*` and non-`tm`, overridden by `options.sampled`;
  - the `recent` ring of 100, `console.debug('[tm]', name, props)` in development;
  - the queue: cap 200 (overflow drops the oldest non-error, else the oldest), flush at 50 items,
    30 s after the first item, 1 s after the latest error (debounced), `flush()`; batches of at
    most 100 items and 16,384 UTF-8 bytes measured on the JSON body, paced one a second, a regular
    flush joining one in progress; `tm.telemetry.dropped { count, reason }` leads the next batch;
  - holds: offline (`TmApi.online`), session not `active`, UI version unknown (read from
    `TmClientMetadataStore` until PC-113's `TmAppVersion`); disabled distributions queue nothing
    and clear what the cold defaults queued; cold launch uses enabled, rate 1;
  - `tmStartTelemetry` wires the app: an effect flushes on a tenant switch and when a hold lifts,
    `visibilitychange` to hidden flushes, `pagehide` flushes one batch, `DestroyRef` stops it; the
    held calls replay untracked, and a held call that throws in development is rethrown on its own
    microtask so the later calls still run.
- **Capture and redaction** (`tellma-core/src/observe/tm-error-capture.ts`, in the same chunk):
  `tmRedactMessage` (the five masks in order, then 200 characters), `tmReduceStack` (V8, Firefox
  and Safari frames; message lines dropped; URL to file name and position; non-ASCII masked; 30
  whole frames within 4,096 characters; top and first same-origin frame), `tmErrorClass`
  (`TmApiError`, `ChunkLoadError` by the three engines' wording, the name, the constructor),
  `TmErrorCapture` (global-only filters: cancelled/unauthenticated `TmApiError`, `ResizeObserver
  loop`, foreign top frame or a wrapped `ErrorEvent` naming a foreign file or `Script error.`;
  fingerprint `class@firstSameOriginFrame` limited to value characters and 64; the 50-record ring;
  10-minute per-fingerprint and 30-per-10-minutes throttles).
- **Call sites.** Every `telemetry.error(e, { source: 'tm-…' })` context became `{ where: … }`
  (the existing `tm-localization` convention), since `source` now names §4.1's source; the
  presenter's `{ source: 'api' }` stays. The contract-mismatch context's `route` became `api`,
  since `route` is reserved.
- **`TmFakeTelemetry`** (`tellma-core-testing/src/tm-fake-telemetry.ts`) keeps `options.traceId`.
- **`tm/telemetry-names`** (`tellma-core-tools/src/eslint/rules/telemetry-names.ts`): literal
  names of `event`/`timing` on a `TmTelemetry` (by type when the config is type-aware, a subclass
  included, else by the receiver's name), the `tm.` areas of Appendix A.2, conditional branches;
  literal action ids in `{ id, labelKey, invoke }` literals and `TmPageActions.invoke`. In the
  preset, and wired into the workspace's `tellma-core`/`core-testing` (type-aware) and
  `module` (by name) blocks. Fixture `src/eslint/fixtures/telemetry/`.
- **Budgets.** "." 49.89 → 50.09 (measured 49.88 → 50.083 linked gzip 6, cap 49.78 → 49.98 gzip
  9); the new chunk budget 4.5. Note in `budgetNotes["."]`.
- **Docs.** `tellma-core` README (new Telemetry and error logging section), `tellma-core-tools`
  README (rule row), ARCHITECTURE.md's `@tellma/core` row (the pipeline is a lazy chunk).

### Deviations

1. The pipeline, capture and redaction are a lazy chunk of the primary loaded at idle after the
   first render; spec 0026 §1 places them in the primary eagerly. The primary had 0.22 KB left
   under the 50 KB cap (D-247), and this keeps 0.02. Errors and items before the load are held
   (at most 200 calls) and replayed with their original timestamps.
2. In development, a malformed call made before the chunk loads throws asynchronously (its own
   microtask) at replay rather than synchronously at the call site. Calls after the load throw
   synchronously, as specified.
3. `TmTelemetryError` is a class of the chunk and is not exported from `@tellma/core`; code sees
   it only by its `name` (the abstract class's TSDoc says so). Exporting it would pull the class
   into the primary.
4. `TmTelemetryOptions.traceId` is added: §3.1's envelope names a per-item trace id, and the
   sketch's options had no way to pass one for events and timings.
5. A run of non-ASCII words with the spaces between them masks to one `…` (§4.3's example
   `القيمة غير صالحة` → `…` needs that); a single run elsewhere masks as specified.
6. `TmTelemetry.error`'s context uses `where` for the caller's location, and `source` only for
   §4.1's three values (anything else is a malformed property). Existing call sites were renamed.
7. Global versus render is read from the event being dispatched (`globalThis.event` is an
   `ErrorEvent` or a `PromiseRejectionEvent` while Angular's global listeners run), since
   Angular calls the same `ErrorHandler` for both.
8. The error records are reachable only through the pipeline (`TmTelemetryPipeline.errors`); the
   support dump (a later checkpoint) has no seam to read them yet.
9. The changed-user guard on a send is TmApi.send's own (spec 0024); the pipeline only reads the
   session's state for its hold.

### Open risks

- **Primary room.** The cap line is 49.98 of 50 at gzip 9: 0.02 KB left. Any later primary
  addition needs savings first.
- **Unit tests now see `TmErrorHandler`.** Every `provideTellma` rig installs it; with the fake
  telemetry it records a `tm.error.captured` item per error Angular handles. TestBed still
  rethrows. I ran the core project in full once (D-151).
- **Type-unaware lint.** `projects/module` lints without a TypeScript project, so receivers are
  known by name (`telemetry`, `…Telemetry`, `actions`, `…Actions`, `inject(TmTelemetry)`); an
  `event` call on an unrelated `…Telemetry` receiver would be checked too.

### What reviewers should examine hardest

- The flush state machine in `TmTelemetryPipeline.flush`/`#sendOne`/`#enqueue`: pacing joins,
  the re-armed 30 s timer while held, drop-count items leading a batch, the defensive drop of an
  item that cannot fit an empty batch, and the disabled path clearing a cold queue.
- `tmStartTelemetry`'s effect (initial values read untracked, flush on switch or hold lift) and
  the untracked replay.
- `TmErrorCapture.#foreign` against real browser stacks (extensions, `Script error.`, Angular's
  wrapper for an `ErrorEvent` without an error).
- The redaction regexes (`URLS`, `EMAILS`, `QUOTED` with its apostrophe rule, `NON_ASCII`).
- The measurement: `pnpm run size:check` on the merged base.
